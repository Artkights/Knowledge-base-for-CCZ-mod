# 版本差异矩阵

## 结论速览

大多数纯数据表在 6.5 与七套本地 6.6 中共用偏移和行宽。必须由变体处理的差异集中在物品行内部字段和兵种特效分配行宽。

## 适用版本

| 项目 | 6.5 | 6.6 标准 | 6.6 厚黑兼容 |
| --- | --- | --- | --- |
| 用户 Profile | 6.5 | 6.6 | 6.6 |
| 物品行宽 | 25 | 25 | 25 |
| 物品名称 | 17 字节 | 15 字节 | 17 字节 |
| 类型/特效 | 固定 `+11/+12` | 按 `+12` 标记动态映射 | 固定 `+11/+12` |
| 兵种特效分配 | `255 x 8` | `255 x 16` | `255 x 8` |
| 人物 token | `UInt16`，允许哨兵 | `UInt16`，允许哨兵 | `UInt16`，允许哨兵 |
| `7-3` | `255 x 16` | 继承，语义证据有限 | 继承，语义证据有限 |

## 已确认事实

人物、列传、兵种系、详细兵种、策略主表、说明和策略数值附表在当前样本矩阵中沿用共性几何。验证等级仍按表记录，不能把“文件足够长”描述成语义完全确认。

## 实现与使用方法

CSV 始终交换逻辑列。相同列名可以从 6.5 导入 6.6，目标 Profile 的 codec 决定实际写入位置。保留字节和资源字段不参与 CSV。

## 风险与边界

跨 Profile CSV 是字段级交换，不是完整二进制格式转换。尤其不能借由 CSV 自动改变 6.6 物品的普通装备/辅助/道具物理类别。

## 证据来源

Profile JSON 差异、codec 单元测试和两个布局族的临时副本写入测试。

## 待验证项

未来样本若改变共性表偏移，应新增表覆盖和新的 `LayoutRevision`，不能继续继承旧几何。
