# CSV 与历史记录

## 结论速览

CSV 交换逻辑字段，历史保存物理差异。二者通过当前 Profile 的 codec 衔接，因此 CSV 不需要知道字段的真实字节位置，历史则必须绑定布局修订。

## 适用版本

所有已解析 Profile 与变体。

## 已确认事实

CSV 默认 UTF-8 BOM，首列 ID，兼容 RFC 4180 引号和换行；导入支持 UTF-8、UTF-16 和 GBK 回退。可按 ID 或行序匹配，拒绝重复 ID、未知列、越界值和不合法的 6.6 类别转换。只读派生列导入时跳过并报告。

历史 schema 为 `2.0`，记录 `ProfileId`、`VariantId`、`LayoutRevision`、检测方法、保存时核心文件指纹、字段前后值、真实物理偏移和前后字节。历史根目录固定为 `.data管理器历史`。

## 实现与使用方法

CSV 导入只形成一条可撤回草稿命令，不直接写盘。一次保存会把所有脏模块合并为一条历史操作。撤回/前进先验证 Profile、变体、布局修订和当前文件哈希，再整体重放各文件差异。

## 风险与边界

schema 1.0 历史缺少布局身份，在双 Profile 模式下拒绝重放。外部修改导致哈希不一致时记录标记为冲突，不静默覆盖。

## 证据来源

CSV 编码与重复 ID 测试、多文件保存测试、同布局撤回/重做测试和跨布局拒绝测试。

## 待验证项

没有跨布局迁移历史字节的功能；跨版本交换应使用逻辑 CSV，并由使用者确认目标语义。
