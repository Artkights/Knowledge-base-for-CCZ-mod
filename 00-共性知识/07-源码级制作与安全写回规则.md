# 源码级制作与安全写回规则

## 结论速览

- 源码中存在某个地址或写入函数，只能证明“实现曾这样做”，不能单独授权其它版本、其它作品或其它工具照搬。
- 目标身份必须同时考虑 PE32/x86、模块归属、文件 SHA256、版本画像和语义签名。文件名、窗口标题、版本号或单个哈希均不能独立证明写入安全。
- 地址解析必须得到唯一匹配，覆盖完整指令边界，位于预期节区，并复核操作数、CALL 目标和加载基址换算；零命中、多命中或语义冲突一律降级。
- 功能可用性、证据状态和写入权限是三个独立维度。任一功能验证通过，不会自动开放同一画像中的其它功能。
- 严格事务、兼容直写和字段级 `DirectUnrestricted` 具有不同安全保证，报告和文档不得把三者统称为“安全写入”。

## 适用版本

- 本页适用于 6.5、6.5pl、6.6 及其派生作品的源码审阅、内存补丁、文件写回、代理 DLL、安装器和 AI 辅助制作。
- 规则来源于 Python 版扳手、小暗补丁 6.6 v0.7 和 CCZModStudio 一方源码；具体地址、表布局、ABI 和资源编号仍以各版本页面为准。
- 6.5pl 必须维持独立画像。来自 6.5 或 6.6 的源码结论，在没有 6.5pl 样本证据时只能登记为待验证。

## 已确认事实

### 身份、地址和语义解析

可靠的目标识别至少包含以下层次：

1. 验证文件和模块确实是 x86 PE32，写入地址属于预期加载模块。
2. 记录文件长度、SHA256、时间戳等身份，但不把哈希当作唯一定位机制。
3. 在内存 PE 映像的可执行节中搜索语义签名，要求唯一命中并覆盖完整指令。
4. 解析绝对操作数、相对 CALL/JMP 和加载基址，确认目标函数与数据之间的调用关系。
5. 对指针表在读取前、预览后和提交前重新解引用；缓存的绝对地址不能跨进程、读档或场景长期复用。

Python 扳手用 `TableLayoutSpec` 描述记录数、步长、字段宽度、解析方式和结构指纹，用 `ResolvedFeature` 分离地址解析结果和访问能力；`SemanticAnchorEvidence` 要求初始化、读取、写入锚点对同一指针和几何达成一致。小暗 `EngineLayout.cpp` 同样从内存映像解析函数、CALL 目标、阶段表和调用者，唯一性或关系校验失败时只关闭对应能力。

### 三个独立状态轴

| 状态轴 | 示例 | 含义 |
| --- | --- | --- |
| 功能访问 | `Unavailable / ReadOnly / ReadWrite` | 当前会话是否能解析和访问该功能。 |
| 证据进度 | `Unavailable -> StaticVerified -> RuntimeVerified -> Enabled` | 结论经过了哪些验证阶段；状态只能逐级提升。 |
| 写入模式 | 严格事务、沙箱、兼容直写、`DirectUnrestricted` | 当前入口实际承诺哪些比较、复读、回滚和发布门禁。 |

证据包应绑定功能键、配方 ID、目标 SHA256、文件长度、自动检查项、原始样本摘要、清单摘要和采集器身份。源码单元测试通过只证明实现符合测试契约，不等于在目标游戏中完成实机验证。

### 写入安全等级

| 模式 | 最低行为 | 不能声称的保证 |
| --- | --- | --- |
| 严格内存/代码事务 | 比较旧值；目标去重且范围不重叠；临时调整页保护；完整写入；写后复读；刷新指令缓存；失败逆序回滚；恢复页保护；回滚或保护恢复失败时锁定污染状态 | 未做运行时行为验收时，不能称为功能已验证。 |
| Python 扳手 `direct_write` | 顺序直写；必要时尽力调整并恢复页保护；代码写入后刷新缓存 | 不比较旧值，不保证复读，不做整体回滚；中途失败可留下部分写入。 |
| 字段级 `DirectUnrestricted` | 仍要求扫描或表解析给出唯一物理位置、边界、宽度和值域，并保留备份、报告和复读 | 绕过档案、旧字节、动态证据和发布清单门禁；结果必须标记 `UnverifiedDirect`。 |
| `DifferentialWriteTransaction` | 目标限于项目目录；目标唯一；比较预览前镜像；写临时文件并验哈希；提交前再次检查；提交后验哈希和可选验证；失败逆序原子恢复 | 只保护采用该事务入口的文件；不自动覆盖其它编辑器或内存写入。 |

保存过原始记录的编辑器必须使用严格比较事务。Python 扳手的 `guarded_compare_exchange_transaction` 即使在 `direct_write` 模式也会比较快照、拒绝重叠、复读新值并在失败时回滚，避免游戏在读取后已修改内存时被静默覆盖。

### 工具整合包的真实门禁

- `ProjectVersionGuardService.EnsureTableCompatibleForWrite()` 和 `EnsureCoreFileCompatibleForWrite()` 当前是空实现，仅保留历史尺寸参考和诊断入口；调用它们不等于写入已被版本护栏阻断。
- `ProjectDetector` 的跨版本回退诊断仍写有“默认阻止写入”，但这是一条诊断字符串，不是所有调用路径都执行的统一强制门禁。实际权限必须沿具体写入服务复核。
- `EffectWriteDecisionService` 分为严格档案路径、沙箱验证路径和 `DirectUnrestricted`。后者仅保留唯一物理位置等最低条件，不能继承严格路径的证据等级。
- `ProjectEffectWriteLock` 提供桌面、Runtime 和 MCP 共用的项目级特效互斥，但只覆盖主动获取该锁并进入相应事务的特效操作，不能宣称锁住所有编辑功能。

### 代理、配置和安装

- 代理 DLL 必须完整保留原 ABI：导出名称、序号、位数、调用约定和参数语义必须一致；原始实现应是唯一转发目标，不能以空桩掩盖缺失接口。
- 配置升级应保留未知字段和未知行。非法数值只能回退到明确的兼容默认值，不能顺手重写未理解的配置。
- 安装器必须验证目标和内嵌载荷、备份原文件、记录哈希和元数据、使用暂存文件提交，并为每个已改目标准备回滚。
- 卸载前必须确认当前文件仍是本安装清单记录的载荷；发现外部修改、备份缺失或哈希不符时应停止，不能静默覆盖用户的新文件。

## 实现/使用方法

### AI 采用源码结论检查表

1. 明确源码目录、文件、提交或 SHA256，并确认没有误读构建产物、旧副本或半成品迁移试验。
2. 区分“源码可见”“单元测试覆盖”“目标样本静态复核”“目标样本运行时验证”和“用户可见行为验收”。
3. 建立目标版本与作品身份，禁止从同名能力推导相同地址、表宽或资源编号。
4. 对地址记录签名、命中数、指令边界、节区、CALL 目标、原字节和加载基址换算。
5. 对表记录地址解析方式、指针来源、容量、步长、字段宽度、空值语义和动态指针复核时机。
6. 明确写入模式及其真实保证；兼容直写和 `DirectUnrestricted` 一律在报告中降级标注。
7. 制定预览、旧值比较、复读、回滚、外部修改拒绝、污染状态处理和卸载恢复方案。
8. 只有同一身份的静态与运行时证据齐全后，才把能力逐级提升到 `Enabled`。

## 风险与边界

- 固定地址可以作为已知样本的回归 Oracle，但不能替代语义解析，也不能跨 6.5、6.5pl、6.6 或 6.6x 作品直接复用。
- `VirtualProtectEx` 成功不代表写入事务成功；短写、复读失败、指令缓存未刷新和保护恢复失败都必须单独处理。
- “有备份”不等于“可回滚”。备份必须绑定写前 SHA，回滚后还需复读或哈希验证。
- 测试夹具、模拟后端和静态样本无法覆盖消息泵、资源加载、线程竞争、游戏状态切换和长期运行稳定性。
- 本页不授权上传 Python、C++、C# 原始源码或二进制；公开仓库只保存提炼结论和来源哈希。
