# 6.4 精确样本知识

本目录的配置与活动表知识绑定洗隋 `Ekd5.exe`、SHA256 `91121D4B5F7FBB987475943A590B76308C0DDB8B6BCD17C218EEDC6568CE2AD8`，对应 `profile.ccz64.xisui.9112`、`ccz-6.4/64-xisui-v1`。证据包括样本字节、完整消费者静态复核、data 管理器源码与历史副本回归，不表示本次运行了游戏或重新执行了管理器专项。36D8 画像只用于扫描性能身份，不继承洗隋地址或布局。

机器事实源为 `data/`，人类阅读页为生成的 `reference/`。该样本活动表为180行、每行8字节，包含三个人物槽、一个兵种槽和整行共享N；其它6.4构建须独立定位。不能套用6.5的255行、6.6的两个兵种槽，或把个人selector255视为通用安全禁用值。

字段布局及其物理可写能力、玩法含义和工具是否已实现操作分别记录。写回仍须核对当前指针、行数、原字节、宽度、共享影响及事务回滚。

## 查询与再提取

人工阅读生成的 `reference/`；机器查询 `index.json` 后按 `structuredDataPath` 打开 JSON。重提取在来源源码工作区提供文件的前提下执行：

```text
python tools/import_data_manager_facts.py --workspace <SOURCE_WORKSPACE> --versions 6.4
python tools/query_kb.py "0x00508998" --version 6.4
python tools/query_kb.py "180×16" --version 6.4
```

导入器默认保留既有审阅 ID，只增加新 ID；显式 `--refresh-existing` 才替换生成实体，使用前必须审查差异。6.5/6.6 原命令默认版本保持不变，导入6.4须显式选择。

`data/tests/` 记录 `--ccz64-compatibility`、`--ccz64-configuration`、`--ccz64-field-writeback` 三个测试契约；`data/workflows/` 记录配置修改、历史恢复与跨版本逻辑字段迁移。2026-10-23 最终历史报告为40张加载表、720个字段首末边界通过和18项明确未测/不适用；早版39表/660项不能混入该口径。覆盖不代表所有中间行、取值或游戏内行为已穷举。

CSV/XLSX 与保存历史保留6.4独立 Profile、Variant 和 LayoutRevision。跨版本使用 TableKey/ID/逻辑字段与目标 Codec 迁移；跨 Profile 直接回导、未知旧修订、将旧保留列解释为新装备字段均应拒绝。来源和历史结果按 `sourceRefs` 对应到 `sources/source-manifest.json` 的可用性及哈希契约。
