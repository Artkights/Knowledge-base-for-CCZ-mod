## 消耗品标签

用户原文列出：

> 消耗品特效 0x28：恢复SP 0x2A HP上升 0x28：MP上升 2C-30/35-39：对应道具号（即2C显示2C道具号，30显示30道具号，以此类推）， 0x31：单挑 0x32：学会策略 0x33：使用策略 0x34：附加技能 0x3A：任务物品 0x3B：合成材料 0x3C：工具物品

可直接归于用户确认的对应关系：

| 编号 | 标签 | 证据边界 |
|---|---|---|
| `0x28` | 恢复SP | 用户标签；同一请求重复使用该编号，冲突处理见下文 |
| `0x2A` | HP上升 | 用户标签 |
| `0x2C–0x30` | 各自的十六进制道具号，例如“2C道具号”“30道具号” | 只确认目录显示方式，不推导实际游戏操作 |
| `0x31` | 单挑 | 用户标签 |
| `0x32` | 学会策略 | 用户标签 |
| `0x33` | 使用策略 | 用户标签 |
| `0x34` | 附加技能 | 用户标签 |
| `0x35–0x39` | 各自的十六进制道具号，例如“35道具号”“39道具号” | 只确认目录显示方式，不推导实际游戏操作 |
| `0x3A` | 任务物品 | 用户标签 |
| `0x3B` | 合成材料 | 用户标签 |
| `0x3C` | 工具物品 | 用户标签 |

`0x28` 在原请求中同时对应“恢复SP”和“MP上升”，不能把二者同时当作无冲突的事实。编辑器实施时结合已有 `0x2B` 仙酒样本线索和连续编号，将“MP上升”归于 `0x2B`，保留 `0x28=恢复SP`。**`0x2B=MP上升` 属于有样本线索支持的推定，不是用户明确给出了 `0x2B`。** 本来源保留冲突原文；补充来源、目录代码或将来的运行时结果应分别登记，不能改写原文为无歧义确认。

用户没有在本轮提供 `0x1A–0x27`、`0x29`、`0x3D` 的新映射；这些编号的目录应引用既有目录源码及其样本/固定名称表线索。
