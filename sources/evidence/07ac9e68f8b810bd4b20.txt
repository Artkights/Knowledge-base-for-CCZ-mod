# 图片导入兼容规则

适用于静态图片自适应导入版。Data 管理器内嵌形象设定和独立形象管理器共用同一素材准备、转换预览及写入流程。

## 使用流程

新增或替换图片时，进入统一窗口：选择素材或目录 → 核对映射 → 准备转换并预览 → 确认写入。

- 除 R/S 动作条和 Meff/Mcall 大小动画包外，静态素材支持 BMP、PNG、JPG、JPEG、GIF、TIF、TIFF、ICO、WebP，按实际内容解码；接受任意尺寸，无需自行转换目标画布、色深或调色板。
- “任意尺寸”指不要求素材预先符合目标规格；素材须能正常解码，单幅上限为6400万像素。未知资源结构仍显示具体原因，不猜测游戏编码。
- GIF、TIFF、ICO、WebP 只取首帧、首页面或首目录项作为静态图片，详情注明来源格式与帧选择；这不等于导入大小动画，也不会生成动画播放记录。
- R/S 素材仍限 BMP、PNG、JPG、JPEG，并保持原生尺寸与帧数。Meff、Mcall 使用经过结构校验的完整动画包入口。
- 单槽“选择”允许任意文件名；也可粘贴路径、拖入素材、从目录自动识别。
- R 分正面和背面；S 分移动、攻击、特技；图标分大图和可选小图；Face0 单列八个表情槽。每个槽都明确绑定目标。
- R/S 目录支持已知动作名和 R 别名 front/back、x/y、1/2；同名候选冲突时由用户选择。Face0 表情角色由用户手动指定，避免同一默认文件自动覆盖八个表情。
- 未识别名字留在待分配列表。主动点击按序分配时才按可见列表顺序映射，不静默依赖文件选择顺序。
- “同一图片应用到所选槽”是显式复用；每个最终物理图号和动作仍分别列出。
- 新增可增加素材组并上移/下移，转换预览显示实际新增编号。
- 准备阶段仅在内存及临时候选中工作，不写项目或历史。错误行修正或排除后须重新准备；整批通过才可提交。
- 预览显示来源、当前资源和实际编码后的结果。RAW显示量化后的效果，不能只看原素材。

## 图片规格与存储

| 类别 | 素材与处理 | 输出 |
|---|---|---|
| 普通E5标准图片 | 任意尺寸，最近邻拉伸填满所选目标画布；新增采用末尾已确认条目模板 | BMP保留原位深、索引调色板、行序与合法尾部；PNG仍PNG，JPG仍JPG |
| 已确认普通RAW图片 | 任意尺寸，转换到已知目标画布，例如Logo 48×48、Range 64×64 | 按项目调色板量化，保留已确认的零字节/两字节尾部；未知RAW拒绝 |
| R正面、背面 | 各48×1280，20个48×64帧；不缩放或补帧 | 文件新增/替换均PNG32 |
| S移动mov | 48×528，11个48×48帧 | 替换按原RAW/BMP/PNG；新增PNG32 |
| S攻击atk | 64×768，12个64×64帧 | 同上 |
| S特技spc | 48×240，5个48×48帧 | 同上 |
| 标准Face | 任意尺寸，中心正方裁切，高质量双三次120×120 | PNG32 |
| 已确认旧版Face | 按实际头像长宽比居中裁切 | 保留该格式要求及合法尾部 |
| Face0八表情 | 逐个指定表情0～7，各自按Face/Tou目标规格中心裁切 | 只写已分配并勾选的表情及对应Tou项 |
| E5成对图标 | 裁有效区、等比最近邻居中，精确画布保留留白 | 大小图BMP24，透明写#F700FF |
| DLL图标/Tou | 按各目标实际规格转换 | 保留目标8/24/32位DIB布局、语言及ID |
| DLL独立位图 | 任意尺寸，最近邻填满各语言变体的实际画布 | 保留各目标DIB位深、调色板、行序、合法尾部与语言；原生ID独立 |
| Weather已验证条目 | 任意尺寸，转换至216×200；从上到下四个216×50帧 | 已确认43200字节RAW8，按项目调色板量化；支持新增和替换 |
| Pmap已验证条目 | 任意尺寸，转换至原模板画布 | 保留16字节专用头，后续RAW8按项目调色板量化；支持新增和替换 |
| 战场地图底图 | 任意尺寸，转换至当前地图底图画布 | JPG24；Hexzmap地形层保持，固定地图槽仅替换 |

普通 E5 新增取末尾已确认条目模板；DLL 独立位图新增取最小数字 ID 的全部语言变体为模板，新 ID 为现存最大 ID 加 1。替换以所选目标的实际规格为准，来源尺寸和来源文件编码不会成为新规格。空档案、未知头部/尾部或无法可靠确认的模板会阻止转换。

Face0 的八个表情槽中，仅表情0默认勾选；给其他表情选图后自动勾选该槽。替换准备仅包含实际提供素材且勾选的表情，可一次修改一个或多个表情；八表情固定结构不扩充或删除。未提供素材的表情保持。

替换已有 S 时，RAW仍使用有效项目调色板，完整条重新量化并保留合法两字节尾部；BMP输出32位BMP，避免旧BMP色表限制新素材；PNG输出32位PNG。JPG可作素材，但不会写成Unit的JPG存储。

外部素材新增R须完整正背组，目标总条目数须为偶数。新增S须完整mov/atk/spc组，三个档案须等长且至少已有240个兵种槽。S每组只追加一个物理图号，新号为原数量+1，三包同步。人物紧凑S及其他游戏引用需另行指定。

替换允许只分配需要修改的R方向或S动作。选中S_242且只分配atk时，仅改Unit_atk的242；其余动作和相邻图号不改。兵种固定槽通过替换维护。

S目录的“物理编号/旧编号”模式需要明确选择。物理S_242就是242；旧版逐图将领S002对应242，旧兵种S001对应2；均不解释成人物紧凑S。旧多转目录不自动展开到相邻物理号。

## 透明与图标

普通E5/DLL图片和头像不自动去除洋红、蓝色背景。PNG32与支持的32位DIB保留Alpha，其他目标按原编码能力处理半透明。R/S真彩分支接受完全透明或近洋红：R≥247、G≤8、B≥248；RAW洋红阈值为R≥248、G≤8、B≥248，写透明索引0，其余颜色按RGB最近色量化，无抖动。RAW不能保留半透明，预览需检查颜色变化。

普通RAW及调色板BMP的文件导入优先把完全透明像素写为索引0，其他像素按原始RGB精确匹配或最近色量化，不复用旧图片的索引。非零半透明按RGB实色处理；普通24/32位BI_RGB BMP的完全透明像素写洋红键色，第四个保留字节与行布局仍按目标保留。PNG保留原始Alpha与RGB。上述文件转换与像素编辑的“保留未改索引”算法分开，避免全透明黑色误保留旧黑色索引及半透明RGB重绘舍入。

图标采用整合包宽容洋红识别：R/B≥210、G≤90、两者差≤70；DLL额外识别纯蓝。来源已等于目标大图尺寸时不裁掉留白；其它尺寸裁可见包围框并等比居中。全透明图可正常导入。

未显式给小图时，从归一后的完整大图派生。E5使用最近邻；DLL两倍尺寸对按右下、右上、左下、左上选择2×2中的首个非透明像素。显式给小图时分别处理，不重新派生覆盖。E5 BMP24不保留半透明；DLL按实际目标位深处理。

## 专用静态资源

Weather 的已验证43200字节条目开放末尾新增与原位替换，任意尺寸素材转换为216×200整条并按项目调色板量化。固定四帧结构保持，禁止删除或重命名编号。Pmap 已验证模板同样开放新增与替换，匹配目标画布与调色板，逐字节保留16字节专用头；禁止删除/重命名编号，Pmap像素编辑暂不可用。

地图普通“替换图片”只修改JPG底图，在统一窗口转换和预览，Hexzmap地形层作为校验依赖保持。地图固定槽没有普通新增入口。“导入地图与地形”保留目录成对导入：`Mxxx.BMP` 固定为专用地形网格，必须保持原网格数与载荷结构；底图可用同名JPG、PNG等其他静态格式。底图本身为BMP时使用`Mxxx_image.bmp`，避免与地形BMP混淆；多个底图候选会拒绝自动选择，底图转换不会从颜色猜测地形。

## 一致性与历史

来源、目标、相关调色板的SHA256绑定到候选计划。预览后更换素材或映射会取消旧任务并释放预览；外部改动任何依赖后提交拒绝，须重准备。最终提交直接使用已预览候选，不再次转换。

多文件一次事务写入，失败回滚；已保存操作可历史撤回/重做。成功后更新图库及人物/兵种相关预览。

像素编辑继续按原编码重建，保留未改索引、尾部和尺寸；其小图卷积派生、复制追加及参考总图协议不因文件导入而改变。已确认RAW、Weather、Pmap和地图底图在统一窗口调用各自编码器；Meff/Mcall动画仍使用完整动画包入口与播放结构校验，未确认结构不会作为普通图片覆盖。

Face/Tou继续联动，从同一原始素材分别生成各尺寸/语言变体，不先缩小Face再放大Tou；Tou缺失时明确提示只写Face，Tou存在但编码失败时整批阻断。Face0文件替换仅写入所指定表情及对应Tou项，其他表情保持。
