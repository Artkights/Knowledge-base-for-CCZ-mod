# 资源事务写回与验收

本轮覆盖 data 管理器所复用的 `形象管理器/src/ImageManager.Core`、链接到 data 管理器的资源页面，以及资源历史适配器。资源操作完成后立即写入磁盘；它们有独立历史，不属于顶部“保存”按钮所管理的数据草稿。

## 已实现的写回保证

- `MutationFile.ExpectedSource` 保存计划生成时的源文件存在性、长度和 SHA-256。普通替换、追加、删除、整文件替换、图标、Face/Tou、R/S、人物指定和地图配对的计划构建均在读取前抓取源状态，构建完毕复核，提交前及暂存结束后再次核对。候选生成后的外部修改、删除和新建路径冲突会拒绝写回。
- 修改构建器使用 `E5Archive.OpenFresh` 重新读取文件，不以预览缓存的长度/修改时间相同作为内容相同的依据。像素编辑及 AI 预览打开前还会保存源状态，避免预览期间的外部修改被旧画面覆盖。
- 先完成全部写前/写后快照、临时文件和候选结构校验，再逐文件替换；写后检查存在性、长度、SHA-256，并重新读取容器。原有只读等文件属性在写回及恢复后保留。
- 历史持久化属于同一个事务。`history.jsonl` 先完整写入临时文件并刷新，再原子替换；写历史失败时资源文件恢复到写前状态，不产生活动历史。
- 撤回和前进会先校验当前状态以及两个方向的快照，再恢复文件；状态改变与撤回/前进记录一次性写入历史。历史无法持久化时，文件恢复到操作前的状态。
- 恢复按文件继续执行，单个锁定文件不会阻止其余文件恢复。恢复后核对长度与 SHA；失败结果逐项列出路径，并保留快照位置。成功恢复时清理临时文件。
- 普通 E5 新增不再直接接收任意非空字节。BMP/PNG/JPG 必须具有可验证的图片边界，并能完整解码和读取像素；专用载荷应使用专用入口。普通新增保留素材原始尺寸与编码，没有凭空设置统一尺寸。

## 批量改名

文件及目录改名保留现有入口。所有待改名项先移入所选目录树以外、同一卷上的暂存目录，再按父目录先于子项的顺序安装到最终位置。嵌套父目录改名会递归计算最终路径，预检表显示实际最终路径。

预览会保存文件内容指纹及目录内的路径/内容指纹；执行、撤回和前进前检查指纹，遇到外部内容变化或目标冲突时拒绝覆盖。内部历史目录不参与批量改名。目录指纹不跟随重解析点。

新历史记录保存完整文件/目录源路径、目标路径及两个方向的内容指纹；data 管理器统一历史中可真实撤回、前进。历史持久化失败时，已安装项先移回暂存区，再恢复原目录及文件，逐项校验。未能恢复的项会报告暂存路径，不会删除含恢复文件的暂存目录。

旧版只有 `RenameMap` 元数据、没有文件快照或完整改名目标的记录仍不具备可靠恢复能力，不能将其伪装成已撤回成功。

## 现有资源页动态提示

资源页新增持续显示的限制区域，随资源类别、S 将领/兵种模式及选择项更新；写操作按钮与像素编辑按钮明确提示立即保存。

| 类别 | 已显示并遵守的规则 |
| --- | --- |
| Mcall | 实际编号 0～154；显示下一编号及还可追加数量，容量耗尽禁用新增；多选超过余量拒绝提交。 |
| 兵种 S | 固定 0～239 槽；导入替换当前槽，删除清空槽，不改变后续编号。 |
| 将领 S | mov 48×528（11 帧）、atk 64×768（12 帧）、spc 48×240（5 帧）；三文件同步。 |
| R | front/back 两条 48×1280，各 20 帧；使用目标调色板。 |
| Weather | 固定 4 帧，单帧 216×50，完整条 216×200；禁止追加、删除及改名。 |
| 地图 | 固定地图槽；JPG/地形 BMP 成对；目标地图尺寸一致且能被 48 整除，地形网格匹配。 |
| Face/Tou | 按目标模板编码；Tou 存在时同步写入，缺失时明确显示仅写 Face。 |
| Item/Mtem/DLL 图标 | 选择目标尺寸大图，自动派生半尺寸小图；配对写入，保留末尾孤立条目。 |
| Cmdicon.dll | 独立原生RT_BITMAP ID，逐项显示实际尺寸；允许稀疏编号。追加使用新ID并保留来源尺寸，删除只移除选中ID的语言变体，不重排其他ID。 |
| 其他普通 E5 | 替换按目标尺寸/编码校验；新增验证实际载荷并扩容，保留素材尺寸。 |

选择目标后显示选择项数量、首项帧数及描述符中已确认的单帧尺寸。未知尺寸不显示猜测数值，而提示保存前按目标图片校验。

## 验证

新增 `ImageManager.Tests/ResourceTransactionTests.cs`，可单独运行：

```powershell
dotnet run --project '形象管理器/src/ImageManager.Tests/ImageManager.Tests.csproj' --configuration Release -- --resource-transactions
```

覆盖以下实际故障与恢复行为：

1. 候选生成后的外部改动、新建目标路径冲突均拒绝覆盖，历史不新增。
2. 长度和时间戳保持不变的 E5 外部修改不会复用过期预览缓存构建候选。
3. 截断 PNG 无法作为普通 E5 新增载荷，目标保持原字节。
4. 历史文件被锁时，双文件资源保存失败恢复；只读属性保留。
5. 历史文件被锁时，撤回和前进失败恢复操作前字节，历史原字节保持。
6. 首个文件恢复被锁时仍继续恢复其余文件，并汇总准确失败路径。
7. 嵌套目录、文件与空目录的改名保存、撤回、前进；写历史失败及改名撤回/前进历史失败均恢复路径。
8. 目录改名后内容被外部修改，撤回拒绝覆盖外部内容。

共享形象管理器完整回归入口：

```powershell
dotnet run --project '形象管理器/src/ImageManager.Tests/ImageManager.Tests.csproj' --configuration Release
```

前一轮控制台显示33个PASS标签，后续独立核对发现其中2项依赖已不存在的外部剪贴板PNG，原测试直接return，不能作为实际执行证据。本版已改为明确SKIP，原日志保留作为历史记录；确定性S三包参考图导入另在资源实际落盘矩阵中验证。最终回归统计、矩阵次数和原始日志以“完整写回与动态约束验收”及 `验证/写回完善` 中的最终记录为准。

Cmdicon专项还发现并修复了真实格式问题：6.5样本含41个不同尺寸的稀疏RT_BITMAP ID，原读取器误用大小图配对，在ID缺口处结束枚举。现在按全部原生ID枚举；实际提交测试检查ID21、108可解码，新增ID保留33×17来源尺寸，删除ID21后其他ID与所有语言变体DIB保持原字节。Itemicon和Mgcicon继续使用已确认的大小图配对规则。

资源布局检查包括WinForms离屏和字体放大测试，不将其表述为真实系统高DPI、多显示器切换验收。

最终共享完整回归为32组通过、0失败、2项明确SKIP；包括57次真实资源事务与Meff六项非法载荷阻断。最新逐行日志见 `../验证/写回完善/资源最终完整回归日志.txt`。Meff直接追加/替换服务、提交候选和磁盘复读均执行专用包Probe和实际Decode；普通PNG、越界播放记录在规划或伪造候选提交时被拒绝，文件与历史保持不变。旧的33个PASS标签不能与这个统计相加。

## 迁移资源候选验证补充

新增 `ImageMigrationResourceConverter.ValidateFile`，在完整临时迁移项目构建后与真实目标安装后各执行一次。前者失败时目标未修改；后者失败时由迁移协调器恢复整批目标。验证器读取未选中的目标配对依赖时，同一次文件快照计算并返回 SHA-256，协调器在提交前复核。

| 类别 | 已实现的候选验证 |
|---|---|
| 已知图像 E5 | 目录、每条解压后长度；标准 BMP/PNG/JPEG 边界、实际解码、像素读回。未确认的 RAW 仅报告结构范围。 |
| R、S | 各类已确认动作条的实际尺寸，或严格 RAW8 长度（允许现有两字节尾部）；逐条检查。 |
| Face、Pmap、Weather | 现有头像尺寸规则、Pmap 16 字节头与像素长度、天气 43200 字节四帧。 |
| Mcall、DT | 复用专用记录/平面/播放引用编解码器，实际解析所有平面。RAW8 使用内置 256 色调色板做结构解码，不将颜色选择表述为游戏内视觉验证。 |
| Map、Hexzmap | JPG/PNG/BMP 实际图像尺寸、48 像素网格、地图对应地形图号及两字节前缀后的精确网格长度；优先临时候选依赖，其次读取并记录目标依赖哈希。 |
| 已知图片 DLL | 资源模式加载，严格枚举数值 RT_BITMAP 及语言变体并实际解码；命名位图、损坏头部和无法枚举的目录拒绝猜测。普通 UI 历史调用保持默认读取模式。 |
| 未确认类别 | 明确返回“验证边界”，不宣称已验证格式，也不将所有 `.e5` 一概当作通用图片容器解析。 |

专项命令：

```powershell
dotnet run --project 'data管理器/src/DataManager.Tests/DataManager.Tests.csproj' --configuration Release --no-build -- --migration-resource-validation '基底/加强版6.5未加密版'
```

已退出 0，输出 `MIGRATION_RESOURCE_VALIDATION_TESTS_OK`。覆盖损坏 E5 目录、截断 PNG、R/S/Face/Weather/Pmap/DT/Mcall 边界、地图和地形的双向配对、fallback 同快照依赖哈希、临时依赖优先、无效 DLL、真实 6.5 DLL 和取消。协调器候选阶段验证失败、实际安装后验证失败的整批恢复、未知类别验证边界提示也已在同一专项入口回归通过。编译为 Release，0 警告、0 错误。

## 范围与仍需区分的限制

- 资源容器追加/删除会重建目录并改变文件长度；不能套用 Data/EXE 普通定长字段“整文件长度不变”的规则。现有条目压缩数据和专用尾部的保留仍由对应编解码器负责。
- PNG/JPG 不能一概判为游戏不支持；基底通用解码函数存在 BMP、PNG、JPEG 分支。本轮验证普通载荷实际可解码；没有将通用解码能力扩大为每一个专用资源类别的游戏内验证。
- 新资源不会自动修改 Data、策略、物品、脚本等引用。普通物理删除也不会自动重映射后续 ID；固定槽继续使用原位规则。除已确认的 Mcall 与兵种 S 等限制外，没有臆造所有资源通用的条目上限。
- 本轮覆盖可捕获的写入/校验/历史失败恢复。没有新增操作系统崩溃或断电后自动重放的恢复日志；不能将逐文件原子替换表述为文件系统级多文件原子提交。
- 测试在临时副本及只读真实样本上运行，没有对用户游戏目录执行图片替换或改名；仍需用户在游戏中确认具体自定义素材的视觉与引用表现。
