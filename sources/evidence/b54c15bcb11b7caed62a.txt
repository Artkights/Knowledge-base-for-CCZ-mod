# 策略与宝物

## 结论速览

策略与宝物业务页编辑文本、数值、标记和表间关系，同时显示资源编号与关联预览。策略可以预览图标、大小动画，宝物可以预览图标；资源本身的新增、替换、删除在形象设定页完成。`Preserve` 资源字节只读展示，数据保存仍保留未修改字节。

## 适用版本

6.5、6.6 标准布局、6.6 厚黑兼容布局和旧山贼登记布局。

## 已确认事实

### 本轮物品语义与扩展表补充

物品的物理行仍为 25 字节。普通武器/防具的 `row+0x15/+0x16/+0x17` 分别是初始能力、效果值、成长值；辅助装备的 `row+0x15` 是辅助特效值，`row+0x16` 为空/保留，`row+0x17` 是适用兵种（`255` 表示所有兵种，`0..39` 表示单个兵种系）；消耗品的 `row+0x15/+0x16` 合并为小端 16 位效果参数，`row+0x17` 不使用。`row+0x18` 为图鉴，业务页使用勾选框编辑。`row+0x13` 始终为价格（/100），提示“255表示不可买卖”。

2026-10-20 起，宝物设置开放读写：辅助特效值绑定原物理字段“初始能力”（`+0x15`），适用兵种下拉绑定原物理字段“能力成长”（`+0x17`），不使用普通装备的 `+0x16` 作为辅助特效值。辅助和消耗品的空/保留字节不伪装成能力或成长；需要查看和修改时在原始字段页编辑，未修改字节原样保留。图鉴、适用兵种及参数都进入统一草稿、保存和 CSV 读写链路，物理列名继续保留以兼容已有 CSV。

山贼国庆 6.6 的五个原始行复核如下。五条价格字节 `+0x13` 均为 `255`，图鉴 `+0x18` 均为 `1`，因此 `+0x17` 不能解释为价格。

| 宝物 | `+0x15` 特效值 | `+0x17` 适用兵种 |
| --- | --- | --- |
| 天毒珠 | 1 | 6：侠客 |
| 太平要术 | 5 | 0：君主 |
| 天毒珠（仿） | 60 | 6：侠客 |
| 左氏春秋 | 22 | 255：所有兵种 |
| 凌风赤兔 | 7 | 27：上将 |

消耗品特效号使用独立的 `0x1A–0x3D` 命名空间，不套用装备特效名称。`0x1A–0x27` 保留 HP/MP 恢复、状态治疗、五维提升、经验和进阶等既有映射，`0x29` 为功勋、`0x3D` 为装备升级。2026-10-20 按用户确认补齐：

| 特效号 | 显示名称 |
| --- | --- |
| `0x28` | 恢复SP |
| `0x2A` | HP上升 |
| `0x2B` | MP上升 |
| `0x2C–0x30`、`0x35–0x39` | 各自十六进制道具号，如 `2C道具号`、`30道具号` |
| `0x31` | 单挑 |
| `0x32` | 学会策略 |
| `0x33` | 使用策略 |
| `0x34` | 附加技能 |
| `0x3A` | 任务物品 |
| `0x3B` | 合成材料 |
| `0x3C` | 工具物品 |

原请求将 `0x28` 重复写为恢复 SP 和 MP 上升；按连续编号与仙酒样本，将 MP 上升登记为 `0x2B`。上述新增目录来源记录为用户确认，不冒充新发现的 EXE 消费者证据；目录外编号仍保留数字和“未确认”。

普通布局的物品 ID 为 `0–103`（`Data.e5`）、`104–254`（`Star.e5`），`255` 是空槽/保留。扩展有两种已验证来源：十八州型使用根目录 `Item.e5`（256×25）和 `Itemmsg.e5`（256×200）；烈焰型的 `Star.e5` 为408×25字节，覆盖104–511，其中255是实际“天工开物”、256–511位于`Star.e5+3800`，说明位于`Imsg.e5+440400`、每行200字节。烈焰型采用本项目高段6.6 codec（15字节名称），不能套根Item的17字节名称格式。启用Star扩展须验证EXE的10200字节加载、目的基址、512条初始化与ID×25索引消费链；说明另验完整ID+1946后乘200的IMSG消费链。`E5/Item.e5`仍是图标档案，不作为扩展数据读取。

策略主表为 144 行、97 字节，包含 11 字节名称、五个基础数值、一个保留图标字节和 80 个详细兵种学习等级。伤害类型、伤害系数、命中率、效果索引、扩展标记与两类 AI 限制位于 EXE 独立附表。效果索引的八分类位与主表的 80 个学习等级分开编辑；扩展标记的未确认保留位仍显示数值位。

大小动画分别读取 EXE 中 144 个单字节编号。小动画按字段值 +1 选择 `Meff.e5` 条目；大动画按字段值 −100 选择 `Mcall` 文件，255 表示无动画。6.5 的施展地形是 30 项全局火/水/风/地类型掩码，不按策略 ID 存储；6.6 缺少布局证据时不开放猜测地址。

宝物由低段 0..103 和高段 104..254 的物理表组合展示。物品分类结合当前 codec 的原始类别标记、当前草稿与项目 `System.ini` 的 `DefID/AssID` 边界判断，缺少有效边界时使用 70/109。装备类型与可装备部队单独显示子页；普通武器/防具类型码直接对应 26 类兵种许可槽，例如类型 2 对应普通枪、类型 20 对应普通铠甲，不按十位数分组。辅助、道具及没有对应装备列的类型不套用这份许可。

6.6 标准 codec 的辅助/道具行把逻辑类型 2/3 显示为“辅助装备/道具”，实际特效号在 `row+0x11`。6.5 与 17 字节兼容 codec 保留固定字段写入：辅助段 `row+0x11` 显示为“实际特效号（类型字节）”，`row+0x12` 显示为“类别标记（特效字节）”；不会将类别 2/3 当成枪类或特效名。实际特效下拉使用专用名称池服务显示 `ID：名称`，物理 CSV 仍保留原字段名与原始写入语义。

跨版本迁移使用 `ItemMigrationMapper` 转换已确认的辅助/道具逻辑字段，按目标 Codec 保留实际效果与类别标记。两侧类别无法确认，或普通装备与辅助/道具之间需要转换时，整行列为不可映射，避免部分字段误写。

## 实现与使用方法

修改策略或宝物后，保存链路只对主动修改的字段生成 codec patch。业务页 CSV 按底层物理表分别导出，并覆盖学习等级或共享装备许可等关联表；派生显示列不导出。宝物已开放的图鉴、适用兵种、参数及原始字段可以通过对应物理列交换；其他表明确标为只读的字段仍仅允许原值回导。物理表入口仍可单独交换当前表。

## 风险与边界

6.6 的类型码 2 与类别标记 2 位于不同语义路径，不能仅按数值相同处理。普通装备的特效号若会把原始标记变为 2/3，首版直接拒绝，避免隐式格式转换。

## 证据来源

6.5/6.6 物品 codec、策略隐藏字节保持测试、装备矩阵派生实现和 CSV 测试。

## 待验证项

未确认语义的策略扩展位标为保留位；未知类型与范围保留原始数字和需实测提示，不赋予未经确认的业务含义。
