## 实现/使用方法

- 可重跑：`工具整合包/静态分析/run-static-analysis.ps1 -GameRoot <目录> -ExeSha256 6929FE0DB049935EEC793CE785D431947E48BED406ED94233F9B3A9C6DB4BCB8 -IncludeLocalDlls -OutputRoot <目录> -Resume`。
- 使用 `query_evidence.py` 查函数、指令和引用，使用 `review_catalog.py` 生成审阅索引。结果按模块 SHA＋RVA 识别。
- 重要审阅顺序：寻址 `004061E4/004061F9`；特效 `004198BE/004101D9/0041301E/0042518F`；范围 `00436511/00436611/00437AFF`；战斗 `0043DADA/00410F1C`。
- 写入前必须验证目标 SHA、PE 节映射、原字节和代码洞；静态候选不得直接生成运行时 Hook。

## 风险与边界

- Ghidra 函数数量是候选；间接调用、孤立代码、代码/数据混排和非标准寄存器函数仍需人工审阅。
- `004061E4`、`004061F9`、`0041B782`、`0041B7D2`、`004837C2`、`00484002` 的空伪代码不能覆盖其汇编中的 `ECX` 指针计算。
- `00420299` 扣减路径只执行 `DEC byte ptr [EAX]`；`CL` 只是允许扣减条件，不是扣减数量。
- `004F0008` 是运行时函数指针槽，不是普通静态特效字段。

## 2026-09-09 装备分类映射表 0x5C4F 核对

本节只适用于本页登记的 `复刻版6.6山贼/Ekd5.exe`（SHA256 `6929FE0DB049935EEC793CE785D431947E48BED406ED94233F9B3A9C6DB4BCB8`）。结论来自原始字节、PE 节映射、静态反汇编、交叉引用和 `Data.e5` 物品样本；动态调试接口本轮返回通用错误，尚未完成实机矩阵。

### 地址身份和作用

`.code` 段原始文件偏移为 `0x400`，RVA 起点为 `0x1000`，因此：

```text
文件偏移 0x5C4F  <=>  运行时 VA 0x0040684F
```

`0x5C4F` 处连续 13 字节为：

```text
0A 00 00 00 00 00 00 02 02 00 01 01 01
```

从文件偏移 `0x5C5C`（VA `0040685C`）开始是下一函数的 `55 8B EC` 序言，所以 `0x5C4F` 是数据表首字节，不是可直接写入“增加数值”的指令地址。

### 汇编调用链

函数 `004067CE` 接收物品 ID，调用 `004837C2` 计算物品记录地址，再由 `0043AD20` 读取 `item_record + 0x11` 的原始类型字段。`004837C2` 的关系为：

```text
ItemRecord = 0x0049F820 + item_id * 0x19
```

当原始类型小于 `0x1A` 时，`004067CE` 执行 `raw_type >> 1`，再读取 `[0x0040684F + index]`；`0x20`～`0x28`、`0xFE` 有单独分支，其他值返回 `0xFF`。等价逻辑为：

```c
uint8_t classify_item(uint8_t raw_type)
{
    if (raw_type == 0x5C) return 0x09;
    if (raw_type < 0x1A) return table[raw_type >> 1];
    switch (raw_type) {
    case 0x20: return 0x00;
    case 0x21: return 0x01;
    case 0x22: return 0x02;
    case 0x23: return 0x03;
    case 0x24: return 0x04;
    case 0x25: return 0x05;
    case 0x26: return 0x06;
    case 0x27: return 0x08;
    case 0x28: return 0x07;
    case 0xFE: return 0x0A;
    default:   return 0xFF;
    }
}
```

装备属性汇总函数 `00407C29` 消费该分类码；五个包装函数分别以能力索引 `0`、`1`、`2`、`3`、`4` 调用它。函数 `00405670` 对分类码 `0x0A` 做特殊处理，使其同时匹配能力索引 `0` 和 `2`，其他分类码按单一索引比较。

### 当前表的完整映射

| 文件偏移 | 原始类型 `item_record+0x11` | 表返回码 | 当前能力解释 |
| ---: | ---: | ---: | --- |
| `0x5C4F` | `00/01` | `0A` | 攻击 + 精神 |
| `0x5C50` | `02/03` | `00` | 攻击 |
| `0x5C51` | `04/05` | `00` | 攻击 |
| `0x5C52` | `06/07` | `00` | 攻击 |
| `0x5C53` | `08/09` | `00` | 攻击 |
| `0x5C54` | `0A/0B` | `00` | 攻击 |
| `0x5C55` | `0C/0D` | `00` | 攻击 |
| `0x5C56` | `0E/0F` | `02` | 精神 |
| `0x5C57` | `10/11` | `02` | 精神 |
| `0x5C58` | `12/13` | `00` | 攻击 |
| `0x5C59` | `14/15` | `01` | 防御 |
| `0x5C5A` | `16/17` | `01` | 防御 |
| `0x5C5B` | `18/19` | `01` | 防御 |

因此本样本的五维索引顺序是：`00=攻击（武力）`、`01=防御（统率）`、`02=精神（智力）`、`03=爆发（敏捷）`、`04=士气（运气）`。用户资料中把 `01` 和 `02` 写反时，应以本节和实际调用链为准。

`Data.e5` 样本交叉验证：铁剑类 `row+0x11=00` 经表得到 `0A`；环首刀类 `02` 得到 `00`；青竹扇类 `0E` 得到 `02`；硬皮甲类 `14` 得到 `01`。这与武器、扇类和防具在装备能力汇总中的归属一致。

### 修改 0x5C4F 为 03 或 04

修改文件偏移 `0x5C4F` 只影响原始类型为 `00/01` 的物品：

| 写入 `0x5C4F` | 这些物品的新分类码 | 数值汇总归属 | 结果 |
| ---: | ---: | --- | --- |
| `03` | `03` | 能力索引 3：爆发/敏捷 | 原来的攻击+精神改为爆发/敏捷单属性 |
| `04` | `04` | 能力索引 4：士气/运气 | 原来的攻击+精神改为士气/运气单属性 |

`03`、`04` 是函数本身已经支持的合法分类码（原始类型 `0x23`、`0x24` 的直接分支），不会自动形成新的双属性组合。若把某条物品记录的 `row+0x11` 直接改成 `03/04`，代码仍会先右移一位并查表；按当前表内容，两者都会落到返回码 `00`，与修改表首字节的效果不同。

装备说明函数 `004086C6` 当前只明确处理分类码 `00`、`02`、`0A` 的标签路径；对 `03/04` 的数值汇总有静态执行路径，但说明文字、图标或标签可能缺失或显示不一致，不能仅凭静态代码保证 UI 正常显示。

本节不适用于把 `row+0x11`、`row+0x12` 在辅助装备/消耗品段一律解释成普通装备分类。该段中 `2/3` 常是类别标记，实际效果候选可能在另一字段，详见[宝物物品设定](../07-数据表与资源/宝物物品设定.md)。
