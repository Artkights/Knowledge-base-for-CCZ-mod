# 战斗公式：三基底公式与常量（2026-10-30）

## 1. 页面与口径

“公式设定”是顶级页，不再属于引擎扫描子页。左侧列出 25 条公式（命中/暴击/连击/伤害/经验/功勋/战场变量），右侧显示计算过程、可改常量与证据；常量在当前基底上可直接修改并写入 `Ekd5.exe`。

- 顶级页标签 `__formulas`，位于“引擎扫描”之后、“扫描诊断”之前。
- 引擎扫描保留 4 个子页：特效管理 / 宝物特效 / 兵种特效 / 常量。
- 公式页常量表列：常量 / 作用 / 6.4 / 6.5 / 6.6 / 新值 / 范围 / 状态。
- 当前基底列头加“（当前）”；“新值”是唯一可编辑列。
- 写入走 `EngineBattleFormulaService.Commit → EngineConstantService.Commit → EngineEffectTransactionService → WorkspaceBinaryTransaction`：整文件备份、等长补丁、写后复读、失败回滚。

人物能力类型按 Profile 顺序固定为：

| 类型 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| 能力 | 武力 | 统帅 | 智力 | 敏捷 | 士气 |

## 2. 命中/闪避

### 2.1 命中率曲线（物理/策略共用）

函数：6.4 `0x0043B50C`，6.5/6.6 `0x0043B53A`。三基底同一套参数。

设攻方能力为 A、守方能力为 D：

- A ≥ 2D：100%
- D ≤ A < 2D：90% + (A−D)×10/D
- D/2 ≤ A < D：60% + (A−D/2)×30/(D/2)
- A < D/2：30% + max(A−D/3, 0)×30/(D/3)

参数：满命中倍率 2（`shl edx,1`，只读）、高段基础 90/系数 10、中段基础 60/系数 30、低段除数 3/基础 30/系数 30、上限 100。6.6 在判定入口 `0x0043B4DE` 用 `cmp eax,19h; jae +5; mov eax,19h` 把最低值钳到 25，主/次两处必须成对写入。

### 2.1b 物理伤害的疾风攻击补正（2026-10-31 复核）

物理伤害函数 6.4/6.5 `0x0043BC62`、6.6 `0x0043BC5A` 在主公式之后进入特效 117（疾风攻击）分支：`0x00413260` 查询特效 117 的值 N，`0x0043F74F` 计算目标“能力值” A——**A 就是目标移动力**（`0x4072BB`，即 6.14 索引 7：兵种行 `+0` + 装备池 + 追赶项，上限 127），再按 `unit+0x1E` 与 `unit+0x1D` 钳制：

```text
A = 0x4072BB(0x4061E4([unit+0]))          // 移动力
if 0x4066E0(unit, 2) != 0（6.6 0x423FE8）：A = 0      // unit+0x1E bit1（束缚/不能移动）
else:
    t = byte[unit+0x1D]
    if t >= 4: A = min(A + 2, 0xFF)         // 0x47FAB5
    elif t == 3: A 不变
    else: A = max(A − 2, 0)                // 0x47FAD0
```

- 6.4/6.5 字节：`0x0043BD7E 2B C2 sub eax,edx`、`0x0043BD80 3C 00 cmp al,0`、`0x0043BD84 F7 D8 neg eax`、`0x0043BD86 6B C0 05 imul eax,eax,5`；仅当 A < N 时追加 `原伤害 × (N−A)×5/100`。
- 6.6 字节：`0x0043BD7E F7 D8 neg eax`、`0x0043BD80 83 C0 0C add eax,0Ch`、`0x0043BD86 0F AF C2 imul eax,edx`；追加 `原伤害 × (12−A)×N/100`，没有 `sub edx`，N 只作倍率、不作门槛。
- 5 与 12 是代码固定项，N 是特效值；逐字节证据与特效分配见 `疾风攻击公式与常量-特效值区分.md`。
- 特效名：内嵌名称池 `0x004CC600+ID×16`（GBK）中，6.5/6.6 的 `0x75` 均为“疾风攻击”；6.5 的 `0xC5` 为“辅助移动力”（`0x004072BB` 在 6.5 额外把该特效值加到能力 7，6.6 的 `0xC5` 名为“无视远程防御”且该处不查询）。

### 2.2 物理命中/闪避

输入是双方敏捷（能力类型 3）。6.4 判定入口 `0x0043B4BA`、命中桩 `0x0043B60B`；6.5/6.6 判定入口 `0x0043B4B6`、命中桩 `0x0043B600`。

6.4/6.5：命中率 ≥85% 时第一次没打中会再判一次，命中率扣 10%，最多判 2 次。

- 阈值 85：6.4 立即数 `0x0043B4FD`、6.5 `0x0043B528`。
- 扣减 10：6.4 `0x0043B503`、6.5 `0x0043B52E`。
- 次数 2：6.4 `0x0043B4E9`、6.5 `0x0043B50A`。

6.6：没有二次补判，改用最低命中率 25 的下限钳制。

命中桩完整顺序（2026-10-31 三基底逐段复核；6.4 `0x0043B60B`、6.5/6.6 `0x0043B600`）：

- 6.4：`[0x500E9A]==2 → 100%` → `0x47EF3D(攻,守)==0 → 0%`（`0x43FF9A(攻)` 查表 `0x4D2138`（类别由 `0x40BF0C` 从 `char+0x2B` 求得）且 `0x41CDDC(守)` 命中选择子 `0x40`）→ `0x4066E0(守,8)!=0 → 100%`（`unit+0x1E` bit3）→ 曲线 `0x43B50C` → `0x4101D9(攻,0x1E,选择子 0x1C,1,1) → 100%` → `0x4101D9(攻,0x1F,0x2F,1,0) → min(hit+值,100)` → `0x4101D9(守,0x20,0x3D,1,0) → max(hit−值,0)` → `0x408EEE`。
- 6.5：`[0x500E9A]==2 → 100%` → `0x43BA9D(守)==0 → 0%`（`0x43BA83`=`0x4101D9(守,0x31,0,0,1)`）→ `0x47EF3D(攻,守)==0 → 0%` → `0x423FE8(守,8)!=0 → 100%`（按 `unit+0x1E` 位掩码）→ 曲线 `0x43B53A` → `0x4101D9(攻,0x1E,0x6B,1,1) → 100%` → `0x4101D9(攻,0x1F,0x35,1,0) → min` → `0x4101D9(守,0x20,0x3D,1,0) → max` → `0x408EEE`。
- 6.6：`[0x500E9B]!=0 → 100%`（演出标志：`0x436DB1` 置 1、`0x436DCC` 置 0）→ `0x43BA9D(守)==0 → 0%` → `0x4E4000(攻,守)!=0 → 100%`（`0x4281AF` 开启时查攻方 `0x42518F(攻,0xE0,0xE0,0,1)`）→ `0x4E4060(攻,守)==0 → 0%`（`0x4281AF` 开启、攻方无选择子 `0xC5`、守方有 `0x40`）→ `0x423FE8(守,2)!=0 → 100%`（bit1）→ 曲线 `0x43B53A` → `0x42518F(攻,0x1E,0x24,1,1) → 100%` → `0x42518F(攻,0x1F,0x65,0,0) → min` → `0x42518F(守,0x20,0x3D,0,0) → max` → `0x408EEE`。

共用尾段 `0x408EEE`（三基底同码）：

```text
delta = 0x408DB1(攻,守,hit,1)
    if [0x505F88] != 0（文件初值 0）：方向档 ∈ {0,1,2} → 百分比 = 档×5 → hit += hit×百分比/100（0x425AD9）
    if 0x406710(守) != 1 且 [0x500E9A]==1 → hit += hit×5/100
    返回 delta
hit = min(hit + delta, 100)（0x47FA89）
hit = max(hit − 0x410EDB(守), 0)（0x47FA9E）
```

- 装备选择子（`0x4079DA`：槽 0/1 比道具 `+0x14`、槽 2 比 `+0x11`）：6.4 `0x1C`=必中、`0x2F`=命中加成、`0x3D`=命中减成、`0x3F`=回避减成；6.5 `0x6B`=必中、`0x35`=命中加成；6.6 `0x24`=必中、`0x65`=命中加成。数值与消耗品特效表同号不同义，不能套用。
- 6.6 的最终守方修正为 `0x45D52B(攻,守,hit)`（对应 6.4/6.5 `0x410EDB`）；`0x408EEE` 其余字节三基底相同。

### 2.3 策略命中/闪避

输入是攻方（智力+士气）对守方（智力+士气）。6.4/6.5 命中桩 `0x0043B6F3`，取能力类型 2 与 4（`0x0043B7E7`、`0x0043B800`）；6.6 命中桩 `0x0043B730`，取类型 2 与 4（`0x0043B7FC`、`0x0043B813`）。曲线、85% 二次补判和 6.6 下限 25 与物理命中一致。

## 3. 暴击/连击发动率

### 3.1 共用发动率曲线

函数 `0x00405D0A`（三基底同址同值）。设攻方能力为 A、守方能力为 D：

- A ≥ 3D：100%
- 2D ≤ A < 3D：20% + (A−2D)×80/D
- D ≤ A < 2D：2% + (A−D)×18/D
- A < D：1%

参数：满率倍率 3、高段倍率 2（`shl ecx,1`，只读）/系数 80/基础 20、低段系数 18/基础 2、最低 1（`xor eax,eax; inc eax`，只读）、上限 100。

### 3.2 物理暴击

输入双方士气（类型 4）。暴击率来源 `0x0040C7D8`（`0x0040C7E9`-`0x0040C7F6`），入口 `0x00405E80`。

1. 双方士气套发动率曲线。
2. 上限 `0x00405ED7`，默认 100。
3. 0..99 随机判定。
4. 通过后进入集气池：6.4 池 0，6.5/6.6 池 2；6.4 调用 `0x00437896`，6.5/6.6 调用 `0x004287A8`。
5. 暴击成功后先把暴击率加 100，再按 `(暴击率+100)/2 / 100` 加伤：
   - 6.4/6.5 在 `0x00405F02` 执行 `sar eax,1`；
   - 6.6 在 `0x0042E4FD` 执行 `sar ecx,1`，并叠加特效 112 的返回值。
   - 暴击率 0 → 额外 +50%；暴击率 100 → 额外 +100%。

### 3.3 策略暴击

输入双方士气（类型 4）。入口 `0x0040CA68`，暴击率包装 `0x0040CADA`，伤害追加 `0x0040CAEB` 执行 `shr eax,2`。

1. 双方士气套发动率曲线。
2. 上限：6.4 `0x0040CAD8`，6.5/6.6 `0x0040CAA5`，默认 100。
3. 随机判定。
4. 集气池：6.4 池 0，6.5/6.6 池 18；6.4 调用 `0x00437896`，6.5/6.6 调用 `0x004287A8`。
5. 额外伤害 = `(暴击率+100)/4 / 100`：暴击率 0 → +25%；暴击率 100 → +50%。

### 3.4 连击率

输入双方敏捷（类型 3）。入口 `0x004060D2`，连击率来源 `0x00405CB9`（`0x00405CCA`-`0x00405CD5`）。

- 有特效 52：连击率 = 特效 52 返回值（默认 100）；6.4 桩 `0x00405CF7`，6.5/6.6 桩 `0x004E411B` 与 `0x004E4145`。
- 否则套发动率曲线。
- 三基底都进入集气池，池号默认 0：`0x0040612E`；6.4 调用 `0x00405CB9` → `0x00437896`，6.5/6.6 调用 `0x004E40E0` → `0x004287A8`。

## 4. 连击次数与连击伤害

- 主动连击发动率：特效 52 返回的数值，默认 100；地址 6.4 `0x00405CF8`、6.5/6.6 `0x004E411C` 与 `0x004E4146`。
- 引导攻击追加次数：击杀后再引导几次，总次数 = 值 + 1。6.4 默认 4，6.5/6.6 默认 2；指令 `0x0042133D`。
- 奋战攻击目标数：6.4/6.5 `0x00405C16`、6.6 `0x00405C13`，三基底默认 8。
- 连击伤害：函数 `0x004E313C`，6.5/6.6 在 `0x004E319C` 执行 `imul eax,[ebp-4]; add eax,本值`。默认 0，表示只取消逐次衰减、不加伤。6.4 同址为空，不适用。

## 5. 攻击伤害

### 5.1 物理攻击

函数 `0x0043BC62`。能力对取 0/1（武力/统帅），入口 `0x0043BCF5`：

- 伤害 = **攻方等级（`char+0x2C`）+ 25**（`0x412674` → `0x4065D0` 读 `+0x2C`，`0x43BD34 add eax,0x19`）
- 攻方武力 ≥ 守方统率：伤害 += (武力−统率)/2（`0x43BD42-0x43BD47`）
- 攻方武力 < 守方统率：伤害 = max(伤害 − (统率−武力)/2, 0)，再保底 1（`0x43BD54-0x43BD64`）

2026-10-31 更正：旧记录“伤害 = 武力 + 25”有误——`0x43BD2C call 0x412674` 取的是等级而非武力，武力只参与能力差项。加 25 在 `0x0043BD34`；能力差 `shr eax,1` 在 `0x0043BD45`/`0x0043BD52`；保底 `inc eax` 在 `0x0043BD64`。之后结算突破、偷袭、疾风、固定增伤、吸血、猛击、盾反等特效。

### 5.2 策略攻击

函数 6.4/6.5 入口 `0x0043C022`，6.6 同段。能力对取 2/2（智力/智力），入口 `0x0043C0F3`：

- 伤害 = **攻方等级（`char+0x2C`）+ 25**（`0x43C0F3 call 0x412674`，`0x43C0FE add eax,0x19`；6.6 同址/`0x43C10A` 起）
- 能力差按“攻方智力−守方智力”除以 3，再用 `0x0047FA9E` 做保底 1

2026-10-31 更正：旧记录“伤害 = 智力 + 25”有误——`0x412674` 经 `0x4065D0` 取的是 `+0x2C` 等级，智力只参与能力差项。加 25 在 `0x0043C0FE`；除数 3 成对 `0x0043C126`/`0x0043C139`。之后结算策伤保底/限伤、MP辅助策略、绝对策略伤害、限制策略伤害、化险为夷、金钱防御、攻守兼备、孤勇者等特效。

策略伤害的两级乘数表（2026-10-31 新增）：

- 第一级 `0x004D1840[策略ID]`：`0x43C10C-0x43C159` 执行 `伤害 = 伤害 × byte[0x4D1840+策略ID] / 100`（`0x425AD9`）。三基底表值不同：6.4/6.5 前 24 项形如 `46 5A 32 46 5A 46 5A 32/3C 46 64 …`，未列出的 ID 默认 `0x1C`（28%）；6.6 为 `50 5A 46 50 5A 32 …`，明显重排。
- 第二级 `0x004D21B0[分组]`：`0x43C15E` 用 `0x40BF0C(char+0x2B)` 求分组，`al<=0x27` 时 `伤害 = 伤害 × byte[0x4D21B0+分组] / 100`（`0x43C169-0x43C17C`）。表值三基底不同（6.4 以 `5F/64/64/5A/6E/82` 为主，6.6 以 `32..A0` 为主）。
- `0x40BF0C` 分组规则：`char+0x2B <= 0x3B → /3`；`0x3C..0x4F → −0x28`；`>=0x50 → 0x28`。

### 5.3 普通反击

函数 `0x004E31B3`（6.5/6.6 同址，6.4 为空）。没有强化反击时，6.5/6.6 在 `0x004E3214` 执行 `imul eax,ecx,3; shr eax,2`，即反击伤害 = 原伤害×3/4；`0x4E321E` 再 `inc eax` 保底 1。

强化反击分支（2026-10-31 新增，6.5/6.6）：

```text
v = 0x4101D9(守方单位, arg1=0x48, 选择子 0x68(6.5)/0x6B(6.6), 1, 0)   // 强化反击特效值
if v == 0: 伤害 = max(伤害×3/4, 1)
else:
    p = (maxHP(0x407263) − curHP(0x41B500)) × 100 / maxHP / 2      // 目标已损失 HP 百分比的一半
    if p != 0: 伤害 += 伤害 × min(p, v) / 100                       // 0x425AD9
```

- `p` 的截断 `min(p, v)` 在 `0x4E31FB-0x4E3200`；伤害追加在 `0x4E320C`。6.4 无此函数（同址为零字节）。

### 5.4 物理伤害的“最大 HP 百分比”前置分支（2026-10-31 三基底复核）

物理伤害函数（6.4/6.5 `0x43BC62`、6.6 `0x43BC5A`）在进入 5.1 的武力/统帅公式前先判断两类“按百分比取伤害”的来源：

```text
若 [0x500E9B] == 0x15（0x436392；6.6 0x436334）：base = 返回值
否则若 0x4101D9(单位, 参数=0x16, 选择子=0x1F, 1, 0) 命中：base = 装备/特效值
若 base 命中：
    if 开关 != 1: base = 最大HP(0x407263) × base / 100   // 0x425AD9
    直接跳到 0x43EA4F 修饰链（跳过 5.1 的武力/统帅公式）
```

- 开关字节：6.4 `0x46230E` = `0x01`（跳过换算，直接用 base）；6.5 `0x46230E` = `0x04`（执行最大HP换算）；6.6 表整体搬到 `0x4CB6BF` = `0x01`（`0x46230E` 在 6.6 已改为 `90` NOP）。
- 同一张 7 字节表的后续字节（6.4/6.5 `0x46230F`、6.6 `0x4CB6C0`）是 `0x452825` 的“按索引启用装备百分比”表：6.4 `02 02 02 02 02 02 02`、6.5 `02 02 02 02 02 02 01`（索引 6/MP 关闭）、6.6 `02 02 02 02 02 02 02`。
- 两条路径都汇入修饰链 `0x43EA4F`（`0x448FD0`/`0x448F53`/`0x4490E0`/`0x4491B3`/`0x434199`/`0x449115`/`0x43C3F0`）再到 `0x43BEED`，最后按守方当前 HP 截断：`0x43BF0E-0x43BF19` 取 `min(伤害, [守方+0x10])`，返回 `0x43BF1C`。
- 6.6 入口额外一步 `0x43BC7B call 0x43637B(守方)`（6.4/6.5 该地址不是同一函数）：`q = 0x45D2DA`（即 `0x4101D9(0x6E, 0x1D, 0, 0)`）；`q==0` 返回 0；否则 `x = 守方最大HP(0x407263) × q / 100`，仅当守方当前 HP（`0x41B500`）> x 时返回 x。非 0 时 `0x43BC85 jne 0x43BEF9` 直接把伤害设为 x 并跳过 5.1 与修饰链，随后仍走 `0x43BF0E` 的当前 HP 截断。
- 注意：`0x436392` 在 6.4/6.5 是“arg1 == arg2 且非 0”的判定桩（`0x43BC96` 用它判 `[0x500E9B]==0x15`），6.6 对应的同名桩搬到 `0x436334`，原地址 `0x436392` 已是其他代码。`0x500E9B` 的静态写入只有 `0x436DB1=1` 与 `0x436DCC=0`（xr2 全量扫描），因此“==0x15”分支在静态可见写入下不可达，除非有经指针/剧本的运行时写入；该分支的实机可达性仍未确认。

### 5.5 策略伤害末段修饰链（2026-10-31 三基底复核）

入口三基底同为 `0x0043C022`。参数：`[ebp+8]` 攻方单位、`ecx/[ebp-0x10]` 守方单位、`[ebp+0x10]` 策略 ID、`[ebp+0x14]` 命中模式（为 0 时先走 `0x43B4BA`/6.6 `0x43B4B6` 策略命中）。5.2 的两级乘数之后（`0x43C17F`）执行本链：

```text
对象 = 0x484002(策略ID) = 0x4A3E77 + ID×0x61        // 0x42B161 注册 0x481440(0x4A3E77, 0x61, 0x44, ctor 0x42B4F0, dtor 0x42B510)：基址/步长/个数
```

| 项 | 6.4 | 6.5 | 6.6 |
| --- | --- | --- | --- |
| 分组阈值 / 分组加成 | `0x40`（`0x43C18E`；不可达，见下）/ `+0x14` | `0x1E`(30) / `+0x28`(40) | `0x15`(21) / `+0x14`(20) |
| 地形/查表加成 | `+0x0F`(15)（`0x43C1DE`） | `+0x19`(25) | `+0x19`(25) |
| 双倍条件 | 策略 ID == `0x14` 且 守方分组 == `0xC`（`0x43C1F0 cmp byte[ebp+0x10],0x14`） | 同 6.4 | `type` == `0x14` 且 守方分组 == `0xC`（`0x43C1F0 cmp byte[ebp-0x24],0x14`） |

- 策略伤害门控 `0x415EFA(策略ID)`：`byte[0x4D18D0+ID] < 4` 才继续，否则为辅助/状态策略直接返回 0。例外：6.4/6.5 仅 IDs `0x46` 或 `0x16`（`0x403975` 只对 `0x16` 返回 1）继续；6.6 改为 `type ∈ {0x1E, 6}` 继续（`0x43C06D`/`0x43C074`）。
- `0x4D18D0` 表每策略 1 字节（0x00..0x43 已核）：6.4/6.5 索引 `0x00..0x15` 为 0、`0x21..0x24` 为 1、`0x26` 为 2、`0x40/0x41` 为 3，其余为 4；6.6 索引 `0x00..0x21` 为 0、`0x2E..0x31` 为 1、`0x36/0x3E` 为 2，其余为 4。只有 `<4` 参与伤害。
- `0x4D1840` 策略倍率表共 `0x90` 字节（到 `0x4D18D0`），按策略 ID 取 1 字节；`0x4D21B0` 分组倍率表 40 项（0x00..0x27），`0x28` 起为下一张表。
- `0x43B4A7(单位)` = `0x40BF0C(0x40658F(单位))`：`0x40658F` 由战场单位取武将记录，`0x40BF0C` 取 `char+0x2B` 的兵种分组（`≤0x3B→/3`、`0x3C..0x4F→−0x28`、`≥0x50→0x28`），因此"守方分组"就是守方兵种分组。6.4 的阈值 `0x40` 超过 `0x40BF0C` 的最大返回值 `0x28`，该 `+20%` 分支静态不可达（疑为改版遗留）；6.5/6.6 的 `0x1E`/`0x15` 可达。
- `0x435991(ptr)`：取 `dword[ptr]`（低字节 x、次字节 y），`x < byte[0x4B422C]`（地图宽）且 `y < byte[0x4B422D]`（地图高）才继续，否则返回 0xFF。6.4/6.5 调 `0x4359BB`：`0x403789` 计算 `index = y×宽 + x`（`movzx eax,byte[ebp+9]`、`imul eax,byte[0x4B422C]`、`add al,byte[ebp+8]`），`0x401669` 取 `0x47FA40(0x4AEB38,0,0,4)` 基址，最终 `byte[基址 + index + 0x640]`。6.6 改调 `0x412557`：同样的 `0x403789`/`0x401669`/`+0x640` 取地形字节，另读 `dword[地形地址+0x640]`（cl 非 0xFF 时经 `0x4061F9`/`0x43FA56` 附加处理），返回值仍为地形字节。调用方传入 `攻方单位指针+6`，即单位 `+6` 起 4 字节为打包坐标；返回值 2 与 `0x17` 是加成地形。
- `0x41553B(0x4B3D08)` 读 `0x48E100` 的 6 列小值表（行 `byte[0x4B3D08+0x11]`、列 `byte[0x4B3D08+4]`，值 0..4）；该表后紧跟“并力杀有把握打败的敌人？/夹击铁骑”等 AI/委任文本，因此暂按“战术/委任档表”登记，`0x4B3D08` 为对应全局对象；值 ≥2 触发加成。
- 链后 `0x40658F` + 类型分支（6.4 `al=0x28`、6.6 `al=0x77` 等）用于选择受击特效/表现 ID，与伤害数值无关，未展开。

## 6. 经验结算（2026-10-30 三基底复核）

### 6.1 个人经验

函数 `0x004037A3`（6.4/6.5 同码；6.6 同址但栈布局与指令顺序重排，结果一致）。设攻方等级 AL、守方等级 DL：

- 基础经验 = `2 × clamp(DL−AL, −1, 47) + 6`
  - 下限 −1：指令 `0x00403846 cmp al,0FFh`（立即数 `0x00403847`）、`0x0040384A mov al,0FFh`
  - 上限 47：指令 `0x0040384C cmp al,2Fh`（立即数 `0x0040384D`）、`0x00403850 mov al,2Fh`
  - 基础 6：`0x00403852 lea ecx,[eax+eax+6]`，位移立即数 `0x00403855`
  - **地址更正（2026-11-01）**：旧述“`0x00403847 cmp`、`0x0040384D cmp`”是把立即数字节当成了指令起始；三基底这一段指令地址完全相同（`0x403846`/`0x40384A`/`0x40384C`/`0x403850`/`0x403852`/`0x403856`），6.6 只是前面的击杀分支被重排、栈局部换名。
- 击杀（本次伤害 ≥ 目标当前 HP）：
  - 判定：`0x004037EF cmp dword [ctx+0x84+索引*4], eax`，`eax = 0x41B500(守方)` 当前 HP；`jb` 表示未击杀。`ctx+0x84+索引*4` 保存该目标的“攻击前 HP”。
  - 命中击杀且当前 HP≠0 → `0x00414E12` 杀敌数 `+1`，再 `0x0042A9C4(1)` 给本场战功 5 字段各 +1。
  - 目标 Data 号 = `word [0x492F90+0x3D06]`（`0x496C96`）时额外 `+48`；
  - 否则额外 `+64 / (max(AL−DL,0) + 2)`，之后仍加等级差基础。
  - 48：6.4/6.5 `0x00403824`（指令 `0x00403821`），6.6 `0x0040381E`（指令 `0x0040381B`）；
  - 64：6.4/6.5 `0x0040383A`（指令 `0x00403839`），6.6 `0x00403833`（指令 `0x00403832`）；
  - 偏移 2：6.4/6.5 `0x00403834`（指令 `0x00403833`），6.6 `0x0040382E`（指令 `0x0040382D`）。
  - 6.6 额外守卫：等级差计算前 `0x0040383B cmp dword [ebp−0Ch],0; je 0x0040386A`（该局部为 0 时整条经验直接返回）。
- 特殊目标来源：`0x00406604 movzx eax,word [ecx+3D06]`；写入点 `0x00412369 mov [0x496C96],ax`（剧本/事件参数，具体命令语义未闭环）。
- 同一行动多次攻击只取最大值：6.5 `0x00406023` 调用、`0x00406043 mov [ctx+428],max`。
- 经验开关 `ctx+600`：为 0 时返回 0。
- 末尾倍率：`0x00403865 call 0x421053(ctx+8?, 1, 经验)`（flag=1，可进入 `0x403D5A` 的 ×2/×4 路径）。

### 6.4 经验倍率与翻倍

- 倍率函数 `0x00421053`（6.6 入口 `0x0042104F`）：
  - `0x00407FAA push 8; call 0x00407C35`（6.6 `0x00407C29`）取角色第 8 项基础能力；
  - `0x00407FB9 add eax,64h`；
  - `0x00425AD9` 执行 `imul eax,[ebp+8]; div 100`。
- 翻倍函数 `0x00403D5A`：
  - `0x0042545F`：只对我军（`[unit+5]==0`）返回 `0x501B00[槽位]`，非 0 时 `shl [ebp+8],1`；
  - `[0x500E9A]==1` 时再 `shl [ebp+8],1`。
- 翻倍的前置开关（2026-10-31 新增）：`0x421053` 仅在第二参 `flag != 0` 且 `byte[0x505FBC] != 0` 时才调用 `0x403D5A`（`0x421068`/`0x421071`；6.6 `0x421066`）。三基底 `0x505FBC` 文件初值均为 0，且 xr2 全量扫描只见这一处读取，因此原始 EXE 下翻倍路径默认关闭。
- 2026-10-31 逐字节复核（`0x403D5A`/6.6 `0x42104F`）：倍率 = `amount × 0x407FAA%`（`0x425AD9`）；`0x42545F(byte[unit])` 非 0 → `shl amount,1`；再 `[0x500E9A]==1` → 再 `shl amount,1`（即最多 ×4）。`0x42545F` 仅在 `unit+5==0`（我军）时返回 `byte[0x501B00+序号]`，因此“×2”只对我军生效。6.6 函数体与 6.4 同构，仅整体前移 4 字节。
- 调用参数：个人经验 `0x403865` push 1、策略经验 `0x421043` push 1（可进入翻倍）；武器经验 `0x403926`、防具经验 `0x403B09` push 0（不进入翻倍，只乘 `0x407FAA` 倍率）。
- `0x501B00` 路线可达（2026-10-31 更正）：命令字节表 `0x00420C8E` 实际 37 字节为 `00 00 01 01 02 02 03 03 09…09 04 05 05 06 06 07 07 03 03 0A 0A 08`，索引 34/35 的值是 `0x0A`（旧记录误写“最大为 9”）。调度 `0x00420BD3` 以 `cmd−0x17` 取表值，`0x00420BF3 mov al,[ebp+0Ch]` 后 `0x00420BF6 jmp [edx*4+0x420C62]`；条目 10 = `0x00420BFD`，执行 `cmp al,14h`、`add eax,0x501B00`、`0x00420C06 mov byte [eax],3`，即命令 `0x39/0x3A` 可把部队序号（<20）的标志置 3。清零端是命令 `0x0A` 的处理函数 `0x00415ACA`（表 `0x00410A38` 索引 8）：先对单位状态数组 `0x4184CC` 清 256 项，再清 `0x501B00` 起 `0x140` 个 dword（`0x00415AED-0x00415B02`）与 `0x510000` 起 `0xC80` 字节（`0x473DF4`）。因此是否生效取决于剧本里 `0x0A`（初始化）与 `0x39/0x3A`（置标志）的先后；静态不再是“不可达”。
- `0x501B00` 的读取端：`0x0042545F` 用 `0x4061F9`（`unit = 0x4A7B20 + 序号×0x30`）取单位，仅 `[unit+5]==0`（我军）时返回 `byte [0x501B00+序号]`；除经验翻倍 `0x00403D5A` 外，另有 `0x0043C9E6` 按标志递减（`dec byte [edx]`，值为 1 时走另一分支）与 `0x00478AE9`（非 0 时带 `0x48C3AC` 参数调用 `0x00478B46`）。
- `0x500E9A` 只见 0/2 两种写入：`0x410595` 写 WORD 0、`0x4225F2`/`0x423378` 写 `(值<<8)|2`、`0x4233EF`/`0x465FE1` 写 WORD 0、`0x41D2E6`/`0x41D70D` 写字节 0；`==1` 的直接写入仍未找到。物理暴击 `0x00405EBB` 在值为 2 时直接取 100% 暴击率（仅 6.4/6.5；6.6 该段 `0x405EB8-0x405EC9` 为 `0x90` NOP，已移除，见 6.19）。
- 个人、武器、防具、策略经验末尾都调用 `0x00421053`：武器/防具只乘 `0x407FAA` 倍率（flag=0）；个人/策略经验在 `0x505FBC != 0` 时还可进入 `0x403D5A` 翻倍。

### 6.5 策略经验

函数 `0x00420EFB`（6.4/6.5 同码，6.6 重排）。开关 `ctx+54C≠0`。

- 类型来源：策略记录 `0x4A3E77 + 策略ID×0x61`，`0x00425AC7 movzx eax,byte [ecx+0Bh]`。
- 类型 2 → 固定 `+20`（6.5 `0x00420F25`，6.6 `0x00420F19`）。
- 类型 1 → 普通档。
- 其他类型：伤害类策略（`0x00415EFA` 查 `0x4D18D0+ID`，值 <4）且击杀目标 → 击杀档；否则普通档。
- 击杀档：攻方<守方 `8×级差+32`（上限 200）；攻方≥守方 `max(32−4×级差,0)`，最低 10。
- 普通档：攻方<守方 `4×级差+10`（上限 100）；攻方≥守方 `max(10−级差÷2,0)`，最低 5。
- 目标 Data 号 = `0x496C96` → 经验 ×2（`0x00420FE8`）；最后乘经验倍率。
- 三路缓存：个人经验 `0x0044DE9E` 取最大写 `ctx+0x502`；武器经验 `0x00421363` 取最大写 `ctx+0x506`；防具经验 `0x00421409` 按策略 ID 写 `ctx+0x50A+ID`（66 项字节）。`0x00451085`（6.4）/`0x0041A0AC`（6.5/6.6）再统一结算：个人 → `0x004088CD`、武器 → `0x004082DD` 槽 0；防具在 `0x00422A53-0x00422A60` 写入槽 1。
- 策略武器经验 `0x00421363`：基础 4（6.4/6.5）/ 3（6.6），自身等级高于目标时 −1，武器类型必须是 2 或 0xA 才计入。

### 6.9 升级能力成长（2026-10-31 新增）

函数 `0x00408D52`（三基底同码，6.6 分发到 `0x0041EC1A`），每次角色升级调用：

```text
q = min(等级(char+0x2C) / 20, 2)      // 0x408D77 mov cl,14h; div ecx; cmp al,3 → 2
if q == 0: 不成长                      // 0x408D83-0x408D85
g = char+0x2B（兵种 ID，初值见 6.13）；cmp al,0FFh / jg 为有符号比较 → g 仅 0..127 继续，0x80..0xFF 不成长
r = g % 3                              // 0x408D8F mov cl,3; div ecx
if r == 2 或 q <= r: 不成长            // 0x408D93/0x408D98
点数 = q − r                           // 0x408DA0 sub byte [ebp-4], dl
0x41EC16(char, 点数, 参数) 分配成长点   // 写入装备槽三字节，见 6.12
```

- 分配器 `0x0041EC16`（6.6 `0x0041EC1A`）：`0x4061E4(单位ID)` 取武将记录，`0x00477ADC` 取成长 ID（`0xFF` 中止），按点数循环调用 `0x0041D468(ecx=0x497750, al=成长ID)` 构造候选对象（对象 `+3`=单位ID、`+8`=单位指针、`+0x10`=武将指针；`0x497750` 为字节表，文件初值全 0、运行时填充，6.6 另作道具 ID 表见 6.12）；内层对槽 0..2 依次 `0x0040E04F`（复制槽三字节）→ `0x00407961`（成长判定）→ 返回 0 时调用 `0x00407FD4` 写入该槽。
- 结论（2026-10-31 更正旧版“+1”）：升级点 = `min(等级/20, 2) − (兵种ID(char+0x2B) % 3)`，仅当 `char+0x2B` 为 0..127、`q > r` 且 `r ≠ 2` 时生效；三基底同码。分配结果不是直接“五维 +1”，而是写入装备槽三字节（道具 ID / 成长值 / 标志），见 6.12。兵种 ID 的初值与消费链见 6.13。

### 6.10 最大 HP/MP 取值（2026-10-31 三基底复核）

取值函数 `0x00407263`（HP）/ `0x0040728F`（MP），三基底同址同码；`this` 为武将记录 `0x4CEA00 + ID × 0x48`（`0x004061E4`）。

```text
bonus = 0x407C35(this, 5 或 6)          // 装备/特效加成池；6.6 同函数在 0x407C29
base  = word[this+0x1B] / word[this+0x1F]
if byte[0x505F38] == 0:                  // 文件初值 0，未找到静态写点
    value = base
else:
    q = word[this+0x35] ÷ P              // 0x40C7C8(击杀数, 1, P) = 击杀数×1/P（整除）
    value = base + base × q / 100        // 0x425AD9(base, q)
return min(value + bonus, 0xFFFF / 0x270F)             // 0x47FA89
```

| 基底 | HP P（`0x407277`） | MP P（`0x4072A3`） | HP 上限 | MP 上限 |
| --- | ---: | ---: | ---: | ---: |
| 6.4 | `0x50` = 80 | `0x0F` = 15 | 65535 | 9999 |
| 6.5 | `0x19` = 25 | `0x19` = 25 | 65535 | 9999 |
| 6.6 | `0x32` = 50 | `0x32` = 50 | 65535 | 9999 |

- `P` 是压栈第三参：`0x414D81`（6.4/6.5）与 `0x405B86`（6.6）实际为 stdcall 两参 `(P, base)`，第三参（`0x407C35` 的加成）由调用者 `pop ecx` 回收后作为 `0x47FA89` 的加项，因此不会丢失。
- **2026-10-31 更正**：杀敌数项是 `base × (击杀 ÷ P) / 100`（先整除再乘百分比），不是旧记录的 `base×(击杀×P)/100`。逐字节：6.4/6.5 `0x414D81`、6.6 `0x405B86` 均为 `push P; push 1; call 0x40C7C8`（`eax=击杀数; imul eax,1; div P`）→ `push eax; push base; call 0x425AD9`。即每 P 次击杀 +1% 初始最大 HP/MP。

- `0x414D81` 特殊分支：当 `P == 0x7F` 时不做乘除，改为“击杀数 ≥ 100 → +1”（平坦 +1）；三基底同码。
- `0x407263` 调用序列已核（6.6 同构）：`0x407C35(this,5)` 压栈作 bonus → `word[+0x1B]` 压栈、`push P` → `0x414D81` → `pop ecx`（=bonus）→ `push 0xFFFF; push eax; push ecx; call 0x47FA89` → `min(value + bonus, 0xFFFF)`。
- 复用算术：`0x00425AD9(a,b) = b × a / 100`；`0x0040C7C8 = eax × arg1 / arg2`；`0x0047FA89(arg1,arg2,arg3) = min(arg2 + arg1, arg3)`（三基底逐字节同码）；`0x0047FA9E`/`0x0047FAD0` 均为 `max(a − b, 0)`。
- 调用点：`0x0043CE43`（回合结算：HP 增量 = `(地形值 0x417B5A + 0x4210F4) × maxHP / 100`（两次 `0x425AD9`，`0x43CE5E`/`0x43CE72`），MP 增量 = `地形值 + 0x421106 + 0x42109C` 的平坦和（`0x43CE5A`/`0x43CE9D`/`0x43CEA8`，不再乘百分比），最后各自夹到上限）、`0x004042B7`/`0x00404B4A`/`0x00406AED`（低血量阈值 `maxHP/5`）、`0x00406BBC`（治疗上限 `min(基础+百分比, 最大HP)`）、`0x004078D1`（`当前HP×100/最大HP`，当前 HP 由 `0x0041B500` 读 `unit+0x10`）。
- `0x407C35`（6.6 `0x407C29`）：遍历装备槽 0/1（`0x4065F0` 取 `+0x2E + 槽×3`，道具记录 `0x4837C2(ID) = 基址(6.4/6.5 0x4A1140、6.6 0x49F820) + ID×0x19`，见 6.18b），槽 2 取 `+0x34` 且按道具 `+0x11` 比对；索引 ≥ 7 由 `0x452825` 原样返回。6.4/6.5 末尾 `0x41A430` 对索引 0..4 追加“特效 `0x90+索引` 的 rate% × 最大 HP”，6.6 无此尾部（`0x407CFF` 直接返回）。

### 6.10b 当前 HP/MP 写入 `0x43F6DB` / `0x43F715`（2026-11-01 新增）

- `0x0043F6DB(unit, value)`：`unit+0x10 = (value <= 0x407263(unit)) ? value : 最大HP`；`0x0043F715(unit, value)`：`unit+0x14 = (value <= 0x40728F(unit)) ? value : 最大MP`。两者 `ret 4`（1 个栈参），`ecx = 单位`。
- 比较是**无符号** `cmp ecx,[ebp-4]; jbe`，且**没有下限钳制**：传入 `0xFFFFFFFF` 等负值会按“超大”落到取最大值的分支（等于写满）。
- 三基底 `0x43F6DB` 起 0x38 字节逐字节相同（`0x43F6E4 push dword[ecx]` → `0x4061E4` → `0x407263/0x40728F` 的顺序也一致）。
- 读取：`0x0041B500(unit) = dword[unit+0x10]`（当前 HP），三基底同址同码；当前 MP 无同名 getter，直接读 `unit+0x14`。
- 调用示例：行动结算 6.5 `0x0042304B`/`0x00423065`（`0x43F6DB(unit, 当前HP + [ctx−0x10])`、`0x43F715(unit, [ctx−0x14])`）、6.6 `0x00423097`/`0x004230A2`；兵种提升链 `0x00453476`（见 6.12）。

### 6.11 武将记录 / 战场单位记录字段（2026-10-31 复核）

    - `0x47FA9E` 逐字节复核 = `max(arg1 − arg2, 0)`（`push ebp` 后读 `[esp+0xC]`=arg2、`[esp+8]`=arg1），6.13 的用法正确。

### 6.12 成长/装备分配（2026-10-31 新增，更正 6.9“+1”）

`0x00407FD4(officer, 槽, flag)` 的实际写入：

```text
div = 20 (6.4/6.5, 0x407FDD b0 14) / 40 (6.6, b0 28)
q'  = min(等级 / div, 2)                       // 0x407FE5-0x407FF3
成长 = 等级 >= 3×div ? 9 : ((等级 % div) / 4 + 1)   // 0x408002-0x408017
if flag != 0:
    成长 = max(成长 − 1, 0)                     // 0x408020 0x47FAD0
    if 成长 == 0: q'<1 → (成长=1, q'=0)；否则 (成长=5, q'=max(q'−1,0))
槽 0：tmpl 0..19；槽 1：tmpl 20..25；槽 2 直接返回（保护 +0x35 杀敌数）
可用性：0x41B782(兵种ID)=0x4A2A27+ID×0x23，0x41C60F(表,tmpl)=byte[表+tmpl+9]
写入：byte[officer+0x2E+槽×3] = 0x482427[tmpl>>1] + q'
      byte[officer+0x2F+槽×3] = 成长
      byte[officer+0x30+槽×3] = 成长>=5 ? 0xFF : 0
```

- 表 `0x482427`（13 字节，三基底差异即“被禁用的成长档”，`0xFF` 项）：6.4 `00 03 06 09 0C 0F FF 15 18 1B 46 49 4C`；6.5 `00 03 06 09 0C FF FF 15 18 1B 46 49 FF`；6.6 `00 03 06 09 FF FF FF 15 18 1B 46 49 4C`。
- `0x00497750` 表文件初值全 0（运行时由培养/剧本流程填充）；`0x0041D468` 用它决定分配的成长 ID。
- 分配完成后仅当 `byte[0x505FC4] != 0` 才调用 `0x4149CF` 重算；`0x505FC4` 文件初值 0（三基底），另有 `0x414C60`（6.6 `0x414C58`）与 6.6 `0x45348F` 同判。
- 重算 `0x004149CF(officer, 起始索引, 单位ID)`：`0x4149E8` 从起始索引递增到 6；每项先 `0x408A60(officer,i)`，再 `0x41055D(单位ID, i)` 取五维功勋记录 `0x508400+ID×0x0E` 的 word，然后：
  - 索引 0..4：`word[officer+0x11+i×2] = 0x408A60 + 功勋[i] + byte[officer+0x21+i]`（`0x414A0E-0x414A28`）
  - 索引 5：`word[officer+0x1B] = 0x408A60 + 功勋[5] + word[table+0x17]`（`0x414A47` 起 `shl edx,5` + `0x17`）
  - 索引 6：`word[officer+0x1F] = 0x408A60 + 功勋[6] + byte[table+0x19]`（`0x414A66 add edx,2`）
  - `table` 以单位 ID × 0x20 索引，基址来自 `0x47FA40(0x4AE4C8,0,0)`（`0x40159C` 返回）；该表与 DATA.E5 同批装载（`0x41B51E` 名表 `0x48BB60` 首项即 `DATA.E5`）。字段已按文件核对：`+0x17` word = 人物行 +23（初始最大 HP，曹操 0xA0=160）、`+0x19` byte = 人物行 +25（初始最大 MP，0x24=36），见 6.11 构造映射。
- 该重算函数同时是“兵种提升”后的刷新路径：6.6 兵种提示文本 `0x48B698`“%s的兵种已变为%s！”所在流程 `0x41D624` 调用 `0x453476`（内含 `0x4149CF` 与最大 HP/MP 写回 `0x43F6DB`/`0x43F715`）。
- 结论：升级分配写入的是“装备槽三字节（道具 ID/等级或成长值/标志）”，不是直接五维 +1；装备经验系统 (`0x4082DD`) 把同两个字节当装备等级/经验使用，说明两条系统复用同一槽位记录。
- 6.6 额外重算调用点：`0x453476` 读表 `0x497750` 首字节作道具 ID（`0x4837C2`），道具 `+0x15` ≥ `0x28` 时跳过；`[0x505FC4]!=0` 时先 `0x4149CF` 重算，再把 `0x407263`/`0x40728F` 结果经 `0x43F6DB`/`0x43F715` 写到 `[0x497758]` 指向的单位。`0x45392B` 以 `word[ecx]−0x1000` 作为重算索引、随后 `0x469ADC`。因此 `0x497750` 在 6.6 也被当作“道具 ID 表”使用（不止分配器候选表）。

- 6.6 `0x453476`/`0x4534DD` 在 6.4/6.5 同址是 `0x90` NOP 填充（改版注入的 6.6 专属流程）。`0x453476` 逐字节：入口读 `byte[0x497750]` 作道具 ID，`0x4837C2` 取道具记录，`byte[道具+0x15] >= 0x28` 跳过；`[0x505FC4]==0` 跳过；否则 `0x4149CF(officer, 0, 单位ID=byte[officer+0])`，再 `0x407263`→`0x43F6DB`、`0x40728F`→`0x43F715` 写到 `[0x497758]` 指向的单位；**返回值 = `0x406610(officer)` = 兵种 ID `char+0x2B`**。
- 6.6 `0x4534DD`（同一道具字节的档位换算）：`v = byte[道具+0x15]`；`v < 0x14` → `3×v + (⌊(arg−1)/3⌋ >= 0x14 ? 1 : 0)`（`arg` = 入口实参 `[ebp+8]`）；`0x14 ≤ v < 0x28` → `v + 0x28`；`v ≥ 0x28` → `arg` 原样；结果压栈调用 `0x40E01F`（`ecx` 为入口对象）。该函数是 6.6 兵种提升的等级/档位计算，与 6.13 的 `(兵种ID%3)×20` 分段互为补充。

### 6.13 基础能力积分 0x00408A60（2026-10-31 新增，三基底逐字节）

函数 `0x00408A60(ecx=武将记录, 索引)`（单栈参、`ret 4`）返回该能力的“兵种积分”基数；索引 0..4 五维、5 HP、6 MP。入口三基底同址；6.6 只把内层 helper 重定位到 `0x004115D7`。

```text
id  = byte[char+0x2B]          // 兵种 ID；0x408A6D，0x408A73 cmp al,3Bh; jg 跳过中间段
L   = byte[char+0x2C]          // 等级；0x408A69 push 0x14（块长 20）
r   = id % 3                   // 0x41FBF1 = xor edx,edx; idiv ecx(=3)，edx=余数
p   = L; acc = 0
if id <= 59:
    if r == 2 且 L >= 40: acc += v(id-1,i)×20; p = max(L-20,0)     // 0x408A85-0x408AAB（0x408A8B shl ecx,1）
    if p >= 20:           acc += v(id-1,i)×20; p = max(p-20,0)     // 0x408AB1-0x408AD0
acc += v(id,i)×p                                                    // 0x408AD3-0x408AEA，始终执行
return acc
```

- 等价式：`id ≤ 59` 时 `acc = v(id−1)×min(L, (id%3)×20) + v(id)×max(L−(id%3)×20, 0)`；`id > 59` 时 `acc = v(id)×L`（跳过中间段但仍走末段）。
- helper 五参 `(索引, 兵种ID, 进度, 武将, 块长)`：6.4/6.5 `0x00408B08`，6.6 重定位 `0x004115D7`（6.6 的 `0x408B08` 已是另一段分配函数）。返回 `eax = max(进度−块长, 0)`、`edx = v×块长`：6.4/6.5 `imul edx,[ebp+0x18]` 后 `push edx` 作为返回值占位、`call 0x47FA9E`、`add esp,8`、`mov edx,[ebp-8]`；6.6 `imul eax,[ebp+0x18]`、`call 0x47FA9E`、`add esp,8`、`pop edx`。
- `0x47FA9E` 三基底逐字节同码 = `max(arg1−arg2, 0)`（`cmp ecx,eax; jae→0; sub eax,ecx`），不是三参 `min`；调用后的 `add esp,8` 只回收两个额外压栈。

取值 `v(C,i)`：

| 项 | 6.4 | 6.5 | 6.6 |
| --- | --- | --- | --- |
| 兵种表 | `0x4A2A27 + C×0x23`（`0x41B782`，三基底同码；80 项） | 同 | 同 |
| 兵种字节 | `0x436CA3(兵种,i) = byte[class+i+2]` | 同 | `0x40DBAE` 同式，经 `0x425097` |
| 成长档 | `0x4072F2`（6 档） | `0x41A534`（7 档 + 特效位） | `0x4072F2`（表驱动 9 档 + 特效位 + 表修正） |
| i≤4 合成 | `(兵种字节 + 成长档)/2`（`0x408B2D-0x408B30 shr 1`） | 同 | `(兵种字节 + 成长档)` 先钳 ≥0 再 `shr 1`（`0x4250D6-0x4250DF`） |
| i=5/6 | 兵种字节（不合成长档） | 同 | 兵种字节 + `0x507EC0` 修正（不合成长档） |

成长档 `grade(officer,i)`（均先判 i>4 → 0）：

- 6.4 `0x4072F2`：`b = byte[+0x21+i]`；有符号比较 `≥0x66→6、≥0x64→5、≥0x5A→4、≥0x4B→3、≥0x32→2、否则 1`（`0x407300-0x40732A`）。
- 6.5 `0x41A534`：`≥0x7F→7、≥0x6F→6、≥0x64→5、≥0x5A→4、≥0x46→3、≥0x32→2、否则 1`（`0x41A542-0x41A574`）；再按 `0x42518F` 依次查询特效 `0xC6..0xCA`（名称池 `0x4CC600+ID×16` 均为“强化成长”），取首个非零值 v，命中则 `grade += 2×((v>>i)&1)`（`0x41A579-0x41A58C`）。
- 6.6 `0x4072F2`：`g = 0x4070E1(officer,1,i)`（无符号读取 `+0x21+i`）；`grade = 0x4CFA00 表中“≤g 的阈值个数”`（表 `01 4E 55 5A 64 6F 73 76 79 FF`，即 1/78/85/90/100/111/115/118/121，FF 哨兵；循环 `0x40730E-0x40731B`，上限 9）。随后 `0x42E4DE` 通过 `0x45D4EF` 扫装备槽 0..2，`0x45D4DC` 查特效 `0x98+槽`（名称池均为“天赐之资”），首个非零 v → `grade += 2×((v>>i)&1)`；最后由 `0x436E3D` 叠加 `0x507EC0` 表按（武将序号, i）的修正字节（0xFF 记为 0）。

### 6.14 能力显示取值链（getter 0x40715D…，2026-10-31 新增）

```text
// 栈复用：core 为 ret 4，只弹掉索引；0x407C35 与 0x436DE1 的结果留在栈上给 0x47FA89
```

### 6.15 升级写回 0x004073F3（2026-10-31 新增）

### 6.16 成长值提升（战功点消耗）0x0046206C / 0x0042AC8F（2026-10-31 新增）

### 6.17 每回合恢复 0x0043CE20（2026-10-31 新增）

6.4/6.5 入口 `0x43CE20`（仅 `0x418C90(unit)=byte[unit+0xC]==2` 时执行；`0x43D00E(unit)` 前置）计算回合开始时的 HP/MP 恢复，并顺带结算“每回合经验”：

```text
    value = value × 0x407FAA(officer) / 100      // 经验倍率百分数
显示/动画 0x450986(...)，随后 unit+0x10 += HP、unit+0x14 += MP
```

- `0x417B5A(ptr)`：`0x435991(ptr)` 取地形；地形 `0x12..0x16` 才有效（`0x12→25`、`0x15→15`，`0x13/0x14/0x16→20`，其它 0，`0x41E467`），返回值即地形恢复百分比。

### 6.18 装备特效取值链 0x4079DA / 0x43C794 / 0x407AF2 / 0x4200FC（2026-10-31 新增）

选择子（0x1A/0x1B/0x44/0x3B/0x36…）到具体道具特效值的解析：

```text
0x4079DA(selector)：扫槽 0..2
    槽0/1：仅宝物（0x40B4E1(item)!=0）参与，类型 = byte[item+0x14]（0x43AD29）
    槽2  ：类型 = byte[item+0x11]（0x43AD20）
    类型 == selector → 返回 1
0x43C794(unit, selector, flag)：命中 → eax=0x64、ecx=1；flag==0 时再调 0x407AF2 求数值
0x407AF2：槽0/1 命中 → 0x4200FC(item+0x16, 装备等级=0x4032DF(slot))
          槽2 命中 → 0x41DD72(item)（返回 word[item+0x15] 等），再经 0x407BA6 合并
```

`0x407BA6(acc, v, mode, arg4)` 合并规则（`0x43C794` 第三参即 mode）：

| mode | 行为 |
| --- | --- |
| ≤1 | `acc += v`（累加） |
| 2 | `acc != 7` 时 `acc = v`（覆盖，7 保留） |
| 3 | `acc |= v`（按位或） |
| 4 或 `mode−5 == arg4` | `acc = v`（覆盖） |
| 其它 | `acc == 0` 时取 `v`（首个非 0 优先） |

- 返回值统一 `min(acc, 0xFF)`。

`0x4200FC(item+0x16, L)`（6.4；`type = byte[item+0x14]`、`v = byte[item+0x16]`）：

- `type==0x1F`：`v *= L+1`；`L+1 < 0xB` 返回 v，否则直接查覆盖表。
- 特殊类型 `{0x76..0x7C, 0x48, 0x72, 0x70, 0x6F, 0x31, 0x66, 0x6C}`：`L < 0xC` 返回 v，否则查覆盖表。
- 其余：`L < 0x12` 返回 v；否则按类型修正——`0x33`（v==4→7）、`0x32`（v×2）、`0x36/0x42/0x46`（v+1）、其他（v×3/2）；再查覆盖表。
- 覆盖表 `0x46236F[type−0x1A]`：字节 ≠ `0xFE` 时覆盖返回值，否则返回 v。
- 6.6 `0x4200F8`：`L < 0x10` 返回 v；`0x72` → `(v×3)>>2`；`0x33/0x32/0x36/0x42/0x46` 同 6.4；其他仅当类别表 `0x4CB6BA[type−0x1A] < 7` 时做 `(v×3)>>1`；`L ≥ 0x12` 时覆盖表 `0x4CB5CA[type−0x1A]`（≠0xFE 覆盖）。
- 数据差异：6.4 覆盖表 `0x46236F` 为真实数据；6.6 同址是 `0x90` NOP，改用 `0x4CB5CA`（覆盖值）与 `0x4CB6BA`（类别，<7 才乘 3/2）两张表。

### 6.19 暴击率 0x00405D0A / 0x0040C7D8（2026-10-31 新增）

比率到百分比的通用曲线 `0x405D0A(a, b)`（三基底同码）：

```text
b >= 3a        -> 100
2a <= b < 3a   -> 20 + 80 × (b − 2a) / a
a <= b < 2a    -> 2 + 18 × (b − a) / a
b < a          -> 1
```

- `0x40C7D8(unit)`：`0x40D2B2` 以“4 号能力（敏捷）对 4 号能力”取双方值（返回 eax/edx），经 `0x405D0A(eax, edx)` 得基础百分比；再叠加 `0x44F9A9(unit+0xC, 1)`。
- `0x44F9A9(unit, mask) = 0x4101D9(unit, 3, 选择子 0x33, 0, 0) & mask`：选择子 `0x33` 的 bit0 = 必暴，命中则 `+100`。
- `0x45EE80`：在基础百分比上叠加 `0x4101D9(unit, 0x79, 选择子 0x52, 0, 0) × byte[0x500C48]`；`0x500C48` 三基底文件初值 0（默认关闭此叠加）。
- 暴击判定（6.4/6.5 `0x405EA4-0x405EF2`）：
  - `[0x500E9A]==2` → 暴击值强制 `0x64`(100)；
  - 否则 `v = 0x40C7D8(unit)`；`v <= 100` 时 `0x437896(0, v)` 掷骰，成功 → `v += 100`（用 +100 标记“已暴击”）；`v > 100` 直接视为必暴。
- **暴击增伤应用**（6.4/6.5 `0x405EEA-0x405F17`）：若 `0x412CF4(攻,守) != 0` → 清空暴击槽（暴击无效）；否则 `伤害 += 伤害 × (暴击值 >> 1) / 100`，并置 `ctx+0x604 = 1`。即暴击值 100 → +50%、200（掷骰成功）→ +100%。
  - `0x412CF4` 内部（2026-10-31 三基底逐字节复核）：`0x412CF8` 取 `dword[unit+0xC]` 子对象 → `0x422E56`（允许暴击）查询 `0x4101D9(子对象, 0x70, 选择子, 1, 1)`；否则 `0x405DCF`（取消暴击）查询 `0x4101D9(unit, 0x30, 选择子, 1, 1)`。
  - **选择子随基底不同**（压栈字节已逐基底核对）：`0x70` 一路——6.4 `00`、6.5 `31h`、6.6 `68h`；`0x30` 一路——6.4/6.5 `41h`、6.6 `00`。特效索引 `0x70`/`0x30` 三基底固定；`0x4101D9` 本身三基底逐字节相同。
  - 旧述“0, 选择子0x70, 1, 0”是把“索引 0x70、选择子 0x00（6.4）”误读为参数位，已更正。
  - **名称（特效名表 `0x4CC600 + ID×0x10`，6.5 实测）**：0x70“强化致命一击”、0x30“防御特殊攻击”、0x31“物理免疫”、0x41“步兵防御”、0x68“劲透攻击”、0x00“每回合恢复HP”；6.6 同名条目为 0x70“暴击增幅”、0x68“献祭光环”、0x41“增加视野”、0x00“生生不息”。**6.4 的 `0x4CC600` 池全 0**，其特效名不在此表。
- 6.6 差异：`0x405EB8-0x405EC9` 被 `0x90` NOP（“阶段==2 直接 100% 暴击”被移除，改为始终走 `0x40C7D8`）；掷骰改用 `0x4287A8(2, v)`，应用改为 `0x42E4FD(slot, v, unit)`：`crit = v>>1 + 0x4101D9(守方,0,选择子 0x70,1,0)`（有额外加成），再 `伤害 += 伤害×crit/100`；另有 `0x42AA2A` 命中时清零暴击槽。

| 待定表 C | `0x49CF68` | `0x40` | `0x81`=129 | `0x426839` | 同位 | 无 |
| 待定表 D | `0x4B6168` | `0x10C` | `4` | `0x4649A8`（cb `0x40E410`） | 同位 | 无 |
| 待定表 E | `0x4B66A8` | `0x10C` | `2` | `0x46A6A7`（cb `0x40E410`） | 同位 | 无 |
| 动态表 F | `[ebp-4]+8` | `0x18` | `0x0C`=12 | `0x42FA37` | `0x41165D` | 动态实例 |

- 6.5 与 6.4 的 14 处 call 地址逐处相同（`0x4267BB`/`0x426839`/`0x42B105`/`0x42B15A`/`0x42B1B0`/`0x42B206`/`0x42B25C`/`0x42B2B3`/`0x43E4C1`/`0x4649A8`/`0x46A6A7`/`0x4726B9`/`0x475807`），唯一差异是动态表 F（12×0x18）的载入：6.4 在 `0x42FA37`（基址 `[ebp-4]+8`），6.5/6.6 在 `0x41165D`（基址 `ecx+8`）。
- 除注明外，载入回调均为 `0x42B510`（空操作）；`0x481440` 的构造回调：道具 6.4 `0x42B4F0`/6.6 `0x415D2A`，其余 `0x45F710`（原样返回）。
- 尺寸核对结论：道具、兵种行、地形消耗三表与 Data.e5 索引 1/3/4 **逐字节尺寸吻合**；策略表注册 68 条但文件段 160 条（见 6.11 索引表备注与 6.23）；武将源行 1024×0x20 由 `0x408C0C` 展开成 0x48 步长记录（`0x41DD08` 只是空回调，不参与展开），见 6.23(d)。
- 表 A 用法部分定位：`0x41B7E2(ID) = [0x4CEA04] + ID×0x28`（调用点 `0x40C768`/`0x41B81E`/`0x466B19`/`0x466C36`）；`0x40C755(flag)` 取 `0x4B0770` 当前槽后按 flag 调 `0x45F670`（武将 ID）或 `0x48196D`；`0x466B19` 对 `i=0..0xF` 逐条 `0x472BFD` 生成 16 个出场槽（每槽 8 字节：ID/序号/1/值）。故表 A 为“出场/部队槽表”，来源是动态指针而非 Data.e5。
- 表 B（`0x49CEF8`，8×0x0E）用法：脚本命令码 `0xF1xx..0xF9xx` 经 `(码−0xF100)>>8` 得索引后内联取记录（`0x42752E`），再调 `0x42AC3D(record,0x8000,0x8000)`、`0x42AE05`、`0x41DF52` → **势力/军团候选表**。注意该公式给出索引 0..8（9 个码段），而注册条数为 8；含该逻辑的函数 `0x42742E` 开头即 `0x426A83(0x49CEF8, 0x70, 0)`（`0x426A83` = 前向 memset，0x70=8×0x0E），证明表 B 只清/建 8 条——`0xF9xx` 若出现会越界到 `0x49CF68`（表 C 首条），除非该码在别处被拦截（待实机确认）。循环边界来自 `0x426A71(6/4/2)` = `0x40167E(idx)` 读全局配置 word。
- 表 C（`0x49CF68`，129×0x40）= **地图部队候选表**（`0x426AA8(word id)=0x49CF68+id×0x40`）：`+0x00` word 武将 ID（`0x41DF81` 读；`0x41DF70` 经 `0x4061E4`→`0x406610` 取兵种）；`+0x04` word X、`+0x06` word Y（setter `0x41DF52`/`0x41DF61`）；`+0x08` word 另一 ID（`0x41DF89`）；`+0x2E` word（setter `0x42AEB9`）；`+0x3A` word 检索键（`0x411F9D`）。`0x42AED1(record,arg)` 先用 `0x426AA8(arg)`+`0x40A962` 解析两条记录，再按 `+4/+6` 与 `+0xA/+0xC` 调 `0x4291F7`（两部队坐标关系判定）。`0x428C30` 用 `(ptr−0x49CF68)>>6` 写回 `word[0x49CEE4]`，清 `+0/+0x16/+0x18` 后调 `0x42AEB9`/`0x41DF52`/`0x41DF61`。上述 setter/getter `0x41DF52`/`0x41DF61`/`0x41DF70`/`0x41DF81`/`0x41DF89` 在三基底逐字节相同；`0x42AEB9` 除尾部 NOP 布局外相同。
- 表 D/E（`0x4B6168`×4、`0x4B66A8`×2，均 0x10C 字节）：均为 C++ 对象池——构造 `0x40C282(ecx=记录, push 5, push 2)`（cdecl 实参顺序为 2、5），析构回调 `0x40E410` 负责释放 `[record+0x20]` 与全局 `[0x492E24]`。D 取记录 `0x4646E0 (imul eax,0x10C; add 0x4B6168)`，延迟初始化 `0x4810F3(0x464994)`；E 两个实例为 `0x4B66A8`/`0x4B67B4`，初始化标志 `byte[0x4B68C4]`，延迟初始化 `0x4810F3(0x46A693)`。语义候选为“特效/图层对象池”，具体用途未定位。
- 全局 `word[0x49CEE4]` = “当前记录索引”（初值 `0xFFFF`，写入点 `0x406661`/`0x426C5F`/`0x414DDE`/`0x428BDF`/`0x4154F9`；读取/比较点 `0x403121`/`0x40A965`/`0x4153FE`/`0x429432`/`0x429BC3`/`0x429C71`/`0x429E99`/`0x478BD6`）。其中 `0x4154F9 mov dword[0x49CEE4],edx` 以 4 字节写 2 字节槽，会覆盖 `0x49CEE6..E7`，属静态可查的越界写，待确认是否为有意布局。
- 6.6 重定位核对：表 B 内联取记录点 6.4 `0x42752E` → 6.6 `0x427517`（同码 `sar 8; imul 0x0E; add 0x49CEF8`）；表 C getter `0x426AA8` 三基底同址同码（`movzx eax,[ebp+8]; shl 6; add 0x49CF68`）。
- 动态表 F（**2026-10-31 语义更正：不是战斗表，是 12 行 UI 列表控件**）：宿主对象 `+8` 起 12×0x18 行对象；构造 `0x42F890` 调 `0x481440(obj+8, 0x18, 0xC, 0x418DE8, 0x42B510)`——`0x418DE8` 是 7 参文字绘制封装（6.6 直接调用点 `0x41A557/0x41A56E/0x41A58B/0x41A5EF/0x41A65E`，内部走 `0x402DFE`/`0x47F740`），`0x42B510` 为空释放回调。对象字段：`+0`=条目数（`min(arg4, i)`）、`+1`=最大文本长度（下限 8）、`+4`=字符串指针数组（以 NULL 结尾）、`+0x128..+0x133`=12 个启用标志（6.4 `0x42F9F2` 写 `byte[obj+i+0x128]`）。loader stub 6.4 `0x42FA20` / 6.5·6.6 `0x41164D`（`ecx+=8; push 0x18; push 0xC; push 0x42B510; call 0x4814E0`）的唯一调用者 `0x485366` 在**三基底均无任何引用**（含 4 字节地址常量扫描），属死代码；6.5/6.6 中也不存在 `+0x128` 标志写入点。
- 动态表 G（3×0x14，cb `0x46279F`）：记录是带 vtable `0x486F00` 的 20 字节对象，析构时调 `0x4628BE` 并维护全局引用计数 `[0x4B68C8]`/`[0x4B68CC]`；宿主基址 `[ebp-4]+0x90`。
- 动态表 H（255×0x34，cb `0x475880`）：每条 52 字节，内含位于 `+0x20` 的子对象；析构回调对 `record+0x20` 调 `0x46279F`；宿主基址 `[ebp-4]+0x1C`。
- F–H 在 Data.e5 目录中没有同尺寸段，语义仍未定位（候选：编成/缓存对象池）。

### 6.23 DATA.E5 分段装载链、字段重排与名表（2026-10-31 新增；更正 6.11/6.22 的道具字段口径）

**(a) 装载原语（6.5 地址；6.6 见 (g)）**
- `0x41FB35(path)`：打开 `DATA.E5`（字符串在 `0x48BB60`，三基底同址）。
- `0x41FC89(index, dest)`（`ret 8`）：读 0x118 处大端 dword 得 `offset0`，按 `(offset0−0x114)/12` 得段数（实测 10；目录基址实测为 `0x110`，与常量 0x114 差 4，但整除后同为 10）；再读 `0x110+index×12` 的大端 `{size,size,offset}`，seek 到 `offset` 并读 `size` 字节到 `dest`，返回 `size`。`dest==0` 时只返回长度不拷贝。
- `0x41B51E(name, index, dest)`（`ret 0xC`）：打开+装载包装，成功返回 1。全量 11 处调用：`0x4010BF`（段1→`0x4A1140`）、`0x41B677`/`0x40432C`/`0x40C380`/`0x4149E1`/`0x4266BD`/`0x43BB37`（段0→缓冲）、`0x41B74E`（段3）、`0x41B7A0`（段4）、`0x41B800`（段2）、`0x41B844`（段5）。除段1外 dest 均为全局段缓冲 `[0x496F60]`（`0x404C92` 写入）。

**(b) 主装载顺序 `0x41B639`（6.6 由 `0x404CAF` 调用；6.4 段1 改调 `0x47D988`）**

```text
0x41B666 段0 → 0x408C0C 逐条展开到 [0x4CEA00]+i*0x48（i=0..0x3FF，1024 条）
0x4010B0 段1 → 道具表（6.5 直接落 0x4A1140 后统一旋转；6.4 走 0x47D988/0x41FECC 解析）

0x41B790 段4 → 0x40956F(30+30 拆分) → 0x4A3517+i*0x3C（40 条）
0x41B7F0 段2 → 0x40D793 → [0x4CEA04]+i*0x28（128 条）
0x40251C(0x492E20)
0x41B834 段5 → 0x40D737 → 0x4A3E77+i*0x61（144 条）+ 尾段 0x610 字节 → 0x4A7510（97×0x10 名表）
```

- 顺序很关键：段1 的“255 槽旋转”会扫过 `0x4A1140..0x4A2A27`（6.5）或 `0x49F820..0x4A2A20`（6.6，512 槽），越界部分随后被段3/段4 覆盖，属无害的历史遗留补丁。

**(d) 段0→0x48 武将记录（`0x408C0C(id, src, 0)`；访问器 `0x4061E4(id)=[0x4CEA00]+id*0x48`）**

实测（段0 行0/1/2）：曹操 `编号0`、兵种0、等级1、五维 `81/98/93/79/87`（源 `51 62 5D 4F 57`）、体力上限 160、MP 36、三槽全 `0xFF`；夏侯惇 `编号1`、兵种9；张辽 `编号2`、兵种 0x36=54。**兵种 ID 不在 `+4`**（旧稿按 `+0x0D` 误标）；`+0x2B` 才是 `0x406610` 读取的兵种字节。

**(e) 道具记录：文件布局 ≠ 内存布局**
- 内存记录（`0x4837C2(ID)=基址+ID*0x19`）：`+0..0x0D` 名称 14、`+0x0E` 恒 0、`+0x11` 大类（奇=宝物）、`+0x12` word（低字节=序号，高字节 `0x00` 普通/`0xFF` 宝物）、`+0x14` **特效 ID**（普通 `0xFF`）、`+0x15` 基础、`+0x16` 附加、`+0x17` 每级成长、`+0x18` 宝物标记。
- 文件记录只差一次三字节重排：`mem[+0x14] ← file[+0x12]`（特效）、`mem[+0x12] ← word(file[+0x13..0x14])`、`mem[+0x0E] ← 0`。所以“Data.e5 索引 1 的 +0x14 是特效 ID”这一旧口径**只在内存记录成立**；文件层对应字段是 `+0x12`（普通 `0xFF`、宝物 `0x1E..0x7C`），`+0x13` 是序号（普通 05/0A/1E，宝物 `0x15..0xA7`），`+0x14` 是 `0x00/0xFF` 标记。
- 6.4：`0x47D9E1(0, 0x68, buf)` 逐条调 `0x41FECC`（先 memcpy 0x10、`+0xE=0`、再按上面重排），随后 `0x47D9E1(0x68, 0xFF, buf)` 从缓冲越界再解析 151 条垃圾槽。
- 6.5：段1 直接整段落表，再以 `push 0xFF; push 0` 作局部变量跑旋转循环（255 槽）。6.6：同型循环上限 `0x200`（512 槽）且基址 `0x49F820`，旋转末槽正好停在 `0x4A2A20`（兵种表前 7 字节）——说明 6.6 把道具容量从 255 扩到 512 并整体前移了表基址。
- 6.6 的道具直引点只剩 `0x4010B4`/`0x42B130`/`0x42B154`/`0x4837CA` 四处；6.4/6.5 另有约 50 处 `imul ecx,0x19; add ecx,0x4A1140` 的内联访问，在 6.6 被 NOP 或改写（如 `0x434EB0..0x434EFF` 全 `0x90`）。因此把 6.5 功能移植到 6.6 时必须把这些内联基址一并改成 `0x49F820`/`0x4837C2`。

**(f) 策略段拆分与特技名表**
- 144 条策略经 `0x40D737` 重排写入 `0x484002(i)=0x4A3E77+i*0x61`（`ret 4`）：
  `mem+0..9`←file`+0..9`、`mem+0xA`=0、`mem+0xF`←file`+0xB`、`mem+0xB..0xE`←file`+0xC..0xF`、`mem+0x10`←file`+0x10`、`mem+0x11..0x60`←file`+0x11..0x60`。
- 紧随其后的 `0x610` 字节（`0xE894` 起，即文件第 144..159 条原样）被拷到 `0x4A7510`，按 16 字节/条 = **97 条特技·技能名表**：`0x41E918(idx)=0x4A7510+idx*0x10`、`0x44D8E4` 同构、`0x466E3D` 依 `[ctx+0x24]` 在 `0x4A7510` 与 `0x4CC600` 两张名表间切换。实测 0..19 号：`重击/猛者/铁壁/沉着/虚实/昂扬/疾走/金刚/威压/威风/毒言/踏破/奋战/捕缚/厄运/连环/攻心/怒发/虚弱/鬼门`；90..96 号：`军师技10..军师技16`。
- 因此旧记录“策略注册 68 条 vs 文件 160 条”的正确解释是：文件 160 条 = **144 条策略记录 + 97 条 16 字节名表**（144×0x61+97×0x10=0x3CA0 精确吻合），`0x4814E0` 的 68 只是生命周期回调注册条数，与数据装载无关。

**证据**：以上均为 6.5 逐字节反汇编 + Data.e5 字节级实测；三基底段表/目录/解析器 `0x40D793`/`0x4202BD`/`0x408C0C`/`0x4061E4`/`0x484002`/`0x4819E0` 逐字节相同；6.6 差异仅 (g) 所列。

**(g) 6.6 重定位差异**
- 装载包装 `0x41B51E` → `0x41B533`；`0x41FC89` 6.4/6.6 与 6.5 同码。
- 主装载 `0x41B639` 同位，段2/段5 loader 为 `0x41B7EE`/`0x41B830`；段1 loader `0x4010B0` 基址立即数 `0x49F820`、旋转上限 `0x200`、表尾 `0x4A0248`。
- 6.4 主装载段1 调 `0x47D988`（内含 `0x41B51E`+`0x47D9E1`+`0x451313(0x4A1B68,0x48C530)`+`0x43E67C`）。

### 6.24 策略记录字段（内存 0x61）与习得等级表（2026-10-31 新增）

**内存记录** `0x484002(ID) = 0x4A3E77 + ID×0x61`（三基底同码）；**文件记录**（Data.e5 段5，144 条有效）需一次重排才能得到内存布局：

| 内存偏移 | 文件偏移 | 含义 | 取值/证据 |
| --- | --- | --- | --- |
| `+0x00..0x09` | 同 | 名称（10 字节，NUL） | 实测“灼热/火阵/…/军师技” |
| `+0x0A` | `+0x0A` | 恒 0（NUL） | `0x40D737` 写 0 |
| `+0x0B` | `+0x0C` | **施放类型**：0=敌方、1=我方、2=全场/天气 | `0x425AC7 = byte[+0x0B]`；`0x420EFB` 取 `byte[ctx]` 作策略ID → `0x484002` → `0x425AC7`，`al==2` 时 `+0x14` |
| `+0x0C` | `+0x0D` | 动画/表现模板 ID（0、`0x0A..0x16`） | 0x421B60 按 `type` 与模板选择 0x1B00/0x3600 帧块 |
| `+0x0D` | `+0x0E` | **范围/半径**（0..6） | `0x484E27 = byte[+0x0D]`；`0x4245C1` 取 `0x484002(id)` 后读 `+0x0D` 与目标距离比较 |
| `+0x0E` | `+0x0F` | **效果值/威力基数**（5..120） | `0x425AD0 = byte[+0x0E]`；`0x43C618` 分支直接以其为数值；`0x4653E9` 取两策略差值（注意：主策略伤害 5.2 的每策略缩放走 `0x4D1840` 表，不读本字段） |
| `+0x0F` | `+0x0B` | **属性/元素**：0=火、1=水、2=土、3=风、`0x26`=雷、`0x14/0x1E` 特殊、`0x19` 四神、`0x28` 召唤… | `0x44270C = byte[+0x0F]`（5.5 修饰链 `type`） |
| `+0x10` | `+0x10` | 说明/帮助条目编号（0..0x2C，按效果族分组：火 0、水 1、风 2、土 3、天气 4/5/6、补给 7…） | 文件实测 |
| `+0x11..0x60` | 同 | **80 个兵种的习得等级**（0=不可学） | `0x4845B2(rec, class) = byte[rec+0x11+class]`；`0x40755D` 以 `== 角色等级(+0x2C)` 生成可学列表（循环 `id<0x90`=144） |

- 重排公式（`0x40D737`，`ret 4`）：`mem+0x0B..0x0E ← file+0x0C..0x0F`、`mem+0x0F ← file+0x0B`、`mem+0x10 ← file+0x10`，其余同偏移。旧记录“策略 +0x0B 是类型”**只在内存记录成立**；文件层同义字段是 `+0x0B`→内存`+0x0F` 的属性，而文件 `+0x0C..0x0F` 才是施放/动画/范围/威力四字节。直接改 Data.e5 时必须按上表换位。
- 实测样例（内存视图）：灼热 `type0 caster0 anim0D range0 power8`；火阵 `0/0/0D/1/16`；火龙 `0/0/0C/2/35`；爆焰 `0/0/05/5/30`；海啸 `1/0/06/0/20`；旋风 `3/0/0D/4/8`；小补给 `0x13/1/0D/0/6`；回归 `0x16/1/01/0/80`；青龙 `0x19/0/0C/6/120`；白虎 `0x19/1/0B/0/80`；三味真火 `0/0/0D/0/40`；虎豹统领 `0x28/0/02/1/40`。
- 144 条之后的 0x610 字节是 97×0x10 特技名表（见 6.23(f)），不属于策略记录；`0x4814E0` 注册的 68 条只是生命周期回调数。
- 字段读取器三基底核对：`0x484002`/`0x4845B2`/`0x425AC7`/`0x425AD0`/`0x484E27`/`0x418C90` 逐字节相同；`0x44270C` 前 10 字节相同（6.6 后续函数布局不同）；`0x450931` 在 6.6 为 `0x90` NOP（6.5 为扫 `0x508C00` 的 FF 分隔双级表，`0x508C00` 为运行时数据，文件体待核）。

### 6.25 经验/升级 8 项常量逐指令复核（2026-10-31，三基底）

以 `0x4088CD`（个人经验结算）与 `0x4082DD`（装备经验结算）的立即数为证据，逐项核对 9.2 表：

| 常量 | 6.4 | 6.5 | 6.6 | 地址与指令 |
| --- | ---: | ---: | ---: | --- |
| 角色最大等级 | 80 | 60 | 99 | `0x4088D2 mov al,50h / 3Ch / 63h`（6.4/6.6 后接 `push eax`；6.5 为单参 thunk，`eax=0x3C` 后 `jmp 0x40D1F7`） |
| 角色每级经验 | 150 | 动态 | 250 | 6.4 `0x4088D5 mov al,96h`；6.6 `0x4088D5 mov al,FAh`；6.5 无固定值 |
| 等级分段（6.5） | — | 20 | — | `0x40D225 mov ecx,14h`（`等级 / 20`） |
| 每档增量（6.5） | — | 50 | — | `0x40D23B imul eax,eax,32h`；`min(等级/20,3)+3 → ×50`（`0x40D22E cmp eax,3/jbe`、`0x40D238 add eax,3`） |
| 宝物经验阈值 | 200 | 200 | 200 | `0x408317 add dl,C8h` |
| 普通经验阈值 | 100 | 150 | 100 | `0x40831C add dl,64h`（6.5 `add dl,96h`） |
| 宝物等级上限 | 9 | 9 | 15 | `0x408326 mov al,9`（6.6 同址 `mov al,0Fh`） |

- 6.5 角色升级阈值公式：`阈值 = (min(⌊等级/20⌋, 3) + 3) × 50`（等级 0..19→150、20..39→200、40..59→250、≥60→300）；6.4/6.6 为固定 150/250 每级。
- 装备经验结算 `0x4082DD(unit, amount, slot)`：`id=0x4065F0(unit,slot)`，`0xFF` 直接返回；`0x40B4E1(item)` 判宝物；阈值 `edx` 与上限 `byte[ebp-8]` 由上表选；`0x4032DF` 读当前等级、`0x409680` 读经验字节（`+0x2E+槽×3+2`），`经验 += amount` 后循环 `经验≥阈值 && 等级<上限 → 经验-=阈值; 等级++` 并 `0x403286` 写回等级；循环位置 6.4/6.5 `0x40835B-0x408376`、6.6 `0x40834E-0x40836A`。
- `0x4088CD` 共同体：`等级(+0x2C) < 最大等级` 才进入；`经验(+0x2D) += amount`；`经验 ≥ 阈值` 时循环 `0x408D52(unit,…,1)`（升级能力成长，见 6.9）并扣阈值；等级达上限时把 `+0x2D` 置 `0xFF`；最后 `0x4158DC(unit)` 刷新。6.5 的 thunk 只传 `maxLevel=60`，阈值在 `0x40D1F7` 内计算后跳回 `0x4088D9`。
- 三基底 `0x4082DD` 前 0x3B 字节逐字节相同（仅阈值/上限立即数与跳转目标不同），`0x4088CD` 三段在 6.4/6.6 为内联参数、6.5 为 thunk。

### 6.26 本场战功（功勋）派发链（2026-10-31 新增；更正 9.5 的 6.6 条件表口径）

**(a) 记录与取址 `0x42ACD2(id, flag)`（`ret 4`，三基底同码）**
```text
if ax >= 0x66 (102): al=0xFF, 失败
if flag != 1: officer=0x4061E4(id); if byte[officer+0x2A]==0xFF: 失败
edx = 0x508000 + id*10        // 102 条 × 10 字节（5 个 word = 五维功勋），0x508000..0x5083FC
返回 al=0（非 0xFF）与 edx=记录
```
- 与第 7 节“五维功勋记录 `0x508400+ID×14`”是**两套表**：`0x508000` 是“本场战功/待结算”，`0x508400` 是“累计功勋（14 字节，含 HP/MP 功勋）”。

**(b) 累加器 `0x42AB8E(增点 a, 战功记录, 武将记录, 字段 t)`（`ret 0x10`）**
```text
if byte[officer + 0x21 + t] >= 0xFF: 直接返回          // 该字段成长值已满
p = &word[rec + t*2]
v = 特效 0x45 的值（选择子 0x67）                        // 6.4 0x412A87 / 6.5 0x42518F / 6.6 同型
if [0x500E9A]==1:
    if [0x505FDC]==0: a *= 2
    else if [0x505F5C]!=0: 直接返回
v += a
idx = 0x477ADC(武将记录, v)                            // 返回 0xFF 表示不适用
if idx != 0xFF 且 byte[0x501B00+idx] != 0: a += 原 a     // 再叠加一次
word[p] += (v 或 a)                                    // 0x42ABF3 add word[edx],cx
```
- 即每次派发的增量 = `特效 0x45 值 + 点数`，全局阶段 `[0x500E9A]==1` 时点数 ×2，且可再叠加一次点数。

**(c) 战后派发点（`0x406000` 段，每个单位一次）**
- `0x406040`：`ctx+0x428 = max(原值, 0x4037A3(...))`（个人经验缓存，见 6.8）；
- `0x406051`：`ctx+0x42c += 0x403870(...)`（武器经验缓存）；
- `0x40605E`：`0x42A8EE(ctx, 单位)` → **字段 0 固定 +1**（`0x42ACD2` + `0x42AB8E(1, rec, officer, 0)`）；
- `0x406069`：`dword[ctx + 索引×4 + 0x430] = 0x403A8A(...)`（防具经验数组）；
- `0x40607B`：`byte[表 + byte[ctx+索引+0x10]]++`（值为 `0xFF` 时不加）——按武将 ID 的出阵计数；**表基址随基底**：6.4 `0x507800`、6.5/6.6 `0x508A00`。文件初值：6.4 `[0]=01`、6.5/6.6 `[0]=FF`，其余 0。
- `0x40608E`：`0x42A96D(ctx, 索引)` → 再派发一组字段（含字段 3，条件见下）；
- `0x40609B`：6.5 `0x42AADB`、6.6 `0x40DC5C`：
  `i=0..2` 取条件表 `byte[i + 表]`（6.4/6.5 表 `0x407826`、6.6 表 `0x41A139`，内容均为 `00 03 04 01 03 02 04`）：
  字段 3 需 `byte[ctx+0x608] >= 1`、字段 4 需 `byte[ctx+0x604] == 1`（两旗标挂在**战斗上下文**上：`ctx+0x604` 即 6.19 的暴击置位，`ctx+0x608` 疑为击杀/击破），其余无条件；命中则 `0x42AB8E(1, rec, officer, 字段)`。
- **更正 9.5**：6.6 的条件表不是 `05 06 06 06 06 06`——那 6 字节位于 6.6 `0x407826` 但**无任何引用**（遗留数据）；6.6 实际读取 `0x41A139`，内容与 6.5 的 `0x407826` 相同（`00 03 04 01 03 02 04`），即三基底派发字段一致。

**(d) 战后合并 `0x42AB32(flag)`（`ret 4`，三基底同码）**
```text
flag==0: id = dword[ecx+4]（武将记录里的武将ID），遍历表下标 0..2
flag!=0: unit = 0x4061F9(byte[ecx+1]); id = dword[unit]，遍历下标 3..4
rec = 0x42ACD2(id,0)；失败返回
for i: field = byte[i + 条件表]；调 0x423F4B(rec, officer, field)
```

**(d2) 战功→成长值兑换 `0x423F4B(战功记录, 武将记录, 字段)`（3 参，`ret 0xC`，三基底同码）**
```text
if [0x505FA8]==0: return                               // 总开关（三基底文件初值 0，默认关闭）
loop:
  if ((1 << 字段) & byte[officer+2]) == 0: return        // 武将允许位掩码
  p = &word[rec + 字段*2]
  count = 0x42AC8F(officer+0x21+字段, p, 1)              // 与战功点分配同一递增成本表（mode 1 只判不扣）
  if count == 0: return                                  // 战功不足
  word[p] -= cost(ax)                                    // 扣本场战功
  byte[officer+0x21+字段]++                              // 成长值 +1
  0x43A409(officer, 字段, 1)                             // 同步显示五维（6.12）
  if [0x501A74] != 0: loop again                         // 连续提升开关
```
- `0x42AC8F` 成本表同 6.16：`g<0x50 → 0x32(50)`；否则 `(g−0x4F)×0xA+0x37`（65/75/85…）。
- 三个开关 `0x505FA8`/`0x501A74`/`0x505FAC` 三基底文件初值均为 0，故“战功/战功点→成长值”默认整条链关闭；`0x423F4B` 的调用点只有 `0x41D26A` 与 `0x42AB7E`。
- 与 6.16 的区别：6.16 花的是“战功点 `0x5083FC`”，本条花的是“本场战功 `0x508000+ID×10` 的对应 word”；两者共用同一成本函数与同一写入目标（`officer+0x21+i`、`+0x11+2i`）。

**(e) 6.6 新增派发点**：全量扫描 `call 0x42AB8E` 在 6.6 多出 `0x40DCA5`（0x40DC5C 内）、`0x4118AC`、`0x422DF5`；6.4 的对应 `call 0x42AB8E` 为 8 处（无 6.5 的 0x42A8EE/0x42AADB 之外的差异）。
- 特效查询实现差异：6.4 `0x42AB8E` 用 `0x412A87(0x45,0x67,1,0,p)`（cdecl 5 参）；6.5 改用 `0x42518F`（`0x40B922` 判定后转 `0x4101D9`（战场单位）或 `0x41301E`（其他），`ret 0x10`）；6.6 再次重定位。

### 6.27 策略武器/防具经验（`0x421363` / `0x421409`）逐指令复核（2026-10-31）

### 6.28 道具功勋分派与本场战功总额（2026-10-31 新增）

**(a) 道具效果分发 `0x4224D4`**
```text
id   = 0x41D124(4)                                // 选目标/使用者；0xFF 直接报错返回
unit = 0x4061F9(id)
eff  = byte[ctx+1]
```

**(b) 两张功勋表取址对称**

**(c) 本场战功总额 `0x423EAD(flag)`（仅 6.5/6.6）**
```text

for i = 0..4: xchg word[rec + i*2], 0；累计旧值       // 0x00423EC7
if flag != 0 且 byte[0x505F3C] != 0: [0x505F40] += 累计   // 0x00423ED9/0x00423EE5
```

- 三基底 `0x505F3C`、`0x505F40` 文件初值均为 0；6.4 无 `0x423EAD` 对应函数，只有 `0x408FA0` 按 `char+2` 位图清理并累计。

- `0x505F40` 的读取消费点为 `0x4108E5`（压栈）与 `0x456CC9`/`0x456DB0`（`0x456CB4`/`0x456DA6`）。其中 `0x456CB4` 首先检查 `[0x505FA8]`（与“战功→成长值”同一总开关），为 0 直接跳过，因此“战功总额消费/显示”链路默认也关闭。
- `0x505F40` 由 `0x456CB4`/`0x456DA6` 消费（6.5/6.6 战功总额显示/结算缓冲区）。
- **开关可达性（2026-10-31）**：`0x505FA8` 全量 5 处引用均为 `cmp byte [505FA8h],0` 读点（`0x41D15E`/`0x423F4E`/`0x440D4B`/`0x456CBA`/`0x47C0C0`），无任何写入；`0x501A74` 仅 `0x423F94` 一处读；`0x505FAC` 仅 `0x46208A` 一处读。故“战功→成长值 / 战功总额消费 / 战功点分配”三条链在静态数据下全部不可达（三基底文件初值均为 0）。

### 6.29 策略禁用查询 `0x450931` 与表 `0x508C00`（2026-10-31 新增）

- 调用点：`0x40755D`（策略学习列表）对 `id=0..0x8F` 逐条：`0x484002(id)` → `0x4845B2(rec, 兵种)` 与 `char+0x2C` 比较；不等时再调 `0x450931(id)`，返回非 0 且 `id == char+0x2C` 才加入列表（`0x41DEA1(rec, 0x48B160)`）。
- `0x450931(id)` 结构（6.5）：`edx=0x508C00`；先跳过第一段（`while byte[edx]!=0xFF: edx++`），`edx++` 后若 `byte[edx]==0xFF` 返回 0；否则进入第二段，逐条比较 `byte[edx]==id`，命中后再比较 `word[edx+1]` 的终止哨兵。
- 表 `0x508C00` 三基底初值不同：
  - 6.4：`00 04 00 04 00 04 FF 10 00 04 00 04 00 04 FF 20 …`（8 字节一组的实表）；
  - 6.5：`FF FF 00 …` → 首个 `FF` 与第二个 `FF` 使查询**恒返回 0**（默认无禁用策略）；
  - 6.6：`01 02 03 00 …`，但 6.6 `0x450931` 整段为 `0x90` NOP，查询不存在。
- 结论：这条链只影响“可习得策略列表”的显示，不参与伤害/经验数值；6.5 默认空表，6.6 已移除该逻辑。

### 6.30 编成/部队槽表 A（Data.e5 段2）字段布局（2026-10-31 新增，2026-11-01 复核更正）

- 记录访问器：6.4/6.5 `0x41B7E2`、6.6 `0x41B7E0`，函数体三基底同码 `imul ecx,ecx,0x28; add ecx,[0x4CEA04]; ret`；128 条。
- 装载映射（`0x40D793`，段2 每条 0x24 字节）：`dword[rec+0]=word[src+0]`、`dword[rec+4]=word[src+2]`、`memcpy(rec+8,src+4,0x20)`。因此**文件字节 k≥4 映射到内存 `rec+k+4`**：文件 `src+0x13` 落在 `rec+0x17`（第一个 16 字节数组末格），`src+0x14..0x23` 落在 `rec+0x18..0x27`。旧述“`+0x14..0x1E` 递增序列”是按**文件偏移**量的，内存偏移一律 +4。
- 内存字段（stride 0x28，记录止于 `+0x27`）：
  - `+0x00` dword ← `word(src+0)`、`+0x04` dword ← `word(src+2)`：**两个武将 ID**。`0x40C755(flag)` 取当前编成槽（`0x415E19`：`word[0x4B0776]` 算术右移 1 后 ≥0x7F 钳到 0x7F）的记录，flag=0 返回 `dword[rec+0]`（`0x45F670` 通用 getter），flag≠0 返回 `dword[rec+4]`（`0x48196D`）。返回值在 `0x419770` 等处经 `0x41992E`：`id>=0x400 → 0`，否则 `0x4061E4(id)`→`0x407775` 取名，故确为武将 ID（上限 0x400 对应段0 的 1024 行）。
  - `+0x08..+0x17` = 16 字节 ID 数组（`0x472BFD(rec,i)=byte[rec+8+i]`，`0xFF`=空）。
  - `+0x18..+0x27` = **第二个 16 字节数组**（`0x4520A8(rec,i)=byte[rec+0x18+i]`，`0xFF`=空）。6.4 同址同码、1 处调用 `0x466C3E`；**6.6 该函数整段 `0x90` NOP 且无调用**。旧述“`+0x18..0x22` 11 字节”更正为 16 字节。
- 实测 6.5 段2 128 条：`(+0,+4)` 分布为 71 条 (165,166)、48 条 (3,23)，其余 (54,121)/(122,121)/(54,120)/(126,122)/(122,122)/(165,41)/(1,1)；两个 ID 数组多为递增集合：record 1..61 为 `0x96..0xA0` 的子集，record 62..77 为 `0x57..0x61`，record 0/38/59/60/61 为空。
- 两个构建函数（6.5 地址，6.4 同位）：
  - `0x466AE3`：i=0..0xF 逐条 `0x41B7E2(cur)` + `0x472BFD(rec,i)`，写 8 字节槽 `{byte+0=ID, byte+1=槽号, word+2=1, dword+4 = ([ebp+0x10]==0 ? 1 : 0x407961([ebp+0x10], ID))}`（`0x466B40`/`0x466B5C`）。
  - `0x466BF6`：构建 **42 槽**（`i<0x10` 且 `byte[ebp-0xc]==0` 读 `0x4520A8(rec,i)`，遇 `0xFF` 或 `i≥0x10` 改读备用缓冲），每项经 `0x416EF9` 写 `{dword=(槽号<<8)|值, dword+4=0}`。
  - 备用缓冲 `0x466CB7`：先循环 12 次（`cmp byte[ebp-0xc],0xB; ja`）写 `0xFFFFFFFF`，再按指针表 `[ebp-8]`（初值 `0x505FF0`，每次 `sub …,8`）读 `byte[*]`：若非 0 且 `i≤该字节`、`i≠3`，调 `0x466C81(ptr, 0xD0+6i, 6)`（`0x466D11 imul edx,6; add dl,0xD0`）；随后按 `0x505FE8`（每次 `sub …,4`）追加 `0x466C81(ptr, 0xCD, 3)`。语义为“从两张指针表补足 42 个 ID 槽”，`0xD0/0xCD` 具体含义待定。
- `0x472BFD` 的另一分支：`[0x505FE0]!=0` 时直接读 `dword[rec+edx+8]`；为 0 时按 `0x40C231()` 返回值的阈值 0xF/0x1E 与成长档表 `0x482427` 计算 ID，再 `movzx al`。
- 结论：表 A 是“编成/部队槽表”（128 槽 = 2 个武将 ID + 2×16 个 ID 槽），与 Data.e5 段2 一一对应；不参与伤害/经验/功勋数值计算。
### 6.31 道具使用表现链与战斗阶段字节 `0x500E9A`（2026-10-31 新增）

**(a) `0x41C74D` 不是数值公式**
- `0x4224D4` 在取到 `word[+0x15]` 后调用 `0x41C74D`，但该函数主体是道具使用的**表现/UI 链**：`0x40159C` 取缓冲、复制 0x1B00 块（`0x40899A`/`0x47FCFD`）、`0x403360`+`0x44FA7E`+`0x44FA1F` 取动画、`0x41C5C7(...,0x10)`、`0x47467A`/`0x423971` 绘制。因此道具功勋/HP/MP 的“数值”仍以 `0x41DD72` 的 `word[+0x15]` 为准，`0x41C74D` 的返回值只用于表现层。
- 结论：`0x2A/0x2B` 的钳制与写回（`0x422569`/`0x42258C`）所用的值来自调用方栈槽，不依赖该 UI 链的返回值。

**(b) 战斗阶段 `0x500E9A`**
- 全量 24 处引用（6.5）。读点包括经验翻倍 `0x43D6C`/`0x42ABB6`、暴击 `0x405EB8`、阶段判定 `0x406B12`/`0x438B13`/`0x43B60E` 等。
- 写点：`0x41D2E6`（byte）、`0x41D69B`（=1）、`0x41D70D`（byte）、`0x410594`（word）、`0x4225F1`（word）、`0x423377`/`0x4233EE`（word）、`0x44EA34`（=0）、`0x4516FC`（`inc byte`）、`0x465FE0`（word）。
- 因此“`[0x500E9A]==1` 时经验 ×2”的条件**可达**（有 `=1` 的静态写入），与 6.4 的“未见写入”旧述不同；6.5 至少存在 `0x41D69B` 显式置 1。
### 6.32 特技习得查询 `0x41873E` 与钳制函数 `0x47FA89`（2026-10-31 新增）

**(a) `0x41873E(table, 技能ID, 武将记录)`**
```text
for i = 0..4:
    e = table + i*3
    if word[e] == 技能ID 且 byte[武将记录+0x2C](等级) >= byte[e+2]:
        return 1
return 0xFF
```
- 表项 3 字节 = `{word 技能ID, byte 需求等级}`，5 条；表指针由调用方经 `ecx` 传入。
- 调用点 `0x4225C1`：`0x41873E` 返回 1 后 `0x41E918` 取特技名记录、`0x425AD0` 读其 `+0x0E`，再与 `byte[0x501C00+...]` 比较——因此这条链是“**特技/技能习得与名称显示**”，不是伤害公式。

**(b) `0x47FA89(a, b, c) = min(a + b, c)`**
```text
ecx = [esp+0Ch]（b） + [ebp+8]（a）
eax = [ebp+10h]（c）
return ecx <= c ? ecx : c
```
- 用于道具效果 `0x2A/0x2B`：`word[unit + idx*4 + 0x1B] = min(旧值 + 数值, 0xFFFF)`（`0x422569` 压 0xFFFF、旧值、数值三参）。
- 旧述“钳到 0xFFFF”应更正为“**旧值 + 数值后取 min**”；同一函数也用于最大 HP/MP 的其他累加点。
### 6.33 特技数据表 `0x41E907` 与 80 条特技循环 `0x4225A2`（2026-10-31 新增）

- `0x41E907(i) = dword[0x500C37] + i×0x10`（`movzx ecx,al; imul ecx,10h; add ecx,[500C37h]`）。`dword[0x500C37]` 三基底初值：6.4/6.5 `0x00511800`、6.6 `0x00512000`，即一张 **80 条 × 0x10 的特技数据表**（与名表 `0x4A7510` 同尺寸、不同基址）。
- `0x4225A2(ctx)`：
  ```text
  officer = 0x40658F(ctx)
  for i = 0..0x4F (80):
      t = 0x41E907(i)                       // 特技记录
      if 0x41873E(?, i, officer) == 1:      // 5×3 字节表判习得
          rec = 0x41E918(i)                 // 0x4A7510 名表
          v = 0x425AD0(rec)                 // 名表 +0x0E（实测 100）
          与 officer 侧阈值比较后返回 i（否则 0）
  返回 (i<<8) | 2
  ```
- 结论：这条链是“特技列表/习得筛选”，与伤害、经验、功勋数值无直接关系；`0x500C37` 的 dword 是特技数据表基址，而 `0x500C38` 另有独立全局（6.4 `0x508998`、6.5 `0x507800`、6.6 `0x511000`），不要混用。
- 静态内容：6.4/6.5 `0x511800`、6.6 `0x512000` 处均为 `00 04 01` 重复 5 次 + 尾字节 `01`（即每条 0x10 记录 = 5 个 `{word 0x0400, 等级 1}` 占位项 + 1 字节），疑为运行时初始化前的默认值；真实技能 ID/等级是否在运行时改写仍未确认。
### 6.34 特效名表 `0x4CC600 + ID×0x10`（2026-10-31 新增）

- 结构：每条 0x10 字节，前 12 字节 GBK 名称 + 4 字节尾部参数；与 6.33 的 `0x41E907`（`0x511800/0x512000`）不同表。
- 6.5 实测：`0x00`“每回合恢复HP”、`0x30`“防御特殊攻击”、`0x31`“物理免疫”、`0x41`“步兵防御”、`0x68`“劲透攻击”、`0x70`“强化致命一击”。
- 6.6 实测：`0x00`“生生不息”、`0x30`“防御特殊攻击”、`0x31`“物理免疫”、`0x41`“增加视野”、`0x68`“献祭光环”、`0x70`“暴击增幅”。

- 结论：6.4 的 `0x70 + 选择子 0x00` 中“0x00”对应 6.4 表首条“每回合恢复HP”（与 6.5 池的 0x00 同义），也可能表示“通配来源（不限选择子）”，待实机/调用点确认。

### 6.35 能力/成长/HP/MP/状态写入分派 `0x406ECA` 与直接设置 `0x407027`（2026-11-01 新增，三基底逐字节）

两个分派函数共用同一套“字段号”布局，`ecx = 武将记录`，栈参 3 个（字段、值、模式）。

#### (a) 增量写入 `0x406ECA(rec, 字段, 值, 模式)`（`ret 0xC`）

| --- | --- | --- | --- |

#### (c) HP/MP 变更模式字节 `0x505F30`

- `0x40DA4A(旧, 值)`（三基底同址、语义相同；6.6 只是把 `mov eax,1` 换成 `push 1; pop eax`）：
  - `[0x505F30]==0` → `旧 > 值 ? 旧−值 : 1`（**扣减，保底 1**）；
  - `==1` → `旧+值`；
  - `≥2` → 直接返回值。
- 写点：`0x406F96`（=1，`0x406ECA` 字段 7/8）、`0x407083`（=2，`0x407027` 字段 7/8）、`0x406FB8`/`0x4070A5`（=0）；读取点 `0x40DA4D mov ecx,dword [0x505F30]`（按 **dword** 读，故 `0x505F30..0x505F33` 初值全 0 才能保证默认模式 0；三基底文件该 4 字节均为 `00`）。

#### (d) 状态/HP/MP 写入 `0x45AA37(编号, 索引, 值, hook, 单位槽)`（`ret 0x14`）

- 定位单位：第 5 参非 0 → `0x4061F9(槽)`（`word[unit]!=0xFFFF` 有效）；否则第 1 参先试 `0x41B888`（`byte[0x505EFC]!=0` 且 `<0xFA` 时按**槽号**取单位），失败再 `0x43E4D6(编号)` 按**武将 ID** 扫描槽 0..0xF9（`0x45F670(unit)=word[unit]&0xFFF`）。
- 前置 `0x418C90(unit)==2`（战场单位类型），否则直接返回。
- 索引 ≤6：`hook!=0` 先 `0x43E6AA(槽, 索引, 值)`；`索引<6` → `byte[unit+索引+0x18]=值`（6.11 的六个状态计数）；`索引==6` 落入跳表首项。
- 索引 6..8 跳表 `0x45AB49`（三基底仅前 3 项有效；6.6 整体重定位 `0x45AAD3/0x45AAFA/0x45AB15`）：
  - 索引 6 → `0x45AACE`：`值&0x80` 非 0 → `0x423FB9(unit,值)`，否则 `0x4240D6(unit,值)`（写 `unit+0x1E` 的 4 个 2-bit 状态槽）。
  - 索引 7 → `0x45AAF5`：`0x41B500(unit)`（当前 HP）→ `0x40DA4A` → `0x43F6DB` 写回 `unit+0x10`。
  - 索引 8 → `0x45AB10`：`0x472840(unit)`（当前 MP）→ `0x40DA4A` → `0x43F715` 写回 `unit+0x14`。
- 收尾 `0x43FCC9(unit)`、`0x4158DC(unit)`（显示/状态刷新）。
- 6.6 差异（同址不同码）：`0x41B888` 后多一个 `cmp eax,0xFF` 判空、随后的槽号改从返回指针 `+4` 读取（`mov ecx,[eax+4]`），`0x43E4D6` 等价入口前移到 `0x43E4D1`；跳表整体 +5 字节。
- 字段 15 的伴随表 `0x501A84` 读端 `0x40C5E6(al)`：`byte[0x501A84+al]==0 ? 1 : 0`（即“该槽位为 0 时返回 1”）。

#### (b) S 剧本命令的当前值读取 `0x4036B0(字段, 编号)`（`ret 8`）

#### (c) 前置兵种积分 `0x413FAC(字段, 武将记录, once)`（`ret 0xC`）


- 6.4/6.5 的 `0x413FAC` 起 0x5A 字节相同；**6.6 同址不同码**：不再递减兵种索引，改为每轮 `0x425097(rec, 字段, 兵种)`（`0x425097 = 0x41B782 + 0x40DBAE` 兵种字节再经 `0x436E3D` 叠 `0x507EC0` 修正），因此 6.6 的结果是 `2 × r × v(当前兵种)`，而 6.4/6.5 是 `2 × Σ v(兵种−1..兵种−r)`。
- 两个调用点（三基底同址）：`0x414A3B`（重算 HP/MP，见 d）与 `0x41D52C`（6.6 `0x41D51E`）：`for 字段=5..6: 0x406ECA(rec, 字段, 0x413FAC(字段, rec, 1), 0)`。**更正（2026-11-01）**：循环计数 `[ebp-4]` 初值来自 `0x41D46B push 5`，条件 `cmp al,6`，故只覆盖**最大 HP / 最大 MP** 两项，五维不加；这是 6.37 兵种提升执行的一部分。

#### (d) `0x4149CF` HP/MP 重算的完整式子（补充 6.13）


- 三基底 `0x4149CF` 起 0x60 字节仅 6.6 的一个 call 偏移不同（`0x41B51E` 等价入口 +0x15），算术与字段布局相同；其中 `0x413FAC` 项是 6.13 旧述没有的（旧述只写 `0x408A60 + 功勋 + 人物行 +0x17/+0x19`）。

#### (e) 兵种升级条件 `0x41D3DC(flag)`（`ret 4`，返回 0/1）


- 提示文本地址 `0x48B64C`/`0x48B668`/`0x48B67C` 为 6.5 值，6.4/6.6 是否同址未逐一核对（仅登记调用关系）。

### 6.37 兵种提升执行 `0x41D468`（2026-11-01 新增，三基底逐字节）

### 6.38 装备成长累计 `0x40B3D7` 与经验倍率索引累计 `0x407C35`（2026-11-01 新增）

用于经验倍率 `0x407FAA = 0x407C35(8) + 100`（6.7 的“装备第 8 类成长”），逐字节复核如下。

```text

  acc = 0
  for 槽 = 0..1:                              // 6.4/6.5 0x407C49 cmp al,1；6.6 0x407C38
      item = 0x4065F0(rec, 槽); if item == 0xFF: continue
      itemRec = 0x4837C2(item)
      L = 0x4032DF(rec, 槽)
      base = 0x40B3D7(itemRec, L)
      if 0x429AD7(索引, item) == 0: acc += base        // 6.6 该过滤在 0x405670
      if 0x40B4E1(itemRec) == 0: continue              // 非宝物
      if 0x40678E(item) != 索引: continue              // 类别映射必须等于索引
      acc += 0x452825(rec, 索引)                        // 宝物附加（先 0x44661A → 0x4200F8(…, 等级)）
  return acc

0x40B3D7(itemRec, 等级):
  g = 0x40B444(itemRec)                        // +0x11 < 0x14 → 0；< 0x1A → 1；否则 byte[+0x14]
  if 0x40C45A(itemRec) == 0: return 0          // 即 g > 1 时不计成长
  acc = 0; i = 0
  while i < 等级 − 1: acc += byte[itemRec + 0x17]; i++      // 0x41B4F7 = byte[+0x17]；6.6 0x4202BB
  return acc                                   // = (等级 − 1) × byte[itemRec+0x17]
```

- `0x40C45A(itemRec)`：`call 0x40B444` → `cmp eax,1; setle cl` → 返回 1 表示 `0x40B444 ≤ 1`（即该道具映射类型为 0 或 1 才吃“每级成长”）。
- `0x40B444`、`0x429AD7` 三基底字节相同；**6.6 的 `0x429AD7` 已是另一段代码**，同类过滤实现在 `0x405670`。
- 类别过滤规则（`0x429AD7(索引, item)`）：`c = 0x4067CE(item)`；`dl = 1`（表示“不匹配、跳过”）当且仅当 `c != 0x0A 或 索引 ∉ {0,2}` 且 `c != 索引`；否则 `dl = 0`（匹配、计入）。因此类别 `0x0A` 对索引 0/2 视为匹配。
- **更正 6.18**：宝物附加的真实入口是 **`0x4200F8`**（不是 `0x4200FC`）；`0x44661A(itemRec) = itemRec + 0x16` 作为 `eax` 传入，函数内 `movzx ecx,byte [eax]`（= `+0x16`）与 `movzx eax,byte [eax-2]`（= `+0x14`），并按 `dl = 装备等级` 分支（阈值 `0x51/0x76/0x7C` 等）。6.6 对应入口 `0x4200F5`。
- 三基底调用目标差异（同址不同码）：类别过滤 `0x429AD7`（6.4/6.5）/ `0x405670`（6.6）；宝物附加 `0x4200F8`（6.4/6.5）/ `0x4200F5`（6.6）；成长字节 `0x41B4F7`（6.4/6.5）/ `0x4202BB`（6.6）；6.4 的 `0x41DD72`、`0x40C45A` 分别落在 `0x41DD74`、`0x40C45C`。
- 用途：`0x407FAA = 0x407C35(索引 8) + 100`（`0x407FB7 add eax,64h`），作为个人/武器/防具/策略经验的统一倍率。

### 6.39 百分比换算 `0x425AD9`、宝物成长表 `0x4200F8` 与 `0x452825`（2026-11-01 新增）

#### (a) `0x425AD9(a, b) = a × b / 100`（三基底同址同码）

- `0x425ADC mov eax,[ebp+0Ch]`；`0x425ADF imul eax,[ebp+8]`；`0x425AE5 mov ecx,64h`；`0x425AEA div ecx` → 无符号整除、余数丢弃。
- 全工程通用：伤害、经验倍率、宝物成长、HP/MP 恢复都换算百分比时调用它（例：`0x43C1E2`、`0x43CF00`、`0x4361F7`、`0x436217`、`0x45287D`）。

#### (b) 宝物成长 `0x4200F8(道具+0x16, dl=装备等级)`（`ret`，无栈参）

- 入参：`eax = 0x44661A(道具记录) = 道具记录 + 0x16`（指向“值”字节）；`ecx = byte[eax]`（值）、`eax = byte[eax-2]`（道具 `+0x14` 类型）、`edx = dl`（等级）。
- **6.5 分支表**（按 `+0x14` 类型）：

| 类型 | 结果 |
| --- | --- |
| `0x76..0x7C`、`0x48`、`0x51`、`0x66`、`0x6C`、`0x6F`、`0x70`、`0x72`、`0x31`、`0x5C`、`0x64` | 原值 |
| `0x1F` | 原值 + 等级（`0x420131 add cl,dl`） |
| `0x55` | 原值 × (等级+1)（`0x4200DC inc edx; 0x4200DD imul ecx,edx`） |
| `0x2F` | 原值 × 等级 + 0x1E（`0x4200EA imul ecx,edx; 0x4200ED add ecx,1Eh`） |
| `0x33` | 原值==4 时 +3 |
| `0x32` | 原值 × 2 |
| `0x36`/`0x42`/`0x46` | 原值 + 1 |
| 其它 | 等级<7 → 原值；否则 原值 × 3 / 2（`0x420166 imul ecx,ecx,3; 0x420169 shr ecx,1`） |

- 收尾（所有分支汇合于 `0x42016B`）：`if 等级 < 0xA → 返回上面的值`；否则 **查表 `byte[0x46236F + (类型 − 0x1A)]`**，表值 `≠ 0xFE` 时以表值返回（`0x42017A mov al,[eax+46236Fh]`、`0x420180 cmp al,0FEh`）。
- **三基底分歧**：6.4/6.5 同址但分支集合不同（6.4 无 `0x51` 项，`0x1F` 走“原值×(等级+1)”的算法：`3C 1F 75 0B 42 0F AF CA`）；6.6 改为 `0x4200F5` 且整体简化（只保留 `0x1F`→原值×(等级+1)、`0x72`→原值×3/2、`0x33`/`0x32`/`0x36`/`0x42`/`0x46` 与查表），表地址 `.data` 侧为 `0x4CB6BA`（另一处 `0x4CB5CA`）。
- 表 `0x46236F` 静态值（6.5）：`64 C8 FF C8 C8 FF C8 C8 C8 C8 C8 C8 C8 FF FF FF FF 64 FF FF FF 64 03 03 0A 02 FE 64 FE C8 C8 64 FE FE 64 64 63 63 FE FE 10 64 FE 64 98`；6.4 仅两处不同（`... 64 FF 03 0A 02 FE ...` 与末尾 `59`）；6.6 该区为 `90` 填充（表已搬走）。

#### (c) `0x452825(索引, ecx=武将记录, eax=成长值)`（`ret`）

```text
v = eax                                   // 由 0x4200F8 返回

if byte[0x46230F + 索引] != 2: return v   // 6.6 基址 0x4CB6C0（0x45283D ba 0F 23 46 00）

elif 索引 == 5: a = dword[rec + 0x1B]     // 最大 HP
else:          a = word[rec + 0x1F]       // 最大 MP（索引 6）

```

- 门控表 `0x46230F`（7 字节）静态：6.4 `02 02 02 02 02 02 02`、6.5 `02 02 02 02 02 02 01`（索引 6 关闭）、6.6 `02 02 02 02 02 02 02`（地址 `0x4CB6C0`）；与 5.4 记的“按索引启用装备百分比”是同一张表。
- `0x436DE1(索引)` 在取能力前被调用（`0x45282D`），其 `ecx/edx` 输出决定走“`[ebp-0x10]`”还是“读能力”分支；该子函数的返回值语义尚未逐指令定名，故此处只登记“能力 × 成长 / 100”这一确定部分。

### 6.40 `0x436DE1` 成长缺口与 `0x452825` 的基数选择（2026-11-01 新增）

#### (a) `0x436DE1(索引, ecx=武将记录, eax=传入成长值)`（`ret 4`，返回 `eax`=补充量、`ecx`=有效标志、`edx`=基准+功勋）

```text
in = eax                                   // [ebp-8]
if 索引 >= 5: return in, ecx=0             // 0x436DE9 cmp dword [ebp+8],5；0x436E9C/0x436E9F
v = 特效查询(0x3D, 0x5C, 6.4=1 / 6.5·6.6=2, 0)   // 6.5/6.6 为 0x42518F，6.4 为 0x412A87（同形；6.4 的 0x42518F 为 44 字节 NOP）；内部按阵营选 0x4101D9 / 0x41301E
if v.标志(edx) == 0 且 v.值(al) == 0: return in, ecx=0
if v.值(al) == 0xFF: 走基准合成
if v.值(al) != 0: base = al                // 特效值即每级基准
else:                                       // 0x436E14
    troop = 0x406610(rec)
    base = (0x436CA3(0x41B782(troop), 索引) + 0x41A534(rec, 索引)) >> 1   // 兵种字节 + 成长档，右移 1
base = (byte)base
x = base × byte[rec+0x2C]（等级） + byte[rec+索引+0x21]（成长值）          // 0x436E46 imul eax,edx；0x436E52 add
0x40BE7D(rec)                               // 取 ID，但结果随后被 5 个 NOP 丢弃（0x436E60-0x436E64）
x += 0x41055D(索引)（永久功勋）              // 0x436E6D add ax,[ebp-0xC]
base2 = x                                   // [ebp-0x10] → 作为 edx 返回
cur = word[rec + 索引×2 + 0x11]             // 0x436E82 movzx edx,word [ecx+edx]
return max(x − cur, 0) + in, ecx=1, edx=base2   // 0x436E89-0x436E9A
```

- 调用点（三基底）：`0x407162`、`0x407197`、`0x4071CC`、`0x407201`、`0x407236`（能力显示/状态链）与 `0x45282D`（宝物成长）；6.6 另多一处 `0x4196AB`。
- **6.6 变体**：入口 `0x436E02`（更短）——`<5` 判定后调 `0x436DF0`（特效查询）、成功则 `0x407D48(索引)` 求基准并把 `[ebp-8]` 直接加上，返回 `ecx=1`；否则返回传入值、`ecx=0`。

#### (b) `0x452825` 的“值”来自哪里（补齐 6.39(c)）

```text
(eax, ecx, edx) = 0x436DE1(索引, rec, 成长值)
if 索引 >= 7 或 byte[0x46230F+索引] != 2: return 成长值      // 0x452884 mov eax,[ebp-8]
if ecx != 0: 值 = edx（基准+功勋）                           // 0x452852 mov ecx,[ebp-10h]
else:        值 = 当前能力（0..4 word+0x11+i×2；5 dword+0x1B；6 word+0x1F）

```

- 因此宝物对某项能力的加成基数：**基准成立时用“基准+功勋”，否则退回“当前能力”**；最终都乘宝物成长百分比。

### 6.41 特效查询分派 `0x42518F` / 6.4 `0x412A87`（2026-11-01 新增）

```text
0x42518F(索引, 选择子, 模式, 0):          // 6.4 同形函数 0x412A87；同样 ret 0x10
    ecx = 调用方传入的 unit（[ebp-4]）
    0x40B922(索引, 选择子, 模式, 0)        // 只透传 4 参，自身 ret（不清栈）
    if 0x40B922() != 0 → 0x4101D9(ecx=unit, 索引, 选择子, 模式, 0)
    else              → 0x41301E(... 同样 4 参)
```

- `0x40B922()` 在 `0x40B913()` 之后取 `al`：`cmp al,3; sete cl; mov eax,ecx` → 返回 `0x40B913()==3` 的布尔值。
- `0x40B913()` = `0x41EDEF(0x4AC63C)`，而 `0x41EDEF(ecx) = byte[ecx]`，故它直接返回 **全局模式字节 `byte[0x4AC63C]`**（不是“阵营函数”；写点与含义见 6.42）。
- 两条分支：
  - `0x4101D9`：按 `ecx`（unit）直接查，内部先 `0x426A07(0,0,0,0,0)` 取默认，再与 `0x505F78` 比较；三基底同址同码。
  - `0x41301E`：先 `0x40BE7D(rec)` 取武将 ID，再 `0x4198BE(0x500C3B, …)`、`0x43C794(unit, …)`、`0x413009(cur, 2, edx, eax)`（`0x413009` 仅当 `ecx==2 且 edx==0` 时把 `eax` 赋给 `edx`，再走 `0x40BF2F`）。
- **6.4 差异**：6.4 的 `0x42518F` 起 44 字节全为 `90`（函数不存在），等价函数是 `0x412A87`（字节形状与 6.5 的 `0x42518F` 相同，`ret 0x10`）；6.4 的调用点 `0x41A447`/`0x42ABAE`/`0x436DFB`/`0x43C54A`/`0x43E1B8` 均指向 `0x412A87`。
- **参数位次（以 0x436DE1 的调用为例）**：`索引=0x3D`、`选择子=0x5C`、`模式=6.4 的 1 / 6.5·6.6 的 2`、第四参=0；第三参在两个版本间差 1，是本轮唯一确认的跨基底常量差异。

### 6.42 全局模式字节 `0x4AC63C` 与合并规则 `0x40BF2F`（2026-11-01 新增）

#### (a) `0x4AC63C` 的写入与读取

- 读取：`0x40B913` 把 `ecx = 0x4AC63C` 后调 `0x41EDEF`，后者仅 `0x41EDF2 movzx eax,byte [ecx]`（三基底同址同码）→ 即 `0x40B913() = byte[0x4AC63C]`；`0x40B922() = (byte[0x4AC63C] == 3)`。
- 写点（**三基底**全量字节扫描 `C6 05 3C C6 4A 00` / `FE 05` / `FE 0D`）：

| 写点 | 6.4 | 6.5 | 6.6 |
| --- | --- | --- | --- |
| 进段置 2 | `0x4426E7`（函数 `0x4426E4`） | `0x416A78`（函数 `0x416A75`） | `0x416A78`（同 6.5） |
| 随后自增到 3 | `0x442700` | `0x416A91` | `0x416A91` |
| 结算前置 3 | `0x43C015` | `0x43C015` | `0x43C010`（前移 5 字节） |

- 进段函数体三基底相同：`置 2 → push 0 / [ebp+8] / [ecx] → 取当前战场对象 → 0x46D9A4 → 自增到 3`；6.4 用 `0x46931E`、6.6 换成 `0x4087F0`、6.5 为 `0x46931E`。
- 6.4 的 `0x416A75` 无任何调用点（该函数只在 6.5/6.6 存在）。
- 初值：三基底文件 `0x4AC63C..0x4AC643` 全为 `00`。
- 结论（静态）：它是**结算/攻击流程的模式字节**——进入某段置 2，攻击/策略结算前置 3；`0x436DE1` 走 `==3` 分支只是“结算中优先用 `0x4101D9`”。业务名称仍待实机确认。

#### (b) `0x40BF2F(mode, a, b)` 合并规则（`ret`，三基底同址同码）

| mode（ecx） | 结果 |
| --- | --- |
| 0 | `a + b`（`0x40BF36 add eax,edx`） |
| 1 | `max(a, b)`（`0x40BF3F cmp eax,edx; 0x40BF43 mov eax,edx`） |
| 3 | `a \| b`（`0x40BF4C or eax,edx`） |
| 其它 | `a != 7` 时取 `max(a,b)`；`a == 7` 时保留 `a`（`0x40BF50 cmp al,7`） |

- 与 6.18 的 `0x407BA6` 是同一族“合并模式”实现（0x407BA6：≤1 累加、2 覆盖、3 或、4 覆盖、其余首个非 0 优先）。

#### (c) `0x413009(mode, ?=edx, a, b)` 包装

```text
if mode(ecx) == 2 且 edx == 0: edx = eax        // 0x41300C cmp ecx,2；0x413011 test edx,edx；0x413015 mov edx,eax
return 0x40BF2F(mode, eax, edx)                 // 0x413017 call 0x40BF2F
```

- 在 `0x41301E`（敌方特效查询）里，`0x413009` 的 `mode` 来自调用方的第三参（`0x436DE1` 用 2/1），因此 `mode==2` 时相当于“以 `eax` 作为 `b` 再合并”。

## 7. 五维功勋记录


- 读取 `0x0041055D`：`cmp ax,66h`（ID ≥102 返回 0）；`0x00411DA5` 读 `char+2A`，非 0（非我军）返回 0；`movsx eax,word [0x508400+ID×14+字段×2]`。
- 写入 `0x00408B52`：`imul eax,0Eh`、`add eax,edx`；模式 0 设值/1 累加/2 扣减；`char+2A==0xFF` 直接返回。

#### 7.1 本场战功表（战斗事件与道具）


- **行动结算循环（2026-11-01 新增，`0x40603D-0x406093`，按目标槽 `[ebp-4]` 循环）**：
  1. `ctx+0x428 = max(原值, 个人经验)`（`0x406043`）；

- 道具效果 `0x2A`/`0x2B`（HP/MP 永久上升）在 `0x0042255C-0x0042258C`：`char+0x1B`/`char+0x1F` 与功勋字段 5/6（记录 `+0xA`）同步加值，上限 `65535`。
- 结论：`0x508400`（永久功勋）仍只由剧本命令写入；战斗事件与道具写入的是 `0x508000` 本场战功，二者不是同一张表。
- `0x505F40` 总额的消费端：`0x00456CB4` 在 `[0x505FA8]!=0` 时用 `0x0040BE7D` 把总额格式化到 `0x004FF3B8`（6.4）/`0x004FFF68`（6.5）/`0x00500B60`（6.6），并从本场战功记录复制 5 字段；`0x00456DA6` 走 `0x7DB` 界面。两处均未调用永久功勋写入 `0x00408B52`，静态上仍未发现本场战功 → 永久功勋的合并路径。
- `0x500E9A` 是状态字节（观测到 0/1/2 三种写入值）：`0x00410594`/`0x0041D2E6`/`0x00465FE0` 清零，`0x004225F1`/`0x00423377` 写 2 并把附加值存 `0x500E9B`，`0x0041D69B` 显式写 1（`0x004516FC` 为 `inc`）；`==1` 才是战功/经验 ×2 的触发值。6.6 `0x004064FB` 只认 `==1`，6.4/6.5 认非 0。
- `0x505FDC` 只有一处写入：`0x00425EFD mov byte [505FDCh],1`（`0x0041DD72` 返回 0 后置位）；`0x00403262` 的布尔判定在 `0x505FDC` 非 0、`0x4CE21F≠1`、`0x500AA0[0x11]≠1` 时返回 0。
- `0x00403262` 同时门控策略防具经验：`0x00421409` 入口即 `call 0x00403262`，返回 0 直接跳到 `0x0042148C` 跳过结算。因此 `0x505FDC` 置位会同时抑制战功 ×2 与策略防具经验。
- `0x505F5C`（2026-11-01 更正）：`[0x500E9A]==1` 且 `[0x505FDC]≠0` 时，`0x0042ABC8` 读到 0 → 不翻倍但照常累加；读到非 0 → `0x0042ABD1 jmp 0x0042ABF6` **整条放弃累加**。

#### 7.2 战功点分配（五维成长）

分配函数 `0x0046206C`（三基底同址）：

- 若 `0x505FAC` 非 0 且 `0x5083FC` 非 0：`pool = 0x5083FC × 第二实参`。
- 对 5 个槽位 `i=0..4`：`v = char[0x21+i]`；`v` 达到上限（6.4=100，6.5/6.6=110）跳过。
- 门槛：`v<80` 为 50；否则 `(v−79)×10+55`。
- `pool ≥ 门槛` 时 `pool -= 门槛`、`v++`、`word[char+0x11+2i]++`，同一槽位继续；余额经 `0x0042ACD2/0x0042AB8E` 转回本场战功。
- 6.4 在函数内内联循环（`0x004620C1-0x004620FE`）；6.5/6.6 调用 `0x0042AC8F`（第三实参 1 时只判不扣）。
- 第二实参（倍率）按调用点：6.4 恒 1；6.5 恒 25；6.6 `0x00409639`/`0x0042AD3B` 为 50、`0x0040C386`/`0x0044CD8D` 为 10。
- 计数器 `0x5083FC`：6.4/6.5 `0x004719A9 inc byte`（函数 `0x00471981`，`0x0041983F` 战后保存流程调用）；6.6 重定位到 `0x0040BB05`（函数 `0x0040BADD`）；上限 255，并同步到单位 `+2`。
- 6.6 的 `0x0040BADD` 无直接/间接调用点（callers3 对入口与区间均无命中，`0x419830` 在 6.6 已改为另一段函数），因此 6.6 的 `0x5083FC` 静态上不会自增，分配池可能恒为 0；需实机复核。

#### 7.3 本场战功兑换成长值 `0x423F4B`（2026-11-01 新增）

函数 `0x00423F4B(记录, 武将记录, 字段)`，**三基底 0x423F4B 起 0x54 字节逐字节相同**：

```text
if byte[0x505FA8] == 0: return                     // 0x423F4E
if ((1 << 字段) & byte[武将+2]) == 0: return        // 每字段独立允许位（0x423F5A-0x423F66）
do {
    word_ptr = 记录 + 字段×2                        // 0x423F68 imul edx,ecx,2; add edx,[ebp+8]
    cost = 0x42AC8F(word_ptr, byte[武将+字段+0x21], 1)   // 第三参=1 → 只判不扣
    if cost == 0: return                             // 0x423F7A 池不足
    word[记录+字段×2] -= cost                        // 0x423F7E sub word [edx],ax
    byte[武将+字段+0x21]++                            // 成长值 +1
    0x43A409(武将记录, 字段, 1)                       // 同步成长值到能力
} while byte[0x501A74] != 0                          // 连续兑换开关
```

- 与 7.2 的门槛函数是同一个 `0x42AC8F`（`v<80` → 50；否则 `(v−79)×10+55`；v≥110 返回 -1），差别只在本处第三参恒为 1（只判）。
- **`0x43A409(武将记录, 字段, flag)` 精确流程（2026-11-01）**：
  - `id = 0x40BE7D(rec) = (rec − [0x4CEA00]) / 0x48`（武将 ID）；
  - `perm = 0x41055D(字段)`：`ax` 传入 ID，ID≥0x66 返回 0；`byte[rec+0x2A]!=0`（非我军）返回 0；否则 `movsx eax, word[0x508400 + id*0x0E + 字段*2]`（**永久功勋表按字段取有符号 word**）；
  - `add = 0x408A60(rec, 字段, perm)`（按 `byte[rec+0x2B]` 兵种、`byte[rec+0x2C]` 等级与 `0x41FBF1` 的成长档计算）；
  - `v = byte[rec + 字段 + 0x21]（成长值） + add`；
  - 我军（`byte[rec+0x2A]==0`）时若 `v <= word[rec+0x11+字段*2]`（现有能力）则直接返回（**只增不减**）；敌军无条件写入；
  - `0x406ECA(rec, 字段, v, 1)`：字段 ≤0xF；≤4 时 `min(v, 0x270F=9999)` 后 `mov word[rec+字段*2+0x11],ax`（`0x406EFE`）；模式≠1 时改为 `min(v+旧值,9999)`；字段 5..9 走跳转表 `0x406FC5`（精确字段表见 6.35(a)：5=最大 HP dword、6=最大 MP、7/8=当前 HP/MP、9=无操作）。
- 三个开关 `0x505FA8`（总开关）、`0x501A74`（连续兑换）、`byte[武将+2]`（逐字段允许位）在静态数据中初值均为 0，见 7.1 的可达性结论。

## 10. 页面常量联动

33 条公式共 253 项常量条目（本版为“模式字节与特效合并规则”补 2 项跨基底只读）。当前基底可改数量：

- 6.4：56 项（6.6 下限、6.6 专属、6.5 分段常量不适用；战场变量装载 7 项、每回合经验 8 项、本场战功与道具/策略经验 44 项、能力写入分派 4 项只读）
- 6.5：62 项
- 6.6：66 项

可改项全部走常量页同一套定义、签名校验、成对写入与写后复读；公式页只负责上下文、范围与公式族语义校验。

## 11. 验证与边界

- `--battle-formulas <基底>`：三基底输出 `BATTLE_FORMULA_TESTS_OK`，公式 33 条、常量 253 项。
- `--battle-formula-write <基底>`：原有曲线/伤害写入，加 17 项经验/升级常量逐个探针写入并回填，并验证非法组合被拦截、文件不变。
- `--engine-constant-audit <基底>`：85 项常量逐项写入、复读、回填；新增签名全部 `hits=1`。
- `--engine-effect-ui <基底>`：公式页显示、列表 33 项、步骤表、常量表、待写入/放弃；截图 `公式设定-{version}-{宽}x{高}.png`、`公式设定-经验-{version}-1280x720.png`、`公式设定-装备经验-{version}-1280x720.png`、`公式设定-每回合经验-{version}-1280x720.png` 与 `公式设定-功勋-{version}-1280x720.png`。
- 静态反汇编与页面显示不等于战场实机验收；曲线、经验与升级类改动建议在测试副本战斗场景复核。
