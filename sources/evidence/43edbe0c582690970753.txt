# 拓展数据实现与验收

交付版本：1.2026.1019.1。默认程序为 `发布/data管理器.exe`，与 `发布-拓展数据完善版/data管理器.exe` 内容一致。窗口标题显示版本，诊断详情显示程序路径、实际游戏目录和布局修订。

- 交互参考本地工具整合包 MainForm.ExtendData；容量、名称识别和统一草稿以本管理器实现为准。

## 物理结构

| 文件 | 一条记录 | 最大容量 |
| --- | --- | --- |
| Effect.e5 | 每人物1024字节：256组“特效ID、效果值、经验、剩余回合” | 1024人物 |
| Effectmsg.e5 | 每特效8字节成长规则 | 256特效 |
| MeffStudy.e5 | 每人物64字节：32组“策略ID、使用次数” | 1024人物 |
| Forge.e5 | 每配方64字节 | 1024配方 |

读取按实际完整记录数确定行数。真实十八州、神话三国、禹夏的Forge.e5为16384字节（256条），不是损坏的64KB文件。Effectmsg.e5的2040/2048字节分别对应255/256条。无完整记录、尾部截断或超过最大容量时，对应分类显示原因，其余分类仍可使用。文件不会因打开或普通保存扩容。

Effect ID255为空，回合255为永久。修改已有特效不会顺带清零经验或改回合；空槽新填入时默认经验0、回合255。主动清空为 `FF 00 00 FF`。整理稳定移动完整4字节记录，重复项保留，单次撤销可恢复。原始回合0仍保存原值，并提示上游无符号递减的语义。

MeffStudy ID255为空，次数255为无限。新增默认次数255，主动清空为 `FF 00`。查询可能扫描全部32槽，但扣次与关末清理可能在第一个空槽停止；面板提示空洞风险，整理操作由用户明确触发。

Effectmsg八字节依次为允许成长、吃书初始效果值、成长上限、临时书回合、成长书经验、攻击经验、受击经验、击杀经验。允许成长按非零判定，已有2/255等值未主动切换时不规范化。第255号为保留槽，只读且原样保留。

Forge名称在0..29，八个物品项在30..53（UInt16 ID + byte 数量），54..57为UInt32金钱，58为材料项数，59为商店编号，60为启用，61为剩余次数（255无限），62..63保留。前N项为材料，其余为产物。装备材料用低7位等级和高位精确等级；消耗品材料用低7位数量。产物使用完整数量/等级字节，不拆高位。物品低字节为255即空，已有255/511/65535等空编码未主动修改时保持原样。

## 名称与界面

四个分类独立维护选择、搜索和页码：人物特效/策略学习读人物名，成长读特效名，锻造读配方名。特效每页10槽（共26页，末页6槽），策略每页8槽（4页）；下拉搜索按真实ID绑定。未知ID和不可读取名称仍可显示。

名称探测扫描PE可执行映射节中的两个独立消费者，提取共同的名称池VA，再按该EXE节表映射到文件。完整255×16字节池须落在映射区，每槽严格GBK/NUL验证，空名称合法。冲突、缺少消费者、乱码和overlay均降级数字ID。此目录只读，不授予EXE写入能力。人物、策略和物品统一使用当前Profile解析后的实际表；扩展物品支持根目录256×25字节的Item.e5，以及具备完整引擎证据的Star.e5内嵌256–511，不将E5/Item.e5图像包作为数据。根Item与Star分别使用自身codec和说明来源，物品名称目录包含真实ID511。

普通编辑使用现有ProjectWorkspace事务。未失焦输入也纳入顶部保存；切人、切类、翻页前校验。RawHex、SHA和原始/草稿对照在高级详情。CSV保留原TableKey和旧键别名，已知旧布局通过明确的兼容规则升级；未知布局不跳过身份检查。已保存历史仍检查当前SHA并按原字节差异恢复。

## 运行与验证

这是离线初始数据编辑器。引擎的EXS存档会保存并恢复人物特效、策略和锻造状态；修改初始e5文件不保证覆盖既有存档。真实基底矩阵分别记录物理读取、名称识别和消费者证据，不把存在数据文件等同于引擎已启用相应功能。

验收日志、真实矩阵JSON和界面截图放在 `验证/拓展数据完善-20261019`。原始基底文件在实施前记录SHA，最终复核；写回验收使用临时副本。

专项命令：

```powershell
dotnet build DataManager.sln --configuration Release
dotnet run --project src/DataManager.Tests --configuration Release --no-build -- --extend-core "实际测试基底"
dotnet run --project src/DataManager.Tests --configuration Release --no-build -- --extend-compatibility "实际测试基底"
dotnet run --project src/DataManager.Tests --configuration Release --no-build -- --extend-ui "实际测试基底" "截图目录"
dotnet run --project src/DataManager.Tests --configuration Release --no-build -- --extend-real-matrix "仓库根目录" "报告目录"
.\发布-拓展数据完善版\data管理器.exe --verify-extend "报告目录\交付EXE验收.json" "实际测试基底"
```

## 本轮实测记录（2026-10-19）

真实矩阵共18个项目全部通过。其中6个项目含拓展文件，共15个文件在临时副本完成单字段编辑、保存、重开和已保存历史撤回/重做：十八州、神话三国、禹夏各4个文件，两份山贼及魏延各1个文件。其余12个项目准确显示缺失分类。矩阵JSON逐项记录实际路径、文件长度、完整行数、名称池定位与消费者证据。

本轮对113个原始基底文件进行了前后SHA-256复核，变更数为0；证据为 `原始基底-修改前SHA256.json` 与 `原始基底-最终SHA256复核.json`。所有可写验收均在临时副本执行。

核心、CSV/旧修订兼容、旧历史、事务原子性和迁移回归均通过。迁移全套使用隔离Debug构建执行，其构建路径、时间和完整输出已明确记录在 `migration-regression.log`；最新兼容专项另以Release执行，记录在 `extend-compatibility-release.log`。最终构建和发布日志分别为 `build.log` 与 `publish.log`，最终交付EXE的独立验收见 `交付EXE验收-最终.json`，发布文件摘要见 `发布SHA256.json`。

真实大表验证中同时修复了原有性能问题：TableSnapshot使用行数组快照，撤销和保存只给不同值赋值，IsDirty按实际表变动失效；一次打开/重载共用同一物理文件的源字节，避免大型EXE为每张表重复驻留。完整矩阵由237.61秒降为144.05秒，保留完整文件复读、源SHA和回滚。

界面截图覆盖1280×720、1920×1080客户区以及125%/150%字体放大；测试设置允许超出当前屏幕的窗口尺寸，并检查实际ClientSize，避免把裁切图当成1920截图。**字体放大检查不等同于真实Windows显示缩放或跨显示器DPI切换验收**。本机未更改系统缩放设置；真实DPI切换仍需在相应显示环境复测。

本轮确认的是文件编辑及静态名称消费者证据，未启动目标游戏逐项验证四种拓展功能或既有EXS存档行为。报告用 `PhysicalFileEditingVerified` 与 `EngineConsumptionNotExecuted` 明确区分这两类结论。
