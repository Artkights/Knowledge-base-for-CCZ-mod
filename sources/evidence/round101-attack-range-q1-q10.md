# 分析-第一百零一轮：剩余十个未解问题（Q1–Q10）逐条闭合

- 目标基底：`基底\加强版6.5未加密版\Ekd5.exe`（SHA-256 `91121D4B…`），对照 6.4/6.6
- 探针：`data管理器\.tmp\scananchors.py`（函数锚点扫描，规避线性反汇编失步）、`scanimm.py`、`scanrefs.py`、`disasm.py`、`dumpbytes.py`
- 原则：只读基底；全部结论以指令字节为证据

---

## 方法说明（新增探针）

线性 `capstone.disasm` 从段起点解码会在数据区失步，导致 `0x4362DD add ecx,0x510000` 这类指令漏扫。
本轮改为“函数锚点扫描”：先按 `55 8B EC` / `55 89 E5` 建立 3207 个函数起点，再在 `[起点, 下一起点)` 内线性解码并匹配立即数/内存位移。此法命中率显著高于全段线性扫描，且每条命中都标注所属函数起点，便于回查。

## Q1 `byte[0x510000]`（cell[0]）的写入者

**结论：两个写入源，cell[0] 与 cell[1] 分工明确。**

1. **清零**：`0x473DF4`
   ```
   473DF4 push ebp / mov ebp,esp / push 0 / push 0xC80 / push 0x510000 / call 0x47FD13
   ```
   即 `memset(0x510000, 0, 0xC80)`（3200 字节）。上层 `0x415AEB` 同时清 `0x501B00` 的 0x140 个 dword（0x500 字节）后再调用它——这是**战场/地图初始化**，不是局内例行清理。

2. **写值**：`0x4556F6`（唯一写 cell[0] 的例行指令）
   ```
   4556F6 ... al=[ebp+8](x), ah=[ebp+0xC](y); push eax; call 0x4362C2 → ecx
   45571C al=[ebp+0x10]; test al,al; je ...
   45572x add dl,0xCF; mov byte ptr [ecx],dl      ← cell[0] = 0xCF + 类型
   4557xx inc al; mov byte ptr [ecx+1],al          ← cell[1] = value + 1
   ```
   即 cell[0] 是**覆盖物/地形状态码（0xCF 基）**，cell[1] 是附加值。上层 `0x45638B` 传入的类型来自 `[ebp+0x20]`。

3. **读取点**：`0x43625B`（特殊目标判定，`dl==0x24` 分支）、`0x44E272`（`==2` 判定）、`0x4749ED`。

**结论**：cell[0] 不是“无人写入”；写入者为 `0x4556F6`，语义为覆盖物状态码，清零者为 `0x473DF4`。

## Q2 `0x4A1140` 表的构建函数

**结论：`0x4A1140` 是 DATA.E5 的第 1 号数据块，不是独立静态表。**

构建链：
```
0x404CA8  call 0x41B639        ← 数据初始化总函数（唯一调用者）
0x41B639  call 0x41B666        → 块 0
          call 0x4010B0        → 块 1 + star.e5
          call 0x41B73E        → 块 3（兵种）
          call 0x41B790        → 块 4
          call 0x41B7F0        → 块 2
          call 0x40251C(0x492E20)
          call 0x41B834        → 块 5（策略 + 必杀）
```

`0x4010B0` 本体：
```
push 0x4A1140 / push 1 / push 0x48BB60("DATA.E5") / call 0x41B51E   ← 解出块 1 到 0x4A1140
循环 104 次（步长 0x19）：[ecx+0xE]=0；[ecx+0x12]=word[[ecx+0x13]]；[ecx+0x14]=[[ecx+0x12]]
mov ecx,0x4A1B68 / mov edx,0x48C530("star.e5") / call 0x451313     ← star.e5(0xED8) 载入 0x4A1B68
```
- 0x4A1140 + 0xA28(2600) = 0x4A1B68，恰好是 104×0x19。
- `0x41B51E(name, index, dest)` 走 `0x4032B0` 构造 → `0x41FB35` 打开 → `0x41FC89(dest, index)` 按 DATA.E5 的 12 字节块索引定位并解出。

**结论**：0x4A1140 由 `0x4010B0` 从 DATA.E5 块 1 载入并就地整理 +0x12/+0x13/+0x14 三个字段；Q “0x25 特殊目标判定读 +0x10==2” 读的就是该 25 字节记录的第 16 字节。

## Q3 `ctx+0x424` 的写入点与 `0x435CE9` 的连接

**结论：ctx+0x424 是“查询上下文缓存的兵种形状 ID”，它的消费者是特殊判定，不是形状展开器。**

- 写入：`0x40628A mov byte ptr [edx+0x424], al`，位于 `0x406232`（坐标/槽/形状缓冲/形状 ID 一次性初始化）。`0x406232` 的唯一调用者是 `0x4064F1`（`0x40650C call 0x406232`）。
- 读取：`0x40CE03 cmp byte ptr [ecx+0x424], 0xA`（`0x40CD39` 特殊技能判定）、`0x4111D4 mov al, byte ptr [ecx+0x424]`。
- `0x435CE9` 的 shape 参数来自调用者/`rec+0x4FC`，**不读 ctx+0x424**。

**修正**：工具说明中 “`0x40782D → ctx+0x424 → 0x4364C7 → 0x435CE9`” 的表述不准确。正确链条为：
```
0x40782D(0x407881) → al → ctx+0x424 → 0x40CD39/0x4111A1（特殊判定）
rec+0x4FC → 0x4364C7 → 0x435CE9（形状展开）
```
两条路都源于兵种形状表，但在上下文中分叉。

## Q4 `0x438AC0` 是否读 `0x407881`

**结论：会，但 `0x438AC0` 不是函数入口。**

- `0x438AC8 call 0x40782D`（取兵种形状 ID），随后 `al==0xFF`/`al==0` 直接跳过，否则 `0x435AAD(unit, shape, buffer, -1, -1)` 展开。
- 全库 `0x407881` 的引用只有 `0x407877` 一处（`movzx eax, byte ptr [eax+0x407881]`），四个调用者共用该访问器：`0x406282`、`0x4109A9`、`0x438AC8`、`0x477E20`。
- `0x438AC0` 于 `0x438940` 函数体内；`0x438940` 无外部 `call` 引用，说明它是被间接分派/内联使用的。

**结论**：AI 与玩家共用同一个兵种形状表；不存在“AI 走另一套形状表”的路径。

## Q5 真正的格子地形表

**结论：范围链路中没有“地形表”；地形不参与范围/穿透判定。**

证据：
- `0x437AFF` 全文只有：边界检查 → `0x418CD0`（把 x,y 打包成 word）→ `0x403789`（`y*width+x`，width 取 `0x4B422C`）→ `0x401669`/`0x40154A` 取池基址 → 写 A 层 `+0x12C0`、B 层 `+0`、M 层 `+0xC80`。
- `0x435884` 只读 `0x40167E(0xC80)`（= 0x4AEB38+0xC80 的 P 层）`+ y*width + x`，用于“该格已有单位/槽号”判定。
- 未发现任何对地图缓冲（MAP 资源，0x61E00）或地形 ID 的读取。

**结论**：3 字节/格的 MAP 缓冲只服务于移动力/显示；攻击/穿透范围由 A/B/P/M/L1/L5 六层决定。

## Q6 `0x505FCC` 的读取者

**结论：`0x505FCC` = 当前战斗/场景模式码，写入点 `0x425F04`，与 `0x505FDC` 互斥。**

写入（`0x425E50` 函数内）：
```
425EF3 call 0x41DD72
425EF8 test eax,eax
425EFA jne 0x425F04
425EFC inc eax; mov byte ptr [0x505FDC], al   ← 返回 0 时置 0x505FDC=1
425F04 mov byte ptr [0x505FCC], al           ← 返回非 0 时写模式码
```
读取者 18 处：`0x40C1E8`、`0x411B7D`、`0x411B9E`、`0x415198`、`0x417EC4`、`0x425FB5`、`0x439030`、`0x439DF1`、`0x439FD1`、`0x43A0CD`、`0x43B444`、`0x446B45`、`0x44816F`、`0x44818E`、`0x4497FB`、`0x44DE6F`、`0x450AE3`、`0x450B50`；取值判定为 1/2。

**结论**：该字节是“技能/必杀/道具使用时的场景阶段码”，不是范围数据；工具不涉及。

## Q7 `0x42399B` 低位误用（撤销旧结论）

**结论：旧结论作废——`0x42399B` 的用法是正确的。**

- `0x435884` 返回 `al` 的来源是 P 层（`0x4AEB38+0xC80`）`+ y*width + x` 的字节；P 层存的是**单位槽号（0..0xF9）**，`>=0xFA` 才返回 `0xFF`。
- `0x423A0C mov al, byte ptr [ebp-0x10]` / `0x423A13 mov cl, al` / `0x4061F9(槽)` / `0x406710(关系码)` 因此是把槽号转单位指针，语义正确。
- 旧判据把“P 层字节”误当成“单位指针低字节”。

**结论**：`flag∈{0,1}` 且 `0x500C44!=1` 时不会产生错误阵营判定；Q7 关闭，无实现缺陷。

## Q8 `0x4B2C44` / `0x4B2C4C` 的读取者

**结论：两者都是“当前行动记录”的控制字段，读写点已全部定位。**

| 地址 | 写点 | 读点 |
| --- | --- | --- |
| `0x4B2C44` | `0x438560`、`0x438575`（`0x438484`）；`0x43A3D5`、`0x43A3E6`（`0x43A55E`） | `0x43A74E`、`0x43B2D4`、`0x43B306`、`0x43B31B`（`cmp byte,0x39`） |
| `0x4B2C4C` | `0x43A780`、`0x43A797`、`0x43A7AF`（`0x43A55E`） | `0x40DEF5`（`cmp dword,0x64`）、`0x43B2D4`/`0x43B306` |

`0x43B31B` 的 `0x39`(57) 与 `0x40DEF5` 的 `0x64`(100) 是两条不同阈值：前者为字节比较，后者以 dword 跨读 `4B2C4C..4F`。

**结论**：Q8 关闭；无悬空字段。

## Q9 6.6 中 `0x435CE9` 的等价地址

**结论：6.6 的 0x435CE9 不是逐字节等价函数（重编译），但分派特征点相同。**

- 6.5 `0x435CE9`：`55 8B EC 51 33 C0 50 50 50 83 EC 14 8B 55 10 …`
- 6.6 `0x435CE9`：`55 8B EC 51 33 C0 50 50 FF 75 10 8A 45 0C 50 …`（+8 起不同，栈帧/参数传递被重写）
- 特征定位：6.6 的 `push dword ptr [eax*4+0x4D13A0]` 位于 **0x435D25**（与 6.5 完全相同）；36 形状分派 `mov edx,[eax*4+0x4D1400]` 位于 **0x43659C**（6.5 为 `0x4365A1`，−5）。

**结论**：以 `0x4D13A0` 经典跳表 + `0x4D1400` 36 形状表两个特征定位 6.6，不要按 −5 整体平移。

## Q10 必杀范围 `+0x0C/+0x0D` 的消费者（推翻旧结论）

**结论：两者都有消费者，工具说明必须修正。**

### DATA.E5 分块布局（本轮首次完整解析）

`0x110` 起 10 项、每项 12 字节（三枚大端 dword：压缩大小、原始大小、文件偏移）：

| 块 | 文件偏移 | 大小 | 内容 | 载入目标 |
| --- | --- | --- | --- | --- |
| 0 | 0x0018C | 0x8000 | 未命名大表 | `[0x496F60]` |
| 1 | 0x0818C | 0xA28 | 104×25 记录 | `0x4A1140` |
| 2 | 0x08BB4 | 0x1200 | 未命名 | `[0x496F60]` |
| 3 | 0x09DB4 | 0xAF0 | **兵种 80×0x23** | `0x4A2A27` |
| 4 | 0x0A8A4 | 0x960 | 未命名 | `[0x496F60]` |
| 5 | 0x0B204 | 0x3CA0 | **策略 144×0x61 + 必杀 97×16** | `[0x496F60]` |
| 6 | 0x0EEA4 | 0xBC | 小表 | — |
| 7 | 0x0EF60 | 0x20 | 小表 | — |
| 8 | 0x0EF80 | 0x20 | 小表 | — |
| 9 | 0x0EFA0 | 0x23 | 小表 | — |

块 5 内部：`0xB204 + 144*0x61 = 0xE894`，`0xE894 + 97*16 = 0xEEA4`。**必杀表不是独立块，而是策略块尾段。**

### 载入与复制

```
0x41B834: 0x41B51E("DATA.E5",5,[0x496F60])
          循环 144 次：0x484002 / 0x40D737  ← 逐条整理策略记录
          push 0x610 / push eax / push 0x4A7510 / call 0x4819E0
```
即 `memcpy(0x4A7510, 必杀段, 0x610)`。**0x4A7510 + 0x610 = 0x4A7B20 = 单位表基址**，布局紧邻。

### 消费者

- 访问器 `0x41E918`：`ecx = id*16 + 0x4A7510; ret`。8 个调用点：`0x4054E6`、`0x407847`、`0x417AB0`、`0x41BD16`、`0x4225D0`、`0x422622`、`0x423915`、`0x43F8EA`。
- **`+0x0D` 消费者（唯一）**：`0x484E27`
  ```
  484E27 movzx eax, byte ptr [ecx+0xD]
  484E2E pop ebp / ret
  ```
  调用链：`0x40782D`（`[0x500E9A]==2` 分支）→ `0x41E918(0x500E9B)` → `0x484E27` 读 +0xD，非 0 时 `0x40782D` 返回 1。
- **`+0x0C` 消费者（唯一）**：`0x43F8EA`
  ```
  43F8EA call 0x41E918
  43F8EF mov al, byte ptr [ecx+0xC]
  43F8F2 mov byte ptr [ebp-8], al
  43F8F5 push 5 / push 0 / push 0x32 / call 0x40CD39
  ```
  随后 `0x40CD24(0x45)` 二次判定。该函数（`0x43F8C0`）把 +0xC 当“必杀范围/类型”参与特殊目标判定。
- 其余调用点：`0x417AB0` 显示文本（`0x42F699`）；`0x4225D0` 写 `word[0x500E9A]=0x0202`（当前必杀 id）；`0x423915` 对 `[0x501C00+id]` 递减（使用次数/冷却）。

**结论**：必杀 `+0x0C`、`+0x0D` **都被引擎读取**；工具“资料字段、无消费者”的说法错误。
