# Profile 系统

## 结论速览

用户只选择 6.5 或 6.6；布局变体是 6.6 Profile 内部的物理格式差异。`ResolvedProfile` 是读取、编辑、保存和历史校验共同使用的最终定义。

## 适用版本

`ccz-6.5` 与 `ccz-6.6`。配置随核心程序集作为嵌入资源发布，运行时不依赖工作目录中额外的 JSON 文件。

## 已确认事实

- `DataProfile` 保存版本、显示名、默认布局和可用变体。
- `ProfileVariant` 保存布局 ID、样本指纹和表覆盖。
- `ProfileMatchResult` 保存匹配等级、检测方法、证据、冲突与手动覆盖状态。
- `ResolvedProfile` 保存最终表定义、模块和稳定的 `LayoutRevision`。
- 表定义包含 `RecordCodecKey`、`VerificationLevel`、布局来源、适用条件及读写能力证据；能力区分可验证、只读证据与不可用。

## 实现与使用方法

6.6 配置继承经过验证的共性表，覆盖物品记录、兵种特效分配等变体布局，并由 `ProfileAugmentationService` 根据当前文件、PE 引用和样本证据补充或覆盖运行时表定义。人物台词、名称池、R/S 和策略施展地形分别检查各自证据，不能因为 Profile 名称相同就套用全部 6.5 偏移。

例如，6.6 撤退台词使用 `Imsg.e5 + 491600`；旧的 `+440200` 区域只用于冲突诊断。6.6 装备特效名称池使用其专用布局；未取得可靠布局证据的 6.6 策略施展地形和 R/S 区域保持只读或不可用。专用二进制服务负责变长名称池、辅助分组等不适合普通定长表的区域。

启动时会校验字段范围不越过行宽，并根据 Profile、变体、表几何、字段与 codec 计算 `LayoutRevision`。修改物理布局定义会产生新的修订值；保存和历史重放继续校验当前实际布局身份。

## 风险与边界

手动覆盖只影响当前会话，不写入项目配置。切换 Profile 或变体会重新加载所有表、引用、业务页和预览关系。历史条目的修订值必须相同，或由 `LayoutRevisionCompatibility` 明确识别为本次拓展字段补齐前的已知修订；它以冻结旧清单、当前文件几何和固定算法重算指纹，未知修订仍禁止重放。手动选择版本不构成缺失字段布局的写入证据。

## 证据来源

`ProfileRegistry`、两个 Profile JSON、Profile 单元测试和跨布局历史冲突测试。

## 待验证项

当前没有通用的第三方 Profile 插件机制；新增版本应进入受测试的内置配置，而不是直接接受任意外部结构定义。
