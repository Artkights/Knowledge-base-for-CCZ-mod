# 装备类型分类与默认装备筛选

修正版本：1.2026.1022.8。适用于当前已识别的 6.4 洗隋、6.5 和 6.6 Profile。

## 分类依据

程序统一使用当前宝物记录的真实类型和类别标记，不再使用宝物 ID 分段、DefID 或 AssID。物理表 items-low/items-high 的分界仍是文件布局，人物默认装备的 0～255 仍是字段容量；两者都不用于决定武器、防具、辅助或消耗品类别。

独立核对的三个样本均在 `VA 0x0040B444` 使用相同判断：先读取运行时记录 `+0x11`；小于 20 返回类别 0，小于 26 返回类别 1，其余返回运行时记录 `+0x14`。6.5/6.6 的加载器在 `VA 0x004010E7..0x004010F5` 将文件 `+0x12` 的类别字节搬到运行时 `+0x14`；6.4 洗隋完整构造器 `VA 0x0041FECC..0x0041FF0F` 同样将文件 `+0x11` 和 `+0x12` 分别映射到运行时 `+0x11` 和 `+0x14`。原始反汇编保存在 `验证/6.4配置与装备类型修正-20261022`，6.4 完整消费链另见 `验证/6.4修正-20261022/data64消费者.md`。

| 文件中的原生类型码 | 文件类别字节 | 最终类别 | 兵种许可槽 |
| --- | --- | --- | --- |
| 0～19 | 任意 | 武器 | 对应 0～19 |
| 20～25 | 任意 | 防具 | 对应 20～25 |
| 26～255 | 0 | 武器 | 无已确认许可槽 |
| 26～255 | 1 | 防具 | 无已确认许可槽 |
| 26～255 | 2 | 辅助装备 | 不使用 26 类许可槽 |
| 26～255 | 3 | 道具/消耗品 | 不使用 26 类许可槽 |
| 26～255 | 其他 | 未知/预留 | 无 |

类型 0 是普通剑，应进入默认武器下拉。普通武器或防具的类别字节恰好是 2/3 时，仍须优先使用类型码，不能当作辅助/消耗品。6.6 动态 Codec 只有在原生类型至少为 26、类别字节为 2/3 时才转换逻辑“宝物类型”和“装备特效号”的物理地址；普通装备的特效 2/3 不再误触发交换。草稿不允许跨越会改变物理寻址的 Codec 边界，以免只改一个字段便颠倒原始字节。

## 默认装备行为

默认武器只列武器，默认防具只列防具，默认辅助只列辅助装备。选项来自当前所有已加载宝物表的草稿，名称、类型修改及撤回立即反映在下拉。编号不参与类别判断：例如 ID 200 的类型 0 是武器，ID 2 的类型 20 是防具，ID 3 的辅助类别进入辅助下拉。

255 固定显示为“无装备”。人物默认装备是单字节 ID，扩展宝物 256 及以上即使类别正确也不能写入，不出现在这三个下拉中。消耗品和未知类别不能作为新默认装备。原先已有的类别不匹配值显示 `ID：原值（类别不匹配）`，进入、离开页面或保存其他字段不会自动改写，也不会阻止无关保存；主动改变引用时执行类别校验。

页面、普通物理表、CSV、多表 CSV、XLSX 和迁移共用类别校验。一次组合操作同时改变宝物类型和人物引用时，按整次操作的最终类型判定，字段或工作表顺序不影响结果。迁移只选择人物引用、漏选必需的宝物类型修改时，整次草稿失败并保留原状态；预览所依赖的未选择类型不会被偷偷补选。

## 验证边界

`--person-equipment` 在三份原件的独立副本运行，覆盖跨 ID 类别、类型 0、普通装备类别字节 2/3、超出 26 的类别回退、未保存类型与撤回、旧错类值保留、255、扩展 ID 300 拒绝、CSV/XLSX、组合顺序和双向迁移选择完整性。`--item-migration` 验证辅助/消耗品原始字节、目标 Codec 复读和拒绝行字节保留。`--core-regression`、写回原子性及页面工作簿回归验证现有保存和交换路径。

自动化验证确认程序读写与引擎证据一致；这不等于对每份衍生 MOD 的游戏内装备行为作过穷举。字段容量、未知/保留字段和消费者损坏时的能力关闭继续遵循各 Profile 的证据。
