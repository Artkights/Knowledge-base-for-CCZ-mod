# 人物与套装特效

> 2026-10-27 更新：本页以下是旧物理模块的历史结构说明，不能作为当前引擎分配写回入口。当前三子页见 [使用入口](01-核心引擎/引擎特效复合绑定与三子页分配池.md)，精确布局见 [活动表版本差异与字段写入契约](01-核心引擎/活动表版本差异与字段写入契约.md)。洗隋9112为180×8，3890的6.5为255×8，二者仅一个兵种槽并共享整行N；25D及F20C的6.6为255×16，两个兵种槽各自N。国庆F20C由 DWORD[00500C3B] 指向00511000（文件0xE2800），不能套用本页旧固定偏移。

## 结论速览

该模块编辑人物、兵种、装备和特效值之间的纯数字关联。6.5/厚黑的兵种特效分配是 8 字节布局，标准 6.6 是 16 字节布局；人物专属/套装专属表保持 `255 x 16`。

## 适用版本

两个 Profile 的所有已登记变体。

## 已确认事实

8 字节布局包含三个 `UInt16` 人物 token、一个兵种 ID 和一个特效值。16 字节布局包含四组人物 token/特效值和两组兵种 ID/特效值。人物 token 允许 0..65535，名称解析仅覆盖实际人物表 ID。

`personal-effects` 位于 `Ekd5.exe+915456`，共 255 行、每行 16 字节。6.6 本地样本该区大多为空，因此验证等级为 `InheritedUnverified`。

## 实现与使用方法

特效业务详情和普通物理表根据当前 Profile 使用相应槽位，不把 8 字节布局的字段套到 16 字节布局。名称池由专用服务解析，说明、分配与特效值分别映射到相应物理表。人物页和人物 CSV 已移除个人/专属特效派生关联列，相关引用统一在本模块编辑。

## 风险与边界

空白、高位或未知 token 不自动改为 0、255 或任意人物 ID。1024 及以上人物 token、255 及以上兵种 token 按空/不限哨兵解释并保留实际数值。验证等级与可写能力分别显示；有可靠偏移、宽度和边界的未知数值可以编辑，缺少布局证据的表保持只读或不可用。
