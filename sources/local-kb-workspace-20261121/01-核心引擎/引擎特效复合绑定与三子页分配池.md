# 引擎特效复合绑定、三子页与分配池

## 结论速览

“宝物设定只显示一个特效号”描述的是装备渠道使用的选择键，不代表这个选择键只能对应一个效果。山贼 6.6 国庆样本中，16：无敌大斧的有效装备特效号是 37。HP 百分比加成消费者、回合恢复消费者和其他装备特效消费者分别读取这个装备号；它们使用各自的效果值模式、叠加方式和分类条件，所以同一个 37 可以在运行时形成多个同时生效的业务效果。

宝物特效管理按“业务效果 → 已定位物理绑定组 → 装备号”关联，人物/兵种另通过真实活动表行槽关联。效果号、宝物 ID、物理调用地址、表索引、兵种槽不是同一个概念，工具必须分别保存。

## 适用版本

本轮扫描和写回覆盖当前可识别的曹操传 6.4、6.5、普通 6.6 与复刻版 6.6 山贼国庆样本。固定地址只作为扫描证据；写回前仍按当前 PE 的签名、字段边界和 SHA 重新验证。国庆样本 Ekd5.exe SHA-256 为 `F20C583296AD2C167AD0C732655B1F90457AA303DF6E8E15CFAA70A822B6EF19`。

6.4洗隋9112、当前6.5的3890、普通6.6的25D、国庆F20C和历史国庆F36是独立画像。布局与字段契约的机器事实源分别见 [6.4结构](../../../_github-kb-target/6.4/data/structures/engine-effect-assignment.json)、[6.5结构](../../../_github-kb-target/6.5/data/structures/engine-effect-assignment.json)、[国庆双槽结构](../../../_github-kb-target/6.6/data/structures/engine-effect-job-slots.json)；详细版本矩阵见 [活动表版本差异与字段写入契约](../../../data管理器/知识库/01-核心引擎/活动表版本差异与字段写入契约.md)。同名或同长度不能替代完整SHA。

剧本专属和套装特技不加入本轮宝物/兵种分配池，也不创建写回草稿。

## 已确认事实

### 四参数装备入口

已确认的四参数顺序是：

```text
push 效果值模式
push 叠加方式
push 宝物特效号
push 个人/兵种特效号
ECX = 当前单位指针
call 004101D9 或相关包装入口
```

效果值模式决定读取配置值或只做拥有判断；叠加方式决定个人渠道与装备渠道如何组合。装备号 37 是共享匹配键，数值 N 仍来自对应宝物真实字段或消费者定义。工具扫描时会保存每个参数的定义链，不能把调用地址、特效名称或物品 ID 直接当作装备号。

`00413009` 的实际契约是寄存器中的 EAX/EDX 聚合与取值路径，不接受上面四个栈参数。因此它被从四参数入口集合和可分配项中排除，避免把取值内部函数误显示成可改绑效果。

当前8字节布局样本的渠道提供器真实入口为`0041301E`、活动表读取器为`004198BE`、ID写入器为`00408811`；`00413070/00419928/00408865`是退出序列地址，不能当作函数入口。两版内部`0040687C`族函数的清栈契约不同：洗隋由调用者清栈，3890由被调`ret4`。ABI事实按精确画像分别保存，不能因入口地址相同而合并。

### 无敌大斧为什么同时有 HP 与回合恢复

物品 16 的装备字段解析为 37。HP 原生消费者先通过装备分类、装备类别门槛和真实装备号判断是否命中，再沿原有等级换算和百分比计算路径得到 HP 加成。回合恢复消费者在另一条效果调用路径中也读取装备号 37，并按自己的拥有/数值模式执行。两个消费者在各自执行阶段满足条件时，分别计算能力或执行恢复，从而共同表现为这件装备的复合行为；不存在必须先把效果拼成一个新的总特效号的步骤。

国庆原始字节进一步确认：`0043C749 → 004101D9` 对应个人效果2（当前显示名“破妄归真”），四个push按顺序为 `1, 1, 37, 2`。它处于 `0043C72C` 的非零参数分支，命中后返回100，跳过 `00407AED` 装备N读取。这条恢复路径应显示“开关／不读取装备数值”；大斧原始50由原生HP消费者单独读取。名称没有“恢复”二字，工具和测试必须按消费调用身份与实际参数核对，不能按中文名字推断语义。

因此，设定页面显示的 37 与引擎中的多个“特效号”并不是一对一关系：37 是装备渠道 selector，多个效果消费者共同引用它。改绑以已证明的物理字段组为单位；同一字段的全部别名和消费者一起进入预览。一个效果号的多个独立字段分别列组，装备号已解析而字段未定位者单列原因；装备号也未知者不算已迁移。独立未知消费者不封锁已经证明的组。

### 活动表单槽、双槽与共享N

| 精确样本 | 活动表VA／文件偏移 | 行数与步长 | 分配与N |
|---|---|---|---|
| 洗隋6.4，SHA前缀91121D4B | `00508998`／`0xDA198` | 180×8，行0..179 | 三个人物槽、一个兵种槽；整行共享N |
| 当前6.5，SHA前缀3890CC32 | `00507800`／`0xD9000` | 255×8，行0..254 | 三个人物槽、一个兵种槽；整行共享N |
| 普通6.6，SHA前缀25D488C8 | 当前指针与PE解析 | 255×16 | 四个人物槽、两个兵种槽；各槽独立N |
| 国庆6.6，SHA前缀F20C5832 | `00511000`／`0xE2800` | 255×16 | 四个人物槽、两个兵种槽；各槽独立N |

8字节行的`+0/+2/+4`是三个人物UInt16 token，`+6`为唯一兵种UInt8槽，`+7`是整行共享N。`004198E5`人物命中路径与`0041990F/00419912`兵种命中路径均读取同行`+7`；修改这个N会影响同行三个人物和一个兵种。`00408811`只写ID，不写N；N是已经定位的磁盘BYTE数值字段，直接编辑不需要虚构一个原生N写函数。

每次打开项目，工具读取 `DWORD[00500C3B]`，验证其指向的活动表、PE 映射、行宽和槽位。国庆样本的指针指向 VA `00511000`，文件偏移为 `0xE2800`；活动表按效果号索引，每行 16 字节。两个兵种分配槽分别位于行内 `+0x0C/+0x0D` 和 `+0x0E/+0x0F`，每槽保存兵种 ID 与独立效果值。匹配函数0042F998使用两个栈参数并以ret 8清栈；BYTE[00505F68]非零时精确匹配，否则按同族且来源ID≤当前ID继承，命中返回AL=0，未命中AL=1。

只有兵种ID字段等于255才是空槽，0..79为详细兵种，80..254异常占用原样保留。单槽表只能显示`*1/*0`，双槽表显示`*2/*1/*0`；未知布局显示诊断，不能冒充`*0`满槽。只有`*0`标红。双槽满槽选择替换槽1、槽2或取消；单槽替换也须显示原归属及共享N影响。选择只记录目标，双击并输入N后才建立草稿。清空槽只把该槽ID写为255，保留N与其他槽字节。同族继承在详情区显示来源槽和实际影响兵种。

### 原生 HP/MP 与 255

HP 与 MP 是独立的原生能力关系，同一个装备号可以同时关联两者。适配器覆盖已验证的武器/防具三处和辅助装备三处消费者，保留其他能力分类、`0x0A` 基础能力语义、等级换算、百分比计算和累加过程。

装备通道卸下使用逻辑值255，但必须有已经安装并复读验证的装备子通道FF守卫。原始匹配器直接比较低字节，没有通用的“selector255必不命中”协议。装备位物品ID为255表示未装备，物品记录中的effect字段255和装备查询selector255则是另外两个位置，不能混称。

对已证明按低字节读取的selector，`push imm8 FF`反汇编可能显示`0xFFFFFFFF`，可以按该字段契约显示为255；这只是数值解码，不证明255具备安全禁用语义。个人selector255不能作为通用卸下值：8字节读取器直接计算行地址，洗隋仅有0..179行，3890仅有0..254行，255可能越界。个人低字节处理须逐入口核实，不能从装备字段推导。

专用守卫只让装备子通道返回未命中，外层已保存的个人结果与后续聚合继续执行；兵种槽255仍按自身空槽契约处理。低字节解码规则不扩展到效果值模式、聚合模式、寄存器聚合或未知参数。完整边界见 [字段与selector机制](../../../_github-kb-target/6.5/data/mechanisms/engine-assignment-field-policy.json)。

## 实现/使用方法

### 三个引擎扫描子页

顶部仍是“引擎扫描”，内部增加“特效管理、宝物特效、兵种特效”三个子页。

- 特效管理左侧显示 `ID：特效名`，右侧保留名称、后缀、说明、调用参数、调用链和反汇编证据。
- 宝物特效左侧显示 `ID：宝物名`，右侧上方是已分配效果，下方是待分配池。
- 兵种特效左侧显示 80 行详细兵种 `ID：兵种名`，右侧同样分为已分配与待分配。

两张分配页的四列固定为“特效号、特效名、特效值、特效说明”。消费者、槽位、来源、继承影响和不可操作原因放在表下详情。当前宝物的共享标签只读显示实际装备特效号和共用宝物，不提供把物品 ID 当作装备号的编辑框。

待分配池排除当前对象已经分配的条目，但保留未分配及分给其他对象的条目。已被其他宝物使用的效果以红色显示；选中时列出全部`ID：宝物名`并要求确认转移。业务分配操作缺少可靠写入位置时显示具体原因；扫描到名称不代表唯一可写消费者。

物理字段是否定位、玩法语义是否确认、程序是否已实现操作分别记录。已定位且边界、宽度、原字节可靠的N等字段，可以直接编辑其合法数值；没有中文名称、没有消费者或池操作尚未实现，不会使物理字段消失。代码改绑另需唯一操作数来源、完整指令边界和ABI，不由物理字段可写性替代。

双击池中条目只更新草稿；双击上方已分配条目把对应装备/兵种槽设为 255 并更新草稿。宝物首次没有有效装备号时，在预览中选择未占用的合法 0x80..0xFD 编号；普通武器/防具先按当前类别转换为对应特殊类别，不能静默写入物品 ID。辅助装备沿其真实字段写入，消耗品使用独立道具体系，不进入装备池。

### 统一事务

宝物调用点、兵种槽、HP/MP 原生关系、物品真实 N 值在一次候选中合并。写入前显示所有绑定转移、共享对象、槽位和值变化，检查当前文件 SHA、原字节、写入区间和适配器冲突。详情页卸下255与分配页HP/MP改绑联合保存时，由统一事务协调生成同一份原生关系和FF守卫载荷。相同物理位置的相同改动去重，不同改动报冲突。

统一事务创建写前备份，提交后重新扫描业务关系；失败时恢复整组文件。原生适配器把自己的版本、签名、原始调用点、helper 摘要和原文件长度放进专用 `.dmefx` PE 节。变长节安装和撤回使用完整文件快照，因此撤回会恢复原 PE 节数、文件长度和 SHA。

## 使用方法

1. 打开项目并进入“引擎扫描”。工具先扫描当前 EXE 和 Imsg，再按当前文件读取物品实际装备号、兵种表指针和原生适配能力。
2. 在“特效管理”确认效果名称、调用链和参数来源。遇到 `00413009` 时按寄存器聚合证据查看，不把它当作四参数可分配入口。
3. 在“宝物特效”选择宝物；标题旁查看实际装备号及共用宝物。双击池条目建立绑定草稿，双击已分配条目卸下为 255。
4. 在“兵种特效”选择详细兵种。按实际单槽`*1/*0`或双槽`*2/*1/*0`处理空槽；满槽选择替换或取消。8字节表修改整行共享N，16字节表修改目标槽独立N，预览应列出对应影响。
5. 点击“预览并写入全部草稿”或使用统一保存快捷键。确认预览中的调用点、共享宝物、槽位、HP/MP 改绑和值来源后再提交。
6. 写入后检查重新扫描结果；失败时不要绕过阻塞原因或套用其他版本固定偏移。

## 风险与边界

循环、包装和表驱动实例均保留完整身份；实际来源唯一且写入宽度与原字节可靠的物理组开放分配，同组全部别名联动，给同一字段设置不同目标时拒绝提交。另一个未定位消费者不封锁独立已定位组。共享来源若跨装备、个人或模式参数角色，则禁止独立改写；只读或未解析参数的定义链也参加危险共享检测。当前洗隋9112的180×8、3890的255×8与25D/F20C的255×16布局已经静态复核，并有全行、边界、损坏拒绝和临时副本事务测试。其他构建仍须按当前文件独立定位，不能继承同版本或国庆固定偏移。字段事实与当前程序支持状态分别更新，不因尚未实现某操作而写成“引擎没有这个字段”。

同一个装备号是全局共享关系。把效果从 37 卸下会影响所有共用 37 的宝物，因此预览必须列出全部对象。共享 N 的修改同样会影响所有读取该物品字段的效果。原生能力关系不能通过修改单一分类表字节伪造，必须安装并校验专用适配。
