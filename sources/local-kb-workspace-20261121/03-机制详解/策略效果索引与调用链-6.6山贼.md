# 策略效果索引与调用链（6.6 山贼）

## 结论速览

- 策略释放后“发生什么”，不是由工具里的“效果索引/Mg8”直接决定，也不是由 `Data.e5` 策略行的 `+0x0B` 直接决定。
- 真正的运行时分派表是 `Ekd5.exe` 的 **144 字节效果类表 `0x004D1570`**（文件 `+0xA2D70`）：`class = byte[0x4D1570 + 策略ID]`，再用 `class` 查处理器跳表 `0x004259C3`（文件 `+0x24DC3`）。
- 处理器把“效果标识”写入策略上下文 `0x00497AF8+0x400`（总标识）和 `+0x401+目标序号`（逐目标标识），再由逐目标应用代码消费。
- 这套结构在 EXE 里是**数据表 + 代码跳表**：换策略效果改数据表即可；换“这一类效果的具体结果”（例如烧山变成什么地形）要改处理器里的代码立即数。
- 本文只绑定当前 `基底\复刻版6.6山贼\Ekd5.exe`（SHA-256 `25D488C874A08553903CDAD9A07FF6FBCD1A38EE6C6B6386F40152DA963D833A`）与 `Data.e5`（SHA-256 `C4B57DD0A9DC3EF2A7FE4D6A36EEAF0F7EDEA06BF2F6407B1A8AE3252E5807CE`）。知识库旧页使用的 `6929FE0D…` 是另一批次样本，地址不可混用。

## 一、先分清四个“索引/标记”

| 名称 | 物理位置 | 取值 | 是否直接决定效果 |
|---|---|---|---|
| 工具“效果索引”/`Mg8` | `0x004D17B0`（文件 `+0xA2FB0`），144 字节 | 位掩码 `0x01/0x02/0x04/0x08…` | **否**。它是分类筛选位，不是处理器索引 |
| `Data.e5` 策略类型 `+0x0B` | `Data.e5 +0xB204 + 策略ID*0x61 + 0x0B` | `0x00..0x2A` | **否**。影响 AI/合法性/界面分组，不直接选处理器 |
| 运行时效果类表 | `0x004D1570`（文件 `+0xA2D70`），144 字节 | `0x00..0x29`，`0x90` 表示无效果 | **是**。这是分派用的“效果类索引” |
| 运行时效果标识 | `0x00497AF8+0x400`、`+0x401+序号` | `0x40..0x5B` 等 | 是处理器产物，供逐目标应用/动画/状态消费 |

> 旧形象指定器里的 `Mg8=667568 / 0xA2FB0` 对应 `0x004D17B0`。它和 `0x004D1570` 相邻但用途不同：前者是分类位，后者是处理器类。不要把两者互相写入。
>
> 旧知识库“战斗数据结构”页写的 `497AF8+254/+255` 是 6.4/6.5 口径；当前 6.6 样本的效果标识在 `+0x400/+0x401`，两者不能混用。

## 二、完整调用链

### 2.1 使用入口

```text
玩家/AI 选择策略
  → 0x0041C0E8 / 0x004179E3 等使用包装
  → 0x00425627(ECX = 0x00497AF8)
```

`0x00425627` 先调用 `0x004251E1` 初始化策略上下文，再调用 `0x0046FCF8` 取得行动结果，然后进入效果分派。

`0x004251E1` 的关键写入：

```asm
004251EE  mov dl,[ebp+8]
004251F1  mov [ecx],dl          ; ctx+0x00 = 策略 ID
004251F6  mov [ecx+1],edx       ; ctx+0x01 = 施法者战场编号
004251F9  mov byte [ecx+0Ch],0FFh
00425207  mov [edx+8],ecx       ; ctx+0x08 = 施法者战术单位指针
00425212  mov [edx+4],ecx       ; ctx+0x04 = 施法者人物记录
00425283  add eax,0Dh           ; 清 +0x0D 目标表（0xFB 字节）
00425299  add eax,108h          ; 清 +0x108 伤害数组（0x3F3 字节）
004252AE  add eax,50Ah          ; 清 +0x50A 附加区（0x42 字节）
```

这解释了后续处理器为什么都从 `ctx+0x0D` 取目标、往 `ctx+0x108` 取伤害、往 `ctx+0x400/0x401` 写效果标识。

### 2.2 效果分派

`0x00425627` 内：

```asm
0042569C  movzx eax, byte ptr [ecx]        ; ECX = 0x00497AF8，[ECX] = 当前策略 ID
0042569C  cmp al, 90h
0042569E  jae 00425988                     ; 策略 ID >= 0x90：跳过效果
004256A4  mov al, [eax + 4D1570h]          ; ★ class = 效果类表[策略ID]
004256AA  jmp dword ptr [eax*4 + 4259C3h]  ; ★ 查处理器跳表
```

要点：

- 索引是**策略 ID**（`0..143`），不是 `+0x0B` 的策略类型。
- `0x4D1570` 的值 `0x90` 表示“该策略没有效果处理器”，直接走公共收尾。
- `0x4259C3` 是 43 项（`0x00..0x2A`）的代码指针表；`0x2A` 与 `0x00` 共用默认项。

### 2.3 处理器写入效果标识

每个处理器先写 `ctx+0x400`，再调用对应的应用函数：

```asm
; 以毒烟为例
00425743  mov byte ptr [edx], 49h          ; EDX = ctx+0x400
00425750  xor eax, eax                     ; 0 = 产生（对敌方）
00425759  push eax
0042575A  mov ecx, [ebp-4]
0042575D  call 004231A8h                   ; 状态应用
```

`ctx+0x400` 是总效果标识；逐目标应用时复制/写入 `ctx+0x401+目标序号`。

### 2.4 逐目标应用

```text
0x00422700 目标循环
  → 读 ctx+0x401+序号
  → 0x00422746 查字节表 0x00422BC2
  → 0x0042274E jmp [eax*4+0x00422AA0]      ; 效果分类跳表
  → 动画/状态/数值应用
```

这部分负责“每个目标显示什么效果、扣什么状态”，与处理器写标识是两级结构。

## 三、三个样例的逐段追踪

### 3.1 毒烟：中毒状态

| 项目 | 值 |
|---|---|
| 策略 ID | `46`（`0x2E`） |
| `Data.e5` 策略类型 `+0x0B` | `0x10` |
| 效果类 `0x4D1570[46]` | `0x09` |
| 处理器 | `0x00425743`（文件 `+0x24B43`） |
| 写入效果标识 | `0x49` |
| 应用入口 | `0x004231A8` |

处理器：

```asm
00425743  mov byte ptr [edx], 49h     ; ctx+0x400 = 0x49
00425750  xor eax, eax                ; 0 = 产生状态
0042575D  call 004231A8h
```

`0x004231A8` 把“产生/取消”转成内部模式，进入 `0x004231C2`：

```text
0x004233F8  取目标、写 ctx+0x0C、校验
0x0042E5CC  对目标施加状态
0x00423594  计算/写入持续回合
0x004251BD  刷新/收尾
```

`0x0042E5CC → 0x0042E5E9` 会遍历 `ctx+0x0D` 目标表，并对每个目标调用通用效果查询 `0x004101D9`（参数含 `0xCA`、`0x85` 通道）。毒烟的具体中毒位由这条状态链写入，不是由 `+0x0B` 直接写。

同类：`毒雾` ID `47` 也是 `class 0x09`，与毒烟共用处理器。

### 3.2 霸气：自身全能力提升

| 项目 | 值 |
|---|---|
| 策略 ID | `85`（`0x55`） |
| `Data.e5` 策略类型 `+0x0B` | `0x1A` |
| 效果类 `0x4D1570[85]` | `0x19` |
| 处理器 | `0x0042579C`（文件 `+0x24B9C`） |
| 写入效果标识 | `0x57` |
| 应用入口 | `0x00424374` |

处理器：

```asm
0042579C  mov byte ptr [edx], 57h     ; ctx+0x400 = 0x57
004257A5  call 00424374h
```

`0x00424374`：

```asm
00424378  mov dl, [ecx+1]              ; 施法者战场编号
0042437D  mov [ecx+0Ch], dx            ; 写入目标槽
00424386  call 0045461Ch               ; 目标/范围准备
0042439C  call 0042044Dh               ; 目标合法性
004243A8  mov dl, [ecx+400h]
004243AE  mov [ecx+401h], dl           ; 总标识复制为逐目标标识
004243B5  call 004251BDh
004243BD  call 00416F0Fh               ; 能力提升应用
```

霸气行 `+0x10 = 0x13`（19）是这类效果的参数；`+0x11..+0x60` 是 80 个兵种的学会等级，`+0x11..+0x13 = 0F 0F 0F` 是兵种 0..2 的学会等级，不是效果参数。`0x00416F0F` 用 `+0x10` 和行内其他基础字段应用增益。

### 3.3 放火烧山：目标地形变火

| 项目 | 值 |
|---|---|
| 策略 ID | `123`（`0x7B`） |
| `Data.e5` 策略类型 `+0x0B` | `0x26` |
| 效果类 `0x4D1570[123]` | `0x29` |
| 处理器 | `0x00425800`（文件 `+0x24C00`） |
| 写入效果标识 | `0x40` |
| 应用入口 | `0x0044C74D` |

处理器：

```asm
00425800  mov ecx, [ebp-4]
00425803  mov al, [ecx]               ; 当前策略 ID
00425805  mov byte ptr [edx], 40h     ; ctx+0x400 = 0x40
00425808  call 0044C74Dh
```

`0x0044C74D` 遍历目标，取目标坐标，再调用地图地形写入：

```asm
0044C756  call 00423198h              ; 取目标/命中判断
0044C780  call 004061F9h              ; 目标槽 → 单位
0044C785  call 00403360h              ; 单位 → 坐标
0044C78A  movzx eax, word ptr [eax]   ; 坐标打包
0044C7E5  push 0
0044C7E7  push 1
0044C7E9  push 1
0044C7EB  push 0
0044C7EC  push 1Dh                     ; ★ 地形类型 = 0x1D
0044C7EE  mov al, dh                   ; y
0044C7F0  push eax
0044C7F1  mov al, dl                   ; x
0044C7F3  push eax
0044C7F9  call 004560F3h               ; 地图区域地形写入
```

结论：

- “变成火”不是 `Data.e5` 行里的一个字段，而是 `0x44C7EC` 的立即数 `0x1D`。
- 六个烧山策略（`123..128`）都映射到 `class 0x29`，所以共用同一个 `0x1D`。
- 它们的差异在 `Data.e5` 行的攻击范围、穿透、MP、参数，不在“地形类型”。

## 四、是否可以更改

### 4.1 推荐改法：换效果类

改 `0x4D1570 + 策略ID` 的一个字节：

- 文件位置：`0xA2D70 + 策略ID`；
- 取值：`0x00..0x29` 为有效处理器类，`0x90` 为无效果；
- 例：把 `0xA2D70 + 46` 从 `0x09` 改成 `0x00`，毒烟会变成单目标伤害类；改成 `0x19`，会走自身全能力提升类。

风险：

- 参数不匹配。伤害类、状态类、增益类读取的行内参数不同；只换类会把原参数解释成别的含义。
- 动画/效果标识不匹配。类处理器会写不同的 `ctx+0x400` 标识，逐目标应用与动画按标识走。
- AI/合法性仍看 `+0x0B` 类型与 `Mg8` 分类；只换 `0x4D1570` 不会同步改变 AI 判断。
- `0x4D1570` 不只服务主分派。静态引用共 8 处，全部是读取，没有发现写入：主分派 `0x4256A6`，以及 `0x4214D5`、`0x4218C1`、`0x4226B9`、`0x43C5F1`、`0x45549F`、`0x46FB6F`、`0x46FE12`。其中 `0x43C5EF` 按类 `0x0C/0x1C/0x0E` 分支，`0x46FB6D`/`0x45549D` 按类 `0x1A` 分支。换类可能同时改变这些旁路逻辑。

### 4.2 改“这一类效果的具体结果”

| 想改 | 改哪里 | 文件偏移 | 影响范围 |
|---|---|---|---|
| 烧山后的地形类型 | `0x0044C7EC` 的 `1D` | `+0x4BBEC` | 所有 `class 0x29` 策略 |
| 毒烟的效果标识 | `0x00425743` 的 `49` | `+0x24B43` | 所有 `class 0x09` 策略 |
| 霸气的效果标识 | `0x0042579C` 的 `57` | `+0x24B9C` | 所有 `class 0x19` 策略 |
| 状态查询通道 | `0x0042E619` 的 `85`、`0x0042E61E` 的 `CA` | `+0x2DA19`、`+0x2DA1E` | 状态应用族 |
| 单策略范围/MP/参数 | `Data.e5 +0xB204 + ID*0x61 + 0x0C..` | `Data.e5` 行内 | 仅该策略 |

这些是**代码立即数**，不是每策略数据。改一个字节会影响整类策略；写入前必须按当前基底 SHA、旧字节和调用边界做校验与备份。

### 4.3 新增效果类：6 个现成空槽

跳表 `0x4259C3` 后面还有 6 个有效项，全部指向默认处理器 `0x4256B1`：

```text
class 2A → 0x4256B1    class 2B → 0x4256B1
class 2C → 0x4256B1    class 2D → 0x4256B1
class 2E → 0x4256B1    class 2F → 0x4256B1
class 30 → 0x90909090（无效，不能使用）
```

当前 144 个策略没有任何一个使用 `0x2A..0x2F`（分组表里只到 `0x29` 和 `0x90`）。因此可以：

1. 在代码洞里写一个新处理器；
2. 把 `0x2A..0x2F` 中某一项的表项改成新处理器地址；
3. 把目标策略的 `0xA2D70+ID` 改成这个类。

表项位置：

```text
0x2A → 文件 +0x24E6B
0x2B → 文件 +0x24E6F
0x2C → 文件 +0x24E73
0x2D → 文件 +0x24E77
0x2E → 文件 +0x24E7B
0x2F → 文件 +0x24E7F
```

处理器 ABI（与现有处理器一致）：

- 进入时 `ECX = 0x497AF8`，`EDX = 0x497AF8+0x400`，`[EBP-4] = 0x497AF8`；
- 写 `byte [edx]` 设置效果标识；
- 用 `mov ecx,[ebp-4]` 后调用现有应用入口；
- 结束后必须 `jmp 0x425810` 走公共收尾，不能 `ret`。

最小形态（示例：设置 `0x5B` 后走通用应用）：

```asm
mov byte ptr [edx], 5Bh
mov ecx, [ebp-4]
call 00423230h
jmp 00425810h
```

如果六个固定类不够，可以：

- 写一个“通用自定义处理器”，在扩展区按策略 ID 读参数表，再执行少量操作（设标识、调应用入口、改地形、加状态）；
- 或者把整张跳表搬到代码洞，改 `0x4256AA` 的 `jmp [eax*4+4259C3h]` 位移，支持更多项。后者是代码补丁，风险和验证成本更高。

**纯数据不能新增效果类。** 因为跳表项是代码地址，数据只能把类指向已有处理器；新增行为至少需要一个代码洞处理器和一个表项。

### 4.4 不建议改的地方

- `0x004259C3` 处理器跳表：它是代码指针表；改它等于把类指向任意代码地址，风险远高于换 `0x4D1570` 的值。
- `0x004D17B0`（`Mg8`）：它只影响分类筛选；把它当效果索引写不会改变实际效果。
- `Data.e5 +0x0B`：它影响 AI/合法性/界面；单独改它不会换处理器。

## 五、验证方法与边界

已完成的静态验证：

1. 在 6.6 山贼 `Ekd5.exe` 中定位 `0x0042569C..0x004256AA` 的分派序列，确认索引是 `[0x497AF8]` 策略 ID，表是 `0x4D1570`，跳表是 `0x4259C3`。
2. 读取 `0x4D1570` 144 字节，确认 `ID46=0x09`、`ID85=0x19`、`ID123..128=0x29`，其余样例与 `Data.e5` 类型相关但不相等。
3. 逐段反汇编 `0x425743`（毒）、`0x42579C`（霸气）、`0x425800`（烧山）及各自应用函数。
4. 确认 `0x44C7EC` 的地形立即数为 `0x1D`，且 `0x4560F3` 按 `(x,y,地形,...)` 写入地图。

尚未闭环：

- 毒烟的最终中毒状态位、持续回合公式，以及 `0x4101D9(0xCA,0x85)` 两个通道的业务名称，仍需固定战场实机采样。
- `地形 0x1D = 火` 由“放火烧山”样例与 `0x4560F3` 调用路径推断，尚未用地图地形表或实机截图逐项确认；`0x1D` 也可能只是“区域改地形”操作码，火属性来自另一层表。
- 霸气 `+0x10` 单个参数与具体能力项的对应关系，需要逐项改值对照；`+0x11..+0x60` 是兵种学会等级，不参与效果计算。
- `class 0x29` 以外的全部处理器语义只按旧论坛索引族归类，未逐类实机验证。
- 本页没有修改任何 EXE 或 `Data.e5`；所有偏移都以当前 SHA 为准。

## 六、版本边界

- 6.5 的同址 `0x00425690` 区域是 NOP，`0x4D1570` 表内容也与 6.6 不同；**不能把本文地址套到 6.5/6.4**。
- 6.6 同族改版可能重排代码或改写 `0x4D1570`；使用前先核对 `Ekd5.exe` SHA 与 `0x0042569C` 附近字节。
- 旧知识库 `复刻版6.6山贼运行时数据结构.md` 绑定 `6929FE0D…`，与当前 `25D488C8…` 不是同一文件；本文不复用其地址结论，只复用其结构分类方法。
