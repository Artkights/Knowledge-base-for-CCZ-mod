### 一、「托管我军主动出击」的**精确实现**（非补丁、非注入）

源码级证据：`ai使用库\扳手\mywindow.py:4175-4189`

```python
if n == 8:                                   # checkBox_8 = 「托管我军主动出击」
    if self.checkBox_8.isChecked():
        for i in range(0, cnt_wo + cnt_you):         # 只遍历 我军 + 友军
            ReadProcessMemory(addr_war + i*len_war, data, 2)
            if data.value == 65535: continue         # 0xFFFF = 空槽
            WriteProcessMemory(addr_war + i*len_war + 0xE, 1, 1)   # ★ 写 1 = 主动出击
    else:
        ... 同上，写 7                              # 7 = 可控
```

- **只改一个字节**：`unit + 0x0E`（AI 方针）。
- 6.6 几何（`engine_profile.py:2368,2393-2396`）：`addr_war=0x004A7B20`、`len_war=0x30`、
  `ours=20 / friends=40 / enemies=190`。
- 本机复现脚本：`_42托管我军.py`（带**快照回滚**，比扳手多一层安全，扳手不回滚原值）。

### 二、结束回合：按键无效，**右键空地才是唯一有效路径**

| 方式 | 实测结果 |
|---|---|
| 空格 `0x20` | ❌ 不弹确认框 |
| 回车 `0x0D` | ❌ 不弹 |
| End `0x23` | ❌ 不弹 |
| **右键空地 → 确认框 → 点「是」** | ✅ **有效**（确认框 `#32770`、正文含「就这站位？等着sl吧」、`是` 在 (890,544) 附近） |

- 实现：`_42结束回合.py` 的 `end_turn_rclick()`（主路径）与 `end_turn()`（按键法，保留但会失败）。
- ⚠️ **托管与结束回合是两件事**：托管只让单位自动出手，**不代替玩家"结束回合"输入**。

### 三、★ 主将阵亡的真实流程（**纠正旧口径**）

- 用户口径（2026-10-15）：主将（0 号）阵亡 ⇒ 弹出对话框「**菜就别玩了**」⇒ **点「是」跳回主界面**。
- 实机核对：**进程没有退出**（PID 不变、窗口仍在），窗口尺寸回到标题页的 800×550 左右。
- ⇒ **纠正**旧口径「主将阵亡 → 战斗结束 → **游戏退出**」：准确说法是
  **"主将阵亡 → 结局框 → 点「是」→ 回到标题页"**，进程存活，可**直接重读 `No.001` 续测**。
- 自动化闭环（`_42结束回合.py` + `_42主动战斗批次.py` 的 `ensure_battle()`）：
  `检测对话框 → 点「是」→ 等"对话框清空 + 标题页判据" → 调 _自动读档进战场.py --go-safe 读 No.001 → 继续打`。

    **正确判据 = 对话框消失 AND 标题页判据**（已修）。

### 四、实时保命（用户口径：快死就加血，别等下一回合人死完）

- 唯一写入点：**`unit + 0x10`（当前 HP，dword）** —— 与 `_自动战斗识别.py` 的"保底写 HP"同源。
- `_42实时保命.py`：每 0.15 秒扫我军/友军非空槽；
  `HP > 0` 且 `HP < 观察峰值 × --ratio` ⇒ 写回峰值（或 `--to` 固定值）；
  **HP==0 的不碰**（真死需要引擎复活函数 `hk.life`，扳手走 `revive_entry_address`，不在本工具范围）。
- 不在战场（无 SmallMap / 战场宽 0）自动跳过，避免在标题页误写。
- 实测：`--ratio 0.35` 时按日志回填 9 次（slot1/slot3 在 165~271 血时被拉回 594/862）。

### 五、★ 断点卡死根因（本轮最贵的教训）

| 环节 | 事实 |
|---|---|
| 现象 | 游戏 `Responding=False`（窗口不响应），**PowerShell 命令也跟着卡住**（`Start-Sleep`/`Get-Content` 全部超时） |
| 根因 | `_42入参条件断点.py` 在 `0x4287A8` 挂**条件断点**；该地址**每次攻击都命中**；条件 `cip%20==0` 仍会频繁暂停；第 40 号作业被 kill 时**清断点没走完**，断点留在进程里 |
| 判据 | `debug_get_state` = `paused` + `Get-Process Ekd5` 的 `Responding=False` + `breakpoint_list` 非 0 |
| 处置 | `breakpoint_delete_all` → **循环 `debug_run` 直到 `running`**（实测第 3 次恢复） → 确认 `Responding=True` |
| 预防 | ① 高频地址**禁止普通断点**，条件断点也要 `cip%50==0` 以上；② 探针脚本必须 `try/finally` 清断点；③ **探针与战斗驱动不要同时跑**；④ 一旦发现 `Responding=False`，先清断点再谈别的 |
