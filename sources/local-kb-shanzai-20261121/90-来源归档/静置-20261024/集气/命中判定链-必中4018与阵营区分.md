# 命中判定链（必中 / 集气闪避 / 阵营区分 / 与 star6.6x 参考文本对照）

## 结论速览

- **「我方回合必中」是这份 6.6山贼基底自带的**，判定在三处：
  **① `0x43B60A` `cmp byte [0x500E9B],0 / jne ⇒ 必中`**、
  **② `0x43B4E8`~`0x43B51E`（`4018`=`0x505EC8` + `0x4B3D18` + 攻击者 `unit+5` 三判据 ⇒ 命中率置 `0x64`）**、
  ③ `0x43B7D7`（策略函数里的特效 `0x1B` 必中）。**三处都在原始基线 `AA1DB360…` 里逐字节相同**。
- **必中 = 把命中率写成 `0x64`（100）**，不是把判定短路成 true；`0x43B526 jae` 会让 100 跳过集气闪避判定。
- **★★ 集气模式下命中率的含义要反过来看**：`0x4287A8(值, 模式)` 里"谁在攒"由 **`[ebp+8]`** 决定——
  **`[ebp+8] == 1` = 防守方分支**：`闪避池 + 100 − 命中率 ≥ 100` ⇒ **闪避触发**，并把池 `−100` 写回；
  **`[ebp+8] == 0` = 攻击方分支**：`池 + 值 ≥ 100` ⇒ **触发暴击/连击**，并把池 `−100`。
  ⇒ **防守方池每收一次攻击，涨 `100 − 命中率`**（不是涨命中率）；命中率 100 ⇒ **涨 0 ⇒ 永远攒不满 ⇒ 必中**。
- **集气 4 字节（KB 已实机确认）**：字节 0 连击、字节 1 物理闪避、字节 2 暴击、字节 3 策略闪避；
  数组 `0x4930C8 + slot*4`（slot = 战场编号，单位记录 `+4`）。
- **引擎只用一个字节区分阵营**：**`unit+0x05`**（`0=我军`、`1=友军`、`2=敌军`）——**这是本页最重要的可复用结论**。
- **与 `【star6.6x】我方回合必中.txt` 的实质差异只有 1 处**：参考文本的阵营门是 **`[ecx+5] ≤ 1`（我军 + 友军）**，
  我们的是 **`[ecx+5] == 0`（只我军）** ⇒ **友军不吃这个必中**。其余三判据、结构、实现位置**完全等价**。

## 已确认事实

### 一、`0x43B600`：物理命中的"两段式"结构（先过滤，再算率）

`0x43B600(ecx = 攻击者, [ebp+8] = 0, [ebp+0xC] = 目标, [ebp+0x10] = 0xFF, [ebp+0x14] = 1)`
——由 `0x43B4B6` 在 `0x43B4CA` 调用（`0x43B4B6` 是**命中率总函数**）。

0043B61B  FF 75 0C                push  [ebp+0xC]           ; 目标
0043B61E  E8 7A 04 00 00          call  0x43BA9D            ; 物理免疫判定（读目标特效 0x31）
0043B623  85 C0                   test  eax, eax

0043B62D  E8 CE 89 0A 00          call  0x4E4000            ; 特效 0xE0（0x4E401B → 0x42518F(0xE0,0xE0,1,0)）

**两条出口的含义**（很容易看错）：

| 出口 | 指令 | 含义 |

### 二、`0x43B4E8`~`0x43B51E`：`4018` 那套必中（物理 + 策略共用）

物理走 `0x43B600`、策略走 `0x43B730`，两条在 **`0x43B4DA` 合流**，所以下面这块两条路径共享：

```asm
0043B4DA  85 C0                    test  eax, eax
0043B4DC  74 56                    je    0x43B534           ; 命中率 0 ⇒ 直接返回 0
0043B4DE  83 F8 19                 cmp   eax, 0x19
0043B4E1  73 05                    jae   0x43B4E8
0043B4E3  B8 19 00 00 00           mov   eax, 0x19         ; ★ 命中率下限 25
0043B4E8  90 × 21                  nop   ×21              ; ★ 21 字节 NOP（可用的改造空间）
0043B4FD  B9 B2 0F 00 00           mov   ecx, 0xFB2        ; ★ 0xFB2 = 4018
0043B502  83 3C 8D 00 20 50 00 00  cmp   dword [ecx*4+0x502000], 0   ; → [0x505EC8]
0043B50A  74 17                    je    0x43B523          ; ≠1 ⇒ 不做必中
0043B50C  80 3D 18 3D 4B 00 00     cmp   byte [0x4B3D18], 0 ; ★ 我方回合？
0043B513  75 0E                    jne   0x43B523          ; 不是 ⇒ 不做必中
0043B515  8B 4D FC                 mov   ecx, [ebp-4]      ; ★ 攻击者
0043B518  80 79 05 00              cmp   byte [ecx+5], 0   ; ★ 攻击者阵营 == 我军？
0043B51C  75 05                    jne   0x43B523          ; 不是 ⇒ 不做必中
0043B51E  B8 64 00 00 00           mov   eax, 0x64        ; ★★ 命中率 = 100
0043B523  83 F8 64                 cmp   eax, 0x64
0043B526  73 0C                    jae   0x43B534         ; ★ 100 ⇒ 跳过集气闪避判定
0043B528  50 / FF 75 F8 / FF 75 F4
0043B52F  E8 74 D2 FE FF           call  0x4287A8         ; 集气/闪避判定
0043B534  8B E5 / 5D / C2 0C 00
```

**判据对照用户口径**：

| 用户口径 | 机器码 | 结论 |
|---|---|---|
| 整型 `4018 = 1` | `0x43B4FD mov ecx,0xFB2` + `0x43B502 cmp dword [ecx*4+0x502000],0` | ✅ `[0x505EC8]` |
| 我方回合 | `0x43B50C cmp byte [0x4B3D18],0` | ✅ 阶段门**在**（`0x4B3D18` = 阶段编号，`0` = 玩家可控阶段） |
| 我方单位 | `0x43B515 mov ecx,[ebp-4]`（攻击者）+ `0x43B518 cmp byte [ecx+5],0` | ✅ 阵营门**在**，但**只放我军** |
| 物理 + 策略都必中 | 两块在 `0x43B4DA` 合流后才判 | ✅ 两条路径共享 |

**语义表**（`P` = 池当前值、`H` = 传入值）：

| `[ebp+8]` | 分支 | 公式 | 触发条件 | 写回 | 触发时 `eax` |
|---|---|---|---|---|---|
| `1` | **防守方**（闪避） | `P + 100 − H` | `P + 100 − H < 100` ⇔ **`P < H`** | `−100` | `1` |
| `0` | **攻击方**（暴击/连击） | `P + H` | `P + H ≥ 100` | `−100` | `1` |
| 任意 | 未触发 | 同左 | 不成立 | 同左（可 `±100`） | `0` |

⇒ **闪避池每收到一次攻击涨 `100 − H`**（`H` = 命中率）。**命中率越高 ⇒ 涨得越少 ⇒ 越难闪避**。
⇒ 命中率 `100` ⇒ 每次涨 `0` ⇒ **池永远攒不满 ⇒ 必定命中**；这正是"必中"的实现方式。
⇒ 命中率 `0` ⇒ 涨 `100` ⇒ **下一次攻击必被闪避**。

**已知调用点与实际传入**：

| 调用点 | 模式 `[ebp+0xC]` | `[ebp+8]`（分支） | 字节 | 类别 |
|---|---|---|---|---|
| `0x406130` | `0`（`push 0`） | 连击率（来自 `0x4E40E0`） | **0** | **连击** |
| `0x43B52F`（物理） | `[ebp-8]`（实机 = `1`） | 命中率 | **1** | **物理闪避** |
| `0x405EDD` | `2`（`push 2`） | 暴击率（`0x40C7D8`） | **2** | **物理暴击** |
| `0x40CAAB` | `0x12`（`push 0x12`） | 策略暴击率（`0x401DAC`） | **2**+策略上下文 | **策略暴击** |
| `0x43B52F`（策略） | `[ebp-8]+0x12`（实机 = `19`） | 命中率 | **3** | **策略闪避** |

> 连击/暴击的 `[ebp+8]` 是"本次率"，闪避的 `[ebp+8]` 是"命中率"——
> **同一个函数、同一个公式，闪避为什么反着用？**
> 因为设计上是"**池涨 = 100 − 命中率**"：把 `H` 代成"命中率"就得到 `P += 100 − H`。
> 换句话说 **`0x4287A8` 的 `[ebp+8]` 语义是"这次还剩多少没被这次攻击吃掉"**，
> 对连击/暴击是"本次积累量"，对闪避是"本次被命中率抵消掉的部分"。**改代码前必须记住这个方向**。

### 四、引擎如何区分命中 / 我军 / 敌军 / 友军

| 维度 | 载体 | 编码 | 证据 |
|---|---|---|---|
| **阵营** | **`unit+0x05`** 单字节 | **`0=我军`、`1=友军`、`2=敌军`** | `0x43B518`；`0x406710 movzx eax,[ecx+5]`；KB 三处一致 |
| 阶段 | `0x4B3D18` 单字节 | `0` = 玩家可控阶段（我方回合）；`!=0` = 其他阶段 | `0x4024CC`、`0x43B50C` |
| 命中 | **返回命中率 0~100，不是布尔** | `0`=不中、`100`=必中、`1~99`=交 RNG | `0x43B4DA`~`0x43B534` |
| 麻痹 ⇒ 物理必中 | 目标 `unit+0x1E` 第 0 个 2-bit 窗口 | `0x43B647 mov ecx,[ebp+0xC]`（**目标**）+ `push 2` | `0x423FE8` |
| 混乱 ⇒ 策略必中 | 同字节第 2 个窗口（`push 8`） | 待实机验证 | — |

> **「必中」= 命中率写 100**；**「免疫物理」是更早的另一条判定**（`0x43B61B → 0x43BA9D`，
> 读**目标**的特效 `0x31`，返回 `0 = 免疫`）——两者互不干扰，别混。

### 五、与 `【star6.6x】我方回合必中.txt` 的逐项对照

参考文本的三段：

| 段 | 参考文本字节 | 作用 |
|---|---|---|
| `-43B680` | `E8 32 FF FF FF` = `call 0x43B2B7`? 更可能是 `call 0x43B5B7`（原文写法歧义） | 把物理函数 `0x43B680` 处的"特效 0x24 判定"换成必中判定 |
| `-43B7D7` | `E8 DB FD FF FF` → `0x43B7D7 + 5 + (−0x225) = 0x43B5B7` | 把策略函数 `0x43B7D7` 处的"特效 0x1B 判定"换成必中判定 |
| `-43B5B7` | 53 字节 | 必中判定本体（含完整序言，因为原序言在 `0x43B4A7`…被跳过） |

参考文本的判定本体解码：

```asm
push ebp / mov ebp,esp / push ecx / push [ebp+0x14] / push [ebp+0x10] / push [ebp+0xC] / push [ebp+8]
call 0x42518F                    ; 原逻辑：特效判定
test eax,eax / jnz 0x43B5D5      ; 有特效 ⇒ 走原流程
cmp byte [0x500E9B], 0           ; ★ 另一个开关（不是 4015，也不是 4018）
je  0x43B5D5
cmp byte [0x4B3D18], 0           ; ★ 我方回合（与我们一模一样）
jne 0x43B5D5
pop ecx
cmp byte [ecx+5], 1              ; ★★ 阵营门：我军(0) 与 友军(1) 都放行
ja  0x43B5D4
inc eax                          ; 必中
mov esp,ebp / pop ebp / ret 0x10
```

**对照表**：

| 判据 | star6.6x 参考文本 | 本样本（6.6山贼） | 是否等价 |
|---|---|---|---|
| 开关变量 | `0x500E9B` | **`4018` = `0x505EC8`**（`0x43B4FD`） | 不同变量，但都是"非 0/==1 ⇒ 开" |
| 我方回合 | `[0x4B3D18] == 0` | **`0x43B50C` 同款判据** | ✅ **完全一致** |
| 阵营门 | **`[ecx+5] ≤ 1`（我军 + 友军）** | **`[ecx+5] == 0`（只我军）** | ❌ **差友军** |
| 实现方式 | 改 `call` 目标到自建洞体 | 直接写在 `0x43B4E8` NOP 区 | 不同写法，效果等价 |
| 生效范围 | 物理 + 策略两个 `call` 点 | 物理 + 策略合流点之后 | ✅ 等价 |

## 风险与边界

- **`4018` 是二合一变量**：改它 = 同时开/关集气与必中。要拆开必须另找整型槽位。
- **`0x43B526 jae` 会让"必中"绕过集气闪避**：命中率 100 时防守方池**不涨不减**。
  如果将来把必中改成"命中率 = 99"或"显式放行"，就会重新走集气判定——**改之前先想清楚要哪种**。
- **`0x43B518` 只放我军**，因此**友军和敌军都不吃这个必中**；但**敌军的攻击**若由我军单位发起反击，
  反击的"攻击者"仍是我军 ⇒ **反击也会必中**（这是原设计，不是 bug）。
- **集气模式外（`4018≠1`）没有这层必中**，走原版随机路径（`0x43786B`）。
- **参考文本不能照抄**：它的两个 `call` 点在本样本是特效判定链（`0x42518F`），顶掉即失去辅助命中/格挡能力。
- **`0x4B3D18` 在文件里初值 0 且**无直接写点**（我扫过 `C6 05` / `A2` / `88 0D` / `89 0D` 全无），
  说明它由运行时**间接**写入；因此"我方回合 == 0"这条口径来自 `0x4024CC` / `0x43B50C` 的用法，

## ★★ 2026-10-15 定案：两条规则的完整实施链（用户口径 ①我方回合必中 ②敌军每四次）

> 用户口径（2026-10-15）：**`4018=1` 集气模式下，①我方回合我方单位必定命中物理与策略；
> ②敌军每四次攻击，必定命中我方单位一次（也就是命中率最低 25%）。**
> 本节把两条规则分别落到机器码，并给出"为什么是 4 次"的算式。

### 变体一（规则①）：我方回合 ⇒ 我方攻击的命中率直接置 100

```asm
0043B4DC  74 56                  je   0x43B534           ; 命中率 0 ⇒ 不中
0043B4E3  B8 19 00 00 00         mov  eax, 0x19         ; ★★ 命中率下限 = 25
0043B4FD  B9 B2 0F 00 00         mov  ecx, 0xFB2        ; 4018
0043B502  83 3C 8D 00 20 50 00 00  cmp dword [ecx*4+0x502000], 0   ; [0x505EC8]==1 ?
0043B50A  74 17                  je   0x43B523
0043B50C  80 3D 18 3D 4B 00 00   cmp  byte [0x4B3D18], 0 ; ★ 我方回合
0043B513  75 0E                  jne  0x43B523
0043B515  8B 4D FC               mov  ecx, [ebp-4]      ; ★ 攻击者
0043B518  80 79 05 00            cmp  byte [ecx+5], 0   ; ★ 阵营 == 我军
0043B51C  75 05                  jne  0x43B523
0043B51E  B8 64 00 00 00         mov  eax, 0x64         ; ★★ 命中率 = 100 ⇒ 必中
0043B523  83 F8 64               cmp  eax, 0x64
0043B526  73 0C                  jae  0x43B534         ; 100 ⇒ 跳过集气闪避判定
```

- 物理走 `0x43B600`、策略走 `0x43B730`，两条在 **`0x43B4DA` 合流**，所以置 100 对**物理与策略同时生效**
  —— 与用户口径"物理和策略伤害都必中"完全一致。
- 置 100 后 `0x43B526 jae` 跳过 `0x4287A8`，**不写闪避池**。

### 变体二（规则②）：命中率下限 25 决定"敌军每四次触发一次"

**第一半 —— 命中率的钳制范围是 `[25, 100]`：**

| 钳制 | 位置 | 作用范围 |
|---|---|---|
| **下限 25** | **`0x43B4E3 mov eax,0x19`**（`cmp eax,0x19 / jae` → 小于则写 25） | 物理与策略**共用**（在合流点之后） |
| 上限 100 | `0x43B549 mov al,0x64`（分段公式顶端 `能力 ≥ 2×对手`）；策略表项直接给 `0x64` | 同上 |

**策略侧专用表 `0x4D1720`（150 项）实测取值**：

| 取值 | 项数 | 走哪条 |
|---|---|---|
| `0 / 1 / 2 / 4` | 1 + 7 + 57 + 1 = **66** | `0x43B907 cmp al,5 / jb` ⇒ **跳过表值**，回落敏捷算式（**受 25 下限保护**） |
| `60 / 70 / 75 / 80 / 90 / 100` | 1+4+1+1+2+75 = **84** | `≥5` ⇒ **直接当命中率**，最小值就是 **60** |

⇒ **策略侧的有效命中率也恒在 `[25,100]`**，没有任何小于 25 的口子。
（注意：表里那些 `1/2/4` **不是百分比**，是"走敏捷算式"的开关值——这是本表最容易被误读的地方。）

**第二半 —— `0x4287A8` 防守方分支的算式：**

```asm
004287EF  83 7D F8 01           cmp  dword [ebp-8], 1   ; 分支选择器（1 = 防守方 = 闪避）
004287F3  75 13                 jne  0x428808
004287F5  83 C2 64              add  edx, 0x64          ; 池 + 100
004287F8  2B 55 08              sub  edx, [ebp+8]       ; − 命中率
004287FB  80 FA 64              cmp  dl, 0x64
004287FE  72 05                 jb   0x428805          ; < 100 ⇒ 闪避触发（eax=1）
00428800  80 EA 64              sub  dl, 0x64           ; ≥ 100 ⇒ 池 −100，不触发
```

等价写法：**`闪避池 + (100 − 命中率) ≥ 100` ⇒ 闪避，并把池 `−100`**，
即 **`闪避池 ≥ 命中率` ⇒ 闪避**。

**两条规则合起来推出"4 次"**（设命中率恒为下限 25）：

| 第几次被打 | 入池前 | 本段涨 `100−25=75` | 结果 |
|---|---|---|---|
| 1 | 0 | 75 | 75 < 100 ⇒ 不闪避（命中） |
| 2 | 75 | 150 | ≥100 ⇒ **闪避**，池 −100 ⇒ 50 |
| 3 | 50 | 125 | ≥100 ⇒ **闪避**，池 −100 ⇒ 25 |
| 4 | 25 | 100 | ≥100 ⇒ **闪避**，池 −100 ⇒ 0 |

⇒ 命中率 25（下限）时，**大约每 4 次攻击就会触发一次闪避判定**。
⇒ **反过来读**：正因为命中率被钉在 **≥25**，闪避池每 4 次**必定**攒满 ⇒
**"敌军每四次攻击必定（触发一次）命中我方单位"这个节奏由 25 下限保证**。
⇒ 若命中率可以低于 25，池会攒得更快、闪避更频繁，"4 次"这个节奏就不成立了
—— **所以用户说"也就是命中率最低 25%"，正是这条节奏的成因**。

### 一句话总结两条规则的实现位置

| 规则 | 实施点 | 机制 |
|---|---|---|
| ① 我方回合我方必中（物理+策略） | `0x43B4E8`~`0x43B51E`（`0x43B4DA` 合流点之后） | 三判据成立 ⇒ 命中率置 `0x64`；`0x43B526 jae` 跳过集气 ⇒ 必中 |
| ② 命中率最低 25 | `0x43B4E3`（合流点之后，物理+策略共用） | 命中率钳到 `[25,100]`；配 `0x4287A8` 的 `池 += 100−命中率` ⇒ 每 4 次一节奏 |
