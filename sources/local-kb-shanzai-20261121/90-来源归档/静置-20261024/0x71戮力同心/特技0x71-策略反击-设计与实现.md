# 特技 0x71 戮力同心 —— 策略反击（只在敌方发起策略时攻击）设计与实现

## 结论速览

- **目标行为**：敌方单位 A 施放策略并结算完成后，凡满足「有 `0x71 戮力同心` + 攻击范围覆盖 A + 不是 A 自己」的我方/友军单位 H，
  各对 A 执行一次物理攻击；**不改动**原有物理反击（同仇敌忾/戮力同心在物理链的现有行为）。
- **钩点（已确认）**：行动分发器 `0x43DEE2` 的 **case 5 = 策略施放**：
  `0x43DF44 mov ecx,[ebp-0x2C]` → **`0x43DF47 call 0x423358`**（5 字节 `E8`，天然对齐）→ `0x43DF4C jmp 0x43DF62`。
  ⇒ 钩 `0x43DF47`，洞里先**原样 `call 0x423358`**，再做反击，最后 `jmp 0x43DF4C`。
- **施法者**：`[ebp-0x2C]`（分发器局部，洞里 `ebp` 未变，可直接读）；单位指针 = `0x4A7B20 + slot*0x30`。
- **候选判定**：
  1. `0x418C90(unit)==2`（有效）
  2. `unit != caster`
  3. `0x405954`（0x71 桩，`ecx=unit`）返回非 0
  4. `0x4091F4(unit, 0x50, 2)` 的攻击范围覆盖施法者
- **执行攻击**：沿用奋战/物理链的调用形态 —— `push <caster_slot>; push <unit[+4]>; call 0x435829`。
- **只对敌方触发**：读 `unit[+5]` 阵营；施法者属敌方组（`0x406710` 非 1）、候选属我方组时才算“敌方打我方的策略”。

## 适用版本

- 样本 `Ekd5.exe` `4A761A94A72D80D17A260E9BCBA0E0A4F2F6C8469CCE0C2F19BDEF2D0A0427CF`。
- 6.5 的「聚势伐谋/敌潮逆噬/多多益善」只作语义参照，不套地址。

## 已确认事实

### 1. 动作分发器（`0x43DEE2`，case 表）

```asm
0x43DEF7  mov  eax,[ebp-0xC]        ; 动作类型
0x43DEFA  mov  [0x501BF9],al        ; 行动类型标志
0x43DF02  cmp  al,0xFF              ; 结束
0x43DF06  cmp  al,1 / jne           ; 1 → 0x43DADA 物理攻击
0x43DF11  cmp  al,2 / jne           ; 2 → 0x42C177
0x43DF1E  cmp  al,3 / jne           ; 3 → 0x40A985
0x43DF29  cmp  al,4 / jne           ; 4 → 0x442718(6)
0x43DF36  cmp  al,5 / jne 0x43DF4E  ; ★ 5 = 策略
0x43DF3A  push ecx / call 0x467C9E  ;   有特例分支
0x43DF42  test eax,eax / jne 0x43DF62
0x43DF44  mov  ecx,[ebp-0x2C]       ;   施法者单位指针
0x43DF47  call 0x423358             ; ★ 策略施放（jmp 0x424D63）
0x43DF4C  jmp  0x43DF62
```

### 2. 策略上下文 `0x497AF8`（库内已验证）

| 偏移 | 语义 |
|---|---|
| `+00` | 策略号 |
| `+01` | 施法者战场编号 |
| `+08` | **施法者单位指针** |
| `+0C` | 选中目标 |
| `+0D+i` | 目标表（`FF` 结束） |
| `+108+4i` | 每目标伤害（写点 `0x423B34`/`0x4242D2`/`0x42463E`） |

⇒ 洞里也可以用 `[0x497AF8+8]` 取施法者；但**施放结束后不清空**，优先用分发器的 `[ebp-0x2C]`。

### 3. 攻击执行形态（奋战 `0x4363F1` 现读）

```asm
0x436448  mov  [ebp-0x10],eax     ; 目标 slot
0x43644B  push eax                ; 目标 slot
0x43644C  mov  ecx,[ebp-4]        ; 攻击者单位
0x43644F  push dword [ecx+4]      ; 攻击者 unit[+4]
0x436452  call 0x435829           ; 打一次
```

## 实现·使用方法（洞体设计）

```
钩 0x43DF47:  E9 <rel32 → 洞>        ; 5B，覆盖原 call 0x423358
洞:
  55 8B EC                    push ebp / mov ebp,esp
  51                          push ecx                  ; 保存寄存器
  52 56 57                    push edx/esi/edi
  ; —— 先做原逻辑：call 0x423358（ecx 仍是分发器设好的施法者）——
  E8 <rel32 → 0x423358>
  ; —— 保存返回值，随后取施法者 ——
  A3 <保存槽>
  8B 5D 08??  ← 注意：进洞后 ebp 变了，施法者要从【分发器 ebp】取
  ...
```

⚠ **关键陷阱**：洞里如果 `push ebp / mov ebp,esp` 建新帧，就**读不到分发器的 `[ebp-0x2C]`**。
两种做法：
1. **不建帧**：进洞后先用 `mov eax,[ebp-0x2C]` 把施法者存到全局 `SAVE`，再建帧；
2. 建帧前 `push ebp` 保存分发器 ebp，之后用 `[esp+…]` 取。

**推荐**：进洞第一条就 `mov eax,[ebp-0x2C]` → `mov [SAVE_CASTER],eax`，再 `push ebp/mov ebp,esp`。

**循环体（伪代码）**：

```c
caster = [SAVE_CASTER];
if (caster == 0) goto done;
if (group(caster) == 1) goto done;          // 只处理“敌方施法”
for (slot = 0; slot < 0xFA; slot++) {
    unit = 0x4A7B20 + slot*0x30;
    if (unit[0] == 0xFFFF) continue;        // 空槽
    if (unit[0x0C] != 2) continue;          // 无效/死亡
    if (unit == caster) continue;
    if (group(unit) != 1) continue;         // 只让“我方组”帮
    if (0x405954(unit) == 0) continue;      // 无 0x71
    if (!in_attack_range(unit, caster)) continue;  // 0x4091F4 结果比对
    attack(unit, caster);                   // push caster_slot / push unit[+4] / call 0x435829
}
done:
  恢复寄存器；jmp 0x43DF4C
```

## 风险与边界

- **重入**：`0x435829` 会走物理攻击链，可能再次进分发器；必须在洞里加**重入标志**（全局 1 字节，进入置 1、退出清 0），否则会无限递归。
- **施法者自身**：`unit == caster` 必须跳过。
- **预览/AI 评估**：`0x435829` 若在 AI 评分里被调用会“假打”；只在真正的动作分发（case 5）后面调用，天然避开预览。
- **动画/时序**：策略结算后立刻插入物理攻击，可能打乱动画队列；需要在实机上观察是否卡动作。
- **`0x4091F4` 共用**：奋战/引导也用它，**不要改它本体**；范围判定只在本洞里读结果。
- **洞位置**：必须走 `_注入地址占用登记.py --check`，按 §3.6 判据（线性、无旁路、指令边界）。
- **写盘**：只走 `_dsh写锁.py` 的 `safe_write_exe()`，自动备份 + 复读 + 审计。

## 补充（查库后）：引擎已有「策略命中响应点」—— 0x5F 策略反击

- `0x5F 策略反击` 的域 = **`0x417941`**（库内 `机器逻辑速查表-字段与函数.md:635` 已记），
  由 **`0x4064D5`** 调用（在伤害应用例程 `0x4064F1` 内）—— 这是**策略命中后的现成回调点**。
- `0x417941` 结构：`ecx+1` 取单位 id → `0x4061F9` 转单位 → 调 `0x40640D`（0x5F 桩）→ 有值则 `dec eax` 后
  `call 0x4179B4`；`0x4179B4` 内部 `ecx=0x497AF8; call 0x425627`（**策略执行器**）⇒ 0x5F 的反击是**反施策略**，不是物理攻击。
- ⇒ 戮力同心要“物理反击”，可复用同一响应点：判 0x71 后改调 **`0x41058D`**（列表执行器：逐个 `call 0x435829` 并 `inc [unit+0x23]`），
  而不是走 `0x4179B4`。收集仍可复用 `0x4223A9(施法者)`（内部即 `0x438EBD` + `0x41058D`）。
- 待确认：`0x4064D5` 处能否拿到**施法者**（`0x417941` 的 ecx 结构里 `[0]`/`[1]`/`[0xC]` 各是什么）；拿到就能不改伤害链地接线。
## 更正：按物理链对比，施法者字段找到了 —— `[ctx+1]`

- 物理链：`0x435829(push unit[+4], push target_slot)`，随后 `0x4223A9(攻击者 unit 指针)` 收集帮手。
- 策略响应（同一段代码，现读 `0x4064C5`..`0x4064D5`）：
  ```asm
  0x4064C5  mov  ecx,[ebp-4]      ; ctx（物理 0x4927F0 / 策略 0x497AF8）
  0x4064C8  push dword [ecx]      ; 目标 slot
  0x4064CA  push dword [ecx+1]    ; ★ 攻击者/施法者 unit id（与物理同字段）
  0x4064CD  call 0x435829         ; 打一次（与物理同一执行器）
  0x4064D2  mov  ecx,[ebp-4]
  0x4064D5  call 0x417941         ; 0x5F 策略反击检查（内部 mov ecx,[ecx+1] 用的就是它）
  ```
  ⇒ **`[ctx]` = 目标 slot、`[ctx+1]` = 攻击者/施法者 unit id**；`0x4061F9` 转单位指针即可。
- **新钩点（优于 0x43DF47）**：`0x4064D5`（`call 0x417941`，5B E8）。
  它在“一次攻击/策略结算完”之后，物理/策略共用，用 **`[ebp-4] == 0x497AF8`** 就能只对策略生效（物理 ctx 是 0x4927F0，自动跳过）。
- 洞体（约 40B）：`call 0x417941` → `cmp [ebp-4],0x497AF8` → 不等就回 `0x4064DA` →
  `movzx ecx, byte [ctx+1]` → `call 0x4061F9`（→施法者）→ `call 0x406710`（阵营组，1=我方组则跳过）→
  `push 施法者; call 0x4223A9`（内部即 `0x438EBD` 收集 + `0x41058D` 逐个 `0x435829` 执行）→ 回 `0x4064DA`。
- 唯一待运行时确认：策略命中时 `[ebp-4]` 是否确实 = `0x497AF8`（一次断点即可；也可在洞里先只打日志）。

## 2026-10-18 19:0x ★ 实机反证：`0x4064D5` **不是**策略钩子（干净样本 `4A761A94`）

> 触发原因：用户反馈「法术版戮力同心从一开始就没触发」，要求先证明 `0x4064D5` 到底会不会执行、
> `[ebp-4]` 是不是 `0x497AF8`。本轮只取证（不写 EXE、不改内存）。

- **样本**：`Ekd5.exe` SHA256 `4A761A94A72D80D17A260E9BCBA0E0A4F2F6C8469CCE0C2F19BDEF2D0A0427CF`（干净，无任何补丁）。
  读 No.001 进战场，`sw4018=1`（集气模式铁律满足），`enemy_alive=50` 起步。
- **断点设计**：`0x4064D5`，条件 `dword:[ebp-4]==0x497AF8`；一轮"托管我军 + 结束回合"，
  敌方 40+ 单位行动、我方 5 个槽全部托管。

### 1. 命中情况

| 断点 | 命中数 | 策略上下文暂停 |
|---|---|---|
| `0x4064D5`（`call 0x417941`） | **127** | **0 次** |
| `0x423358`（策略施放入口） | **0** | — |
| `0x43DF47`（分发器 case 5 的 `call 0x423358`） | **0** | — |

- `0x4064D5` **确实被执行**（127 次），但**没有一次**是策略上下文。
- **对照实验（证明条件表达式没写错）**：把条件临时换成 `dword:[ebp-4]==0x4927F0`
  ⇒ **立刻命中并暂停**；暂停时 `eval_expression "[ebp-4]"` = `0x004927F0`、
  `byte:[0x501BF9]` = `0x000000FF`。
  ⇒ 「条件机制正确」+「策略真的没来过」两个结论同时成立，**不是条件写错导致的假阴性**。
- ⚠ **`byte:[0x501BF9]==5` 不能当策略条件**：命中当下它是 `0xFF`（分发器最后一次写入的残值）。
  14 个补丁版本里若用这个条件，会**永远不命中**。

### 2. 敌方到底放没放策略 —— 关键坑：`0x497AF8` 会被 AI 预演写入

轮内 `0x497AF8` 出现过 **4 组不同内容**，但 `0x423358`/`0x43DF47` 命中数都是 **0**
⇒ **它们不是"真正施放"，是 AI 评估/预演留下的残值**：

| 策略号 `+0` | 施法者 `+1` | 施法者指针 `+8` | 选中目标 `+0xC` | 目标表 `+0xD` |
|---|---|---|---|---|
| `0x41`(65) | `0x54`(84) | `0x004A8AE0` | `0x5C`(92) | 92, FF |
| `0x37`(55) | `0x54`(84) | `0x004A8AE0` | `0x50`(80) | 80, FF |
| `0x7D`(125) | `0x4D`(77) | `0x004A8990` | `0x4D`(77) | 77, FF |
| `0x37`(55) | `0x64`(100) | `0x004A8DE0` | `0x70`(112) | 112, FF |

- 施法者 slot 84 实测 `camp = 2`（敌方）、`data_id = 510`；slot 92 `camp = 2`、`data_id = 0x136`。
  ⇒ 敌方**确实往策略上下文里写过东西**，但**没有执行**。
- ⇒ **`0x497AF8` 有内容 ≠ 策略发生了**（呼应 `02-数据结构\复刻版6.6山贼策略记录与施法对象.md:141`
  的"施放结束后不清空"）。判"策略真的发生"必须另有判据：`0x423358`/`0x425627` 命中、
  或施法者 MP 实际扣减。**本轮 0 次真策略**。

### 3. 静态结构同样支持"`0x4064D5` 是物理专用"

```asm
0x4064C5  mov  ecx,[ebp-4]      ; ctx
0x4064C8  push dword [ecx]      ; ← 目标 slot（物理 ctx 的 [0]）
0x4064CA  push dword [ecx+1]    ; ← 攻击者 slot（= unit[+4]，物理 ctx 的 [1]）
0x4064CD  call 0x435829         ; 打一次
0x4064D5  call 0x417941         ; 0x5F「策略反击」检查（防守方用策略反制）
```

- **物理上下文**实测 `0x4927F0` = `04 6D 00 00 01 00 00 00` ⇒ `[0]=4`、`[1]=0x6D(109)`，
  正好符合"目标 slot / 攻击者 slot"的压栈顺序。
- **策略上下文** `[0]` 是**策略号**、`[1]` 是**施法者编号** ⇒ 这段代码若拿策略上下文本跑，
  会把"策略号"当成目标槽、把"施法者"当成攻击者，**逻辑上是错的**。
- ⇒ 结构性结论：`0x4064D5` 位于**物理攻击结算**路径尾部的 0x5F 检查处，
  **不是"策略施放后"的回调点**。这也解释了为什么 5 版补丁"从一开始就没触发"。
