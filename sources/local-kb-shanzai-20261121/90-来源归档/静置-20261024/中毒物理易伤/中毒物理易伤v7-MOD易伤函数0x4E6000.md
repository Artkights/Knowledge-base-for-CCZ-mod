# 中毒物理易伤 v7：MOD 自有易伤函数 0x4E6000（重大发现 + 现状）

> 样本：`Ekd5.exe`，干净底 `2A555B0B0D476CE1B10510406586A6F148513EDCA740BAF67CCBC422F06F0083`；
> 本次补丁后 `2D001F4C43B31DC5657684331DA2B348D573F574B8C916C66BBDC4A2C68E25DE`（44 字节）

## 结论速览

1. **`0x4E6000` 是 MOD 自有的「物理易伤结算」函数**（不是空洞、不是数据区）。
   签名：`[EBP+8]=伤害值`、`[EBP+0xC]=攻击者`、**`[EBP+0x10]=目标单位`**，出口 `RET 0xC`。
   调用点：**物理伤害公式 `0x43BC5A` 内部的 `0x43BDBF`**（参数：目标、攻击者、当前伤害），返回值写回公式局部 `[EBP-4]`。
   它内部就是 `0x425AD9(伤害, 特效值)` → `ADD EAX,[EBP+8]` ⇒ **现成的「物理易伤 +X%」**。
2. ⇒ **「物理易伤地址」就是它**（连同特技 `0xF6` 的查询桩 `0x4E0000` / `0x4E008F`）。
   用户问「有没有可能我们没有这个物理易伤的地址」——**有，就是 `0x4E6000`，且它是普通 CALL/RET 函数**。
3. **v7 补丁（本次）**：把 `0x4E6052` 的 `call 0x425ad9` 改成 `call 0x4E6110`（注入函数），
   注入函数先判 `[目标+0x1E] & 0x10`（中毒）⇒ 未中毒时逐字节复刻原生两条 `PUSH` + `CALL`；
   中毒时额外 `PUSH 20` 走同一条 `0x425AD9` 并把结果加到最终值 ⇒ **×1.2**。
   **只 1 条 JMP、回归用引擎原生 `RET 0xC`、运算复用引擎现成函数**。
4. **实测：连续 4 轮（含 8 个中毒敌人在场）推进回合，进程全部存活** ⇒ 相比 v6 系列「每轮必崩」是质变。
   ⚠ **但「×1.2 效果」尚未取得运行时证据**：断点计数显示公式 `0x43BC5A` 被调 8 次，
   而注入函数 `0x4E6110` **命中 0 次** ⇒ **普通物理攻击不一定经过 `0x43BDBF` 这条分支**（见「待验证项」）。

## 已确认事实

### 1. `0x4E6000` 反汇编（本样本）
```asm
004E6000  PUSH EBP / MOV EBP,ESP
004E6003  PUSH 0 / PUSH 1 / PUSH 0 / PUSH 0xC4 / PUSH 0xFF / PUSH 0xFF / PUSH 0
004E601D  MOV ECX,[EBP+0xC]          ; 攻击者
004E6020  CALL 0x4E0000              ; 查特技（内部再 CALL 0x4101D9 两次）
004E6025  TEST EAX,EAX / JE 0x4E605B
004E6029  PUSH EAX / PUSH 1 / PUSH [EBP+0xC] / PUSH [EBP+0x10]
004E6032  CALL 0x4E008F              ; 查
004E6037  TEST EAX,EAX / JE 0x4E605B
004E603B  PUSH 0 / PUSH [EBP+0xC] / PUSH [EBP+0x10]
004E6043  CALL 0x4E008F
004E6048  TEST EAX,EAX / JNE 0x4E6059   ; 命中 ⇒ 加成 0
004E604C  PUSH [EBP-4]               ; ★ 特效值
004E604F  PUSH [EBP+8]               ; 伤害
004E6052  CALL 0x425AD9              ; ★★ 伤害×特效值÷100
004E6057  JMP 0x4E605B
004E6059  XOR EAX,EAX
004E605B  ADD EAX,[EBP+8]            ; ★★★ 加回原伤害 = 「物理易伤 +X%」
004E605E  MOV ESP,EBP / POP EBP / RET 0xC
```
`0x4E0000`（子查询1）：`RET 0x1C`，7 个参数，内部两次 `CALL 0x4101D9`（特技引擎），
按 `[EBP+0x1C]` 是否为 0 决定「取较大值」还是「相加」。

### 2. 公式里的调用点
```asm
0043BDB6  PUSH [EBP+8]      ; 目标单位
0043BDB9  PUSH [EBP-0x2C]   ; 攻击者
0043BDBC  PUSH [EBP-4]      ; 当前伤害
0043BDBF  CALL 0x4E6000
0043BDC4  MOV [EBP-4],EAX   ; 伤害 ← 结算后
0043BDC7  JMP 0x43F1E8      ; 进特技链
```

### 3. v7 补丁字节（已写入并进程内复读）
```
0x4E6052 : E8 82 FA F3 FF  →  E8 B9 00 00 00      (call 0x4E6110)
0x4E6110 : 注入函数 41B：
  MOV ECX,[EBP+0x10] / TEST BYTE [ECX+0x1E],0x10 / JZ native
  PUSH 0x14 / PUSH [EBP+8] / CALL 0x425AD9 / MOV EDX,EAX / JMP done
  native: XOR EDX,EDX
  done:   PUSH [EBP-4] / PUSH [EBP+8] / CALL 0x425AD9 / ADD EAX,EDX / RET 0xC
```
洞址 `0x4E6110` 的双重复核（**这一步必须做**）：
* 干净样本里 `0x4E60FB` 起 7429B 全为 `00`；`0x4E60F6` 是上一函数 `0x4E6064` 的 `RET` ⇒ 洞在函数之外；
* **全代码 46956 条 `call/jmp` 中没有一条落进 `0x4E6110~0x4E6140`**；
* 不在 1753 个「补丁文本引用地址」内。

## 风险与边界

1. ⚠ **`0x4E6000` 曾被误判为空洞**：我早先从**已被自己 v6 残留清零的文件**里扫洞，把 MOD 正在使用的函数当成空闲区。
   ⇒ **铁律：扫洞必须从干净样本扫**（本次已改，`_扫安全洞表.py` 就是干净样本口径）。
2. **`[+0x1E]` 的低位玄机**：用户资料给出 `0x02/0x04/0x08/0x10` 的**位组合**语义，
   而 `0x423FE8` 内部是**逐次 `SHR 1`** ⇒ 选择子 `0x10` = 测 bit4 = 中毒（两处引擎自判都用 `push 0x10`）。
   写作「选择子 = 位掩码」不准确，应为「**选择子用作右移次数**」。
3. `0x4E6132` / `0x4E6136` 这类断点会让 x32dbg 把首字节换成 `0xCC`；**读字节要用 hexdump 工具**（MCP `memory_read` 返回的是原始内存，可放心用）。

## 证据来源

* 静态复读（本样本、只读）：`0x4E6000` / `0x4E0000` / `0x4E008F` / `0x43BC5A` 全函数 / `0x4E6064`；
* 洞表扫描 + 全代码跳转扫描（46956 条）+ 1753 个补丁引用地址交叉排除；
* 运行时：断点 `0x43BC5A` 命中 8 次、`0x4E6110` 命中 0 次；连续 4 轮推进回合进程存活。

## 待验证项

* **P0：`0x43BDBF`（`call 0x4E6000`）到底在什么条件下执行？**
  实测「公式被调 8 次、注入函数 0 次」⇒ 该分支不是普通攻击必经之路。
  需在其入口下断点，配合一次**实战攻击**读 `[EBP+8]`/`[EBP-0xC]`/`[EBP+0x10]` 等局部量判定条件；
  若它只在"目标带某特技"时走，则 v7 的挂点覆盖面不足 ⇒ 需改挂到**所有物理攻击必经**的位置。
* **P0：×1.2 的运行时数值证据**（需一次真实攻击：读 `0x425AD9` 入参与函数出口 `EAX` 计算比值）。
* P1：`0x4E0000` 的 7 个参数语义（哪几个是特技号区间 `0xFF/0xFF/0xC4`）。
