## 一、已确认事实（现样本实测）

### 1. 特技链的槽表与契约

链体在函数 `0x43F07C` 内；每槽统一形态：**收上一槽累加值 → 返回新值**，固定 3 个 push：

```asm
0043F26E  FF 75 D4     push [ebp-0x2C]   ; 攻击者单位
0043F271  FF 75 08     push [ebp+8]      ; 伤害累加值
0043F274  FF 75 FC     push [ebp-4]      ; 累加值副本
0043F277  E8 0B 2B 00 00  call 0x441D87  ; ★ 第 8 槽
0043F27C  89 45 FC     mov  [ebp-4], eax ; 写回累加器
0043F27F  E9 48 CB FF FF  jmp 0x43BDCC   ; 链尾 → 回到公式/结算
```
（槽表：1 `0x43C31D` / 2 `0x43EA00` / 3 `0x441C81` / 4 `0x441E09` / 5 `0x441E9C` /
6 `0x441EE8` 回马 / 7 `0x442392` 劲透 / **8 `0x441D87`**。）

### 2. 第 8 槽 `0x441D87`（130B，`ret 0xC`）三步——**这就是"物理易伤"的真身**

```asm
00441D87  push ebp / mov ebp,esp
 ① mov ecx,[ebp+0x10] / call 0x45D513(守卫) → call 0x441D39(查 0xF2)   ; 扣减支
    test eax,eax / je 跳过 ; cmp eax,0x64 / jb → push [ebp+8] / push eax / call 0x425AD9
                              ; 特效值 ≥100 ⇒ eax=1（保底 1）
    sub dword [ebp+8], eax
 ② mov ecx,[ebp+0x0C] / call 0x45D513(守卫) → call 0x441D53(查 0xF6 = 物理易伤)
    test eax,eax / je 跳过 ; push [ebp+8] / push eax / call 0x425AD9   ; 值×特效值/100
    ★ 00441DE7  03 45 08    add eax,[ebp+8]     ; ← **加回点（= 本需求的落点）**
    mov [ebp+8], eax
 ③ mov ecx,[ebp+0x0C] / call 0x441D6D(查 0xFF) → 命中 ⇒ mov eax,0x270F(9999) 直接返回
 出口 mov eax,[ebp+8] / ret 0xC
```
- **`0x441D53` = 13 字节查询桩**：`push 0xF6 / call 0x4101D9 / ret`（桩内**不重设 ECX** ⇒ 依赖调用者的 ECX = 单位）。
- **`0x45D513` = 共用守卫**：`push 0 / 0 / 0x59 / 0xFE → call 0x42518F`（查个人 `0xFE` / 装备 `0x59`，命中即跳过整链）。
- **特技号 `0xF6` = 246「※物理易伤」，名表 flag `02` = `+%d%%`**（`0x4CC600 + 0xF6×16`）。

### 3. 链的入口（上页口径需修正）

- `call 0x43F1E8`（rel32 精确扫描）= **0 处**；真正的进入方式 = **`0x43BDC7` 处的 `E9` 跳转**（在物理伤害公式 `0x43BC5A` 内）。
- 另一条同族通路：`0x42423D(value, 单位, flag)` ← 由 `0x43BEDF` 调用（`0x43BC5A` 内，**仅当 `[ebp+0xC]==0`** 才走）。
- ⚠ **库内冲突（P0）**：一处写"预览与实战共用 `0x43F1E8~0x43F27F`"（断点命中 2 次），
  另一处说该口径**已被证伪**（"预览函数不调用该链、`call 0x43F1E8` = 0 处"）。
  后者只证了"没有 `call rel32` 直指"⇒ **不构成证伪**（本页已补：真入口是 `0x43BDC7` 的跳转）。
  ⇒ **本条必须先实机定案**，因为它决定"预览会不会显示这 20%"。

## 二、实现方案（推荐 = 链尾插槽，克隆第 8 槽）

### 方案 R：新增「中毒易伤」槽（纯复用三件套）

新增函数（建议放代码洞，约 70~90 字节）：

```asm
; boost_poison(ecx = 目标单位);  [ebp+8]=伤害值, [ebp+0xC]=目标, [ebp+0x10]=攻击者
push ebp / mov ebp,esp
  mov  ecx,[ebp+0xC]        ; 目标单位
  push 0x10                 ; ★ 中毒选择子（= 2<<3）
  call 0x423FE8             ; 中毒窗口非零？（引擎权威状态测试）
  test eax,eax / je 出口
  ; —— 命中：+20%（固定 20，或用特技/变量给值）——
  push 20                   ; 百分点（可选：改读全局整型变量/特技特效值）
  push dword [ebp+8]        ; 当前伤害
  call 0x425AD9             ; a*b/100  ⇒ (伤害×20)/100
  add  eax,[ebp+8]          ; 加回
出口:
  mov esp,ebp / pop ebp / ret 0xC
```

接入方式（**必须保守**，两种择一）：
- **R1（改链尾，最小改动）**：把 `0x43F277` 的 `call 0x441D87` 改成 `jmp <trampoline>`；
  trampoline 里 **先按原参数 `call 0x441D87`**（物理易伤原样保留）→ 存 EAX →
  `push [ebp-0x2C] / push [ebp+8] / push eax` + `mov ecx,[ebp+0xC]` → `call boost_poison` →
  `mov [ebp-4],eax` → `jmp 0x43F27F`（回链尾）。
  ⚠ 要保留 `0x43F26E/271/274` 三条 push（因为原 `call` 吃栈上的 3 个参数）。
- **R2（克隆整槽，最稳）**：复制 `0x441D87` 130 字节到洞内 → 把其中**第 ② 步**的
  `call 0x441D53`（查 `0xF6`）替换成 **查中毒窗口**（`push 0x10 / call 0x423FE8`，注意重设 `ECX`）→
  再把 `0x43F277` 的 `call` 目标改成克隆体。
  ⇒ **不碰引擎原有代码体**（该块与初版逐字节相同，是"1:1 可比"资产，不宜改内字节）；语义 = **中毒时 +20%，且原 `0xF6` 特技不再作用于这处**（或保留双查，见下）。
- **R2+（双条件）**：克隆体第 ② 步先查 `0xF6`、再加查中毒窗口，两者**各自**加值 ⇒ 特技与中毒可叠加（更灵活）。

### 方案 S（你说的备选）：直接用现有特技

- 给**装备/兵种**挂 `0xF6`，特效值填 `20` ⇒ **立刻 +20% 物理易伤**，**零代码**。
- 代价：触发条件是"装备/兵种带这个特技"，**不是"目标中毒"** ⇒ **不满足"中毒才增伤"的语义**。
- 适用：若你只是想要"某个单位打人更疼"，这是最快的；若要"中毒状态成为物理易伤来源"，必须走方案 R。

## 四、风险与边界

1. **预览/实战一致性未定案**（最重要）：链若共用，预览会一起变（可能被要求"预览不许显示"）。

   见 `暴击预览-成功案例6.5F版注入补丁与6.6移植.md`）。
2. **链被多处复用**：`0x43BC5A`（物理伤害公式）**有 5 处调用者**（`0x405E6D` 主路径 + `0x419AED`/`0x438A2A`/`0x438CCA`/`0x440668`）
   ⇒ 改动会波及其中**所有**场景（含预估/AI 打分）。**必须逐处判定是否需要**。
3. **百分比无钳制**：现有 246/248 都无上限；本方案固定 20 则无此问题（除非改成读特技值）。
4. **`0x45D513` 是共用守卫**：命中个人 `0xFE`/装备 `0x59` 会**跳过整条链** ⇒
   若目标带了这两个，中毒 20% **也不会生效**（需你确认是否符合预期）。
5. **叠加顺序**：方案 R1 是"先算 `0xF6`、再乘中毒"，R2/R2+ 是"链内顺序"⇒ **叠加基准不同**（先加后乘 vs 各自独立加）**结果会不同**，需指定。
6. **"敌军"限定**：需求说"敌军受到伤害"——本方案按**任意目标中毒**生效（不分敌我）。
   若要"只对敌人生效"，需再加阵营判定（目标 `unit+5` 阵营 vs 攻击者）。

## 2026-10-16 13:50 ★★ A/B 对照结论 + 一个**写入器真 bug**（本次最大收获）

### 1. ★ 写入器 bug：`_搬回写入.py` 每段只读**第一行** hex（已修）

- **现象**：同一份补丁文本，修好前写入 **50 字节**，修好后写入 **239 字节**。
- **根因**：`parse_patch()` 在 `-地址` 之后**只取紧随的第一行** hex 作为该段内容
  （旧代码 `if not hx: for nxt in lines[i+1:]: ... break`），
  ⇒ **多行段被静默截断**（实测：142 字节的洞只写 9 字节；256 字节只写 16 字节；本补丁只写 50/239）。
- **影响面**：本工作区**多份既有补丁文本都是多行段**
  （例：`HP-MP辅助叠加改造-完整技术文档.txt` = 7 段 37 hex 行）⇒ 任何用该工具应用这类补丁的操作都会**只写每段第一行**。
- **修法（本次已改 `_搬回写入.py`，向后兼容单段）**：
  1. 段头之后**连续吃 hex 行**，直到遇到注释行 / 下一个 `-地址` / 非 hex 行；
  2. 新增**硬护栏**：`声明前像长度 > 解析出段长` ⇒ **直接拒绝写入**（返回 5），
