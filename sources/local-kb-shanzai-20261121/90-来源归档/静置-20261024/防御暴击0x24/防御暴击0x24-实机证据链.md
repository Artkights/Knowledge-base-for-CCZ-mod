# 防御暴击 0x24 —— 实机证据链（v5）

## ⚠️ 2026-10-14 晚追加：本页第 1 节结论已被**限定**，引用前必读

本页与其它页面曾对"v5 到底减不减伤"给出**互斥结论**，原因是同一批断点数据被写成了两种叙事。
现按时间顺序收口为**唯一口径**（证据都保留，不再互斥）：

| 观测 | 事实 | 说明 |
|---|---|---|
| ① 断点 `0x452C24` 命中 1 次，`EAX=112`、`ECX=100`、`EDX=ctx+0x84` | `150 × 75 / 100 = 112` **算术与写回都正确** | 证明"只要有正确的 V，减伤链算得对、写得对" |
| ② 命中时实测 **`ESI = 0`** | 系数 = `100 − 0 = 100` ⇒ **该次零减伤** | 证明"取 V 的那一步并不总能拿到真实特效值" |

- 两次观测**不矛盾**，它们覆盖的是**两个不同分支**；差异出在 `0x42aa2a`（v5 用来取 `0x24` 特效值的调用）
  **返回语义未定**：返回布尔值时 V=0（零减伤），返回真实特效值时才减伤。
- ✅ **`0x42aa2a` 的返回语义已定案（2026-10-14，离线反汇编，见本页末「0x42aa2a 定案」）**：
  它**不是** `0x24` 的特效值读取器，而是**双特技复合谓词** ——
  「若单位有 `0x70 暴击增幅`（特效值 > 0）⇒ 返回 **0**（禁用 0x24 减伤）；否则返回 `0x24` 的特效值」。
  ⇒ **v5 的零减伤之谜解开**：`[ecx+0xc]` 指向的单位若有 `0x70`，`eax` 恒为 0 ⇒ V=0 ⇒ 系数 100 ⇒ 零减伤。
  **这是 v5 的设计缺陷，不是"随机时有时无"。**
- ⇒ **最终口径（以本条为准）**：
  **v5 = 减伤算术与写回正确，但 V 取自 `0x42aa2a` ⇒ 遇 `0x70` 必为零减伤；**
  **v6-fix 改为补丁体内自查 `0x24` 特效值 ⇒ 不再依赖 `0x42aa2a`，V 可靠（已实机 10 回合无崩溃）。**
- ⚠️ **2026-10-14 晚·本条再次更新（"已回滚"作废）**：
  `0x43A6D4` 崩溃根因已定位并修复 —— 崩因是 **v6 代码洞起点 `0x452E68` 踩在历史补丁
  函数 `0x452E18` 结尾 `ret 4`（`C2 04 00`）的立即数末字节上**，覆盖后变成 `ret 0x5604`，
  该函数每次返回额外抬高 ESP `0x5600`=22016 字节 ⇒ ESP 跑出线程栈 ⇒ `push` 写未提交页。
  已改洞起点为 `0x452E69`，同配置实机 **10 回合无崩溃**（SHA `135A22E7…`）。
  ⇒ **v6-fix 当前在位，"已回滚"作废**；`0x42aa2a` 的返回语义**不再**是卡点
  （v6 补丁自查表取真实 V）。详见本页末尾「v6 崩溃根因与修复」。
  **仍未做**：逐帧核对预览飘字数值是否等于减伤后的实际掉血（需只读采样，勿挂断点）。
- 引用本页时：第 1 节只作为"算术正确性"的证据，**不能**据此说"v5 已实现减伤"。

## 结论速览

- **v5 把减伤结果写回伤害槽 `ctx+0x84`** —— 由 x32dbg 断点取得**执行级证据**（非推断）。
  ⚠️ 但该次命中 `EAX=112` 只证明"算得对、写得对"，**不能反推进入时的 V 是真实特效值**；见上方追加条。
- **连击路径不再闪退**：只读采样 331 条、跨 11 分钟，其中连击=1 共 72 条、连击=2 共 5 条，
  期间进程存活；v4 在该路径必崩。
- **ExtendData 特效查表**结构实测打通（基址 + RVA `0x217E08`，4 槽 × 8B/行），
  **但战斗中写入会被游戏还原** ⇒ 固定条件测试需改数据源/存档。
- 「伤害预览显示减伤后实际伤害」在**显示链层面成立**（飘字调用点 `0x404A58` 推入 `[ecx+0x84]`）；
  但**前提是减伤真的发生了** —— 而 v5 的 V 不可靠，故该需求**尚未落地**。

## 已确认事实

### 1. 执行级证据：v5 减伤算术与写回

| 项 | 值 |
|---|---|
| 断点 | `0x452C24`（v5 补丁体内，减伤算术完成点） |
| 命中次数 | **1** |
| `EAX` | `0x00000070` = **112**（减伤后的值） |
| `ECX` | `0x00000064` = **100**（除数） |
| `EDX` | `0x00492874` = **`ctx+0x84`（伤害槽地址）** |
| 读 `[0x492874]` | `0x00000070` = **112**（与 EAX 一致） |

⇒ `150 × 75 / 100 = 112`（`ECX=100` 印证"百分比换算"），且**写回的正是伤害槽**
⇒ 后续显示链读同一槽位，**飘字必然显示减伤后的值**。

### 2. 连击路径稳定性（只读采样）

| 项 | 值 |
|---|---|
| 表地址 | `ExtendData.dll` 基址 + RVA **`0x217E08`** |
| 行长 | **`0x400`** |
| 角色数 | `1024` |
| 每行槽位 | **4 个个人特技槽 × 8 字节** |


## ⚠️ 采样器配对缺陷（2026-10-14 发现，重要）

`_减伤实机采样.py` 目前用"**最近一次战斗上下文**"给 HP 下降配对攻击者与暴击标志。
实测该做法**不可靠**：

- 伤害槽（`ctx+0x84`）在**动画播放前**写入；
- HP 扣减要等**动画播完**（库内旧记录："实测差 11 秒"）；
- ⇒ 配出来的 `from` / `crit` 可能是**下一个攻击者**的。

**反证（不合逻辑的配对）**：

```
slot4  -> slot4   非暴击中位 562   暴击中位 109    ← 暴击低于非暴击 5 倍，不可能
slot72 -> slot4   非暴击中位 933   暴击中位 577    ← 同样反了
```

⇒ **不要用这套配对做"同目标暴击/非暴击"的精细校验**。
修法（待做）：把"伤害槽写入时刻"与"HP 下降时刻"分开记录，
用**伤害槽的值**关联目标（而不是用时间最近的上下文）。

## 可用的减伤证据（不依赖暴击配对）

伤害**数值**是可靠的（直接读 HP 差）。用"**同一攻击者打不同目标**"对比：

| 攻击者 | 目标 | 带 0x24 | 伤害中位 |
|---|---|---|---|
| `slot4` | `slot72` | **是（值20）** | **99** |
| `slot4` | `slot91` | 否 | 133 |
| `slot4` | `slot90` | 否 | 151 |
| `slot4` | `slot95/98/112` | 否 | 240~251 |

- 带 `0x24` 的目标受到伤害**显著更低**，方向与"减伤生效"一致。
- ⚠️ 攻击力有浮动、各目标防御可能不同 ⇒ **方向性旁证**，非精确校验。

## 另一条独立旁证：同攻击者 → 两个 0x24 目标

| 目标 | 0x24 值 | 伤害中位（slot4 打） |
|---|---|---|
| `slot72` | 20 | 98~99 |
| `slot84` | 25 | 87 |

- 实测比值约 `0.89`；理论 `(1−0.25)/(1−0.20) = 0.9375`。
- **方向正确**（值大的减伤更多）。

## ★ v5 补丁的触发链（2026-10-14 反汇编 + 断点实测）

**挂钩点 `0x405EF9` 不是无条件的**：

```asm
00405EDD  call 0x4287a8          ; ★ 暴击随机判定
00405EE2  test eax,eax
00405EE4  je   0x405f24          ; 没暴击 → 直接跳过补丁
00405EF0  call 0x42aa2a          ; ★ 查防御暴击 0x24
00405EF5  test eax,eax
00405EF7  je   0x405f02          ; 目标没 0x24 → 跳过补丁
00405EF9  jmp  0x452c00          ; ★★ 两条件都满足才进 v5 减伤
```

⇒ **触发链 = `本次攻击暴击` ∧ `目标带 0x24`**。

- 实测：`0x452C00` 命中 **0** 次，`0x4101D9`（双通道检测桩）命中 **2** 次
  ⇒ 当时"带 0x24 但没出暴击"。
- **结论**：**非暴击攻击永远不会进 v5 补丁** ⇒ 0x24 的减伤**只对暴击生效**，
  这与"防御**暴击**"的语义一致，但也是"普通攻击看不出减伤"的原因。

### 若要让非暴击也减伤（可选改造）

需要在**非暴击路径**另设挂钩点：即 `0x405F02` 之后（原生应用伤害处）
或 `0x405F4B` 之前，加一段"查 0x24 → 按 V 减伤"的代码洞。
⚠️ 这会改变 0x24 的语义（原文是"被**暴击**时减伤"），需你确认是否要改。

## ★ 加特技的正确公式（普罗源码实测）


实测一次写入后回读时该角色特技从 0 个变成 3 个 ⇒ **游戏会在某些时机（读档/进战场）

## ★ v5 面对带 `0x24` 目标时：预览显示的是「未减伤」值

## ★ 原版对 0x24 的真实语义：布尔免疫（伤害清零），槽值不参与计算

下游分水岭（`0x405F24` 汇合点之后）：

- 原版：**"有 0x24" ⇒ 伤害恒为 0 ⇒ 永远走 `0x40601D`**；槽里的值（数据表给的是 20）

### 4. 由此得出的三条结论

1. **v5 的"零减伤"不是随机**：`0x42aa2a` 在单位拥有 `0x70 暴击增幅` 时**必定返回 0**
   ⇒ V=0 ⇒ 系数 `100-0=100` ⇒ 零减伤。**这是确定的分支，不是概率。**

2. **v6-fix 已绕开它**：补丁体（`0x452E69`，见下）自己遍历特效表取 `0x24` 的真值，
