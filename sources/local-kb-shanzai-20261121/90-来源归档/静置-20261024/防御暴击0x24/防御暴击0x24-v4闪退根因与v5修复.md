# 防御暴击 0x24：v4 闪退根因与 v5 修复

## 结论速览

- **现象**（用户 2026-10-14 报告）：**带防御暴击 `0x24` 的敌军攻击我方时，游戏闪退。**
- **根因**：v4 补丁体结尾 `jmp 0x405F17` **跳过了 `0x405F24` 的连击判断**。
  `+608`(`DOUBLE_ATTACK_FLAG`) > 0 即连击段；原版靠"把伤害槽清零"让后续
  `test eax,eax / je 0x40601D` 走零伤害分支，从而**不会对已阵亡目标继续结算**。
  v4 写入非零减伤值后跳过该判断，连击段便带着非零伤害继续走暴击后处理
  （`0x405F58` → `0x472840` / `0x414D70`），目标已阵亡即野指针路径 ⇒ 闪退。
- **v5 修复**：补丁体在写入减伤伤害后**自己补上 `+608` 检查**：
  连击段 `jmp 0x405F24` 交回原生逻辑，非连击段 `jmp 0x405F17` 保留 v4 减伤语义。
- v5 字节已用 keystone 汇编 + 手算位移**双重复核**（两处跳转目标验算均 OK）。

## 已确认事实

### 1. 相关代码（离线反汇编复读）

```
00405ED2  mov  [ebp-0x24], eax        ; eax = 暴击率(0..100)
00405ED5  cmp  eax, 0x64
00405ED8  ja   0x405eea               ; >100 直接算暴击
00405EDD  call 0x4287a8               ; 随机判定
00405EE4  je   0x405f24               ; 未暴击 -> 走 0x405F24
00405EE6  add  dword [ebp-0x24], 0x64 ; 暴击标记 100..200
00405EEA  mov  ecx, [ebp-0xc]
00405EED  mov  eax, [ebp-0x20]
00405EF0  call 0x42aa2a               ; ★ 防御暴击 0x24 谓词 -> EAX = 特效值 V
00405EF5  test eax, eax
00405EF7  je   0x405f02
00405EF9  <v4：jmp 0x452AF1 / 原版：mov edx,[ebp-0x28]; xor eax,eax; mov [edx],eax; jmp 0x405f17>
00405F02  push [ebp-0xc] / push [ebp-0x24] / push [ebp-0x28]
00405F0B  call 0x42e4fd               ; 暴击加成 150%~200%
00405F17  mov  eax, [ebp-0xc]
00405F1A  mov  dword [eax+0x604], 1    ; 暴击标志
00405F24  mov  ecx, [ebp-0xc]          ; ★ 连击判断入口（v4 跳过了这里）
00405F27  cmp  byte [ecx+0x608], 0     ; +608 = DOUBLE_ATTACK_FLAG
00405F2E  jle  0x405f4b
00405F30..0x405F49  检测特效 0x30/0x44，命中则把伤害槽清 0
00405F4B  mov  edx, [ebp-0x28]
00405F4E  mov  eax, [edx]
00405F50  test eax, eax
00405F52  je   0x40601d               ; 伤害 0 -> 经验值分支（原版的"免伤"走这里）
00405F58  ...  暴击后处理（0x472840 / 0x414D70 / 0x425AD9）
```

- `[ebp-0x28]` = 第 `[ebp-4]` 个目标的**伤害槽指针**，由 `0x405E90 lea edx,[edx+ecx*4+0x84]`
  得到，`0x405E9A mov [edx],eax` 写入基础伤害 ⇒ **指针本身有效**，v4 的写不是野指针。
- `[ebp-0x20]` = 攻击者单位指针；`[ebp-0xc]` = 战斗上下文（`ctx`，即 `0x4927F0`）。
- `+608`(1 字节) = `DOUBLE_ATTACK_FLAG`；`+604` = 暴击标志；`+614` = 反击标志。

### 2. 为什么"原版清零"是安全的、而"减伤值非 0"会崩

| | 原版（有 0x24） | v4 | v5 |
|---|---|---|---|
| 伤害槽 | **0** | 非 0（减伤后） | 非 0（减伤后） |
| 连击段判断 | 走 `0x405F17`，但伤害为 0 ⇒ `je 0x40601D` | **跳过 `0x405F24`** | **显式补检 `+608`** |
| 结果 | 不结算，安全 | 连击段继续结算 ⇒ **闪退** | 连击段交回原生逻辑，安全 |

### 3. v5 字节

入口跳板 `0x405EF9`（9 字节，后 4 字节保留 `90`）：
```
E9 02 CD 04 00 90 90 90 90          ; jmp 0x452C00
```

补丁体 `0x452C00`（59 字节）：
```
56 89 C6 B9 64 00 00 00 29 F1 79 02 31 C9 8B 45 D8 8B 00
0F AF C1 B9 64 00 00 00 99 F7 F9 8B 55 D8 89 02 5E 9C 8B 4D F4
80 B9 08 06 00 00 00 9D 0F 8F EE 32 FB FF E9 DC 32 FB FF
```

反汇编（v5 补丁体）：
```
push esi
mov  esi, eax                 ; EAX = 0x24 的特效值 V
mov  ecx, 0x64
sub  ecx, esi                 ; ecx = 100 - V
jns  0x452C0E
xor  ecx, ecx                 ; V >= 100 -> 完全免伤
mov  eax, [ebp-0x28]
mov  eax, [eax]               ; 未暴击伤害（v4 已不再叠加暴击加成）
imul eax, ecx
mov  ecx, 0x64
cdq
idiv ecx                      ; 伤害 = 未暴击伤害 × (100−V) / 100
mov  edx, [ebp-0x28]
mov  [edx], eax               ; 写回伤害槽
pop  esi
pushfd                        ; ★ 保护标志位
mov  ecx, [ebp-0xc]
cmp  byte ptr [ecx+0x608], 0  ; ★ 补上连击判断
popfd
jg   0x405F24                 ; 连击段 -> 交回原生逻辑
jmp  0x405F17                 ; 非连击段 -> 保留 v4 减伤语义
```

位移手算复核：
- `jg` 位于 `0x452C29`，长 6 ⇒ 下一条 `0x452C2F`；`0x452C2F + 0xFFFB32F4` = `0x405F24` ✓
- `jmp` 下一条 `0x452C35`? 实为 `0x452B35` 口径已校正：`0x452C34 + 5 = 0x452C39`；
  keystone 给出 `E9 DC 32 FB FF` ⇒ `0x452C39 + 0xFFFB32DC` = `0x405F17` ✓
- 入口跳板 `0x405EF9 + 5 + 0x0004CD02` = `0x452C00` ✓
（三条均由 `_v5防御暴击修复.py` 的 `verify_displacement()` 自动验算，预演已输出 OK）

## 风险与边界

- **连击段仍然"免伤"**（交回原生逻辑 ⇒ 走特效归零/零伤害分支）。这是**故意**的：
  完全免伤不会崩，而对已阵亡目标结算会崩。若要连击段也吃减伤，需要另行改造
  `0x405F24..0x405F49` 的归零分支并重做安全性验证，风险更高。
- 本修复只解决**闪退**；v4/v5 的"减伤数值是否正确"仍需实机采样（见待验证清单）。
- 换样本（SHA 变了）时 `--apply` 会被 SHA 校验拦住，不会误写。
- 回滚点：v5 写入前自动备份 `Ekd5备份\补丁前备份\Ekd5.exe.bak_before_critdef24v5_<时间戳>`。

### 由此得到的三条结论

1. **v5 补丁确实被执行**：`0x452C00` 只能由 `0x405EF9` 的 `jmp 0x452C00` 进入
   （该地址是补丁专属的代码洞位置），命中即为铁证。
2. **v5 在"非连击路径"下是安全的**：样本 A 里 v5 执行后进程继续存活。
3. **连击路径（`+608 > 0`）另有崩溃点**：样本 B 里 FF 出现在 `连击=1` 的伤害之后。
   也就是说 —— v5 补回的 `cmp byte [ecx+0x608],0` 只解决了"跳过判断"，
   但**交回原生 `0x405F24` 之后那条分支本身**在特定条件下仍会崩。

  需要在本补丁内取到**目标单位指针**以读当前 HP（`[ebp-0x20]` 是攻击者，
  目标需由 `ctx+0x01` 的 slot 反查单位表或用 `0x40658F`）。
- **P1**：确认 `0x4B4250`（显示上下文）与 `+0xC` 的真实语义，
  以及 `0x4D4200` 那张表的用途。
- **P1**：确认 `0x4E30E1` / `0x4E3000`（连击判定/执行）的入参与返回语义。

### 证据来源

- `_自动打几轮.py` / 内联断点跟踪脚本的运行输出（逐步命中序列 + ctx 读数）。
- 离线反汇编：`_dsh反汇编工作台.py da 0x4D4000 30`、`da 0x4064F1 40`。
- 跳转来源：字节级 `E9 rel32` 扫描（`0x4363B0 -> 0x4D4000`）。

### ⚠️ 口径修正（2026-10-14 追加）：`0x4D4022` **不是**崩溃点

对**当前 EXE**（`A9FD91560E715F40A5D77483CF673A2F16522EC0BDA1F93852A4915F8E2D5DF2` = v5 + envsave）
重新执行 `_dsh反汇编工作台.py da 0x4D4000 40`，注入函数自带的**三道空值保护**是完整的：

```
004D4014  85 FF          test edi, edi          ; 回合和 == 0 → 跳过
004D4016  74 2F          je   0x4D4047
004D4018  8B 1D 50 42 4B 00  mov ebx, [0x4B4250] ; 显示上下文
004D401E  85 DB          test ebx, ebx          ; ★ 上下文 NULL → 跳过
004D4020  74 25          je   0x4D4047
004D4022  8B 4B 0C       mov  ecx, [ebx+0xC]
004D4025  85 C9          test ecx, ecx          ; ★ 攻击者 NULL → 跳过
004D4027  74 1E          je   0x4D4047
```

⇒ **`[0x4B4250]` 为空时根本执行不到 `0x4D4022`**；`0x4D4022` 至多是"断点停在那里"被记成了崩溃点
（`_抓连击崩溃.py` 的 `NEAR` 集合里本来就把它当疑似点下过断点）。
**在真正拿到异常码之前，`0x4D4022 = 崩溃点` 这条口径撤回。**

**该函数内唯一没有保护的解引用是入口处**：

```
004D4005  8B 74 24 1C    mov  esi, [esp+0x1C]   ; 参数2 = 目标单位指针
004D4009  0F B6 46 1E    movzx eax, byte [esi+0x1E]   ; ★ 无 NULL 检查，esi 非法即崩
```

即：若 `0x4363B0`（vendor 伤害修正）在某个路径上以**空/非法目标指针**被调用，
崩溃点应是 `0x4D4009` 而不是 `0x4D4022`。候选修法：入口补 `test esi,esi / je 跳过`
（注入块可整体后移 4 字节，`je` 的 rel8 不变、两处 rel32 需按新地址重算）。

**取真凭据的手段（已就绪）**：已为 `Ekd5.exe` 打开本地崩溃转储
（`HKLM\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps\Ekd5.exe`，
`DumpType=2` 全转储 → `大鲸鱼产生专用\_崩溃转储\`）。复现一次崩溃即可从转储读出
**异常码 + 出错地址 + 当时的 `esi`/`[0x4B4250]`**，不必再靠断点猜。

## ★ v6 崩溃根因与修复（2026-10-14，已闭环）

### 一句话根因

**代码洞起点选错 1 个字节。** v6 补丁体写在 `0x452E68`，而那个字节是历史补丁函数
`0x452E18` 结尾指令 `8B E5 5D C2 04 00`（`mov esp,ebp; pop ebp; ret 4`）的
**立即数末字节 `00`**。补丁体首字节 `56`（`push esi`）覆盖它之后，
指令从 `C2 04 00`（`ret 4`）变成 `C2 04 56`（**`ret 0x5604`**）。

### 因果链（每步都有独立证据）

| # | 事实 | 证据类型 |
|---|---|---|
| 1 | `0x452E66` 原为 `C2 04 00`（`ret 4`） | 基线 `Ekd5.exe.bak_20261012_180738` 字节复读 |
| 2 | v6 写 `0x452E68` = `56`（`push esi`） | v6-fix 前字节复读（SHA `B6EBDE6B…`） |
| 3 | `ret 4` → `ret 0x5604`，返回时 ESP 额外 +0x5600 = 22016 字节 | 反汇编 |
| 4 | ESP 跑出线程栈 | **minidump** 解析 |
| 5 | 在 `0x43A6D4` 的 `push ecx` 写 `ESP-4`（未提交页） | minidump + x32dbg |
| 6 | `c0000005`（写访问冲突） | WER 事件 1000 + dump |

### 数字对账（三条独立来源互相咬合）

```
线程栈范围（dump）        = [0x00749000, 0x00750000)   仅 0x7000 = 28 KB
dump: 访问类型            = 写
dump: 访问地址            = 0x00755330   （= ESP-4，push 的落点）
dump: 该地址可读          = False

正常 ESP ≈ EBP-0x38 = 0x74FD20；+0x5600 = 0x755320 ≈ 实测 0x755334 ✓（差 20 字节）
```

### 现场的关键形态（可用于快速识别同类问题）

- 异常落在 **`push`/`pop`/`call` 这类"触碰栈"的指令**上，且 `ESP` **高于** `EBP`；
- `memory_get_info(ESP)` 显示 **`MEM_RESERVE` / `protection=UNKNOWN`**；
- 栈顶内存**读不到**（不是权限问题，是那页没提交）；
- 调用栈（EBP 链）**完全健康**、无递归、返回地址在栈里只残留 1 份
  ⇒ 不是递归、不是反复调用累积，而是**单次返回把 ESP 抬飞**。

### 修复

1. `CAVE_V6`：`0x452E68` → **`0x452E69`**（真正的 `90` 填充起点，连续 157 字节）；
2. 预检判据收紧：只接受 **`0x90`/`0xCC`**，**不再把 `0x00` 当空白**；
   并在写前打印"洞前 16 字节"供人工核对洞起点是否落在指令中间。
