## 结论速览

- 物理暴击伤害公式（用户口径，权威）：`最终 = 原伤害 × (基数 + [暴击率×1/2] + 特技 0x70 特效值) / 100`。**基数取决于分支**：**常规暴击（`0x4287A8` 判定成功、`0x405EE6` 给 K 加 100）⇒ 基数 = 150**；**暴击率 > 100 的必暴分支（`0x405ED8 ja` 跳过加 100）⇒ 基数 = 100**。特技 `0x70` 的特效值是**额外加算**。⇒ 即用户原式 `150% + [暴击率×1/2]%` 在常规暴击路径下成立，不是被"修正"掉。详见本页末「K 有两个分支」（含字节复读）。

## 一、★ 物理暴击伤害公式（用户口径，权威）

```
物理暴击造成的伤害 = 原伤害 × (100% + [暴击率 × 1/2]%)
```

- **基数 100%**（不是 150%）—— 即"暴击本身不加成，加成全部来自 `暴击率/2`"
- **特技 `0x70`（暴击伤害增幅）**：在其特效值存在时**额外加算**：
  `最终 = 原伤害 × (100 + 暴击率/2 + 特效值) / 100`

**与静态代码的对应**：

```asm
00405ED5  cmp eax, 0x64          ; eax = 暴击率（`0x40C7D8` 的返回值，0x100=十进制256？实测为百分数）
00405ED8  ja  0x405EEA           ; ★ 暴击率 > 100 ⇒ 跳过下面那条 add
00405EDD  call 0x4287A8(2, eax)  ; 随机判定（累积机制，见下）
00405EE4  je  0x405F24           ; 未暴击 ⇒ 跳过
00405EE6  add [ebp-0x24], 0x64   ; ★ 暴击率≤100 且判定成功：K = 暴击率 + 100
00405EEA  ...
00405F02  push [ebp-0x24] → call 0x42E4FD   ; ★ 把 [ebp-0x24] 当 K 用
```

`0x42E4FD` 内部：

```asm
0042E513  mov ecx,[ebp+0xC]      ; = [ebp-0x24]（即上面的 K）
0042E516  sar ecx,1              ; ★ K/2  ← 就是公式里的「暴击率 × 1/2」
0042E51C  add ecx,eax            ; + 特技 0x70 的特效值（加算）
0042E524  call 0x425AD9          ; ×百分比/100
0042E52C  add [edx],eax          ; 加进伤害
```

⇒ **`暴击率>100` 时 `[ebp-0x24]` 保留原值**，所以 `K/2` 自然变大 ⇒ **额外增伤**（用户所指）。

## 二、暴击率来源与累积机制

```asm
00405ECD  call 0x40C7D8          ; → EAX = 暴击判定值
00405ED2  mov [ebp-0x24], eax
```

`0x40C7D8` 内部：

```asm
0040C7E4  call 0x4061f9          ; 单位指针
0040C7F6  call 0x40d2ab          ; 取值
0040C80A  call 0x44f9a9          ; 查特技 0x33（掩码 0x31）
0040C813  add [ebp-8], 0x64      ; 有该特技 ⇒ +100
0040C81A  call 0x45eeb0          ; 上限钳制等
```

`0x44F9A9`：`push 0 / 3 / 0x31 / 0x33 → call 0x4101D9 → and eax,[ebp+8]`（按位掩码）。

**累积暴击机制**（`0x4287A8`）：

- `[ebp+8]` = 传入值（本处为暴击率），`[ebp+0xC]` = 模式（1=被攻击方）
- 累积值存 `0x4930C8 + 单位索引*4`（本样本读到的是 `0x0A0A0A0A` 之类的常量，**真实布局待复核**）
- 模式0：`累积 + 暴击率 ≥ 100` ⇒ 暴击并 `-100`；模式1：`累积 + 100 - 暴击率 ≥ 100` ⇒ 暴击

## ★★ 2026-10-14 口径纠正：`K` 有**两个分支**，不是"150% 被修正为 100%"

**字节复读证据**（样本 SHA `135A22E7…`）：

```asm
00405ECD  call 0x40c7d8          ; EAX = 暴击率
00405ED2  mov  [ebp-0x24],eax    ; K 初值 = 暴击率
00405ED5  cmp  eax,0x64
00405ED8  ja   0x405eea          ; ★ 暴击率>100 ⇒ 跳过下一条 ⇒ K 保持 = 暴击率
00405EDD  call 0x4287a8(2,eax)   ; 随机判定
00405EE4  je   0x405f24          ; 判定失败 ⇒ 不暴击（走 0x405F24 分支）
00405EE6  add  [ebp-0x24],0x64   ; ★ 判定成功 ⇒ K = 暴击率 + 100
00405EEA  mov  ecx,[ebp-0xc]
00405EED  mov  eax,[ebp-0x20]
00405EF0  call 0x42aa2a          ; 取 0x24（防御暴击）判定
00405EF9  (v6-fix 跳板)
00405F02  push [ebp-0xc]
00405F05  push [ebp-0x24]        ; ★ 把 K 传给 0x42E4FD
00405F08  push [ebp-0x28]
00405F0B  call 0x42e4fd          ; 暴击加成
```

| 分支 | 条件 | `K` = `[ebp-0x24]` | 最终系数 |
|---|---|---|---|
| **常规暴击** | 暴击率 ≤ 100 且 `0x4287A8` 判定成功 | 暴击率 **+ 100** | **150% + [暴击率×1/2]%** |
| **必暴分支** | 暴击率 **> 100**（`ja` 跳过 `+100`） | 暴击率 | **100% + [暴击率×1/2]%** |

- ⇒ **用户原口径 `150% + [暴击率×1/2]%` 在常规暴击路径下正确**，不是被"修正"掉。
- ⇒ 本页速览第 1 条的"修正为 100%"表述，只适用于**暴击率>100 的必暴分支**。
- 两分支都再叠加特技 `0x70` 的**加算**值（`0x42E51C add ecx,eax`）。

## ★★ 2026-10-14 用户补充：**普罗集气模式**（整型 `4018` = `0x505EC8`）

> 用户口径原文：整形 `4018=1`，地址 `505EC8`。假如暴气为 70，本次理论暴击率为 30，
> `70＋30>=100`，普罗集气模式：在角色每次进行攻击，闪避/暴击/连击都会储存
> **伤害预览中显示的闪气/暴气/连气**，当该类别集气达到 100 时，伤害预览对应显示为**红色**，
> 则**必定触发**闪避/暴击/连击。**99% 暴击率是不能暴击的，必须达到 100% 才能触发暴击。**

### 机制要点

| 项 | 内容 |
|---|---|
| **开关** | 整型变量 `4018`，地址 **`0x505EC8`**；`= 1` 表示启用集气模式 |
| **三类集气** | 闪避（闪气）/ 暴击（暴气）/ 连击（连气），**各自独立累计** |
| **显示位置** | **伤害预览面板**（即用户截图里的「命中/暴击/连击」三行） |
| **满值表现** | 集气达 **100** ⇒ 预览对应项**显示为红色** ⇒ **必定触发** |
| **判定式** | `已有集气 + 本次理论率 ≥ 100` ⇒ 该类触发（例：暴气 70 + 本次 30 = 100 ⇒ 必暴） |
| **累积存放** | `0x4930C8 + 单位索引*4`（与 `0x4287A8` 的累积数组一致） |

**关键推论**：集气模式下**暴击是"累计必触发"，不是"单次按概率掷骰"**；
因此 **99% 暴击率不会暴击**，必须累计到 100 才触发。
⇒ 干等战斗**不一定出暴击**，验证时必须先把集气喂满（或选已满的单位）。

### ⇒ 由此定死「暴击伤害公式两分支」的归属

| 分支 | 触发条件 | `K`（`[ebp-0x24]`） | 最终系数 |
|---|---|---|---|
| **A 常规** | 本次理论率 **≤ 100**，且 `0x4287A8` 集气判定成功 | 率 **+ 100** | **150% + [暴击率×1/2]%** |
| **B 溢出** | 本次理论率 **> 100**（`0x405ED8 ja 0x405EEA` 跳过 `+100`） | 率 | **100% + [暴击率×1/2]%** |

- 两分支**并存**，不是"150% 被修正为 100%"。
- 用户原公式 `150% + [暴击率×1/2]%` 对应 **A 常规**（集气触发路径）；
  `100% + [暴击率×1/2]%` 对应 **B 溢出**（本次率本身就 >100 的情形）。
- 实机数据（基础 428 → 暴击 693，倍率 1.62）与 **A 常规**一致：

## 2026-10-17 追加：★★★ 集气模式（4018=1）下的「暴击预览」对齐 —— v2 已装并静态复读通过

> 起因（用户口径）：「在集气模式 4018=1 的情况下，暴击集气实际已经可以暴击了，但是暴击预览因为未达到 100% 或者别的原因，预览的并非暴击后的伤害结算」

### 一、根因（v1 洞体缺集气判定）

* v1 洞体 `0x457DB4` 在算完暴击率后是：`0x457DFA 83 F8 64 cmp eax,0x64` / `0x457DFD 72 26 jb no_bonus`
  ⇒ **暴击率 < 100 一律不加成**；只有 `==100` 走 `mov eax,0xC8`、`>100` 直接当 K。
* 实战不是这样：`0x405EDD E8 C6 28 02 00 call 0x4287A8(K,2)` 先做**累计判定**（`0x405ED5 83 F8 64 / 0x405ED8 77 10 ja` 只在 K>100 时跳过），
  命中才 `0x405EE6 83 45 DC 64 add [ebp-0x24],0x64`（K+=100）→ `0x405F0B call 0x42E4FD(&damage,K,ctx)`。
  ⇒ 集气模式下「已有集气 + 本次率 >= 100」即必暴，**K 可以只有 30**；v1 预览却按非暴击显示。

### 二、★ 定案：`0x4287A8` 模式 2 读的是**攻击者**的集气字节（此前「余数最低位」的表述过糊）

```asm
004287C3  3C 01          cmp  al,1          ; al = 模式/16（0=物理 / 1=策略）
004287C5  74 07          je   0x4287CE
004287C7  B8 F0 27 49 00 mov  eax,0x4927F0  ; 物理上下文
004287CC  EB 0E          jmp  0x4287DC      ; ★ 直接跳走：edx 仍 = mode&1（模式2 ⇒ 0 ⇒ ctx+0）
004287CE  B8 F8 7A 49 00 mov  eax,0x497AF8  ; 策略上下文（只有这一支才走下面 3 行）
004287D5  74 04          je   0x4287DB
004287D7  B2 0C          mov  dl,0x0C
004287DB  42             inc  edx
004287DC  0F B6 0C 10    movzx ecx,byte [eax+edx]
```

* **物理**：模式 `2`（物理暴击）⇒ `ctx+0`；模式 `1`（物理闪避）⇒ `ctx+1`；模式 `0`（连击）⇒ `ctx+0`。
* `ctx+0` = **攻击者战场编号**、`ctx+1` = **目标战场编号** —— 后者有直接写入证据：
  `0x405E32 88 51 01 mov [ecx+1],dl`（`ecx` = `[ebp-0xC]` = ctx，`dl` = 逐目标循环里读到的目标编号）。
* 判定式（`0x428808..0x428811`）：`add edx,[ebp+8]` → `cmp dl,0x64` → `jb` 不触发；否则 `inc eax` 并 `sub dl,0x64`（扣 100）。
  ⇒ 集气字节地址 = **`0x4930C8 + 攻击者战场编号*4 + 2`**。
* `0x4287BA 80 3D DC 5F 50 00 00 cmp byte [0x505FDC],0` ⇒ 非 0 走**原版随机** `0x43786B`；该开关实测 **=0**。

### 三、预览帧的身份（v1/v2 都依赖它，本轮逐条复核）

`0x441626 call 0x44049E`（`ecx` = 目标单位、`[ebp+8]` = 模式 1/2/3、`[ebp+0xC]` = 攻击者编号、`[ebp+0x10]` = 目标编号）内：

| 槽 | 身份 | 证据 |
|---|---|---|
| `[ebp-0x28]` | **目标单位** | `0x43BC5A` 的 `[ebp+8]`（实战略同源，库内标「★ 目标单位」）；`0x44062C push [edx+0x10]` 画 HP 条；`0x44068D` 用 `[目标+0x10]` 算血量 |
| `[ebp-0x2C]` | **攻击者单位** | `0x440656 mov cl,[ebp+0xC]` → `0x4061F9` → `0x44065E` 存；`0x440668` 作 `0x43BC5A` 的 `ecx` |
| `[ebp-0x18]` | 预览伤害 | `0x44066D` 写入、`0x440683` 读出 |

* `0x40C7D8({+1=目标编号, +0xC=攻击者单位指针})`：先 `8A 49 01 mov cl,[ecx+1]` → `0x4061F9`（目标单位），
  再用 `[ecx+0xC]`（攻击者）查特技 `0x33`（+100）⇒ 与 ctx 的同名语义完全一致。
* 预览面板 `0x4131CF` 印证同一口径：`[ebp+0x10]` = 目标（算暴击率）、`[ebp+0x14]` = 攻击者（**显示集气**）。

### 四、v2 实现（只读，不消耗集气）

* 挂钩点仍是 `0x44066D`（5 字节）：`89 45 E8 6A 01` → `E9 ED FD FE FF`（→ `0x43045F`）。
* 洞体搬到 **`0x43045F`（169 字节，`0x43045F~0x430507`）**：该段 `.code` 连续 `0x90` = **4324 字节**（`0x43045F~0x431542`，
  `0x431543` 起是活代码）；`_注入地址占用登记.py --check` 报**空闲**，全映像无该址 4 字节指针、无 `E8/E9` 指入。
  旧洞 `0x457DB4`（122 字节）已**清回 `0x90`**（它紧贴 `0x457E2E` 的「奋战攻击 v1」声明区，原 122 字节已无余量）。
* 洞体判定（与 `0x405ED5..0x405EE6` 同构）：
  1. `K = 0x40C7D8(...)`；`K > 100` ⇒ 直接以 K 进加成（与实战 `ja` 一致）。
  2. `[0x505EC8] != 1`（非集气）⇒ 旧口径（`K==100` 视 200，`K<100` 不暴击）。
  3. `[0x505FDC] != 0` ⇒ 不打加成（实战走随机，预览无法预测，取保守）。
  4. 否则读 `byte[0x4930C8 + byte[攻击者单位+4]*4 + 2]`；`(字节 + K) >= 100` ⇒ `K += 100`
     （**只读、不写回、不扣 100** ⇒ 预览反复评估不会吃掉实战的暴击）。
  5. 加成仍走 `0x42E4FD(&damage, K, {+0xC=攻击者单位})`（与实战 `ctx+0xC` = 攻击者等价）；最后按**目标 HP**封顶。

### 六、仍存的差异（本版故意不做）

1. `0x42AA2A`（目标 `0x24` 完全免伤 / 攻击者 `0x70` 互斥）需要物理上下文 `0x4927F0`，预览帧没有 ⇒ 预览仍不显示 0x24 免伤。
