# 异常状态位定义（`unit+0x1E`）

样本：`复刻版6.6山贼\Ekd5.exe`
证据 SHA256：`08EF607BCB4422EA3400B37D0CBFECF4A39839F440018E80157577102C8BF914`（本次写入后）

## 结论速览

单位异常状态存在 **`unit+0x1E`**（1 字节）里，是**单 bit 标志**（不是"2-bit 位段"）：

| 异常状态 | 字节掩码（窗口） | 代码里的选择子 |
|---|---|---|
| **麻痹** | **`0x03`**（位 0-1） | `0x02` |
| **封锁**（旧称禁咒） | **`0x0C`**（位 2-3） | `0x04` |
| **混乱** | **`0x30`**（位 4-5） | `0x08` |
| **中毒** | **`0xC0`**（位 6-7） | `0x10` |
| 正常（无异常） | `0xFF` | 显示分支里单独判等 |
| 选择子 `0x01` | — | **永不命中**（`0x423FE8` 先右移再测第 0 位） |
| `0x01` | 未知 | 见"待验证项" |
| `0x20 / 0x40 / 0x80` | 未见于上述循环 | 未验证 |

- 每个 2-bit 窗口各自独立，窗口非零即算该状态存在。
- 窗口内取值 `1/2/3` 的含义（强度？剩余回合？）**待验证**。
- **第二处独立证据**：特技 `0xE2` 向死而生的实现 `0x43D472` 用 `xor eax,eax / mov al,2 / shl eax,cl`（i=0..3）生成 `0x02/0x04/0x08/0x10` 去测状态 —— 与上面的显示循环取同一组位值。
- ⚠️ **不要把 `0x03 / 0x0C / 0x30 / 0xC0` 当成状态位**：那组 2-bit 掩码属于**全局设定里的「异常持续回合」四项**（旧条目里搞混过，见 `90-来源归档/复刻版6.6山贼错误知识纠正台账.md`）。

## 适用版本

- 复刻版6.6山贼当前样本；地址为 VA，改前按补丁纪律复读原字节。

## 已确认事实

### 1. 逐状态显示循环（位值来源）`0x478A10`

```asm
00478A10  push ebp / mov ebp,esp / push 0 / sub esp,0xF8 / push 0
00478A1C  mov  ecx,[ebp+0xC]            ; 状态字节（参数）
00478A1F  cmp  cl,0xFF / jne 0x478A30
00478A24  mov  eax,0x486D00             ; 0xFF → 「正常」
00478A38  mov  [ebp-0xC],esp            ; 输出缓冲
00478A3B  mov  ecx,[ebp-4]              ; i（0 起）
00478A3E  cmp  cl,4 / jae 0x478A71      ; 循环 4 次
00478A43  mov  eax,1
00478A48  inc  ecx
00478A49  shl  eax,cl                   ; ★ 测试位 = 1 << (i+1) → 0x02/0x04/0x08/0x10
00478A4B  push eax / mov ecx,[ebp-8] / call 0x4240E2   ; 位测试
00478A54  test eax,eax / je 0x478A6C    ; 未置位 → 下一个
00478A5D  imul ecx,ecx,5                ; 名字 stride = 5 字节
00478A61  add  ecx,0x486D06             ; ★ 名字表基址 = 「麻痹」
00478A67  push ecx / push [ebp-0xC] / call 0x47ABA8    ; 追加名字
00478A6E  inc  [ebp-4] / jmp 0x478A3B
```

⇒ i=0 测 `0x02` 取「麻痹」、i=1 测 `0x04` 取「封锁」、i=2 测 `0x08` 取「混乱」、i=3 测 `0x10` 取「中毒」——**位值与名字一一对应**。

### 2. 状态名表（VA `0x486CFC` 起，stride 5）

| VA | 名 |
|---|---|
| `0x486CFC` | 无 |
| `0x486D00` | 正常 |
| `0x486D06` | **麻痹** |
| `0x486D0B` | **封锁** |
| `0x486D10` | **混乱** |
| `0x486D15` | **中毒** |
| `0x486D1A` | 行动完毕 |

（「行动完毕」由另一处判定单独打印：`0x478B1A`–`0x478B24` 引用 `0x486D1A`，与上面 4 状态的位循环无关。）

### 3. 策略类型 → 状态字节 映射表 `0x420630`

字节序列：`00 01 03 02 0C 04 05 06 06 06 06 0A 0A 0A 0A 02 04 00 01 07 08 09 0C 0C 0C`
—— 取值全部是 **bit0–3 的组合**（`01/02/03/04/05/06/07/08/09/0A/0C`），与"状态＝位标志"一致；其中 `0x01` 出现于此表但**不在**上面 4 状态的显示循环里 → 语义待验证。

### 4. 清除点

`mov byte [reg+0x1E], 0` 出现在 `0x4248A0`、`0x441827`、`0x4427B1`、`0x45336F`（四处均为**整体清零**）。

## 实现·使用方法

- 判某个状态：`movzx eax,byte [unit+0x1E]` 后 `test al, <位值>`。
- 多状态命中：按位与后逐位累加（本库「异常追袭」特技的 256 字节查表 `0x4D4200` 就是这个做法：位映射 = 麻痹`0x02`/封锁`0x04`/混乱`0x08`/中毒`0x10`，权重 2/1/2/5，`b & 0x01` 与 `b & 0xE0` 一律忽略）。
- 写状态：优先调用引擎的状态函数，不建议裸写该字节（旧工具与早期注入样本都踩过）。

## 风险与边界

- `0x01` 的语义未定；上面 4 状态的位值来自**显示循环**，若某状态在别处用不同位（例如"毒"与"中毒"分开），需另证。
- 本页只覆盖 `unit+0x1E`；`unit+0x0D`（行动状态位）与 `0x508B00`（二次行动状态数组）是另外的字段，不要混用。
- 全局设定的「异常持续回合」是**另一个对象**（2-bit 位段：麻痹 `0x03`/禁咒 `0x0C`/混乱 `0x30`/中毒 `0xC0`；见更新记录 2026-07 条目），与本页位值**不可互换**。

### 策略类型 → 状态字节表 `0x420630`（运行时复读，24 字节）

```
00 01 03 02 0C 04 05 06 06 06 06 0A 0A 0A 0A 02 04 00 01 07 08 09 0C 0C
```

按 2-bit 窗口拆解：`0x0A` = 麻痹2+封锁2；`0x0C` = 封锁3；`0x05` = 麻痹1+封锁1 ⇒ **窗口里存的是 1~3 的"量"（强度或持续回合），逐状态独立且可组合** —— 与"中毒3/禁咒1/麻痹2/混乱2"这类设计值同量级。

### 状态名表（运行时复读，VA `0x486CF6` 起）

`%s ` / `无` / `正常 ` / `麻痹` / `封锁` / `混乱` / `中毒` / `行动完毕` —— 与静态一致，「封锁」为实际用字。

## ★ 活体实测定案（2026-10-13，x32dbg 挂在运行中的游戏上）

样本：用户正在运行的游戏（`Ekd5.exe` PID 3760，base `0x00400000`）；战术单位数组 `0x4A7B20`（250×0x30），58 条活体单位。

| 单位 | Data 号 | `+0x1E` | 拆成 2-bit 窗口 | 含义 |
|---|---|---|---|---|
| unit3 | `0x0001` | **`0x22`** | 窗口0=2、窗口2=2 | **麻痹 2 回合 + 混乱 2 回合** |
| unit4 | `0x001D` | **`0xC0`** | 窗口3=3 | **中毒 3 回合** |

关羽记录原始 48 字节（`0x4A7BB0`）：
```
01 00 00 00 03 00 0A 18 FF 00 00 04 02 00 07 00 5A 02 00 00 20 00 00 00 06 03 03 06 03 06 22 01 FF FF ...
```
（`+0x10` HP=`0x25A`=602，`+0x14` MP=32，`+0x1E`=0x22，`+0x1F`=0x01）

### 结论（三条，均由活体数据支持）

1. 状态字节 = **4 组 2-bit 窗口**（单 bit 模型**否决**）。
2. **窗口里的数字 = 该状态的剩余/持续回合数**（1~3，与设计值 中毒3/麻痹2/混乱2 完全吻合）。
3. 窗口顺序与掩码：**窗口0 麻痹 `0x03` / 窗口1 封锁 `0x0C` / 窗口2 混乱 `0x30` / 窗口3 中毒 `0xC0`**。

### 由此得到的直接用法

- 取回合和：`回合和 = (字节 & 3) + ((字节>>2) & 3) + ((字节>>4) & 3) + ((字节>>6) & 3)`（各窗口值 = 各自剩余回合）。
- 例：关羽 `0x22` → 2+2 = **4**；中毒者 `0xC0` → **3**；四种全中 `0xFF` → 3+3+3+3 = **12**。
- 若要做"特效值 × 回合和"的加成，**直接用窗口值求和**即可，无需补丁自维护倒计时（本库「异常追袭」原先用固定权重表，可按此升级为真实回合和）。

## 2026-10-15 第 2 轮：随机状态攻击 `0x42119B` 全函数 + 写入路径 `0x4240D6` + 组掩码表使用者

### 1. `0x42119B`（GCC 序言 `55 89 E5`，`ret 8`，2 个栈参）

### 2. 写入路径 `0x4240D6`（函数入口 `55 8B EC`，紧邻取反掩码表右侧）

- `0x4240D6` 由 `0x42119B` 调用（参数：`ECX = unit`、`push 选择子`），
  **它就是外部页所称"写入路径将被选中的状态组设为 `3`"的落点**（写入初值 = `3` 待下一轮逐条取证）。
- 位置旁证：`0x4240CA`=`FC F3 CF 3F`、`0x4240D2`=`03 0C 30 C0`、`0x4240D6`=函数序言 `55 8B EC`
  ⇒ 三张表/函数在同一小段内，`0x4240D6` 属"状态写入"族。

### 3. `0x4240D2`（`03 0C 30 C0` 组掩码表）的使用者（P2 闭环）

`xref 0x4240D2` ⇒ **2 处**：`0x423FD5`（就在状态查询函数 `0x423FE8` 之前，属同一族）
与 `0x4399C2`（另一处调用）。**均无 call/jmp 直指、无数据段指针** ⇒ 它是被"指令内 disp32"引用的只读表。

## 2026-10-15 第 3 轮：写入路径 `0x4240D6` / 判定 `0x47FB32` / 取值 `0x4032DF` 全解（静态）

> 样本 `Ekd5.exe` SHA256 `25DB2211FE8F495DE4993BAB296C23C180E18679F00A0E43B47B1FD2034B7EAF`；
> **原始字节已回读核对**（`db 0x4211E4 24` / `db 0x4240C8 24`）；证据层级 = 1 静态。

### 1. `0x4240D6` = 状态"置位写入"：**按选择子的置位位序 OR 掩码表**（不是"设为 3"）

```asm
004240D9  push 0 / push ecx        ; [ebp-4]=0(i)、[ebp-8]=ECX(unit)
004240DC  xor edx,edx              ; dl = 累计掩码 = 0
004240DE  mov ecx,[ebp-4] / cmp ecx,4 / jae 0x4240FB   ; ★ 只扫 selector 的 bit0..bit3
004240E6  shr dword [ebp+8],1      ; selector >>= 1
004240E9  test al,1 / je 0x4240F6  ; 该位为 1 才累加
004240F0  or  dl,byte [ecx+0x4240CE]   ; ★★ 掩码表[bitIndex]（原始字节 = 02 04 20 C0）
004240FB  pop ecx / or byte [ecx+0x1E],dl   ; ★★ 把掩码 OR 进 unit+0x1E
00424102  ret 4                    ; stdcall，清 1 个栈参
```

**掩码表 `0x4240CE` = `02 04 20 C0`**（按 selector 的 **bit0→bit3** 索引）：
bit0→`0x02`（麻痹窗口值 2）、bit1→`0x04`（封锁值 1）、bit2→`0x20`（混乱值 2）、bit3→`0xC0`（中毒值 3）
⇒ 写入的是**该位对应类别的"强度值"位型**，**不是统一设 3**（外部页口径需重定位，见对账页）。
紧邻的 `0x4240D2` = `03 0C 30 C0` 是**另一张表**（窗口掩码，由 `0x423FD5`/`0x4399C2` 使用），两张表不可混。

### 2. `0x47FB32` = 百分比阈值判定（**语义已定**）

```asm
0047FB35  push 0x64 / call 0x47FB13   ; 取 0..99 随机数
0047FB3C  cmp eax,[ebp+8]             ; 随机 vs 参数
0047FB3F  mov eax,1 / adc eax,-1      ; EAX = (随机 < 参数) ? 1 : 0
0047FB48  ret 4
```
⇒ **参数 = 命中百分比**：`0x64`(100) ⇒ **恒真**；`0` ⇒ **恒假**。
结合 `0x42119B` 表2 `0x4211EC` = `00 64 64 00` ⇒ 四类里**只有 i=1、i=2 恒通过**，i=0、i=3 **恒不通过**（本样本硬编码）。

### 3. `0x4032DF(arg)` = 读 `byte [ECX + 0x2F + arg*3]`（步长 3 的字段数组）

```asm
004032E2  movzx eax,byte [ebp+8] / imul edx,eax,3
004032E9  movzx eax,byte [ecx + edx + 0x2F] / ret 4
```
`0x42119B` 以 `arg=0` 调用 ⇒ 取的是 **`[arg2 + 0x2F]`**。
⚠ 但表1 `0x4211E8` = `00 00 00 00` ⇒ `AL × 0` ⇒ **这个取值在本样本被乘零、实际不参与阈值**
（即"按对象数值加权的随机状态"在本样本**失效**，阈值退化为常量 `{0,100,100,0}`）。

### 4. ★ 疑点（静态发现，需运行时确认）：**选择子位序不匹配**

- 查询侧 `0x423FE8` 用 **`2<<i`** = `0x02/0x04/0x08/0x10`（内部**先右移一位**再测 bit0）；
  本页第 2 轮记录 `0x42119B` 的 **表3 `0x4211F0` = `04 10 02 08`** 也属这一族（置位在 bit1..bit4）。
- 写入侧 `0x4240D6` **不预移位**，只扫 **bit0..bit3** ⇒ 收到 `0x10`（bit4）时**什么都不写**；
  且 `0x04`(本意封锁) 会被当成 bit2 → 写 `0x20`(混乱)、`0x02`(本意麻痹) 被当成 bit1 → 写 `0x04`(封锁)。
- ⇒ 若 `0x42119B` 确实把 `04 10 02 08` 直接传给 `0x4240D6`，则**实际写入的类别是错位的、且有一类越界丢失**
  （这与"随机状态只施加 2 类"叠加后，净效果可疑）。
  **本库不据此下"是 bug"的断言**（第 0-1 条）——登记为 P2，判据见待验证清单（实机看 `unit+0x1E` 实际变化 + 断点比对）。

## 2026-10-15 第 11 轮补：`unit+0x1E`（异常状态）的**第三条写入路径**（统一入口）

本页第 1/3 轮登记的写入路径之外，**新增一条更上层的统一入口**：

| 路径 | 形态 | 说明 |
|---|---|---|
| `0x42119B` → `0x4240D6` | 逐类掷骰后按 selector 位序 OR 掩码表 | 第 2/3 轮（"随机状态攻击"） |
| `0x42402C` 清除路径 → `0x45AA37` | 回合恢复：`(unit[0], 6, 选择子\|0x80, 1, unit[4])` | 第 1 轮 |
| **`0x45AA37(编号, 6, 值, …)`** | **统一入口**：值 `& 0x80` ⇒ `0x423FB9`（清除）；否则 ⇒ `0x4240D6`（置位） | **第 11 轮（本轮）** |

- ⇒ **`0x45AA37` 的类别号 `6` 就是"异常状态"这一类**，其内部再按 `0x80` 位分流到"清除"或"置位"。
- **`0x80` 位的语义**：**"清除/负面方向"标志**（与第 8 轮 `0x4240D6` 里 `or al,0x80` 的"强制清除"标记一致）。
- 本条与第 3 轮的结论**不冲突**：`0x4240D6` 仍是"按位 OR 掩码表"的**实际写者**；
  `0x45AA37` 是**上层门禁 + 分流器**（含编号解析与 `0x418C90==2` 校验）。

## 2026-10-15 第 12 轮：`unit+0x1E` 的**两个互补写入器**（置位 / 清除）

> 样本 SHA `25DB2211…`；**证据层级 = 1 静态**。两者形态一致（4 轮位扫描 + OR 表），**只差"测位方向"与"所用表"**。

### 置位版 `0x4240D6`（第 3 轮已解）

```asm
004240DC  xor edx,edx
004240DE  mov ecx,[ebp-4] / cmp ecx,4 / jae 0x4240FB    ; i = 0..3
004240E6  shr dword [ebp+8],1        ; selector >>= 1
004240EC  test al,1 / je 0x4240F6    ; ★ 位为 **1** 才累加
004240F0  or  dl, byte [ecx + 0x4240CE]                 ; 表 = `02 04 20 C0`
004240FC  or  byte [ecx_unit + 0x1E], dl                 ; 写 `unit+0x1E`
```

### 清除版 `0x423FB9`（本轮新解，47 字节）

```asm
00423FBF  xor edx,edx
00423FC1  mov ecx,[ebp-4] / cmp ecx,4 / jae 0x423FDE    ; i = 0..3
00423FC9  shr dword [ebp+8],1        ; selector >>= 1
00423FCF  test al,1 / jne 0x423FD9   ; ★ 位为 **1** 就跳过（不累加）
00423FD3  or  dl, byte [ecx + 0x4240D2]                 ; 表 = `03 0C 30 C0`
00423FDE  …                          ; 同样 OR 进 `unit+0x1E`
```

### 对照

| | `0x4240D6`（置位版） | `0x423FB9`（清除版） |
|---|---|---|
| 测位条件 | selector 位 **= 1** 才累加 | selector 位 **= 0** 才累加 |
| 掩码表 | `0x4240CE` = `02 04 20 C0` | `0x4240D2` = `03 0C 30 C0` |
| 写入 | `or byte [unit+0x1E], dl` | 同 |

⇒ **两者对同一 selector 互补**：一个设"被选中的类别"，一个设"未被选中的类别"。
第 11 轮 `0x45AA37` 类别 6 的 `0x80` 分流（含 `0x80` ⇒ `0x423FB9`）由此得到解释。

- **⚠ 数值语义（P2，别急着下结论）**：`0x4240CE` 的 4 个值按 2-bit 窗口读作"麻痹 2 / 封锁 1 / 混乱 2 / 中毒 3"，
  `0x4240D2` 则每窗口都是 3。究竟哪个数值代表"存在/正常/剩余回合"，
  **必须实机读 `unit+0x1E` 前后值**才能定（本库第 1/4 轮的"3 = 初值、随回合递减"是外部页口径的旁证，未在 6.6 实测）。
  判据：在 `0x4240D6` / `0x423FB9` 命中处读 `[ebp+8]`(selector) 与 `[ecx_unit+0x1E]` 前后值（**前提 `4018=1`**，按第 0-1 条做对照）。

## 2026-10-15 第 29 轮（**实机 + x32dbg**）：异常状态写入器 `0x4240D6` 的运行时常量与**两处自我更正**

### 4. ⚠ 两处**自我更正**（已入纠正台账）

1. **上一条我把 `0x4240D6` 称作"次入口（不是函数首）"—— 错。**
   现读字节 = **`55 8B EC`**（完整序言）⇒ **它是函数入口**。当时是 `funcstart` 的"前置边界"启发式**没认出来**就下了结论
   ⇒ 再证纪律第 5 条：**`funcstart` 只作线索，定性必须 `db` 序言字节**。
2. **上一条我按 5 个栈 dword 逐条标了 "arg1..arg4" —— 错。**
   调用点是 `push eax`（**只 1 个参数**）⇒ `[esp+0x08]/[esp+0x0C]/[esp+0x10]` 是**调用者栈帧残留**。
   ⇒ 教训：**`--stack N` 读出的"栈内容"必须先用调用点静态指令核对"推了几个"**，否则会把残留当参数。

### 5. 仍待定性（下一步判据已明确）

- **`ecx` 语义两说**：函数内 `cmp ecx,4 / jae` 明示它**期望 0..3 的小索引**；而本次现场 `ecx = 0x4A7BE0`（槽 4 单位指针）。
  ⇒ 要么"指针分支"另有用途，要么 **`ecx` 在不同调用点上语义不同**。
  **判据**：再抓 2~3 次，比较**不同返回地址**下的 `ecx` 与栈参数（若某次 `ecx ∈ 0..3` ⇒ 小索引说成立）。
- **掩码与 `+0x1E` 的对应**：本次写入参数 `0x10`（bit4）——与实测状态值 `0x80`（bit7）**不是同一位** ⇒ 说明 `0x80` 由**另一条路径/另一张表**落下；
  ⇒ 要把"某状态 = 某 bit"定死，需要在 `0x4240D6` 命中时**同时读被写对象的 `+0x1E`**（下一步给探针加 `--mem-at-ecx` 之类）。

### 6. ★★ 第 29 轮·补（第二次抓取，`--reg-mem`）：`ecx` 语义**定死为单位指针**，上一节的"两说"消解

> 工具：`_x32断点探针.py --address 0x4240D6 --watch ecx --stack 4 --reg-mem ecx,32 --mem 0x4240CE --secs 200`
> （本轮为该工具**再新增 `--reg-mem REG,N`**：命中时读"寄存器指向的内存"）；样本 `69A9074A…`（PID 6300）。

**命中现场的 `ecx` 指向对象 dump（32 字节）**：


| 偏移 | 值 | 本库字段 | 交叉核对 |
|---|---|---|---|
| `+0x00` | `01 00` | **DataID = 1** | = **关羽**，与驱动日志 `slot4 data1(关羽)` **一致** ✓ |
| `+0x05` | `00` | **阵营 = 0（我军）** | 槽 4 是我军 ✓ |

2. 函数内 `mov ecx,[ebp-4]` 取的是 **它自己 `push 0`（`6A 00`）压入的局部计数器**（初值 0）
   ⇒ `cmp ecx,4 / jae` 是**遍历那 4 项掩码表的循环条件**，**与入口 `ecx` 无关** ⇒ 上一节"`ecx` 语义两说"**消解**。
3. **参数链**：调用点 `0x420E58` 把 `表 0x420E7F[值>>1]` 压栈 ⇒ 本次 = `0x10`；**`+0x1E` 写入前 = 0**
   ⇒ 该次调用把 **bit4 (`0x10`)** 落到关羽身上（**是"置位"还是"清除"未定**，见待验证）。
4. 注意：掩码表 `0x4240CE`=`02 04 20 C0` / `0x4240D2`=`03 0C 30 C0`（两张 4 字节表）与调用点的 `0x420E7F`=`08 10 02 04`
   是**三张不同的表**；本次用的是 `0x420E7F`（**单 bit**：`08/10/02/04`）。
