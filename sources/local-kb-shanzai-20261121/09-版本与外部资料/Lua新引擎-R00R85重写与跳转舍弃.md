# Lua新引擎R00/R85重写、往返与跳转舍弃

## 结论速览

- 本页v2为历史阶段，当前v3已消除TF3500链，详见[独立EEX制作合同](Lua新引擎-独立EEX事件编写合同.md)；按用户“无条件跳转跨过的中间段就是不要”的意图迁移有效需求，不能把文件中仍存在的每段剧情/初始化都强制保留。
- 当前新游戏TF3500=1支配三处R00原76，v2剪除三个中间业务段；R85只删父帧必跳旧会议/1500钱，保留INT2500!=1可达的姜维/陈到加入与奖励。不承诺TF3500=0旧存档或中途Scene恢复等价。
- 复用既有Trace/parser及cczEditor2Doc的完整树writer合同；参考16R+当前根双R共18份逐字节往返一致，v2仅复核双R，不重复参考集。
- 12/13菜单按当前native共享选择字段合同，新增明确76出口；静态局部路径通过不等于完整VM或所有选项实点通过。
- 难度菜单初拍仅两行是逐行呈现中途；同次运行下一输入前画面已完整五档。不能把初拍行数当容量上限。
- 主控v2已正常收尾到R85奖励节点，未标稳定军营；v3静态候选已就绪，正式部署/动态状态以主控最新交接为准，不出击、不进S85。整体主线继续。

## 已确认事实

参考16R严格覆盖18399条，但11/12/13没有使用实例，不能由未使用推不支持。编码复用现有参数载荷与树结构，scene/section/child长度回填，76按目标节点重算相对位移；18份未改样本字节完全相等。

v2按当前新游戏合同删除源R00 [7780,11206)、[11275,15433)、[15482,19316)；这些位置均为原条件76越过的中段。顺序初始化TF3500=1支配三处条件，当前主控owned运行只读亦确认TF3500=1。 后续当前ctx布局/保存证据表明TF3500超普通TF0..2047区域；运行值1不证明合法/持久，v3已移除该setter/四个条件空跳并保留真分支必要动作，不能把v2历史写法当独立制作模板。R85删除[324,1463)；INT2500两条前置路径均跳过此段。另一跳转虽可越过加入段，但INT2500!=1仍会执行，故[1463,4926)加入/奖励必须保留。入边机器审阅确认剪除区间无其他原76目标或独立section入口；条件false和旧保存PC入口是明确范围差异。

v2所有保留节点与v1的opcode/参数载荷逐条一致；76只重算位移、目标节点身份不变。两个v2严格全字节覆盖，R00五菜单共13选项、R85四菜单局部45组路径通过；不模拟全部非菜单条件或财物状态。R85三项难度取消分支原case4改case3，原对白保留。

菜单画面对照为同一次正式运行：01:04:44难度初拍两行，01:05:08下一选择前完整五档；01:06:27暴走初拍一行，01:06:40无选择输入观察已两行。A线实际观图，输入属于主控。当前native显示按行推进、逐字绘制并等待，输入行命中以实际绘制行数遍历；五档后三项尚未逐一实点，不把可见与全部业务验证混同。

## 实现/使用方法

库内既有实现：`_剧本体检.py:parse_eex/parse_block/parse_command`、`Trace.parse`、`参考R与当前需求.py:parse/render`；编码适配源为`cczEditor2Doc.cpp:OnSaveDocument`，不另造参数解析器。当前工具只写分析目录，不能自行部署正式游戏。

```powershell
python -X utf8 大鲸鱼产生专用\lua引擎\R00重写执行\本批-20261117\重写与编解码.py --v2
```

独立产物为`大鲸鱼产生专用/lua引擎/R00重写执行/本批-20261117/v2/`：两个候选、总验收、逐命令需求映射、初始化审计、菜单路径和`*-v2入边与保留对照.json`。主控独占备份部署、前像和写后回读；只自然新游戏到稳定R85军营，每动作前后状态与画面。菜单等文字/行数稳定后取样，不因初拍部分行改脚本。
