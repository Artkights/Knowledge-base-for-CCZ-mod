> 来源：`[本地盘]\qq\qq群\6.6增加一个显示.txt`、`[本地盘]\qq\qq群\【star6.6x】战前培养.txt`

## 结论速览

- **《战前培养》：已经打进我们的样本了。** 资料给的 **8 段补丁全部逐字节一致**（基线与当前样本都一致），
  长度 2~32 字节，地址 `0x00469F8F / 0x00469FD1 / 0x00469B55 / 0x0046A094 / 0x0045382A / 0x0046C2A8 / 0x004538C8 / 0x00453DB1`。
  ⇒ 该资料是**现状说明 + 维护参考**，不是"待执行方案"。
- **《6.6增加一个显示》：还没有注入，且不能照抄。** 它的两个落点在我们样本里是 **nop 代码洞**：
  `0x00451800`（新函数 `sub_451800`）与 `0x00451990`（9 项字符串指针表）**整块都是 `90`**。
- ★ 但**目标逻辑我们已经有了**：我们样本 `0x0047873E` 处是**同一段逻辑的内联形态** ——
  `call 0x004358C5` → `test eax,eax / jz / mov al,2B` → `mov [0x500E43],al` → `mov eax,edx` → `call 0x0040111A` → 写控件 `1016`。
  资料做的事是：**把这段抽成函数 `sub_451800`，并扩充出"写控件 1022"的部分**，再把 `0x0047873E` 改成 `call 0x00451800`。
- ★ **两份资料的 166 模板不是同一个定制版**：资料里是 `328×306`、标签为「攻击/防御/精神/爆发/士气/移动」「武力/统率力/智力/敏捷/运气」；
  我们的是 `456×350`、标签为「攻击力/防御力/精神力/反应/士气/移动力」「武力/统率力/谋略/敏捷/胆魄」。
  ⇒ **模板（控件 ID、坐标、标签名）必须按我们样本重排，不能直接粘贴**。

### 2. 资料声明的使用前提（现状约束）

- 道具号**必须从 data `161` 起**，按 **武/统/智/敏/运/经验/HP/MP/功勋** 顺序预设排列；
- 果子培养上限、等级上限、升级经验**默认读引擎预设**，适配形象指定器/CM —— 但**大改过这些内容可能不兼容**；
- 经验果在**满级**时吃 → 变更为 **+5 HP、+2 MP 上限**（满级后战场上依旧无法使用）；
- **HP/MP 只能给 data `0-101`** 使用（未处理超过 65535 的情况）；
- 除功勋外，使用其他道具后**强制重算 7 围**。

### 3. 《6.6增加一个显示》的落点与现状

| 落点 | 资料内容 | 我们样本现状 |
|---|---|---|
| `0x0047873E` | 改成 `FF 75 08 / E8 BA90FDFF`（`push [ebp+8]; call 0x00451800`） | 是**内联版同逻辑**（`call 0x4358C5` → `mov [0x500E43],al` → `call 0x40111A` → 写 `1016`） |
| `0x00451800` | 新函数 `sub_451800`（写 `1016` + 写新增控件 `1022`） | **整块 `90`（nop 洞，可直接注入）** |
| `0x00451990` | 9 项字符串指针表 → `0x004519B8~0x004519D0` | **整块 `90`（nop 洞）** |
| `[0x500E43]` | 写 `'+'`(2B) —— 即 `0x500E44` 档位字符表的 **索引 -1 位**（对应控件 `1016`） | 运行时才写；与我在 `sub_4783CE` 独立反汇编出的口径**互相印证** |
| `[0x504EE0]` | 字节索引表：`[ecx] & 0xFFF` → 查表 → 索引 | 未初始化（全 0） |
| 新增控件 `1022` | `CONTROL "Bttttt", 1022, STATIC, SS_LEFT|WS_CHILD|WS_VISIBLE, 170, 34, 23, 8` | 我们 166 的 49 个控件里**没有 1022** |

### 4. 与既有结论的印证关系

- `0x500E43`（1016 的档位位）与 `0x500E44 + i`（2001~2005）是**同一张表**：
  我在 `sub_4783CE`（WM_CTLCOLORSTATIC）里读到的 `cmp eax,0x3F8 → eax=-1 → add eax,0x500E44` 正好落在 `0x500E43` ✓。
- `1016` 的显示文本由 `sub_40111A` 取得，`2001~2005` 由 `sub_4070E1(i,1)` 取得 —— 与[对话框资源库-直读与对照图鉴](../07-数据表与资源/对话框资源库-直读与对照图鉴.md)第 7 节一致。

## 实现·使用方法

**要用《6.6增加一个显示》把 166 加一个显示位，按下面顺序做（不能照抄资料）：**

1. **定坐标**：先在**我们**的 166 模板（`456×350`）里选一个空位放新控件（资料用的 `170,34,23,8` 是按它那版 `328×306` 排的）。
   可先用 `_对话框图鉴.py` 渲染 `166_武将情报.png` 看空位。
2. **加控件**：在 `.rsrc` 的 166 模板里新增一个 `STATIC`（资料用 ID `1022`），并给它一个**我们这边没用过的 ID**（先查 `controls` 表避开冲突）。
3. **注入函数**：把 `0x00451800` 那段洞**按我们样本的偏移重写**（`push 3FE`→改成我们新控件的 ID；表地址按实际填）。
4. **改调用点**：`0x0047873E` 处由内联改为 `call` 新函数（或直接把"写 1022"追加在内联段后面，**更省事且不动洞**）。
5. **填表**：把 `0x504EE0`（索引表）与 `0x451990`（字符串指针表）按需要的语义填好。
6. **写 exe**：必须走 `_dsh写锁.py` 的 `safe_write_exe()`（备份 + 旧字节锁 + 写后复读 + 审计）。

**《战前培养》**：无需再注入；改道具/数值时读它的"前置约束"一节（尤其是"道具号从 161 起、顺序固定"）。

## 风险与边界

- **跨定制版风险**：资料的 166/328 模板与我们的**不同版**（尺寸、标签名、控件 ID 都不同）。
  直接粘贴模板会把界面改坏（模块位置/尺寸不符），**必须按我们样本重排**。
- **地址绑定**：资料里的地址只在其原始 star6.6x 样本上保证成立；在我们样本上**已逐段核对过《战前培养》8 段**，
  但《增加显示》的 `0x451800/0x451990` 是**空位**，需自行编写。
- **`[0x504EE0]`/`[0x451990]` 语义未确认**：资料里给的字符串字节**不完整**（只列到 `0x4519CB`），
  按 GBK 解出的词不连贯（见"待验证项"），**未经实机验证不要当成属性名使用**。
- **写 `Ekd5.exe` 的红线**：本章任何落地都走 `_dsh写锁.py`，且写前确认游戏未运行。
- 资料里那段"**删除这段内容（含此行）后可正常注入**"是**论坛贴的格式约定**（RH 粘贴用），不是代码的一部分 —— 照抄前先删掉那两行标记。
