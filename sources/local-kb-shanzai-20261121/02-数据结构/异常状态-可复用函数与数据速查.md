## 已确认事实

### 1. 状态字段与位值

- 字段：`unit+0x1E`（1字节），由四个2-bit状态窗口组成；全零才是四窗口均无状态。不能把显示接口的0xFF特例套作活体字段的“正常”。
- `0x02/0x04/0x08/0x10`是`0x423FE8`的窗口选择子，分别查麻痹/封锁/混乱/中毒；不是状态字段的直接bit掩码。实际窗口掩码为`0x03/0x0C/0x30/0xC0`。
- 中毒只读判据为`((status >> 6) & 3) != 0`，与选择子0x10分开。窗口阶段1/2/3的生命周期和显示回合语义按已绑定证据使用，本轮E2复核只要求判别是否仍中毒。详见`02-数据结构/异常状态位定义.md`及本页仿真节。

### 3. 函数速查（ABI 均为实测反汇编）

| 地址 | 签名 / ABI | 语义 | 证据 |
|---|---|---|---|
| `0x4101D9` | 调用方 `push 装备号 / push 个人号`（+ 前置模式参数）→ EAX = 特效值 | **核心特技/特效取值引擎**（模式、叠加、渠道由调用方组织） | `0x43D47E` 处 `push 0/0 + push 0xE2/0xE2 → call 0x4101D9` |
| `0x42518F` | 4 个栈参（模式 / 叠加 / 装备号 / 个人号），ECX = 单位，`ret 0x10` | **双渠道包装**（个人 + 宝物/装备），EAX = 特效值；不能区分"没有特技"与"特效值 0" | 本库《破坏MP攻击-特效值化》《方寸天地》两处实现均用它实测通过 |
| `0x425AD9` | `(a, b)` 两个栈参，`ret 8` | **`a * b / 100`**（百分比助手） | 反汇编：`imul eax,[ebp+8] / mov ecx,0x64 / div ecx` |
| `0x423FE8` | `push selector` + ECX=单位，`ret 4`；返回非0=命中 | 选择子02/04/08/10依次查状态位0-1/2-3/4-5/6-7窗口是否非零；选择子01永不命中，不返回窗口阶段值。 |
| `0x478A10` | `push` 状态字节 + 输出缓冲（`ret 8`） | **状态字节 → 状态名字串**（按位循环取 `0x486D06 + i*5` 拼进缓冲；`0xFF` → 「正常」） | 反汇编 `0x478A10`–`0x478B40` |
| `0x4240E2` | 同类循环（在被调用序列中），内部有 `or dl,[ecx+0x4240CE]` | 疑为"状态名拼接/取字符"变体（**未细究**） | 反汇编片段；本轮扫描未找到直接 caller（可能经中间层） |

### 4. 数据表 `0x420630`（策略/类型 → 状态字节）

字节：`00 01 03 02 0C 04 05 06 06 06 06 0A 0A 0A 0A 02 04 00 01 07 08 09 0C 0C 0C`
取值全是 bit 组合（`01/02/03/04/05/06/07/08/09/0A/0C`）→ 与"状态字节是位标志"一致；其中 `0x01` 不在四状态显示循环里，语义待验证。

```
; ① 判某个状态是否命中（例如中毒 0x10）
push 0x10
mov  ecx, <战术单位指针>
call 0x423FE8          ; EAX != 0 → 命中
; ② 数"有几种异常状态"（向死而生的做法）
count = 0
for i in 0..3:
    push (2 << i)      ; 0x02/0x04/0x08/0x10
    mov  ecx, <单位>
    call 0x423FE8
    if (eax != 0) count++
; ③ 取特技特效值（个人 + 装备双渠道同号）
push 0 / push 0 / push <装备号> / push <个人号>
mov  ecx, <单位>
call 0x42518F          ; EAX = 特效值
; ④ 把 count*特效值 变成百分比加成（全能力 += 基础 × count × 特效值 / 100）
push (count * 特效值) / push <基础值>
call 0x425AD9          ; EAX = 百分比结果
; ⑤ 把状态字节转成显示用的名字串 → 可直接喂给内部信息/说明输出
push <状态字节> / push <缓冲>
call 0x478A10
```

## 风险与边界

- **`0x423FE8`的模型已闭合**：选择子每轮右移1位，状态每轮右移2位；02/04/08/10选择四窗口，0x10对应最高两位。旧“若实际单bit、可能错位”的假设已由本页既有真值表及2026-11-07当前字节否定，不再作为待测前提。不要把选择子直接与状态字节相与。
- 不要裸写 `unit+0x1E`：优先调用引擎的状态函数；清除点见上表。
- 本页所有地址均为当前样本（SHA 见开头），跨版本先按补丁纪律复读原字节。
- 与 `unit+0x0D`（行动状态位）和 `0x508B00`（二次行动状态数组）**不是同一套东西**，别混用。

## 附：`0x423FE8` 逐字节仿真结论（2026-10-13）

把该助手在 Python 里逐指令仿真，对 256 个状态字节 × 各选择子跑真值表：

| 选择子 | 实际测试的窗口 | 命中条件 |
|---|---|---|
| `0x02` | 位 0-1 | 该窗口非零（麻痹） |
| `0x04` | 位 2-3 | 同上（封锁） |
| `0x08` | 位 4-5 | 同上（混乱） |
| `0x10` | 位 6-7 | 同上（中毒） |
| `0x01` | — | **永不命中**（先右移再测，第 0 位作废） |

⇒ 状态字节是 **4 组 2-bit 窗口**；代码里的 `0x02/0x04/0x08/0x10` 是**窗口选择子**，真正的字节掩码是 `0x03/0x0C/0x30/0xC0`。窗口内取值 1/2/3 的语义待验证。

## ★ 活体实测（2026-10-13）：窗口值 = 剩余回合数

关羽 `+0x1E`=`0x22`（麻痹2+混乱2）、另一单位 `+0x1E`=`0xC0`（中毒3）⇒ 窗口里存的是**回合数**。
取回合和：`(b&3)+((b>>2)&3)+((b>>4)&3)+((b>>6)&3)`。

### 3. ⚠ 两处口径更正

1. **「状态 `0xFF` 立即返回 0」不成立**（应删/改写旧表述）：完整 23 条里**没有**对 `+0x1E` 的 `0xFF` 特判；
   入口只做 `movzx edx,[ecx+0x1E]`，随后纯按窗口取值。`0xFF` 的"正常"语义只在**显示层** `0x478A10`（本页第 3 节已记）。
2. `[ebp-4]` / `[ebp-8]` 的初值来自 `push 0` + `push edx`（状态字节压在 `[ebp-8]`），故循环体读的 `[ebp-8]` 就是**状态字节的工作副本**；
   `[ebp+8]`（mask）被原地 `shr` 消耗 ⇒ **同一 mask 变量不可复用第二次调用**（调用方每轮重新压栈，这也解释了调用点为何都紧跟一次 `push`）。

## ★ 2026-10-22 静态收口（T7）：`0x43D472` 向死而生实现已完整，唯一直接调用者 `0x43D460`

### 1. 函数体（到 `ret`）
```
push eax / mov ecx,[ebp-4]
push 0 / push 0 / push 0xE2 / push 0xE2
call 0x4101D9              ; 查个人/装备 0xE2 的特效值 ⇒ EAX
test eax,eax / je 0x43D4D3 ; 无 0xE2 ⇒ 直接返回 [ebp-8]
push eax
i = 0 .. 3:
  mask = 2 << i            ; 0x02/0x04/0x08/0x10
  call 0x423FE8(unit, mask) ; 状态测试（读 unit+0x1E，只读）
  命中 ⇒ [ebp-0x14]++       ; 状态个数
结束:
  eax = 状态个数
  edx = [ebp-0xC]          ; 特效值
  imul eax, edx
  call 0x425AD9            ; a*b/100
  add [ebp-8], eax
  return [ebp-8]
```
### 2. 调用链
- 全映像 E8/E9 扫描：**唯一直接调用者 `0x43D460`**（`call 0x43D472`，随后 `jmp 0x4200AE`）。
- `0x43D460` 位于大函数尾部块（同块前有 `call 0x43CB00`、`jmp 0x43BD0B`），入口需按 `0x43BD0B` 区域回溯。
- 状态位：`0x423FE8` 只读 `unit+0x1E`；**本函数不写状态位**，写回由调用者/上层结算处理。

### 3. 结论
- T7 的“实现模板”已升级为**逐条字节级**：0xE2 查询 → 4 状态计数 → `count×特效值` → `×1/100` → 累加。
- 仍模糊：调用者大函数的入口与触发时机（是否只在策略/物理结算收尾）。
