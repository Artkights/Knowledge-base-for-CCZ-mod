#### 状态数组详解

##### 508B00 - 二次行动状态数组

用于跟踪每个单位的二次行动使用状态，每个单位占用1字节：

| 值 | 含义 |
|----|------|
| `00` | 本回合尚未触发，等待激活 |
| `01` | 单位不拥有该特技，不可用 |
| `FF` | 本回合已触发过，已使用（受保护） |

**状态转换流程**：

```
回合开始 → 重置循环将所有 508B00[i] 设为 00
    ↓
行动处理 → 调用点2判定：有特技→写00，无特技→写01
    ↓
行动结束 → 调用点1检查=00 → 判定通过 → 恢复行动 → 写FF
    ↓
再次行动 → 调用点1检查=FF → ≠0 → 跳过（不再触发）
```

##### 500E9D - 目标单位数组

引导攻击系统使用此数组存储候选目标列表：

```
[500E9D]     = 目标1单位编号
[500E9D + 1] = 目标2单位编号
[500E9D + 2] = 目标3单位编号
...
[500E9D + n] = FF  (列表终止符)
```

#### 6.6 扳手三类变量边界

6.6 的 4096 个布尔变量直接存放在 `0x492FC8..0x4931C7` 的 512 字节位图中，位序为 MSB-first：

```text
address = 0x492FC8 + index / 8
mask    = 0x80 >> (index % 8)
```

变量 0/7 分别使用 `0x492FC8` 的 `0x80/0x01`，变量 8 使用 `0x492FC9` 的 `0x80`，变量 32 使用 `0x492FCC` 的 `0x80`。`0x492FC8` 不是数量头，`0x492FCC` 也不是变量 0 的起点。写入时必须读改写单个承载字节，保留另外七个位。

整型变量从 `0x502000` 起，每项 4 字节，按 Int32 解释，合法编号为 `0..4095`。信奈、新改、清儿三份 6.6 样本均存在联合访问序列 `66 81 F9 00 10 73 ... 8D 0C 8D 00 20 50 00`，含义是先执行 `cmp index,0x1000 / jae invalid`，再按 `0x502000 + index*4` 访问。

指针变量从 `0x506000` 起，每项 4 字节，按 UInt32 解释。其合法编号不是 4096 项，而是 `0..480`，共 481 项。多条独立访问路径使用 `cmp index,0x1E0 / ja invalid`；可作为静态定位锚点的联合序列为 `66 81 F9 E0 01 77 ... 8D 0C 8D 00 60 50 00`。编号 `481` 及以上会落入其它全局区域，任何工具都必须在内存访问前拒绝，不能继续沿用“指针变量 4096 项”的旧错误画像。

Python 扳手保留 `variable_count=4096` 仅为旧接口兼容；权威边界分别是 `variable_bool_count=4096`、`variable_int_count=4096`、`variable_ptr_count=481`，并记录在各自变量布局的 `recordCount` 中。

该规则只属于 6.6 扳手画像，不覆盖当前知识库的 6.5 默认写回口径；完整来源和错误结论黑名单见 `../06-项目与工具链/曹操传6.6扳手适配与自动回归验证.md`。

### 2026-10-15 追加：☆ `4018` = **`0x505EC8` 同址二义** —— 既是集气模式开关，也是「我方回合我方必中」开关

**证据**：当前样本 `36694DBE…` 与原始基线 `AA1DB360…` 在 `0x43B4DA` 起 0x58 字节、`0x43B600` 起 0x40 字节
**逐字节相同** ⇒ 下面两块都是**样本自带**，不是本项目后加的补丁。

#### 必中块（`0x43B4E8`~`0x43B51E`，物理/策略合流点之后）

```asm
0043B4FD  B9 B2 0F 00 00           mov  ecx, 0xFB2             ; 0xFB2 = 4018
0043B502  83 3C 8D 00 20 50 00 00  cmp  dword [ecx*4+0x502000], 0   ; → [0x505EC8]
0043B50A  74 17                    je   43B523                ; ≠1 则不做必中
0043B50C  80 3D 18 3D 4B 00 00     cmp  byte [0x4B3D18], 0     ; 我方回合？
0043B513  75 0E                    jne  43B523
0043B515  8B 4D FC                 mov  ecx, [ebp-4]           ; ecx = 攻击者
0043B518  80 79 05 00              cmp  byte [ecx+5], 0        ; 攻击者阵营 = 我军？
0043B51C  75 05                    jne  43B523
0043B51E  B8 64 00 00 00           mov  eax, 0x64              ; ★ 命中率 = 100
0043B523  83 F8 64                 cmp  eax, 0x64
0043B526  73 0C                    jae  43B534                 ; ★ 100 ⇒ 跳过集气闪避判定
```

- **三条判据**：`[0x505EC8]==1` → `[0x4B3D18]==0`（我方回合）→ **攻击者** `unit+0x05==0`（我军）。
- 置 100 后由 `0x43B526 jae` 直接跳过 `0x4287A8`（集气/闪避判定）⇒ 必定命中，且不累积闪避值。
- **`0x505EC8` 的四处既有引用语义不变**：`0x4131F7` 预览显示集气、`0x42882C` 集气写回分叉、
  `0x42893F` 集气判定（`0x428925` **是预览用命中率函数**，调用点 `0x44067B/0x440763/0x44092D/0x440992`）、`0x445D66` = **策略预览 `0x445D3A` 取集气字节2（暴击）**；
  **新增第 5 处引用就是 `0x43B4FD` 的必中**。⇒ 结论不是"推翻集气模式"，而是**同一变量二义**。

#### 引擎区分阵营 / 阶段 / 命中的口径

| 维度 | 载体 | 编码 | 证据 |
|---|---|---|---|
| 阵营（我/友/敌） | `unit+0x05` 单字节 | `0=我军`、`1=友军`、`2=敌军` | `0x43B518`；`0x406710` `movzx eax,[ecx+5]` |
| 阶段（我方/敌方回合） | `0x4B3D18` 单字节 | `0=玩家可控阶段` | `0x4024CC`、`0x43B50C` |
| 命中与否 | **返回命中率 0~100**（非布尔） | `0`=不中、`100`=必中、`1~99`=交 RNG | `0x43B4DA`~`0x43B534` |
| 麻痹导致物理必中 | 目标 `unit+0x1E` 第 0 个 2-bit 窗口 | `push 2` ⇒ `0x423FE8` 非 0 ⇒ 必中 | `0x43B645`~`0x43B64A`（`mov ecx,[ebp+0xC]` = **目标**） |

> 「必中」= 把命中率写成 100，**不是**短路布尔；「免疫物理」是更早的另一条判定
> （`0x43B61B → 0x43BA9D`，读**目标**的特效 `0x31`，`0 = 免疫`），两者互不干扰。
