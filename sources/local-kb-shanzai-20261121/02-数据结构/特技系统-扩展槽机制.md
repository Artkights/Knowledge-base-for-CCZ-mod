# 特技系统 —— 扩展槽机制（普罗源码）

## 结论速览

- 特技表的**真实结构**：`person_effect[1024][256][4]`，即
  **1024 个角色 × 256 个特技槽 × 4 字节 = 1,048,576 字节（正好 1 MB）**。
- **每个角色占 `0x400`（1024）字节**，槽 `i` 在行内偏移 `i × 4`。
- 槽的 4 个字节：**`[特技号, 特效值, 经验值, 剩余回合]`**
  - 特技号 `0xFF` = **空槽**
  - 剩余回合 `0xFF` = **永久**；否则每回合 -1，减到 0 就删除（**临时特技**）
- 表地址由 DLL 注册到 **`[0x4F0004]`**；访问用**角色号**索引（不是战场 slot）。
- 战场 slot → 角色号：**`*(WORD*)(0x4A7B20 + slot*0x30)`**（`0xFFFF` = 空位）。

### 2. 读 / 写 / 增 / 删（`dllmain.cpp`）

- **查**：遍历槽，`person_effect[per_id][i][0] == effect_id` 时取
  `[1]`(值) `[2]`(经验) `[3]`(回合)；遇 `0xFF` 停。
- **增**（`AddPersonEffect`）：先找 `0xFF` 空槽，写入
  `[0]=effect_id, [1]=effect_value, [2]=0, [3]=effect_round`。
- **改**：命中同号则更新 `[1]`；若值为 0 则**置空**（`[1]=0, [0]=0xFF`）。
- **删**（`DeleteEffectPos`）：把后面的槽**前移一格**（数组压缩），直到遇 `0xFF`。

## 实现·使用方法

### 给某个战场单位加特技（正确公式）

```python
# 1) 战场 slot -> 角色号
data_id = read_u16(0x4A7B20 + slot * 0x30)      # 0xFFFF = 空位
# 2) 取表基址
base = read_u32(0x4F0004)
# 3) 写槽 i（0..255 里挑空槽）
write(base + data_id * 0x400 + i * 4,
      bytes([skill_id, value, 0x00, 0xFF]))     # 0xFF = 永久
```

## 风险与边界

- `0xFF` 同时用作「空槽标记」与「永久回合」，靠**字段位置**区分：
  `[0]==0xFF` 是空槽，`[3]==0xFF` 是永久。
- **槽数组是压缩的**：删除会前移，所以**外部缓存槽号会失效**，每次都要重读。
- 改内存后**读档可能被覆盖**（DLL 自己有存读档：写 `person_effect` 到文件）。

### 1. ★ ExtendModifier 的定位：**外置编辑器**（游戏目录下 `ExtendModifier.exe`）

### 2. ★ 双模式（`ExtendModifierTEJI.cpp` 源码原文）

```c
void CExtendModifierTEJI::loadData(int per) {
    if (mode == false) {                                   // —— 初值模式 ——
        ifstream file("Effect.e5", ios::binary);
        file.seekg(per * 256 * 4, ios::beg);               // 角色号 × 1024
        file.read(reinterpret_cast<char*>(&person_effect), 256 * 4);
    } else {                                               // —— 内存模式 ——
        char* addr;
        ReadProcessMemory(hpro, (LPVOID)(0x4F0004), &addr, 4, 0);       // ★ 取表基址
        ReadProcessMemory(hpro, (LPVOID)(addr + per * 256 * 4), &person_effect, 256 * 4, 0);
    }
}
// SaveData 与之对称：初值模式写回 Effect.e5；内存模式 WriteProcessMemory 到 addr + per*1024
```

- **`per * 256 * 4` = 角色号 × `0x400`（1024）** ⇒ 与本工作区 `_加特技v2.py` 用的公式**逐字相同** ✓
- **`ExtendModifierDlg.cpp::ON_MODE()`**（**菜单第 6 项 `ID_32773`**，菜单文字 `模式:初始` / `模式:内存`）：
  切到内存模式时用 `EnumWindows` **按窗口类名前 6 字符 == `"SOUSOU"`** 找到游戏窗口 → `OpenProcess(...VM_READ|VM_WRITE|VM_OPERATION|CREATE_THREAD|QUERY_INFORMATION)`
  ⇒ **与我们在 `_42结束回合.py:find_game()` 修出的"必须按 class `SOUSOU` 找窗口"互相印证** ✓

### 4. "某角色有没有某特技"的正确判定口径

1. **要判"现在（本局）有没有"⇒ 读内存**：`addr = [0x4F0004]`，行 = `addr + 角色号×0x400`，遍历 256 个 4B 条目找 `[0] == 特技号`。
2. **要判"存档/初值有没有"⇒ 读 `Effect.e5`**（同布局，按文件偏移）。
3. 字段：`[0]` 特技号（**`0xFF` = 空槽**）、`[1]` 特效值、`[2]` 经验、`[3]` 剩余回合（**`0xFF` = 永久**；否则每回合 −1，到 0 删除）。
4. **战场 slot → 角色号** = `*(WORD*)(0x4A7B20 + slot*0x30)`（`0xFFFF` = 空位）。
5. ⚠ **源码级陷阱（极易踩）**：`ExtendData` 的"查"是**遍历到 `0xFF` 就停**（数组必须**紧凑**；`DeleteEffectPos` 删除时会把后面的条目**前移压缩**）
   ⇒ **写入必须落在"第一个空槽"**，一旦在中间制造空洞，**后面的特技会被引擎漏读**。
   （本会话我们用 `_加特技v2.py` 写入时，它落的正是第一个空槽：`原值 FF 03 00 FF → 新值 49 14 00 FF`，**未制造空洞** ✓）

### 5. ★ 实测：**初值 ≠ 运行时**（判定时必须说清口径）

| 特技 | `Effect.e5`（初值） | 运行时内存表 |
|---|---|---|
| `0x24` 防御暴击 | **角色 47 槽0** 值=1 永久 | **角色 47 条目4**（前面还有 `30 01 / 29 41 / 60 ff / 10 64`） |
| `0x49`/`0x4A`/`0x4B`/`0x4C`/`0x4D` | **0 处** | **0 处** |

- ⇒ 同一特技在**两处的槽位不同**（运行时表里条目更多，疑由读档/脚本在运行时追加）⇒ **不能拿文件偏移当运行时槽位**。
- ⇒ **两条通道独立一致地表明**：当前数据里 **没有任何角色拥有 `0x49`–`0x4D`**；它们只被 **9 行物品**引用
  （`Star.e5`：`ID5 守护之魂`、`ID11 狼牙箭矢`、`ID41 太平清领道`、`ID48 无敌战船`；`ID128..132` 连续五行 = 五维拆分）
  ⇒ **结论：这五个特技当前只可能由物品/装备授予**（与"16B 特技行的人物/兵种槽全空"自洽）。
