# 战场 0 号槽 = 玩家主控位（`DataID=0` 不是空槽）

> 建立日期 2026-10-15｜用户口径确认：「是0号位」｜证据：实机只读采样 + 用户现场确认

## 结论速览

1. **`slot 0` 是玩家手动操作的主控位** ⇒ 托管（写 `unit+0x0E=1`）**对它的写入不保留**，引擎把它维持为
   **`+0x0E = 7`（可控）**；其余我方/友军槽才变 `1`。**这是设计，不是 bug，不要去"修"它。**
   > ⚠️ **本页的增量只有这一条**（"引擎会把 slot0 维持回 7"）。
   > `+0x0E` 的**取值表**与**托管写法早就落盘**，不要在别处重复推导、更不要拿去问用户：
   > * `大鲸鱼产生专用\_42托管我军.py` 的 **docstring 就是 `0x0E` 取值全表**
   >   （`0` 攻击武将/到指定点、`1` 主动出击、`2` 坚守原地、`3` 被动出击、
   >   `4` 跟随武将/逃到指定点、**`7` = 可控（我军默认）**）
   > * `03-机制详解\策略目标判定与AI方针.md`、`06-项目与工具链\曹操传6.6扳手适配与自动回归验证.md`
2. **`DataID = 0` ≠ 空槽**。空槽判据是 **`0xFFFF`**；`0` 是 `Data.e5` 里的**占位/空角色**记录，
   所以"看不到 0 号角色"是正常的 —— 它对应的是**玩家自己操作的那个单位**。
3. **托管实现（板手 `mywindow.py:4176-4189`）本来就会给 slot0 写 `1`**，
   但**引擎随后改回 `7`** ⇒ 外部观察到的就是"只有 slot0 没被托管"。
4. **自动化里不要跳过 `DataID == 0`**：那是玩家的主控单位，跳过它等于让主将不还手。
   要跳过的是 `DataID == 0xFFFF`（真空槽）。
5. 汇报托管结果时，**必须显式打印"slot0 保留为玩家可控（`+0x0E=7`）"**，
   否则使用者会以为托管漏了 0 号角色（2026-10-15 用户实际提出过这个疑问）。

## 适用版本

* 复刻版 6.6山贼，样本 SHA `813F4D7190EC52CE2A153519491E17158778633176AA3B42CC35722CCDA5C902`（1148928 字节）。
* 单位表基址 `0x4A7B20`、步长 `0x30`（标准 6.6 口径；`0x4B2C50 / 0x24` 是旧 6.x，**不要用**）。

实机只读采样（2026-10-15，`4018=1`，战场宽 20，存活 59）：

```

  0       0          7          6550        0x00          2      ← 玩家主控，+0E 恒为 7
  1      30          1           862        0x08          2
  2       2          1           760        0x00          2
  3      22          1           594        0x08          2
  4       1          1          7063        0x00          2
```

* 对 35 个槽执行"板手托管"（非 `0xFFFF` 槽写 `unit+0x0E=1`）后，**slot0 的 `+0x0E` 读数仍为 `7`**。
* 库内既有口径佐证：`00-总览与规范\更新记录.md:1205` ——
  `*(WORD*)(0x4A7B20 + slot*0x30)` = **角色号 data_id**（**`0xFFFF` 空位**）。
* 字段全表佐证：`更新记录.md:1632` —— `+0x05` 阵营、`+0x06/+0x07` X/Y、`+0x08` AI 目标槽、
  `+0x0C` 显示状态（**3 = 死亡**）、`+0x0D` 已行动掩码、`+0x0E` **AI 方针（7 = 可控）**。

## 实现·使用方法

判空槽（**唯一正确写法**）：

```python
did = read_u16(unit + 0x00)
if did == 0xFFFF:
    continue            # 真空槽才跳过；did == 0 是玩家主控，必须处理
```

托管我军（板手口径，**包含 slot0**，让引擎自己决定是否维持可控）：

```python
for i in range(cnt_wo + cnt_you):          # 我方 15 + 友军 20（旧版全局默认；标准 6.6 为 20/40）
    if read_u16(addr_war + i*0x30) == 0xFFFF:
        continue
    write_u8(addr_wo + i*0x30 + 0x0E, 1)   # 引擎会把 slot0 维持为 7
```

判断"某单位是否已死"（板手 `LockThread` 口径，`mywindow.py:7243-7246`）：

```python
hp==0 and read_u16(unit) != 0xFFFF and read_u8(unit+0x0C) == 3   # 死亡
```

汇报模板（避免使用者误判托管漏项）：

```
托管：写入 N 槽（unit+0x0E=1）
  注意 slot0（DataID=0）= 玩家主控位，引擎维持 +0x0E=7，**不属于托管范围**
```

## 风险与边界

* **不要把 `DataID == 0` 当空槽跳过** —— 会让玩家主控单位在本回合不出手（表现为"主将站着不动"）。
* **不要试图强行把 slot0 写成 `1` 并期待它保留** —— 引擎会改回 `7`；反复写只会浪费写入次数。
* `DataID` 的低 WORD 才是角色号；**`unit+04` 不是 Data 号**（用户 2026-06-09 纠错，见 `待验证清单.md:589`）。
* 本结论建立在"标准 6.6 单位表"上；旧 6.x 基底（`0x4B2C50 / 0x24`）不适用。
