# 单位结构体

## 结论速览

- 当前 6.5 同时存在战术单位记录、人物运行时记录和策略记录，三者不能混用。
- 战术单位数组为 `004A7B20`，每槽 `30H` 字节，战场编号只用于计算槽位地址。
- `unit+00` 的低 WORD 是 Data 号，`FFFF` 表示空槽；`unit+04` 是 BYTE 战场形象号，`unit+04..+07` 是形象/阵营/X/Y 的原始打包 DWORD，不是 Data 号或独立 DWORD 显示编号。
- 人物运行时记录基址来自指针槽 `[004CEA00]`，每人 `48H` 字节；`004061E4` 按 Data 号取人物记录。
- `004A3E77 + id * 61H` 是策略记录表，`00484002` 是策略号转策略记录指针。旧知识库曾把它误写为人物 Data 数组，本页已纠正。
- 当前 HP 是 `unit+10` 的 DWORD，已由 6.5 x32dbg 写断点闭环；当前 MP 是 `unit+14` 的 DWORD，已有多源支持但 setter 仍待动态闭环。
- `unit+0x0C`（显示状态 view）的**唯一设置器 = `0x443120`**，全 exe 仅 3 个调用者（`3`/`2`/`1`）⇒ **`view==3` 唯一静态来源 = 阵亡函数 `0x441744`**；攻击后的判死发生在攻击分发 `0x43DB23` **返回之后**（`0x4065D9`→`0x42BC14`→`0x40502B`）。详见页尾「2026-10-21 第 29 轮」。

## 适用版本

- 默认适用：当前规范 6.5 未加密 `Ekd5.exe`，SHA256 `F9A357585F4D77C273A8BADD3E4EF4062983CC81D8040C0CB74768FAB7C04F5F`。
- 6.4 文档和旧扳手源码只用于字段对照；升级为 6.5 写入规则的项目必须有当前 EXE 静态证据或动态证据。
- 论坛旧版的 `004B2C50 + id * 24H` 只说明结构演化，不能替代当前 `004A7B20 + id * 30H`。

## 实现/使用方法

### 两种单位编号

#### Data 号

- 角色在项目数据中的持久编号。
- 当前函数以 16 位无符号值接收，不能只读一个字节。
- 战术单位记录的 `unit+00..+01` 保存该值；`FFFF` 表示该战术槽无单位。
- 需要人物固有属性时，通过 `004061E4` 或 `0040658F` 取得人物运行时记录。

#### 战场编号

- 当前战斗内的临时槽位编号，范围 `0..249`。
- 不要求再从战术单位内部读取，已知编号即可调用 `004061F9`。
- 反击、多目标策略和 AI 阶段会改变“当前攻击者/目标”，应以当下上下文字段为准。

关系如下：

```text
战场编号
  -> 004061F9
  -> TacticalUnit* = 004A7B20 + id * 30H
  -> WORD [unit+00] = Data号
  -> 004061E4
  -> RuntimeCharacter* = [004CEA00] + data_id * 48H
```

策略号走另一条链：

```text
策略号
  -> 00484002
  -> StrategyRecord* = 004A3E77 + strategy_id * 61H
```

### 战术单位数组

```asm
004061F9  push  ebp
004061FC  movzx ecx, cl
004061FF  imul  ecx, ecx, 30
00406202  add   ecx, 004A7B20
00406209  ret
```

计算式：

```text
unit_ptr = 004A7B20 + battlefield_id * 30H
```

### 战术单位字段

| 偏移 | 大小 | 推荐语义 | 证据等级/边界 |
|------|------|----------|---------------|
| `+00` | 2 字节 | Data 号；`FFFF` 空槽 | 当前 EXE + 旧工具源码 |
| `+02` | 2 字节 | Data 号载体高位或扩展字段 | 多处按 DWORD 搬运，高位语义待证 |
| `+04` | 1 字节 / 4 字节打包视图 | 战场形象号 / `packed_display_state` | `+05/+06/+07` 分别为阵营/X/Y；DWORD 只保留原始打包值 |
| `+05` | 1 字节 | 阵营：`00` 我、`01` 友、`>=02` 敌 | 多源一致 |
| `+06/+07` | 各 1 字节 | 当前 X/Y | 读取已用；写入函数待“只移动”动态闭环 |
| `+08` | 1 字节 | AI 攻击/跟随目标战场编号 | 外部佐证 |
| `+09/+0A` | 各 1 字节 | AI 移动目标 X/Y | 外部佐证 |
| `+0B` | 1 字节 | AI 行动顺序 | 外部佐证 |
| `+0C` | 1 字节 | 显示/隐藏/退场状态 | 外部佐证 |
| `+0D` | 1 字节 | 行动状态位，`08` 与 S 形象翻转相关 | 当前逻辑 + 旧工具源码；bit 语义未全闭环 |
| `+0E` | 1 字节 | AI/控制策略；`07` 为可控 | 外部佐证 + 旧工具源码 |
| `+0F` | 1 字节 | 朝向 `0/1/2/3 = 上/右/下/左` | 多源一致 |
| `+10` | 4 字节 | 当前 HP | 当前 6.5 动态闭环 |
| `+14` | 4 字节 | 当前 MP | 多源一致；setter 待动态 |
| `+18..+1D` | 6 字节 | 攻、防、精、爆、士、移动临时档位 | 旧工具 + 补丁样本 |
| `+1E` | 1 字节 | 异常状态 | 旧工具 + 补丁样本 |
| `+1F` | 1 字节 | 撤退台词状态 | 6.4 外部佐证；待动态 |
| `+20/+21` | 2 字节 | 限制区域或第二目标坐标 | 来源冲突，不可写 |
| `+22` | 1 字节 | 未知扩展字段 | 待证 |
| `+23` | 1 字节 | 回合扩展/戮力同心计数候选 | 当前回合路径会清零，业务语义待证 |
| `+24..+2F` | 12 字节 | 扩展区 | 未建立字段级规则 |

读取这两个字段的现成函数（2026-10-13 复读确认，补丁里可直接调用）：

| 函数 | 反汇编 | 语义 |
|---|---|---|
| `00472840` | `55 8B EC / 0F B7 41 14 / 5D C3` | `movzx eax, word ptr [ecx+0x14]` → **当前 MP**（WORD 读取，不做符号扩展/裁剪） |
| `0041B500` | `55 8B EC / 8B 41 10 / 5D C3` | `mov eax, dword ptr [ecx+0x10]` → **当前 HP**（DWORD） |

> 库内多处旧注把 `00472840` 写成「MP 基值 / MP 上限」，实际它就是 `+0x14` 的当前 MP。做「按值扣减」类特效时，此函数正好可以当**上限钳制**用（例：`伤害 = min(特效值, 00472840(目标))`，见 `../03-机制详解/破坏MP攻击-特效值化.md`）；不钳制会出现 MP 变负后被后续逻辑拉回上限的现象（实机表现为“回满蓝”）。

`+0D` 的当前保守用法：
```asm
; 00406690，按掩码清行动位
movzx eax, byte ptr [ebp+08]
not   eax
and   byte ptr [ecx+0D], al
ret   04
```

- 参数是位掩码，不是位号。
- 旧工具以 `unit+0D |= 06` 标“已行动”，以 `unit+0D &= F8` 清行动相关位。
- `01/02/04/06` 在移动、攻击、待命和二次行动中的准确语义仍需分动作验证。

`+1E` 是**单 bit 状态标志**：麻痹 `0x02` / 封锁(禁咒) `0x04` / 混乱 `0x08` / 中毒 `0x10`，`0xFF` = 正常（实证见 `02-数据结构/异常状态位定义.md`，来源 `0x478A10` 显示循环）。
⚠️ 纠正：早前「四组 2-bit 状态（`C0/30/0C/03`）」的说法把**全局设定的持续回合字段**误当成了状态位；那组掩码仍属全局设定，不可与本字段互换。
新增实现仍应优先调用游戏状态函数，而不是裸写该字节。

### 注入时的取值规则

1. 已有战场编号：调用 `004061F9` 取战术单位指针。
2. 已有战术单位指针：从 `unit+00` 取 16 位 Data 号；不要从 `unit+04` 取 Data 号。
3. 需要人物记录：调用 `0040658F`，或把 Data 号传给 `004061E4`。
4. 需要策略记录：从 `00497AF8+00` 等上下文取得策略号，再调用 `00484002`。
5. 需要当前 HP/MP：读战术单位 `+10/+14`；需要 HP/MP 上限：读人物运行时记录对应字段或调用已验证 getter。

## 风险与边界

- 主程序、Runtime 和 GameDebug 已统一引用 `EngineRuntimeSemanticRegistry`；`UnitDataIdOffset=0x00`，`00484002` 返回 `StrategyRecord*`。历史兼容别名只用于一个发布周期，不授予写入权限。
- `unit+00` 多处以 DWORD 搬运，但当前 Data 号转换函数只读取低 WORD。不要自行解释高 2 字节。
- `unit+04` 是一字节战场形象号；例如 `34 02 0A 0B` 解码为形象 `34H`、阵营 `02H`、坐标 `0AH/0BH`，打包原值为 `0B0A0234H`。不得把它解释为槽位编号。
- 战术单位字段是运行时状态。直接改 HP、MP、坐标、退场或状态可能绕过刷新、上限、事件和剧情逻辑。
- 跨版本必须重新确认数组基址、步长、动态人物基址指针槽和 getter 指令签名。

## ★★ 2026-10-14 补：两个取址函数与**调用约定差异**（易踩坑）

引擎里"拿记录指针"只有这两个入口，**约定不同**，写补丁/注入时混用必错：

```asm
; ① 人物 DATA 记录（每人 0x48 = 72 字节）

004061E5  8B EC           mov  ebp,esp
004061E7  0F B7 4D 08     movzx ecx,word ptr [ebp+8]   ; 参数：人物 Data 编号（WORD，走栈）
004061EB  6B C9 48        imul ecx,ecx,0x48
004061EE  03 0D 00 EA 4C 00   add ecx,dword ptr [0x4cea00]  ; + 基址指针
004061F4  5D              pop  ebp
004061F5  C2 04 00        ret  4                        ; ★ 栈传参 + 清栈

; ② 战场单位记录（每槽 0x30 = 48 字节）
004061F9  55              push ebp
004061FA  8B EC           mov  ebp,esp
004061FC  0F B6 C9        movzx ecx,cl                 ; ★ 参数：战场编号走 CL（寄存器！）
004061FF  6B C9 30        imul ecx,ecx,0x30
00406202  81 C1 20 7B 4A 00   add ecx,0x4a7b20
```

## 2026-10-15 第 8 轮：**字段索引→偏移总表**（补全）+ 钳制函数 `0x47FA89` 语义定案

> 样本 `Ekd5.exe` SHA256 `25DB2211FE8F495DE4993BAB296C23C180E18679F00A0E43B47B1FD2034B7EAF`；**证据层级 = 1 静态**；
> 工具 `_dsh反汇编工作台.py`（`func`，本轮又修了它的"重排序言"漏判）。

### 1. 访问器契约（`0x406ECA`，`ret 0xC`）

- **`ECX` = 记录指针**；栈参：`[ebp+8] = 字段索引`、`[ebp+0xC] = 参数`、`[ebp+0x10] = 模式`。
- 写值 = **`0x47FA89(旧值, 参数, 上限)`**；**模式 `== 1` ⇒ 旧值按 `0` 处理（覆盖写）**，否则**累加**。
- 进入索引 `7/8` 分支时置全局标志 **`[0x505F30] = 1`**；公共出口 `0x406FB8` 复位为 `0`（疑"记录脏/重算中"标记）。

### 2. ★ `0x47FA89(a, b, cap)` = **`min(a + b, cap)`**（有符号比较）

```asm
0047FA89  55                  push ebp
0047FA8A  8B 4C 24 0C         mov  ecx, dword ptr [esp + 0xC]   ; 第 3 参（＝b？见下）
0047FA8E  8B EC               mov  ebp, esp
0047FA90  03 4D 08            add  ecx, dword ptr [ebp + 8]     ; a + b
0047FA93  8B 45 10            mov  eax, dword ptr [ebp + 0x10]  ; cap
0047FA96  3B C8               cmp  ecx, eax
0047FA98  7F 02               jg   0x47FA9C                   ; ★ 有符号
0047FA9A  8B C1               mov  eax, ecx
0047FA9C  5D / C3             pop ebp / ret                     ; 调用方 add esp,0xC 清栈
```
⇒ 语义 = **"加值并封顶"**（不是"取较小值"，而是先加后封顶）。
结合访问器：**五项 word（索引 0..4）与 dword/wd（5/6）上限 `9999`；五围字节（索引 0x0A..0x0E）上限 `100`。**

### 3. 字段索引 → 记录偏移总表（实测）

| 索引 | 目标 | 宽度 | 上限 | 备注 |
|---|---|---|---|---|
| `0..4` | `记录 + 0x11 + 索引*2` | **word ×5** | `9999` | 外部页「`+0x11` 是**索引 0** 的 word 原始攻击属性」的落点 |
| `5` | `记录 + 0x1B` | dword | `9999` | |
| `6` | `记录 + 0x1F` | word | `9999` | |
| `7` / `8` | —（走 `0x406F96`） | — | — | 置 `[0x505F30]=1` → `0x40BE7D` **反查记录编号** → 另一套调用（索引作为参数传入） |
| `9` | `记录 + 0x2C` | byte | — | 访问器走公共出口；`getter 0x422E9D` 直读该字节 |
| **`0x0A..0x0E`** | **`记录 + 0x17 + 索引` = `+0x21..+0x25`** | **byte ×5** | **`100`** | **五围**（与既有页"五围在 `+0x21`"吻合；索引 0x0A ⇒ 第一维） |

- `getter 0x422E9D` 的映射与之**一致**（`0..4` word、`5` dword `+0x1B`、`6` word `+0x1F`、`9` byte `+0x2C`，`0x0A..0x0E` 同走 `+0x17+索引`）。
- ⇒ **对"改引擎/加特技时安全读写人物记录"直接可用**：改任何字段都应尽量走 `0x406ECA`（自带封顶与模式），
  而不是自己 `mov`——后者会绕过 `9999`/`100` 上限与 `[0x505F30]` 的**模式开关**（第 14 轮更正：原写"脏标记"）。

### 4. 本轮顺带暴露并修掉的**第三条工具局限**（详见工具链页）

⇒ 与本库第 7 轮登记的链起点 `0x43F5FF`（末尾也是 `cmp eax,0x270F / mov eax,0x270F`）**语义一致**：

### 2. `0x42211E`（191 字节）—— **半字节编码拆解器**

## 2026-10-27｜当前 6.6 战场单位 `+0x24`：0x40 死亡结算→回合消费链（静态）

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B。本节只读复核当前镜像；未启动游戏、未附加 x32dbg，未写 EXE、RS 或 SV。

### 字段与入口

- 对战场单位记录 `U=0x4A7B20+slot*0x30`，`U+0x24` 是一个字节运行态槽。低 7 位承载“0x40 已触发次数”（当前静态口径为 0..127），bit7 是待处理标记；它与人物记录/外部 `R` 的同偏移字段分开，人物记录 `R+0x24` 的“敏”不能套到这里。
- `0x45D3BE` 是当前样本的 0x40 查询桩：固定压入 `0/0/0x54/0x40`，调用 `0x4101D9` 后返回配置值。直接消费点为死亡结算 `0x4290CD`，其上游由 `0x4037F0` 物理判死或 `0x420F7C` 策略判死进入。
- `0x4290CD` 返回后，`0x4290DE` 将配置返回值与 `BYTE[U+0x24]` 比较；当当前计数小于配置值时执行 `OR BYTE[U+0x24],0x80`，随后经 `0x40658F→0x426BA0` 增加杀敌计数。这里的写入对象已由入口 ECX/判死上下文闭合为战场单位 U。

### 回合消费与行动影响

- `0x41B508` 是待处理位的回合消费端：先用 `0x4061F9` 按输入槽取 U，再测试 `BYTE[U+0x24]` 的 bit7；命中后清除待处理位（保留低 7 位）。
- 清位后调用 `0x418C90(U)` 读取 `BYTE[U+0x0C]` 的 view。只有 view==2 时才递增同一 `U+0x24` 计数，并调用 `0x412D9D/0x43E6AA`（参数 `0x88,6`）；函数返回值为 1 时由调用者跳过该单位本回合行动。
- 因此当前静态链可写成：

```text
slot
  -> 0x4061F9
  -> U = 0x4A7B20 + slot*0x30
  -> 0x45D3BE(0x40) 查询配置
  -> 0x4290CD/0x4290DE 死亡结算
  -> U+0x24 |= 0x80（待处理）
  -> 0x41B508 清 bit7
  -> view=U+0x0C
  -> view==2 时 U+0x24++、0x88/6 效果、跳过行动
```

### 与 slot/DataID/R 的边界

- `0x4061F9` 只负责 `slot→U` 解析；上述 0x40 三个节点没有直接读取 `U[0]`/DataID，也没有直接调用 `0x40BE7D` 生成 R。需要把一次现场归并到角色编号时，仍须由同一 slot 同时复读 `U`、`U[0]`（DataID）和对应 `R`，不能从 `U+0x24` 单独反推人物号。
- `U+0x24` 也不是 HP、MP、`ctx+0x84` 或策略资源槽；当前样本在这条链上只看到计数/待处理位、杀敌计数和行动跳过副作用。若要讨论伤害结果，必须另接 HP/MP setter 链。

### 当前可下的静态结论与动态交接

- 已闭合：0x40 查询配置、死亡结算置 bit7、回合消费清位/条件自增/行动跳过，以及与杀敌计数的先后调用关系。
- 未闭合：运行时一次死亡是否在同一回合立即消费、view==2 的实际角色集合、配置值与低 7 位计数的现场变化，以及该事件是否同时更新 DataID/R 相关投影。
- 交给另一会话在 `4018=1` 下验证：同一 `slot/U/U[0]/R` 记录动作前后 `U+0x0C/U+0x24`、`0x45D3BE` 返回值、`0x4290DE` 置位与 `0x41B508` 清位/递增的时间顺序；同时复读 `phase/enemy_alive/ours_ready`。判据是 bit7 只在死亡结算门满足时置位，消费后清零，view==2 才出现低 7 位加一和跳过行动。
