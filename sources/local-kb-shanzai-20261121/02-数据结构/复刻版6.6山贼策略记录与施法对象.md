# 复刻版6.6山贼策略记录与施法对象

## 结论速览

- **策略号 = Data.e5 策略表的物理序号**，与编辑器（形象指定器）左侧列表的十六进制标签同值：`Data.e5` 表首 `0xB204 + 策略号×0x61`，共 144 条、步长 97 字节；运行时同表在 `0x4A3E77 + 策略号×0x61`，取址函数 `0x484002`。
- **加载器把每条记录的 6 个字段换位**：施法对象→`+0B`、施法范围→`+0C`、效果范围→`+0D`、消耗MP→`+0E`、策略类型→`+0F`、图标→`+10`；名称 `+00..+0A` 与 80 个学会等级 `+11..+60` 位置不变。**改数据用 Data.e5 偏移，读/钩运行时用换位后的偏移，两者不可照抄。**
- **对我军/敌军由 `施法对象`（Data.e5 `+0C`）决定**：`0`=敌方、`1`=我方（含空地）、`2`=战场/天气。运行时取值点 `0x425AC7`（读 `+0B`），判定函数 `0x4390EF`，可用挂钩点 `0x43915D`。
- **施放结果写在策略上下文 `0x497AF8`**：`+00` 策略号、`+01` 施法者战场编号、`+0C` 选中目标、`+0D+i` 目标表（`FF` 结束）、`+108+4i` 每目标伤害。**施放结束后不清空**，残值会误导拦截补丁。
- **空地目标用 `0xFE` 标记**：`0x4554B3` 写 `[0x4B4250+0x61]`，放行判定在 `0x406E2B` → `0x435CE9`，落格结果进物块（地形改块）表 `0x4B3D21`。
- exe 侧另有 **10 张每策略 1 字节属性表**，文件偏移 `0xA2CE0` 起、各 144 字节、`+策略号` 定位；其中 `0xA2D70+策略号` = 效果索引，经跳板表 `0x4259C3` 分派到具体处理函数。

## 适用版本

- 仅适用当前项目样本 `复刻版6.6山贼/Ekd5.exe`：SHA256 `A168DC99F260D39CF2575090CA7210DFB5185FFB1667313E4432DE88FA7B44C5`，1,148,928 字节。
- `Data.e5`：SHA256 `CDE1BB1CD7DD0BA8ECED6137AE3790EAEA8C27ED946A3417E467C1CB363C7FD0`，61,379 字节。
- 知识库既有记录里的“6.6山贼权威样本” `6929FE0D…`（1,146,880 字节）**不是当前文件**，跨 SHA 不得直接套用本页地址。
- 不适用曹操传加强版 6.5、6.6x、6.4 与其它 MOD；6.5 的策略字段口径见 `../02-数据结构/6.4-6.5运行时静态数据表地址.md`。

## 已确认事实

### 1. 表位置、步长与镜像关系

| 对象 | 地址/公式 | 证据 |
|---|---|---|
| 运行时策略记录 | `0x4A3E77 + 策略号×0x61` | 取址函数 `0x484002` 原字节 `55 8B EC 6B C9 61 81 C1 77 3E 4A 00 5D C3`（`imul ecx,ecx,61h` + `add ecx,4A3E77h`） |
| 磁盘源数据 | `Data.e5 0xB204 + 策略号×0x61` | 144 条名称逐条 GBK 枚举；表尾 `0xE894` |
| Data.e5 装载镜像基址 | `0x498C73` | 三张表交叉：兵种详细 `0x4A2A27`↔`0x9DB4`、兵种地形 `0x4A3517`↔`0xA8A4`、策略 `0x4A3E77`↔`0xB204`，差值恒为 `0x498C73` |
| 表链首尾相接 | `0x9DB4 + 80×35 = 0xA8A4`；`0xA8A4 + 40×60 = 0xB204` | 与运行时 `0x4A2A27 / 0x4A3517 / 0x4A3E77` 同步成立 |

- 兵种详细、兵种地形两张表在运行时与 `Data.e5` **逐字节一致**（实机复读）；只有策略记录被加载器做了字段换位。
- 当前 exe 中 `0x4A3E77` 所在区域在文件里没有初始数据（属 `.text2` 未初始化段），**直接改 exe 对应文件偏移无效，必须改 `Data.e5`**。

### 2. Data.e5 策略记录字段（编辑器同口径）

| 偏移 | 语义 | 小火(0x00) 实测 | 觉醒(0x3F) 实测 |
|---|---|---|---|
| `+00..+0A` | 名称（11 字节，GBK，补 0） | `小火` | `觉醒` |
| `+0B` | 策略类型 | `00` 攻击(火) | `15` |
| `+0C` | **施法对象** `0`敌/`1`我方(含空地)/`2`战场 | `00` 敌方 | `01` 我方 |
| `+0D` | 施法范围（Hitarea 索引） | `0D` | `0D` |
| `+0E` | 效果范围（Effarea 索引） | `00` | `00` |
| `+0F` | 消耗 MP | `06` | `08` |
| `+10` | 图标 | `00` | `09` |
| `+11..+60` | 80 个兵种学会等级 | 群英/诸侯/人杰=5，小刀手=0 | — |

- `施法对象` 分布：`0`=75 条（对敌）、`1`=66 条（我方/空地/任意格）、`2`=3 条（豪雨/晴明/昙天，天气类）。
- 名称样例：`0x00 小火`、`0x12 小石头`、`0x34 无情铁手`、`0x36 八阵图`、`0x37 补给`、`0x3F 觉醒`、`0x59 回归`、`0x5E 纵火`、`0x88 豪雨`、`0x8F 白虎慰灵`。

### 5. 施放三态判定链

| 环节 | 函数/地址 | 关键逻辑 |
|---|---|---|
| **对敌/对友（共用+AI）** | `0x4390EF`，挂钩点 `0x43915D`（原 5 字节 `33 C0 40 EB 02`） | `0x484002`→`0x425AC7` 取运行时 `+0B`：`0`→必须势力不同、`1`→必须势力相同、`≥2`→不限；势力值来自 `0x406710`（单位 `+5` 经表 `0x40672D` 映射：我/友=1、敌=0、第四方=2） |
| **类型附加条件** | `0x42044D`，取类型用 `0x420A9B`→`0x44270C`（运行时 `+0F`） | 状态位表 `0x420630`；类型 `0x0F..0x12` 走 `0x423FE8` 状态检查；类型 `0x16`（回归类）检查施法者≠目标并提示 `0x48B86E`；类型 ≥4 走跳表 `0x42060C`（HP/MP 条件） |
| **执行前最终闸门** | `0x417B77`（`ret 0x10`，唯一调用者 `0x42341A`） | `al==0xFE` 时用 `[ctx+0x0D]` 顶替目标；内部调 `0x42044D` |
| **玩家选格合法性** | `0x45533D` → `0x45554F` | 先判 `[ebp+0x10]`（行动类型）：**<4 直接走 `0x455565`，不查下面的表**；`≥4` 且技能号 `<0x4A` → `0x43623B`；技能号 `≥0x4A` → `0x40E975`（内部 `0x40E9C4` 同款地形规则） |
| `0x43623B` 内部 | `0x4362C4` 读 `0x510000` 表 | 普通策略要求该字节 `==0` 再过地形规则（`0x412557`：地形 `<5` 或 `==7` 放行）；威吓(0x24)/咒骂(0x25) 要求 `!=0`（见风险节） |
| **空地放行** | `0x4554B3` 写 `[0x4B4250+0x61]` → `0x406E2B` → `0x435CE9` | 开关来源：行动类型1→`0x407835`；类型2/3→`0x4837C2`+`0x41DD72`；策略→`0x41A10C`（读 `[id+0x4D14E0]` bit1 辅助穿透） |
| **范围目标过滤/追加** | `0x437AFF` | `0x406710` 势力、`0x41B500` HP、去重后追加到 `0x4AC748`（WORD 项：低字节单位号、高字节 `FF`），游标 `0x4B2C34` |
| 格→单位号 | `0x435884` | 无单位返回 `FF`；越界/非法返回 `FF` |

### 6. 施放结果与物块

策略上下文 `0x497AF8`（同批还有 `[ctx+0x400]`、`[ctx+0x54C]` 等字段）：

| 偏移 | 内容 | 实机样例 |
|---|---|---|
| `+00` | 策略号 | `0x23` 压迫 / `0x3F` 觉醒 / `0x5E` 纵火 |
| `+01` | 施法者战场编号 | `02`(unit2) / `00`(unit0) |
| `+04` | 上下文指针（随流程变化） | `0x03061090` / `0x03061000` |
| `+08` | 施法者单位记录指针 | `0x4A7B80`(unit2) / `0x4A7B20`(unit0) |
| `+0C` | 选中目标（单位号；空地类为锚点） | `0x54`(unit84 敌) / `0x04`(unit4 我)；纵火点击过程中曾读到 `FF`（目标未定态） |
| `+0D+i` | 目标表，`FF` 结束 | `54 FF`（对敌单目标）、`04 FF`（对我军单目标） |
| `+108+4i` | 每目标伤害（DWORD） | 压迫/觉醒=0；伤血类策略才有值 |

- **实机三态样本**：压迫(0x23)→敌方 unit84；觉醒(0x3F)→我方 unit4；纵火(0x5E)→空格 (9,19)，上下文记录的是效果锚点（施法者）而非格子。
- **追加样本（420 秒抓取窗口内自动记录）**：觉醒(0x3F)→unit4、放火烧山(0x7B)→unit96 / unit108、纵火(0x5E) 在点击过程中 `+0C=FF` 且目标表为空，确认后才写入锚点 —— 说明 `+0C` 存在"未定 → 已定"两态。
- 物块（地形改块）表 `0x4B3D21`：250 项 × 5 字节 = `X, Y, 新地形, 原地形, 编号`；纵火实测在 `(9,19)` 写入 `类型=0x1A`（火）。
- `0x4AC748` 是范围扫描的候选/追加数组，**不等于最终目标表**；最终目标以 `[ctx+0x0D]` 为准。

### 7. 死表 `0x510000`

- 全 exe 只有两处引用：读 `0x4362DE`（`0x4362C4` 内），写 `0x473DE1` 的 `memset(0x510000, 0, 0xC80)`。
- 战场内、选格后、施放后三次实机复读均为全 0 ⇒ 该字节恒为 `0`，属引擎遗留缓冲。

## 实现/使用方法

1. **改数值/文字/对象/范围（首选）**：用形象指定器或直接改 `Data.e5`，`偏移 = 0xB204 + 策略号×0x61`，字段见「已确认事实 2」。例：让某策略可对我军/空地 → 把 `+0C` 由 `00` 改 `01`。
2. **换效果（A 策略执行 B 的效果）**：改 `Ekd5.exe` 文件偏移 `0xA2D70 + 策略号` 的效果索引（或挂钩跳板表 `0x4259C3`）。
3. **换 AI 行为/命中上限/伤害系数/是否伤血/动画/学会类别/模仿与穿透位**：改 `0xA2E00 / 0xA2E90 / 0xA2F20 / 0xA3040 / 0xA30D0 / 0xA3160 / 0xA31F0 / 0xA2FB0 / 0xA2CE0` 加 `策略号` 的那一字节。
4. **不重启游戏热改（只影响本次进程）**：写 `0x4A3E77 + 策略号×0x61` 的 `+0B 对象 / +0C 范围 / +0D 效果范围 / +0E MP / +0F 类型 / +10 图标`。
5. **需要分情况限制（如"不能对 AI=坚守 的敌人使用"）**：挂 `0x43915D`（对敌/对友判定）、`0x417B77`（执行前最终闸门，效果类策略必经）、`0x406E2B`（空地）。判断"当前正在施放什么"要用 `0x497AF8` 的**本次写入时机**，不能只看残值。
6. **实机验证工具**（本机 x32dbg MCP，`127.0.0.1:3000`）：`大鲸鱼产生专用/_施放记录器.py`（只读、不打断，自动记录每次施放的策略号/施法者/目标/伤害/物块）；`大鲸鱼产生专用/_抓格判定.py`（断点 `0x43623B` / `0x436262` 抓选格现场）。
7. 任何 exe/Data.e5 写入都必须遵守项目护栏：目标 SHA 校验、旧字节锁、备份、写入后复读。

## 风险与边界

- **行动类型会绕过选格判定**：`0x45533D` 先判 `[ebp+0x10] < 4`，玩家正常施放策略走该分支，不经过 `0x43623B`，因此也不受死表 `0x510000` 与地形规则约束；只有"行动类型 ≥4 且技能号 <0x4A"才会进入。实机验证：威吓(0x24)/咒骂(0x25)/落雷(0x18)/补给(0x37) 的施放对 `0x43623B` 命中次数为 0；在 `0x43623B` / `0x436262` 双断点常驻 420 秒的窗口内，觉醒(0x3F)/纵火(0x5E)/放火烧山(0x7B) 的多次施放同样 0 命中。
- **死表带来的特例**：在"行动类型 ≥4"路径中，威吓(0x24)/咒骂(0x25) 要求 `0x510000` 表字节 `!=0`，而该表恒为 0 ⇒ 该路径下这两个策略会被永久拦截。
- **策略上下文不清空**：`0x497AF8` 在施放结束后保留残值（三个不同策略依次读数可见），把它当"正在施放"的信号会误伤物理攻击等其它流程。
- **空地类策略的格子不在 `+0C`**：`+0C/+0D` 记录的是效果锚点（施法者）；真实格子在 `0x435CE9` 扩展链与物块表 `0x4B3D21`。
- **跨 SHA 风险**：本页地址绑定 `A168DC99…`；知识库既有 `6929FE0D…`（1,146,880 字节）样本的地址结论不能与本页混用，`0x42B171/0x42B195` 注册循环按 `count=0x44(68)` 初始化，与 144 条表的关系仍未证实。
- 本页只开放"改数据/改属性表/挂钩"三类用法；`0x510000`、`0x4AC748` 等缓冲区不得整体覆盖。

  4. `arg4=byte[0x505F2C]`（全局标志）；
  5. `arg5=[U+0x04]`（该 U 的 slot/编号字段，低字节由 `0x45AA37` 的对象解析门消费）。
- 这条调用点不能简化成“把 U 指针传给 `0x45AA37`”：传入的是 U 内的 DataID 与 slot 值。已有其它调用点也显示参数5可直接作为单位槽号；因此动态记录必须同时保存 `U`、`U[0]`、`U+0x04` 和五个入栈值。
- 类别号 0..5 的确定写点是 `U+0x18+类别`；类别6 进入 `0x423FB9/0x4240D6` 异常状态分支；类别7/8 才分别进入 `0x43F6DB` HP setter / `0x43F715` MP setter。当前 0x7B 是否以哪一类别调用仍属动态问题。


### 6. 调用者 ABI 护栏

- `0x42AC44` 是当前可确认的完整 7 参数调用者；而 `0x420EB9` 的对象首字段等于 2 分支目前只压入 6 个参数就调用 `0x45ADE7`，与被调方 `ret 0x1C` 的 7 参数清栈契约不匹配。该分支可由静态条件选择，但应标为 ABI 失配的遗留候选，不能直接当作正常 0x7B 目标 UI 路径。
- `0x420EB9` 的对象首字段不等于 2 分支另走 5 参数 `0x45AA37`，与上述矩形候选生产链分开。动态短窗应优先确认 `0x42AC44/0x420EF2` 的完整调用，再观察 `0x420EB9` 分支是否真的返回且 ESP/父帧保持一致。
