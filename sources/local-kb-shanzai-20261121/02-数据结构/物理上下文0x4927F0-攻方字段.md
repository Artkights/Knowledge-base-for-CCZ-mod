# 物理上下文 `0x4927F0` 的攻方字段（用户口径 2026-10-18）

## 1. 结论速览

1. `0x4927F0`（十进制 **4794352**）= 物理攻击上下文基址；用户口径：**`+0` = 攻方战场编号**。
2. `0x4927F8`（4794360）= **攻方 Data 内存地址**（人物/Data 记录指针）。
3. `0x4927FC`（4794364）= **攻方战场内存地址**（战场单位记录指针，`0x4A7B20 + slot*0x30` 那一条）。
4. 据此，判定「敌军发起物理攻击」可以直接读这三个字段，**不需要**再用 `0x4061F9` 把编号转成单位指针。
5. 触发条件不需要命中/闪避/反击：只要物理攻击发起、`0x4927F0` 被填好即可（用户口径「别管他命中不命中」）。

## 2. 适用版本

`Ekd5.exe` 当前样本 `3C6E11F98C8BD8D2086C00F4DEC5FE3EE4FC460CDBF129EB82D1E4F41B7B6F14`（含移星易宿 v2）。

## 3. 已确认事实

| 地址 | 语义 | 证据类型 |
|---|---|---|
| `0x4927F0` | 攻方战场编号（slot，byte） | 用户口径（2026-10-18 22:1x） |
| `0x4927F1` | **防方（被攻击者）战场编号**（byte） | 用户口径（2026-10-18 22:23） |
| `0x4927F8` | 攻方 Data 内存地址 | 用户口径 |
| `0x4927FC` | 攻方战场内存地址（单位记录指针） | 用户口径 |

- 与旧口径的差别：本库早前把 `0x4927F0` 的两个字节写成「`+0` 目标、`+1` 攻击者」（见 `03-机制详解\特技0x71-策略反击-设计与实现.md` 的物理链注释），
  但那是**反击上下文**（`0x4064C5` 处 `[ebp-4]`）的观察；**攻击上下文**按用户新口径以本页为准。
- `+0` 与 `+1` 是**相邻两个字节**（旧样本快照 `04 6D 00 00 01 00 00 00`），因此读编号要用 `movzx ..., byte`，不能读 dword。

## 4. 实现·使用方法

```asm
mov ecx, 0x4927F0
movzx eax, byte [ecx]        ; 攻方战场编号
mov edx, [0x4927FC]          ; 攻方战场内存地址 = 单位记录指针（可直接当 ECX 用）
mov ebx, [0x4927F8]          ; 攻方 Data 内存地址（查 Data 记录时用）
```
- 移星易宿 v2 已用 `0x4927F0`（攻方编号）/ `[0x4927FC]`（攻方单位指针）/ `0x4927F1`（防方编号）取数，
  洞体里**省掉了**对攻方那一次 `call 0x4061F9`（洞体 688 → 672 字节）。
- 防方单位仍需 `0x4061F9(byte[0x4927F1])` 转换（上下文里没给防方指针字段）。

## 5. 风险与边界

- `0x4927F0` 只在物理攻击/反击期间有效；不在攻击链上的代码读到的是残值。
- 反击上下文（`0x4064C5` 那条函数）与攻击上下文的字段顺序**不一定相同**，不要互相套用。
- 这三个字段是指针/编号，**只读**；不要往这里写。

## 6. 证据来源

- 用户口径 2026-10-18 22:1x（三条地址原文：`4794352(4927F0H) 攻方战场编号`、`4794360(4927F8H) 攻方 Data内存 地址`、`4794364(4927FCH) 攻方 战场内存 地址`）
- 旧样本字节快照：`03-机制详解\特技0x71-策略反击-设计与实现.md`（物理上下文 `04 6D 00 00 01 00 00 00`）
