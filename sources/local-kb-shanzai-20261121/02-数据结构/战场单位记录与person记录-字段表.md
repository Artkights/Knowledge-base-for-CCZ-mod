# 战场单位记录 与 person 记录（字段表）

> 适用样本：`Ekd5.exe` **SHA256 `2AC91CB8…E3A7D45`**｜归并自 `可搬回清单-初版对照.md` **§124–§127**（含一次字段归属纠正 §126）
> ⚠ **别把两个结构的 `+0xC` 弄混** —— 这是本页最重要的一条（§126 纠正过）✓

## 1. 结论速览

1. **战场单位记录**：`0x4A7B20 + slot×0x30`（**slot 0–59 我方 / 60–249 敌方**，已运行时证实）✓
2. **person 记录**：`[0x4CEA00] + Data号×0x48`（运行时 `[0x4CEA00]` = `0x03151000`）✓
3. **由"单位记录"取 person 指针**：`0x40658F`（约定：**`ecx` = 单位记录** ⇒ 取 `[ecx]` 的 **Data号** ⇒ `call 0x4061E4` ⇒ `eax` = person 指针）✓
4. **每单位结算的门禁是「单位记录 `+0xC` == 2」**（**不是** person 的 `+0xC`）—— `0x43CDDD`（由 `0x44EE9A` 调用）以 `ecx` = 单位记录进入 ✓
5. person 的 **`+0x21`** 是"0–100+ 的百分量"：> 100 时把超出部分按百分比加成（`0x43C4F0` 段）✓

## 2. 战场单位记录（`0x4A7B20 + slot×0x30`）

| 偏移 | 宽度 | 语义 | 现测（战场，58 个占用单位）| 证据 |
|---|---|---|---|---|
| `+0x00` | WORD | 单位数据号（`0xFFFF` = 空位）| slot1 = 30、slot60 = 496、slot72 = 330 | 运行时 ✓ |
| `+0x05` | byte | **阵营**：`0` = 我方、`2` = 敌方 | slot 0–59 我方 / 60 起 `2` | 运行时 ✓（§81/§117/§127）|
| **`+0x0C`** | byte | **单位状态码**：`2` = 正常参战；`3` 疑"阵亡/撤退"（唯一取 3 者 HP = 0）；`1` 疑"待机/增援"（12 个敌方）| 分布 `2`×45、`3`×1、`1`×12 | 运行时 ✓（§127）|
| `+0x0D` | byte | action（行动状态）| 多为 0、个别 8 | 运行时 ✓ |
| **`+0x0E`** | byte | **控制方**：**`7` = 玩家控制**；敌方为 `1`/`3` | 我方 4 个单位全为 7 | 运行时 ✓（§127；与 `_42托管我军.py` docstring 一致）|
| `+0x10` | WORD | HP | slot1 = 862、slot2 = 0 | 运行时 ✓ |
| `+0x1E` | — | 中毒/异常相关字段（库内既有）| — | 库内既有页 |

## 3. person 记录（`[0x4CEA00] + Data号×0x48`）

| 偏移 | 形态 | 语义/现测 | 证据 |
|---|---|---|---|
| `+0x00` | 小值 | `0x101E`（slot1）/ `0x114A`（slot72）⇒ 疑数值（经验/上限类）| 运行时（§125）|
| **`+0x04`** | dword | 编号（slot1 = 30、slot72 = 525）⇒ **不是索引**（slot1 恰等于索引）| 运行时 ✓；**真判定读它的低字节**（§123/§124）|
| **`+0x08`** | GBK 文本 | **名字**（slot1 = `B3 C2 B5 BD` = 「曹仁」✓）| 运行时 ✓ |
| `+0x0C` | 值 | `0`（slot1）/ `212`（slot72）⇒ **不是"每单位结算门禁"**（见 §1.4）| 运行时 ✓ |
| `+0x11` 起 | WORD 数组 | 129 / 197 / 226 / 126 / 151 / 94 …（疑属性/成长）| 运行时（§125）|
| **`+0x21`** | byte | **0–100+ 百分量**：slot1 = 89（<100 ⇒ 不加成）、slot72 = 100（边界）| 运行时 ✓ + 静态链（§119/§125 交叉验证）|

## 4. 实现·使用方法

- **从单位记录取 person**：`ecx` = 单位记录 ⇒ `call 0x40658F`（返回 `eax`）✓
- **从 Data号直接取 person**：`call 0x4061E4`（= `[0x4CEA00] + Data号×0x48`）✓
- **读/写某单位字段**：用 `0x4A7B20 + slot×0x30 + 偏移`（先确认 `+0x00 != 0xFFFF`）✓
- **判"该单位是否参与每单位结算"**：读**单位记录** `+0x0C`，`== 2` 才继续 ✓

## 5. 风险与边界

- ⚠ **`+0xC` 有两个**：**单位记录的 `+0xC` = 状态码**（门禁用它）；**person 的 `+0xC`** = 另一个值（实测 0/212）⇒ **写补丁/做判断时务必写清是哪一个** ✓（§126 已纠正一次）
- person 的 `+4`、`+0x11` 语义**未定**；`+0x00` 语义未定 ✓
- `[0x4CEA00]` 是**运行时动态基址**（实测 `0x03151000`）⇒ **不可硬编码**，必须现读 ✓

## 6. 证据来源

- 运行时只读：`_ccz公共.Mem`（§125/§127）；门禁现场静态复读 `0x43CDDD`（§126）
- 静态复读：`0x40658F`（§124）、`0x426A07`（§123）、`0x43C4F0` 段（§119）

## 7. 待验证项（P1）

## ★ 2026-10-27 当前 6.6：person/R 的 `+0x2B/+0x2C` 角色信息写入链（静态）

样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B。本节只读当前镜像，未启动游戏、未附加 x32dbg，未写入 `Ekd5.exe`、`RS` 或 `SV`。

### 1. 结构与对象边界

- `0x4061E4` 从栈取 WORD DataID，按 `[0x4CEA00] + DataID*0x48` 得到 person/R 指针并返回到 ECX；`0x40658F` 先从 U 的 `U[0]` 取 DataID，再进入该转换。
- 因而下列 `[ecx+0x2B]`、`[ecx+0x2C]` 只有在调用者已把 ECX 绑定到 `0x4061E4` 返回值时，才可归入 person/R；不能把同偏移的对象记录访问直接套过来。

### 2. `R+0x2B` 的直接写入谱

- `0x40E01F` 是明确的四字节栈参数 setter：取 `[ebp+8]` 的低字节，执行 `mov byte ptr [ecx+0x2B],al`，`ret 4`。它本身不生成 DataID，也不接收战场 slot。
- `0x414BD4` 的当前样本路径先以 `DataID<0x400` 调 `0x4061E4`，保存返回的 R 到 `[ebp-0x18]`，随后以 R 为 ECX 调 `0x40E01F`；这是“DataID → person/R → 写 `R+0x2B`”的直接静态证据。
- `0x40C2E7` 先把同一 R 交给 `0x40BF0C` 做类别归一化，再在满足分支时用 `0x40E01F` 写回 `R+0x2B`；`0x422E2C`、`0x43702E`、`0x453528` 是其它写入调用面，产品名称和具体运行时对象仍不由静态单点命名。
- `0x40BF0C` 的归一化规则仍为：原值小于 `0x3B` 时除以 3，`0x3B..0x4F` 时减 `0x28`，大于等于 `0x50` 时钳到 `0x28`。这是类别索引转换，不是 slot/DataID 转换。

### 3. `R+0x2C` 的直接写入谱与百分量消费

- `0x40E012` 是对应的四字节栈参数 setter：`mov byte ptr [ecx+0x2C],al; ret 4`。
- `0x40C2E7` 在策略/效果分支先读取 `R+0x2C` 与局部量比较；必要时执行 `局部量 -= R+0x2C`，否则把 `0` 写入 `R+0x2C`，随后再写 `R+0x2B`。这条关系只能命名为“百分量门与类别写入相邻出现”，不能把 `+0x2C` 直接叫 HP/MP。
- `0x43C4F0` 读取 `R+0x21+i`，当该值大于 100 时把超出部分送入 `0x425AD9` 百分比计算；这与 `R+0x2C` 属于不同偏移，不能混成同一百分量字段。

### 4. 与战场 slot 的静态交互结论

```text
battle slot
  -> 0x4061F9
  -> U = 0x4A7B20 + slot*0x30
  -> U[0] = DataID
  -> 0x4061E4 / 0x40658F
  -> R = [0x4CEA00] + DataID*0x48
  -> 0x40E01F 写 R+0x2B
  -> 0x40E012 写 R+0x2C
  -> 0x40BF0C / 0x467C9E 进入类别/策略分派
```

这闭合了“战场编号找到角色信息记录，再由角色信息参与类别/策略分派”的静态输入链；它没有证明 `R+0x2B` 的每个数值对应哪个产品兵种名称，也没有证明 `R+0x2C` 在每条效果路径上的最终运行时值。

### 5. 动态交接（本会话不执行）

- 在 `4018=1` 下任选一个非空 slot，记录 `slot/U/U[0]/R`，只读观察 `0x414BD4`、`0x40C2E7` 或 `0x40E01F` 命中时的 ECX、参数和 `R+0x2B` 前后值；判据是 ECX 等于同一 `0x4061E4(U[0])` 返回的 R。
- 另取一条 `0x40E012` 命中，记录 `R+0x2C` 前后值和父返回地址；不得把 `R+0x2C` 变化直接解释成 HP/MP 变化。
