# 引擎地址表（普罗源码权威版）

## 结论速览

- 来源：**Puluomiyuhun（普罗）的 `CCZ-ExtendData` 源码** `ExtendData/constants.h`
  （<http[本地盘]//github.com/Puluomiyuhun/CCZ-ExtendData>）。
- 本地副本：`大鲸鱼产生专用\_外部源码\CCZ-ExtendData\ExtendData\constants.h`
- **这是"扩展数据 DLL"的作者自己维护的地址表** ⇒ 比逐条反汇编猜出来的更权威。
- **纠正了两处我们踩过的坑**（见下「纠正」小节）。

## 适用版本

- 曹操传 6.6 系（`Ekd5.exe`）+ `ExtendData.dll`（扩展数据 DLL）。
- ⚠️ 地址是**运行时绝对地址**（非 RVA），仅在默认基址下成立。

## 已确认事实

### 1. 核心基址

| 宏 | 地址 | 说明 |
|---|---|---|
| `ADDR_UNIT_BASE` | **`0x4A7B20`** | 战场单位表；`UNIT_ENTRY_SIZE = 48 (0x30)`；`UNIT_MAX_COUNT = 250` |
| `ADDR_CHAR_DYN_PTR` | **`0x4CEA00`** | **角色动态数据指针（DWORD，需解引用）**；`CHAR_DYN_ENTRY_SIZE = 0x48` |
| `ADDR_COMBAT_DATA` | **`0x4927F0`** | 物理战斗上下文 |
| `ADDR_STRATEGY_DATA` | `0x497AF8` | 策略战斗数据 |
| `ADDR_STRATEGY_SUCCESS` | `0x498048` | 策略是否成功使用 |
| `ADDR_FUNC_TABLE` | **`0x4F0000`** | **DLL 向引擎注册的接口地址表** |

### 2. ★ `0x4F0004` 的真相（此前完全靠猜）

`dllmain.cpp` 第 625~630 行：

```c
hpro = OpenProcess(PROCESS_CREATE_THREAD | PROCESS_VM_OPERATION | PROCESS_VM_WRITE
                 | PROCESS_VM_READ | PROCESS_QUERY_INFORMATION, FALSE, dwCurrentProcessId);
WriteProcessMemory(hpro, (LPVOID)(ADDR_FUNC_TABLE + 0x00), &addr, 4, 0);
addr = (DWORD)person_effect;                                    // ★
WriteProcessMemory(hpro, (LPVOID)(ADDR_FUNC_TABLE + 0x04), &addr, 4, 0);   // ★
```

⇒ **`[0x4F0004]` = DLL 把自己内部 `person_effect` 数组的地址注册给引擎**。
游戏通过它访问特技数据 —— 这就是 ExtendModifier「内存模式」读的那个基址。

### 3. ★ 特技数据真实布局（`globals.h`）

```c
#define PERSON_MAX        1024
#define EFFECT_SLOT_MAX   256
#define MEFF_SLOT_MAX     32

extern unsigned int  person_mes[PERSON_MAX][MES_VAR_MAX];              // [1024][50]
extern unsigned char person_effect[PERSON_MAX][EFFECT_SLOT_MAX][4];    // ★ [1024][256][4]
extern unsigned char person_meff[PERSON_MAX][MEFF_SLOT_MAX][2];        // [1024][32][2]
extern unsigned char effect_message[256][EFFECT_MSG_FIELDS];           // [256][8]
extern unsigned int  global_var[PERSON_MAX];
```

- `person_effect` 大小 = `1024 × 256 × 4` = **1,048,576 字节 = 正好 1 MB**
  ⇒ 与我们在 `ExtendData.dll + 0x217E08` 读到的 1 MB 表**完全同构**。
- **每个角色的「一行」= `256 × 4 = 1024 (0x400)` 字节** ⇒
  `槽 i` 在行内偏移 `i × 4`。
- 槽的 4 个字节含义（由 `dllmain.cpp` 的读写推出）：

  | 偏移 | 含义 |
  |---|---|
  | `+0` | **特技号**（`0xFF` = 空槽） |
  | `+1` | **特效值**（如防御暴击的减伤百分比 V） |
  | `+2` | **经验值**（`effect_message[effect_id][4]` 累加） |
  | `+3` | **剩余回合**（`0xFF` = 永久；否则每回合 -1，到 0 删除） |

  ⇒ 我们内存里看到的 `24 4B 00 FF` 就是：特技号 `0x24`、值 `75`、经验 `0`、**永久**。

### 4. ★ 战场单位 ↔ 角色的映射（此前搞错的）

`dllmain.cpp` 第 204~217 行：

```c
// 物理攻击
ReadProcessMemory(hpro, (LPCVOID)(ADDR_COMBAT_DATA + 4), &data_id, 2, 0);   // 攻击者角色号
// 策略攻击
ReadProcessMemory(hpro, (LPCVOID)(ADDR_STRATEGY_DATA + 1), &var_id, 1, 0);  // 战场 slot
DWORD data_id_addr = ADDR_UNIT_BASE + var_id * UNIT_ENTRY_SIZE;
ReadProcessMemory(hpro, (LPCVOID)data_id_addr, &data_id, 2, 0);             // ★ 角色号
```

- **`ADDR_UNIT_BASE + slot × 0x30 + 0x00`（WORD）= 该单位的角色号 `data_id`**；
  `0xFFFF` 表示空位。
- ⇒ **`person_effect` 用「角色号」索引，不是战场 slot**。
  这解释了此前"S158 的 slot72 与角色 330 对不上"的困惑。
- `ADDR_COMBAT_DATA + 4`（WORD）= **当前物理攻击者的角色号**。

### 5. 角色固定数据 / 名表

| 宏 | 地址 | 说明 |
|---|---|---|
| `ADDR_EFFECT_NAME` | **`0x4CC600`** | 特技名称表，每项 `EFFECT_NAME_SIZE = 0x10 (16)` 字节 |
| `ADDR_FACE_TABLE` | `0x50F000` | 头像表（每角色 2 字节） |
| `ADDR_CHAR_FIXED` | `0x4A3E77` | ⚠️ **策略名字符串表**（`CHAR_FIXED_ENTRY_SIZE = 0x61`） |

> **纠正 1**：`0x4A3E77` **不是**角色数据基址（源码注释明确写了"曾被误标"）。
> 角色数据请用 `ADDR_CHAR_DYN_PTR`（`[0x4CEA00]`，`0x48` 字节/角色）。
>
> **纠正 2**：`ADDR_EFFECT_NAME = 0x4CC600`
> —— 与我们此前把旧口径 `0x4CC800` 纠正为 **`0x4CC600`** 的结论**完全一致**，
> 等于第三方独立确认。

### 9. DLL 导出接口（引擎回调它）

`dllmain.cpp` 里的 `extern "C" __declspec(dllexport)`：

- `GetRoundChange(kind)`：`kind=0` 每回合给临时特技的「剩余回合」减 1，到 0 就 `DeleteEffectPos`；
  `kind=1` 关卡结束时按脚本变量 `3990`/`3992` 清理临时特技。
- `GetAttack(kind)`：`kind=0` 物理、`kind=1` 策略；取攻击者角色号。
- `AddPersonEffect(data_id, effect_id, value, round)`：加特技（`round=255` 即永久）。
- `ChangePersonMeff` / `DeleteEffectPos` / `AddEffectEXP` 等。

## 实现·使用方法

```bat
:: 拉取/更新源码副本
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_拉普罗源码.py

:: 读运行时特技表（= [0x4F0004] + 角色号 × 0x400）
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_读运行时特效表.py

:: 反汇编 ExtendModifier（看它的读写公式）
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_逆向ExtendModifier.py
```

**给战场单位加特技的正确步骤**（据源码）：

1. 由战场 slot 取角色号：`data_id = *(WORD*)(0x4A7B20 + slot*0x30)`
   （`0xFFFF` = 空位）
2. 基址 `base = *(DWORD*)0x4F0004`
3. 写槽：`off = base + data_id*0x400 + i*4`
   写入 `[特技号, 特效值, 经验, 回合]`（回合 `0xFF` = 永久）

## 风险与边界

- 地址为**运行时绝对地址**，仅默认基址成立；带 ASLR 的环境需按模块基址换算。
- `person_effect` 是 **DLL 内部数组**，写它等于直接改 DLL 数据段 —— 属于内存操作，
  不涉及 `Ekd5.exe` 写入（因此**不需要写锁**，但要遵守"只读校验优先"）。
- 源码里 `person_effect` 由**存档/DLL 自己的文件**加载（`dllmain.cpp` 450~465 行有
  `file.write(person_effect, sizeof(...))`）⇒ **改内存后读档可能被覆盖**，
  与我们的实测一致。
