## 结论速览

- `Guide.cpp` 是「打开 R/S 剧本 → 生成简易攻略」的读取器，同时提供**EEX 框架规则**与**S 剧本事件语义**两层口径；本工作区唯一被验证能跑通全库 173 个 `.eex` 的解析口径就是它（移植版见 `_剧本体检.py`）。
- 2026-10-15 三方互证结果：**9 项完全一致**（EEX 框架、跳转命名、异常状态位、物品名字表偏移、部署槽位编号、`0x4C` 隐藏前提、`0x46/0x47` 循环数组形态、`0x4E` 方针槽位、**参数个数 × 指令大全类型码（抽查 10 条全中）**）；**1 项必须纠正口径**（`0x4D` 的 13 个真实参数槽 ≠ 指令大全的「模板 3 槽」）；**8 项属新增知识**（剧本侧 AI 枚举 0..6、阵营枚举 0..6、属性枚举 15 项、异常掩码 `0x80` 解除位与 HP/MP 损失槽、撤退/死亡标志槽、`1025/1026` 特殊人物号、`0x59` 需全表一致、状态变更合并规则）。

## 已确认事实

### 1. EEX 框架（`Guide.cpp:366-397`）

```text
文件头：size >= 14 且 bytes[0..3] == 'E','E','X',0x00        ; 魔数 EEX\0
偏移表尾：i32 @ +10 = tableEnd
          要求 tableEnd >= 14、<= 文件长度、(tableEnd - 10) % 4 == 0
场景偏移表：从 +10 起，每 4 字节一个 i32 场景偏移（步长 4，到 tableEnd 为止）
          每个场景偏移必须 >= tableEnd 且 < 文件长度
每个场景：u16 sectionCount，随后 sectionCount 个「u16 sectionLength + 该长度的块」
块内：由 ParseBlock 递归解析（见下）
```

- 注意：**场景偏移表本身没有项目数**，项目数 = `(tableEnd - 10) / 4`；`tableEnd` 不是场景数。
- 空文件/坏文件判据：魔数不符、`tableEnd` 越界、`(tableEnd-10)` 不是 4 的倍数、任一场景偏移 < tableEnd → 直接判解析失败。

### 2. 命令框架：每个参数 = 「2 字节类型码 + 载荷」（`Guide.cpp:216-276`）

```text
每条命令：u16 rawId（2 字节），rawId 必须 < 124（kParamCounts 长度）
参数个数：count = kParamCounts[rawId]
          特例：0x46 → 11*20 = 220 个；0x47 → 12*80 = 960 个（循环数组部署）
          槽位循环：0x46/0x47 用 index % baseCount，其余用 index
每个参数：先读 u16 tag（编辑器类型码，例如 0x2/0x4/0x3/0x23/0x24/0x2F/0x30…）
          再按该命令的掩码读载荷：
            · 文本槽（kTextMasks 置位）→ NUL 结尾的 GBK 字符串（读到 0x00 为止，含 0x00 占 1 字节）
            · DWORD 槽（kDwordMasks 置位）→ i32（4 字节）
            · 其余 → u16（按 int16 解释）
          特例：0x05 变量测试 的前两个槽是「变长数组」：u16 个数(<=4096) + 该个数个 u16
```

- **`tag` 被读取后丢弃**（`(void)tag`，`Guide.cpp:273`）：Guide.cpp **不靠类型码**解释参数，而靠自己那四张掩码表 + 少量按命令号的硬编码覆盖（`Guide.cpp:235-242`）。
- 硬编码覆盖（原样）：`0x14/0x16/0x69` 文本槽 = 位0；`0x15` 文本槽 = 位2；`0x63` 文本槽 = 位1；`0x4C` DWORD 槽 = 位2；`0x4E` DWORD 槽 = 位 2,3,4,5,9,10；`0x46` DWORD 槽 = 位 2,3,9,10；`0x47` DWORD 槽 = 位 3,4,10,11。
- 四张表（各 124 项，索引 = 命令号 `0x00..0x7B`）：`kParamCounts`（参数个数）、`kDwordMasks`（哪些槽是 4 字节）、`kTextMasks`（哪些槽是文本）、`kCanOpenSubEvent`（哪些命令后面能跟子事件块）。
- ⚠️ **不要手抄这四张表**：库内已有教训——手抄版在 `S_85` 偏移 10771 处解析崩掉，用脚本从 `Guide.cpp` 抽取的版本一次通过（见 [剧本特技性能画像与三条落地路线](./剧本特技性能画像与三条落地路线.md) 与 `00-总览与规范/更新记录.md` 同日条目，以及 `_剧本体检.py:14-29` 的表头注释）。

### 3. 块与子事件的递归规则（`Guide.cpp:288-364`）

- 根块（段落块）从 `nextBlock = 1` 开始编号 → **根块 ID 从 1 起**。
- 每个块一个游标，按命令顺序推进；每读到一条命令就记录 `block/event/conditions`。
- 两种「开子块」入口：
  1. `frame.head && command.id == 0`：段首遇到 `0x00 事件结束` → 其后 `u16 子块长度` + 子块内容（`cursor = 子块起点 + 长度`）。
  2. `pendingSubEvent && kCanOpenSubEvent[command.id]`：**上一条是 `0x01 子事件设定`**（`command.id == 1` 会置 `pendingSubEvent`），且当前命令允许开子事件 → 同样读 `u16 子块长度` + 子块。
- 条件继承：`ShouldInheritCondition(cmd) = cmd.id != 0x00 && cmd.id != 0x01 && !IsInternalEventMarker(cmd)`；段首（`head`）命令进 `headerConditions` 并随子块下传，非段首则进 `conditions`。
- `IsInternalEventMarker`：`0x02 内部信息` 恒为内部标记；`0x05` 且 `values == [0, 1, x>=0]`（两个空/单元素数组组合）也算内部标记 → **不参与条件继承**。
- 嵌套上限 512 层；越界一律判失败。

### 5. 参数槽语义（互证重点）

#### 5.1 `0x4D 武将状态变更`：13 槽完整解码

`Guide.cpp:1012-1080` 明确要求 `values.size() >= 13`，各槽含义：

| 槽 | Guide.cpp 用法 | 与指令大全类型码对齐 | 语义 |
|---:|---|---|---|
| P1 | `values[0]` 目标类型：`0`=按人物号 / `1`=按战场号 / `2`=按区域 | 类型码 `0x41` | 目标选择器 |
| P2 | `values[1]`（目标类型 0 时用） | `0x2` | 人物编号 |
| P3 | `values[2]`（目标类型 1 时用） | `0x4` | 战场编号 |
| P4-P7 | `values[3..6]`（目标类型 2 时用）= X1,Y1,X2,Y2 | `0x4`×4 | 区域四角（代码会自行取 min/max 归一） |
| P8 | `values[7]`（区域目标时用） | `0x3` | **阵营枚举**（见 5.4） |
| P9 | `values[8]` = 属性编号 `0..5` | `0x2F` | `0..4`=攻/防/精/爆/士，`5`=移动力 |
| P10 | `values[9]` = 变化 `0..2` | `0x18` | `0`=下降 `1`=恢复正常 `2`=上升 |
| P11 | `values[10]` = 状态掩码 | `0x30` | 见 5.3（申请/解除异常） |
| P12 | `values[11]` | `0x4` | HP 减少量 |
| P13 | `values[12]` | `0x4` | MP 减少量 |

> ⚠️ **口径纠正**：`剧本指令大全/05-4C-5E战场操作.md` 的 `0x4D` 条目写「模板槽位数 3」（P1 武将编号/P2 状态类别/P3 操作方式），那是**编辑器模板的命名槽**；**磁盘上真实是 13 个参数槽**（其「旧源码布局」13 个类型码 `0x41 0x2 0x4 0x4 0x4 0x4 0x4 0x3 0x2F 0x18 0x30 0x4 0x4` 才对得上 Guide.cpp 的取值位置）。写回草稿时按 13 槽写，按 3 槽读会全错位。

#### 5.2 `0x4E 武将方针变更`：剧本侧 AI 枚举 `0..6`（≠ 运行时 `unit+0x0E`）

`PolicyName`（`Guide.cpp:550-556`）原样映射：

| 剧本槽值 | 名称 |
|---:|---|
| 0 | 被动出击 |
| 1 | 主动出击 |
| 2 | 坚守原地 |
| 3 | 攻击指定武将 |
| 4 | 前往指定地点 |
| 5 | 跟随指定武将 |
| 6 | 撤往指定地点 |

对照运行时字段 `unit+0x0E`（本库已确认：`1`主动 `2`坚守 `3`被动 `0`攻击武将/到指定点 `4`跟随武将/逃到指定点 `7`可控）⇒ **两套编码不同名同序号，不可互相套用**。可推断的对应关系（按语义配对，待实机确认）：剧本 `0↔运行时 3`、`1↔1`、`2↔2`、`3↔0(+0x08 有目标)`、`4↔0(+0x09/+0x0A 坐标)`、`5↔4(+0x08)`、`6↔4(+坐标)`；运行时 `7`=可控 在剧本侧没有对应枚举。

#### 5.3 异常状态掩码：位 `2/4/8/16` + **`0x80` 解除位**

`JoinedAbnormalNames`（`Guide.cpp:936-947`）与 `AddStateChangeEntries`（`1072-1077`）：

```text
bit 0x02 = 麻痹    bit 0x04 = 封咒    bit 0x08 = 混乱    bit 0x10 = 中毒
0x80 置位 → 解除这些状态；否则 → 施加这些状态
掩码在代码里按 & 0x7E 过滤（位 1..6；位 1/5/6 未命名）
```

- **与 `02-数据结构/异常状态位定义.md` 完全一致**（`unit+0x1E` 用的是单 bit `0x02/0x04/0x08/0x10`），并且**再次否证**“2-bit 窗口 `0x03/0x0C/0x30/0xC0`”那套错误口径。
- 新增：剧本侧的 **`0x80`=解除标志**，以及“全掩码 `0x1E` 时输出「陷入异常/解除异常」”的措辞规则（`989-999`）。
- 命名差异：Guide.cpp 用「封咒」，本库页用「封锁（旧称禁咒）」，同一 bit。

#### 5.4 阵营枚举（区域目标）`0..6`

`CampTargetName`（`Guide.cpp:1005-1010`）：`0`我军 `1`友军 `2`敌军 `3`援军 `4`我军及友军 `5`敌军及援军 `6`全部部队。

- 与 `unit+0x05` 的运行时阵营（`0`我/`1`友/`>=2`敌）**不是同一套**：这里是**剧本目标选择用的 7 项枚举**。

#### 5.5 属性变化：剧本 `0/1/2` ≠ 运行时 `1/3/6`

- 剧本槽（`values[9]`）与产出文本（`AttributeChangeText`，`949-971`）：`0`下降 / `1`恢复正常 / `2`上升；掩码位 `0..4`=攻/防/精/爆/士（`0x1F` 时合并成「全能力」），位 `5`（`0x20`）=移动力。
- 运行时字段 `unit+0x18..+0x1D` 的写入值是 `1`减 / `3`正常 / `6`增（扳手源码口径，见 `02-数据结构/战场运行时内存-6.4资料与6.5复核.md`）。
- ⇒ **读剧本用 0/1/2，读/写运行时字段用 1/3/6**；二者是「剧本枚举 → 引擎写入值」的转换关系（对应关系按语义配对，待实机复核）。

### 三、0x77 变量运算的运算符（6.6 现读，×10797 全库第三高频）
