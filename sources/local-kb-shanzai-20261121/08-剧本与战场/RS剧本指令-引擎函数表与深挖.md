## 结论速览

- `函数表.txt` 是 **命令分派表**：`0x410A38 + (命令-2)*4`；共 **126 项 = 命令 0x02..0x7F**；命令 `0x00`/`0x01` 由分派器 `0x4109E6` 特判，不在表里。
- 与本地 **6.5 原始版**逐项比对：**100/126 完全一致**（94 个非占位 + 6 个 `0x4D0000` 占位也相同）；**26 项非占位入口不同**（其中 21 项在 6.5 是 NOP/函数中段，5 项是合法函数头但不在 6.5 表里）⇒ **这张表来自另一个 6.5/6.6 家族构建，源 EXE 不在本机**；这 26 条的精确反汇编需要源 EXE。
- 分派器 `0x4109E6`：`call 0x40FCB2` 读 2 字节 → 低字节=命令，存 `ctx+0x2E` → `cmp eax,0x79; ja` 返回 5 → `cmd<=1` 特判 → `sub eax,2; call [eax*4+0x410A38]`。
- 状态机表 `0x486610` 共 5 项（`0x40FFD0 / 0x40FE3D / 0x4109E6 / 0x480612 / 0x418BBC`）；`0x4109E6` 是“读/执行一条 RS 指令”的状态。
- 参数读取器：`0x40FC7F` 读 u8（`ctx+0x08` 计数、`ctx+0x0C` 游标）；`0x40FCB2` 读 u16；`0x40FC90` 读 u32；`0x40FC62` 读 0 结尾字符串；`0x4183F7` 按“类型码”取参（**4=数值、5=字符串**、`0x38/0x39` 等特殊）。
- 代表性指令：`0x02 内部信息` = 读 1 个字符串（类型 5），成功返回 1、失败 5；`0x03 else` = 直接返回 6；`0x14 对话` = 读字符串 + `&` 说话人/`*` 控制码解析 + `0x417DF6` 显示；`0x72 信息传送` = 读 2 参数后按 `0x47D8DF` 的 5 项子功能表分派。
- `0x7A`/`0x7B` 这张表和 6.5 原始版里都是 **`0x004D0000` 占位**（未实现）；7B 五类测试是 QQ 补丁后加的，见 [信息传送测试7B-五类测试-6.5pl移植](../03-机制详解/信息传送测试7B-五类测试-6.5pl移植.md)。

## 已确认事实

### 1. 表结构与分派器

- 表基址 `0x410A38`；命令 `N` 的表项 = `[0x410A38 + (N-2)*4]`；`N=0x02..0x7F`。
- 分派器 `0x4109E6`（6.5 原始版现读）：
  ```asm
  004109E6 55                 push ebp
  004109E7 8B EC              mov  ebp, esp
  004109E9 51                 push ecx
  004109EA E8 C3 F2 FF FF     call 0x40FCB2        ; 读 2 字节；低字节=命令
  004109EF 50                 push eax
  004109F0 8B 55 FC           mov  edx, [ebp-4]    ; edx = ctx
  004109F3 88 42 2E           mov  [edx+0x2E], al  ; 当前命令存 ctx+0x2E
  004109F6 83 F8 79           cmp  eax, 0x79
  004109F9 77 34              ja   0x410A2F        ; >0x79 → eax=5
  004109FB 3C 01              cmp  al, 1
  004109FD 77 14              ja   0x410A13
  004109FF 83 C0 03           add  eax, 3
  00410A02 3C 04              cmp  al, 4
  00410A04 75 24              jne  0x410A2A
  00410A06 8B 52 0C           mov  edx, [edx+0x0C]
  00410A09 4A                 dec  edx
  00410A0A 4A                 dec  edx
  00410A0B 89 15 4C E7 4C 00  mov  [0x4CE74C], edx   ; cmd=1 子事件设定
  00410A11 EB 17              jmp  0x410A2A
  00410A13 52                 push edx              ; ctx 作为参数
  00410A14 83 E8 02           sub  eax, 2
  00410A17 FF 14 85 38 0A 41 00 call [eax*4+0x410A38]
  00410A1E 83 C4 04           add  esp, 4
  00410A21 83 7D F8 76        cmp  dword [ebp-8], 0x76
  00410A25 75 03              jne  0x410A2A
  00410A27 89 4D F8           mov  [ebp-8], ecx
  00410A2A 8B 4D F8           mov  ecx, [ebp-8]
  00410A2D EB 05              jmp  0x410A34
  00410A2F B8 05 00 00 00     mov  eax, 5
  00410A34 8B E5              mov  esp, ebp
  00410A36 5D                 pop  ebp
  00410A37 C3                 ret
  ```
- 返回值：`cmd 0` → eax=3；`cmd 1` → eax=4；`cmd 2..0x79` → 处理函数返回值；`>0x79` → eax=5。
- **`[ebp-8]` 异常**：`push ecx` 只分配 `[ebp-4]`，`[ebp-8]` 在标准帧外；`cmp [ebp-8],0x76` 疑为调用方共享栈槽/自定义约定。**未定论，需 x32dbg 实机确认**（不要据此改代码）。
- 状态机表 `0x486610`：`0x40FFD0, 0x40FE3D, 0x4109E6, 0x480612, 0x418BBC, 0`。`0x4109E6` 是其中一个状态函数；`0x418A97` 有 `mov [ecx], 0x486610`（把表挂到场景对象）。
- 表末两地址 `0x414EDC` / `0x41F5E2`：在 6.5 原始版是函数中段（`inc eax; add al,[edx]` / `push 0; push 0x100…`），**不是函数头**；源构建在这两处也不同，不能当入口。

### 2. 参数读取器

| 函数 | 机器码要点 | 语义 | ctx 字段 |
|---|---|---|---|
| `0x40FC7F` | `inc [ecx+8]`；`eax=[ecx+0xC]`；`movzx eax,byte[eax]`；`inc [ecx+0xC]` | 读 1 字节 | `+8` 计数、`+0xC` 游标 |
| `0x40FCB2` | 调 `0x40FC7F` 两次，低字节 \| 高字节<<8 | 读 u16（分派器用它取命令） | 同上 |
| `0x40FC90` | 调 `0x40FCB2` 两次，低 16 \| 高 16<<16 | 读 u32 | 同上 |
| `0x40FC62` | `eax=[ecx+0xC]`；循环到 NUL；`inc [ecx+0xC]` | 读 0 结尾字符串，返回首指针 | `+0xC` |
| `0x4183F7` | 当前F607现读：tag `0x04`读有符号32位；仅当前opcode `<0x6E`且值负时按INT[-v]读取。tag `0x02/0x38/0x39`的16位负值-4097..-2按INT[-v-2]，-1不作INT；`0x76`负跳转不套普通参数规则。tag5另按原分支 | **按类型取参**；不能简写“负数再读u16”或对全部负数取abs当变量。证据见全S_R有类型占用普查-20261107/负引用与数值解析器现读.txt、有限独审；目标EXE F6079EB9…5CCBC5 | 同上 |

- 常见类型码（来自 `code_instruct` 与处理函数 `push` 立即数）：`4`=整数/数值、`5`=字符串、`2`=变量/人物槽、`0x26`=询问项、`0x35`=变量、`0x38/0x39`=特殊。
- `0x4183F7` 的类型不匹配时会 `inc [ebp-4]`（记录“类型不对”），但仍按请求类型读；具体消费由处理函数决定。

### 4. 重点指令深挖

#### `0x02` 内部信息 / `0x03` else / `0x04` 询问测试

- `0x02`（`0x41177D`，34 B）：`push 5; call 0x4183F7` 读一个字符串；失败返回 5，成功返回 1。**它只“读掉”一个字符串参数**，真正的显示由外层/后续状态处理。
- `0x03`（`0x4834C6`，10 B）：`mov eax,6; ret` —— 纯控制码，返回 6（else 分支标记）。
- `0x04`（`0x4116FF`，60 B）：`push 0x26` 读一个“询问项”（u16）；`0x8000` 失败返回 5；否则 `push eax; push 0x48B3AC; push 1; call 0x42F699`，再与 `[ebp-4]` 比较，相等返回 1，不等返回 0。`0x48B3AC` 是询问项文本表/上下文。

#### `0x14` 对话（`0x413661`，442 B）

- 先 `push 5; call 0x4183F7` 读字符串；失败返回 5。
- `call 0x40B922` 取当前文本/窗口上下文；`[ebp-0x14]` 是字符串游标。
- 字符串格式：`&` 开头 → 说话人/头像段（`0x47FB4C` 查人物、`0x4061F9` 取单位、`0x418C90`/`0x45F670` 取立绘/表情）；`*` 开头 → 控制码（`0x4082AC` 解析并跳过）；其余字节进 `[ebp-0x420]` 文本缓冲区（上限 0x400）。
- 文本布局 `call 0x44DEEF` → 显示 `0x417DF6`（`0x492F90` 上下文）；`0x501FFF` 是“跳过/快进”标志；两条显示路径 `0x42D5B0`（带 0x20 控制）与 `0x45965D`（`0x4B5DF0` 窗口）。
- 结尾处理 `0x0A 0x26`（换行+&）等控制序列；`0x4137E9..0x413806` 负责推进游标。

#### `0x72` 信息传送（`0x47D89E`，65 B）

- `push 4` 读 P1（数值，子功能号）；`push 5` 读 P2（字符串/参数）；任一失败返回 5。
- `call [P1*4 + 0x47D8DF]`；表 5 项：`0x4081F2 / 0x40C4B7 / 0x41419F / 0x40221B / 0x402AA6`。这就是“72 信息传送”的 5 个子功能（不是 7B）。
- 返回 1；`P1` 只接受 0..4（表长 5），越界会读表外，**剧本里必须保证 0..4**。
- **6.6 现读（2026-10-24，样本 SHA `6FFE872652AAF32D08D71871DF56B4A672C280684D8C55667DF4FA3CF1FDC2DC`）**：同址、表长 **38**（跳转表 `0x47D8DF` 索引 0..37，紧接 `90 90 90 90`），前 5 项与上行相同；「P1 只接受 0..4」仅适用于 6.5，6.6 无范围校验 ⇒ 见 `03-机制详解/信息传送0x72-现行结论.md`。

#### `0x77` 变量运算（`0x416C87`，322 B）

- 读 5 个参数；类型码来自 `0x416C82` 的 5 字节表（`push` 到 `0x4183F7`）。
- 参数存 `[ebp+ecx*4-0x14]`；核心是 `0x506000 + id*4` 的整型变量数组（`cmp eax,0x12F` 上限 0x12F=303）。
- `cmp ecx,2` 区分“单目/双目”运算；`0x416C82` 表决定每个槽的类型（数值/变量/字符串）。
- 具体运算符表在 `0x416C..` 附近；本页不展开每个运算符，反汇编见 atlas `0x416C87`。

#### `0x44` 战斗初始化（文件入口 `0x412222`，6.5 实际 `0x412226`，155 B）

- **文件入口 `0x412222` 在 6.5 是上一函数的 `mov esp,ebp; pop ebp; ret` 尾巴**，不是函数头；6.5 实际入口是 `0x412226`（`push ebp; mov ebp,esp`）。这说明源构建在此处代码布局不同，6.5 版应以 `0x412226` 为准。
- 逻辑：`[0x4CE79C]=0`；循环 `0..0x3FF` 调 `0x4061E4`（人物记录）→ `[ecx+0x19]=al`，并把 `dx` 写入 `0x508A00 + i*2`；`0x4184CC` 清/设每项；`0x426C3B` 初始化；`0x48B350` 是 0xFA 项的表（`word`，`-1` 结尾）；`0x418DD0` 取项指针并写 `[eax]=edx`、`[eax+8]=0`；最后读 `0x505EC4` 等全局。

#### `0x48` 敌方装备设定（`0x411CD9`，204 B）

- `push 0x3B; push 0; push 2` 读一个“数量/类型”参数（`0x3B`=59，`0x8000` 失败返回）。
- 循环读 3 组（每组 2 个）道具/装备 ID：`push (i + [ebp-0x20]); call 0x4183F7`；`0xFFFF` 归一为 0；存 `[ebp+i*4-0x1C]`；`cmp ecx,2` 控制前 3 组。
- 之后把这 6 个值写入敌方单位的装备槽（具体写入点在 `0x411D..` 之后，atlas 可查）。

#### `0x5A` 战场操作开始（`0x410549`，20 B）

- `mov ecx,0x4B3D08; call 0x44BAC2; mov eax,1; ret` —— 把 `0x4B3D08` 这个战场/天气上下文交给 `0x44BAC2` 启动，返回 1。`0x4B3D08` 也是 7b-4 天气测试读的全局。

#### `0x7B` 信息传送测试（占位）

- 文件表、6.5 原始版表项都是 `0x004D0000`（**未实现占位**）；`0x4D0000` 在 6.5 里是 `90` NOP 串/零区，不能当函数反汇编。
- 现在能用的 7B 五类测试是后加补丁（`0x4E7500` 入口、`0x4E7400..0x4E7D02`），见 [信息传送测试7B-五类测试-6.5pl移植](../03-机制详解/信息传送测试7B-五类测试-6.5pl移植.md)。
