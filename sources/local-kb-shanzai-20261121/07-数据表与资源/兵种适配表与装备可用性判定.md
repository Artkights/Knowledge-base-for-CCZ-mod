# 兵种适配表与装备可用性判定（`0x44C341` / `0x420E83`）

> 样本：`Ekd5.exe` SHA256 `C77A18BFA52CFF159AC11E59880ED0B3FBB481E5ADAE016DE67059330F07FD64`
> 工具：`大鲸鱼产生专用\_查兵种适配表.py`
> 线索来源：用户提供的《Star6.5引擎常用修改地址整理 by狂风》第「二.装备」第 7 条

## 一、结论速览

1. **「辅助装备指定多个兵种」表 = `0x44C341`**，**6.6 沿用 6.5 同址**（本样本实测命中）。
2. **表结构**：`FF` 开头、`FF` 分隔、**`FF` 结尾**；组内是**大兵种序号**（每字节一个）。
   本样本实测 = **4 组 / 共 16 个兵种号**：
   ```
   FF | 01 0B 0C 1D 1F | FF | 09 0B 0C 1F | FF | 06 04 0C 16 | FF | 05 23 24 | FF | 90 90 …
      ↑ 第1组(5个)      分隔  第2组(4个)    分隔  第3组(4个)    分隔  第4组(3个)    结尾  NOP填充
   ```
   表后紧跟 `90`(NOP) 填充，再后是函数序言 `55 8B EC`（下一函数起点 `0x44C378`）。
3. **查表函数 = `0x420E83`**（`cl` / `al` 双字节入参）：
   * `cl == 0xFF` ⇒ 返回 **1**（无条件允许）
   * `cl == al` ⇒ 返回 **1**（同兵种）
   * 否则遍历 `0x44C341`：**定位含 `cl` 的组，再在该组内找 `al`**；找到 ⇒ **1**，走到组尾/表尾 ⇒ **0**。
   ⇒ **语义 = 「`cl` 与 `al` 是否属于同一兵种组」**，即**"是否允许装备"**。
4. **调用者只有 2 处**：`0x4079B3`、`0x428631`。
5. ⚠ **`物品记录 +0x14` 不是纯遗留位** —— `0x428625` 处 `cmp byte[ecx+0x14], 3` 真实参与判定
   （与推导表旧注「旧 6.5 图标遗留」冲突，见第五节）。

## 二、适用版本

- 本页地址/字节对应**复刻版6.6山贼当前样本**（SHA 见页首）。
- **表地址 `0x44C341` 跨 6.5/6.6 相同**（6.5 由用户资料给出，6.6 实测命中）
  ⇒ 该表是**引擎内固定数据**，不是 MOD 数据文件内容。
- 具体**组数与兵种号**随 MOD 改动会变（本样本 4 组 16 值），**引用数值前必须现读**。

## 三、已确认事实

### 3.1 表内容（实测字节）

`0x44C341`（`.code`）原始 64 字节：
```
FF 01 0B 0C 1D 1F FF 09 0B 0C 1F FF 06 04 0C 16 FF 05 23 24 FF 90 90 90 90 90 90 90 90 90 90
90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90 55 8B EC B9 58 75 4B 00 E8 C9 31 FC
```
- **4 组**：`01 0B 0C 1D 1F` / `09 0B 0C 1F` / `06 04 0C 16` / `05 23 24`
- 表占用 **22 字节**（含收尾 FF），其后 `90` 填充至 `0x44C378`（下一函数序言）

### 3.2 查表函数 `0x420E83` 完整反汇编

```asm
00420E83  55              push ebp
00420E84  8B EC           mov ebp, esp
00420E86  80 F9 FF        cmp cl, 0FFh
00420E89  74 29           je  00420EB4          ; cl==FF ⇒ eax=1
00420E8B  3A C8           cmp cl, al
00420E8D  74 25           je  00420EB4          ; cl==al ⇒ eax=1
00420E8F  BA 41 C3 44 00  mov edx, 44C341h      ; ★ 载入兵种适配表
00420E94  EB 01           jmp 00420E97
00420E96  42              inc edx               ; （循环入口）
00420E97  80 3A FF        cmp byte [edx], 0FFh
00420E9A  75 FA           jne 00420E96          ; 跳过到下一个 FF
00420E9C  42              inc edx
00420E9D  80 3A FF        cmp byte [edx], 0FFh
00420EA0  74 0E           je  00420EB0          ; 连续 FF ⇒ 表尾 ⇒ 未找到
00420EA2  3A 0A           cmp cl, byte [edx]    ; 找 cl
00420EA4  75 F0           jne 00420E96
00420EA6  42              inc edx
00420EA7  3A 02           cmp al, byte [edx]    ; 在**同组内**找 al
00420EA9  74 09           je  00420EB4          ; 找到 ⇒ eax=1
00420EAB  80 3A FF        cmp byte [edx], 0FFh
00420EAE  75 F6           jne 00420EA6          ; 组内继续
00420EB0  33 C0           xor eax, eax          ; 未找到 ⇒ 0
00420EB2  EB 03           jmp 00420EB7
00420EB4  33 C0           xor eax, eax
00420EB6  40              inc eax               ; ⇒ 1
00420EB7  5D              pop ebp
```

> **⚠ 反汇编陷阱（已记录）**：直接以"表地址常量出现处"为起点反汇编会把常量 `41 C3 44 00`
> 误当指令（显示成 `inc ecx / ret / inc esp`）。必须**向上回溯到 `55 8B EC`** 才是函数真起点。
> `_查兵种适配表.py` 已实现该回溯（`--callers` / 3b 节）。

### 3.3 调用点与入参来源

| 调用点 | `cl` 来源 | `al` 来源 | 上下文 |
|---|---|---|---|
| **`0x4079B3`** | `call 0x4202BB` ⇒ **`byte[ecx+0x17]`** | `call 0x40BF0C` ⇒ 由 **`byte[ecx+0x2B]`** 归一化 | 见 3.4 |
| **`0x428631`** | `[ebp-0x14]` | `[ebp-4]` | **物品记录判定链内**：先 `movzx eax, byte[ecx+0x11]`（类型）`cmp al,0x1A`，再 `cmp byte[ecx+0x14],3` |

**`0x4202BB`**（getter，3 条指令）：
```asm
004202BB  55              push ebp
004202BC  8B EC           mov ebp, esp
004202BE  0F B6 41 17     movzx eax, byte [ecx + 17h]
004202C2  5D              pop ebp
004202C3  C3              ret
```

**`0x40BF0C`**（档位归一化；`0x40BF2F` 即本库已定案的"叠加方式解释器"，二者同族相邻）：
```asm
0040BF10  0F B6 41 2B     movzx eax, byte [ecx + 2Bh]
0040BF15  3C 3B           cmp al, 3Bh
0040BF17  77 09           ja  0040BF22
0040BF19  B9 03 00 00 00  mov ecx, 3
0040BF1E  F7 F9           idiv ecx                 ; al <= 0x3B ⇒ al/3
0040BF22  3C 50           cmp al, 50h
0040BF24  73 04           jae 0040BF2A
0040BF26  2C 28           sub al, 28h              ; 0x3C..0x4F ⇒ al-0x28
0040BF2A  B0 28           mov al, 28h              ; >=0x50 ⇒ 0x28
```

### 3.4 调用者 `0x407961` 的判定链（"能否装备"）

```asm
00407961  55              push ebp
00407964  51              push ecx
0040796A  0F B6 4D 08     movzx ecx, byte [ebp+8]   ; 入参 = 1 个字节
0040796E  80 F9 FF        cmp cl, 0FFh
00407973  40              inc eax                   ; cl==FF ⇒ 返回 1
00407976  E8 47 BE 07 00  call 004837C2
0040797E  E8 C1 3A 00 00  call 0040B444             ; 返回 al（分类）
00407983  3C 03           cmp al, 3  ⇒ eax=0
0040798B  3C 02           cmp al, 2  ⇒ 另一分支（call 004202BB / 0041B782 / 00430369）
004079AD  8B 55 F0        mov edx, [ebp-10h]
004079B0  8B 4D F8        mov ecx, [ebp-8]
004079B3  E8 CB 94 01 00  call 00420E83             ; ★ 查兵种组
```
⇒ **`al` 由 `0040BF0C` 留下（`mov edx,…`/`mov ecx,…` 不改 eax）**，`cl` 由 `004202BB` 的返回值给出。

## 四、实现·使用方法

```bash
python 大鲸鱼产生专用\_查兵种适配表.py                     # 解析表 + 搜同类表 + 找引用 + 干净反汇编 + 调用者
python 大鲸鱼产生专用\_查兵种适配表.py --no-xref            # 只要前两项（快）
python 大鲸鱼产生专用\_查兵种适配表.py --callers            # 额外打印调用者完整上下文
python 大鲸鱼产生专用\_查兵种适配表.py --disasm 0x407961,120  # 任意地址反汇编
```
输出同时写 `大鲸鱼产生专用\_兵种适配表.md`。

**改表方法**（若要调整"辅助装备可装备兵种"）：
- 直接改 `0x44C341` 起的字节：`FF` 开头、组内写兵种号、`FF` 分隔、`FF` 结尾；
- **必须保留收尾 `FF`**，且**总长度不得超过原表占用的空间**（本样本表后是 `90` 填充到 `0x44C378`）
  ⇒ 可用空间 **22 + 填充** 字节；**超长会覆盖下一函数**。
- 写 `Ekd5.exe` **必须**走 `大鲸鱼产生专用\_dsh写锁.py` 的 `safe_write_exe()`（AGENTS.md §3.5）。

## 五、风险与边界

- **⚠ 与推导表旧注冲突**：`【6.6山贼】物品记录地址推导.xlsx` 把 `物品记录 +0x14` 标为
  **"旧 6.5 图标遗留位（写入时保留原值）"**，但 `0x428625` 处 `cmp byte[ecx+0x14], 3`
  **真实参与判定** ⇒ **`+0x14` 有语义**。**当前处置：仍按"保留原值"写入**（未定语义前不动它），
  并登记为待验证项。
- **`cl` 的确切来源（`[ecx+0x17]`）取决于 `ecx` 指向什么结构**：本页只确认"取值位置"，
  未确认 `ecx` 是"部队/人物记录"还是别的结构。
- **本表是"辅助装备"口径**（用户资料标题），**是否也约束普通武器/防具未知**。
- 未做**游戏内行为验证**（未在 x32dbg 里命中 `0x420E83`）⇒ 结论级别为**静态反汇编 + 数据实测**，
  非"实机命中"。

## ★ 2026-10-22 静态补注（B4）：兵种适配判定 `0x420E83` 的完整顺序（逐字节）

> 样本 SHA256 `8736F795E0B69AECE11229B6A1468E42B87D0B753A72B61560BBA9D41F3AA06B`（现读）。未实机。

### 判定顺序（`0x420E83`，ECX=装备方兵种? AL=被适配兵种? CL=目标兵种）
1. `cmp cl,0xFF / je 允许` ⇒ 0xFF 通配直接允许（返回 1）。
2. `cmp cl,al / je 允许` ⇒ 同值直接允许（返回 1）。
3. `mov edx,0x44C341`；`jmp` 后先 `inc edx` 直到第一个 `0xFF` ⇒ **跳过表的第 1 段**（首段是表头/保留组，不参与配对）。
4. 之后循环：`cmp byte [edx],0xFF / je 拒绝(0)` ⇒ `FF` 是组/表终止符；
   `cmp cl,[edx] / jne 继续` ⇒ 命中左值后 `inc edx`，`cmp al,[edx] / je 允许`，否则继续到下一个 `0xFF`。
5. 走到终止 `FF` 仍未配对 ⇒ 返回 0。

### 表形态（`0x44C341` 现读）
`FF 01 0B 0C 1D 1F FF 09 0B 0C 1F FF ...` ⇒ 以 `FF` 分隔的“同组可互相适配”配对段；首字节 `FF` 立即结束第 1 段（即第 1 段为空）。

### 判据
- 反汇编逐条：两处“直接允许”（`0xFF`、同值），一处“跳过首段”，一处“逐组配对 + FF 终止”。
- 仍模糊：`CL`/`AL` 各自到底是“兵种号”还是“装备类型”，需结合 `0x420E83` 调用者（待补）。
