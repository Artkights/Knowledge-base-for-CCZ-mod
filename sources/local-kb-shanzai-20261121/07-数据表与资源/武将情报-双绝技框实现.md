## 已确认事实

### 1. ★ 说明框（343）的完整链路

```
166「武将情报」按钮控件 1450（显示当前角色第一特性名）
  → WM_COMMAND：0x4793A4  cmp eax, 0x5AA (1450)
  → 0x4793AE  call 0x4793BB            ← 按钮处理
  → 0x4793DA  push 0x157 (343)
  → 0x4793DF  call 0x46D098            ← CreateDialogParamA(hInst,343,hWnd,0x46D0F8,0)

343 的对话过程 0x46D0F8（DlgProc）：
  0x46D15E  push [ebp+8]               ← hDlg
  0x46D161  call 0x4C0600              ← 读一个特性 → 填 2051/2052
  ★ 0x4C0600 全局仅此 1 个调用点
```

### 2. ★★ 数据模型（最关键，踩了很多坑才定下来）

`Amsg.e5` 每条 **200 字节**；**一个「特性」占 2 条**（名字槽 + 描述槽）：

```
特性 s 的名字 = (2s+1)*200      特性 s 的描述 = (2s+2)*200
```

| 概念 | 槽位 | 谁读 |
|---|---|---|
| 角色 N 的**第一特技** | 特性 **N** | 游戏原生（`0x4C0600`）；**166 的按钮 1450 也读这里** |
| 角色 N 的**第二特技** | 特性 **N+800** | 本补丁（hook `0x4C0617` → 洞）|

★ **为什么第二格是 N+800 而不是 2N/2N+1**：
- 试过「角色 N → 特性 2N / 2N+1」并把第一栏改成读 2N → **按钮 1450 与第一栏对不上**
  （按钮读特性 N，第一栏读特性 2N）→ 用户直接指出"偏移没迁移对"。
- 也试过改 `0x4C0600` 的 `shl eax,1`→`shl eax,2` 来整体平移 → 当时 Amsg 只有 1024 槽，
  编号大时越界 → **界面空白 + 闪退**。
- **结论：第一格必须保持「特性 N」（与按钮同源），第二格用 N+800 才能两者一致。**

### 3. ★ 可寻址范围与扩容

- `0x4C0600` 里索引来自 `0x40BE7D([0x500E28])`：
  `编号 = ([0x500E28] - [0x4CEA00]) / 0x48`（**32 位**，不是单字节！）
- `CczEditor-66sz.config`：`Game_Unit_Count = 800` → 800 个角色（0~799）
- 800 人 × 2 格 = 1600 特性 → 需 `(2*1599+2)*200 = 640000` 字节
- **实测 Amsg 原为 409800 字节（仅 1024 特性）→ 必须扩容**，现为 **800000 字节**

### 4. ★ 字号 / 行距：**本引擎不可调**

- IAT 里有 `CreateFontA`/`SendMessageA`/`SendDlgItemMessageA`，但**全 exe 零调用点**（游戏不用它们）
- 试过：`CreateFontA` + `WM_SETFONT`（字体句柄创建成功，`va_FONT` 非 0，但**控件字形不变**）
- 试过：改模板 `pointsize 9→12`（**只影响 DLU 换算 → 框变大，字体不变**）
- 试过：`weight 0→400`、`charset 0→0x86` → 仍无变化
- **结论：该引擎的对话框字体不受模板字段与 WM_SETFONT 影响，字号/行距不可调。**
  最终已**撤除无效的字体补丁代码**，Ekd5.exe 只保留双格逻辑（洞内字体调用 0 个）。
  （已恢复模板原值 9pt / weight 0 / charset 0）

## 风险与边界

- **不要改 `0x4C0600` 的索引逻辑**（`shl eax,1`）：它同时也是按钮 1450 的数据源语义基准，
  改了会导致按钮与说明框不一致；且旧版 Amsg 不够大时会越界闪退。
- **不要扩 `.rsrc` 段尺寸**（文件变大 → Windows 拒载"不是有效的应用程序"）；
  343 之所以能加高，是因为新模板正好塞进段尾余量。
- **不要在 343 的 DlgProc 里自己读文件**（v1~v3 三次闪退）；本方案是在游戏自己的
  文件读取函数 `0x4C0600` **内部**做的（同一上下文它有 File IO）。
- **`cmp` 立即数必须用 imm32**：`83 3D <a> C8` 会把 `0xC8` 符号扩展成 `-56`，
  使无符号 `jb` **恒成立**、永远跳过填充（曾导致第二栏空白）。
- 字号/行距**不可调**（见上），不要在这上面继续投入。

**★ 新增坑（花钱换来的）：向引擎发 `WM_COMMAND(2060)` 会崩**

```
00482715  55        push ebp
00482716  8B EC     mov ebp,esp
00482718  0F B7 01  movzx eax,word ptr [ecx]      ← 崩在这（异常 c0000005 / c000041d，RVA 0x82718）
0048271B  80 E4 0F  and ah,0xF
0048271E  5D        pop ebp
0048271F  C3        ret
```
`0x482715` 是成员函数，`ecx` 由 thunk `0x482720` 的 `mov ecx,[ebp+0x10]`（第二参数）传入；
引擎的 166 命令分发表**不认识 DLL 运行时新建的 2060** ⇒ this 变成垃圾 ⇒ 解引用即崩。
**结论：2060 / 任何 DLL 自建控件只能用物理点击（`_ccz公共.safe_click` 点矩形中心），禁止 `PostMessage/SendMessage` 发 WM_COMMAND。**
`_验收166双绝技框.py` 对 2060 走 WM_COMMAND，**不适用**，跑它会崩。

**坑：166 有 17 个 `id=65535`** ⇒ 不能按 id 定位 Static，只能按 `对话框模板.json` 的 `controls` **索引**；
脚本里已加 `expect_idx` 自检（22→65535、32→1382、37→1387、14→1021、11→1018 …），索引一错就 assert 失败。
