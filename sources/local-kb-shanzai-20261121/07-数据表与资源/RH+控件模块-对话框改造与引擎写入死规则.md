## 结论速览（可直接照抄的死规则）

1. **改 `.rsrc` 尺寸时，五个字段一律按「实际数据尾」反算**，不许用「旧值 + grow」：
   段 `Misc_VirtualSize` / 段 `SizeOfRawData` / `SizeOfImage` / `SizeOfInitializedData` /
   **资源数据目录 `IMAGE_DIRECTORY_ENTRY_RESOURCE.Size`**。
   ★ 最常见死法：漏改**资源目录 Size** ⇒ 它只覆盖到旧数据尾，而新模板 RVA 已越界
   （179 实测：Size 只到 `0x146E04`，DataEntry 已指向 `0x147000`）⇒ 打开那个界面就闪退。
2. **从代码洞调用 `0x4862D8`（SetDlgItemTextA 指针）前，必须复刻原调用点的 `EAX`/`ECX`。**
   不复刻 ⇒ 游戏解析出错误的窗口/控件，在 `WM_SETTEXT` 回调里 AV
   （事件日志：`COMCTL32.dll` + `0xc000041d`「用户回调内异常」）。
3. **`E8` 进洞 ⇒ 栈顶多一个返回地址**：洞入口 `pop` 取走，原调用做完 `push` 放回，最后 `ret`。
   漏掉这一步 ⇒ 参数整体错位，`ret` 会跳到控件 ID（如 `0x579`）⇒ 必崩。
4. **DIALOGEX（167）追加控件项前，必须补 4 个零字节**（原模板 732 + 4 = 736 才合法）。
   逐偏移实测：728/730/732/735 全部失败，只有 736 能建成对话框。
5. **模板改动一律先过「Windows 亲自解析」这道闸门**：
   `CreateDialogIndirectParamW` 建 dialog + `GetDlgItem(新ID)` 非 0，才算模板合法。
   （离线，不花用户一次重启。）
6. **本位行文字另写控件时，格式串不能用基底的 `"\n%s+%u"`**（那是接在已有文字后面换行用的）；
   必须换成 `"%s+%u"`，否则首字符是换行、第二行被 8 DU 高控件裁掉 ⇒ 看起来是「空白」。
7. **RH（Resource Hacker）5.1.8 命令行没有 `-action opensave`**（报 `Error: invalid action`）。
   `_新建绝技框.py` 里「RH 重建资源段」那步**从未生效**，一直走的是「RH 没产出 → 写自建版本」兜底
   ⇒ **343 双绝技框的成功不是 RH 的功劳**，是「新模板正好塞进段尾余量、PE 头零改动」。
8. **控件 ID 与自定义类（atom 130）不是崩因**：343 新增 `2053/2054`、179 新增 `1460–1462`
   实机都能画（179 资源版能显示 3 行 `E2`）。崩因永远先怀疑「PE 字段 / 调用约定 / 模板结构」。

## 正确流程（对话框改造 + 洞内写控件）

### A. 只改坐标/尺寸（等长，最安全）
1. 定位控件：**优先按「ID + 现有矩形」在数据块里搜**，别按 MS 规范推头部
   （167 是 DIALOGEX，字体串后控件起点比规范多 4 字节）。
2. 前像断言 → 改写 4 个 `short` → 反查回读 → 写盘（不改 PE 字段）。
3. 脚本：`_改167效果框.py` / `_改167版面.py`。

### B. 新增控件（会加长模板 ⇒ 必须扩资源）
1. 复原要保留的控件矩形；`cdit + 1`（EX 在 header+16）。
2. **项前补 4 个零字节**（DIALOGEX）→ 追控件项（`exStyle/style/x,y,cx,cy/id/class/title/cctldata`）。
3. 模板追加到文件尾（按 `FileAlignment` 对齐）→ 改 DataEntry → **五个 PE 字段按数据尾反算**。
4. **离线闸门**：`CreateDialogIndirectParamW` + `GetDlgItem(新ID)`。
5. 脚本：`_改179装备页B.py`（经典模板 + 扩段）、`_改167加E2.py`（EX + 4 字节 + 离线闸门）。

### C. 洞内写控件文字（引擎层）
1. 先找到**游戏自己写同组控件**的那条调用（例：167 的 `0x40B328`、179 的 `0x476FCB`）；
   参数来源就是它上游 push 的东西（167 用 `[ebp+0xc]` = 物品编号）。
2. 取 6 字节 `FF 15 <ptr>` → 换成 `E8 cave` + `90`。
3. 洞体骨架（照抄顺序，不能省）：
   ```
   mov [g_ecx],ecx / mov [g_eax],eax     ; 存原寄存器
   pop eax / mov [g_ret],eax             ; 取走 E8 的返回地址
   mov ecx,[g_ecx] / mov eax,[g_eax]     ; 装回
   call [0x4862D8]                       ; 原调用（文字照旧写原控件）
   ... 生成附加文字 → push 参数 → call [0x4862D8]（写新控件，EAX=新控件ID）
   push dword [g_ret] / ret
   ```
4. 复用基底拼串段：搬 `0x4D25A4..0x4D2605`（查 `0x4D0564` 表），**去掉它开头那次 `0x461FC8`**，
   两处格式串立即数换成本地副本（`"%s+%u"` / `" %s+%u"`）。
5. 脚本：`_改167附加属性写入.py`（167）、`_临时_生成179实现v13.py`（179）。

### D. 验证链条（缺一不可）
1. **写盘前**：前像逐段断言（`_应用补丁通用.py` 或脚本内断言）。
2. **模板层**：离线 `CreateDialogIndirectParamW`。
3. **不崩**：`python _样本时间线.py`（更新 SHA 闸门）→ `python 大鲸鱼专用\_自动读档进战场.py --go`。
4. **文字对不对**：读进程内存里的洞内 BUF（`_临时_读BUF.py` 可改成任意地址）。
5. **崩了怎么查**：`Get-WinEvent -LogName Application` 过滤 `Ekd5`，看 `出错模块` / `异常代码`
   （`0xc000041d` = 用户回调内异常 ⇒ 十有八九是 `WM_SETTEXT` 打到了错窗口）。
