# 兵种名表与兵种号字段（`0x48C570` 指针表 + 段 #0 `+0x11`）

> 样本：`Ekd5.exe` SHA256 `2A555B0B0D476CE1B10510406586A6F148513EDCA740BAF67CCBC422F06F0083`
> 工具：`大鲸鱼产生专用\_找兵种名表.py`、`_查兵种适配表.py`（输出 `_兵种号名字表.md`）

## 一、结论速览

1. **兵种名指针表在 `Ekd5.exe` 的 `file 0x8AF70`（VA `0x48C570`，节 `.text2`）**：
   **DWORD 指针数组，0-based 索引**，每项指向名字池里的一个 `00` 结尾 GBK 串。
2. **名字池在 `file 0x8B010`（VA `0x48C610`）起**，`00` 分隔、**变长**（君主/步兵 4 字节，骑马策士 8 字节）。
3. **共 40 项（兵种号 `0x00`~`0x27`）**：
   ```
   [00]君主 [01]步兵 [02]弓兵 [03]轻骑 [04]重骑 [05]弓骑 [06]侠客 [07]山贼
   [08]策士 [09]医生 [0A]道士 [0B]骑马策士 [0C]女兵 [0D]西凉骑 [0E]枪兵 [0F]水军
   [10]将军 [11]都督 [12]炮车 [13]大戟士 [14]驭兽 [15]皇 [16]虎卫 [17]锦帆
   [18]横江武射 [19]白马义从 [1A]修罗 [1B]上将 [1C]武绝 [1D]奇才 [1E]花枪将 [1F]王佐
   [20]骁骑 [21]青州精锐 [22]虎豹骑 [23]孤羿 [24]狙翎 [25]国士 [26]王 [27]陷阵
   ```
4. **与兵种适配表 `0x44C341` 的 12 个序号完全对上**（见第三节）。
   其中 **`0x06` → 侠客**，与用户截图里「适合兵种：侠客」**完全吻合** ✓
5. **武将/部队表的兵种号字段**：`Data.e5` 段 #0（`0x18C` 起，**32 字节/条**）的
   **`+0x11`** 就是兵种号；`0xFF` 为**特例**（刘备 = `FF`），与查表函数 `0x420E83` 的
   `cmp cl,0xFF ⇒ 直接放行` **相互印证** ✓

## 二、已确认事实

### 2.1 指针表（实测）

```
file 0x8AF70（VA 0x48C570）：
  10 C6 48 00 | 19 C6 48 00 | 22 C6 48 00 | 2B C6 48 00 | 34 C6 48 00 | 3D C6 48 00 | 46 C6 48 00 | 4F C6 48 00 …
  = 0x48C610 / 0x48C619 / 0x48C622 / 0x48C62B / 0x48C634 / 0x48C63D / 0x48C646 / 0x48C64F
    君主      步兵       弓兵       轻骑       重骑       弓骑       侠客       山贼
```
- 每项间隔 = 名字长度 + 1（`00`）⇒ **验证：君主(4)+1=5？实际 0x48C619-0x48C610 = 9** ⇒
  **每项占 9 字节**（名字区每项 9 字节：最多 4 汉字 + 填充），而**指针数组按 4 字节/项**。
  ⚠ 注意：**指针表项（4B）与名字池项（9B）步长不同**，不要混用（我曾误用 9 字节步长解析指针表而错位）。

### 2.2 名字池（`00` 分隔、变长，到"扩充内存不足…"文本为止）

- `file 0x8B010` 起 → `file 0x8B178` 结束（其后是 `扩充内存不足(%s)。…` 的提示文本 ⇒ **池的自然边界**）。
- 池内共 **40** 个兵种名（另见第四节：池里名字**每条 9 字节**，不足补 `00`）。

### 2.3 部队/武将表的兵种号（`Data.e5` 段 #0）

`Data.e5` 段 #0 = `0x18C` 起、**32768 字节 = 1024 × 32**，是**部队/单位表**：

```
记录 0 刘备  C1 F5 B1 B8 | 00×13 | FF 5B 5D 58 5C 5D C8 00 0A 00 01 00 FF FF FF
               名字(4)      填充(13)  ↑+0x11 = FF（特例）
记录 1 关羽  B9 D8 D3 F0 | 00×13 | 01 00 01 00 FF …
记录 2 张飞  D5 C5 B7 C9 | 00×13 | 02 00 02 00 FF …
记录 3 马超  C2 ED B3 AC | 00×13 | 03 00 03 00 FF …
记录 4 赵云  D5 D4 D4 C6 | 00×13 | 4F 02 04 00 FF …      ← +0x11 = 0x4F？
记录 6 马岱  C2 ED E1 B7 | 00×13 | 06 00 06 00 FF …
记录 7 严颜  D1 CF D1 D5 | 00×13 | 07 00 06 00 FF …
```

- **名字区 = 17 字节**（`+0x00`~`+0x10`），**`+0x11` = 兵种号** ✓
- `0xFF` = 特例（刘备）。⚠ **赵云记录 `+0x11 = 0x4F` 超出 40 项** ⇒ 说明段 #0 里
  **并非所有记录都是"部队"**（也可能是其它结构复用），或 `+0x11` 在部分记录里是别的字段。
  ⇒ **引用前建议先判 `+0x11 < 40`**。

|---|---|---|---|---|---|
| `01` | 步兵 | `09` | 医生 | `1D` | 奇才 |

## 四、实现·使用方法

### 4.1 读兵种名（建议实现，EXE 改版后仍可用）

```python
# 1) 解析节表拿到 .text2 的 (VA, file_offset) 映射，别硬编码
# 2) 指针表起点：file 0x8AF70（VA 0x48C570）
# 3) 逐 4 字节读 DWORD；只接受落在 .text2 区间内的指针；解码其指向的 GBK 串
def load_breed_names():
    d = open(EXE, "rb").read()
    va0, fo0 = sec_of(".text2")            # 本样本 = (0x48B000, 0x89A00)
    names, p = [], 0x8AF70
    while True:
        v = struct.unpack_from("<I", d, p)[0]
        if not (va0 <= v < va0 + 0x33000):  # .text2 vsize
            break
        nm = d[fo0 + (v - va0):][:12].split(b"\x00")[0].decode("gbk", "replace")
        if not nm:
            break
        names.append(nm); p += 4
        if len(names) > 200:
            break
    return names
```
- **护栏**：若 `names[0] != "君主"` 或长度不为 40，**降级为只显示编号**并提示"兵种名表已变化"。

### 4.2 命令行

```bash
python 大鲸鱼产生专用\_找兵种名表.py                  # 在 EXE 里搜兵种名并做成表检测（输出 _兵种名表定位.md）
python 大鲸鱼产生专用\_查兵种适配表.py                 # 兵种组表 + 调用者（输出 _兵种适配表.md）
```

## 五、风险与边界

- **指针表/名字池都在 `.text2` 的只读数据区** ⇒ 理论上可改，但**改名字会牵动指针表**（变长），
  **本工具只读不写**；若要改名，务必同步维护指针数组。
- **`file 0x8AF70` 是文件偏移** ⇒ 若 EXE 改版导致节表变化，**必须现读节表换算**（勿硬编码）。
- ⚠ **不要用 VA 直接当文件偏移**（本次踩坑：`_找兵种名表.py` 输出的是文件偏移，被误当 VA ⇒ dump 全落空）。
- 名字池的自然边界靠"扩充内存不足…"文本判定；**换 MOD 后该边界可能不同** ⇒ 用"指针必须落在 `.text2`"作主判据更稳。

## 七、待验证项

- **P2**：段 #0 里 `+0x11 ≥ 40` 的记录（如赵云 `0x4F`）到底是什么 —— 是否非部队记录、或该字段另有含义。
- **P2**：兵种名池里**每项是否真为 9 字节**（含填充）—— 本页按"指针表 4B/项 + 池内名字 00 分隔"处理；
  若存在 5 汉字以上的兵种名，需复核 9 字节假设。
- **P2**：`Data.e5` 段 #0 的其它字段（`+0x12`~`+0x1B`）语义。
