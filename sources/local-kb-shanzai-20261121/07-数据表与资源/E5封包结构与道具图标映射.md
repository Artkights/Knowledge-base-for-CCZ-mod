# E5 封包（Ls12）结构与道具图标映射

> 样本：`Ekd5.exe` SHA256 `C77A18BFA52CFF159AC11E59880ED0B3FBB481E5ADAE016DE67059330F07FD64`
> 工具：`大鲸鱼产生专用\_解析E5封包.py`、`_导出道具图标.py`、`_道具属性编辑.py`

## 一、结论速览

1. **E5 资源文件（`Data.e5` / `E5\Item.e5` …）是 `Ls12` 索引封包**：头 16 字节 = ASCII `Ls12` + 12 个空格；
   **目录从文件绝对偏移 `0x110` 开始，每项 12 字节、大端三字段**：
   `stored_length` / `decoded_length` / `payload_offset`（相对文件开头的负载偏移）。
2. **`stored != decoded` ⇒ 该条目 LS12 压缩**；本样本 `Data.e5` 10 项中 **0 项压缩**、
   `E5\Item.e5` 513 项中 2 项压缩 ⇒ **实测段基本是明文，可直接读**。
3. **`Data.e5` 的物品记录段 = 目录第 2 项（索引 1）**：`payload_offset 0x818C`、`stored 2600`
   ⇒ **2600 ÷ 25 = 104 条**，正是 **ID 0~103** ✓（与 `【6.6山贼】物品记录地址推导.xlsx` 完全一致）
4. **`E5\Item.e5` 的每个条目就是一个完整 BMP 文件**（负载以 `42 4D`="BM" 开头）：
   小图 **822 字节 = 54 + 16×16×3**、大图 **3126 字节 = 54 + 32×32×3**，
   目录里 **小/大交替成对**。
5. **★ 图标映射（实测定案）**：`物品记录 +0x0F 的 icon 字段 = N`
   ⇒ **小图(16×16) = 目录第 `2N` 项、大图(32×32) = 第 `2N+1` 项**（0-based）。
6. **`Star.e5` 不是 `Ls12`**（头部是裸 GBK 文本）⇒ 其物品记录**从文件偏移 0 开始**（无 16 字节头）。

## 二、适用版本

- 本页结论对应 **复刻版6.6山贼** 当前样本（SHA 见页首）。
- 格式层（`Ls12` 目录 / 每项 12 字节大端）来自**库内既有结论 + 外部镜像双向印证**，跨版本较稳：
  * `07-数据表与资源\人物形象-RS-形象指定器.md:195`
    「`Pmapobj.e5`、`Unit_atk.e5`、`Unit_mov.e5`、`Unit_spc.e5`、`E5\Face.e5` 头部均为 `Ls12`；
     真实图片目录从文件绝对偏移 `110` 开始，每张图索引 12 字节，大端读取」
  * `大鲸鱼产生专用\_外部源码\_云端快照\artkights__Knowledge-base-for-CCZ-mod\6.5\reference\file-formats.md`

### 3.3 ★ 图标映射定案（含反证）

- **候选映射**：
  - A：`icon N ⇒ 条目 2N−2 / 2N−1`
  - **B：`icon N ⇒ 条目 2N / 2N+1`  ← 实测成立**
- **定案过程**：
  1. 若按"道具 ID 直接套 CzzHelper 公式 `101 + ID×2`" ⇒ ID 0（铁剑）应指向**条目 #0**
     ⇒ 实测 `#0`/`#1` 是**全空白图** ⇒ **该路径被否定**（本 MOD 用 `+0x0F` 的 icon 字段）。
  2. 鹤羽扇（ID 23）`icon = 24` ⇒ B 映射指向条目 **#49** ⇒ 实测为**黑白羽毛扇** ✓（符合"鹤羽"）；
     A 映射指向 #47 ⇒ 红棕描金扇（亦为扇，无法区分）。
  3. 银剑（ID 1）`icon = 19` ⇒ B 映射 #38/#39 ⇒ 实测 **#39 = 蓝银剑** ✓（符合"银"）；铁剑（ID 0）
     `icon = 20` ⇒ B 映射 #41 = **黑白铁色剑** ✓ ⇒ **语义与外观自洽**。
- **旁证（CzzHelper 源码）**：`ai使用库\CzzHelper及源码\CczHelper\ItemIconID.cpp`
  ```cpp
  UINT CItemIconID::GetItemIconID(int nItemIdx){
      if(nItemIdx==0xFF) return 0;
      if(m_pItemData->HasLoadFile()) return m_pItemData->Find(nItemIdx, ID_COL, ICON_COL);
      if(nItemIdx>100) nItemIdx-=25;
      return 101 + nItemIdx*2;        // 资源号 101 起、步长 2 ⇒ 每道具 小图+大图
  }
  ```
  `res\ItemIconID_Normal.csv` 亦为 `101→ItemID 0`、`103→1`、`105→2`…
  ⇒ **"资源号 101 = 目录条目 #0"、步长 2 与 B 映射一致**；本 MOD 的 `nItemIdx` 取 `+0x0F` 字段。

### 3.4 ★ `ItemData` 结构（CzzHelper `StructFromCcz.h:269`，6.5 布局）

```cpp
struct ItemData {
    char szName[17];   BYTE byType;    BYTE byPrice;   // byPrice 0xFF = 不出售
    BYTE byIcon;       BYTE bySpEffect; BYTE byLvOne; BYTE bySpValue; BYTE byLvInc;
    bool bIsSpItem;    // 01:yes
};   // 17 + 8 = 25 字节
```

**6.5 → 6.6 布局对照（本样本实测）**：

| 6.6 偏移 | 6.6 字段 | 对应 6.5 字段 |
|---|---|---|
| `+0x00..0x0E` | 名称（15B GBK） | `szName[17]`（**6.6 缩为 15**） |
| `+0x0F` | **图标** | `byIcon`（**在 6.5 里排第 4**） |
| `+0x10` | 保留 / 次要标志（待定） | —— |
| `+0x11` | **类型** | `byType` |
| `+0x12` | **特效号**（0xFF=无） | `bySpEffect` |
| `+0x13` | **价格 ×100** | `byPrice` |
| `+0x14` | 旧 6.5 图标遗留 | —— |
| `+0x15` | **初始能力** | `byLvOne` |
| `+0x16` | **特效值** | `bySpValue` |
| `+0x17` | **成长值** | `byLvInc` |
| `+0x18` | **宝物图鉴（01 显示）** | **`bIsSpItem`（01:yes）** ← 语义确认 |

⇒ **6.6 把 `szName` 从 17 缩到 15 腾出 2 字节，并重排了字段顺序**；
这也印证外部镜像 `file-formats.md` 的 `format.item.split-data-star`：
「6.5 名称区 `0x11` 字节；**6.6 名称区 `0x0F` 字节，后续字段位置相应不同**」。

## 2026-10-16 ★★ 追加：物品记录字段值分布（`+0x10`/`+0x14`/`+0x18` 定性）

对 256 条物品记录（Data.e5 ID 0–103 + Star.e5 ID 104–255）逐字段统计（工具：临时统计脚本，结论已并入本页）。

### 一、`+0x18` = 宝物图鉴标志（**已独立验证**）

```
取值仅 3 种：00×127 条 / 01×128 条 / 02×1 条
```
- **`01` 恰好 128 条** ←→ 用户截图的道具编辑器左下角显示「**宝物图鉴数为 128**」 ⇒ **两路吻合** ✓✓✓

- ⚠ 存在 **1 条异常值 `02`** ⇒ 待查（可能是特殊条目或数据瑕疵）。

### 二、`+0x10` = 爆炸/特殊使用方式参数（**不是"不消耗"**）

```
取值 7 种：00×236 / 01×8 / 02×6 / 0A×1 / 0D×1 / 11×3 / 1D×1   ⇒ 非 0 共 20 条
```
**非 0 的 20 条全部是爆炸类道具**：

| 土雷/石雷/铁雷/风火雷/彻地雷/轰天雷 **（引）** | `01` | 与推导表「雷道具段 0/1/2 ⇒ (普)/(引)/(控)」**吻合** |
| 同上 **（控）** | `02` | 同上 |
| 鞭炮 / 新年大鞭炮 | `11` | |
| 爆破筒 | `0D` | |
| 炸药包 | `1D` | |
| 核弹 | `0A` | |
| E2热兵 / e4 | `01` | |

⇒ **`+0x10` 是"特殊使用方式/爆炸参数"**（推测为爆炸半径或表现类型），
**不是布尔 flag** ⇒ **可排除它是「不消耗」**。

### 三、`+0x14` 是多值字段（**不是布尔**）

```
取值 164 种（00×48 条起）⇒ 绝非凡布尔标志
```
