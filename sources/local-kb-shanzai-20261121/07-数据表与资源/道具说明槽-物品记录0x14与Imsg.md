# 道具说明（`Imsg.e5`）—— 文件层规则 + 引擎侧反汇编

> 样本：`Ekd5.exe` SHA256 `2A555B0B0D476CE1B10510406586A6F148513EDCA740BAF67CCBC422F06F0083`
> 工具：`大鲸鱼产生专用\_解析Imsg道具说明.py`、`_道具属性编辑.py`（`load_item_desc`）
> 用户口径 2026-10-16：**「一个道具说明是 200 字符，按 ID 顺序从 0 铁剑开始」**

## 一、结论速览

### 1.1 ★ 文件层规则（实测 **100% 命中**）

```
一个道具的说明 = 200 字节，从 ID 0（铁剑）开始顺排：
   说明槽号 = 道具 ID + 68
   文件偏移 = 375600 + (道具 ID + 68) × 200        （375600 = 0x5BB30）
   说明文本 = 该 200 字节内首个 \x00 之前的 GBK 串；空 = 该道具未写说明
```
**全表 256 条：191 条非空**；锚点全中（见 1.2）。

### 1.2 锚点核对（用户提供的实测）

| 道具 | ID | 说明槽 | 偏移 | 内容 | 来源 |

### 1.3 ★ 引擎侧反汇编（"取道具说明"）

```asm
; ── 入口 0x40BFBD（调用者传入"道具 ID"）
0040BFC0  8B 45 0C        mov  eax, [ebp+0Ch]      ; 入参 = 道具 ID
0040BFC3  3C 50           cmp  al, 50h             ; ID >= 80 ⇒ 不取（走别处）
0040BFC5  73 0E           jae  0040BFD5
0040BFC7  05 5E 01 00 00  add  eax, 15Eh           ; ★ 内存索引 = ID + 350
0040BFCC  50              push eax
0040BFCD  FF 75 08        push [ebp+8]             ; 目标缓冲
0040BFD0  E8 81 FF FF FF  call 0040BF56

; ── 真正的取说明 0x40BF56
0040BF59  68 C8 00 00 00  push 0C8h                ; ★ 长度 200（与"一个道具说明 200 字符"一致）
0040BF5E  FF 75 08        push [ebp+8]
0040BF61  8B 4D 0C        mov  ecx, [ebp+0Ch]      ; 索引
0040BF64  69 C9 C8 00 00 00  imul ecx, ecx, 0C8h    ; ★ 索引 × 200
0040BF6A  51              push ecx
0040BF6B  B9 BC E4 4A 00  mov  ecx, 4AE4BCh        ; ★ 说明存储（全局对象）
0040BF70  E8 0F D2 00 00  call 00419184           ; 拷贝 200 字节
0040BF75  8B 55 08        mov  edx, [ebp+8]
0040BF78  C6 82 C8 00 00 00 00  mov byte [edx+0C8h], 0   ; 末尾补 \0
```
- **`0x40BF56` 共 10 处调用者**（前 4 个同在 `0x40BFxx` 家族：`0x40BFD0/0x40BFF7/0x40C027/0x40C0E7`，
  另有 `0x4143AE / 0x4190AA / 0x419230 / 0x425AA2` 等）。
- **内存索引 = ID + 350**，与**文件层槽号 = ID + 68** 不同 ⇒ **加载时发生过重排/选择性拷贝**。
  ⇒ **结论：写文件用"文件层规则"；理解引擎行为用"内存层规则"**，两者别混。

## 二、★ 纠正我此前的两个错误结论

| 项 | 我的错误 | 更正 |
|---|---|---|
| **① 拿 UE 行首算整除** | 见 `(0x5FA70−375600)/200 = 1964.08` 不整除 ⇒ 断言"定长 200 结构不成立、说明是变长排列" | 用户给的 `0x5FA70` 是 **UE 行首**，文本实际从 **`0x5FA78`** 开始（= `375600+81×200` **整除**）⇒ **定长 200 成立** |
| **② 用物品记录第 20 字节当说明索引** | 断言"记录里的 `+0x14` 字段 = 说明槽号"（因 ID14 该字段 = 82 = 槽 82 巧合一致） | **不成立**：ID0 该字段 = 27，而铁剑的说明槽是 **68**。该字段是**旧 6.5 图标遗留编号**（推导表原注是对的）。**说明索引只由「ID + 68」决定** |
| ③ （更早）把槽里「帅吗宝贝」判成"混入台词" | 加过"内容不像道具说明"的警示 | 用户：**那也是说明，作者故意这样写** ⇒ 已删除警示 |

## 三、实现·使用方法

```python
IMSG_ITEM_BASE, IMSG_ITEM_STRIDE, IMSG_ITEM_ID_OFFSET = 375600, 200, 68

def item_desc(item_id):
    off = IMSG_ITEM_BASE + (int(item_id) + IMSG_ITEM_ID_OFFSET) * IMSG_ITEM_STRIDE
    d = open(os.path.join(ROOT, "Imsg.e5"), "rb").read()
    raw = d[off:off + IMSG_ITEM_STRIDE].split(b"\x00")[0]
    t = raw.decode("gbk", "replace")
    return (t if t.strip() else None), off
```

- 已接入 `_道具属性编辑.py`：Tab1 下方「道具说明」区显示
  **`ID 顺序 N（= 道具 ID） ／ 说明槽 N+68 ／ Imsg.e5 偏移 0xX`** + 说明正文（**不出现 `0x14` 写法**）。
- 全解析工具：`python 大鲸鱼产生专用\_解析Imsg道具说明.py [--around 0x5FA78] [--scan A B] [--max N]`。

## 五、★★ `Imsg.e5` 的「内存布局 vs 文件布局」（2026-10-16 第 10 轮，goal ③）

### 5.1 结论速览

1. **`0x4AE4BC` 是「说明存储的全局对象地址」** —— 全 EXE **仅 4 处引用，且全是 `mov ecx, 0x4AE4BC`**（`B9 imm32`）：
   `0x401DE8 / 0x40BF6B / 0x418BB1 / 0x42BE89`
   ⇒ 它**不是指针变量**（与 `0x4CEA00` 那种 `add ecx,[0x4CEA00]` **结构不同**）。
2. **`86000`（特技说明 BASE）与 `375600`（道具说明 BASE）在 EXE 里硬编码 0 次** ✓
   ⇒ **引擎不区分 `Imsg.e5` 的"区"** —— 那两个数只是**文件内偏移**，`槽 430 / 1878` 也只是**推算值**。
3. **引擎按"逻辑索引 × 200"读说明**：
   ```asm
   ; 0x40BFBD（取说明入口）
   mov  eax, [ebp+0Ch]      ; 道具 ID
   cmp  al, 50h             ; ID ≥ 80 ⇒ 走别处
   add  eax, 15Eh           ; ★ 索引 = ID + 350
   call 0040BF56            ; → [0x4AE4BC] + 索引×200，取 200 字节
   ```
4. **★ 两套编号不一致**：**引擎索引 = `ID + 350`**；**文件槽号 = `ID + 68`** ⇒ **相差 282 槽**
   ⇒ **内存布局与文件布局不同**（加载时重排过）⇒ **写文件用文件编号、理解引擎行为用内存编号**。

### 5.2 含义与实操建议

| 场景 | 用哪套编号 |
|---|---|
| **编辑 `Imsg.e5`（改说明文字）** | **文件编号**：`偏移 = 375600 + (ID + 68) × 200` ✓ |
| **理解引擎行为 / 下断点** | **内存编号**：`[0x4AE4BC] + (ID + 350) × 200` ✓ |
| **跨版本移植** | **两套都要重新实测**（重排规则未定案）|

> ⚠ **不要再把两套编号混用**（本页早先版本曾因此得出"槽区混用"的错误印象）。

### 5.3 待验证项

- **重排规则**：为什么文件 `ID+68` 到内存变成 `ID+350`（差 282）——
  是否"只拷贝非空槽"、"按区重排"、或"另有头部占用"。**建议**：在引擎加载完成后（需开游戏）对比
  文件与内存的对应关系；或继续静态分析 `0x4AE4BC` 的初始化点（**4 处引用之一应是初始化**）。
- **`0x40BFBD` 的 `ID ≥ 0x50` 分支**（走哪条路取说明）。
- `Imsg.e5` 各区（策略说明 / 特技说明 / 人物列传 / 道具说明 / 称号）在**内存中的对应位置**。
- `0x418BB1` / `0x42BE89` / `0x401DE8` 三处 `mov ecx,0x4AE4BC` 的用途（是否分别对应不同区）。

## 六、★★ `0x4AE4BC` 的四处引用与「加载 `IMSG.E5`」（2026-10-16 第 11 轮）

### 6.1 四处引用的确切用途（全部反汇编确认）

| 引用点 | 上下文 | 用途 |
|---|---|---|
| **`0x401DE6`** | `mov ecx,0x4AE4BC` → `call 0x4032B0` → `push 0x418BAD` → `call 0x4810F3` | **构造 + 注册回调**（`0x4810F3` 与武将表用的是**同一个注册函数**）|

### 6.2 ★★ `0x42BE89` —— 加载 `IMSG.E5`

```asm

0042BE83  68 68 BB 48 00   push 48BB68h          ; ★ 字符串 = "IMSG.E5"

0042BE8D  E8 CA D0 FE FF   call 00418F5C         ; ★ 把 .e5 加载进对象

0042BE97  E8 D1 29 01 00   call 0043E86D
```

**⇒ `0x48BB68` / `0x48BBA0` 正是 EXE 内那张「`.e5` 表名清单」里的
`IMSG.E5` / `U_SELECT.E5`**（见 `e5表名清单与加载器.md` §3.1）
⇒ **"先建表名索引"这个动作在本轮直接兑现了价值**（一眼认出地址对应的文件）✓

**⇒ 新增通用函数**：**`0x418F5C` = 把 `.e5` 加载进对象**（参数：`ecx`=对象，`push 文件名`，`push 0`）。

### 6.3 「差 282 槽」的成因方向

- 引擎索引 = **`ID + 350`**；文件槽号 = **`ID + 68`** ⇒ 差 **282 槽 = 56400 字节**；
- `IMSG.E5` 是**整体加载**进 `0x4AE4BC` 对象的（上面已证）⇒ **内存对象前段另有内容**，
  `IMSG` 的数据段接在其后 ⇒ **口径不同源于"对象内的偏移"vs"文件内偏移"**。
- **实操口径（重申）**：**写文件用文件编号**（`375600 + (ID+68)×200`）；
  **理解引擎/下断点用内存编号**（`[0x4AE4BC] + (ID+350)×200`）。

### 24.1 `0x40BAD4` 与 `0x0B` 标志数组（定案）

- **`0x40BAD4` = 除法助手**：`xor edx,edx; idiv [esp+4]; ret 4` ⇒ `eax /= arg`（此前误判为"查表定位器"）。
- **`0x40C6CC(P1, 符号)` 是 thiscall（ecx=剧本解释器 ctx）**：`eax=P1/8`（条目号）、edx=P1%8；目标字节 = **`[ctx+0x38 + P1/8]`**；掩码表 `0x41858F` = `7F BF DF EF F7 FB FD FE` = **大端位序**（P1%8=0 → bit7）：先 `and` 清 bit(7-P1%8)，再 `or` 置 `符号<<(7-P1%8)`（符号=-1 时 or 0xFF 全置）。
- ⇒ **`0x0B 变量赋值` 真身 = 剧本上下文 `ctx+0x38` 起的标志位数组置位**（每字节 8 标志、大端排位）——「一次性事件标志」的存储位置由此定案。

### 24.2 `0x423FE8` 与 S_85 变量 917（定案，与库内速查页互证）

- 独立反汇编与 `02-数据结构\异常状态-可复用函数与数据速查.md` §3 完全一致：`unit+0x1E` 1 字节状态窗口、4 个 2-bit 字段（存回合数）、`mask` 每轮 `shr 1` / 窗口每轮 `shr 2`、返回该字段状态级 0~3。
- 选择子口径（库内现行结论页）：`0x02麻痹 / 0x04禁咒 / 0x08混乱 / 0x10中毒`；`0x01` 永不命中。
- ⇒ **`0x7B P1=5` 续段的 `1<<bit` 机理定案**：`1<<bit` 恰好生成选择子——**bit=1麻痹 / 2禁咒 / 3混乱 / 4中毒 有效；bit=0（选择子 0x01）是永不命中的陷阱**；bit≥5 越出 4 窗口循环同样返回 0。

## 二十五、★★ 纠正：0x7B P1=5 参数格式（count/stride 曾弄反；作者注释终局印证）

- **纠正对象**：§24.2 末两条。原文「1<<bit 恰好生成选择子——bit=1麻痹…」与「S_85 变量 917 的语义 = 异常状态字段号」——**错**。
- **纠正依据（三方咬合）**：
  1. 反汇编复核 `0x42CC8E` 跳板 push 顺序（`push esp(out); push 2; push 4; push P2`）× cdecl ⇒ `0x42C6C5` 的 `[ebp+0xC]=4`=**循环 4 项**、`[ebp+0x10]=2`=**word 步长**——此前把 count/stride 弄反（误记"解析前 2 项、stride=4"）；
  2. 续段取数：`word[ebp-0xA]=buf[1]`=单位号、`byte[ebp-0xC]=buf[0]`=选择方式、`byte[ebp-8]=buf[2]`=移位用的位号；
  3. **作者亲写注释**（`RS\新特技系统.eex`，本轮全库普查发现）：`'1,5,1,1\n检测data5号，处于麻痹状态时'`——buf[1]=5=data5号 ✓、buf[2]=1→1<<1=0x02 麻痹 ✓。
