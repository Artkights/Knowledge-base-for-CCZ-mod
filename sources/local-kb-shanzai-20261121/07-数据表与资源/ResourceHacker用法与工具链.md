# Resource Hacker（RH）用法与工具链 —— 曹操传界面/对话框改造

> **为什么单开一页**：RH 是曹操传 MOD 界**改界面/对话框的第一工具**，
> 但它**直接写盘、绕过我们的写锁**（`Ekd5写入串行化规则.md` 明写"RH 写回不受保护"），
> 且我们已有**自研 `.rsrc` 直读**可以完全替代它的"读"功能。
> 建立日期：2026-10-15｜用户口径：RH 相关用法要单独整理一份。

## 结论速览

1. **安装位置**：`ai使用库\Resource Hacker v5.1.8 Build 360\ResourceHacker.exe`
   （另一份在 `[本地盘]\qq\qq群\ResourceHacker\`）。**PE 资源编辑器**，不是调试器。
2. **★★ 纪律：RH 直接写盘，不受 `_dsh写锁.py` 保护** ——
   人工在 RH 里点保存之前，**先跑 `_dsh写锁.py status`**，确认没有别的写入者。
3. **"读"不要用 RH**：自研 `_对话框资源解析.py` 直读 PE `.rsrc`（纯标准库、不依赖 GUI），
   与 RH 导出**逐控件互验 659/659 满分**（`对话框资源库-直读与对照图鉴.md`）。
4. **只有"保存改动"这一步才需要 RH**（或在 GUI 里改资源），
   写 `Ekd5.exe` 的**推荐路径仍是补丁文本 → `_dsh写锁.py`**。
5. **三个已有 RH 自动化脚本**：`_RH自动化.py`（探测 GUI 结构）、`_RH导航.py`（键盘导航资源树）、
   `_RH改166.py`（导航到 Dialog 166 → 打开编辑器 → 读/改 → 保存）。
6. **RH 的坑**：导出 rc 有**双 BOM**（解析前必须全清）；控件 ID 为 `-1` 对应 `0xFFFF`/`0xFFFFFFFF`。

## 一、RH 在我们链路里的位置

| 任务 | 用 RH？ | 该用什么 |
|---|---|---|
| 读 41 个对话框的标题/控件/坐标 | ❌ 不用 | `_对话框资源解析.py`（自研直读）/ `_对话框图鉴.py`（渲染对照图） |
| 与外部资料对账（如"166 武将情报"长什么样） | ✅ 可作**权威对照** | `_rh工作目录/rh对话框_UTF8.rc`（RH 导出，注意双 BOM） |
| **改对话框文字/控件** | ✅ 可用 | RH GUI（人工），或补丁文本走写锁 |
| 改 PE 资源以外的东西（代码、数据表） | ❌ 不要 | 反汇编工作台 + 写锁 |
| 批量/可复现的界面改造 | ❌ 不推荐 | 自带 `_RH改166.py` 只是 GUI 自动化，**不是可复现的补丁** |

## 二、三个 RH 自动化脚本（现状）

| 脚本 | 干什么 | 关键实现 |
|---|---|---|
| `_RH自动化.py` | 探测 RH 顶层窗口与子控件结构（为自动化做准备） | `EnumWindows` + 递归 `EnumChildWindows`，类名/标题用 GBK 解码 |
| `_RH导航.py` | 在资源树里移动 | RH 资源树是 `TTreeView`，**控件 id = `263538`**；支持 `→` 展开、字母键跳节点、回车打开 |
| `_RH改166.py` | 导航到 **Dialog 166** → 打开对话框编辑器 → 读/改 → 保存 | 树操作 + 鼠标消息（`MOUSEEVENTF_ABSOLUTE`）；**保存即写盘** |

> ⚠️ 这三个都是**GUI 自动化**：依赖窗口布局与控件 id，**换 RH 版本或换主题就会失效**；
> 而且它们**不产生可复读的补丁文本**，因此**不可审计**。能用补丁文本解决的就不要用它们。

## 三、RH 用法要点（人工操作）

1. **打开**：`ResourceHacker.exe` → 文件 → 打开 → 选 `Ekd5.exe`（**先备份！**）。
2. **找对话框**：左侧树 `Dialog` → 展开 → 选中目标 ID（如 `166`「武将情报」、`279`「行动菜单」、`343`）。
3. **看/改**：右侧显示 `DIALOG` 定义（`CONTROL "文字", id, CLASS, style, x, y, w, h`）；
   双击可开**可视化编辑器**拖控件。
4. **保存**：文件 → 保存（**这一步直接改写 `Ekd5.exe`**）。
   - 若游戏正在运行，保存会失败或产生不一致 → **先完全退出游戏**。
   - 保存前先 `_dsh写锁.py status`。
5. **命令行导出**（只读，安全）：
   ```
   ResourceHacker.exe -open Ekd5.exe -save dlg166.rc -action extract -mask DIALOG,166,
   ```
   （具体参数以 RH 5.1.8 帮助为准；我们历史上的导出产物在 `_rh工作目录\rh对话框_UTF8.rc`）

## 四、已知坑（都踩过）

| 坑 | 事实 | 处置 |
|---|---|---|
| **RH 写盘绕过写锁** | `Ekd5写入串行化规则.md`：本锁只保护走本模块的写入者 | 人工改前先 `_dsh写锁.py status`；改后跑 `_样本时间线.py` 现读 SHA |
| 导出 rc 有**双 BOM** | `对话框资源库-直读与对照图鉴.md:229` | 解析前**全清 BOM**，否则首个字段名带 `\ufeff` 失配 |
| 控件 ID 显示 `-1` | RH 把 `0xFFFF`/`0xFFFFFFFF` 显示成 `-1` | 比对时统一按 `-1` |
| **一次只能存一个文件名** | 同名二次保存会提示"无法备份" | 换名保存，或改完立刻用我们的写锁+补丁文本固化 |
| 资源扩容边界 | 加控件/加对话框可能超出 `.rsrc` 空间 | 见 `07-数据表与资源/Ekd5界面改造边界与PE资源扩容.md` |

## 五、推荐工作流（读 → 设计 → 写 → 验）

```
① 读   : _对话框资源解析.py show <id>        （自研直读，零依赖）
② 对照 : _对话框图鉴.py <id>                 （渲染成图 + Excel/SQLite，便于与实机截图比对）
③ 设计 : 写清"哪个控件、改成什么"（文字/坐标/新增控件）
④ 写   : 优先做**补丁文本** → _补丁体检.py → _dsh写锁.py safe_write_exe()
         （只有确实要动资源树结构时，才用 RH GUI，且先查锁）
⑤ 验   : _样本时间线.py 现读 SHA + 改动总账 _改动总账.py + 实机截图
```

## 风险与边界

- 本页不含 RH 的**源码**（RH 是闭源免费工具，Delphi 编写）；只有**用法与自动化脚本**。
- RH 版本差异：我们实测的是 **5.1.8 Build 360**；换版本后控件 id（如 `263538`）与菜单结构可能变。
- **绝不要**用 RH 同时改 `Ekd5.exe` 与我们的补丁流程 —— 两条写入路径并发会破坏 SHA 基线。
