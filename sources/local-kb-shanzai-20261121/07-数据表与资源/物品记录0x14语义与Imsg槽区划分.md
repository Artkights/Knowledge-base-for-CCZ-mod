> 工具：`大鲸鱼产生专用\_道具属性编辑.py`（`load_items` / `type_label`）、`_解析Imsg道具说明.py`

## 一、结论速览

1. **`Imsg.e5` 就是一条 200 字节槽序列**：`槽 n 的文件偏移 = 200 × n`，**共 4285 槽**（文件 857117 字节，尾部余 117）。
   **非空槽 2109 / 4285**，形成 **76 个连续非空区**，且**按内容分区**（见 §三）。
2. **`物品记录 +0x14` 是「三重角色」字段**（我早先"旧 6.5 图标遗留编号"的说法**不完整**）：
   - **① 类型 ≥ `0x1A` 时决定「类型名索引」**：`索引 = (+0x14) + 11`（`0x40B460`；设计上 `+0x14 ∈ 0..3`）；
   - **② `+0x14 == 3`（"特殊道具"标志）**：`0x423102` 与 `0x428625` 都以它分支
     —— `==3` ⇒ 特效查**另一张表**（`0x4CE000 + idx×9`）；`≠3` ⇒ 查**表 A**（`0x4CB7A0 + idx×16`）；
     且 `==3` 时**跳过兵种组检查**；
   - **③ 在 `0x40B444` 里作「装备大类」的返回值**（<0x14⇒0、0x14~0x19⇒1、≥0x1A⇒`+0x14`）。
3. **`+0x14 > 3` 的记录（≥0x1A 段有 100 条）不会越界** —— 因为它们只被用于"是否 `==3`"的判定；
   **只有"真正是辅助类"（`+0x14 ∈ 0..3`）时才拿去算类型名**。⇒ 我先前担心的"索引越界"是多余的。
4. **`< 0x1A` 段那条唯一的奇偶例外 = `ID107`，名字就叫「空置3」** ⇒ 作者自标的**占位记录**，
   奇偶与图鉴标志不一致属**预期**，不是异常。

## 七、风险与边界

- `+0x14` 是**多义字段**：引用它前必须**明确当前上下文**（是算类型名？判特殊道具？还是取辅助大类？）。

### 10.2 ★ 索引链条（三级函数）

```asm
; ① 0x40B444 —— 装备大类
类型 < 0x14        ⇒ 0      （武器）
0x14 ≤ 类型 < 0x1A ⇒ 1      （防具）
类型 ≥ 0x1A        ⇒ +0x14  （辅助，用 +0x14 细分）

; ② 0x40C45A —— "是否武器/防具"（大类 ≤ 1 ?）
0040C45D  E8 E2 EF FF FF  call 0x40B444
0040C464  83 F8 01        cmp  eax, 1
0040C467  0F 9E C1        setle cl        ; eax ≤ 1 ⇒ 1；否则 0

; ③ 0x40B4BD —— 求"效果索引"
call 0x40C45A
test eax, eax / je …
  非0（武器/防具）⇒ movzx eax, byte[ecx+0x14]   ; ★ 用 +0x14
  为0（辅助）      ⇒ movzx eax, byte[ecx+0x11]   ;   用 类型
sub eax, 0x1A                                    ; ★ 索引 = 值 − 0x1A
```
⇒ **武器/防具的"效果号"就是 `+0x14`**；辅助装备用**类型号**。

### 10.3 ★ 选表（`0x4230F9`）

```asm
cmp  byte[ecx+0x14], 3
  ≠3 ⇒ 索引×16 + 0x4CB7A0     ; 表 A =「特技/特效」（16B/条）
  ==3 ⇒ 索引×9  + 0x4CE000    ; ★ =「使用效果名表」（9B/条）
```
⇒ **`+0x14 == 3` = 「特殊道具」**：使用「使用效果」体系，并**跳过兵种组检查**（`0x428625` 印证）。

## 十一、★ 追加：`0x4CE000` 表上限 / 第 9 字节 / 全部读点归类（2026-10-16 三挖）

### 11.1 表有效上限 = **idx 0~57（共 58 条）**

```
[54] 50热兵器   [55] 51热兵器   [56] 52热兵器   [57] 53热兵器   ← 最后一条有效
[58] 00 41 75 74 6F 00 4C 6F 67   = "\0Auto\0Log"
[59] 6F 2E 41 76 69 00 00 00 BF   = "o.Avi"
[60~66] …Open.Avi / End.Avi / Press.Avi / Mov%03u.Avi
```
**⇒ `idx ≥ 58` 已越界**，其后紧跟的是**影片文件名 ASCII 串**（`Auto`/`Log`/`*.Avi`），
与效果表无关 ⇒ 读表时**必须夹 `idx ≤ 57`**。

### 11.2 第 9 字节 = **「效果参数」**

- 58 条中**只有 `idx 39「杀伤HP」` 的第 9 字节非 0**（= `0xBB`）；
- 原因是**名字长度**：其它条目名字较短、8 字节名字区被 `\0` 填充，第 9 字节自然为 0；
  **"杀伤HP" 用满 8 字节**（`杀伤`4 + `HP`2 + 2 填充）⇒ **额外参数落在第 9 字节**。
- ⇒ **记录结构 = 8 字节名字 + 1 字节参数**；**"杀伤HP"这类效果需要额外数值**，故用得上。
- ⚠ `0xBB = 187` 的确切语义（伤害系数？固定值？）**待验证**。

### 11.3 `0x4CE000` 的 4 个引用点（含两条**不同的索引路径**）

| `0x423116` | `索引 = 0x40B4BD(...)`（`+0x14` 或 类型号，`−0x1A`） | `+0x14 == 3` 时切到本表 |
| **`0x43A4B4`** | **`索引 = 参数 + 7`**（`add eax,7` → `imul 9`） | 另一条路径：**由参数直接定位条目** |
| **`0x4412C7`** | **`索引 = 类型号 − 0x1A`**，且**先看全局 `[0x500AD7] == 3`** | ⚠ **这里用的是 `+0x11`，不是 `+0x14`** |
