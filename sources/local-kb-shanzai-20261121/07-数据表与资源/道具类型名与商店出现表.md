# 道具类型名 与 商店出现表（`Ekd5.exe`）

> 样本：`Ekd5.exe` SHA256 `2A555B0B0D476CE1B10510406586A6F148513EDCA740BAF67CCBC422F06F0083`
> 工具：`大鲸鱼产生专用\_查类型与商店表.py`（xref + 上下文反汇编 + 指针表解引用）、
> `_道具属性编辑.py`（`load_type_names()` / `type_label()` / `eff_label()`）
> 用户口径 2026-10-16：①「道具类型、特殊效果，需要未点开时候也显示特效名称」
> ②「反汇编看看能不能找到装备类型」③ 提供 `0x482427` 商店表原值

## 一、结论速览

1. **道具类型名表**在 `.text2`：**指针表 `file 0x8A604`（VA `0x48BC04`）15 项** →
   名字池 `file 0x8AC74`（VA `0x48C274`）：
   ```
   [0]将剑 [1]长柄 [2]弓弩 [3]砍刀 [4]炮车 [5]枪戟 [6]斧锤 [7]扇
   [8]宝剑 [9]短刃 [10]铠甲 [11]游装 [12]袍服 [13]辅助 [14]道具
   ```
2. **★ 类型号 → 类型名索引的换算法在 `0x40B460`**（引擎原件，已反汇编核实）：
   ```
   类型(+0x11) < 0x1A  ⇒  索引 = 类型 >> 1          （sar，**奇数同样适用**）
   类型(+0x11) ≥ 0x1A  ⇒  索引 = (记录 +0x14) + 11   （+0x14 ∈ 0..3 → 游装/袍服/辅助/道具）
   ```
   - **`>>1` 不是"只对偶数"** —— `sar eax,1` 对 `3` 得 `1`（长柄），与引擎一致。
   - **`+0x14` 不是纯遗留字段**：**辅助/道具段（类型 ≥ 0x1A）靠它决定类型名**。
3. **实测锚点**（与游戏内「武将情报 → 属性」一致）：
   | ID | 名称 | 类型 raw | 类型名 | 游戏内 |
   |---:|---|---:|---|---|
   | 0 | 铁剑 | 0 | 将剑 | — |
   | 4 | 亮银枪 | 10 | 枪戟 | — |
   | 6 | 桦木弓 | 4 | 弓弩 | — |
   | **30** | **古今双绝** | **1** | **将剑** | **属性：将剑** ✓ |
   | 32 | 风雷双铁戟 | 19 | 短刃 | — |
   | 46 | 黄沙龙雀刀 | 3 | 长柄 | — |
4. **特效名**：表 A（`0x4CB600` 起，237 条）直接可用；实测 `99 → 同仇敌忾`（与 ID46 说明"效果二：同仇敌忾6次"吻合）、
   `110 → 剑荡山河`、`105 → 一骑当千`、`95 → 攻守兼备`；`255 = 无`。
5. **商店出现表**：**VA `0x482427`（file `0x81827`）**，每字节一组、步长 3：
   ```
   原始 13 组：00 03 06 09 0C 0F 12 | 15 18 1B | 39 3C 3F
               └武器加攻击 7 组──────┘ └加精神 3┘ └护具 3┘
   ```
   某组首字节改 `FF` ⇒ **该组不出现在商店**。（本样本实测已被改为 `00 03 06 09 FF FF FF 15 18 1B` ✓）

## 二、适用版本

- 对应上列样本 SHA。地址为**本样本实测**；换 MOD 后应重新 xref（§2.5 门禁）。
- ⚠ `0x482427` 是 **VA**（用户给的 `00482427` 形式）⇒ **文件偏移 = `file 0x81827`**（`.code`：VA `0x401000` ↔ file `0x400`）。
  **不要把它当 file offset 用**（`0x482427` 已超出文件大小 `0x118800`）。

## 三、已确认事实

### 3.1 `0x40B460` 反汇编（类型名索引换算，原件）

```asm
0040B460  55              push ebp
0040B461  8B EC           mov  ebp, esp
0040B463  0F B6 41 11     movzx eax, byte ptr [ecx + 0x11]   ; 类型号
0040B467  3C 1A           cmp  al, 1Ah
0040B469  73 04           jae  0040B46F
0040B46B  D1 F8           sar  eax, 1                        ; 类型 < 0x1A ⇒ >>1
0040B46D  EB 06           jmp  0040B475
0040B46F  8A 41 14        mov  al, byte ptr [ecx + 0x14]     ; 类型 ≥ 0x1A ⇒ 取 +0x14
0040B472  83 C0 0B        add  eax, 0Bh                      ;   + 11
0040B475  5D              pop  ebp
0040B476  C3              ret
```

### 3.2 调用点（唯一已确认的直接引用）

```asm
0040B2B7  8B 4D F4        mov  ecx, [ebp-0Ch]                ; 物品记录
0040B2BA  E8 A1 01 00 00  call 0040B460                      ; ★ 算索引
0040B2BF  FF 34 85 04 BC 48 00  push dword [eax*4 + 48BC04h]  ; ★ 类型名 = 指针表[索引]
0040B2C6  68 FF 03 00 00  push 3FFh                          ; 控件 id 1023「属性」？
```
> `推 [eax*4 + 0x48BC04]` 即"类型名指针表[索引]" ⇒ **索引 = `0x40B460` 的返回值**，链条闭合。

### 3.3 xref 汇总

| 表 | VA | 引用处（VA，取前几） |
|---|---|---|
| 类型名指针表 | `0x48BC04` | `0x40B2C2` / `0x46796D` / `0x477F7B` |
| 商店出现表 | `0x482427` | `0x4080C9` / `0x40CA27` / `0x472C27` / `0x477F38` |

### 3.4 商店出现表的语义（用户口径 + 字节核对）

- 表按**装备组**排列，**步长 3**（一组的 3 件装备共享一个"基准编号"）。
- **玩家军队平均等级**升到该组阈值 ⇒ 该组装备**依次出现在商店**。
- **把某组首字节改为 `FF`** ⇒ **该组不再出现**（用户已用此法屏蔽了武器 4/5/6）。
- ⚠ **具体阈值与"依次"的步进**尚未反汇编确认（见第五节）。

## 五、风险与边界

- **类型 ≥ 0x1A 分支**：`索引 = +0x14 + 11` 只对 `+0x14 ∈ 0..3` 落在表内；
  实测 ID181~192 等辅助/道具的 `+0x14 = 0` ⇒ 索引 11 =「游装」，**是否语义正确待验证**
  （直觉上辅助装备应为 `[13] 辅助`）⇒ 已在界面保留 raw 编号便于核对。
- **`FF` 屏蔽商店**属**功能副作用**：改的是引擎数据表，需走 `_dsh写锁.safe_write_exe()`（AGENTS.md §3.5）。
- 商店表的"阈值/顺序"未定案 ⇒ 不要据本页推断"某等级一定出某装备"。

## 八、★ 追加：类型号奇偶 = 「普通 / 宝物」（用户口径 2026-10-16）

### 8.1 规则与实测范围

- **用户口径**：**道具类型号偶数 ⇒ 前缀「普通」；奇数 ⇒ 前缀「宝物」**。
- **实测限定（重要）**：该规则**只在 `类型 < 0x1A` 段成立**：
  - `< 0x1A` 段：**108 / 109 条与图鉴标志 `+0x18` 一致** ✓（唯 1 条例外见 8.3）
  - `≥ 0x1A` 段（辅助/道具段）：**全表 67 条不符** ✗
    （例：ID111 深渊的爪皇 类型 `110` 偶数但 `+0x18 = 1`；ID113 噬月银狮盔 类型 `36` 偶数但 `+0x18 = 1`）
  ⇒ **`≥ 0x1A` 段的类型号是另一套编码，奇偶不表示稀有度**，界面**不加前缀**。

### 8.2 抽查（与 `+0x18` 图鉴、价格互相印证）

| ID | 名称 | 类型 | 前缀+类型名 | `+0x18` | 价格 | 判断 |
|---:|---|---:|---|---:|---:|---|
| 0 | 铁剑 | 0 | 普通 0 将剑 | 0 | 5 | 普通 ✓ |
| 4 | 亮银枪 | 10 | 普通 10 枪戟 | 0 | 10 | 普通 ✓ |
| 6 | 桦木弓 | 4 | 普通 4 弓弩 | 0 | 5 | 普通 ✓ |
| 12 | 素缨挽雪 | 11 | 宝物 11 枪戟 | 1 | 255 | 宝物 ✓ |
| 14 | 逐月追光 | 5 | 宝物 5 弓弩 | 1 | 255 | 宝物 ✓ |
| **30** | **古今双绝** | **1** | **宝物 1 将剑** | **1** | **255** | **宝物 ✓** |

## 九、★★★ 商店出现表的**完整机制**（2026-10-16 反汇编定案）

### 9.1 表的语义：**「装备组基准编号」表**

```
表[组索引] = 该组第一件装备的编号；一组 3 件 ⇒ 装备号 = 表值 + 0 / +1 / +2
组索引 = 装备类型(+0x11) >> 1        ← ★ 与"类型名换算"同一个 >>1
```

**实测对照**（原始 13 组 `00 03 06 09 0C 0F 12 | 15 18 1B | 39 3C 3F`）：

| 组索引 | 表值 | 覆盖的类型 `+0x11` | 含义（用户注释）|
|---:|---:|---|---|
| 0 | `0x00` | `0x00~0x01` | 武器1 加攻击（编号 0,1,2 = 剑类）|
| 1 | `0x03` | `0x02~0x03` | 武器2 加攻击 |
| 2 | `0x06` | `0x04~0x05` | 武器3 加攻击 |
| 3 | `0x09` | `0x06~0x07` | 武器4 加攻击 |
| 4 | `0x0C` | `0x08~0x09` | 武器5 加攻击 |
| 5 | `0x0F` | `0x0A~0x0B` | 武器6 加攻击 |
| 6 | `0x12` | `0x0C~0x0D` | 武器7 加攻击 |
| 7 | `0x15` | `0x0E~0x0F` | 武器1 加精神 |
| 8 | `0x18` | `0x10~0x11` | 武器2 加精神 |
| 9 | `0x1B` | `0x12~0x13` | 武器3 加攻击和精神 |
| **10** | **`0x39`** | **`0x14~0x15`** | **护具1 铠甲** |
| **11** | **`0x3C`** | **`0x16~0x17`** | **护具2 武将衣服** |
| **12** | **`0x3F`** | **`0x18~0x19`** | **护具3 文官衣服** |

> **★ 与用户注释逐条吻合**（`0x14>>1=10 ⇒ 0x39 护具1 铠甲`；`0x16>>1=11 ⇒ 0x3C`；`0x18>>1=12 ⇒ 0x3F`）✓

### 9.2 `FF` 为什么能屏蔽

**基准 = `0xFF`** ⇒ 后续按 `基准 + 序号` 生成的装备号**无效/溢出** ⇒ **该组不进商店** ✓
（本样本实测已被改为 `00 03 06 09 FF FF FF 15 18 1B …`，即屏蔽了武器 4/5/6 三组）

## 十二、★★★ 商店机制收尾：阵营/等级偏移 + **补位逻辑**（2026-10-16）

### 12.1 ★ 两个字段偏移（决定"谁能算进平均等级"）

