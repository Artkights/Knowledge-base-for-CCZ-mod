## 结论速览



1. **现行方案 = 路线 A**：第四组以 `LB_INSERTSTRING` **插到「附加技能：」组之后**

   （引擎在第 3 组之后预留了 10..24 一堆空白行，追加到末尾会隔很远）。

   实测刘备：`8 附加技能： / 9 "  --" / 10 装备附加特技： / 11 武器：真元流转 31 /

   12 护具：强化地形 110 / 13 辅助：同心协力 4`。

2. **必须每次先删旧组**：`0x478664` 每次刷新（切武将/重开 166）都会执行 H4，

   不删会重复累加（实测行数 27→29 一路上涨）。判据：`itemData ∈ [H5, H5+1536)` ⇒ 必是本补丁的行

   （数据行在 H5+0..1440、标题串在 H5+1440）。

3. **★★★ 通用教训（影响全工作区所有补丁）：Win32 API 是 stdcall，调用后**不许**再 `add esp,N`**。

   旧代码在每个 `call dword ptr [IAT]` 后都写了 `add esp,8/16/48`（多余），ESP 每调一次多抬一截。

   调用次数少时靠 `leave` 复位侥幸不炸；一旦循环里调用 20+ 次（本次扫描列表）ESP 漂移 400B，

   后续 push 的参数全部错位 ⇒ 行数少了/插入失败。**删掉全部多余 add_esp 后行数从 1 行变 3 行**。

   （唯一例外：`wsprintfA` 是 **cdecl**，调用者必须 `add esp,20` 清 5 个参数。）

4. **「第二框」方案在当前引擎下不可行**（两条实证，见下「否决清单」）。

5. **0x45FACA 不是代码洞** —— 它落在一张活跃数据表中间，往里写代码 ⇒ 读档点「是」即退。

   最终洞 = **0x4EEA50**（1536B = 行缓冲 15×96 + 标题串）。

6. **1391/1392/1393 / 1500 / 1313 全是嵌套控件**（Tab 页子对话框内），`GetDlgItem(hDlg,ID)` 一律 NULL。

7. `0x478664` 是 166 的刷新函数（开头 `GetDlgItem([ebp+8],1027)`），调用点

   **0x47904D / 0x479380 / 0x479760**，全部在 166 的 DlgProc 内。
