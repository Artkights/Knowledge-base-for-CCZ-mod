# 注入地址占用登记（多会话防撞表）

> **本页是"机制与口径"页**；**实际占用数据**在 `大鲸鱼产生专用\_注入地址占用登记.md`（工具自动生成，随时重建）。
> 适用样本：`复刻版6.6山贼\Ekd5.exe`（SHA 每轮现读；本页基于 `F3455B30…` 写就）
> 入口命令：`python 大鲸鱼产生专用\_注入地址占用登记.py`

## 结论速览

1. **本工作区有多个并行会话写同一个 `Ekd5.exe`** ⇒ **定注入落点前必须先查占用**，
   否则会撞车。**实测撞车实例**：并行补丁「奋战攻击次数按特效值 v1」占 `0x457E2E..0x457E7A`（77 B），
   而另一处新洞起点 `0x457E7B` **正好**是它尾巴。
2. **⚠ 补丁不一定有 txt**：实测「奋战攻击 v1」**只有 `_应用-*.py`**（直接写盘，绕过 txt 体系）
   ⇒ 登记器**必须同时扫 py**，用 **`ast` 静态**提取模块级 `HOOK_VA/CAVE_VA/*_VA` 与长度常量。
3. **"被声明" ≠ "已启用"**：`0x4363B0` 被**未激活**的「异常追袭」旧版文本声明，
   但现读是原始字节 ⇒ **实际可用**。⇒ 查询结果必须**逐个人工确认那份占用是否已停用**。
4. **重叠要分类**，不能只看数量：当前 274 段 / **112 对重叠**，其中
   **★真撞车可疑 ~54 对 / 同功能多版本 ~38 对 / 文档日志混入 ~17 对** —— 只有第一类需要处理。

## 已确认事实

* 数据源与规模（样本 `F3455B30…`）：**96 个来源、274 段**（`*.txt` 的 `-地址` 段 ＋ `_应用/_生成-*.py` 的 `*_VA`）。
* 补丁 txt 的格式约定（`.eex` 风格）：
  ```
  -<8位十六进制地址>
  <十六进制字节，可多行、空格或逗号分隔>
  ```
  正文/注释行（`#` 开头）与空行不参与计数；**同一文件可有多段**。
* 抽取 py 常量时的**三次踩坑**（都写进工具 docstring 了）：
  ① **正则不能锚行尾** —— 实际行尾常带中文注释（`CAVE_VA = 0x457E2E          # .code 内…`），
     锚 `$` 会**全漏**；
  ② **不能按"出现顺序"配长度** —— 会把 `CAVE_LEN=77` 配给钩点 `0x43646D` ⇒ **假重叠**；
  ③ **不能按变量名猜长度**（"离得近的 HOOK/CAVE"仍会把钩点长度配给洞）。
  ⇒ 正解：`ast.parse` 只取**模块级 Assign**，地址取 `*_VA`，
  长度取 `bytes.fromhex(...)` / `b"..."` / `int` / `b"..."*N` 的**实际字节数**。

## 风险与边界

* **登记是"声明占用"，不是"已写入"**：它扫的是补丁文本与脚本里的地址声明，
  **不代表该补丁已经打进当前 `Ekd5.exe`**。判"是否已启用"要**现读该地址的字节**。
* **回滚文本的地址**按"通常已释放"处理，但**不保证**：需要现读确认。
* `补丁前备份\` 已 **139 个备份 / 77 种 SHA**，且语义是「**写入前的文件**」——
  **不是基线样本**，也**永远不含最新态**。找基线不要指望它。
* 登记表**不会自动更新**：每次改动补丁文本 / 新增脚本后要**重建**。

## ★★ 2026-10-16 21:3x 定案：登记表里**唯一被标"真撞车"的那对，实际无风险**（`0x457DB4`）

### 一对的两个补丁是什么

| | 补丁 A：`暴击槽-链尾代理` | 补丁 B：`暴击预览-预览路径专用槽` |
|---|---|---|
| 挂点 | `0x43F27F`（**共用特技链链尾**）| `0x44066D`（**预览函数内** `mov [ebp-0x18],eax`）|
| 洞 | `0x457D7B` +72 B ⇒ `457D7B..457DC3` | `0x457DB4` +87 B ⇒ `457DB4..457E0B` |
| 语义 | **预览与实战同时**得暴击加成（改共用链）| **只影响预览**，不动实战、不动共用链 |
| 现读 | **未装**（`0x43F27F` = 原样 `E9 48 CB FF FF`；`0x457D7B` = 57 B 纯 `90`）| **已装**（`0x44066D` = `E9 42 77 01 00`）|

**⇒ 二者是【同一需求（预览显示暴击后伤害）的两个替代方案】⇒ 只会装一个 ⇒ 不是撞车。**

### 补丁 B 的运行时正确性已逐项核过（全部通过）

`0x457DB4` **不是"别人注入体的开头"**，而是一个**自洽的内联钩子**：
```
00457DB4  9C              pushfd
00457DB5  51 52           push ecx / push edx
00457DB7  FF 75 D8        push [ebp-0x28]
00457DBA  FF 75 D4        push [ebp-0x2C]
00457DBD  50              push eax
00457DBE  E8 0D000000     call 0x457DD0        ← 真身是子函数（stdcall，ret 0xC）
00457DC3  5A 59 9D        pop edx / pop ecx / popfd
00457DC6  89 45 E8        mov [ebp-0x18], eax  ← ★ 复刻被覆盖的那条原指令
00457DC9  6A 01           push 1
00457DCB  E9 A288FEFF     jmp 0x440672         ← 回到挂点+5，基线流程继续
```

| 检查项 | 结果 |
|---|---|
| **栈收支** | 进钩 `ESP=S` → 5 push + call ⇒ `S-28` → `ret 0xC` ⇒ `S-12` → 3 次 `pop` ⇒ **`S`** ✅ 平衡 |
| **寄存器契约** | 子函数（34 条指令）只写 `EAX/ECX/EBP/ESP`，**`EBX/ESI/EDI` 一个都没动**；钩子保存 `EAX/ECX/EDX`+`pushfd` ⇒ **覆盖到位** ✅ |
| **挂点后续需求** | `0x440672` 起只读 `[ebp±]` 局部量，**不依赖易失寄存器** ✅ |
| **返回路径** | `jmp 0x440672` = 挂点+5，且 `push 1` 复刻了原指令后的压栈 ✅ |
| **洞区归属** | `0x457D7B..0x457DB3`（57 B）是纯 `90`；`0x457DB4` 起才是活代码 ⇒ **补丁 A 的"72 B 洞"实际只有 57 B 可用** |

### ★ 唯一瑕疵：**文本与实机不符**（不影响运行，但会误导后人）

* 文本声明的洞体是 **87 B**、开头 `50 51 52 53 56 57 83 EC 04 …`（`pushad` 风格）
* 实机装的是 **63 B**（`457DB4..457DCE`）、开头 `9C 51 52 FF 75 D8 …`（`pushfd` 风格）
* **全文搜索：文本声明的 87 B 版本在文件里【找不到】** ⇒ 实机用的是**另一版（优化版）**，文本没跟上。
  ⇒ 引用该补丁时**必须现读** `0x457DB4`，不要照抄文本。

### 教训（写进口径）

1. **"区间相交"不等于"冲突"** —— 还要看**是否同一需求的两个方案**。本例 A/B 就是替代关系。
2. **判"某洞是否被占"要看清"洞的可用段"**：本例从 `0x457D7B` 数连续 `90` 只有 **57 B**（到 `0x457DB3`），
   而不是文本声称的 72 B —— **文本的长度声明可能过时**。
3. **遇到"洞体前几条指令像 `pushfd/push ecx/…`"不要立刻当"外来代码"**：
   本工作区的注入体**普遍用这种保存前缀**（对比「奋战攻击 v1」的 `0x457E2E` 也是同类形态）。
   判占用仍然要用**生成器字节全文搜**（见本页前文），而不是目视。
