# 核心引擎 - 特技判定系统

## 结论速览

- 适用：本页未标注目标 EXE SHA 与版本，复刻版6.6山贼套用 `4101D9`、`600XXX`、`9BBFE4` 等地址前须先按目标 EXE 复读核对。
- 双渠道判定核心 `4101D9`：装备渠道或个人渠道**任一通过即视为拥有该特技**；叠加标志为 `2` 时改为优先查装备渠道，装备渠道没有才回退个人渠道。
- `4101D9` 返回什么由效果值标志决定：标志 `1` → EAX 为 `1`（拥有）/`0`（不拥有），用于纯开关型特技；标志 `0` → EAX 为具体数值或 `0`，用于有强度等级的特技；EDX 同时返回判定结果标志。
- 三条调用路径：标准 `桩函数 421XXX → 调度函数 600XXX（设 EDX 偏移 + 9BBFE4 查表）→ 4101D9`；内联 `任意位置 push 4 个参数 → call 4101D9`；包装 `42518F → 40B922 前置验证 → 通过 call 4101D9 / 失败 call 41301E`（回退为仅双渠道判定）。
- 模组开发推荐走内联直调：绕过调度函数与 `9BBFE4` 查表，不需要在 `600000` 区域新建调度函数，也不需要声明 EDX 偏移。
- 调用时 4 个 push 的顺序固定为：效果值标志 / 叠加标志 / 装备特效号 / 个人特效号（格式与现成实例见 `桩函数.md`）。

## 详细记录

#### 概述

曹操传引擎的核心特技判定系统采用双渠道判定机制，通过统一的函数调用链完成特技的存在性判定和效果值计算。

#### 双渠道判定机制

##### 判定逻辑

系统同时检查两个渠道来判断角色是否拥有某项特技：

| 渠道 | 检查内容 | 数据来源 |
|------|----------|----------|
| **装备渠道** | 角色携带的装备是否提供该特技 | 装备特效号 |
| **个人渠道** | 角色自身是否拥有该特技 | 个人特效号 |

**判定规则**：只要任一渠道判定通过，即视为角色拥有该特技。

##### 特殊规则

当叠加标志为 `2` 时，优先级规则变为：
- 优先检查装备渠道
- 若装备渠道无该特技，则检查个人渠道作为备选

#### 核心引擎函数

##### 4101D9 - 双渠道特技判定核心

**地址**：`4101D9`

**功能**：执行特技的双渠道判定，并根据效果值标志决定返回值类型。

**返回值**：

| 效果值标志 | EAX 返回值 | 说明 |
|------------|------------|------|
| `1` (不需要效果值) | `1` = 拥有 / `0` = 不拥有 | 纯开关型特技 |
| `0` (需要效果值) | 具体数值或 `0` | 有强度等级的特技 |

**EDX**：返回判定结果标志，供内部使用。

#### 调用流程

##### 标准路径（引擎原生）

```
游戏逻辑层
    ↓
桩函数 - 421XXX
    ↓ 传递4个参数
调度函数 - 600XXX
    ↓ 设置EDX偏移 + 9BBFE4查表
核心引擎 - 4101D9
    ↓ 双渠道判定 + 读取效果值
游戏逻辑层 (使用返回值)
```

##### 内联直接调用路径（补丁采用 ⭐ 推荐用于模组开发）

```
游戏逻辑层 (任意位置)
    ↓ push 4个参数，直接调用
核心引擎 - 4101D9
    ↓ 双渠道判定 + 读取效果值
游戏逻辑层 (使用返回值)
```

**优势**：绕过调度函数和查表（9BBFE4），更简洁，不需要在 600000 区域创建新的调度函数，也不需要声明 EDX 偏移。

##### 包装调用路径（辅助五维补丁采用）

```
游戏逻辑层
    ↓ push 4个参数
42518F (包装函数)
    ↓ 调用 40B922 进行前置验证
    ├── 验证通过 → call 4101D9 (核心引擎)
    └── 验证失败 → call 41301E (回退：仅双渠道判定)
游戏逻辑层 (使用返回值)
```

## 2026-10-15 第 11 轮：`0x45AA37` = **单位属性/状态的统一设置入口**（6 参、带门禁）

> 样本 `Ekd5.exe` SHA256 `25DB2211FE8F495DE4993BAB296C23C180E18679F00A0E43B47B1FD2034B7EAF`；**证据层级 = 1 静态**；
> 工具 `_dsh反汇编工作台.py`（`func`/`da`/`xref`）。

### 1. 签名与门禁（281 字节）

```
0x45AA37(arg1, arg2_类别号, arg3_值, arg4_标志, arg5_模式)   ⚠【第 13 轮更正：原写 6 参，实为 5 参（`ret 0x14`）】
  arg1=[ebp+8]  编号/对象      arg2=[ebp+0xC] 类别号（≤5 / ==6 / >6 三种处理）
  arg3=[ebp+0x10] 值           arg4=[ebp+0x14] 标志
  arg5=[ebp+0x18] 模式字节：非 0 ⇒ 该值当"战场编号"用；为 0 ⇒ arg1 当编号查表
```

```asm
0045AA3E  mov cl,[ebp+0x18] / test cl,cl / je 0x45AA56   ; 模式分支
  非0：call 0x4061F9（战场编号→TacticalUnit*）；cmp word [ecx],0xFFFF ⇒ 空槽退出
  0  ：mov ecx,[ebp+8] / call 0x41B882（查表）→ 若 0 则 cmp ecx,0x400 / ja ⇒ 退出
        push ecx / call 0x43E4D6（查表）→ EAX
0045AA7E  mov [ebp-4],eax / cmp al,0xFF / je 退出          ; 门禁 1
0045AA85  mov [ebp-8],ecx                                  ; ★ 对象指针
0045AA88  call 0x418C90 / cmp al,2 / jne 退出              ; ★★ 门禁 2：必须 == 2
```

### 2. 类别号分派（本轮解出，**与既有登记字段直接对应**）

| 类别号 | 处理 | 落点 |
|---|---|---|
| **`0..5`** | `mov byte [对象 + 0x18 + 类别号], 值`（若 `arg4 != 0` 先 `call 0x43E6AA`） | **`unit+0x18..+0x1D` 六项能力状态档位**（本库已登记，正常值 3） |
| **`6`** | 值 `& 0x80` ≠ 0 ⇒ `call 0x423FB9`；否则 ⇒ **`call 0x4240D6`** | **异常状态 `unit+0x1E`**：`0x4240D6` 即第 3 轮解出的"按 selector 位序 OR 掩码表 `02 04 20 C0`"写入器 |
| **`>6`** | `sub eax,6 / jmp dword [eax*4 + 0x45AB49]` | 跳转表（更多类别，待展开） |

### 3. ★★ 跨轮印证（把三轮知识连成一条线）

- 第 1 轮**异常状态清除路径**：`0x4240B7 call 0x45AA37`，参数 `(unit[0], 6, 选择子|0x80, 1, unit[4])`
  ⇒ 类别号 `6`、值含 **`0x80`** ⇒ 命中上表第 2 行 ⇒ **走 `0x423FB9`**。
  ⇒ **`0x80` 位 = "清除/负面方向"标志**（与第 8 轮 `0x4240D6` 里 `or al,0x80` 的"强制清除"标记一致）。
- 第 10 轮**字段索引 `7/8`**（`0x406F96`）把 `(编号, 索引, 参数, 1, 0)` 交给 `0x45AA37`
  ⇒ 因类别号是 7/8（`>6`）⇒ 走跳转表分支。
- 第 3 轮**字段访问器 `0x406ECA`** 的索引 `9`/`0x0A..0x0E` 等也可与这里的类别号体系对照（两条体系：**记录字段访问器** vs **单位属性设置入口**）。
- `0x41B882` / `0x43E4D6` = **编号→表项** 的解析器（`0x426A07` 分支 B 也用过 `0x43E4D6`）。

### 4. 调用者（原始扫描 **9 处**）

`0x406FB3`、`0x4070A0`、`0x414396`、`0x420ECE`、`0x4240B7`、`0x4263E6`、`0x42BC81`、`0x43C9C8`（另 1 处见工具全清单）。

### 5. 实践含义（改引擎直接可用）

- **想改能力档位（`unit+0x18..+0x1D`）或异常状态（`unit+0x1E`）⇒ 调 `0x45AA37`**（类别号 0..5 / 6），
  **不要自己 `mov`** —— 它会做"编号解析 + 3 道门禁 + 界面刷新/派发"，自己写会绕过校验并可能不同步界面。
- 参数约定：**值在 `arg3`**；异常状态的"选择子"用本库既有口径 `2<<i`（`0x02/0x04/0x08/0x10`），
  **要清除就把 `0x80` 或上**（与第 1 轮清除路径一致）。

## 2026-10-15 第 12 轮：类别号**安全边界**纠正 + `0x418C90` 门禁真相

### 1. ★ 纠正（第 11 轮的 off-by-one）：`0x45AA37` **只支持类别号 `0..8`**

跳转表 `0x45AB49`（`sub eax,6` **之后**用 `eax` 索引 ⇒ `idx = 类别号 - 6`）：

| 类别号 | idx | 目标 | 说明 |
|---|---|---|---|
| `6` | 0 | `0x45AAD3` | 异常状态分支（值 `&0x80` ⇒ `0x423FB9` / 否则 `0x4240D6`） |
| `7` | 1 | `0x45AAFA` | 另一类（字段索引 7 走这条） |
| `8` | 2 | `0x45AB15` | 另一类（字段索引 8 走这条） |
| **`9` 及以上** | ≥3 | **`0x90909090`（NOP 填充）** | **越界 ⇒ 执行 NOP 滑落，未定义/崩溃** |

⇒ **`0x45AA37` 的类别号必须 ≤ 8**。**mod 时若传入 ≥9 会掉进 NOP 区** —— 这是必须写进契约的安全边界。

### 2. `0x418C90`（9 字节）= 门禁③ 的**真实含义**

```asm
00418C90  55            push ebp
00418C91  8B EC         mov  ebp,esp
00418C93  0F B6 41 0C   movzx eax, byte [ecx + 0xC]   ; ★ 读 `对象 + 0x0C` 的字节
00418C97  5D / C3       pop ebp / ret
```
⇒ 第 11 轮门禁③"**`0x418C90` 返回值必须 `== 2`**"实为：**`byte [对象 + 0x0C] == 2`**。
⇒ 即"**只有 `+0x0C == 2` 的对象**才允许经 `0x45AA37` 改属性/状态"（疑为单位类型/阵营判定；`+0x0C` 语义见 P2）。

### 3. 已核实的调用者/使用者交叉

- `0x4240D2`（表 `03 0C 30 C0`）的两处引用（第 2 轮 `xref`）：`0x423FD5`（**本轮定性 = 清除版写入器 `0x423FB9` 内部**）与 `0x4399C2`。
- `0x45AA37` 的调用者 9 处不变（见第 11 轮节）。

## 2026-10-15 第 13 轮：`0x45AA37` 类别号**完整总表**（含 HP/MP）+ 参数个数纠正

### 1. ★★ 类别号 → 落点 完整总表（`ret 0x14`，5 个栈参）

| 类别号 | 落点 | 实现 |
|---|---|---|
| `0..5` | **六项能力状态档位** `unit+0x18+类别` | `mov byte [unit+0x18+类别], 值`（`arg4!=0` 时先 `call 0x43E6AA`） |
| `6` | **异常状态** `unit+0x1E` | 值 `&0x80` ⇒ `0x423FB9`（清除版）/ 否则 ⇒ `0x4240D6`（置位版） |
| **`7`** | **HP** | `call 0x41B500`（当前 HP）→ `call 0x40DA4A`（旧值, `arg3`）→ **`call 0x43F6DB`**（HP setter） |
| **`8`** | **MP** | `call 0x472840`（当前 MP）→ `call 0x40DA4A`（旧值, `arg3`）→ **`call 0x43F715`**（MP setter） |
| `9+` | **越界** | 跳转表 `0x45AB49` 之外 ⇒ `0x90909090`（NOP 滑落，未定义） |

公共出口（`7`/`8` 与 `6` 分支共用）：`call 0x43FCC9` → `call 0x4158DC`（收尾/刷新），然后 `ret 0x14`。

⇒ **`0x45AA37` 是引擎的"单位数值统一设置器"**：**能力档位 / 异常状态 / HP / MP 全走它**。
`0x41B500`（当前 HP）、`0x472840`（当前 MP）、`0x43F6DB`（HP setter）、`0x43F715`（MP setter）**全部是本库既有登记的地址**
⇒ 本轮把"设置侧"与既有"读取侧"接上了。类别 `7`/`8` 中间的 `0x40DA4A(旧值, 新值)` 是**计算层**（P2）。

### 2. ★ 纠正（我第 11 轮的表述）：是 **5 个栈参**，不是 6 个

- 依据：函数末尾 **`ret 0x14`**（`0x14` = 20 = 5×4），且只读 `[ebp+8]/[ebp+0xC]/[ebp+0x10]/[ebp+0x14]/[ebp+0x18]` 五个位置。
- 正确签名：**`0x45AA37(编号/对象, 类别号, 值, 标志, 模式)`**
  （`arg5 = [ebp+0x18]` = 模式字节；第 11 轮我写的"arg6"是**多算的一列**）。

### 3. 调用者（不变，9 处）

`0x406FB3`、`0x4070A0`、`0x414396`、`0x420ECE`、`0x4240B7`、`0x4263E6`、`0x42BC81`、`0x43C9C8`（+1）。

## 2026-10-15 第 14 轮：`0x40DA4A` = **HP/MP 三模式数值变更器**（并把 `[0x505F30]` 语义定案）

### 1. `0x40DA4A(旧值EAX, 参数EDX)` —— 39 字节，按全局 `[0x505F30]` 选模式

```asm
0040DA4A  push ebp / mov ebp,esp
0040DA4D  mov  ecx, dword [0x505F30]      ; ★ 全局模式开关
0040DA53  test ecx,ecx / jne 0x40DA64
0040DA57  cmp  eax,edx / ja 0x40DA60      ; ── 模式 0（默认）：
0040DA5B  push 1 / pop eax                ;    旧值 <= 参数 ⇒ 返回 **1**（保底 1）
0040DA60  sub  eax,edx                     ;    旧值 >  参数 ⇒ 返回 **旧值 - 参数**
0040DA64  cmp  ecx,1 / jne 0x40DA6D       ; ── 模式 1：
0040DA69  add  eax,edx                     ;    返回 **旧值 + 参数**
0040DA6D  mov  eax,edx                     ; ── 模式 >= 2：返回 **参数**（赋值/覆盖）
```

| `[0x505F30]` | 语义 | 结果 |
|---|---|---|
| `0`（默认） | **减法** | `旧值 > 参数 ? 旧值-参数 : 1`（**HP/MP 永不低于 1**） |
| `1` | **加法** | `旧值 + 参数` |
| `>= 2` | **赋值** | `参数` |

### 2. ★★ `[0x505F30]` 语义**定案**（并纠正我在第 8/10 轮的猜测）

- **正确定性**：`[0x505F30]` = **"资源（HP/MP）数值变更模式"全局开关**（`0`=减 / `1`=加 / `>=2`=赋值）。
- **我此前的写法（作废）**：第 8/10 轮我把它称作"**记录脏/重算中标记**（进入分支置 1、出口复位 0）" —— **错**，
  它其实是"**先置成加法模式、调用完再复位成减法模式**"的模式设置/还原。
- **证据**：`0x406F96`（字段索引 `7/8`）`mov byte [0x505F30],1` → `call 0x45AA37` → 出口 `mov byte [0x505F30],0`；
  而 `0x45AA37` 类别 `7/8` 正是 `0x40DA4A(当前HP/MP, arg3)`。⇒ **该分支 = "给记录加 HP/MP"**。

### 3. 完整链路（本轮把三个函数接成一条链）

```
0x406ECA(记录, 索引=7或8, 参数, 模式)
   → mov byte [0x505F30], 1            ; 切到"加法"模式
   → 0x40BE7D 反查编号
   → 0x45AA37(编号, 7|8, 参数, 1, 0)
        → 0x41B500 / 0x472840 取当前 HP / MP
        → 0x40DA4A(旧值, 参数)         ; ★ 加法：旧值 + 参数
        → 0x43F6DB / 0x43F715 写回（自带上限裁剪）
        → 0x43FCC9 → 0x4158DC 收尾刷新
   → mov byte [0x505F30], 0            ; 复位为"减法"模式
```
⇒ **`0x45AA37` 的 `arg3` 语义**：模式 `0/1` 时是**增量**，模式 `>=2` 时是**目标值**。
⇒ 实践含义（对本工作区）：**给人物/单位加 HP/MP 应走 `0x45AA37` 类别 `7/8` 且先把 `[0x505F30]` 置 1**
（或直接调 `0x406ECA` 的索引 `7/8`）；要"设为固定值"则置 `[0x505F30] = 2`。
**不要自己 `mov [unit+0x10], …`**（会绕过上限裁剪与收尾刷新）。

## 2026-10-15 第 19 轮：`0x43FCC9` = **"改完属性后的界面刷新"收尾**（实践结论的机制层证据）

```asm
0043FCC9  push ebp / mov ebp,esp
0043FCCC  call 0x418C90            ; EAX = byte [ECX+0x0C]（显示状态 view）
0043FCD1  cmp  al,2 / jne 0x43FCDD ; ★ 仅当 view == 2 才继续
0043FCD5  push dword [ecx+6]       ; ★ 压 `unit+0x06` 的 dword（本库登记：+0x06/+0x07 = X/Y 坐标）
0043FCD8  call 0x42A5B5            ; ★ 以坐标参数调用 ⇒ 疑"刷新该格/重绘"
0043FCDD  pop ebp / ret
```

### 意义（把三条既有结论串起来）

1. `0x45AA37`（单位数值统一设置器）在改完 **能力档位/异常状态/HP/MP** 后，**出口会调 `0x43FCC9`**
   （第 13/14 轮已登记出口链：`0x43FCC9` → `0x4158DC`）。
2. `0x43FCC9` 的形状 = **"view==2 时，拿该单位的 X/Y 去调 `0x42A5B5`"** ⇒ **这就是界面刷新/重绘**。
3. ⇒ **机制层证据**：**"改单位属性必须走 `0x45AA37`（或 `0x406ECA`），不要自己 `mov` 内存"** ——
   自己写会**跳过 `0x43FCC9` 的按格刷新**，导致界面不同步（这正是第 13/14 轮给出的实践口径的根据）。
4. 顺带：`0x418C90`（`view` 读取）**在本函数里再次充当门禁** ⇒ 与 `0x45AA37` 门禁③同源
   ⇒ "**只有 view==2 的单位**才会被刷新"（`view==3` 死亡单位既不写属性、也不刷新）。

## 2026-10-15 第 21 轮：界面刷新链**末端**解出（`0x42A5B5` → `0x45218F(x, y, 1, 1)`）

```asm
0042A5B5  push ebp / mov ebp,esp
0042A5B8  call 0x42C075            ; ★ 取视口原点的格坐标（第 22/25 轮更正：不是"滚动偏移"）
0042A5BD  sub  byte [ebp+9], al    ; ★ 用偏移修正 Y
0042A5C0  sub  byte [ebp+8], dl    ; ★ 用偏移修正 X
0042A5C3  push 1 / push 1
0042A5C7  push dword [ebp+9]       ; 修正后的 Y
0042A5CA  push dword [ebp+8]       ; 修正后的 X
0042A5CD  call 0x45218F            ; ★ 4 参 (x, y, 1, 1) ⇒ 按格重绘/刷新
0042A5D2  pop ebp / ret 4          ; 清自身 1 个入参
```

### 完整刷新链（把第 19 轮与本轮接起来）

```
0x45AA37（单位数值统一设置器）
  └─ 出口 → 0x43FCC9           ; view==2 才继续（门禁）
       └─ push dword [unit+0x06]   ; ★ X/Y 打包
          └─ 0x42A5B5              ; 减视口原点格坐标（第 22/25 轮更正）
               └─ 0x45218F(x, y, 1, 1)   ; ★ 按格重绘
```

**都会跳过 `0x43FCC9 → 0x42A5B5 → 0x45218F` 这条按格重绘链** ⇒ 界面不同步。
