# 特技改造标准作业流程（SOP）

> **本页回答"要改造/新增一个特技，从头到尾按什么顺序做、每步用什么工具、什么判据才准过、哪里最容易翻车"。**
> 它是特技优化的**唯一流程入口**：机制细节去各专题页，流程与闸门只认本页。
> 建立日期：2026-10-14（用户口径：为后续特技优化做知识准备）

## 结论速览

- 全流程 **8 个阶段**，每个阶段都有**不许跳过的闸门**。历史上 90% 的返工来自跳过闸门 ①（没定特技号能不能被引擎查到）
  和 ⑥（没做补丁体检就写）。
- **三条铁律**（每条都对应一次真实事故）：
  1. **每次 `call 0x4101D9` 之前必须重设 `ECX`（单位指针）** —— 它返回后 ECX 已被破坏；
     违反 ⇒ **点击敌人（伤害预览走修正链）时闪退**。
  2. **一个功能 = 一个 hook + 一个洞**，洞尾**原样执行**被覆盖指令 —— 违反 ⇒ 跳转网、无法回滚。
  3. **结论必须绑定"地址 + 字节 + SHA"三件套**，只写 SHA 的结论会随样本改写立即过期
     （样本会被并发会话反复改写，见 `06-项目与工具链/样本SHA时间线与现行补丁.md`）。
- 动手前先跑三条只读命令：**查库 → 读现役状态 → 算字节**（见第 0 节）。

## 适用版本

- 目标：`复刻版6.6山贼\Ekd5.exe`（**SHA 每轮现读**，见 `样本SHA时间线与现行补丁.md`）。
- 对照样本：`ai使用库\复刻版6.6\初版Ekd5.exe`（用于"搬回被删特技"，节偏移一致可直接按同 VA 比对）。
- 地址一律为 `0x00400000` 参考 VA；所有写入走 `大鲸鱼产生专用\_dsh写锁.py`。

## 阶段 ① 定特技号（决策树 —— 最容易翻车的一步）

**核心问题：引擎认不认这个号？**「名字放进名称表」**不等于**「引擎会实现它」。

```
要加特技
├─ 用现成的空槽？
│   ├─ 名称表空位：0xF4 / 0xF9 —— ⚠️ 这两格【不在】引擎查询列表里，放上去不会生效
│   └─ 改用「被查询过但名字被占」的号 → 走下面三条
├─ 引擎是否查询过该特技号？
│   ├─ 查过（当前 exe 共 105 个号）→ ✅ 可直接用
│   └─ 没查过
│       ├─ 初版查过、当前被删 → 【技法 B】抄回被 NOP 的内联块
│       └─ 从没查过
│           ├─ 效果在共享链里、只靠桩取值 → 【技法 A】扩展已有查询桩
│           ├─ ★ 只在「预览/实战共用链」上生效即可（如伤害预览） → 【技法 C】共用链追加
│           └─ 都不是 → 自建 hook + 洞（阶段 ③ 起走完整流程）
└─ 提示：名称表 VA 0x4CC600 / 文件偏移 0x9E800，每条 16 字节 = 15 字节 GBK 名 + 1 字节 flag
```

| 技法 | 写法 | 适用 | 注意 |
|---|---|---|---|
| **A 扩展查询桩** | 桩改成"先查 A，没有就查 B" | 效果块在共享链（如 `0x441D87`）里 | ⚠️ **两次 `call 0x4101D9` 之间必须重建 ECX** |
| **B 抄回内联块** | 从初版 exe 抄字节，**只改特技号那 1 个字节** | 初版有、当前被 NOP 的专用块 | 指令长度必须一致 ⇒ 相对跳转/调用无需重算 |
| **C 共用链追加** ★ | 在**预览与实战共用**的特技修正链尾部追加处理 | 要"预览也显示效果"（减伤/增伤/倍率） | ⚠️ **绝不能碰 `[eax+0x604]`（暴击标志）**；栈必须配平 |

**技法 A 的正确形态**（已实机验证）：

```asm
; 0x441D39 (26B) → E9 rel32 + NOP...      ; jmp 0x432500
; 0x432500 新桩：
    push ebp / mov ebp,esp
    push 0 / push 1 / push 0 / push 0F2h / call 0x4101D9
    test eax,eax / jne done
    mov  eax,[ebp]          ; ★ 取调用者(链函数)的 EBP
    mov  ecx,[eax+0x10]     ; ★ ECX = 链函数的 [ebp+0x10] = 单位指针（必须重建！）
    push 0 / push 1 / push 0 / push 0FCh / call 0x4101D9
  done:
    mov esp,ebp / pop ebp / ret
```

**技法 C 的正确形态（2026-10-14 实机验证通过：防御暴击预览减伤）**：

> **场景**：某个效果（如减伤）只在实战生效，**预览看不到**。原因是效果加在了
> "预览不经过的路径"上（如 `0x405EF9`），而预览只走到共用链就取数了。

```asm
; 前提：找到一条【预览与实战共用】的链（本样本 = 0x43F1E8~0x43F27F 特技修正链）
;       验证方法：等价跳转补丁 + 执行断点，看"指向目标出预览"时是否命中
;
; 在链尾（或既有补丁体内）改写：
    pop  ebx                     ; 先做原有的栈恢复（照抄原指令）
    pop  edx
    jmp  <cave>                  ; 跳到自己的代码
  <cave>:
    mov  ecx, 100
    sub  ecx, esi                ; 系数 = 100 − V（V 通常已在 ESI 里，别重复查表）
    jns  ok
    xor  ecx, ecx                ; 负数钳 0
  ok:
    mov  eax, [ebp-0x28]         ; 伤害槽指针
    mov  eax, [eax]
    push eax
    push ecx
    call 0x425AD9                ; stdcall：eax = 伤害 × 系数 / 100
    mov  edx, [ebp-0x28]
    mov  [edx], eax              ; 写回伤害槽
    pop  esi                     ; ★ 栈配平（原路径的 pop esi 在此补上）
    jmp  0x405F24                ; ★★ 出口：跳过 0x405F17 的暴击标志置位
```

**四条硬约束（每条都对应一次真实闪退）**：

| # | 约束 | 为什么 |
|---|---|---|
| 1 | **入口的 push/pop 必须与出口逐条配平** | v2/v3 因漏 `pop esi`、重复 push 而攻击闪退 |
| 2 | **rel32 一律用脚本反算，不手算** | v4 手算差 2 字节 ⇒ 跳进代码中段 |
| 3 | **绝不能让流程经过 `0x405F17`** | 那是 `mov [eax+0x604],1`（`CRITICAL_HIT_FLAG`）⇒ 假暴击动画 |
| 4 | **`jg`/`jns` 等条件跳转要紧跟比较指令** | 原补丁体用 `pushfd`/`popfd` 保护标志位；穿插栈操作会让语义脆弱 |

**找链入口的查法**：
1. 先确认"预览与实战共用哪条链"——用等价跳转 + 断点验证（见 `03-机制详解/物理伤害计算链与预览不同步.md` 第 12 节）；
2. 链函数通常形如 `push 参数 / call <特技函数> / mov [ebp-4],eax` 的重复序列（结果累加在同一个槽）；
3. 入口参数与中间变量（如 `[ebp-0x28]` 伤害槽指针、`[ebp-0xC]` ctx）**照抄链上既有调用**，不要自己猜。
**闸门 ①**：新特技号**必须**在"引擎查询列表"里，或已确定用技法 A/B 落地。
**查清单**：`03-机制详解/特技定义表与空位搬移.md` 第"一·补"节（含 105 个已查询号与 37 个被删号）。

## 阶段 ② 定数据结构（特技怎么"挂"到单位上）

**加特技的唯一正确公式**（用 slot 当角色号是既往最大实操坑）：

```
特效表项地址 = [0x4F0004] + 角色号 × 1024
角色号      = *(WORD*)(0x4A7B20 + slot × 0x30)      ; 注意是单位记录里的 Data 号，≠ 战场 slot
```

- 特效值恒为 **1 字节**（读取器 `0x4198DD` 的 `movzx eax,al`）⇒ 要表达"掩码 + 档位"必须自己压缩
  （范例：修罗之怒 = 低 5 位掩码 + 档位×32）。
- 特效表**同时存在于 exe（`0x511000`）与存档（`SV*.E5S` 偏移 `0x10000`）**，
  **读档后生效的是存档那份** ⇒ 改值必须改存档，不能只改 exe。
- 存档被覆盖的时机、`Effect.e5` → 内存表的加载链，见 `02-数据结构/特技系统-扩展槽机制.md`。

**说明栏显示（flag）**：名称表行尾 1 字节 flag 决定显示方式
（`0x00` 不显示 / `0x01` `+%d` / `0x02` `+%d%%` / `0x03` `-%d%%` / `0x04` `%d%%` / `0x05` `%d` / `0x06` `%d次`）。
⚠️ **说明分派只收 flag + 特效值，不收特技号** ⇒ 同 flag 的技能无法区分；
要区分就**整条替换分派入口**（`0x452C8B → jmp 洞`），在洞里按 flag 分流，不必改 flag 值。

**闸门 ②**：写清"这个特技存在哪、用什么 flag 显示、改 exe 还是改存档"。

## 阶段 ③ 定落点（hook 点 + 调用约定）

**Hook 契约必填项**（缺一项就不许进阶段 ⑤）：
SHA / hook 地址 / 触发阶段 / 单位指针来源 / 冲突组 / 覆盖长度 / 旧字节 / 返回地址 /
原指令策略 / EFLAGS 与寄存器要求 / 动态验证场景。

**Hook 至少 5 字节**（`E9 rel32`），但**覆盖长度必须扩到完整指令边界**；
覆盖范围含 `ret`、间接跳转、无法完整解码或重编码时必须**放弃自动搬迁**。

**三种手法取舍**：

| 手法 | 何时用 | 代价 |
|---|---|---|
| `jmp`（默认） | 原指令 ≥5 字节 | 不碰栈；多处会呈"跳转网" |
| `call` | 洞里需要函数感、或多入口复用同一段 | 栈上多一个返回地址，洞内碰栈须计入 |
| 压缩原代码 | 原指令不足 5 字节 | 改动面最小最干净 |

**必须先查清被调用函数的入参寄存器**（这条对应"点击敌人闪退"事故）。

**闸门 ③**：把 Hook 契约按 `01-核心引擎/地址语义与Hook契约.md` 的字段写全，并**核对冲突组**
（同址是否已有别的补丁；`特技重叠分析.md` 记了 18 个特技里 8 组共用地址）。

## 阶段 ④ 写代码（洞内汇编）

### ⛔ 4.0 找代码洞的致命陷阱（2026-10-14 血案，必读）

**"这块地方有足够的 `00`/`90`" ≠ "这块地方可以放代码"。**

实测事故（v6 防御暴击，`c0000005 @ 0x43A6D4`，连续 4 次闪退）：

```
洞起点选 0x452E68
但 0x452E18 是历史补丁函数，其结尾是   ret 4  =  C2 04 00
                                          ↑        ↑
                                       操作码  立即数(2 字节: 04 00)
0x452E68 正好落在立即数的【末字节 00】上 ⇒ 覆盖后指令变成  ret 0x5604
⇒ 函数返回时 ESP 被抬高 0x5600 = 22016 字节 ⇒ 跑出线程栈
⇒ 0x43A6D4 的 push ecx 写到未提交页 ⇒ c0000005
```

**选洞三条硬判据**：

| # | 判据 | 做法 |
|---|---|---|
| 1 | **起点不能落在任何指令内部** | 对洞起点**往前回看反汇编**（多解几条），确认它不在 `C2/C3/C8…` 之后、不在立即数里 |
| 2 | **预检只认 `90` / `CC`** | **`0x00` 可能是指令立即数，不能当"空洞"**；`.text3`/`.api` 里成片 `00` 尤其危险 |
| 3 | **别贴着 `ret N` 放** | `ret imm16` 带 2 字节立即数，紧跟其后的字节**看起来是填充，实际属于上一条指令** |

```bat
:: 洞起点前 48 字节回看，确认边界
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_dsh反汇编工作台.py da 0x452E40 48
:: 找洞（注意：它会标 at_section_tail，但不判断字节是否属于指令立即数）
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_dsh反汇编工作台.py cave 64
```

> ⚠️ `cave` 找的是"连续 `00`/`90` 段"，**它不判断这些字节是否属于某条指令的立即数** —— 那一步只能靠回看反汇编。

### 4.1 洞内写法

- 洞尾**原样执行**被覆盖的指令再跳回（语义是"插入"，不是"改写"）。
- 洞内**单向流程**，洞与洞之间**不互相跳转**。
- 需要调用的引擎函数速查：`04-函数速查/函数速查表.md`、`02-数据结构/异常状态-可复用函数与数据速查.md`。
- 可复用的**现成模板**：
  | 模板 | 地址 | 复用方式 |
  |---|---|---|
  | 向死而生（按异常状态个数加成） | `0x43D472` | 换掩码 = 只认某几种状态；"个数×特效值"换查表 = 倍率型 |
  | 异常追袭（状态回合权重） | 洞 `0x4D4000` + 表 `0x4D4200` | ⚠️ 该补丁栈帧有缺陷，复用前先读 `03-机制详解/异常追袭-栈帧缺陷与回滚.md` |
  | 修罗之怒（掩码 + 档位） | 洞 `0x4D4300`/`0x4D4400` | 1 字节特效值表达多维语义的标准做法 |
  | 防御暴击 v6-fix（洞起点踩立即数的反面教材） | 洞 `0x452E69` | **洞起点从 `0x452E68` 移到 `0x452E69`** 即修复；修完连续 10 回合无崩溃 |

**闸门 ④**：用工作台把汇编**算成机器码**并复核（不许手算位移）：
```bat
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_dsh反汇编工作台.py asm 0x4D4300 "push ebp"
```

## 阶段 ⑤ 打包补丁（生成可复读的注入文本）

补丁 txt 规范：`-<地址> <十六进制字节>` 逐行；**注释里写清 SHA、旧字节、用途、回滚点**。
- 完整技术文档 → 普通 txt；**只含改动** → 同目录 `【6.6山贼】xxx.txt`。
- 归档：`_归档检查.py`（归位 → 改注释路径 → 清 MOTW → 重算判定 → 重写清单）。

**闸门 ⑤**：**补丁体检** —— 写之前必须跑，别等写完才发现撞车：
```bat
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_补丁体检.py "大鲸鱼产生专用\【6.6山贼】新特技-xxx.txt"
```
判定只有四种：`已打过 / 可打 / 冲突 / 无法判定`。
⚠️ **跳转目标撞别人的洞，区间求交查不出来** —— 体检工具会单独报这类；
实测全量 35 篇有 **42 条互撞 / 11 个文件对**，最严重一对同址 89 字节互斥、**只能选一份**。

纪律（W1–W5，见 `00-总览与规范/Ekd5写入串行化规则.md`）：
**进程未运行 → 跨进程写锁 → SHA 匹配 → 自动备份 → 写后复读比对 → 审计行**。
- 锁被占用**必须报错退出**，不得抢占。
- **禁止**任何直接 `open(EXE,'wb')` 或 `shutil.copy2(备份, EXE)`。
- 写完**必须**重生成 `_改动总账.md`：`python 大鲸鱼产生专用\_改动总账.py`。

**闸门 ⑥**：写后复读必须逐字节一致；`_样本时间线.py` 复跑一次，确认新 SHA 与新备份成对出现。

### 7.2 执行级（x32dbg：证明"这段代码真的跑了"）

**必须先探活、必须收尾**（通道契约见 `06-项目与工具链/逆向调试工具链总纲-x32dbg与MCP.md`）：
```bat
大鲸鱼产生专用\_x32.cmd state                       :: 永远第一步
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_x32断点探针.py --address <地址> --watch eax,ecx --secs 120
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\_x32栈漂移探针.py --address <地址> --secs 60 --max 400
大鲸鱼产生专用\_pyrun.cmd 大鲸鱼产生专用\run_cleanup.py --stop
```

**四条硬纪律**：
1. **命中即记录、立即放行**（不立即放行 ⇒ 游戏长时间卡住、推进脚本全打空 —— 用户已两次提醒）。
2. **禁止无条件 `debug_run` 循环**（本引擎用异常做流程控制；放行未处理异常 = 终结进程，**已造成事故**）。
   自建实例可配 `_x32保活.py`；**用户正在玩的实例严禁**。
3. **软件断点会阻塞游戏**：`fast_resume` 不能保证不阻塞（实测 `hit_count=1` 且动画卡住）
   ⇒ 高频函数与伤害入口**默认禁用执行断点**。
4. **断点命中 ≠ 真的发生了一次攻击**（`0x405DE1` 的祖父层 `0x4064F1` 有 11 个调用者）
   ⇒ 必须同时核对上下文变化与 HP 下降。

### 7.3 实机（用户侧，最小化打扰）

- **只读采样优先**，不挂调试器：`_减伤实机采样.py` / `_实机验证v5.py`（采样 **按回合分批 `--rounds 5`**）。

### 9.1 四类操作的本质与最小手法

| 操作 | 本质 | 最小手法（够用就别升级） | 判据 |
|---|---|---|---|
| **移植**（从初版/参照版搬回） | 引擎**曾经实现过**、现在被 NOP 掉的内联块 | **技法 B**：从参照版抄字节，**只改特技号那 1 个字节**；指令长度必须一致 ⇒ 相对跳转/调用**不用重算** | 搬回后 `da` 逐条与参照版一致；`_补丁体检.py` 判"可打" |
| **新增**（引擎从没查过这个号） | 要让引擎"认"这个特技号 | **技法 A**（扩展查询桩：先查 A 没有就查 B；⚠ **两次 `call 0x4101D9` 之间必须重建 ECX**）／<br>**技法 C**（在**预览与实战共用链**尾部追加，用于减伤/增伤/倍率）／<br>都不满足才自建 hook + 洞（阶段 ③~⑦ 完整流程） | 桩查到的号 = 名称表目标行号；实机看到效果 |
| **修改**（已实现，但行为/数值/文案不对） | 改**数值** 或 改**判定** 或 改**流程** | 三个粒度**从低到高**：① **只改数值** ⇒ 改数据表/存档（**不碰代码**）② **改判定** ⇒ 改 1 个字节的 `cmp`/`jcc`/掩码 ③ **改流程** ⇒ hook + 洞 | ①必须改**存档**（见 9.3）；②③要写 Hook 契约 |
| **移除**（想失效但保留代码） | 让效果不生效，且**可逆** | 见 9.2 四手法 | "退役/复活"可逆（库内已有对应工具） |

### 9.2 ★ 移除的四种手法（按代价从低到高，**优先选小的**）

| # | 手法 | 具体做法 | 代价 / 风险 |
|---|---|---|---|
| **1** | **数据层禁用**（首选） | 把该特技从单位/装备上摘掉：特效值置 `0xFF` 或清零；改**存档**那份特效表 | **不碰代码，天然可逆**；缺点：只对"数据驱动"的特技有效 |
| **2** | **桩短路** | 在该特技的查询桩/取值点把结果写死：`xor eax,eax; ret`（返回 0 = 无该特技）或 `mov al,0xFF`（`0x4101D9` 的"无"返回值） | 只改 2~3 字节；⚠ 必须确认该桩**只有这一个消费者** |
| **3** | **内联块 NOP** | 把专用块整段填 `90` —— **这就是初版里"被删特技"的形态**（故"移植"与"移除"是同一枚硬币两面） | 必须先**提取原字节存档**才能复活：`_特技退役-提取.py` / `_特技退役-复活.py` |
| **4** | **链上禁用**（别选） | 在共用链里插"本号直接跳过"分支 | 要动共用链 ⇒ 影响所有走该链的特技；代价与风险最高 |

> ⛔ **任何移除都不得**：碰 `[eax+0x604]`（暴击标志，SOP 纪律 3）、破坏栈配平（纪律 1）、
> 或让流程经过 `0x405F17`（假暴击动画）。

### 9.3 修改的"改哪儿"速查（本样本已定案的三个坑）

| 想改 | 正确位置 | 坑 |
|---|---|---|
| 特技**数值**（特效值） | **存档** `SV*.E5S` 偏移 `0x10000` 的特效表（`[0x4F0004] + 角色号*1024`）；exe 的 `0x511000` 那份**读档后被覆盖** | 只改 exe ⇒ 读档即失效（SOP 纪律 9） |

### 9.5 跳转的四种基本形态（写 hook 时按这张表挑）

| 形态 | 机器码 | 何时用 | 纪律 |
|---|---|---|---|
| **5 字节 hook** | `E9 rel32`（+ NOP 补到指令边界） | 原指令 ≥5 字节（**默认**） | rel32 **必须脚本反算**（手算差 2 字节 ⇒ 跳进指令中段） |
| **调用点插 call** | `E8 rel32` | 洞里需要函数感、或多入口复用同一段 | 洞里碰栈要把**返回地址**计入（栈高度多 4） |
| **压缩原代码** | 重编码更短等价序列 | 原指令不足 5 字节 | 改动面最小；必须先证明等价 |
| **蹦床 trampoline** | `pushfd / push ecx / push edx / … / call 体 / pop / popfd / 复刻被覆盖指令 / jmp 回` | 需要保护标志位与寄存器（**伤害链必备**） | **复刻被覆盖的原指令** + **栈逐条配平**（入口 push/pop 与出口必须对账） |

- **调用约定从机器码确认，不看函数名**：`ret N` = callee 清栈；调用者 `add esp,N` = cdecl。
  例：`0x425AD9` 是 stdcall（`ret 8`）、`0x43623B` 是 cdecl（调用方 `add esp,4`）、`0x42A423` 是 stdcall（`ret 4`）。
- **冲突组**：同一地址可能已有别的补丁 ⇒ 阶段 ③ 必须核对（`特技重叠分析.md` 记了 18 个特技里 **8 组共用地址**）；
  **跳转目标撞别人的洞，区间求交查不出来** ⇒ 只能靠 `_补丁体检.py` 的专门报告。

### 9.6 ★ 选洞：`_改动总账.py` 的"可用代码洞"表**不能直接当可写清单**

现读该表前几名（`0x4EEA3D` 71139B、`0x4D34F1` 51983B、`0x4C0820` 43424B、`0x508C03` 27645B、`0x4E7E2D` 27603B、`0x457E2E` 5439B…）

## 第 10 节　★「原地保留」还是「外部化 + 重定位」？（用户 2026-10-15 提问）

> **用户原话**：「**移除后为什么还要在汇编里面保留不必要的代码啊？这样不会占用内存或者代码行吗？
> 你可以做个存储特技的工具，需要了就整理新的跳转偏移地址就好了，没必要还留在原 Ekd5 吧**」

### 10.1 先回答"占不占内存/代码行"（三条事实，别凭直觉）

| 问题 | 事实 |
|---|---|
| **占运行时内存吗？** | **不占（几乎）**。NOP 掉的代码**不执行**；而且它和活代码**同在一个 4KB 页**里 ⇒ 这一页**本来就要加载** ⇒ **几乎省不出 RAM**。PE 节**不能按页回收**，所以"删掉几十字节"对内存没有可观测影响。 |
| **占文件/节空间吗？** | **占**（就是那几十~几百字节）。但我们压根不缺空间：`_改动总账.py` 现读**30 个候选洞**（`0x4EEA3D` 71KB、`0x4D34F1` 52KB…），我们自己的洞（`0x457DB4` 起）才用了 **122 字节**。 |
| **那为什么还留？** | 留的**不是"不必要的代码"，而是"零风险的退路"**：① 相对位移（`E9/E8/Jcc`）是**按原地址算死的**，原地保留 ⇒ 复活时**不用重算、不用重新验收**；② 三件套（地址+字节+SHA）仍可追溯；③ 一个功能一个 hook 一个洞（纪律 2），删了洞就断了这条链。 |

### 10.2 外部化的**真实代价**（用户方案要付的账）

| 代价 | 说明 |
|---|---|
| **必须重算 rel** | 整体刚性搬迁时：**模块内**相对跳转位移**不变**（两头一起动）；**模块外**目标（引擎函数、钩子回跳点）**必须重算** ⇒ 需要工具（见 10.4）。 |
| **钩子点也要跟着改** | 原址的 `E9 rel32`（跳到洞）也是"模块外引用洞"的一条 ⇒ 必须一起重生成。 |
| **必须重做验收** | 五级证据里第 2~5 级（写回、运行时读回、受控启动、游戏内验收）**全部作废重来**。"字节对了"不等于跑得对。 |
| **可追溯性下降** | 代码离开了它原来的 SHA ⇒ 下次别人 diff 总账时看不到它，容易"幽灵代码"。 |

### 10.3 ⇒ 采用规则（**默认小、例外大**）

| 场景 | 做法 |
|---|---|
| 只是**不想要这个特技**（常见） | **原地 NOP**（第 9.2 节手法 ③）+ 退役档案留字节 ⇒ **不要搬** |
| 要**回收一大块空间**给新功能（≥ 几百字节，且该功能短期不会复活） | 才走**外部化**：导出档案 → 清空原区 → 需要时用 `_特技重定位.py` 装到新洞 |
| 要**跨构建/跨版本复用**同一实现 | **必须外部化**（原地址在新构建里未必还是洞） |

### 10.4 工具：存储那一半**早就有**，缺的是"装到新家"

| 能力 | 工具 | 说明 |
|---|---|---|
| **存储**（导出退役档案） | `_特技退役-提取.py` | 产出 `特技退役档案\<名>\`：`README.md` + `meta.json` + `patch\*.txt` + `原字节\*.bin` |
| **复活**（**原址**写回） | `_特技退役-复活.py` | 读档案，把原始字节写回**同一 VA**（走 `_dsh写锁.py`） |
| **★ 重定位装配**（搬到**新**地址） | **`_特技重定位.py`（本轮新建）** | 自动重算所有**模块外**相对位移，输出可直接用的补丁文本 |

`_特技重定位.py` 的语义（**第一版踩坑后修正，务必记住**）：

* **模块内**目标（跳转目标也落在被搬区间里）⇒ 位移**不变**（跳转是相对的，两头一起动）；
* **模块外**目标（`0x40C7D8` / `0x4287A8` / `0x42E4FD` / 回跳 `0x440672`…）⇒ **重算**，目标地址保持不变；
* **绝对立即数**（`push 0xF6`、`mov eax,0x4F0004`）⇒ **不动**（同映像内搬家仍有效）；
* **绝对地址指向被搬区间内部**（表/指针自引用）⇒ **报"需人工重指向"**；
* **rel8 且目标是模块外**、搬得太远（>±127）⇒ **报错**，需先人工改成 `0F 8x rel32` 形态再整段重生成。

**判据（现读，可复现）**：把现役暴击预览洞 `0x457DB4`（87B）搬到 `0x458800`（+2636）——
7 条相对跳转逐条重算（4 条模块外 `call/jmp` 位移改变、3 条模块内 `Jcc` 位移**不变**），
`--roundtrip`（搬回原址）**逐字节一致 ✓**；搬到 `0x4D8000`（+524876）同样正常。

名表基址早在 2026-10-14 就由 `0x4CC800` 更正为 **`0x4CC600`**（判据：GBK 搜「覆海之龙」命中 `0x4CC600`；

**但工具与部分页仍用旧值** ⇒ 会让"退役/复活"写错行（偏 32 行 = `0x200`）：
