# 策略射程判定 —— 属性表 + 段表 + 展开器（实读反汇编）

## 1. 结论速览

1. **策略射程 = 段表里的「相对坐标列表」**，不是半径数字：
   `范围号 = 运行时策略记录 +0x0C（Data.e5 +0x0D）` → `段指针 = dword[0x4D1400 + 范围号*4]` → 段内容是
   `(dx,dy)` 字节对，**以 `FF FF` 结尾**。
2. **下标就是范围号本身，不是「编号-2」**（此前库内“段表 `+(值-2)*4`”的说法只对某个特定调用点成立，
   通用路径 `0x42A6D1 / 0x43659C` 都是 `[eax*4 + 0x4D1400]`，直接用的范围号）。
3. 展开器（把段表变成可达格）= **`0x436511`**，`0x412B30`（策略先手的目标校验）调的就是它。
4. `0x4D19F0[策略号]` **不是射程表**，是策略类别标志（`>0x63` 且 `≠0xFF` 记为“特殊类”）；
   **`0x4D1600` / `0x4D1690` 不是射程表**：它们是 AI 使用策略的偏好/条件枚举（16 case，见页尾 S4 纠正节）；
   射程码来自 Data.e5 `+0x0D`（运行时 `+0x0C`）。

## 2. 已确认事实（证据 = 静态复读，样本 SHA 见下）

| 事实 | 地址 / 证据 |
|---|---|
| AI 限制值查表（不是射程） | `0x43987F  mov al, byte [eax+0x4D1600]`（另一分支 `0x439877 … [eax+0x4D1690]`） |
| 段表索引 | `0x42A6D1 / 0x42A80D / 0x4528D1: push dword [eax*4+0x4D1400]`；`0x43659C: mov edx,[eax*4+0x4D1400]` |

## 3. 与其它“范围”的区分（别再混）

| 机制 | 地址 | 用途 |
|---|---|---|
| **策略射程** | Data.e5 `+0x0D`（运行时 `+0x0C`）→ `0x4D1400` → (dx,dy) 段 | 策略能打到哪一格（本次要复用的就是它） |
| 物理支援范围（0x71 戮力同心） | `0x42E2B7` + `0x4091F4(0x50,2,2,0)` | 固定形状，与策略无关 ⇒ 不能用来判策略射程 |
| 施法可用性 | `0x417AF6` → `0x423FE8`(状态) + `0x472840`(MP) + `0x417B27` | **只判状态与 MP，不判射程** |
| 目标有效性 | `0x412B30` → `0x436511` | 取可达格并比对目标格 |

## 4. 复用于「移星易宿」的建议写法

候选单位能否用策略 S 打到攻方 A：

```
范围号 = byte[0x4A3E77 + S*0x61 + 0x0C]     ; = Data.e5 +0x0D（运行时已换位）
若 范围号 == 0x0B → 跳过（该方向无段表）
idx    = 范围号（0x00..0x0A）或 范围号-2（0x0C..0x25）   ; 0x436594 现读规则
段指针 = dword[0x4D1400 + idx*4]
   若 段指针 < 0x4D2000 或 >= 0x4D2600 → 跳过（idx 9 指向 0x452958 代码区，必须挡）
循环 (dx,dy) = 段[0],[1], …
   若 dx==0xFF 且 dy==0xFF → 结束（不可达）
   若 候选.X + dx == 攻方.X 且 候选.Y + dy == 攻方.Y → 可达
```

> ★ 2026-10-24 现读纠正：旧写法 `byte[0x4D1600 + S]` 已作废 —— `0x4D1600` 是 AI 使用偏好表（唯一读者 `0x43987F`），不是射程表。

- 这样**射程口径和引擎完全一致**，而且能在施法前就筛掉不可达的候选（避免白扣 MP/无效施法）；
- **枚举候选人仍然要遍历单位表**（引擎没有“按策略射程收集同阵营”的现成循环，`0x438EBD` 是 0x71 专用）；
  枚举 ≠ 判范围，两件事别混。

## 8. 实测补充：段表有异常项 + 必须做指针区间校验（2026-10-19）

> ⚠ **2026-10-24 标注：本节 §8.1~8.3 的 `0x4D1600` 写法是 v17 初版历史，已作废**（见 §9/§10 与页尾 S4）。
> 现行生成器读策略记录 `+0x0C`；下文保留仅为失败路径留痕。

### 8.1 段表不是连续的 0..11

`0x4D1400` 起逐项检查（合法 = 落在 `0x4D2000..0x4D2600`）：

```
编号0..8   → 合法（0x4D2228 … 0x4D2270）
编号9      → 0x00452958   ★ 异常：指向 .code 代码区
编号10..23 → 合法（0x4D2288 … 0x4D2336）
```

`0x4D1600[策略号]` 的取值分布（前 0x90 字节，⚠ 这是 **AI 使用码**，不是范围号）：
`5:40  13:79  2:1  3:1  14:4  4:2  6:2  7:5  10:2  11:2  15:4  12:2`
⇒ 该分布只说明 AI 偏好覆盖了 16 个 case 中的 12 个；**与射程上限无关**（范围码现读分布见页尾 S4）。

### 8.2 崩溃教训（真事）

按“范围号直接查段表、不做校验”的写法，遇到 **编号 9**（指针 `0x452958` 指向代码）时，
循环会把代码字节当 `(dx,dy)` 一路扫下去，扫到不可读区域 ⇒ **游戏闪退**
（表现为“敌军在策略射程外发起攻击时闪退”）。

**正确写法（已落到 v17）**：

```asm
mov al,[S]                       ; 特效值
movzx eax,al
dec eax                          ; ★ 策略号 = 特效值-1（0x4D1600 按策略号索引）
movzx eax,byte [eax+0x4D1600]    ; 范围号
cmp al,0x3F ; ja  skip           ; 上限放宽（真校验在下面）
mov eax,[eax*4+0x4D1400]         ; 段指针
cmp eax,0x4D1000 ; jb  skip      ; ★ 指针区间校验
cmp eax,0x4D2600 ; jae skip      ; ★
```

### 8.3 索引是「策略号」不是「特效值」

我们约定 `0xFC 特效值 = 策略号+1`，而 `0x4D1600` 按**策略号**索引 ⇒ 查表前必须 `dec eax`。
（v17 初版漏了这一步，读到的是“下一个策略”的范围号。）
段表终止判断 P0：0x4305E2/0x4305EB 的 83 FA FF/83 FB FF 与 movzx 不匹配，FF FF 不会命中，应改为 80 FA FF/80 FB FF。目标/攻方 call 0x4061F9 后也缺少 word[unit]=FFFF 哨兵检查。

## 16. ★★ 2026-10-21 22:0x 实测：`0x412B30` 的第 3 个参数走 **EAX**（T3 关键结论）

- **实测现场**（断点 `0x412B33`，一次干净命中）：`ret=0x4064B5`（调用点 `0x4064B0`）、`arg1=0x004A7BE0`（= `0x4A7B20+6*0x30`，**单位指针**，单位号 1 / 我方 / xy=(9,24) / HP=391）、`EAX=0xFFFFFF01`。
- **静态自洽**：`0x412B30` 序言后是 `push 0 / push 0 / **push eax** / push [arg1+6]`，所以第三个实参就是**调用者留在 EAX 里的 dword**，即 4 字节 packed 范围描述符。`0xFFFFFF01` = `01 FF FF FF` = 形状 1（九宫 9 格）+ 3 个 `FF`(跳过) —— 与 §16 之前的 v17 写法 `or eax,0x0B0B0B00` 完全同构。

## 19. CczEditor 预览的**可用边界**（2026-10-21 四张图 + 段表对算）

**一、预览确实是同一份段数据，但只在「装得进 7×7」时能数格**

- `0x20`（名「12格」）段 `0x4D2366` = (1,0)(1,1)(2,2) → 展开 = **3×3 方块 + 4 个孤立角格 = 13 格**（5×5 范围）。截图 7×7 全图与该形状**逐格一致**（含 4 个孤立角格这种细节，不可能是巧合）⇒ 编辑器用引擎同一份形状数据渲染。

## 23. ★ EFFAREA.E5 条目格式解析 + `0x4B5FD0` 填充者（T16，2026-10-22 Trae 静态）

> 样本：`E5\Effarea.e5` 67927 B，SHA256 `BF12D0AD47261E022B220EAFFCB801CBAABF9A69EB3B565CC8579F849E23FE1E`
> 研究副本：`大鲸鱼产生专用\_EFFAREA-研究副本-20261022.e5`（**只读复制**，SHA 与原文件一致；未用 CczEditor 改码、未保存）
> 本节闭合 §22 边界两条：①「条目格式未解析」；②「`0x4B5FD0` 由谁填充」。

### 23.1 结论速览

1. 文件 = **`Ls12` 头(16 B) + 256 B 调色板 + 10×12 B 索引项(0x110~0x187) + 4 B 零终止(0x188) + 10 个 PNG（从 0x18C 起）**。
2. 每个条目是**完整 PNG**：**64×64、8 bit**；N=0~8 为 color type 6（RGBA），N=9 为 type 2（RGB）。
   ⇒ `0x47E09B(0,0,0x40,0x40,dest)` 的 `0x40/0x40` = **目标表面 64×64**，与 PNG 尺寸逐条一致。
3. 索引项 12 B = **[size(BE32)] [size 重复(BE32)] [offset(BE32)]**（三项均大端）。
4. **码 N → 条目偏移公式**：
   ```
   off(N)  = BE32( file[0x118 + 12*N] )
   size(N) = BE32( file[0x110 + 12*N] )      # +4 处是同一值的重复
   data(N) = file[off(N) : off(N)+size(N)]   # 完整 PNG
   ```
