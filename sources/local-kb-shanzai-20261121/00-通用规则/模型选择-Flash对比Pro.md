## 三、结合本项目需求的决定性理由

1. **Pro 不能读图**。本项目有像素级美术链路（R/S 人物形象、地图、战场、E5 资源、宝物图标），
   Pro 无法看图 → 看图任务只能走 Flash。这是硬性排除项，不是偏好问题。
2. **能力上限 Flash 更高**（官方实测），逆向/写桩/剧本指令解析这类重推理任务不吃亏。
3. **本项目 99% 输入是缓存命中**（系统提示 + 知识库稳定复用），
   V4.1-Flash 的 KV Cache 压缩让这个模式的成本进一步放大优势。
4. **500 → 2500 并发**：多子智能体并行（批量诊断、批量补丁判定）时 Flash 不会撞限流。
5. **改错地址的代价远高于模型差价**。本项目要改 Ekd5.exe 偏移、写桩、搬特技，
   一次写错的重装/回滚成本 >> 省下的 50 元。所以要的是「上下文稳定」，不是「中途换模型」。

### Pro 的唯一合理场景
同一 Bug 反复卡住（如反复崩溃定位、跨版本行为不一致又查不出原因）时，
**单次**切 Pro 换个推理路径当「第二意见」，**不要作为长会话主力**（长会话换模型会丢掉既有上下文的连续性优势）。
