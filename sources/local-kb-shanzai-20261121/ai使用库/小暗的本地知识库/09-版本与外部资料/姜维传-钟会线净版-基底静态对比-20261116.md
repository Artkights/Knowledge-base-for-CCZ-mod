## 二、核心结论：两套完全不同的构建体系

**不是"同基底打不同补丁"，而是两条独立路线：**

- **6.6 山贼**：原版曹操传引擎（老编译时间戳），靠 `koeicda.dll` 等外部 DLL + 内存补丁（改立即数 / 借洞塞函数 / inline hook）扩展。
- **钟会线净版**：**C++ 重编译引擎 + 内嵌 Lua 5 解释器 + 脚本化战斗调度**，机制逻辑大量下沉到 Lua 脚本（`lua_battle_scheduler_v46.lua`、`buildings.lua`）。

## 三、PE 结构差异要点

### 1. 编译链与运行库（最关键差异）
- 对方导入 **MSVCP140.dll(43) / VCRUNTIME140.dll(20) / api-ms-win-crt-* 全套** ⇒ 现代 **MSVC C++ 工具链**重编译。
- 6.6 无 C++ 运行库，导入 `koeicda.dll(12) / GDIPLUS / Jpg` ⇒ 原版引擎 + 外部核心 DLL。

### 2. 节表布局完全不同
- 6.6：`.code / .text1 / .text2 / .text3 / .btdata / .rsrc / .api…`（原版多节分布，含 `.btdata` 补丁数据节）。
- 对方：`.text(1.54MB) / .rdata / .data / .idata / .reloc / .rsrc / .00cfg / .tls`（标准 C++ 编译单大 `.text` + TLS，**无 `.btdata`**）。

### 3. 安全特性
- 对方 `DllCharacteristics=0x8140`（含 ASLR/NX 等），6.6 为 `0x0`（无）。
- 对方有 TLS 目录、394 个重定位项、2 个调试目录；6.6 均无。

### 4. 入口点
- 6.6 `0x817e0` vs 对方 `0x10a0`，完全不同。

## 四、Lua 内嵌证据（对方独有，6.6 完全没有）

对方 EXE 内字符串命中：`Lua 5.`(2) / `lua_`(5) / `coroutine`(5) / `require`(14)，且**未导入任何 lua*.dll** ⇒ **Lua 5 解释器静态链接/内嵌进 EXE**。

配合目录内脚本：
- `lua_battle_scheduler_v46.lua`（协议版本 46）：AI 目标选择、伤害预测评分、协程调度，"所有 native 操作在恢复本协程前返回"。
- `buildings.lua`：临时建筑（路障/平台/粮仓/门等）时长与属性，加载于新战场/读档。

⇒ 对方把**战斗调度、AI 评分、临时建筑**等逻辑放到 Lua 脚本层，native 层只做底层操作。这是与 6.6"改引擎字节打补丁"根本不同的构造方式。
