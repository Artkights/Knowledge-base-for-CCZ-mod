## 结论速览

1. **特技是通过「桩」调用的**，形态统一：
   ```asm
   004210F4  55 8B EC 6A 00 6A 00 6A 43 6A 00 E8 8B 40 00 00 5D C3
             push ebp / mov ebp,esp / push p1 / push p2 / push <特技号> / push <名表id>
             call 0x0042518F / pop ebp / ret
   ```
   ⇒ **4 个参数**：`p1`、`p2`（特效值/标志）、**第 3 个 = 特技号**、**第 4 个 = 名表 id**（实测逐一对上）。
2. **两组编号绝不能混**（此前 `_tmp_核对桩起点.py` 混淆，导致一串假"不一致"）：
   - **名表 id**（`0x00`、`0x01`…）= 决定**显示名字**（名表 `0x4CC600` 第 id 项）
   - **桩内特技号**（`0x43`/`0x1B`/`0x25`/`0x5E`…）= 引擎内部特技编号（禹夏工具称「**装备特技号**」）
3. **禹夏工具箱三列口径定案**：`编号 = 名表id` ｜ `装备特技号 = 桩内特技号` ｜ `桩起始点 = 桩入口`。
4. **全量扫描结果（本样本现读）**：判定调用点 **213** 个（`0x4101D9` 148 / `0x42518F` 58 / `0x413009` 7），
   覆盖 **163 个名表 id**，其中 **154 个可回溯到桩入口**，40 个 unresolved。
5. **桩的统一出口 = `0x0042518F`**，与库页 `01-核心引擎\地址语义与Hook契约.md` 登记的 **`ability_check_wrapper`（特技包装判定）** 是同一地址 ⇒ 禹夏从"桩"侧、库内从"核心引擎"侧，**两头对上**。

### P2-1｜41 个 unresolved 的成因（已分类，工具 `_桩参数诊断.py`）

判据：把 `back_args` 的 `maxsteps` 由 24 加大到 96（且不越过所在函数的 `55 8B EC` 入口）后重试。

| 分类 | 数量 | 说明 |

### 参数化桩的重要澄清

`0x40399F` **并不直接调用三个判定入口**，而是：
```asm
004039A5  8B 45 F8        mov eax, [ebp-8]      ; 特效值（调用者传入）
004039A8  3C 06           cmp al, 6
004039AA  73 44           jae 0x4039F0
004039AC  83 C0 08        add eax, 8            ; ★ 特技号 = 特效值 + 8
004039B6  E8 79 29 03 00  call 0x436334          ; ← 另一条判定入口，非三入口之一
```
⇒ 该类桩的**特技号由"特效值 + 8"算出**（`al` 0~5 ⇒ 特技号 8~13），故**天然不产生 4 个立即数**；`0x436334` 是**第四条判定入口**（本页此前只登记三条，待补扫）。

## 2026-10-16 ★★ 定案：桩四参数之 `stack`（第 2 个 push）四值语义 —— `0x40BF2F` 是解释器

### 一、追链路径（三层转发后才到解释器）

```
桩: push eff / push stack / push equip / push per / call 0x42518F
  └ 0x42518F（双渠道包装）      不改参数，留给下游
      └ 0x4101D9（核心判定）    push [ebp+0x14]/[ebp+0x10]/[ebp+0xC]/[ebp+8] → call 0x41301E（原样转发，不解释）
          └ 0x41301E（渠道B）   push [ebp-4] / push [ebp+0x10](=stack) / push [ebp+8] → call 0x4198BE
              └ 0x4198BE        mov ecx,[ebp+0xC](=stack) → call 0x413009
                  └ 0x413009    cmp ecx,2 ⇒ 仅对 2 特判；其余原样
                      └ 0x40BF2F   ★★ 四路分派（真正的解释器）
```
（`0x413009` 只有 15 条指令：`cmp ecx,2 / jne / test edx,edx / jne / mov edx,eax`，然后 `call 0x40BF2F`；`call` 不清 ECX ⇒ `0x40BF2F` 仍能看到 stack。）
