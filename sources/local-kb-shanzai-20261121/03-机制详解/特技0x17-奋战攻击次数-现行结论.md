# 特技 0x17「奋战攻击」次数按特效值 —— 现行结论

> **状态（2026-10-24 现读）：当前样本未安装。**
> 样本 `Ekd5.exe` SHA256 `8F55EB4756A406A00D18B3CAC576008D76BA61E7E82C7E6C9A8E1B0974B4A44A`
> 现读：`0x436476 = 80 7D F8 02 73`（原版 `cmp byte [ebp-8],2`）、`0x457EC0` 22 字节全 `90`
> 目标：**奋战攻击（`0x17`）的攻击次数 = 引擎合并后的特效值 V + 1**（原版固定 `2+1=3` 次）
> 证据：静态反汇编 + 实机验收（`4018=1`；V=3 ⇒ 4 次、V=4 ⇒ 5 次）

## 结论速览

1. **原版行为**：`0x436476` 硬编码上限 `2` ⇒ 循环外先打 1 次 + 上限 2 ⇒ **固定 3 次**。
2. **v2 现行方案**：把 `0x436476` 的 5 字节换成 `call 0x457EC0`，洞内 22 字节调引擎桩 `0x478E5D` 取特效值，再与计数 `[ebp-8]` 比较 ⇒ **总次数 = V + 1**。
3. **已实测**：V=3 ⇒ 打 4 次；V=4 ⇒ 打 5 次（旧版固定 3 次）。**V=2 与旧版上限撞车，无法区分**。
4. **当前样本未安装**；`_应用补丁通用.py` 预演三段前像**全部一致**（2026-10-24 现读，见下）。
5. **引导攻击 `0x18` 同构**（原版 `0x42133D cmp byte [ebp-8],2`），补丁已实测「可以了」；两补丁挂点/洞完全不同 ⇒ **可共存**。
6. **v1 已退役**：自写循环只扫个人特技表 `[0x4F0004]`，找不到 `0x17` 就 `al=2`；「v1 漏装备渠道」**未证实**（见 §已知边界）。

## 现行补丁（v2）

| 段 | 地址 | 原字节 | 新字节 |
|---|---|---|---|
| 挂点 | `0x436476`（5B） | `80 7D F8 02 73` | `E8 45 1A 02 00`（`call 0x457EC0`） |
| jae 尾字节 | `0x43647B`（1B） | `11` | `90` |
| 代码洞 | `0x457EC0`（22B） | `90`×22 | `8B 4D FC E8 95 0F 02 00 38 45 F8 0F 83 BC E5 FD FF E9 A6 E5 FD FF` |

洞内反汇编（22B）：

```asm
0x457EC0  mov  ecx, [ebp-4]        ; 攻击者指针
0x457EC3  call 0x478E5D            ; 引擎桩 ⇒ al = 合并后的特效值
0x457EC8  cmp  byte [ebp-8], al    ; [ebp-8] = 本次攻击计数
0x457ECB  jae  0x43648D            ; 计数 ≥ 特效值 ⇒ 结束
0x457ED1  jmp  0x43647C            ; 否则继续下一次
```

**次数公式**：计数从 0 起，第 1 次在循环外已打 ⇒ **总次数 = V + 1**。
`v1` 的硬编码 `cmp [ebp-8],2`（= 3 次）正好等于 `V=2` 的情形，公式自洽。

## 验收判据

1. 前提：`4018`（集气模式）= 1（`0x505EC8`）。
2. 给 `slot 0`（或任意单位）的特技槽装 `0x17`，特效值设 V（`[特效号][特效值][经验][剩余回合]`，槽偏移 = 角色号×1024 + 槽号×4）。
3. 在 **≥ V+1 个敌军旁**攻击，观察实际攻击次数 = **V+1**。
4. 历史实测：**V=3 ⇒ 4 次；V=4 ⇒ 5 次**（均通过；判据以游戏内观察为准，五级证据第 5 级）。

## v1（已退役）与 v2 的差别

| | v1 | v2（现行） |
|---|---|---|
| 挂点 | `0x43646D`（15B） | `0x436476`（5B） |
| 洞 | `0x457E2E`（77B） | `0x457EC0`（22B） |
| 取值 | **自己扫个人特技表 `[0x4F0004]`** 找 `0x17` 取 `[+1]` | **调引擎桩 `0x478E5D`**，用引擎合并后的值 |
| 找不到 `0x17` | `mov al,2`（仍是 3 次） | `al==0` ⇒ `cmp [ebp-8],0` ⇒ 立即结束（1 次） |

v1 洞体关键反汇编（77B）：

```asm
0x457E2E  inc  dword [ebp-8]
0x457E31  cmp  byte [ebp-0x14], 0x17
0x457E35  je   0x457E71                 ; 当前就是 0x17 ⇒ 直接回
0x457E37  movzx eax, byte [ebp+8]       ; slot
0x457E3B  imul  eax, eax, 0x30
0x457E3E  movzx ecx, word [eax+0x4A7B20]; 角色号
0x457E45  shl   ecx, 0xA                ; ×1024
0x457E48  mov   edx, [0x4F0004]         ; 个人特技表基址
0x457E4E  add   ecx, edx
0x457E50  mov   edx, 0x100              ; 最多 256 槽
0x457E55  cmp   byte [ecx], 0x17
0x457E58  je    0x457E69
0x457E5A  cmp   byte [ecx], 0xFF        ; 空槽 ⇒ 停
0x457E5D  je    0x457E65
0x457E5F  add   ecx, 4 / dec edx / jne 0x457E55
0x457E65  mov   al, 2                   ; 找不到 ⇒ 默认 2
0x457E69  mov   al, byte [ecx+1]        ; 找到 ⇒ 特效值
0x457E6C  cmp   byte [ebp-8], al / jae 0x457E76 / jmp 0x43647C
```

**⇒ v1 只遍历 `[0x4F0004]`（个人特技表）是反汇编铁证** ✓
**⇒ 「装备渠道存在且不在个人表里」没有证实** —— 库内只有 `0xF6`（物理易伤）的装备挂例；`0x17` 能否装备/兵种挂仍是开放项 ⚠

## 引导攻击 `0x18`（同构，已实测）

| 段 | 地址 | 原字节 | 新字节 |
|---|---|---|---|
| 挂点 | `0x42133D`（5B） | `80 7D F8 02 73` | `E8 BE 6B 03 00`（`call 0x457F00`） |
| jae 尾字节 | `0x421342`（1B） | `16` | `90` |
| 代码洞 | `0x457F00`（22B） | `90`×22 | `8B 4D FC E8 C8 91 FC FF 38 45 F8 0F 83 48 94 FC FF E9 2D 94 FC FF` |

原版 `0x42133A inc byte [ebp-8]` / `0x42133D cmp byte [ebp-8],2` / `0x421341 jae` ⇒ 固定 3 次。
`0x18` 与 `0x17` 的**桩入口不同**（`0x4210D0` vs `0x478E5D`），但**桩内号都是 `0x36`**。
用户实测确认「可以了」（见旧页 §120）。

## 已知边界 / 待验证

* **装备挂 `0x17` 未证实**：库内无证据；`0x17` 能否装备/兵种挂是 P1。若要在编辑器里试，挂完后读 `[0x4F0004] + 角色号×1024` 看 `0x17` 是否出现在个人表里（出现 ⇒ 个人表即合并态，v1 也不漏；不出现 ⇒ v1 确实漏）。
* **`0x4101D9` 的 4 次循环 = 遍历攻击者周围 4 格**（§124 反汇编定案），**不是**“4 个特技渠道”；`0x4359F5` 是邻居坐标计算，不是迭代器。
* **第三个数据点 V=5 ⇒ 6 次未测**；**上限未测**：`al` 是字节 ⇒ 理论最大 255 ⇒ 256 次，可能先卡在目标数/动画时长。
* **`2A555B0B…` 不是纯原生样本**：含 18 条搬回补丁 + 两处预览门（`0x43BECE` 8B、`0x43C2DD` 6B）。历史底座应记 `D5A2F54C…`（两处门控皆 NOP，无搬回）。
* **`0x42133D` 原版尾字节是 `16`**（本补丁前像）；旧稿若写 `11` 是奋战版的 `0x43647B`，别混。
* 两处预览门 `0x43BECE` / `0x43C2DD` 属伤害预览旁支，与本补丁无直接关系。
