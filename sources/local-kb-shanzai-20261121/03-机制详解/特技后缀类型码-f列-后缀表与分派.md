# 特技后缀类型码（f 列）— 后缀表、分派与格式串

> 用户口径 2026-10-16：「**ue 这块区域的 f 列，都是兵种特技对应的后缀**，你可以检索对应一下，**后续我可能做后缀编辑器**」。
> 本页把"f 列 → 后缀"整条链**现读**清楚（样本 SHA `DE4AE18414AD04A41158243A6FCCB12FBE6DED53E7EFF930425751D5A804B02B`）。

## 结论速览

1. **f 列 = 兵种特技名表（`0x9E800` / VA `0x4CC600`）每行偏移 `15` 的那个字节 = 后缀类型码**，不是"显示开关"。
2. **分派代码**：`VA 0x4621C1` .. `0x462271`（`cmp al,1` / `cmp al,2` / `cmp al,7` + 指针表取值 + 两个格式化调用）。
3. **后缀指针表**：`VA 0x462274`（文件 `0x61674`），索引 = **`f-1`**，共 6 项 ⇒ `f=1..6`：

   | 索引 | 指向 | 字符串 | 对应 f |
   |---|---|---|---|
   | 0 | `0x48E6A8` | `+%d` | `01` |
   | 1 | `0x48E694` | `+%d%%` | `02` |
   | 2 | `0x48E69C` | `-%d%%` | `03` |
   | 3 | `0x48E695` | `%d%%` | `04` |
   | 4 | `0x48E6B0` | `%d` | `05` |
   | 5 | `0x48C541` | `%d次` | `06` |

4. ★★ **函数开头有"没有拼接目标就什么都不加"的早退**（**纠正**我先前"`f=00` ⇒ 显示 `--`"的说法）：
   `0x4621C1 cmp dword [ebp+0xC],0` → `je 0x462236` → `jmp 0x462269`（`mov eax,[ebp-4] … ret 0xC`）
   ⇒ **`arg3`（`[ebp+0xC]`，拼接目标）为 0 时直接返回、不追加任何后缀 ⇒ 显示为空白**。
   ⇒ **`f=00` 的实际表现是"空白"**（✅ 用户实机：`0x02 破妄归真` 后缀**空白**）；
   `--`（`0x48E6AC`）只在"有拼接目标"的调用上下文才会被拼上。
5. **`f=01` 的两个特例**：值 `[ebp-4] == 0xFF` ⇒ 用 `0x48E6A4`（`色`）；值 `== 0` ⇒ 用 `--`；否则 `+%d`。
   ⚠ **用户口径（2026-10-16）**：`色` **估计也是备用空值**（不是展示文案）；`--` 同理只在特定上下文出现。
   ⇒ **"空白 / 备用空值"这一族不要当作展示语义**，编辑器按"无后缀"处理。
6. **`f ≥ 07` = 文字描述类**：先 `call 0x460510`（生成说明文本到 `[ebp-0x1C]`），再以 `0x48E6C4`（`%s`）拼接
   ⇒ 这类特技显示的是**一段文字**而不是"数值+后缀"（例：`0x80/0x81/0x82 能力替换`、`0x95-0x97 穿透攻击`、`0x9B-0x9D 远距攻击`、`0x9F 方寸天地`、`0x33 致命一击`）。

## 二、实现·使用方法（做"后缀编辑器"要改哪里）

1. **改某个特技的后缀** ⇒ 改 `Ekd5.exe` 文件偏移 **`0x9E800 + 号*16 + 15`** 的 1 个字节为新的 f 值（`00`..`06`，或 `≥07` 走文字描述）。
   ⚠ **`f=00` 与两处特判（值=0 / 值=0xFF）按"无后缀/占位"处理**，不要当成可选的展示样式。
2. **改后缀文案本身**（例如把 `+%d%%` 改成别的）⇒ 改格式串池内的字符串（**注意每串 4 字节对齐、以 `00` 结尾**，且**不能比原串长**以免踩到后一个串）：
   `+%d`@`0x48E6A8`、`+%d%%`@`0x48E694`、`-%d%%`@`0x48E69C`、`%d%%`@`0x48E695`、`%d`@`0x48E6B0`、`%d次`@`0x48C541`、`色`@`0x48E6A4`、`--`@`0x48E6AC`、`%s`@`0x48E6C4`。
   ⚠ `0x48E695`（`%d%%`）是**从 `+%d%%` 的中间切进去**的复用（`+%d%%` 在 `0x48E694`）⇒ 改 `+%d%%` 会**连带改掉 `04` 的后缀**，必须一起考虑。
3. **新增 f 取值**（`≥07` 的文字描述）⇒ 由 `0x460510` 生成，属于代码侧改动，**不能只改表**。
4. **数据来源**：`大鲸鱼产生专用\_特技名表.tsv` / `.json`（列含 `特技号 / 十进制 / 名字 / 显示flag(=f 列) / VA / 文件偏移 / 原始16字节`）⇒ 编辑器可直接读。

## 三、风险与边界

- `f` 只影响**显示**，不改变特技的战斗效果（效果由该号的实现代码决定）。
- `f=1` 与 `f=2` 有"值=0/0xFF"的特判 ⇒ 同一个 f 在不同数值下显示不同（空白 / `--` / `色`）。
- `f≥07` 的文本由 `0x460510` 产出，**文本内容取决于该函数与特技号**，不是格式串能改的。

## 四、证据来源

- 分派代码：`VA 0x4621C1`（`cmp dword [ebp+0xC],0` 早退）→ `0x4621C8`（`cmp al,0`）→ `0x4621F2`（`cmp al,1`）→ `0x462213`（`cmp al,2`）→ `0x46223B`（`cmp al,7`）→ 指针表 `0x462240 mov ecx,[eax*4+0x462274]` → `0x462249`（`call 0x460510` + `%s`）。
- 后缀指针表：`VA 0x462274`（文件 `0x61674`）6 项 dword；格式串池：文件 `0x8D08C`..`0x8D0B4`。
- 表结构：`0x9E800` 255×16（名字 12B GBK + 2B 零 + **f 1B**）。
- 实机：用户 2026-10-16 确认 `0x02 破妄归真` 后缀**空白**。

## 五、待验证项

- ✅ **已由用户实机确认（2026-10-16）**：`f=00` 的特技（`0x02 破妄归真`）后缀**是空白**（不是 `--`）
  ⇒ 对应代码里的 **`arg3 == 0` 早退分支**（`0x4621C1 je 0x462236`）；我先前"显示 `--`"的读法**已更正**。
- ✅ **用户口径**：`f=01` 且值 `= 0xFF` 时的 `色`（`0x48E6A4`）**估计是备用空值**，不是展示文案。
- 仍待：`0x460510` 对 `≥07` 各 f 值的具体分支差异（不同 f 是否产出不同类型文本）；
  以及 `f=00` 在"有拼接目标"的上下文里究竟何时真的显示 `--`（哪个 UI/调用方传了非 0 的 arg3）。

## 六、`f ≥ 07` 的文本生成器 `0x460510`（2026-10-16 扫描）

**签名**：`0x460510(al = f 值, ecx = 值, edx = 输出缓冲)`（调用点 `0x462249`：`mov ecx,[ebp-4] / lea edx,[ebp-0x1C] / call 0x460510`）。
**性质**：**按 f 值分支的文本生成器** —— 输出一段文字，随后由调用点用 `%s`（`0x48E6C4`）拼到特技名后面。

**扫描到的分支与文本来源**（`VA 0x460510`..`0x460660` 逐字节扫 `cmp al,imm8` / `push imm32` / `mov r,imm32`）：

| f | 分支 | 文本来源 |
|---|---|---|
| `07` | `0x4605C8` | 分支存在（内容待读） |
| `08` | `0x46058F` | 分支存在（同段还用 `cmp cl,6`） |
| `09` | `0x4605BA` | 分支存在 |
| `0A` | `0x460561` | 分支存在 |
| `0B` | `0x46056B` | 分支存在；该段有 `mov ecx,0x48B3E1` = 字符串 **「全能力」** |
| `0C` | `0x460554` | **指针表 `0x40620A`**（`mov ecx,[ecx*4+0x40620A]`） |
| `10` | `0x460517` | **指针表 `0x41CCD6`**（`mov ecx,[ecx*4+0x41CCD6]`，前置 `cmp cl,3` / `and cl,3`） |
| `11` | `0x46052C` | **名表行 `0x49` 的 `+9` 处**（`push 0x4CCA99`）—— 即取该行名字的**后半段** |
| `12` | `0x4605AF` | 分支存在 |
| `13` | `0x460540` | **名表行 `0xA9`**（`push 0x4CD090`，该行名字现读 = 「回马攻击」） |

**结论（对后缀编辑器）**：
- `f ≥ 07` 的显示文本**由代码生成**（从名表其它行 / 指针表 / 固定字符串拼），**改 f 值只能切换分支，不能自定义文案**；
- 想改 `≥07` 的文案 ⇒ 要么改它引用的**名表行**（`0x9E800 + 行*16`）或**字符串**（如 `0x48B3E1` 的「全能力」），要么改代码；
- `0x0D / 0x0E / 0x0F` 三个 f 值在本次扫描窗口（`0x460510..0x460660`）内**未见分支** ⇒ 可能在窗口之外或用别的方式分派，**待补扫**。

## 七、`0x460510` 完整分支表（函数边界 `0x460510`..`0x4605D5`）＋两张指针表清单（2026-10-16 补扫）

**函数边界现读**：`0x460510 push ebp … 0x4605D2 mov esp,ebp / pop ebp / ret`（后面 `0x4605D6` 起是 `90` 填充）
⇒ **`0x460510` 的函数体只有 0xC6 字节**，所有分支都在里面。

**接口推论**：`0x462249` 处 `call 0x460510` 之后，调用方用 **`%s`**（`0x48E6C4`）把**`ecx` 指向的字符串**拼上去
⇒ **`0x460510` 是"把文本指针写进 `ECX` 返回"**（`edx`/栈上缓冲只是暂存）。

| f | 分支 VA | 文本来源（现读） |
|---|---|---|
| `07` | `0x4605C8` | `dec ecx` → `call 0x484002` ⇒ **按（值−1）查 Data/策略记录** ⇒ 文本 = **该策略/记录的名字**（与 §一 的 `0x5D 攻击追加 / 0x5E 策略先手 / 0x5F 策略反击` 吻合） |
| `08` | `0x46058F` | 分支存在（含 `cmp cl,6`） |
| `09` | `0x4605BA` | `mov eax,[ebp-0xC]` → `call 0x423D45` ⇒ 文本由 `0x423D45` 产出 |
| `0A` | `0x460561` | 分支存在 |
| `0B` | `0x46056B`；`0x460588 mov ecx,0x48B3E1` | 字符串 **「全能力」**（`0x48B3E1`） |
| `0C` | `0x460554` | **指针表 `0x40620A`**（见下） |
| `10` | `0x460517` | **指针表 `0x41CCD6`**（`[值 & 3]`，见下） |
| `11` | `0x46052C` | `push 0x4CCA99 / call 0x460600` ⇒ **名表行 `0x49` 的 `+9` 字节处**（取该行名字后半段） |
| `12` | `0x4605AF` | `call 0x4837C2` |
| `13` | `0x460540` | `push 0x4CD090 / call 0x460600` ⇒ **名表行 `0xA9`**（现读「回马攻击」） |
| **`0D` / `0E` / `0F`** | **无分支** | 落到 `0x4605CA jne 0x4605D2` ⇒ **直接返回、不生成文本**（`ecx` 保持原值）⇒ 界面上应是"无附加文本"，**待实机确认** |

**⚠ 认字更正**：`0x48E6A4` 的 GBK 字节 `C9 B1` = **`杀`**（`U+6740`）—— 我先前写的 **"色"是错的**（色 = `U+8272` = `C9AB`）。
它同时出现在两处：`f=01` 且值 `= 0xFF` 的分支（`0x462201`）与 **`0x41CCD6[3]`** ⇒ 与"攻击/策略/杀"这一组同族，**更像有意义的文案而非空值占位**（与用户"备用空值"的判断不同，建议实机再看一眼）。

### 7.3 对"后缀编辑器"的最终口径

| f | 能否由表自定义文案 | 说明 |
|---|---|---|
| `00` | —（无后缀/空白） | 引擎 `arg3==0` 早退 |

## 九、★ 更正与扩展：后缀有**两族消费者**（`0x460510` 之外还有一族）——2026-10-16 深夜

> 起因：并行会话的 `待验证清单` 记有一条「后缀 flag `7`~`0x14` 段格式串待挖（**实测存在 `0x0B/0x0F/0x10/0x11`**）」，
> 与本页 §7 的「`0x0D/0x0E/0x0F` 本构建无分支」**看似冲突** ⇒ 复核后确认：**两句话各自都对，但指的是两族不同的消费者**。

### 9.1 族一：`0x460510`（数值后缀，兵种特技名表展示路径）

见本页 §3–§7：后缀指针表 `0x462274`（`f=1..6`）+ 各 `≥07` 分支；**`0D/0E/0F` 在此函数里确实没有 case** ⇒ 走默认（不生成文本）。

### 9.2 ★ 族二：`0x461FC8` → `0x461ED6` → …（说明/名词拼接路径）

- **调用者**：`0x4697F3 call 0x461FC8`（另一处 UI；其后用 `[ebp+ecx*4-0x5C]` 的 256 项指针表按号取名再拼接）。
- **`0x461FC8` 的形状**（`0x461FC8`..`0x462048`，`ret 0x10`）：
  * `cmp ch,2 / jb`（**f < 2**，注意这里用 `ch` = 该 16 位值的高字节 ⇒ 与族一同一个 flag）；
  * `f <= 2` ⇒ `imul eax,eax,5 / add eax,0x486AE0`（**属性名表 `0x486ADB` 的下一条目起**）+ 格式 **`"%s +%u"`（`0x48E680`）**；
  * `f == 0x0A` ⇒ `call 0x40B8A5`；
  * **`f >= 0x0D` ⇒ 转交 `0x461ED6`**（`push 1 / push [ebp+0x10] / push [ebp+0xC] / push [ebp+8] / call 0x461ED6`）。
- **`0x461ED6` 及邻近（扫 `0x461E00..0x462100`）见到的 case/来源**：
  * `cmp al,09`（×2）、`cmp ch,2`、**`cmp al,1A`**、`cmp cl,1C` / `cmp cl,28` / `cmp cl,1B`、`cmp al,05`、`cmp al,0FF`；
  * 字符串/格式：**`"%s (%s)"`（`0x48E660`）**、`"%s"`（`0x48E66B`）、`"%s +%u"`（`0x48E680`）；另有 `0x4B68FC` / `0x4B6900`（`.api` 内的空串/占位串）；
  * 调用链里出现 `0x4837C2`（族一 `f=12` 也调它）、`0x40B3D7`、`0x40B460`、`0x4067CE`、`0x40B8A5`、`0x4230F9`、`0x43AD20` 等。
  ⇒ **`0x0B/0x0F/0x10/0x11` 以及最高到 `0x1A` 的"格式串"就在这一族** ✓——**与并行会话的实测观察一致**。

### 9.3 结论（给编辑器的口径）

1. **后缀号（名表偏移 15 的字节）在两族里是同一个字段**，但**两族各自实现一部分取值**：
   * 族一（`0x460510`）：数值后缀 `01`–`06` + 文字 `07`–`13`（`0D/0E/0F` 缺）；
   * 族二（`0x461FC8`/`0x461ED6`）：说明/名词拼接，覆盖含 **`0x1A`** 的更宽取值（`0x0B/0x0F/0x10/0x11` 在这里有实现）。
2. 因此**不要**只说"某 f 值无实现"——必须写清**是哪一族**（本页 §7 的说法限定为族一）。
3. 待挖（P2）：族二各 case 的**完整映射表**（尤其 `0x0B/0x0F/0x10/0x11` 与 `0x1A`），以及它到底服务哪个界面（`0x4697F3` 的调用者链）。

## 十、★ 名表字段宽度复核：**偏移 14 并非恒为 0**（2026-10-16 深夜）

> 动机：族二分派里出现 `cmp ch,2`（**高字节**判断），提示"后缀号"可能不是单字节字段 ⇒ 对两张名表逐行统计 `[13]/[14]/[15]`。

### 10.1 现读统计（兵种特技名表 `0x9E800`，255 行）

| 偏移 | 分布 |
|---|---|
| `[13]` | `00`×254、`DB`×1 |
| **`[14]`** | `00`×253、**`AA`×1、`ED`×1** |
| `[15]` | `00`×80、`01`×5、`02`×31、`03`×11、`04`×70、`05`×10、`06`×5、`07`×3、`08`×2、`09`×6、`0A`×7、`0B`×12、`0C`×3、`0D`×3、`0E`×1、`0F`×4、`10`×1、`12`×1 |

**`[14]` 非 0 的两行（就是它们）**：
- 行 **`0xAA`**：`[13]=00 [14]=AA [15]=00`，名字 = **封锁攻击范围**
- 行 **`0xED`**：`[13]=00 [14]=ED [15]=04`，名字 = （空）

### 10.2 判读（**已确认** vs **推断**）

- **已确认**：`[14]` **不是**恒 0 的填充 —— 至少 `0xAA`/`0xED` 两行有值；因此**不能**把"后缀号"简单当成"名字后 3 字节全 0 + 第 4 字节"的结构来处理（写编辑器时若把 `[14]` 归零，会**破坏这两行**）。
- **推断（待证）**：该字段可能是 **16 位小端**：`[14]` = 低位、`[15]` = 高位；族二代码里的 `cmp ch,2` 判的就是**高位**（= `[15]`），`cl` = 低位（= `[14]`）。
  ⇒ 若成立，则"后缀号"应读作 **`[14] | ([15]<<8)`**，而不是单字节 `[15]`。
  ⚠ 但族一（`0x460510`）里 `01`–`06` 的分支明显是按**单字节**取值（后缀指针表 `[f-1]`），两者需要一次**实机/断点**才能定论。
- **对「后缀编辑器」的安全建议**：**只改 `[15]`，绝不把 `[14]` 清零**（保持原值即可），除非先证明 `[14]` 是保留字节。

### 10.3 待验证

1. `[14]` 的语义（类别？扩展位？）—— 需要：① 读族二 `0x461ED6` 里 `ch` 的来源（哪个字段送进 `[ebp+0xC]`）；② 实机看 `0xAA`/`0xED` 两行特技的显示差异。
2. `[13]`（`0xAA` 行的 `DB`、宝物表多行的非 0）是否属于**前一行名字的溢出/残留**（名字 12B 满 12 字符时无 0 结尾，会侵入 `[12]`、`[13]`）—— 这更可能，因为"封锁攻击范围"正好是 **6 个汉字 = 12 字节**（**无 0 终止符**！）⇒ **`[12]`/`[13]` 被名字占满**，`[13]=00` 却… 嗯，6 汉字占 `[0..11]`，`[12]` 起应是 0；`[14]=AA` 仍无法用此解释。
   ⇒ 仍列为待验证（**不要**据此改任何字节）。

   ⇒ 与 §8 的 f 表**逐条一致** ⇒ **`f=1..6` 现在是双证据**（第一份 `0x460510` 字符串表 + 第二份本表）。
2. **`f=0x09` = 五围/移动力简称表 `0x48EC6A`（3 B/项）**：`攻 / 防 / 精 / 爆 / 士 / 移`（现读前 6 项，之后即非表数据）；
   索引由 `0x40BAD4(…, 0x20)` 算出 ⇒ 值疑为**位掩码**（bit0..bit5）。
   ⇒ 与第一份的 `f=0x08`（属性名，5 B/项 `0x486ADB`）对照 ⇒ **`0x08` = 全名 / `0x09` = 简称**（第一份 `0x09` 的"组合"分支待复核）。
3. **`f ≥ 0x10`（除 `0x10`）⇒ 第二份实现写空串**（`0x4283E7`）⇒ 禹夏表 `0x11`–`0x14` 在本构建第二份里**不支持**（第一份待查）。
4. **`f=0x10` 格式串 = `0x48B58C` = `"%s"`** ⇒ 表项字符串（武器/防具/辅助/ALL）**直接就是后缀文本**。

## 十一·补（2026-10-16 24:5x）：`f=0x09` 更正为「单属性简称」；`f=0x0A/0x0B` 满掩码 = 「全能」；第一份支持到 `f=0x13`

**更正（重要，取代本页 §8 的旧口径）**：
- **`f=0x09` = 单属性简称**（两份实现**都** `call 0x423D45` ⇒ 索引 `值÷32` ⇒ 表 `0x48EC6A`（3 B/项）= **攻/防/精/爆/士/移**）；
  ⇒ 本页 §8 原写「`0x09` = 属性组合」**是错的**（把 `0x0A` 的行为记到了 `0x09`）。
- **`f=0x0A` = 六项掩码（`0x3F`）**、**`f=0x0B` = 五项掩码（`0x1F`）**；**掩码满 ⇒ 后缀 = 「全能」**（串 `0x48B3E1` 现读 `C8 AB C4 DC C1 A6 00` = 「全能」）；
  掩码不满 ⇒ `call 0x423D96`（按位置拼属性名）。

**第一份实现（`0x460510` 系）的支持范围（现读）**：`0x07` 策略名 ｜ `0x08` 属性名（5 B/项 `0x486ADB`）｜ **`0x09` 单属性简称** ｜ `0x0A`/`0x0B` 掩码（满⇒全能）｜ `0x0C` 表 `0x40620A`（范围形状名）｜ `0x10` 表 `0x41CCD6` = [`0x500C4D`,`0x500C49`,`0x500C4E`(运行时缓冲), `0x48E6A4`] ｜ **`0x11`** `0x460600(0x4CCA99)` ｜ **`0x12`** `call 0x4837C2` ｜ **`0x13`** `0x460600(0x4CD090)` ｜ `0x14` 未见。
⇒ **本构建至少支持到 `f=0x13`**（第二份 `0x428350` 系只到 `0x10`）⇒ 编辑器可选值范围建议按**第一份**取。

**⚠ 与 §十·补 的口径差异提醒**：本页 §十·补 曾写"禹夏 `0x11`–`0x14` 在本构建第二份里不支持"——**该句只对第二份成立**；第一份支持 `0x11`/`0x12`/`0x13`（详见上）。

## 十二·补（2026-10-16 25:1x）：**行布局定案**（`[14]` = 效果 ID，不是保留位）+ `f=0x11`/`0x12` 疑原始缺陷 + `f=0x14` 无实现

**★★ 行布局（最终口径，取代本页此前"只改 `[15]`"的模糊表述）**

| 字段 | 含义 | 编辑器可否改 |
|---|---|---|
| `[0]`..`[12]` | **名字**（≤13 字节；`[13]` 应为 `00` 终止符；详见 §47 规则） | ✅ 可改（≤13 字节，>13 警告、>14 拒绝） |
| `[13]` | 名字终止 `00` | ✅ 随名字维护 |
| **`[14]`** | **效果 ID**（★有强证据：在「忽视攻击/防御/精神/速度/士气」上**逐行 +1**（`9C`→`A0`）；后续行名直接把 id 写进名字，如 **`A3空效果`/`A4空效果`**） | ❌ **必须原样保留** |
| **`[15]`** | **f 列 = 后缀码** | ✅ **唯一允许改的字段** |

**新增两条"引擎原始问题"（与初版逐字节一致，非本 MOD 引入）**：
1. **`f=0x11`**：`0x460530 push 0x4CCA99` ⇒ 基址**不是 16 的倍数**（row `0x49` = `0x4CCA90`，`+9` 落在名字中）——若为 `0x4CCA90` 则语义为「辅助攻击力 / 辅助防御力」一对，**疑原始笔误**；
2. **`f=0x12`**：`0x4837C5 imul ecx,ecx,0x19`（步长 25）索引 `0x49F820`，而该处数据是 **16 B/项**（`0x49F7C0` 区「忽视攻击/防御/精神/速度/士气」行，`[14]` = 效果 id `9C`→`A0`）——**步长与数据不符**。
⇒ **编辑器建议**：对 `0x11`/`0x12` **加警告**（"引擎此处索引疑似原始缺陷，实机显示需自行确认"）。

**`f=0x14`：两份实现都没有**（第一份 `0x460510` 函数体已完整读完至 `0x4605D5 ret`，分支覆盖 `0x07/0x08/0x09/0x0A/0x0B/0x0C/0x10/0x11/0x12/0x13`；第二份 `0x428350` 对 `f ≥ 0x10` 除 `0x10` 外置空）
⇒ **可选 f 值上限 = `0x13`**。

## 十三·补（2026-10-17 06:4x）：**f 值支持矩阵（定稿）** + 第三处外层分派 `0x4621C8` + `0x48E6A4` = 满值符号

**★ 存在三处按 f 分派的实现**（此前只记了两处）：
1. `0x460510`（第一份，只处理**高段** `f=0x07`–`0x13`，`f≤6` 直接 `ret`）；
2. `0x428350`（第二份，通用；`f=0x10` 由 `0x452C81` 特判）；
3. **`0x4621C8`（外层分派，本轮新发现）**：`cmp al,0` ⇒ **`f=0`**（值 `0x1C`/`0x28` 走特殊分支，其它值**清零**）；`cmp al,1` ⇒ **`f=1`**（**值 `0xFF` ⇒ 用满值符号 `0x48E6A4`**）；`0x462249` 再调 `0x460510`。

**★ f 支持矩阵（并集口径）**：

| f | 第一份 | 第二份 | 外层 | 语义 |
|---|---|---|---|---|
| `0x00` | ❌（直返）| 默认含 0? | ✅ | 空白（值 `0x1C`/`0x28` 例外） |
| `0x01`–`0x06` | ❌ | ✅ `0x462274` | ✅（f=1） | `+%d`/`+%d%%`/`-%d%%`/`%d%%`/`%d`/`%d次` |
| `0x07`/`0x08`/`0x09` | ✅ | ✅ | — | 策略名 / 属性全名 / 属性简称 |
| `0x0A`/`0x0B` | ✅ | ✅ | — | 六项(满⇒全能) / 五项 |
| `0x0C` | ✅ | ✅ | — | 范围形状名 |
| **`0x0D`–`0x0F`** | **❌** | ✅ | — | 方向 / 地形 / 攻击·策略·ALL |
| `0x10` | ✅ `0x41CCD6` | ✅ `0x452CCD` | — | 装备类 |
| `0x11`/`0x12`/`0x13` | ✅ | ❌ | — | 掩码→名表行 / `0x4837C2` / …（**0x11、0x12 有引擎原始不一致，加警告**） |
| **`0x14`** | ❌ | ❌ | — | **不可用** |

⇒ **编辑器口径**：**可选 f = `0x00`–`0x13`**（`0x0D`–`0x0F` 仅第二份支持；`0x11`–`0x13` 仅第一份支持）；**`0x14` 禁用**。

**★ `0x48E6A4` 语义修正**：它不是"某个汉字串"，而是 **"值 == `0xFF`（满/无限）时用的符号串"**（GBK `C9 B1`，单符号）—— 出现在 `f == 1 && 值 == 0xFF` 的分支；本页 §十二·补 里"第一份 `f=0x10` 表第 4 项"的说法需按此复核。
