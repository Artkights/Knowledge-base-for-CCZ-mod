# 修罗之怒与全能力结算链

> **补丁设计、改动字节、工具链、当前进度 → 见《[修罗之怒改造-总纲与交接](修罗之怒改造-总纲与交接.md)》**。
> 本页只维护**引擎事实**（结构、地址、语义、判据）。

## 结论速览

- **特效表是 `255 × 16` 的指针型表**：指针在 `DWORD[0x500C3B]`，本样本 = `0x511000`；fatal 段 `0x512000`。
  行结构 = **4 × [UInt16 人物token + BYTE 值] + 2 × [BYTE 兵种号 + BYTE 值]**（即"4+2"）。
- **特效值恒为 1 字节**：读值链末端 `0x4198BD` 的 `0F B6 C0 / shr al,5` 用 `movzx al` 封顶；
  行内每个槽只有 1 字节 ⇒ **特效值不可能超过 255**。
- **特效值两处都存**：`Ekd5.exe` 的 `0x511000`（启动默认）**和** `SV\SVxxx.E5S` 的 `0x10000`（每档快照）。
  ★ **实机只读证据：读档后生效的是存档那份**（运行时表 == `SV000`/`SV001`，≠ exe 默认）⇒ 改值要改存档。
- **三条渠道会「相加」**：`0x4101D9` 参1 = **人物/兵种特效号**（两者共用名称空间）、参2 = 宝物特效号、
  参3 = **叠加方式**（本样本修罗之怒 = `0` = 相加）。⇒ 人物槽 + 兵种槽 + 宝物全部按整数相加。
- **能力索引 0=攻 1=防 2=精 3=敏 4=士**，来源是 `[[ebp]+0x1C]`（`0x43CB00` 帧）。
- 查表最终转到 **`ExtendData.dll`**（经 `DWORD[0x4F0008]`），不是纯 exe。

## 已确认事实

### 1. 特效表结构与位置

```
指针槽 0x500C3B → 表基址（本样本 0x511000）
行 = 特技号 × 16 字节
    +0x00  4 × [UInt16 人物token][BYTE 特效值]   （12 字节）
    +0x0C  2 × [BYTE 兵种号][BYTE 特效值]        （4 字节）
```
- 兵种号字段实测取值只有 `1~79` 与 `255`（共 61 种），**255 出现 390/512** = 空槽；
  与清理口径「兵种=255、特效值=0」吻合。
- 实测样本：`0x51` = `00 04 08 | 00 04 0A | 00 04 0C | 00 04 1E | 49 10 | FF 1E`
  ⇒ 人物槽 `(1024, 8/10/12/30)`、**兵种槽 `(兵种 73, 16)`**。
- 人物 token 实测恒为 `1024`，与 `DWORD[0x505F78] = 0x400` 的比较关系**未完全拆开**（P1）。
- 行偏移速查：`0x51` = exe `0x511510` / 存档 `0x10510`；`0xF4` = exe `0x511F40` / 存档 `0x10F40`。

### 2. `0x4101D9`（效果值查询桩）与合并核心

| 栈参 | 含义 |
|---|---|
| 参1（栈顶） | **人物/兵种特效号**（共用名称空间；`255` 可作真实扩展编号） |
| 参2 | **宝物特效号**（独立名称空间；`0` = 禁用该渠道） |
| 参3 | **叠加方式**：`0`=相加 `1`=取大 `3`=按位或 |
| 参4 | 效果值方式 |

- `ECX` = 待判定单位指针；`ret 0x10`；返回值 `EAX` = 开关或特效值。
- ★ **`0x4101D9` 会解引用 `EDX`**（`0x4101F1` 的 `mov ecx,[edx]`，随后 `cmp ecx,[0x505F78]`）。
  改写调用方时**必须保证 EDX 是有效指针**，否则踩空。
- 合并核心 `0x432640`：`movzx ebx,[0x4326E0]` → `test/jne` → flag `0` 走 `0x43269C`（原逻辑）、
  flag `1` = HP 模式、否则 = MP 模式；epilogue 在 `0x4326C0`；分支点 `0x432656`。
- 全局区 `0x4326E0`：flag 1 字节 + 8 个能力累加器 `0x4326E1..0x4326E8`（`0x4326E9..EB` 空闲）。
- 另一个常用包装：`0x42518F`（4 栈参 / ECX=单位 / `ret 0x10`），**不能区分"没有特技"与"特效值 0"**。

### 3. 宝物特效值的位置

- 存在**物品行 `+0x16`**：`Data.e5+0x818C` 起 104 行、`Star.e5+0` 起 151 行，**行长 `0x19`**。
- 行内：`+0x11` = 类型/辅助装备及消耗品的有效特效号，`+0x12` = 原始类别标记（2/3）或普通装备的有效号，
  `+0x16` = **宝物特效值**（实测取值 1~87，也是 1 字节）。
- ★ 宝物特效名表在 **`0x4CB600`**（raw `0x9D800`），与**人物/兵种特效名表 `0x4CC600`**（raw `0x9E800`）
  是**两套完全不同的表**（例：`0x51` 在宝物表叫「斗将」，在人物表叫「修罗之怒」；`0x6D` 宝物表 = 「鬼神之勇」）。
  ⚠️ 曾把 `0x4CD600` 误当宝物名表 —— 那其实是人物表的 `0x00~0x0F` 行。

### 4. HP 取值链（用于"每损失 2% 生命"这类触发）

| 用途 | 入口 | 说明 |
|---|---|---|
| 当前 HP | `0x41B500` | `mov eax,[ecx+0x10]` |
| 最大 HP | `0x407263(人物记录)` | → `0x407C29(5)` → `movzx eax,word[rec+0x1B]` → `0x405B86(职业,0x50)` → 夹 `0xFFFF` |
| 百分比乘除 | `0x425AD9(a,b)` | = `a*b/100` |

### 5. 说明栏（特技说明文字）链路

```
0x418DA0  movzx eax, byte [ecx+0x0F]    ← flag 取自名表行第 16 字节
0x418DA5  mov al, byte [ebp+0x10]       ← ★ 特效值在此被截成低字节
0x418DAD  call 0x428346 → jmp 0x452C81 → jmp 0x4322D3   （分派器）
0x4322D3  flag 分派；flag ≥ 0x10 时落到 0x43236E（原为 0x428350 的"空串"分支）
         格式串 0x4323D3 = "%s+%d%%"；写调用 [0x4862C0] = sprintf
回到 0x418DB2 → sprintf(输出, "%s %s"(0x48E668), 名表行, 说明文本)
```
- 名表行 = 15 字节 GBK 名称 + 第 16 字节 flag；**名称上限 15 字节 = 7 个汉字**。
- 能力名片段（可复用）：`0x4323DC`"攻" `0x4323DF`"防" `0x4323E2`"攻防" `0x4323E7`"精"
  `0x4323EA`"敏" `0x4323ED`"士" `0x4323F0`"精敏" `0x4323FA`"敏士"。

### 6. 扩展模块：`ExtendData.dll`

- `DWORD[0x4F0008] = 0x6B35BCA0`，**在 exe 映像之外** ⇒ 由 `AutoDLL.ini` 加载的 `ExtendData.dll`。
- 函数 = DLL RVA `0x5BCA0`；表基址 RVA `0x217E08`，**行长 `0x400`，256 项 × 4 字节**
  （`key` + 3 数据字节），`key == 0xFF` 终止、`key == 参2` 匹配；循环上界
  `DWORD[DLL+0x1D3A44] = 256`。
- 该表**超出 `.data` 的 RawSize(0x5800)** ⇒ 运行时填充。几何与 `Effect.e5`（1024 × 0x400）吻合（P1）。
- 本样本的 `ExtendData.dll` 与 `ExtendData_原始.dll` 相差 4543 段 / 133710 字节（P2，未分析）。

## 风险与边界

- ★ **"掩码 + 百分比"装在一个字节里，相加会失效**（掩码清空 / 加错能力 / 百分比漂移）：
  根因是掩码要"或"、百分比要"加"，而引擎只提供一种合并方式。解法与证据见总纲。
- ★ **改存档才生效**：只改 exe 的 `0x511000` 会在读档后被 `SV*.E5S` 冲掉。
- ★ **`0x4101D9` 依赖有效 `EDX`**（见上），任何改写调用方的地方都要先保存/恢复它。
- ★ **原版修罗之怒在 `0x45B69C` 有 `je 0x45B6DA`**：特效值为 0 时跳过后续算术，
  任何插在该点之后的钩子都会被绕过。
- 特效表行的 `0x0C` 之后是**兵种槽**，不是"4 字节尾巴"；改行时不要越界。
