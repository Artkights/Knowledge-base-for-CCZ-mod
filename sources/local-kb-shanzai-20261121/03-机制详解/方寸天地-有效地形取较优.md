# 方寸天地（个人 0x9F）：有效地形改为「取较优」并真正生效

样本：`复刻版6.6山贼\Ekd5.exe`
对照样本：`ai使用库\复刻版6.6\初版Ekd5.exe`（SHA256 `EDE480FE8DF843CB012E1EAC57ED64745A9C73EB4E190DED4A95A15CE4DC678E`，1130496 字节；节区布局与本工程一致，可按同一 VA 对照）

## 结论速览

- 方寸天地的引擎实现是**有效地形函数 `0x43FA56`**：有 `0x9F` → 地形 = 特效值 − 1；无 → 原地形。原逻辑是**硬覆盖**（站在发挥值更高的地形上会被强制改成 N）。
- 但它的**唯一调用者** `0x412557`（获取地形）在 `0x412584` 调它之后的 14 字节（`0x412589..0x412596`）**在初版与当前都是 NOP** → 返回给上层的始终是「原地形」，**方寸天地实际没有生效**。
- 已改造为「**地形保底**」并让它真正生效：`有效地形 = 原地形 与 N 中地形发挥值更高者`。两处改动共 143 字节（`0x43FA56` 129 字节 + `0x412589` 14 字节），补丁文件 `大鲸鱼产生专用/【6.6山贼】方寸天地-有效地形取较优.txt`（v3）。
- ⚠️ **v1/v2 曾静默失效（v3 已修）**：地形发挥表只有 **40 条**（`0x4A3517 + 兵种系*0x3C`，`40*0x3C = 0x960` 刚好接上策略表 `0x4A3E77`），而**兵种有 80 个**（`Data.e5 0x9DB4` 起 `80*0x23 = 0xAF0` 刚好接到地形表 `0xA8A4`）→ **兵种 ≠ 兵种系**。实测（存档 `SV001.E5S`）关羽 **兵种 = `0x31` = 49**：v1 直接被「兵种 ≥ 40 放弃」挡掉；v2 用 `兵种>>1`=24；**v3 改用引擎自带换算 `0x40BF0C`（`≤59 → 兵种/3`；`60..79 → 兵种-40`；`≥80 → 40`）→ 49/3 = 系 16**。
- **交叉验证**：系 16 的「平原」发挥值 = **105**，与情报界面显示的「平原 105%」完全一致 ✅；同系「村庄」= **112** ⇒ v3 生效后站平原应变为 `村庄 112%`。
- 只影响带 `0x9F`（或装备特效 `0x65`）的单位；其余单位返回值不变，战斗数值不受影响。**v3 已实机验证通过（用户 2026-10-13 确认「没问题了」）。**

## 适用版本

- 仅适用复刻版6.6山贼当前样本及其后续同源构建；改前必须核对 `0x43FA56` 与 `0x412589` 两处原字节（见「详细记录」）。

## 已确认事实

### 调用链（地形从哪来、到哪去）

```
0x412557  获取地形（ECX/栈参 = 战场编号）
  ├─ 0x403789、0x40167E：坐标/索引换算 → lea eax,[eax+ecx+0x640]
  ├─ movzx edx,[eax]              ; 原地形
  ├─ mov ecx,[eax+0x640]          ; 战场编号
  ├─ call 0x4061F9                ; get_unit_ptr：ECX = 0x4A7B20 + 编号*0x30（战术单位）
  ├─ call 0x43FA56                ; ★ 有效地形（0x9F 在此处理）
  └─ 0x412589..0x412596 = NOP×14  ; ★ 初版/当前都丢弃了上一步的返回值 → pop eax 返回原地形
        └─ 0x435991 单位地形（24 处调用，含战斗公式 0x437F9F、0x43818E、0x4385CB、0x43872F…）
              └─ 0x43F7B8 地形发挥/修正计算（11 处调用）
```

### 兵种地形发挥值

| 项 | 位置 | 说明 |
|---|---|---|
| 磁盘表 | `Data.e5 @ 0xA8A4`，40 条 × `0x3C` | 前 30 字节 = 30 种地形的**发挥值（百分数，越大越好）**；后 30 字节 = 移动消耗 |
| 运行时表 | `0x4A3517 + 兵种系 * 0x3C` | `0x41B7D2`：ECX = 兵种系 → ECX = 记录指针 |
| 取发挥值 | `0x41F62A` | `add ecx,[ebp+8]` / `movzx eax,[ecx]` / `ret 4`：ECX = 记录，栈参 = 地形 → EAX = 发挥值 |
| 人物 ID | 战术单位 `+0x00`（WORD） | `0x4061E4`：`push id` → ECX = `[0x4CEA00] + id*0x48`（人物记录） |
| 兵种 | 人物记录 `+0x2B` | `0x406610`：ECX = 人物记录 → EAX = 兵种 |

实测样本（`Data.e5`）：家族 0 = `108 108 103 103 103 50 50 100 100 95 …`；家族 3 = `110 110 90 92 90 50 50 95 90 90 …`；家族 20 = `105 105 115 115 115 50 50 90 90 90 …`。可见第 6/7 项多为 `50`（水域类惩罚），平原类多为 `105~110`。

### 初版 0x43FA56 的完整设计（对照用）

初版桩（`0x43FA56`，`ret` 不收栈，由调用者 `pop eax` 清理）：

```
push ebp / mov ebp,esp / push ecx
push 1 / push 1 / push 0 / push 0x9F / call 0x4101D9   ; 初版装备号为 0
test eax,eax / je
dec al                          ; N = 特效值-1
mov cl,[ebp+8]                  ; 原地形
cmp cl,0x12 / jb 覆盖            ; 原地形 < 0x12 → 覆盖
cmp cl,0x16 / jbe 保留           ; 0x12..0x16 保留原地形
覆盖: mov [ebp+8],al
; 之后还有：0x47D422 的 bit4 → 地形=0x12；0xFD（深陷泥潭）→ 地形=0x0A
mov eax,[ebp+8] / mov esp,ebp / pop ebp / ret
```

- 当前样本里，这段被裁成只剩「`0x9F` 覆盖」部分，且装备号被改成 `0x65`（宝物「天声震落」），其余（`0xFD`、`0x47D422`）为 NOP。
- 其后 `0x43FAC7..0x43FB26`（96 字节）是初版 `0xFD` 相关块的 NOP 残留，本补丁复用。

## 实现/使用方法

补丁文件：`大鲸鱼产生专用/【6.6山贼】方寸天地-有效地形取较优.txt`

| 改动 | 位置 | 内容 |
|---|---|---|
| ① 让结果生效 | `0x412589`（14 字节） | `89 04 24`（`mov [esp],eax`，覆盖栈上待 `pop eax` 的原值）+ 11×`90` |
| ② 新有效地形函数 | `0x43FA56`（129 字节） | 见下 |

新函数逻辑（入口 ECX = 战术单位指针，`[ebp+8]` = 原地形；出口 EAX = 有效地形；`ret` 不收栈，与调用者约定一致）：

```asm
push ebp / mov ebp,esp / push ebx / push esi / push edi / sub esp,0x10
mov  esi,ecx                     ; 战术单位
movzx ebx,byte [ebp+8]           ; 原地形
push 0 / push 1 / push 0x65 / push 0x9F
mov  ecx,esi / call 0x42518F      ; EAX = 特效值（双渠道判定包装，触发条件保持原样）
test eax,eax / jz  orig
dec  eax / movzx edi,al           ; edi = N
cmp  ebx,0x1E / jae orig          ; 原地形越界
cmp  edi,0x1E / jae orig          ; N 越界
movzx eax,word [esi]              ; 人物ID
cmp  eax,0xFFFF / je orig
push eax / call 0x4061E4          ; ECX = 人物记录
call 0x406610                     ; EAX = 兵种
cmp  eax,40 / jae orig
mov  ecx,eax / call 0x41B7D2      ; ECX = 兵种地形记录
mov  [ebp-0x14],ecx
push ebx / call 0x41F62A          ; EAX = 记录[原地形]
mov  [ebp-0x18],eax
push edi / mov ecx,[ebp-0x14] / call 0x41F62A   ; EAX = 记录[N]
cmp  eax,[ebp-0x18] / jbe orig    ; N 不更高 → 原地形
mov  eax,edi / jmp done
orig: mov eax,ebx
done: add esp,0x10 / pop edi / pop esi / pop ebx / mov esp,ebp / pop ebp / ret
```

- 回滚：`0x412589` 起 14 字节恢复 `90×14`，`0x43FA56` 起恢复原桩
  `55 8B EC 51 6A 00 6A 01 68 65 00 00 00 68 9F 00 00 00 E8 22 57 FE FF 85 C0 74 12 48`；
  或直接用备份 `Ekd5备份\补丁前备份\Ekd5.exe.bak_before_fangcun_20261013_041358`。

## 风险与边界

- **未做实机验证**：本页结论来自静态复读（当前 EXE + 初版对照）与数据结构核对。
- **作用面**：只有当单位拥有 `0x9F`（或装备特效 `0x65`）时才会进入比较逻辑；无技能单位返回原地形，与改造前完全一致。
- **越界保护**：原地形或 N ≥ `0x1E`、人物 ID = `0xFFFF`、**兵种系 > 40**（v3 由 `0x40BF0C` 给出）时返回原地形，避免读到移动消耗段或越界。
- **兵种 → 兵种系 的换算（已从引擎代码确认，v3 起直接调用）**：`0x40BF0C`（ECX = 人物记录 → EAX = 兵种系）

  ```asm
  0040BF0C  movzx eax, byte [ecx+2B]      ; 兵种
            cmp   al, 3B  / ja  L2
            mov   ecx, 3  / idiv ecx       ; ≤ 0x3B(59)  → 兵种系 = 兵种 / 3
  L2:       cmp   al, 50  / jae L3
            sub   al, 28                    ; 0x3C..0x4F(60..79) → 兵种系 = 兵种 - 40
  L3:       mov   al, 28                    ; ≥ 80 → 40（上限）
  ```

  **交叉验证**：关羽兵种 = `49` → 系 = `49/3` = **16** → 该系「平原」发挥值 = **105**，与情报界面显示的「平原 105%」**完全一致** ✅；同系「村庄」= **112** ⇒ v3 生效后站平原应显示/结算为 `村庄 112%`。
  （v1 直接拿兵种 49 被「≥40 放弃」挡掉；v2 用 `兵种>>1`=24 是错的。）
- **装备渠道 `0x65`**：当前桩的装备号为 `0x65`（宝物名表 = 「天声震落」）。也就是说带该特效的装备同样会获得「地形保底」。这是**沿用现状**，若不需要可把 `0x68 65 00 00 00` 改成 `6A 00`（装备号 0）。
- **说明显示未动**：`0x9F` 的显示 flag = `0x0E`（个人名表 `0x9E800+0x9F*16+15`），会按 `0x48C470` 表显示地形名，保持原样。
- **初版别的分支未恢复**：`0x12..0x16 保留原地形`、`0x47D422 bit4 → 地形 0x12`、`0xFD → 地形 0x0A` 三处初版逻辑本次**没有**搬回（用户只要求方寸天地取较优）。若要恢复需另开补丁。

## 地形发挥 `0x43F7B8` 的 11 个消费者（2026-10-13 补）

`0x43F7B8`（地形发挥计算）是 `0x435991`（单位地形 → 有效地形）的下游；**方寸天地/v3 改的就是这条链的源头**，所以它的作用面就是下面这些消费点：

|---|---|---|---|

| `0x437FAB` | `0x437E23` | `0x427795`、`0x43896D`、`0x43A8E9`、`0x43A9A1`、`0x43AEF8`、`0x43AF3E` | 战斗/AI 评估 |
| `0x4381D2` | `0x43817B` | `0x43806E`、`0x438085`、`0x438277`、`0x43828F`、`0x43AE96`、`0x43B05B` | 战斗计算 |
| `0x4385D4`、`0x438738` | `0x438484` | `0x40D949`、`0x40DEF0`、`0x40DF15`、`0x41E6FD`、`0x421D2A`、`0x43376C` | 战斗计算（一个函数两处消费） |

**实践含义**：

1. 方寸天地 v3 生效后，**战斗数值、能力面板、情报那行百分比**会同时跟着变（因为它们共用同一条「有效地形 → 发挥值」链）。
2. 若哪天只想让某个消费点受影响（例如只改战斗、不改情报显示），可以改在这些消费点自己的取值上，而不动 `0x43FA56`。
3. `0x40D2AB` 是调用面最广的一个（6 个上层），改动之前要特别留意它。
2026-10-22 0x9F 原始业务找到（DSH，静态）：现行样本 0x43FA56 的 13B+62B 被 NOP 擦除（只剩 检测→[ebp+8]=配置值-1→返回），但 10-14 旧样本（大鲸鱼产生专用\_自检工作区\skill_retire_tl6gqcg5\Ekd5.exe，mtime 10-14 04:49）里 0x43FA56 完整：push ebx/esi/edi; sub esp,0x10; mov esi,ecx; movzx ebx,[ebp+8]; push 0/1/0x65/0x9F; call 0x42518F; dec eax; movzx edi,al; cmp ebx,0x1E/jae; cmp edi,0x1E/jae; movzx eax,word[esi]; cmp eax,0xFFFF/je; call 0x4061E4; call 0x40BF0C（归类）; cmp eax,0x29/jae; call 0x41B7D2（兵种系）; push ebx/call 0x41F62A（地形发挥值1）; push edi/call 0x41F62A（地形发挥值2）; cmp eax,[ebp-0x18]/jbe。⇒ 0x9F=方寸天地：比较自身与目标地形发挥值（0x41F62A×2），取较优。现行样本因业务被 NOP 擦除而无实际效果。
