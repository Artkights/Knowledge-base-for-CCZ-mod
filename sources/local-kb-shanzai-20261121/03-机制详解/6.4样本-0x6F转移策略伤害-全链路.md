## 一、结论速览

1. **`0x6F` = 「转移策略伤害」**（名表 `0x4FFC50`，flag `0x04`）
2. **取值桩 = `0x41A6E8`**：`push 0 / push 1 / push 0x23 / push 0x6F` → `call 0x4101D9`（4-push 形态；类别码 `0x23`）
3. **处理函数 = `0x41A957`**（唯一调用者 `0x4251A6`）—— 真正实现
4. **包装 = `0x4251A0`**：`push [ebp+8] → call 0x41A957 → ret 4`（唯一调用者 `0x4231D5`）
5. **流程挂点 = `0x4231D5`**：在**策略伤害数组 `ctx+0x108+4*i` 全部写完之后**调用
6. **语义（现读推出）**：把打在该单位身上的**策略伤害按效果值百分比扣下来**，**转嫁给另一个单位**
   - 承接者选取：遍历全局表 `0x4AC748`（`0xFF` 结尾），跳过自己，取 **`+0x10` 字段最小者**
   - 写回：`sub [原目标槽], eax` → `add [承接者槽], 转移量`（带上限比较）

## 三、全链路（逐层）

### ① 名表
- **表基 = `0x4FF560`**（16 B/项：名字 14 B + `+0x0E/+0x0F` 两字节，`+0x0F` 疑似 flag）
- `0x6F @0x4FFC50` = **转移策略伤害**，`flag=0x04`
- 邻近对照：
  | id | 地址 | 名字 | flag |
  |---|---|---|---|
  | `0x6D` | `0x4FFC30` | 精神替换防御 | `0x00` |
  | `0x6E` | `0x4FFC40` | 攻击替换精神 | `0x00` |
  | **`0x6F`** | **`0x4FFC50`** | **转移策略伤害** | **`0x04`** |
  | `0x70` | `0x4FFC60` | 无视特殊防御 | `0x00` |
  | `0x71` | `0x4FFC70` | 戮力同心 | `0x05` |

### ② 取值桩 `0x41A6E8`（唯一调用者 `0x41A995`）
```
0x41A6E8  push ebp
0x41A6E9  mov  ebp, esp
0x41A6EB  push 0
0x41A6ED  push 1
0x41A6EF  push 0x23          ; 类别码
0x41A6F4  push 0x6F          ; ★ id（前后夹着 NOP，说明此桩被手工改过）
0x41A6F9  call 0x4101D9      ; 取效果值
0x41A6FE  pop  ebp
0x41A6FF  ret
```
> `0x4101D9` 是**取特技效果值入口**（6.4 与 6.6 前 6 字节一致：`55 8B EC 51 33 C0`）
> 注意：6.4 **没有** 6.6 的 `0x42518F`「分流包装」（那一段在 6.4 是 NOP 区）

### ③ 处理函数 `0x41A957`（真正的实现；唯一调用者 `0x4251A6`）
```
0x41A957 push ebp / mov ebp,esp / push 0,0,0 / sub esp,0x1C
; ---- 第 1 段：数列表长度（0xFF 结尾，列表项在 +0xD 起）----
0x41A963 mov  ecx, [ebp+8]              ; 参数 = 目标列表
0x41A968 cmp  byte [ecx+edx+0xD], 0xFF  ; 找 0xFF 终止
0x41A972 mov  [ebp-0x20], edx            ; 长度
; ---- 第 2 段：遍历目标 ----
0x41A97A loop: i < len
0x41A989   mov  ecx, [eax+ecx+0xD]       ; 第 i 个目标槽
0x41A98D   call 0x4061F9                  ; 槽 → 人物记录（0x30 步长）
0x41A995   call 0x41A6E8                  ; ★ 查有没有 0x6F
0x41A99A   test eax,eax / je 下一个        ; 没有 ⇒ skip
0x41A99E   mov  [ebp-0x18], eax            ; 保存「效果值」
0x41A9A1   call 0x425B12                    ; 分配 4800 B 缓冲
0x41A9A6   push 0 / 0 / 0x50 / 2 → call 0x41A854   ; 策略结算辅助（见下）
; ---- 第 3 段：挑承接者（最小 +0x10）----
0x41A9BF   [ebp-0x10] = 0xFF（未定）
0x41A9C8   al = byte [i + 0x4AC748]         ; ★ 全局候选表（0xFF 结尾）
0x41A9DA   cmp  cl, byte [[ebp+8]+1]         ; 跳过「自己」
0x41A9E2   call 0x4061F9                      ; 候选槽 → 记录
0x41A9E7   call 0x41B500                       ; = mov eax,[ecx+0x10] 取字段
0x41A9EC   cmp  eax, [ebp-0x28] / jae 下一个    ; 取最小
0x41A9F1   [ebp-0x28]=eax ; [ebp-0x10]=cl        ; 记下最优承接者
; ---- 第 4 段：写回伤害数组 ----
0x41AA0B   lea  eax, [ctx + ecx*4 + 0x108]        ; ★ 策略伤害槽（ctx = 0x497AF8）
0x41AA14   cmp  edx, [ebp-0x18]
0x41AA1B   push [ebp-0x18] / call 0x425AD9          ; 百分比乘算：转移量 = 伤害×效果值%
0x41AA24   sub  dword [ecx], eax                     ; ★★ 原目标 -= 转移量
0x41AA26   cmp  eax,[ebp-0x28] / ja ; mov [ebp-0x28],eax
0x41AA3F   al = byte [list + i + 0xD]                ; 找承接者在列表里的项
0x41AA4C   mov  eax, [ecx + edx*4 + 0x108]           ; 承接者的伤害槽
0x41AA53   add  eax, [ebp-0x28]                       ; ★★ 承接者 += 转移量
0x41AA56   cmp  eax, [ebp-0x24] / jbe                ; 与上限比较（防溢出/封顶）
```

### ④ 被调辅助
| 地址 | 现读 | 含义 |
|---|---|---|
| `0x425B12` | 库内既有 | 分配 **4800 字节**缓冲 |
| `0x41A854` | `cmp [ebp+0xC],0x50` → `mov ecx,0x497AF8` → `movzx eax,byte [ecx+0x4FB]` → `call 0x407C00` → `call 0x436511` | **策略结算辅助**：`0x497AF8` 是**策略独立上下文**，取 `+0x4FB` 一个字节 |
| `0x41B500` | `mov eax,[ecx+0x10]; ret` | **取单位记录的 `+0x10` 字段**（用于挑"最小者"）|
| `0x4061F9` | 库内既有 | 槽 → 人物记录（**0x30 步长**）|
| `0x40658F` | 库内既有 | 取人物运行时记录（**0x48 步长**）|
| `0x425AD9` | 库内既有 | 百分比乘算 |

### ⑤ 包装与流程挂点
```
0x4251A0  push ebp / mov ebp,esp
0x4251A3  push [ebp+8]
0x4251A6  call 0x41A957          ; ★ 转交处理函数
0x4251AB..0x4251B2  nop（6 个）
0x4251B3  mov esp,ebp / pop ebp / ret 4
```
**唯一调用者 = `0x4231D5`**，位于策略伤害结算函数内：
```
0x4231B2  mov [ecx+edx*4+0x108], eax   ; 先把每目标的策略伤害写进数组
0x4231C3  mov byte [ecx+edx+0x401], al  ; 写目标标志
0x4231CB  call 0x44DE9E                  ; 目标后处理
0x4231D0  jmp  0x423177                  ; 继续循环
...
0x4231D2  push [ebp-8]                    ; ★ 循环结束后
0x4231D5  call 0x4251A0                    ; ★ 进入 0x6F 转移
0x4231DA  mov  ecx,[ebp-8]
0x4231DD  cmp  byte [0x500C46], 0          ; 全局开关
0x4231E6  call 0x4390A9                     ; 另一判定
```
⇒ **时机**：**策略伤害全部算完并写进 `ctx+0x108+4*i` 之后、应用之前**，才做"转移"。

## 四、⚠ 与 6.6 的关键差异（移植必看）

| 项 | 6.4（本页）| 6.6（当前工作样本）| 影响 |
|---|---|---|---|
| 名表基 | **`0x4FF560`** | `0x49F400` | **不能混用** |
| `id 0x6F` 的含义 | **转移策略伤害**（flag `0x04`）| **「作者懒得删的」**（已废弃，无消费者）| **同 id 不同含义，绝不能套用** |
| 分流包装 `getter` | **无**（`0x42518F` 是 NOP 区）| `0x42518F` = 分流包装 | 桩形态不同 |
| 代码节 | `.text` + `.data2(0x4CE000)` | `.code` + `.text3(0x4CE000)` | 结构相似但命名不同 |
| 策略上下文 | **`0x497AF8`**（与 6.6 相同）| `0x497AF8` | ✓ 可沿用 |
| 策略伤害数组 | **`ctx+0x108+4*i`** | 同 | ✓ 可沿用 |
| 0xFF 终止列表 | `0x436499`/本页 `+0xD` 项 | 同族 | 需现读核对 |

**移植到 6.6 时的风险点**：
1. `0x41A957` 这类"处理函数"在 6.6 **可能不存在**（6.6 的 `0x6F` 已废弃）⇒ 需要自己实现等效逻辑
2. 承接者选取用的是 `+0x10` 字段最小者 —— **6.6 里 `+0x10` 是 HP（u16）**，语义要重新确认
3. 6.4 的 `0x4AC748` 候选表在 6.6 是否同址/同构，**必须现读**
4. 6.4 的包装 `0x4251A0` 前后是 NOP，说明这段是**被作者改过的位置**；6.6 对应位置不一定有空间

0x6F 桩     0x41A6E8  → call 0x4101D9 @0x41A6F9

## 六、🐞 bug 复查：「被转移伤害杀死的人会原地满血复活」（2026-10-17 23:38 追加）

> 用户口径：承接者 = **血最低的**；现象 = **被策略转移杀死的人原地满血复活**。
> 以下均为 **6.4 样本现读**（SHA `9D9B3B33…`），两条候选根因都附地址。

### 6.1 相关指令（现读）
```
; 转移量计算
0x41AA19  push eax                    ; &伤害槽
0x41AA1A  push edx                    ; 原伤害
0x41AA1B  push [ebp-0x18]            ; 0x6F 效果值（百分比）
0x41AA1E  call 0x425AD9                ; ⇒ eax = 原伤害 × 效果值 / 100（**无符号 div**）
0x425AD9: mov eax,[ebp+0xC] / imul eax,[ebp+8] / xor edx,edx / mov ecx,0x64 / div ecx

; ★ 原目标扣伤害：**没有下限保护**
0x41AA23  pop  ecx                    ; ecx = &原目标伤害槽
0x41AA24  sub  dword [ecx], eax        ; ★★ 原伤害 -= 转移量（可能变负）

; ★ 承接者加伤害：**钳到不超过其 HP**
0x41AA4C  mov  eax, [ecx+edx*4+0x108] ; 承接者当前伤害
0x41AA53  add  eax, [ebp-0x28]         ; + 转移量
0x41AA56  cmp  eax, [ebp-0x24]         ; 与 [ebp-0x24] 比（= 承接者 +0x10 = 血）
0x41AA59  jbe  0x41AA6D
0x41AA5B  mov  eax, [ebp-0x24]          ; 超血 ⇒ 取「血」值（可以刚好打死）
0x41AA6D  lea  ecx, [ecx+edx*4+0x108]
0x41AA74  mov  [ecx], eax                ; 写承接者伤害

; ★ 被转死的承接者被「追加进列表」
0x41AA60  mov  eax, [ebp-0x10]           ; 承接者槽号
0x41AA63  mov  byte [ecx+edx+0xD], al     ; 写进列表项
0x41AA67  inc  dword [ebp-0xc]             ; 新增计数
0x41AA8A  push -1 / push eax / push (list+0xD+len) / call 0x47FD13   ; 0x47FD13 = 按字节填充(memset 型)
0x41AA9C  add  esp, 0xC
```

### 6.2 候选根因 ①（最可能）：**原目标伤害变负数 ⇒ 反向加血**
- 转移量 = `原伤害 × 效果值%`（**无符号乘除**）
- 只要**效果值 > 100**（例如 120/150），转移量就**大于原伤害**
- `0x41AA24 sub` **没有下限** ⇒ 原目标伤害槽变**负数**
- 负数伤害在"扣 HP"环节会被当成治疗/或触发死亡保护 ⇒ 表现就是 **HP 反而变满**

### 6.3 候选根因 ②：**被转死的承接者被 append 回列表 ⇒ 二次处理**
- 承接者的伤害被 `cmp/jbe/mov` **钳到 ≤ 它的血**（`0x41AA56-0x41AA5B`）⇒ **刚好能打死**
- 打完却把该单位**写进列表 `+0xD` 并计数**（`0x41AA60-0x41AA67`），末尾用 `0x47FD13` 把新项补齐
- ⇒ 列表被扩容后，同一流程很可能**又遍历到它** ⇒ 二次结算 ⇒ 出现"满血/异常"

### 6.4 一处强证据：**作者把保护 NOP 掉了**
```
0x41AA14  cmp  edx, dword ptr [ebp - 0x18]    ; 原伤害 vs 效果值
0x41AA17  nop
0x41AA18  nop        ← ★ 这里原本是一条 2 字节指令（74 xx / 76 xx / EB xx）
0x41AA19  push eax
```
⇒ 原意极可能是「**原伤害 ≤ 效果值时就分支掉**」（即 `min(转移量, 原伤害)` 的保险），
**被 NOP 成两个 90 ⇒ 保险被拆掉** ⇒ 与"效果值 > 100 就会出问题"完全吻合。

### 6.5 复刻时的正确写法（避开这两个 bug）
在 6.6 上复刻时按这个逻辑写，**两个坑一起避掉**：
```c
// 对每个「有 0x6F 的目标 i」：
dmg  = 伤害槽[i];
xfer = min(dmg * 效果值 / 100, dmg);        // ★ 修法A：转移量绝不超过原伤害
伤害槽[i] -= xfer;                           // ⇒ 永不为负（等价修法B：if(<0) =0）
// 在候选表里找「存活 且 != 自己 且 HP 最低」的单位 j
伤害槽[j] = min(伤害槽[j] + xfer, HP[j]);     // 钳到 ≤ HP（原实现已有）
// ★ 修法C：**不要**把 j 追加进列表（原实现在 0x41AA60-0x41AA67 做了，疑似二次处理来源）
```
- **修法A**：`xfer = min(xfer, dmg)` ← 恢复被 NOP 的保护
- **修法B**：`伤害槽[i] = max(伤害槽[i] - xfer, 0)`
- **修法C**：去掉「把承接者 append 进列表 + 计数 + `0x47FD13` 补齐」这一整段

### 6.6 若要 100% 复现原 mod 行为（含这个 bug）
那就**不要**加 A/B/C —— 但要接受"效果值 > 100 时会出满血复活"。
**建议**：复刻时直接带修法 A+C（成本极低，且不影响效果值 ≤ 100 的正常表现）。
