# 周边人数-九宫格与阵营组（引擎函数 0x41BC4A）

## 结论速览

- **引擎没有「周边人数」全局变量**：权威实现是函数 **`0x41BC4A(ecx = 单位记录指针, 栈参数 = side)`**，计数结果在 **`eax`**，调用完即弃、不落内存。
- 范围 = **九宫格** `X-1..X+1 × Y-1..Y+1`，**含中心格** ⇒ 自己属于被统计的阵营组时**会把自己算进去**（6.5「聚势伐谋」说明里的「+1」就是这件事）。
- `side` 取值（`0x44CB12` 实读）：`0..3` = 精确阵营相等；**`4` = 我方组（阵营 < 2）**；**`5` = 敌方组（阵营 2 / 3）**；`6` = 全部。
- 阵营 `2` 在 `0x44CB12` 内还会按**出场编号 `unit+4`** 重映射：`< 0x14` → 按 0（我军）、`< 0x3C` → 按 1（友军）、否则仍 2。
- 6.6 原生已有两处「阵营 + 周边人数」消费点：
  - **`0x4363B0`** = `0x55 万夫莫敌`（个人 `0x71 戮力同心`）通道：`伤害 += 伤害 × ((周围敌方人数 + 1) × 特效值)%`；
  - **`0x478EAB`** = `0x47 一骑当千` 桩：按周围**同阵营**人数对数值折半（实测该桩**高频生效**）。
- 另一张「周边目标 slot 列表」`0x500EA5`（奋战 `0x4363F1` / 引导 `0x4212F1` 共用，`0xFF` 终止、**无计数变量**）；`0x500E9C` 是**引导链目标数**（**独立 byte**），不是周边人数。相邻的 `0x500E9A` 是**阶段/列表标志的 1 字节槽**（写点 byte/word 混合，word 只覆盖 `0x500E9A~0x500E9B`），`0x500E9D` 是**byte 目标数组**（`FF` 终止）；四者相邻但**不构成 dword 结构**（宽度权威表：`00-总览与规范\待验证清单.md`「2026-10-26 N1」节）。
- 只读监测工具：`大鲸鱼产生专用\_周边人数探针.py`（2026-10-18 实机跑通，输出样例见下）。

## 已确认事实

### 1. `0x41BC4A` 契约（本样本现读，capstone）

```asm
0x41BC4A  push ebp / mov ebp,esp
0x41BC4D  cmp  byte [ecx+0x0E], 7      ; [unit+0x0E] == 7（玩家可控）?
0x41BC51  je   0x41BC67                ; 是 ⇒ 直接用单位表坐标
0x41BC53  cmp  byte [0x4B3D18], 0      ; 非可控单位：动画/预览位移标志?
0x41BC5A  je   0x41BC67
0x41BC5C  push 1 / call 0x407BF6       ; 否则取动态坐标对象
0x41BC63  push dword [eax]
0x41BC67  push dword [ecx+6]           ; ★ push 即局部：[ebp-4]=X, [ebp-3]=Y
0x41BC6A  ... 计算 X+1 / Y+1 / X-1 / Y-1（0 下界保护）...
0x41BC87  push 1 / push [ebp+8]        ; mode=1, side
0x41BC8C  mov  ecx, 0x4B3D08           ; 矩形扫描上下文
0x41BC91  call 0x428DF1                ; → eax = 人数
0x41BC98  ret  4
```

- `push dword [ecx+6]` 把 X/Y 两个字节压到 `[ebp-4]`/`[ebp-3]`，属于 MSVC「用 `push` 分配局部变量」手法（与 `特技0x17-奋战攻击次数改造.md:805` §83.2 同一机制）。
- 函数体内**无自己的 `mov [ebp-4],…`** —— 查「未初始化局部」时必须同时看 `push`/`esp` 位移，否则会误判。

### 2. 逐格判定链（`0x428DF1` → `0x44CB12`）

| 地址 | 作用 | 判据 / 返回值 |
|---|---|---|
| `0x428DF1` | 矩形/全表扫描入口 | `[ebp+0xC]==1` ⇒ 走矩形分支（`x0..x1`,`y0..y1`）；否则扫全 slot |
| `0x435884` | 坐标 → 战场 slot | 无效返回 `0xFF` |
| `0x4061F9` | slot → 单位记录指针 | `ecx = 0x4A7B20 + slot*0x30` |
| `0x418C90` | 取 `byte[unit+0x0C]`（显示状态） | `== 2` 才算有效单位（3 = 死亡） |
| `0x44CB12` | `side` 与单位阵营匹配 | 返回 1/0，累加到 `[ebp-4]` |

### 3. `side` 语义（`0x44CB12` 现读）

```asm
0x44CB17  mov  ecx,[ebp+0xC]      ; unit
0x44CB1A  call 0x413172           ; eax = byte[unit+5]，越界(>6)归 0
0x44CB1F  cmp  al,2 / jne 0x44CB34
0x44CB23  cmp  byte [ecx+4],0x14  ; 阵营 2 再按出场编号细分
0x44CB29  xor  eax,eax            ;   < 0x14 ⇒ 0（我军）
0x44CB33  dec  eax                ;   < 0x3C ⇒ 1（友军）
0x44CB48  cmp  al,4 / ja …        ; side 4 ⇒ al<2 ? 1 : 0   （我方组）
0x44CB59  cmp  al,5 / ja …        ; side 5 ⇒ al∈{2,3} ? 1 : 0（敌方组）
```

⇒ 结论：**4 = 我方组、5 = 敌方组**；`0..3` 精确匹配；`6` 一律通过。

### 4. 原生消费点

| 地址 | 特技 | 行为 | 证据 |
|---|---|---|---|
| `0x4363B0` | `0x55 万夫莫敌` / `0x71 戮力同心` | `eax = 0x43C3DE()` 取特效值 K → `0x406710(unit)` 判组 → 取互补 `side` → `0x41BC4A(unit, side)` → `inc eax` → `imul K` → `0x425AD9` 百分比 → `add [ebp+8]`。语义 = **全能力按周围敌人数提升**（不是伤害） | 静态反汇编；**调用点 = `0x4C0385`**（在能力结算 `0x4C0300` 内），详见 `03-机制详解\特技0x55-万夫莫敌-全能力提升.md` |
| `0x478EAB` | `0x47 一骑当千` | `0x4101D9(0,0,0x69,0x47)` 判有无 → `0x406710` 判组取**同组** `side` → `0x41BC4A` → 人数为 0/仅自己 ⇒ 不减；≥2 ⇒ `shr [ebp-4],1`（数值减半） | 静态 + KB 实机：断点 `0x478EB6` **74 次/30 秒**（`原版与现样本分离-特技接入点跨版本对照.md:323`） |

### 5. 另两张「周边 / 目标」表（不要与 `0x41BC4A` 混用）

| 地址 | 语义 | 是否有计数 |
|---|---|---|
| `0x500EA5` | 奋战/引导共用的**周边目标 slot 列表**，`0xFF` 终止；由 `0x436499` → `0x4091F4`（候选 `0x4AC748`）→ `0x419A67`（去重 + 可击杀优先）构建 | **无**；人数 = 数到 `0xFF` |
| `0x500E9A` | **阶段/列表标志**（1 字节槽；byte/word 写点混合，word 只到 `+0x01`） | 无（不是计数） |
| `0x500E9B` | `0x500E9A` 的相邻字节：word 写时＝选择索引高字节；另有窄域“必中开关”两个直接 byte 写点（运行时值 pending） | 无 |
| `0x500E9C` | **引导攻击链**目标数量（**独立 `byte`**，3 写 2 读），配 `0x500E9D` 数组（**byte 项**，`0xFF` 终止） | 有，但属「引导链」不是「周边」 |
| `0x500E9D` | 引导链**目标单位编号 byte 数组**；`0x405C05/0x405C0A` 的 `mov dword …,0xFFFFFFFF` 是**连续 8 字节 FF 哨兵填充**，不是 dword 元素 | 无（数 `0xFF`） |
| `0x4AC748` / `[0x4B2C34]` | 范围候选表（WORD 项，高字节 `0xFF`）/ 写游标 | 候选项数 ≈ `(游标-0x4AC748)/2`，空闲时游标 = 0 |

## 风险与边界

- 探针用**静态 X/Y**；`0x41BC4A` 在「非玩家可控单位 + `[0x4B3D18]!=0`」时会改用动态坐标对象 ⇒ **战斗位移动画中的瞬时值可能与探针不同**。
- **⚠ 已更正（2026-10-18 15:3x）**：本文初版写「`0x4363B0` 全映像找不到调用点」——**错**。
  它的调用点是 **`0x4C0385`**（`call 0x4363B0`，位于 `.api` 节的能力结算函数 `0x4C0300` 内）。
  漏检原因：首轮 xref 扫描把 `rel32` 当**文件偏移**相加，而调用方（`.api`）与被调方（`.code`）的
  `VA→rawptr` 差不同 ⇒ 跨节调用全部漏掉。**正确算法：`目标VA = 源VA + 5 + rel32`**（在 VA 空间算）。
  修正后复扫：`0x4363B0` = 1 处、`0x478EAB` = 1 处（`0x4C037B`）、`0x43C3DE` = 2 处。
- 阵营 `4/5/6` 的单位是否参与「我方组/敌方组」尚未实测（示例战斗里只有 0 与 2）。
- 九宫格**含自身**：写「周围敌人数量」类公式时若要排除自己，需要额外减 1（或按 `0x41BC4A` 后自行判断）。
- 本页不改任何字节；探针只读，不写进程内存、不写 `Ekd5.exe`。

## 待验证项

- **P0**：实机断点 `0x41BC4A` 返回处（`0x41BC98`），把 `eax` 与探针同一 slot 的计数逐一比对（至少覆盖「含自己 / 不含自己」两种）。
- **P0**：`0x4363B0`（万夫莫敌/戮力同心）到底有没有调用者：给单位配 `0x55` 后打一场，断点 `0x4363B0` 看命中；0 命中则登记「6.6 未接线」。
- **P1**：阵营 `4/5/6` 的语义，以及 `0x44CB12` 只把 `2` 重映射、不重映射 `3` 的原因。
- **P1**：`0x407BF6(1)` 返回对象与 `[0x4B3D18]` 的语义（动态坐标何时启用）。
- **P2**：`0x500EA5` 列表容量（`0x50` 哨兵与 `0x43F8C0` 的关系）—— 与「周边人数」无直接关系，但同属周边目标链。
