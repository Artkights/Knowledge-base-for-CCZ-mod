## 结论速览

1. **语义**：敌军对我方 A 发起**物理攻击**时，若持技持有者 H 站在 A 的**上下左右紧邻 4 格**内，
   则按特效值百分比，把 A 的一部分伤害**分摊到 H 身上**（H 替 A 挨）。
2. **特效值是掩码：`≤100` = 十字（上下左右）+ 百分比；`>100` = 八方 + (值−100)%**。
   例：`1` = 十字 1%、`100` = 十字 100%、`101` = 八方 1%、`200` = 八方 100%。flag 同 `0x57` 用 `0x04`。
3. **十字与八方是两套判定**：十字 `|dx|+|dy|==1` 自己算；八方 `max(|dx|,|dy|)==1`，
   ~~可复用 `0x43BAD5`~~ ⇒ **该函数在本样本不存在**（2026-10-28 现读 `0x43BAD5` 起全 `90`），
   两档都须手写。中心都是**持技持有者**（纠正明细见 §6.2）。
4. **本特技不会复刻策略侧「复活」** —— 它走物理链，物理分发后天然有
   `0x439470 → 0x4065D9 → 0x42BC14 → 0x40502B` 全槽判死。**仍必须"用完即清"**。
5. **号位 `0x99` 现读空闲**：名表 `0x4CCF90` = `D4 A4 C1 F4` + 全零（「预留」）；
   但 `0x99` **没有任何既有桩查询** ⇒ 必须新增查询点。
6. **最大缺口 = 挂点未定位**（物理伤害写入阶段的具体地址未定），见 §6。
7. **多持有者取最近、只触发一次**；**同时持 `0x57` 时让位**（本特技整段跳过）；
   被分摊致死的 H **走物理链正常退场**，不手写 HP/`view`（见 §三·五）。

## 一、核心语义

> 敌军物理攻击我方 A → H 在 A 的十字 4 格内且持 `0x99` → 按 p% 把 A 的伤害分摊给 H。

| 参数 | 取值 | 做歪长什么样 |
|---|---|---|
| 谁分摊给谁 | A（被攻击者）→ **H（持技持有者自己）** | 转给敌方 HP 最小者 ⇒ 那是借力打力 `0x57` |
| 分摊多少 | 特效值掩码：`p = 值`（`≤100`）或 `值−100`（`>100`）；转移量 = A 伤害 × p% | 把 p 当半径 ⇒ 范围错；把 p 当次数 ⇒ 扣次数错 |
| 什么时候 | **物理伤害写入阶段** | 攻击发起前 ⇒ 伤害还没算出来，分摊量是猜的 |

**特效值解码（掩码，用户 2026-10-28 定）**

| 特效值 `v` | 范围 | 转移比例 `p` |
|---|---|---|
| `0` | — | **不触发**（视为未持有）|
| `1~100` | **十字**（上下左右）| `p = v` % |
| `101~200` | **八方**（含对角）| `p = v − 100` % |
| `>200` | — | **无效跳过**（用户 2026-10-28 定）|

**中心与距离（写死，别再问）**

- 中心 = **持技持有者 H**（不是被攻击目标）。
- 十字档（`v ≤ 100`）：`|dx| + |dy| == 1`，**对角不算**。
- 八方档（`v > 100`）：`max(|dx|, |dy|) == 1`，**对角算**。
- 臂长固定 **1 格**（两档都只是紧邻一圈）。

## 三·五、多持有者与 `0x57` 优先级（用户 2026-10-28 定）

**多持有者：取最近，只触发一次**

> **★「槽号」定义（别和 Data 号混）**：槽号 = **战场槽位索引 `0~0xFA`（250 个）**，不是 Data 序号。
> `0x4061F9(slot)` ⇒ 记录 `0x4A7B20 + slot×0x30`；记录 `+0x00` 才是 **Data 号**（`0xFFFF` = 空槽），
> `+0x04` = 该单位的槽号。⚠ **刘备的 Data 号就是 0，不能用 `==0` 判空**。
> 实测槽位分布：我方 `0..4`、敌方 `60..75+` ⇒ 顺序遍历天然先命中我方。

- **注意**：十字档与八方档的候选**距离都等于 1**（都只是紧邻一圈）⇒ 字面上的"最近"无法区分。
  **默认实现**：按槽号 `0 → 0xFA` 顺序遍历，**取第一个命中者**，触发后立刻退出，不再找第二个。
  将来若做臂长 >1，再引入真正的距离比较。
- **只发一次**：同一次物理攻击里 `0x99` 最多分摊一次，不论场上有几个持有者。
- **已定（用户 2026-10-28 确认）**：按槽号 `0 → 0xFA` 顺序遍历，取第一个命中者。

**与 `0x57` 借力打力的优先级**

- **`0x57` 优先**：持有者同时持 `0x57` 与 `0x99` 时，**先判 `0x57`，命中即整段跳过 `0x99`**。
- 为什么：`0x57` 已把伤害转给"范围最弱"单位；再分摊一次 = **二次转移**，
  总伤害不再守恒，且飘字对不上。
- 实现：`0x99` 触发前先查 `0x57`（同桩、号换成 `0x57`），查不到才走分摊。
  ⚠ `0x4101D9` / `0x42518F` **每次调用前必须重置 `ECX` = 单位指针**。

**被分摊致死的 H**

- 走物理链原生退场：`0x439470 → 0x4065D9 → 0x42BC14 → 0x40502B → 0x441744`。
- **禁止手写** `[unit+0x0C]` / `view` / `[unit+0x10]` —— 手写只会得到残尸或瞬退。

## 四、实现要点

1. **必须新增查询点**：`0x99` 无任何既有桩查询 ⇒ 在物理伤害写入阶段内联桩：
   `push 0 / push 1 / push <桩内号> / movzx eax,byte[<参数>] / push eax / call 0x42518F`，
   `test eax,eax / je 跳过`。**每次调用前 `ECX` 必须是单位指针**。
2. **范围判定分两档**：读 `unit+0x06`/`+0x07`（x/y）。
   十字档 `|dx|+|dy|==1`；八方档 `max(|dx|,|dy|)==1` ⇒ **两档都手写**。
   ⚠ 原文"可复用 `0x43BAD5`、返回值反转"作废：现读该址全 `90`（函数未装入本样本）；
   且有"`al=0` 免疫 / `al=1` 放行"反转语义的是 `0x43BA9D`（原版值≠0即免疫，不判距离）。
3. **伤害写入**：照 `0x418205` 的写法 —— A 的伤害扣掉 p% 后的量写 `ctx+0x84[原位置]`，
   H 追加一条 `ctx+0x10` 槽 + 写 `ctx+0x84[新位置]`。
4. **用完即清**：照抄 `0x452907` 尾部 `push -1 / push 新增数 / push (ctx+0x10+原数) / call 0x47FD13`。
5. **判死交给物理链**：不写 `[unit+0x0C]=3`、不 `HP=0 + call 0x441744`。

## 五、禁止项（本特技专属）

1. **不要调 `0x4AC748` 候选表**（那是借力打力的"选最弱"逻辑）；本特技只认**持有者紧邻一圈**（十字或八方，按掩码）。
2. **不要复用 `0x57` 的 `0x43C402` 取比例**（它服务 `0x57` 的配置；本特技用自己的特效值）。
3. **不要引用 `0x43BAD5`**（2026-10-28 现读：该址全 `90`，判定函数在本样本不存在）；
   八方按 `unit+0x06/+0x07` 手写切比雪夫 ≤1。
4. **不要照抄策略 `0x6F` 的"追加后不清"** —— 那是策略侧"复活"的成因之一。
5. **不要手写 HP 或 `view`** —— 物理链自带判死与退场。

### 6.1 挂点定位与静态论证（2026-10-28，只读；基底 `48560923…`／工作基底 `2B279F3F…` 两处字节相同）

**物理链现读（`_dsh反汇编工作台.py func/da`）**

```
0x4527FE  call 0x405DE1        ; 物理伤害计算 → 写 ctx+0x84（ctx = 0x4927F0）
0x45280A  call 0x452907
            0x452911 call 0x40CFF6   ; 逐槽"钳到 HP"，并可能改写 ctx+0x84
            0x452918 jne 0x452928    ; 非 0 → 跳过 0x57
            0x45291D call 0x418205   ; 0x57 借力打力域（追加 ctx+0x10 + 写 ctx+0x84）
            0x452928 汇合点 ← 两条分支都到这里
            0x45292B call 0x4526E7   ; 演出/飘字（只读 ctx[0]/ctx[1]）
            0x452930 mov ecx,[ebp-4]
0x452933  call 0x405966        ; ★ 逐槽扣 HP/MP + 判死（真正的"应用"）
            0x45293F memset(ctx+0x10+[ebp-8], [ebp-0xC], 0xFF)  ; 用完即清
```

- `ctx+0x84` 的**写**在 `0x405DE1` 内 ⇒ 那是 §3.6.2 第二组**黑名单**（6 次实证必崩），
  **不能挂"写之前"**。
- `ctx+0x84` 的**消费**在 `0x405966`：`0x405ACD call 0x41B500`(HP) → `sub eax,[ebp-0x14]`(伤害)
  → `0x43F6DB` 写回；`0x405B36 call 0x411072` 判死。⇒ **0x99 必须在 `0x405966` 之前追加槽**。
- `0x452928` 是 `0x40CFF6` 两条分支的汇合点（`0x452918` 的 `jne` 是**短跳 rel8**，
  `xref` 的 rel32 扫描**扫不到**，别据此判"无引用"），到 `0x452933` 之间无任何跳转落点。

**为什么选 `0x452933` 而不是 `0x452930`**

- 洞要 `E9 rel32`（5 B）⇒ 覆盖窗口必须 ≥5 B 且是整数条指令。
  `0x452930`（`8B 4D FC`）+ `0x452933`（`E8 …`）= 8 B（3+5），但要多写"回填 `mov ecx,[ebp-4]`"；
  **直接替换 `0x452933` 的 5 字节 `call`** 则：等长、单条指令、`0x452930` 原样保留、
  洞尾 `jmp 0x405966` 即**尾调用**（返回地址仍是 `0x452938`）。
- `xref 0x452930` / `xref 0x452933` 均 **0 引用** ⇒ **入边唯一**（仅 0x45292B 顺序流入）。

**影响面（第二组"最小"）**

- `0x405966` 另有 2 个调用者：`0x404BB3`（函数 `0x404B46`，置 `[0x500C44]=2`，
  走 `0x41F91A`/`0x435829`，形态像预览/推演）与 `0x42D368`（`ecx=0x497AF8` = **策略**上下文）。
  改 `0x452933` 的 `call` 目标**只影响物理这一条**，另两处原样。
- 与已验收的 `0x57` 借力打力**同一条链**（`0x418205` 的唯一调用者就是 `0x452907`）
  ⇒ 覆盖面与 `0x57` 完全一致，不是新开一条路。

**寄存器 / 栈契约（过关）**

- 进入时 `ECX = ctx`（`0x452930 mov ecx,[ebp-4]` 刚写入）、`EBP` = `0x452907` 帧、`ESP` 在帧内。
- 洞体 `pushfd` + `pushad` 保存；`popad` + `popfd` 还原后 `jmp 0x405966`
  ⇒ `ECX=ctx` 已还原、标志位已还原、原 `call` 的返回地址未变。

**追加槽与"用完即清"（最容易写错的一处）**

- 只要在 `0x405966` 之前把 H 追加进 `ctx+0x10`、把分摊量写进 `ctx+0x84[新下标]`，
  H 就会走**原生物理判死**（不写 HP、不写 `view`）。
- 清理在 `0x45293F`：`memset(ctx+0x10+[ebp-8], [ebp-0xC], 0xFF)`
  ⇒ 洞体**必须**维护 `0x452907` 的帧变量：`[ebp-8] = 原槽数 N`、`[ebp-0xC] += 本次追加数`。
- ⚠ `[ebp-0xC]` 初值 0（`0x45290C push 0`）；**`0x57` 未触发时 `[ebp-8]` 是 `push ecx` 留下的 ctx**
  （垃圾）⇒ 洞体一旦追加就**必须自己写 `[ebp-8]`**，否则 `memset` 会写到数据区。
  实现口径：先扫 `ctx+0x10` 得当前槽数 M；`[ebp-0xC]==0` 时令 `[ebp-8]=M`，随后 `[ebp-0xC]+=追加数`。
