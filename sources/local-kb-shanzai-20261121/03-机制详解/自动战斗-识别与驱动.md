## 结论速览

**A. 识别（怎么知道在战场、怎么读状态）**

1. **战场判据（唯一可靠）**：`SmallMap` 顶层窗口可见 **且** `0x4B422C`（战场宽）> 0
   **且**主窗口客户区宽 ≥ 900。⚠️ `ChanSuoName`/`SiJianName` 在战场里**不显示**（拿它们当判据永远误判）；
   ⚠️ 单位表里的"我 5 / 敌 42"**不是**战场标志（标题页也残留这份数据）。
   ⚠️ **客户区宽度会变**（实测 640×440 / 800×550 / 960×728 / 1200×…），
   ⇒ **不要用固定宽度当判据**，用"三选二"更稳（`: `_42结束回合.py` 的 `at_title()`）。
2. **主将阵亡不是"游戏退出"**：会弹结局框「**菜就别玩了**」→ **点「是」回到标题页**，
   **进程与窗口都还在**（实机 2026-10-15 核对）⇒ 自动化可直接重读 `No.001` 续测。
   （旧口径"主将阵亡→战斗结束→游戏退出"已纠正，见 [纠错台账](../90-来源归档/复刻版6.6山贼错误知识纠正台账.md)。）
3. **暴击是"预演"写入的**：`0x4927F0+604=1` 与伤害槽 `+84` 在**伤害分配阶段**就写好，
   HP 真正扣减要等动画播完（实测差 11 秒）⇒ 掉血时**不能**用当帧上下文判暴击，必须**回查最近一次以该单位为目标的上下文**。
4. **加速字节 `0x4B3D20` 只是状态指示**（引擎自己在 1↔3 狂刷）；**注入按键对该引擎完全无效**（AutoDLL 钩子丢弃）。
   权威口径见 [加速机制与0x4B3D20口径](./加速机制与0x4B3D20口径.md)。

**B. 主动战斗（本轮新增，实机跑通）**

5. **「托管我军主动出击」= 对我军+友军每个非空槽写 `unit+0x0E = 1`**（**一个字节，非补丁、非注入**）；
   取消勾选写回 `7`（可控）。源码级证据 `ai使用库\扳手\mywindow.py:4175-4189`。
   实测效果：一回合**我军出手 10 次、敌军死亡 9 个**。
6. **结束回合：按键全部无效**（空格 `0x20` / 回车 `0x0D` / End `0x23` 实测都不弹确认框）；
   **唯一有效路径 = 右键空地 → 确认框 → 点「是」**。
   ⚠️ **托管 ≠ 结束回合**：托管只让单位自动出手，**不代替"结束回合"输入**。
7. **实时保命**：唯一写入点是 **`unit+0x10`（当前 HP，dword）**；
   低于"观察峰值 × 阈值"就回填峰值；**`HP==0` 的不碰**（真死要引擎复活函数）。

**C. 读档（点不中的根因已定案）**

8. **★ 标题页自绘按钮必须"先悬停再点击"**：`SetCursorPos` 后**只等 0.12~0.2 秒就点 ⇒ 一律无效**；
   等 **0.5~0.6 秒**再点 ⇒ 立刻弹出「读取进度」。**这是"读档总点不中"的唯一根因**。
9. **坐标按客户区比例算**（基准 960×728，`烽烟再起` = 比例 `0.7146 / 0.3022`）；
   但**布局真的变时会点错项**（实测点错过、弹出「结束游戏」）⇒ **每次点击后必须验证弹出的是不是预期对话框**（R1 硬断言已内建：确认框文本必须以 `进度No.001` 开头）。
10. **权威读档入口只有一条**：`_自动读档进战场.py --go-safe`（由 `_42结束回合.load_001()` 调用）。
    **不要再新写读档脚本**（工作区已有 50+ 个）。

## 已确认事实

### A. 内存锚点

| 用途 | 地址 | 说明 |
|---|---|---|
| 战术单位数组 | `0x4A7B20 + slot*0x30` | `+00` Data 号（`FFFF`=空）、`+05` 阵营（0我/1友/2敌）、`+06/+07` X/Y、`+0C` 显示状态、`+0D` 行动（`00`未动）、**`+0E` AI 方针**、`+10` 当前 HP、`+14` 当前 MP |
| 战场宽/高 | `0x4B422C` / `0x4B422D` | 战场里 `14 1A` = 20×26；标题页为 0 |
| 阶段字节 | `0x4B3D18` | 实测在 `0↔2` 间随回合切换；`0` = 玩家可控阶段 |
| 集气模式开关 | `0x505EC8`（整型 `4018`） | **=1 时集气模式**；战斗测试前提，见 [集气模式-闪避暴击连击](./集气模式-闪避暴击连击.md) |
| 集气数组 | `0x4930C8 + slot*4` | 字节 0 连击 / 1 物理闪避 / 2 暴击 / 3 策略闪避 |
| 战斗上下文 | `0x4927F0`（基址本身，不是指针） | `+00` 攻击者 slot、`+01` 目标 slot、`+84` HP 伤害数组、`+254` 策略伤害、`+604` 暴击标志、`+608` 连击、`+614` 反击 |
| 加速参考字节 | `0x4B3D20` | 引擎自刷，**只是状态指示** |

**`unit+0x0E` 的取值表**（[策略目标判定与AI方针](./策略目标判定与AI方针.md)）：

| 值 | 含义 |
|---|---|
| `0` | 攻击武将 / 到指定点 |
| **`1`** | **主动出击** ← 托管写这个 |
| `2` | 坚守原地 |
| `3` | 被动出击（敌军常见默认） |
| `4` | 跟随武将 / 逃到指定点 |
| **`7`** | **可控**（我军默认；取消托管写回这个） |

### B. ★ 主动自动战斗闭环（2026-10-15 实机跑通）

**B1「托管我军主动出击」的精确实现**

**B4 实时保命**

- 写入点：**`unit+0x10`**；每 0.15 秒扫我军/友军非空槽；

### C. 读档点击协议（权威）

- **自绘按钮（标题页「烽烟再起」）**：必须 **抢前台 → `SetCursorPos` → 悬停 `≥0.5s` → `mouse_event` 点击**。
  `PostMessage`/`SendMessage` 的鼠标消息**一律无效**。
- **对话框部分**（`读取进度` 列表 / `读取` 确认框）是**标准 `#32770`**，有真实控件矩形 ⇒ 坐标按控件矩形算，不用猜。
- **存档行必须物理点击**：`LVM_SETITEMSTATE` 只改控件选中态，游戏不认（不会弹「读取」确认框）。
- **R1 硬断言**：确认框 `Static` 文本必须以 `进度No.001` 开头，不是就点「否」并退出。
- **读档后先进"出战准备界面"**（氪金系统），**不是**直接进战场 ⇒ 判据要看**战场宽 `[0x4B422C] > 0`**。

### D. 自动化脚本的铁律（ctypes）

1. 句柄 `restype = ctypes.c_void_p`（否则 64 位 Python 静默截断）；带进程句柄的 API 必须设 `argtypes`；
   而 `SendMessageW` 这类**不能设**。
2. `restype=c_void_p` 之后不能再 `'%d' % hwnd`（TypeError）→ 先 `int()`。
3. `WriteProcessMemory` 用 **`create_string_buffer`** 直接传（不要 `c_char` + `byref`，
   实测会返回 False 但其实已写入）。
4. `ShowWindow`：`SW_MINIMIZE=6`、`SW_RESTORE=9`。
5. `%s` 对元组要写成 `% ((a,b,c,d),)`。
6. 清障不得最小化 `Progman/WorkerW/CabinetWClass` 等系统窗口与输入法窗口。
7. **抢前台绝不注入 ALT**（确认框上 ALT = 取消）。

## 实现·使用方法

### 推荐主循环（主动战斗，可直接抄）

```python
# 0) 前置：游戏已运行（本页只负责战场内；进战场用 _自动读档进战场.py --go-safe）
pid  = find_ekd5();  ph = OpenProcess(0x1F0FFF, False, pid)

# 1) 战场判据（三选二）
in_battle = (SmallMap可见 and read_u8(0x4B422C) > 0) or 客户区宽 >= 900

# 2) 托管我军（只写一个字节；先存快照以便回滚）
for slot in 0..cnt_wo+cnt_you-1:
    if read_u16(0x4A7B20+slot*0x30) == 0xFFFF: continue
    if read_u8(0x4A7B20+slot*0x30+5) in (0,1):          # 我军/友军
        write_u8(0x4A7B20+slot*0x30+0x0E, 1)            # ★ 主动出击

# 3) 保命（可选，防主将早死）
每 0.15s: if 0 < hp < peak*ratio: write_u32(unit+0x10, peak)

# 4) 分批推进：每批 rounds=5 回合
while 本批回合数 < 5:
    等 ctx(0x4927F0) 攻/防 slot 稳定 4 秒
    focus(游戏窗口) → 右键空地 → 找含「站位」的 #32770 → 点「是」   # ★ 唯一有效路径
    结算窗口 6 秒（只读采样）

# 5) 阵亡自愈：我军存活==0 或 出现结局框
if 有 #32770 对话框: 点「是」 → 等【对话框消失 AND 标题页判据】
→ _自动读档进战场.py --go-safe（只读 No.001）→ 回第 2 步
```

## 风险与边界

- **★ 断点会把游戏整体挂住（本轮最贵的教训）**：

  | 环节 | 事实 |
  |---|---|
  | 现象 | 游戏 `Responding=False`（窗口不响应），**连 PowerShell 命令都跟着卡住** |
  | 根因 | 在**高频地址**（`0x4287A8` 集气判定入口，**每次攻击都进**）挂断点；条件 `cip%20==0` 仍频繁暂停；脚本被 kill 时**清断点没走完**，断点留在进程里 |
  | 判据 | `debug_get_state = paused` + `Get-Process Ekd5` 的 `Responding=False` + `breakpoint_list` 非 0 |
  | 处置 | `breakpoint_delete_all` → **循环 `debug_run` 直到 `running`** → 确认 `Responding=True` |
  | 预防 | ① 高频地址**禁止普通断点**（条件断点也要 `cip%50==0` 以上）；② 探针必须 `try/finally` 清断点；③ **探针与战斗驱动不要同时跑** |

- **保命（写 HP）会污染样本**：触发过保命的伤害段必须从统计里剔除；要干净样本就别开保命。
- **托管会覆盖玩家的手动控制**（`+0x0E=7 → 1`）；退出前用快照回滚 `--off`。
- 写内存只涉及 `unit+0x0E`、`unit+0x10`、`0x4B3D20`；**不设断点、不写 EXE、不碰存档**（调试器路径另行说明）。
- **注入按键一律无效**（AutoDLL 钩子）⇒ 任何"靠按键驱动"的方案在 6.6山贼都不成立。
- **读档盲点有风险**：比例法在布局变化时会点错（实测点出过「结束游戏」）⇒ 必须验证弹出内容。

## ★ 2026-10-15 追加：怎么区分「点击送不到」和「游戏没在消费输入」

> 背景：本轮"读档总点不中"，先后排除了坐标、遮挡、hover、焦点、权限，最后发现
> **根本不是点击的问题——游戏进程没在处理输入**。这段是排查顺序，下次照这个走，别绕。

### 一、先跑这条（5 秒出结论，只读）

```
python 大鲸鱼产生专用\大鲸鱼启动诊断.py
```

它只读四件事：单位表是否初始化、**内存 5 秒内是否变化**、窗口是否活动、进程是否管理员。
结论只有两种：

- `[2] 出现「变化」` ⇒ 游戏在跑 ⇒ 再谈点击；
- `[2] 变化次数 = 0` ⇒ **游戏没在跑** ⇒ **此时任何自动点击都不可能成功**，
  先解决游戏本身（重启用平时的方式启动 / 手动点一下窗口 / 必要时重启系统）。

### 二、判定"游戏没在消费输入"的四件套（全部实测过）

| 判据 | 实测值（故障时） | 说明 |
|---|---|---|
| 内存变化 | **5 秒零变化**，连 `0x4B3D20` 都停在 `0` | 引擎循环没在推进 |
| CPU 占用 | **3 秒 3031ms（≈满 1 核）** | ⇒ 是**忙等空转**，不是死锁 ⇒ 不是"卡死" |
| `GetActiveWindow` / `GetFocus` | **均为 0** | 窗口不是活动窗口（外观发灰） |
| **四个输入通道** | `PostMessage` / `mouse_event` / `SendInput` / 键盘 **全部无效** | 通道无罪，是没人消费 |

### 三、★ 纠正一条本会话的错推断

早先推断"游戏窗口未被激活 ⇒ 点击失效"。**实测推翻**：
用 `AttachThreadInput` 强制激活后（`GetActiveWindow` 确实变成游戏、`GetFocus` 也拿到），
**点击仍然无效** ⇒ **"未激活"不是根因**，只是个伴随现象。

### 四、附带坑：窗口可能在屏幕外

实测游戏窗口落在 **`(-4,-4)`**（大半在屏幕外），客户区原点只在 `(0,54)`
⇒ `ClientToScreen(0,0)` 算出的小坐标会让"客户区比例法"的目标点落到**窗口外面**
（表现为：点也算对了、`WindowFromPoint` 却是别的东西 / 什么都没有）。

**处置**：点击前校验窗口矩形在屏幕内；不在就先移回来：

```python
u32.SetWindowPos(hwnd, 0, 200, 80, 0, 0, SWP_NOSIZE | SWP_SHOWWINDOW)   # HWND_TOP=0
```

### 五、排查顺序建议（从便宜到贵）

1. `大鲸鱼启动诊断.py`（5 秒，只读）→ 游戏在不在跑；
2. 窗口是否在屏幕内（`GetWindowRect` 与屏幕矩形比对）；
3. 点击点归属（`WindowFromPoint`）是否就是游戏；
4. 坐标是否对（截图叠客户区网格比对，**只用于事后验证，不用于硬点**）；
5. 最后才怀疑输入通道。

### 三、四条闸门：从"提示"升级为**可证伪的拒绝**
