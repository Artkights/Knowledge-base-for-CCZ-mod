## 结论速览

1. **`0x71` = 戮力同心**，语义 = **协力反击**：敌方回合、敌军攻击友方单位时，若该敌军落在「带 `0x71` 的友方单位」的攻击范围内，该单位出手打这个敌军（用户口径，`协力:5`、`更新:15168`）。
2. **「策略反击」是 `0x5F`，不是 `0x71`**：名表 `0x4CCBF0` 现读 GBK `B2 DF C2 D4 B7 B4 BB F7` = 策略反击、`+0F=07`（文字类）；`0x4CCD10` 现读 GBK `C2 BE C1 A6 CD AC D0 C4` = 戮力同心、`+0F=06`（`%d次` 类）。两条链不同、执行方式不同（`0x5F` 反**施策略**，`0x71` 出**物理攻击**）。
3. **`0x71` 本体无需补丁**：查询桩 / 2 项函数指针表 / 收集器 / 次数门 / 结果字节**全部原生在位** ⇒ 现状 = 引擎自带行为。
4. **v7「法术版」（钩 `0x41C0F9`）在当前基底未装**：`0x41C0F9 = E8 29 95 00 00` 是原生 `call 0x425627`；v7 洞 `0x430978` 前 8 字节全 `90`；`0x4305DA / 0x4308E0 / 0x430950` 亦全 `90` ⇒ 历史样本 `2BE174C0…A86225` 那版**已不在盘**（不得写成现行态）。
5. **三个错挂点永久证伪**：`0x4064D5`（127 次命中全物理、策略 0 次）、`0x43DF47`（分发器 case5，从未执行）、`0x423358`（入口首字节 `55`，不是 5 字节 `E8` 前像）⇒ 见 `复盘:48`、`待验证清单:2980`。
6. **栈契约死规则**：凡钩 `0x438F75`（原 `call 0x41058D`）做分流的补丁，**出口必须尾 `jmp`**；用 `call` 套层 ⇒ type=0/1 栈帧低 4 字节，`0x71` 反击自身是完整物理攻击会重入 `0x4223A9→0x438EBD→0x438F75`，偏差累积 → `0xC0000409`（/GS）闪退。当前样本修复在位（`0x432016 = E9 …` → `jmp 0x41058D`），证据 = `协力:156-165`（用户实测「不崩，勠力同心正常」）。

## 次数 / 范围 / 阵营门禁（现行口径）

* **渠道门禁**：`0x4101D9(个人号, 装备号, B, A)` 是**双渠道**查询（个人/兵种表 ∪ 装备渠道）。
  桩的 **4 个 push 位置决定字段**：`[ebp+8]`=D=个人/兵种号（**只有这一个能拿去查 `0x4CC600` 名表**）、`[ebp+0xC]`=C=装备渠道号。
  ⇒ 所以 `0x43C3DE`（`0/1/0x71/0x55`）是**万夫莫敌**（个人 `0x55`、装备 `0x71`），与戮力同心**无关**；`0x405954`（`0/0/0x58/0x71`）才是 `0x71`。判据 `0x41301E`（只对 `[ebp+8]` 取低字节 → `0x4198BE` 按 16 字节行索引查名表）：`协力:114-154`、`更新:15178-15181`。**先按位置、再按数字**，这是本族踩过一次的错判根因。
* **次数门**：`[unit+0x23]`（战场单位记录 `0x4A7B20 + slot*0x30`）与桩返回值比较 —— 现读 `0x438F34 cmp cl,al` / `jae 跳过`；界面对应「戮」字段（`协力:99`、`协力:113` 仍列 P2）。
  执行器 `0x41058D` 每出一个反击者会**自己** `inc byte [ecx+0x23]`（`更新:15386`）⇒ 任何钩本族的补丁**不得重复自增**。
* **范围门**：`0x4091F4(候选, 0x50, 2)` 构造候选单位的**引擎攻击范围**（奋战 `0x4363F1` / 引导 `0x4212F1` 共用同一个范围构建器）⇒ 「在攻击范围内」= 引擎范围，**不是固定九宫格**（`协力:100`）。**`0x4091F4` 本体不许改**（`设计:116`）。
* **阵营门**：物理协力反击的筛选链 = `0x418C90(unit)==2`（有效）→ `cmp ecx,[ebp+8]` 跳过攻击者自己 → `0x42E2B7(攻击者, 候选)` 通过（`edx==0`）→ `0x426B33(候选)==0`（`协力:14-20`、`更新:15167`）。
  法术版路线若要「只对敌方施法出手」，阵营组用 `0x406710(unit)`（`1` = 我方组；`设计:17`、`更新:15384`）。
* **判定时序门**（v6 死在这里）：策略施放**前** `ctx+0x0D` 目标表 = `FF`（空）、**后** = `00 FF` ⇒ 触发判定必须放在执行器 `call` **返回之后**（`复盘:57`、`更新:15453`）。
* **上下文口径**：策略 ctx `0x497AF8`（`+0` 策略号 / `+1` 施法者编号 / `+8` 施法者指针 / `+0C` 选中 / `+0D+i` 目标表 / `+108+4i` 每目标伤害）；物理 ctx `0x4927F0`（`[0]` 目标 slot、`[1]` 攻击者 slot）。
  ⚠ **`0x497AF8` 有内容 ≠ 策略真的发生**（AI 预演会写残值）；⚠ **`byte[0x501BF9]==5` 不能当策略判据**（命中当下实测是 `0xFF` 残值）——两条都已证伪（`设计:190-209`）。判物理/策略**永远用上下文指针** `[ebp-4] ∈ {0x4927F0, 0x497AF8}`。
