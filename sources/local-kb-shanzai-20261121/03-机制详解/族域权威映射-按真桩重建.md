### 更正 1：并非"10 个桩编号未解出"，实际只有 **2 个**，且它们是 `0x00` / `0x01`

| 桩 | 真实形态 | 结论 |
|---|---|---|
| `0x4210F4` | `push 0 / push 0 / push 0x43 / push 0 / call 0x42518F` | **最后一个 push = 特技号 `0x00`**（覆海之龙）|
| `0x421106` | `push 0 / push 0 / push 0x1B / push 1 / call 0x42518F` | **最后一个 push = 特技号 `0x01`**（真元流转）|

**根因（我的写法错）**：脚本里用 `pushes[-1]` 当特技号，但 `0` 是 **falsy** ⇒
被我的 `"if pushes"` / `"if p is not None"` 之外的判空写法吞成 `None`，误报"编号未解出"。
⇒ **教训：`0` 是合法特技号（`0x00` 覆海之龙），判空必须用 `is not None`，不能用 truthiness。**

### 更正 2：桩覆盖的准确数字

```
真桩总数 = 101
  ├ 有直接调用者（= 有域）        = 94  ✅
  └ 无直接调用者                  = 7
```
7 个无调用者的桩（**地址在全映像只以 4 字节立即数出现 1 次，且那处经复核是"字节巧合"**）：
`0x405942`(0x3B) / `0x42F8A1`(0x65) / `0x42F8B3`(0x66) / `0x43D0D6`(0x67) /
`0x43D0E8`(0x68) / `0x422E44`(0x6F) / `0x405954`(0x71)

**⇒ 这 7 个的桩存在但**：不被 `E8` 直接调用、也没有真实的 4 字节立即数引用

**本页不给出它们的域**（避免再犯"同域特技群"式的推断）。

## ★★★ 2026-10-17 05:5x 定案：**7 个"无直接调用者"的桩 = 经「跳转表 + 间接调用」分派**（已全部解释）

### 一、机制（实证）

**分派形态**：
```asm
00438F26  8B 45 F4                 mov  eax,[ebp-0xC]              ; 取分派索引
00438F29  FF 14 85 2B5E4100        call dword ptr [eax*4 + 0x415E2B]  ; ★ 表基址 + eax*4
00438F30  59                       pop  ecx
00438F31  84 C0                    test al,al
```
⇒ **`call dword ptr [eax*4 + 表基址]`** —— 这就是"没有 `E8` 调用者"的原因
（`_扫真桩.py` 只反查了 `E8`）。

**两张已定位的跳转表**：

| 表基址 | 项 | 内容 |
|---|---|---|
| **`0x415E2B`** | 至少 2 项 | `[0]=0x405942`（特技 `0x3B`）、`[1]=0x405954`（特技 `0x71`）—— 实测被 `0x438F29` 的 `call [eax*4+0x415E2B]` 使用 |
| **`0x42F8C8`** | 4 项 | `[0]=0x42F8A1`（`0x65`）、`[1]=0x42F8B3`（`0x66`）、`[2]=0x43D0D6`（`0x67`）、`[3]=0x43D0E8`（`0x68`）|

### 二、7 个桩的逐项结论

| 桩 | 特技 | 桩体（已复核**合法**）| 通道 |
|---|---|---|---|
| `0x405942` | `0x3B` | `push 0/1/0x63/0x3B → call 0x4101D9` | **表 `0x415E2B` 的 `[0]`** |
| `0x405954` | `0x71` | `push 0/0/0x58/0x71 → call` | **表 `0x415E2B` 的 `[1]`** |
| `0x42F8A1` | `0x65` | `push 0/0/0x52/0x65 → call` | **表 `0x42F8C8` 的 `[0]`** |
| `0x42F8B3` | `0x66` | `push 0/0/0/0x66 → call` | **表 `0x42F8C8` 的 `[1]`** |
| `0x43D0D6` | `0x67` | `push 0/0/0/0x67 → call` | **表 `0x42F8C8` 的 `[2]`** |
| `0x43D0E8` | `0x68` | `push 0/0/0/0x68 → call` | **表 `0x42F8C8` 的 `[3]`** |
| `0x422E44` | `0x6F` | `push 0/3/0x48/0x6F → call` | **未查到**（其地址在全映像 0 处出现、无 `E8`/`E9`/`EB`）⇒ 疑似**经 `E9` 从别处汇入**或**当前构建未启用** |

**⇒ 6/7 已定案（跳转表分派），1 个（`0x6F`）仍未定位。**

### 三、★ 更正我自己上一轮的说法

上一轮我在本页写过：*"那 6 处立即数命中经复核是字节巧合（落在 `ret` 后的数据里 / 指令中间）"*。
**该说法不准确，现更正**：那些位置**确实是数据**（跳转表的表项），
**不是"巧合"、也不是"无引用"** —— 它们是**表的第 N 项**，只是**不在 `E8` 调用者的形式里**。
⇒ 正确表述：**"不是 `E8` 直接调用，而是经跳转表间接分派"**。

**教训（新增）**：判"某地址有没有被引用"时，
**除了 `E8`/`E9`/`EB`，还要查"该地址是否作为 `[reg*4 + base]` 的 `base` 或表项出现"** ——
即**"间接分派表"**这一形态。工具：`_无调用者桩通道.py`（查 `E9`/`EB`）+ 本页的表定位法。
