# 特技判定链：架构、全部入口与关键函数

> 样本：`Ekd5.exe`（本文写作时 SHA `F3455B30875036DFB5A2DD01FDFE82C665A2FE6ADF1B7380BA9F740489C4A366`
> = 干净样本 `2A555B0B…` + 「奋战攻击次数按特效值 v1」补丁；补丁只改 `0x43646D`/`0x457E2E`，
> **与本文所有地址无重叠**）
> 证据类型：**静态反汇编**（capstone 5.0.7，现读）+ 调用者反查（`E8 rel32` 扫描）+ 常量字节复读
> 触发：用户「**反汇编所有特技，查一下，学一下知识**」（2026-10-16）

## 结论速览

1. **特技判定链是四层**：
   ```
   特技桩（每个特技一个小函数）→ 0x42518F（桩统一出口）→ 0x40B922（分流）
        ├─ 真分支 → 0x4101D9 → 0x426A07（按 id 分界查）
        └─ 假分支 → 0x41301E → 0x40BE7D（指针→角色号）
   ```
2. **`0x40B922()` 的真相 = 「`byte[0x4AC63C] == 3` ?」** ——
   因为 `0x40B913` = `0x41EDEF(0x4AC63C)`，而 **`0x41EDEF` 只做一条指令：`movzx eax, byte [ecx]`**
   ⇒ **`0x41EDEF(任意地址) = 读该地址的第 1 个字节`**。
   ⇒ `0x4AC63C` 是**全局分流字节**（在 `.text2` 运行时填充区，静态复读"不在节内"是正常的）。
3. **`0x42518F` = 桩的统一出口**（`ret 0x10`，4 参数）；**59 处调用者**（库内另一页记 58，吻合）。
4. **三组编号必须分清**（沿用 `03-机制详解\特技桩映射体系.md` 的口径）：
   **名表 id**（决定显示名字，名表 `0x4CC600` 第 id 项）× **桩内特技号**（引擎内部编号）× **桩入口 VA**。
5. **全量映射（本样本现读）**：**判定点 218 个**，覆盖 **174 个名表 id**，其中 **165 有桩**、**24 unresolved**。
   产出文件：`大鲸鱼产生专用\_特技桩映射.md` / `_特技桩映射.json`。

* 曹操传 6.6 系（`Ekd5.exe`）+ `ExtendData.dll`。

## 已确认事实

### 1. 桩的统一形态（库内已记，本样本复核一致）
```asm
004210F4  55 8B EC            push ebp / mov ebp,esp
          6A 00 6A 00         push p1 / push p2
          6A 43 6A 00         push <桩内特技号> / push <名表id>
          E8 8B 40 00 00      call 0x42518F
          5D C3               pop ebp / ret
```
⇒ **4 个参数**：`p1`、`p2`（特效值/标志）、**第 3 = 桩内特技号**、**第 4 = 名表 id**。

### 2. 桩统一出口 `0x42518F`（现读反汇编）
```asm
0x42518F  push ebp / mov ebp,esp / push ecx
0x425193  push [ebp+0x14] / push [ebp+0x10] / push [ebp+0x0C] / push [ebp+8]
0x42519F  call 0x40B922          ; ★ 分流判定
0x4251A4  mov  ecx,[ebp-4]
0x4251A7  test eax,eax
0x4251A9  je   0x4251B2
0x4251AB  call 0x4101D9          ; 真分支
0x4251B0  jmp  0x4251B7
0x4251B2  call 0x41301E          ; 假分支
0x4251B7  mov  esp,ebp / pop ebp / ret 0x10
```

### 3. 分流判定 `0x40B922` = 「`byte[0x4AC63C] == 3`」
```asm
0x40B913  mov  ecx, 0x4AC63C      ; 全局字节地址
0x40B91B  call 0x41EDEF
0x41EDEF  movzx eax, byte ptr [ecx]   ; ★★ 就这一条：读第 1 个字节
          ret
0x40B922  call 0x40B913
0x40B92C  cmp  al, 3
0x40B92E  sete cl                 ; ⇒ eax = (byte[0x4AC63C] == 3)
```
**⇒ `0x40B922` 有 **83 处调用者**（通用分流）。**

### 4. 真分支 `0x4101D9`（152 处调用者）
```asm
0x4101DD  xor eax,eax ; push eax ×5      ; 5 个 0 参数
0x4101E4  call 0x426A07                  ; ★ 查特技
0x4101E9  cmp  al, 0xFF
0x4101EB  je   0x41021C                  ; 0xFF = 没有
0x4101F0  push edx
0x4101F1  mov  ecx,[edx]
0x4101F3  cmp  ecx,[0x505F78]            ; ★ 与上限比较
0x4101F9  jae  0x4101FE
```

### 5. 查特技实体 `0x426A07`（**只有 4 处调用者**：`0x407838` / `0x4101E4` / `0x411269` / `0x465ACC`）
```asm
0x426A0B  movzx eax, word ptr [ecx]      ; 读一个 WORD
0x426A0E  cmp   ax, 0x1000
0x426A12  jae   0x426A21                 ; ≥0x1000 ⇒ 走下面
0x426A14  call  0x40658F ; mov al,[edx+4] ; <0x1000 ⇒ 走这条
0x426A21  push  eax
0x426A22  call  0x40B922                 ; ★ 又是分流
0x426A2E  and   ah, 0x0F                 ; 取高字节低 4 位
0x426A31  mov   ecx,[0x500AC8]           ; 一个指针
0x426A37  cmp   eax,[ecx]
0x426A3C  call  0x43E4D6                 ; ★ 最终查询
```


### ★ 攻关新特技/新机制的入手顺序（本文最大的实用价值）
1. **先在 `_特技桩映射.json` 里按"名字"或"名表id"找到目标** ⇒ 拿到 **桩内特技号 + 桩入口 + 判定点**
2. **反汇编桩入口** ⇒ 看 `push p1 / push p2 / push 桩内号 / push 名表id` 四个参数
3. **反汇编"判定点"的调用上下文** ⇒ 看 `call 0x4101D9`(或 `0x42518F`) **之后的代码** ⇒ 那就是**该特技的作用**
4. 若桩是**参数化桩**（如 `0x40399F cmp al,6`、`0x4039F6 cmp al,4`）⇒ 说明一族特技共用一个实现，靠参数区分
5. **绝不混用**：名表 id ≠ 桩内特技号

## 风险与边界

1. **`0x4AC63C`（分流字节）在 `.text2` 运行时填充区** ⇒ 静态复读"不在任何节内"**不代表不存在**；
   本库已有专门认知（`.text2` VSize `0x33000` ≫ RawSize `0x6800`）。**判"地址是否存在"必须区分"文件里"与"运行时"**。
2. **两组编号混用会导致一串假"不一致"**（库内 `_tmp_核对桩起点.py` 曾因此误报）⇒ 见速览第 4 条。
3. **`0x41EDEF` 只有一条指令** ⇒ 任何"它做了复杂判定"的推断都是错的；**本文已用现读反汇编纠正**。
4. **库内 `特技桩映射体系.md` 基于另一个样本 SHA**（`D5A2F54C…`）⇒ 引用其数字前**必须在本样本重核**。

## 71. ★★★★★ 第四判定入口 `0x436334` + 「域 ↔ 内联桩」交叉核对（2026-10-16，DSH）

### 71.1 ★ `0x436334` 的形态与另外三个入口**完全不同**
```asm
0x436334  push ebp / mov ebp,esp
0x436337  mov  al, byte ptr [ebp+8]     ; ★ 参数1 = 一个 BYTE（特效值）
0x43633A  cmp  al, 0
0x43633C  je   0x436351                 ; ==0 ⇒ 返回 0
0x43633E  mov  ecx, dword ptr [ebp+0xC] ; ★ 参数2 = DWORD
0x436341  cmp  al, cl                   ; ★ 比较（不是"查特技号"）
0x436343  jne  0x436351
0x436345  call 0x41E918
0x43634A  call 0x436357
0x436353  pop ebp / ret 8
```
**⇒ `0x436334(byte 特效值, dword 比较值)` = 「特效值 ≠ 0 且 == `cl` 则继续，否则返回 0」**
**⇒ ⇒ 它**不是**"特技判定入口"，而是**"按特效值查开关"**的辅助。**
（另三个入口 `0x4101D9` / `0x42518F` / `0x413009` 的形态都是"4 个 push + 查特技号"。）

**四个入口的调用者数（本样本现读）**：
| 入口 | 调用者数 |
|---|---:|
| `0x4101D9` | **152** |
| `0x42518F` | **59** |
| `0x413009` | 7 |
| **`0x436334`** | **7**（`0x4039B6` / `0x403A0D` / `0x405A4D` / `0x406B7C` / `0x41108A` / **`0x436415`** / `0x472D79`）|

**⚠ 注意 `0x436415`** —— 它**在 `0x4363F1`（奋战攻击函数）体内** ⇒ 待查。

### 71.2 ★★ 库内 `待验证清单.md:2206` 的表述需**细化**（不是"二选一"）
库内原文：
> 「参数化桩 `0x40399F`（`cmp al,6` + `add eax,8` ⇒ 特技号 = 特效值+8）**走的是 `call 0x436334`，不是** `0x4101D9`/`0x42518F`/`0x413009`」

**实测：`0x40399F` **两条路都走**** ——
```asm
0x4039A8  cmp  al, 6
0x4039AA  jae  0x4039F0        ; ★ 值 ≥6 ⇒ 跳去另一条路
0x4039AC  add  eax, 8          ;     号 = 特效值 + 8
0x4039B6  call 0x436334        ; ★ 值 <6 ⇒ 走第四入口
…
0x4039D5  call 0x4101D9        ; ★ 值 ≥6 ⇒ 走 `0x4101D9`
```
**⇒ 定案**：`0x40399F`：**`特效值<6` ⇒ `0x436334`（号 = 值 + 8）；`特效值≥6` ⇒ `0x4101D9`**
**同理 `0x4039F6`**（`cmp al,4` + `add eax,0xF`）：**`<4` ⇒ `0x436334`（号 = 值 + 0xF，即 15~18）；`≥4` ⇒ `0x4101D9`**

## 2026-10-18：0x06–0x0B破坏能力位掩码合并可行性

### 结论速览
- 若这里的 0x06–0x0B 指特技号，它们在当前名表中分别是“破坏攻击、破坏防御、破坏精神、破坏爆发、破坏士气、破坏移动”，是六个独立特技号，不是已确认共用一个参数的单一入口。

- f 列的 0x0A/0x0B 是显示用的六位/五位属性掩码；f=0x06–0x09 是次数、策略名、属性全名、属性简称（03-机制详解\特技后缀类型码-f列-后缀表与分派.md:396-405）。

### 实现·使用方法
建议保留 0x06–0x0B 六个旧特技号，优先追踪 0x0C 桩读取的效果值，再决定是否把该值解释为掩码：
- 0x01 破坏攻击
- 0x02 破坏防御
- 0x04 破坏精神
- 0x08 破坏爆发
- 0x10 破坏士气
- 0x20 破坏移动
- 0x3F 六项全选
例：0x03=攻击+防御，0x15=攻击+精神+士气，0x1F=除移动外五项。
“只控制数量、随机选 N 项”不是同一规则；那需要先取 popcount(N) 再做随机抽取，不能把数值 N 直接当位掩码。

### 风险与边界
- 外部 6.6x 资料提到 1/2/4/8/16/32、63 全部、64 随机，但它只能作为设计参考，不能代替当前 6.6 山贼样本的实机闭环。
- 直接把 0x06–0x0B 六个旧入口改成一个入口，可能破坏现有单项特技、存档或脚本兼容性；本次未写 EXE。

## 2026-10-18 追加：0x0C 数量控制已在当前样本存在

### 结论速览
- 当前样本 0x0C 的处理链已经把查询到的效果值当作“破坏数量”：返回 0 直接退出，正值超过 6 时钳为 6。

### 实现·使用方法

## 2026-10-18 追加：成功策略位掩码案例与装备 0x0C 的接口差异
