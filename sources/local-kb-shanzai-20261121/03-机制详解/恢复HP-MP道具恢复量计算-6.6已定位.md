# 恢复HP/MP 道具的恢复量计算（6.6 山贼·已定位）

> ★ **数值写法对照（用户口径 2026-10-15：「人类普遍爱 10 进制，但数据偏向 `0x` 即 16 进制」）**
> 本页同一批常量，**十六进制 / 十进制 / 十进制来源**并列，检索时两种写法都能命中：
>
> | 十六进制 | 十进制 | 含义 |
> |---|---:|---|
> | `0x1A` | **26** | 特效号 = **回复 HP** |
> | `0x1B` | **27** | 特效号 = **回复 MP** |
> | `0x28` | **40** | 第三类分支 |
> | `0xFF` | **255** | 效果值 = 全恢复（`+0x15`） |
> | `0x19` | **25** | 物品表行长（`+0x15` 的 25 也是它，别混） |
> | `0x43C44A` | 4440138 | 恢复量函数入口 VA |
> | `0x4837C2` | 4732866 | 物品表索引函数 |
> | `0x49F820` | 4847648 | 物品表运行时基址 |
> | `+0x15` | +21 | 效果值（回复量）——**道具 170 豆 = 130** |
> | `+0x13` | +19 | 特效号（道具段）——**豆 = 26** |

## 结论速览

1. **函数入口 = `0x43C44A`**（十进制 4440138；`ret 8`，两个栈参：`[ebp+8]` 道具编号、`[ebp+0xC]` 受用者）。
   **原版/2011 帖在同址 `0x43C42E`** ⇒ 6.6 只**整体位移 +0x1C**（同一编译单元小幅漂移）。
2. **恢复量公式 = `min(效果值, 总HP − 当前HP)`**；**效果值 `0xFF`（255）⇒ 全恢复**（取 `总HP − 当前HP`）。
   与 2011 帖逐条同构（帖中那段 `0x43C42E` 就是它）。
3. **分支按"特效号"分**：`0x1A`（**26**）= **回复 HP**、`0x1B`（**27**）= **回复 MP**、
   `0x28`（**40**）= 第三类（`0xFF − al` 后同流程）。
4. **特效号/特效值怎么取**：依次调
   `0x4837C2`（物品表索引：`0x49F820 + 道具编号×0x19`）→ `0x41DD72`（取**特效值**）
   → `0x43AD20`（取**特效号**）；受用者由 `0x40658F` 取得。
5. **★ 数据侧对账（Star.e5 实测，用户口径「ID160 开始就是道具，170 是恢复豆，特效值是回复量」）**：
   道具 **170 豆 / 171 麦 / 172 米** 的 `+0x13` = **`0x1A`（回复）**，
   `+0x15` = **回复量（130 / 164 / …）** ⇒ **与代码里的判定完全一致**。
6. **⚠ 修正一处库内字段口径**：本页实测（Star.e5 原始字节）
   **特效号在 `+0x13`、特效值在 `+0x15`**；
   而 `07-数据表与资源/宝物物品设定.md` 记的是「`+0x12` 特效号、`+0x15` 初始能力、`+0x16` 特效值」
   ⇒ **该页这三格需按本轮实测复核**（未推翻整页，仅此三格存疑，已登待验证）。

## 已确认事实

### 一、代码（6.6 现读反汇编，`func 0x43C44A`）

```asm
0043C44A  55                  push ebp
0043C44B  8BEC                mov  ebp,esp
0043C44D  51                  push ecx
0043C44E  E8 3CA1FCFF         call 0x40658F          ; 取受用者（原版此处是 *0x48+0x4A1B68 的运行时记录）
0043C453  51                  push ecx
0043C454  0FB74D 08           movzx ecx, word [ebp+8] ; ★ 道具编号（word）
0043C458  E8 65730400         call 0x4837C2          ; ★ 物品表索引 = 0x49F820 + id*0x19
0043C45D  51                  push ecx
0043C45E  E8 0F19FEFF         call 0x41DD72          ; ★ 取特效值（item+0x15）
0043C463  51                  push ecx
0043C464  8B4D F4             mov  ecx,[ebp-0xC]
0043C467  E8 B4E8FFFF         call 0x43AD20          ; ★ 取特效号
0043C46C  8B4D F8             mov  ecx,[ebp-8]
0043C46F  3C 1A               cmp  al,0x1A            ; ┐ 特效号 0x1A = 回复HP
0043C471  75 07               jne  0x43C47A          ; │
0043C473  E8 EBADFCFF         call 0x407263          ; │ → 总 HP
0043C478  EB 23               jmp  0x43C49D           ; ┘
0043C47A  3C 1B               cmp  al,0x1B            ; ┐ 特效号 0x1B = 回复MP
0043C47C  75 0B               jne  0x43C489          ; │
0043C47E  E8 0CAEFFFF         call 0x40728F          ; │ → 总 MP
0043C483  83 45 FC 04         add  dword [ebp-4],4    ; │ 局部 +4（区分 HP/MP 分支）
0043C487  EB 14               jmp  0x43C49D           ; ┘
0043C489  3C 28               cmp  al,0x28            ; ┐ 第三类
0043C48B  75 21               jne  0x43C4AE          ; │
0043C48D  8B4D FC             mov  ecx,[ebp-4]        ; │
0043C490  E8 7383FEFF         call 0x424808          ; │
0043C495  B2 FF               mov  dl,0xFF            ; │
0043C497  2A D0               sub  dl,al              ; │ 0xFF - al
0043C499  8A C2               mov  al,dl              ; ┘
0043C49B  EB 06               jmp  0x43C4A3
0043C49D  8B4D FC             mov  ecx,[ebp-4]
0043C4A0  2B 41 10            sub  eax,dword [ecx+0x10]  ; ★ 总HP/MP − 当前值（unit+0x10=Hpcur / +0x14=Mpcur）
0043C4A3  80 7D F0 FF         cmp  byte [ebp-0x10],0xFF  ; ★ 效果值 == 0xFF ?
0043C4A7  74 08               je   0x43C4B1            ;   ⇒ 全恢复（直接用"总−当前"）
0043C4A9  3B45 F0             cmp  eax,[ebp-0x10]
0043C4AC  72 03               jb   0x43C4B1            ;   余量 < 效果值 ⇒ 用余量
0043C4AE  8B45 F0             mov  eax,[ebp-0x10]       ;   ★ 否则用效果值
0043C4B1  8BE5                mov  esp,ebp
0043C4B3  5D                  pop  ebp
0043C4B4  C2 0800             ret  8
```

**语义**：`恢复量 = min(效果值, 总HP或MP − 当前值)`；`效果值 == 0xFF` ⇒ `总 − 当前`（全恢复）。

### 三、怎么找到的（可复用打法）

1. **不要整函数搜指纹** —— 帖中 `0x43C42E` 的序言 `55 8B EC 83 EC 1C …` 在 6.6 是 `55 8B EC 51 …`
   （**编译器改了序言**）⇒ 整段指纹 0 命中，**假阴性**，害我先走了弯路。
2. **改用"语义常量"搜** —— 从数据侧拿到**特效号 `0x1A`**，再搜 `3C 1A`（`cmp al,0x1A`）；
   16 处命中里 `0x43C46F` 一眼可辨（紧邻 `cmp al,0x1B`/`cmp al,0x28`）。
3. **先看数据、再找代码** —— 用户提示"从 data 的道具号入手"直接绕开了断点取证，
   几分钟定位；**数据表是最省事的入口**。

## 实现·使用方法

> ⚠ **跑 `_dsh反汇编工作台.py` 必须用 DSH 运行时那份 Python**：它**顶层 `import keystone`**，
> 而 `keystone` **只装在**
> `%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`；
> 系统 `Python314` 只有 `capstone` ⇒ 用错解释器时 `func`/`df`/`xref` **所有子命令**
> 齐刷刷 `ModuleNotFoundError: keystone`（本轮实测踩到）。

- **改回复量**：改 `Star.e5` 里对应道具记录的 **`+0x15`**（特效值）。
  道具 170（豆）在 `Star.e5` 偏移 **`0x672`**，其 `+0x15` 位于文件偏移 **`0x672+0x15 = 0x687`**。
  ⚠ 写 `Star.e5` **不是写 EXE**，但仍属**游戏数据文件** ⇒ 动前先备份并说明；
  若用户在编辑该文件，**必须先问**（AGENTS.md §0.0 精神）。
- **想要"按百分比恢复"**：改 `0x43C49D~0x43C4AE` 那几行（把 `效果值` 换成 `总HP × 效率 / 100`），
  **这正是 2011 帖给出的改法所在的位置**（帖中改 `0x43C4A9` 起；6.6 对应 `0x43C49D` 起）。
  当前 `0x43C4A3` 的 `0xFF ⇒ 全恢复` 分支若要保留，需一并设计。
- **同一类的"是否显示可恢复"** 与 **豆袋动画** 未在本页确认（见待验证）。

## 风险与边界

1. 本页结论为**静态反汇编 + 数据表字节复读**，**未做实机运行验证**（证据等级：静态）。
2. `0x43C44A` 的**参数含义**（`[ebp+8]`=道具编号 word、`[ebp+0xC]`=受用者）来自 2011 帖的注释 +
   控制流推断，**未实机确认**；`word` 宽度是我从 `movzx ecx, word [ebp+8]` 读出的。
3. `0x40658F`（取受用者）与 `0x43AD20`（取特效号）的内部语义未展开；
   2011 帖称原版用 `*0x48 + 0x4A1B68`，**6.6 的对应关系未核对**。
4. **写 `Star.e5`/`Data.e5` 不在写锁（`_dsh写锁.py`）管辖范围内** —— 写锁只管 `Ekd5.exe`。
   ⇒ 改道具表**必须自行备份 + 复读比对**，没有工具的第三重校验保护。
