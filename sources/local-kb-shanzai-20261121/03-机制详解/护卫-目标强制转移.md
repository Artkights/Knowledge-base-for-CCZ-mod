# 护卫-目标强制转移（九宫友军代受）

## 结论速览

- 「九宫范围内的友军被攻击时，**目标强制转为自己**」= 两段式改动：
  1. **判定入口替换**：把 `0x410F1C`（攻击可行性判定）第 4 条指令 `0x410F23` 的 `call`
     换成 `call 0x41AABC`（护卫选择），**返回的 `ecx` = 护卫者**，
     由于 `0x410F1C` 后续全部以 `ecx` 为"目标"，**目标就此被顶替**；
  2. **执行入口参数交换**：在调用 `0x4064F1`（真正发动攻击，内含连击循环）之前，
     用 `xchg` 交换攻守两个参数（`0x4105C8` / `0x43ACA2` / `0x43DB63` 三处）。
- ★ **最省力的"改目标"手法**：不要去改"目标变量"，而是**替换判定链第一步的 `call` 目标**，
  让被调函数返回**新的目标指针到 `ecx`** —— 后续判定（状态、特技、范围、命中）会自动跟着新目标走。
- ★ **偷栈取参**：本项目引擎大量使用 Borland register/fastcall 约定（参数不显式压栈、
  callee 用 `ret` 由调用者清栈），因此补丁用两种方式"偷看"调用者的栈：
  - 桩函数 `0x41AA98`：`mov edx,[esp-4]` / `mov ecx,[esp-0x10]` / `mov ecx,[ecx+4]` / `ret`；
  - 被调函数直接读 `[ebp+8]…[ebp+0x18]`（这些位置其实是**调用者的栈内容**）。
- ★ **返回地址当"调用来源指纹"**：`0x41AABC` 用 `cmp dword [ebp+0x10], 0x417C11`
  判断"这次是不是从 `0x417C0C` 那条路径来的"。`0x417C11` 正是 `call 0x410F1C` 的**下一条指令地址**
  ⇒ 命中即跳过护卫 ⇒ **这就是注释里"目标被围攻时无效"的判据**。
- 三条前置条件的落点：
  | 注释 | 实现地址 | 手法 |
  |---|---|---|
  | 混乱时无效 | `0x41AB0A` `push 8` + `call 0x423FE8` | 状态位 8 命中即跳过 |
  | 特效值≠1 时护卫者必须在敌人攻击范围内 | `0x41AB21` `cmp al,1` / `je`，否则 `0x43F8C0` + `0x412B30` | 特技值 =1 直接放行，否则做范围判定 |
  | 目标被围攻时无效 | `0x41AAD1` `cmp [ebp+0x10],0x417C11` | 返回地址指纹 |
- **当前样本已装 6.6x 版护卫**（10 段里 7 段逐字节一致，含 4 处 hook 与特技号 `DA`）。
  差异只有两个**可配置项**：生效范围（`0x41AAE4` 当前 `00` = 4 向，文本为 `01` = 8 向）
  与提示语（当前"掩护！"，文本"休伤吾主！"）。

## 已确认事实

### 一、代码洞 `0x41AA98`~`0x41AB9C` 内存放三个函数

```asm
41AA98  8B 54 24 FC      mov  edx,[esp-4]        ; ★ 偷栈桩：取调用者栈槽
41AA9C  8B 4C 24 F0      mov  ecx,[esp-0x10]     ; ★ 另一个栈槽
41AAA0  8B 49 04         mov  ecx,[ecx+4]        ; 取其 +4 字段
41AAA3  C3               ret
41AAA4  55 8B EC         push ebp / mov ebp,esp
41AAA7  6A 01            push 1                  ; 效果值标志 = 1（要值）
41AAA9  6A 01            push 1                  ; 叠加标志 = 1（不可叠加）
41AAAB  68 00 00 00 00   push 0                  ; 宝物号（参数行 -41AAAC）
41AAB0  68 DA 00 00 00   push 0xDA               ; 个人特技号（参数行 -41AAB1）
41AAB5  E8 1F 57 FF FF   call 0x4101D9           ; 核心特技引擎，ecx = 单位指针
41AABA  5D C3            pop ebp / ret
41AABC  …                ← 护卫主逻辑（见第三节）
```

- `0x41AAA4` 是**取特技值的包装**（对应物理免疫里的 `0x43BA83`）：不设置 `ecx`，
  因此调用前必须先把单位放进 `ecx`。
- `0x41AA98` **只改 `edx`/`ecx`，不动 `eax`** ⇒ 调用点后面紧跟的 `test eax,eax`
  测的是**进入该点之前就存在的 `eax`**（即 `0x410F1C` 的判定结果），这是设计而非笔误。

### 二、判定入口替换：`0x410F1C` 的完整契约

```asm
410F32  75 62            jne  410F96           ; 有 → 返回 0
410F34  8B 4D F8         mov  ecx,[ebp-8]      ; ★ 注意：函数只 push 了 ecx 一次，
…                                              ;   [ebp-8] 是调用者的栈内容
410F61  8B 4D F8         mov  ecx,[ebp-8]
```

- `0x410F1C` 返回 `al` = 1（可攻击）/ 0（不可）/ `0xFF`（特殊，调用点专门判它）。
- **补丁只改了 `0x410F23` 一处 5 字节**，却完成了"目标顶替" —— 因为紧接着的
  `push ecx; push 8; call 0x423FE8`、`call 0x410F0A`、`call 0x412B30` 全部以 `ecx` 为对象。
- 调用点（`0x4105C4`、`0x43AC9E`、`0x43DB76`、`0x417C11`）统一写 `cmp al,0xFF / je <跳过>`。

### 三、护卫主逻辑 `0x41AABC`：参数靠偷栈，选人靠遍历

**栈对应关系**（这是本页最关键的一张表）：`0x410F23` 处只写了 `call`，
没有压任何参数，所以 `0x41AABC` 读到的"参数"其实是 `0x410F1C` 的栈：

| `0x41AABC` 读 | 实际来源 | 含义 |
|---|---|---|
| `[ebp+8]` | `0x410F1C` 的 `[ebp-4]` | 进入 `0x410F1C` 时的 `ecx` |
| `[ebp+0xC]` | 保存的 old `ebp` | 无用 |
| **`[ebp+0x10]`** | **`0x410F1C` 的返回地址** | **调用来源指纹**（`0x417C11` = 围攻路径） |
| `[ebp+0x14]` | `0x410F1C` 的参数 2 | `0x43DB63` 路径用 |
| `[ebp+0x18]` | `0x410F1C` 的参数 1 | 原目标（`0x41AB58` 取回） |

推导依据：`0x410F1C` 序言为 `push ebp / mov ebp,esp / push ecx`（仅一个局部），
故 `ebp_41AABC = ebp_410F1C - 8`，于是 `[ebp+0x10] = [ebp_410F1C + 4]` = 返回地址。

**主流程**：

```asm

41AAC1  51               push ecx              ; [ebp-8] = 原参数1
41AAC2  E8 32 B7 FE FF   call 0x4061F9         ; 战场编号 → 单位指针（走 cl，返回 ecx）
41AAC7  51               push ecx              ; [ebp-0xC]  = 当前目标（初值）
```

```asm

4105D6  B9 F0 27 49 00   mov  ecx,0x4927F0      ; ctx
```

- `0x4064F1` = **发动一次物理攻击**（`0x4064F4 push ecx` 存 ctx，`0x406514` 清 `ctx+0x608`，
  `0x40651D inc [eax+0x608]` 与 `0x40655A jne 0x40651D` 构成**连击循环**，
  末尾 `0x4E30E1`/`0x4E3000` 在 `.text3`）。
  它内部还有 `cmp byte [0x500E9A],1` 的分支 ⇒ `0x500E9A` = **攻击类型/战斗模式标志**。
- 三处 `xchg` 方向不同（A 是 `ecx,edx`，B/C 是 `edx,ecx`），但都发生在 `push` 之前，
  因此**交换的是同一个二元组** —— 顺序差异来自各路径的寄存器初值不同；
  改补丁时必须**连方向一起照抄**。

## 实现/使用方法

### 1. 参数配置表（全部是单点字节）

| 地址 | 当前样本 | 文本值 | 含义 |
|---|---|---|---|
| `0x41AAAC` | `00` | `00` | 宝物号（00 = 不含宝物） |
| `0x41AAB1` | `DA` | `DA` | 个人特技号（6.5 版默认 `D1`） |
| `0x41AAE4` | **`00`** | **`01`** | 生效范围：`00` = 4 向（十字），`01` = 8 向（九宫） |
| `0x41AB7B` | `04 04` | `04 04` | 说话开关：`00 00` = 不说话；`04 04` = 说话（`add eax,0x404` 的立即数） |
| `0x41AFE0` | **"掩护！"** | **"休伤吾主！"** | 触发提示语（GBK，必须 `00` 结尾，长短随意） |

⇒ **当前样本与文本只差"范围"和"提示语"两项**。若只想把护卫范围从十字扩到九宫，
**写 1 字节即可**：`-41AAE4  01`（该地址落在 `0x41AA98` 段内部，单独写 1 字节不会破坏其它代码）。

### 2. 「改目标」类特效的通用套路（本页最值得复用的部分）

```asm
; 第一步：在"目标确定"或"攻击可行性判定"函数的最前面，替换它的第一条 call
;         （被调函数返回"新目标指针"到 ecx）
41xxxx  mov  ecx,[ebp+8]        ; 原目标编号（引擎原有指令）
41xxxx  call <护卫选择>          ; ★ 换成自己的函数；返回 ecx = 新目标
41xxxx  push ecx                ; 后续全部逻辑自动跟着 ecx 走
        ...
; 第二步：在"真正发动攻击"的调用点前，交换攻守参数
        call <偷栈取参桩>        ; edx / ecx ← 调用者的两个栈槽
        test eax,eax
        je   skip
        xchg ecx,edx            ; ★ 交换
skip:   push edx
        push ecx
        mov  ecx,<ctx>          ; 0x4927F0
        call <发动攻击>          ; 0x4064F1
```

**偷栈桩的写法**（当无法给被调函数传参时）：

```asm
<桩>:  mov edx,[esp-4]     ; 调用者的某个栈槽（相对 call 后的 sp）
       mov ecx,[esp-0x10]  ; 另一个栈槽
       mov ecx,[ecx+4]     ; 取其 +4 字段
       ret
```

**"调用来源指纹"的写法**（用于只在特定调用路径上生效）：

```asm
mov eax,<目标调用点的下一条指令地址>   ; 例如 0x417C11
cmp [ebp+0x10],eax                    ; [ebp+0x10] = 调用者的返回地址
je  <跳过分支>
```

## 风险与边界

- ★ **整份照抄会改掉两个现网配置**：生效范围 `00 → 01`（十字变九宫）、
  提示语 `"掩护！" → "休伤吾主！"`。前者是**行为变化**，后者是**文本变化**，需先确认再写。
- ★ **偷栈强绑定栈布局**：`0x41AA98` 的 `[esp-4]`/`[esp-0x10]`、
  `0x41AABC` 的 `[ebp+8]`/`[ebp+0x10]`/`[ebp+0x18]` 全部依赖
  "调用点当时的 sp/ebp 位置"。**换样本、换编译器、或在调用点前后插入字节，
  都会取到错误的值**（症状：目标乱换、崩溃）。跨版本迁移时必须重新推导整条栈链。
- **与殭屍大法的代码区重叠**（6.5 记录）：护卫占 `41AA98-41AB9E`，
  殭屍大法占 `41AB00-41AB2F` —— 6.6x 版护卫实际用到 `0x41AB9C`，
  两者**不能原样共存**，必须重排代码洞并重算相对跳转。
- **`0x41AABC` 用 `ret` 而非 `ret n`**（调用者清栈），它读 5 个"参数"但不弹栈；
  若在其他调用点复用，必须保证同样的栈布局与清栈方式。
- **判定与执行必须成对**：只改判定入口（目标被顶替）而不改执行入口，
  会出现"预览显示打护卫者、实际打原目标"之类的不同步；反之亦然。
- **`0x410F1C` 是公共判定**：`0x4105C8`、`0x43ACA2`、`0x43DB63`、`0x417C11` 四条路径都经过它，
  改 `0x410F23` 会对**全部四条**生效（这正是"和先手同触发时机"的原因）。
