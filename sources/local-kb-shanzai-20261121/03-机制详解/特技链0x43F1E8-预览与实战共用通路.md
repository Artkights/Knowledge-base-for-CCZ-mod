# 特技链 `0x43F1E8~0x43F290`：伤害预览与实战为什么能一致

> **触发**（用户口径 2026-10-15）：提供「回马攻击」「劲透攻击」两个特技补丁，
> 并问：「结合相关代码，分析其完成伤害预览显示的原因，**我们暴击预览是否能够通过这个去完成**，
> 数据库中是否能够理解 #发起攻击前方向记录 / #临时储存攻击前方向 / #先手攻击前方向记录
> 以及攻击时若侧向转身伤害增加、反向转身效果翻倍」。
> → 本页是完整回答。

## 结论速览

1. **★ 预览与实战共用同一条伤害公式，公式内部就会过特技链** —— 这是"预览能显示加成"的根因：
   ```
   预览 0x44049E ──0x440668 call──▶ 伤害公式 0x43BC5A
   实战 0x405DE1 ──0x405E6D call──▶ 伤害公式 0x43BC5A
                                        │ 公式内部 0x43BEDF call 0x42423D
                                        ▼
                       0x42423D → 0x43BCA9 → 0x43F1E8【特技链】
   ```
   ⇒ **链上任何加成，预览与实战自动一致**，不需要额外写预览代码。
2. **暴击做不到同样是这个原因**：`call 0x42E4FD`（暴击加成）**全映像只有 1 个调用者 = `0x405F0B`**，
   在**实战路径**上；预览函数 `0x44049E` 的调用表里没有它 ⇒ 预览看不到暴击。
3. **★ 暴击预览的正解 = 把暴击加成做成特技链上的"第 9 个槽"**（见 §实现方案），
   而不是去改 `0x44049E` 内部的局部变量（那是无效的，且会崩）。
4. **`#临时储存攻击前方向` 的真相**：`0x441EE7` 是 `0x441EE4` 处 `C2 08 00`（`ret 8`）
   的**立即数高字节**（本来恒为 0）。补丁**把这个恒 0 字节当全局变量用**——
   改它不影响 `ret 8` 语义。**这是"借指令字节当变量"的技巧，不是自修改代码。**
5. **本机当前未应用这两个补丁**：`0x441EE7` 实测 = `00`、`0x43F23D` 实测仍是 `call 0x441EE8`
   —— 但**第 7 槽 `call 0x442392`（劲透攻击）已在链内**，说明劲透是原有特技、回马是新增槽。

## 适用版本

* 样本 `Ekd5.exe`，SHA 见 `_样本时间线.md` 现读（地址只对该 SHA 成立）。
* 证据类型：静态复读（`_dsh反汇编工作台.py`）+ MCP `exe_bytes` 字节复读。

## 已确认事实

### 一、特技链的调用契约

链体位于函数 **`0x43F07C`** 内（`0x43F1E8`~`0x43F290`），模式高度统一——
**每槽收上一槽的累加值、返回新累加值**：

```asm
0043F1EE  push [ebp-0x2C]     ┐
0043F1F1  push [ebp+8]        │ 固定 4 参数
0043F1EE  push [ebp-4]        │   [ebp+0xC] / [ebp-0x2C] / [ebp+8] / [ebp-4]
          call <槽函数>        ┘
0043F1F6  mov  [ebp-4], eax   ; ★ 结果写回累加器
```

| 槽 | 调用点 | 目标 | 归属 |
|---|---|---|---|
| 1 | `0x43F1F1` | `0x43C31D` | 已有特技 |
| 2 | `0x43F202` | `0x43EA00` | 已有特技 |
| 3 | `0x43F213` | `0x441C81` | 已有特技 |
| 4 | `0x43F224` | `0x441E09` | 已有特技 |
| 5 | `0x43F235` | `0x441E9C` | 已有特技 |
| **6** | `0x43F249` | **`0x441EE8`** | **回马攻击**（用户要加） |
| 7 | `0x43F266` | `0x442392` | **劲透攻击** |
| 8 | `0x43F277` | `0x441D87` | 已有特技 |

* 槽 6 的插入方式（用户文本 `-43F23D` 那 5 行）：在 `0x43F23D` 处
  `push [ebp+0xC] / push [ebp-0x2C] / push [ebp+8] / push [ebp-4] / call 0x441EE8 / mov [ebp-4],eax`，
  并在其后补 `cmp [ebp+0xC],0 / jne ... / cmp [ebp+0x40],0 / jne <跳过槽7>` 的条件逻辑。
* 槽 7/8 之间（`0x43F251`~`0x43F26E`）确实存在 `cmp [ebp+0xC],0` / `cmp [ebp+0x40],0` 的**跳过判定**。

### 二、`#临时储存攻击前方向` = `0x441EE7`

```asm
00441EE4  C2 08 00     ret 8      ; C2=opcode, 08=imm16 低字节, 00=imm16 高字节
00441EE7  00                     ; ★ 这个高字节被当全局变量用（本来恒 0）
```

* 读：`00441F13  movzx ecx, byte [0x441EE7]`
* 写：由 `#发起攻击前方向记录`（`-43583A` → `call 0x441EE8`）与
  `#先手攻击前方向记录`（`-410F8D` → `call 0x410F8D+5` 目标）在攻击开始时写入。
* **注意**：`0x43583A` 原本是 `E8 24 C7 00 00` = `call 0x441F63`；
  补丁把它改成 `call 0x441EE8`（记录方向）⇒ **原 `0x441F63` 的调用被搬进了新函数体内**
  （见 `0x441F63` 之后的第二段函数：`call 0x4061F9` 等）。

### 三、方向判定与倍率（`0x441EE8`）

```asm
00441EE8  push ebp / mov ebp,esp
00441EEB  mov  ecx,[ebp+0x10]          ; 参数3
00441EEE  push 0 / push 1 / push 0 / push 0xA9
00441EFC  call 0x4101D9                ; 检查特技 0xA9（回马攻击）
00441F01  test eax,eax / je 0x441F5A   ; 无该特技 ⇒ 直接返回
00441F05  push eax                     ; 保存效果值（倍率增量）
00441F06  cmp  dword [ebp+0x14], 0
00441F0A  jne  0x441F1C
00441F0C  mov  ecx,[ebp+0x10]
00441F0F  movzx eax, byte [ecx+0x0F]   ; ★ 目标当前朝向（+0x0F）
00441F13  movzx ecx, byte [0x441EE7]   ; ★ 攻击前朝向（临时储存）
00441F1A  jmp  0x441F3D
00441F1C  ... push ... call 0x435539    ; 另一路径：算朝向
00441F33  mov  ecx,[ebp+0x10]
00441F36  movzx ecx, byte [ecx+0x0F]
00441F3A  movzx eax, al
00441F3D  cmp  eax, ecx
00441F3F  je   0x441F5A                ; ★ 同向 ⇒ 不加成
          ... 0xD0 65 FC（shl byte [ebp-4],1）或同类 ⇒ ★ 反向转身效果翻倍
00441F..  push 效果值 / push [ebp+8] / call 0x425AD9 / add [ebp+8],eax
00441F..  mov eax,[ebp+8] / mov esp,ebp / pop ebp / ret 0x10
```

* **朝向字段 = 单位结构 `+0x0F`**（与库里"战场编号×4 计集气"无关，是朝向字节）。
* 语义：与攻击前朝向**相同** ⇒ 不加成；**不同** ⇒ 加效果值；
  **反向（相差 2，即 180°）** ⇒ 翻倍。

## 实现·使用方法

### ★ 把暴击加成做成特技链的第 9 个槽（推荐方案）

`0x42E4FD` 的契约（实测反汇编）：

```asm
0042E4FD  mov  ecx,[ebp+0x10]   ; 参数3 = ctx
0042E503  mov  ecx,[ecx+0x0C]   ; → 攻击者
0042E506  push 0/1/0/0x70  / call 0x4101D9   ; 特技 0x70 的效果值
0042E513  mov  ecx,[ebp+0x0C]   ; 参数2 = 暴击率
0042E516  sar  ecx,1            ; K = 暴击率/2
0042E51C  add  ecx,eax          ; K += 0x70 效果值
0042E521  push [edx] / push ecx / call 0x425AD9   ; 伤害 += 伤害*K/100
0042E52C  add  [edx],eax
0042E531  ret  0x0C             ; ★ 3 参数
```

⇒ 槽内实现（伪汇编，落点建议 `0x43F290` 之后的链尾或新增跳转）：

```
; 入参沿用链的固定帧：ecx=[ebp-0x2C](攻击者) / edx=[ebp+8](伤害槽) / [ebp+0xC]
mov  edx, [ebp+8]
mov  [edx], <当前累加伤害>        ; 与链的 [ebp-4] 对齐
push [ebp+0xC]                   ; 参数3 ctx
mov  eax, <攻击者战场编号>
mov  ecx, <K>                    ; K = 暴击率 或 暴击率+100（>100 时不加 100）
push ecx / push edx
call 0x42E4FD
mov  [ebp-4], [edx]              ; 取回累加值
```

**前置判定（必须自己加，`0x42E4FD` 不判）**：
`集气模式 4018==1` 且 `byte [0x4930C8 + 攻击者编号*4 + 2] >= 100`；
其中 `K` 的取法照 `0x405ED5`：**暴击率 ≤ 100 ⇒ K = 暴击率 + 100；> 100 ⇒ K = 暴击率**。
**★ 判定依据必须是"攻击者自己的暴击集气"**，不能拿目标 slot 查表（这正是先前补丁走偏之处）。

## 风险与边界

* **★ 必须用 x32dbg 验证后再打**：先前把暴击逻辑放进 `0x44049E` 内部（改 `[ebp-0x18]`）
  的版本导致**读档时进程退出**（转储 `0xC0000409` GS 栈检查失败），已回滚。
  改"链上新增槽"与改"预览函数内部"是**完全不同的位置**，但仍需执行级验证。
* 槽内调用必须**保持链的栈契约**（`ret` 清理与 `[ebp-4]` 写回），否则会重演栈破坏。
* `0x43F251`~`0x43F26E` 的条件分支（`[ebp+0xC]` / `[ebp+0x40]`）语义**未闭环**，
  新增槽时不要踩这两个字段。
* 代码洞：`0x457DB4`~`0x459000`（`0x90`×4684）。
  **注意 `0x457D7B` 不是洞起点，它是补丁点自身**（`E9 DD 76 01 00`）。

## 证据来源

* 静态复读：`0x43F1E8~0x43F290` 链体、`0x43BEDF call 0x42423D`、`0x42423D → 0x43BCA9`、
  `0x43BC5A` 的 5 个调用者（`0x405E6D`/`0x419AED`/`0x438A2A`/`0x438CCA`/**`0x440668`(预览)**）、

**本页上面有几处错误，以本节为准。** 详见 `03-机制详解/回马攻击0xA9与劲透攻击0xDF-特技号核对.md`。

|---|---|---|
| 把 `68 DF` 读成 ASCII `"DF"` | `0x4423A1 = 68 DF 00 00 00` | 是 **`push 0xDF`** —— **劲透攻击 = 特技号 `0xDF`** |
| 「回马攻击补丁**尚未**应用」 | `0x441EE8` 前 24 字节与 `0x441EE8` 索引下的补丁字节一致；链上 `0x43F249` 已 `call 0x441EE8` | **★ 已装**。`0x441EE7 = 00` 只是**初始值**，不能当"未装"依据 |
