## 2. 已证事实（静态现读，**不要重复推导**）

调用链：`byte[0x4D1570+0x6F]=0x27` → 分派 `0x425627` → `.text3` 垫片 `0x4E4700` → 效果跳表 `0x4259C3[0x27] = 0x4256F5` → `0x425710`（`ctx+0x400=0x5B`）→ `0x423230` → 逐目标函数 `0x423594` → hook `0x42365C` → 结算 `0x4251BD`（= `0x421496` + `0x42269C` + `[ctx+0x550]=1`）。

1. **全链按 `0xFF` 列表遍历，不存在计数遍历**：`0x423261`、`0x422700/0x422704`、`0x42E5E9` 三处都是 `cmp …,0xFF` 收尾；收尸 `0x40502B` 是 **0..0xF9 全槽扫**（`cmp cl,0xFA ; jae`）。
   `ctx+0x0C` 是"**当前目标 id**"（`0x423261` / `0x42270C` 写入），**不是计数**。
2. **追加项必被结算**：flag=0 → `0x422BC2[0]=0x00` → 跳表 idx0 → `0x42284E`；伤害≠0 ⇒ `[ebp-0xC]=0xFF` ⇒ `0x42291D`。flag≥0x90 → `0x422864` → 同样 `0xFF` ⇒ `0x42291D`。**两条只跳过特效，扣血照旧**。
3. **伤害钳位是引擎做的**：常规类型在 `0x422999` `dmg=min_signed(dmg,HP)`；`0x43F6DB` 写 HP 时只有"超上限压回"，**没有下限 1、没有治疗**。`0x41B500` = `mov eax,[ecx+0x10]; ret`（读 HP）。
   类型分派是精确比较（`0x42293B/0x422944/0x422948/0x422950`：`0x20/3/0x0E/0x18`），0x27 走**常规分支**；类型 0x18 读 `ctx+0x10C`，转移链只写 `+0x108` ⇒ 不可达。
4. **结算内 HP==0 不判死**：`0x422A1E call 0x41B500 / test / jbe 0x422A47` ⇒ 直接进下一目标，无 `0x441744`。阵亡只能靠事后全槽扫。
5. **`0x441744` 无 HP 门禁**：唯一前置 `0x44174F cmp byte[ecx+0xC],2 / jne 0x441890`；全函数无 `0x41B500`；结尾 `0x44181A push 3 / 0x44181F call 0x443120`（= `mov [ecx+0xC],al`）**直写 view=3**，`0x441827` 清状态位。
6. **收尸扫确实存在，但带闸门**：`0x42BC14` 唯一路径 → `0x40502B`；`0x42BC14` 的 7 个调用点之一是**外层状态机 `0x44E0D9` 内的 `0x44E540` / `0x44E54D`**（`0x44E0D9` 由 `0x44ED7F` 逐方调用）。
   闸门：`cmp [ebp-0x1C],0 / je 0x44E620`、`cmp [ctx+1],2 / je 0x44E583`、`cmp [ctx+1],5 / je 0x44E59C`。
   ⇒ 旧结论「策略链不跑全槽判死」只对**策略子链**成立，**不是整轮行动都不跑**（§3.7 已修正）。
7. `0x44DE9E` 只更新 `ctx+0x502/+0x506`（最大伤害）与 `ctx+0x50A`（守护位），**不治疗**。

## 4. 待证伪（按优先级）+ v24 审计清单

### 4.1 复活根因（优先级从高到低）

- **A（首选）收尸扫被跳过**：策略行动那一轮 `0x44E0D9` 的 `[ebp-0x1C]` 或 `[ctx+1]` 落进跳过分支。
  判据：在 `0x44E0D9` 入口、`0x44E540`/`0x44E54D` 各打**不暂停日志点**，同一次施法记录 `[ebp-0x1C]`、`[ctx+1]`、是否到达 `0x40502B`、到达时该承接者 `[unit+0xC]`/HP。
- **B 选人没有 view/HP 过滤**：洞内扫 `0x4AC748` 只跳原目标 `[edi+0x34]`、施法者 `[edi+0x28]`，按 `HP*1000/maxHP` 取最小比值，**未见 view/HP 过滤**。
  判据：在洞内选人段读候选 `[+0x0C]`（view）与 HP；若承接者本身 view≠2 或 HP≤0，追加位伤害被钳成 0 ⇒ 不会"复活"，只会白费转移量。
- **C HP 被事后抬回**：`0x45AB05 → 0x40DA4A`（`[0x505F30]==0` 模式）有"下限 1"分支。
  判据：`_阵亡收集链探针.py --scan` 的 `C-满血` 标签；命中即抓"0→上限"的写入者。
- **D 洞写错单位/槽位**：`.append` 位置与 `.found` 索引错位、或多个原目标命中同一承接者时二次追加。
  判据：洞内日志打印 `pos` / receiver id / 写入前槽值 / 追加后 `ctx+pos+0xD` 与 `ctx+pos+0xE`；与结算 `0x42269C` 实际扫到的序列逐项对账。

### 4.2 v24 补丁审计（逐项给 PASS / RISK / FAIL）

1. **挂点共享面（最大未知风险）**：确认 `0x423594` 只因效果 `0x27` 到达；并现读 `byte[0x4D1570+i]` 全 256 项，**列出所有 ==0x27 的策略 id**。若不止 0x6F，本补丁会作用到那些策略上 ⇒ 必须先报用户。
   命令：`python 大鲸鱼产生专用\_dsh反汇编工作台.py db 0x4D1570 256`。
2. **追加位 flag 残留**：洞内 `.append` **不写** `ctx+pos+0x401`（v14 写过 `0xFF`，v15 已删）。flag=0/≥0x90 安全；但若残留 ∈ `0x5F..0x8F`，`0x422746 sub eax,0x3F` 得 `0x20..0x50`，`mov al,[eax+0x422BC2]` **读表外字节**再跳表 ⇒ 可能崩。
   先 `db 0x422BC2 64` 看表外内容；若要消除不确定性，最小修法是追加时写 0：`C6 84 0E 01 04 00 00 00`（7 B，**行为与残留 0 完全一致，只是确定化**），先确认洞里剩 7 B。
3. **参数块与 scratch 是否撞车**：段 3 在 `0x458400` 写 `0x18`（24%），洞内又用 scratch 存 计数/索引/转移量/候选/HP/施法者/原目标。**以 v15 txt 与 `0x458000` 反汇编为准核对偏移**，别信记忆；若重叠 ⇒ 百分比运行期被踩。
4. **栈纪律**：洞入口 `pushad`（+`pushfd`?）、出口 `lea esp,[ebp-0x3C]` —— 核对洞内局部不越过 `ebp-0x40`，出口恰好复原被覆盖的 5 B。

6. **名表**：`0x4CCCF0` 写入长度/内容，与邻居 `0x4CCD10`（0x71）/`0x4CCBF0`（0x5F）不撞。
7. **上限**：`cmp ecx,0xFA / jae` 列表满则静默丢弃转移量 —— 可接受，但要写进文档。
8. **百分比**：`0x458400=0x18`（24%）是否就是用户要的值 —— **问用户**，别猜。
9. **跨施法幂等**：每次施法前 `0x42528F` memset 覆盖 `ctx+0x108..0x4FA` ⇒ 列表/槽位应重置；核对 `ctx+0xD` 列表也被重置（若不在 memset 范围，需另证）。

## §3.15 现读更正：0x27共享效果的直接调用边界（2026-10-25，只读）

- 原文把 `0x4256F5→0x423230→0x423594→0x42365C` 写成一条连续调用链；当前干净样本反汇编应更正为：`0x4256F5` 落入 `0x425710..0x425737`，`0x425737→0x423230`，随后是 `0x43B4B6/0x44DE9E`。
- 当前 `0x423230` 只有直接调用点 `0x425737`；当前 `0x423594` 只有直接调用点 `0x4231E5`，`0x42365C` 是 `0x423594` 尾声。二者不是当前静态证据下的同一条连续链。
- 因此 `0x42365C` 作为精简候选挂点尚不能证明会被 `0x6F→0x27` 路径执行；A 闸门 `0x44E0D9` 与 0x6F共享效果路径的中间桥接仍待继续静态追踪。


## §3.16 再更正：0x42365C 属于另一组效果入口（2026-10-25，只读）
