# 物理伤害计算链与「预览不同步」根因

> **本页回答两件事**：① 物理攻击的伤害是怎么构成的（公式与数据来源）；
> ② 为什么"攻击前预览"显示的是**未减伤**的伤害。
> 建立日期：2026-10-14｜证据类型：**离线反汇编 + 文件复读**（样本 SHA `135A22E7…`），未挂断点。

## 结论速览

**物理伤害在一次调用里走完：公式计算 → 写伤害槽 → 暴击/减伤修槽。**

```
0x405DE1  伤害主控函数（每次物理伤害的入口；v5/v6 补丁点 0x405EF9 在此函数内）
   │  入口先清零两个伤害槽：ctx+0x84（物理）、ctx+0x254（策略）   ← 0x405DEA~0x405E12
   │  遍历目标数组，逐目标处理
   ├─ 0x405E6D  call 0x43BC5A     ← ★ 物理伤害公式
   │             ↓ 返回 EAX = 该目标的伤害值
   └─ 0x405E9A  mov [edx], eax    ← ★ 写入伤害槽 ctx+0x84（edx = ctx + n*4 + 0x84）
                 ↓
      ctx+0x84 = 伤害值
                 ↓
      0x405EDD  call 0x4287a8     ← 暴击随机判定
      0x405EF0  call 0x42aa2a     ← 防御暴击 0x24 谓词（双特技复合谓词）
      0x405EF9  ← ★ v5/v6 补丁跳板：把 ctx+0x84 按 (100-V)/100 改小
      0x405F17  mov [eax+0x604], 1 ← 写暴击标志
      0x404A77（物理飘字）读的正是 ctx+0x84
```

## 一、物理伤害公式（`0x43BC5A`）

```
伤害 = 伤害基数(25) + 等级 + (攻击 - 防御) / 2
                                └─ 右移 1 位实现（shr eax,1）
```

**当前样本逐字节对应**（文件复读，`Ekd5.exe` SHA `135A22E7…`）：

| VA | 字节 | 指令 | 含义 |
|---|---|---|---|
| `0x43BD36` | `83 C0 19` | `add eax,0x19` | **伤害基数 = 25** |
| `0x43BD37` | `89 45 FC` | `mov [ebp-4],eax` | 初值存入累加槽 `[ebp-4]` |
| `0x43BD3A` | `8B 45 E0` | `mov eax,[ebp-0x20]` | 取**攻击** |
| `0x43BD3D` | `3B 45 F0` | `cmp eax,[ebp-0x10]` | 与**防御**比较 |
| `0x43BD40` | `72 0A` | `jb 0x43BD4C` | 攻击 < 防御 ⇒ 负数分支 |
| `0x43BD42` | `2B 45 F0` | `sub eax,[ebp-0x10]` | `攻击 - 防御` |
| `0x43BD45` | `D1 E8` | `shr eax,1` | **÷ 2** |
| `0x43BD47` | `01 45 FC` | `add [ebp-4],eax` | 累加到初值 |
| `0x43BD4C` | `8B 45 F0` | `mov eax,[ebp-0x10]` | 负数分支：取防御 |
| `0x43BD4F` | `2B 45 E0` | `sub eax,[ebp-0x20]` | `防御 - 攻击` |
| `0x43BD52` | `D1 E8` | `shr eax,1` | **÷ 2** |
| `0x43BD58` | `E8 41 3D 04 00` | `call 0x47fa9e` | 下限保护 |
| `0x43BD68` | … | `call 0x413260` → 若返回非 0：`call 0x43f74f` + `0x43c708` + `imul` + `call 0x425ad9`（= `a*b/100`） | **特技/倍率修正段**（在公式之后叠加） |

- 操作数来源：函数入口调 `0x40658f`（单位→人物记录）、`0x43637b`；
  `[ebp-0x20]` / `[ebp-0x10]` 两个操作数的**赋值点位于 `0x43BC96~0x43BCE4` 的 NOP 区**
  （历史补丁痕迹，见"风险与边界"）。
- ⚠️ 旧文本（`Star6.5引擎CMF人工地址清单`）把**物理伤害基数**记在 `0x3B136`，
  与当前样本的公式内立即数 `0x43BD36` 不是同一处，引用时别混。

## 二、★ 为什么"预览"看不到减伤（根因）

**关键在同一函数内的先后顺序**：

| 次序 | 地址 | 动作 | `ctx+0x84` 的值 |
|---|---|---|---|
| 1 | `0x405E6D` | 调 `0x43BC5A` 算出**基础伤害** | — |
| 2 | `0x405E9A` | `mov [edx],eax` **写入伤害槽** | `D`（未减伤） |
| 3 | `0x405EF9` | **v5/v6 补丁**：按 `(100-V)/100` 改小 | `D×(100-V)/100` |
| 4 | `0x404A77` | 物理飘字读槽显示 | 显示第 3 步的值 ✅ |

⇒ **飘字（伤害数字）显示的是减伤后的值**（因为它在第 4 步才读）。
⇒ 但**"攻击前预览"是另一条路径**：它在**指向/选中目标**时就要出数字，
   若它读的是第 2 步之后的槽值、或独立复制了 `0x43BC5A` 的返回值，
   就**必然拿到未减伤的值 D** —— 这就是实测"改 `0x24` 取值、预览不动"的原因。

**"预览显示减伤后的伤害"要落地，只有一个方向**：
找到预览读数的**那一个点**，让它读**第 3 步之后**的 `ctx+0x84`（或让预览也过一遍减伤）。
而**不能**在 `0x405EF9` 再想办法 —— 那里已经晚了/早了，与预览时机错开。

## 三、怎么找预览的读点（**方法已修正：不要挂断点**）

### ⛔ 先记一次失败教训（2026-10-14 实机，代价是骚扰了用户）

第一次尝试：在 `0x405E9A`（写槽）与 `0x405EF5`（减伤判定）各挂一个断点，让用户"指向敌人看预览"。

**结果失败**：用户**只点了一下我军 1 号角色**（还没做任何攻击操作）就命中断点、游戏被暂停。
⇒ 这两个点在**选中/预估**阶段就会执行（伤害预估路径也走这条链）
⇒ **"挂断点等预览"这个思路本身是错的**：命中噪音太大，且软件断点会把游戏整个挂起。

**正确方法（用户口径）：只读采样 + 差分配对，不挂断点。**

### 正确的验证做法

1. 先用 `_单位面板.py` 拿到**我方单位身份与坐标**（见第四节），确定"谁打谁"——
   不要再让用户报"我点的是一号角色"。
2. 只读轮询 `ctx+0x84`（物理伤害槽），记录**每次变化**：旧值 → 新值、时间戳、`ctx+0x00/+0x01`。
3. 让用户把鼠标**指向目标看出预览数字**（不必攻击）。
4. 比对：
   - 采样到的槽值变化前后**都不等于**界面预览数字 ⇒ 预览**不读**该槽（另有预估链）；
   - 某次槽值 == 预览数字 ⇒ 预览读的就是该槽，再看它落在减伤前还是减伤后。
5. **差分配对是关键**：伤害槽在动画前写入、HP 在动画后扣减，
   用"槽值差分 ↔ HP 差分"配对才不会错配（`_减伤采样v2.py` 已按此实现，直接复用其配对逻辑）。

### 候选读点

| 候选 | 说明 |
|---|---|
| 读 `ctx+0x84` | 若成立，预览值应能等于某次槽值 |
| 读 `0x43BC5A` 返回值的副本 | 预览路径自己存了一份公式结果 |
| 独立预估缓冲 | 需另找写入点 |

> 附：预览链/攻击链共享的既有定位 —— `0x436511` 服务预览与实际攻击、`0x4AC748` 是临时目标表。

## 五、★ 实机闭环数据（2026-10-14，用户实测 + 只读配对）

**条件**：`0x24` 特效值 = **25**（用户提供）⇒ 减伤系数 = `100−25` = **75%**，
即 `最终伤害 = 减伤前伤害 × 0.75`。**攻击者**：slot4（关羽）。
采集：`_预览实测采样.py` 只读轮询，**槽值差分 == HP 掉血量**配对。

| t(s) | 目标 | 带 `0x24` | 暴击标志 | **槽值 = 实际掉血** | 反推减伤前 |
|---|---|---|---|---|---|
| 279.6 | slot72 (data330) | 是 | **0** | **132** | 176.0 |
| 282.6 | slot84 (data510) | 是 | **0** | **128** | 170.7 |
| 286.0 | slot70 (data490) | 否 | **1** | **249** | 249（无减伤） |
| **289.4** | **slot84 (data510)** | 是 | **0** | **138** | **184.0** |
| 292.4 | slot85 (data396) | 否 | **1** | **336** | 336（无减伤） |

**四条已确认结论**：

1. **伤害槽 `ctx+0x84` 就是唯一真值** —— 5 次配对**全部精确相等**（槽值 == HP 掉血量）。
2. **有 `0x24` 时暴击标志恒为 0** —— 3 次带 `0x24` 全部 `暴击标志=0`，2 次不带 `0x24` 全部 `=1`。
   **实机证实**「攻击防御暴击的人不出暴击」，与静态吻合
   （`0x405EF9` 跳过了 `0x405F17` 的 `mov [eax+0x604],1`）。
3. **减伤系数 0.75 被精确验证** —— 同一目标 slot84 两次 `128` / `138`，
   反推减伤前为 `170.7` / `184.0`（差 ≈13，来自等级或浮动），但**两次乘了同一个 0.75** ⇒ `V=25` 成立。
4. **暴击落差大** —— 不带 `0x24` 的 `249` / `336` 远高于带 `0x24` 的 `128~138`（约 1.9~2.6 倍）。

**尚未取到的**：**"指向敌人时的预览数字"**。
`_候选值实时监视.py` 盯了 150 秒：`ctx+0x84` **只在攻击瞬间**变化（与 `ctx+0x00` 同步），
**前 86 秒"指向"期间无任何候选地址变化** ⇒ 预览数字**不写**
`ctx+0x84` / `ctx+0x254` / `0x497AF8` / `0x4AC748`；
要么落在别处，要么在**更早**（选中攻击菜单）就已算完。

## 七、★★ 预览值实证：181（用户实测，2026-10-14）

**最强的一条实机证据**：指向 `slot84`（**参军1**，data510，坐标 (8,17)，`0x24`=25）时，
界面**预览显示 181**。而同一目标随后被攻击，**实际掉血 138**。

```
反推：138 ÷ (100−25)/100 = 138 ÷ 0.75 = 184.0
预览：181                                  ← 与 184 只差 3（取整/浮动）
```

⇒ **结论（已闭环）**：**预览 = 公式原值（未减伤、未暴击）**；减伤只作用在实战分支。
用户独立表述与此一致：「预览是普通攻击的伤害，但没有计算特效值的减伤」。

**两个"不算"的静态依据**：
- **减伤**只在 `0x405EF9`（实战分支）施加，预览链不经过它；
- **暴击**由 `0x428925` 施加（在 `0x440668` 调用点可见：`call 0x43BC5A` 之后才 `call 0x428925`），
  预览链**不调** `0x428925`。

**顺带定性的 5 个共用公式调用点**（`call 0x43BC5A`，全文件 5 处）：

| 调用点 | 用途 | 判据 |
|---|---|---|
| `0x405E6D` | **实战结算** | 在 `0x405DE1` 主控内，写伤害槽 `ctx+0x84` |
| `0x419AED` | 筛选"可一击击杀" | `cmp eax,[ecx+0x10]`（HP）→ 收集目标 |
| `0x438A2A` | **AI 打分**：伤害占 HP 百分比 | `imul eax,eax,0x64` / `div` HP → `add [ebp-4],eax` |
| `0x438CCA` | **AI 打分**：能否一击击杀 | `cmp [ebp-0xc],HP` → 能杀 +10 分、不能 +3 分 |
| `0x440668` | 含暴击的伤害判定 | 之后 `call 0x428925`（★ 暴击计算真身） |

⚠️ **纠正一次误判**：`0x438A2A`/`0x438CCA` 曾被我当成"预览"，
实为 **AI 选目标打分**（`0x438xxx` 是范围预览/目标准备链，但**它算的是"哪些格可选"，不是那个数字**）。

## 九、预览定位：四轮尝试全部未命中（负面结论同样重要）

用户第二次实测：**指向另一个敌人时预览 = 201**（第一个目标是 181）。

| 轮次 | 方法 | 结果 |
|---|---|---|
| 1 | 搜 181 → 4 个候选改值（`_改值看反应.py`，改 999 各停 9 秒） | **预览无反应**；复核发现那些地址是全 0 区 / GBK 文本 / `03` 数组 |
| 2 | 40 秒差分（取消选择→重新指向） | **0 处新增、0 处消失** |
| 3 | 576KB 全量快照差分（`_全量差异定位.py`） | 只 2 处变化，**事后连续采样确认是每 2 秒自变的计时器** |
| 4 | **指纹法**（`_预览值指纹.py`）：181→11 处、201→9 处，取**交集** | **交集 = 0 处** | （脚本已静置 → `大鲸鱼产生专用\_冻结证据_20261024\暴击通用\_预览值指纹.py`）
| 5 | 搜差值 `201−181=20`（若同一变量被覆写，变化量必为 20） | 81 处命中，噪音过大 |

**由轮次 4 得出的关键判断**：
> **预览值不是"一个会被覆写的变量"** —— 181 与 201 在内存里**没有任何共同位置**。
> 所以它更可能是：① 每次按目标**现算**（存在寄存器/栈上，不落地）；② 以**浮点**形式存储（整数搜索抓不到）；
> ③ 直接写绘制缓冲区（一次性像素/字形，不保留数值）。

**⇒ "找预览值的内存地址"这条路应判定为低效**，应转向**执行级定位**：
在预览路径上取执行级证据（条件断点 / 命中即读栈），或直接改**预览那条调用链**的返回值。

**另一条更省事的路线（用户已提过，备选）**：
不改原预览函数，而是**自建预览修正**——在显示前对预览值做一次 `×(100−V)/100`。
前提同样是先找到"显示前那个值"，所以仍绕不开上面这一步。

## 十、已明确的两条静态事实（可直接用于改造）
