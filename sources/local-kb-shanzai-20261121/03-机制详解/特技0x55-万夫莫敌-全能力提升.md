# 特技 0x55 万夫莫敌 / 0x71 戮力同心 —— 全能力按周围敌人数提升

## 结论速览

- **语义**：`全能力 = 基础值 × (1 + (X+1) × N / 100)`。`X` = 自身**九宫格内敌方阵营组**单位数，`N` = 特技特效值（byte1）。
- **实现链（全部为静态现读，非推断）**：
  `0x43C4C0(能力索引)` 算单项能力 → `0x4C0300(unit, 值, 索引)` 能力结算 →
  **`0x4C0385 call 0x4363B0`（万夫莫敌）** → 回到 `0x43C51C` → 上限截断 `0x270F = 9999`。
- **`0x4363B0` 是唯一实现**：`N = 0x43C3DE()`（桩：个人 `0x55` / 装备 `0x71` 双渠道）；`0x406710(unit)` 判阵营组；
  取**互补** side（我方组→`5`、其余→`4`）；`X = 0x41BC4A(unit, side)`；`pct = (X+1) × N`；`值 += 值 × pct / 100`（`0x425AD9`）。
- **与 `0x47 一骑当千` 串联**：同一结算函数内，先 `0x4C037B call 0x478EAB`（一骑当千），
  再把其返回值喂给 `0x4C0385 call 0x4363B0`（万夫莫敌）——**两者不是互斥，是逐段链式修正**。
- **`0x4363B0` 的直接调用点只有 1 个：`0x4C0385`**（`call 0x4363B0`，位于 `.api` 节 `0x4C0300` 内）。
- **现场**（PID 25480，读档 `No.001`，`4018=1`）：`slot0` 有 `0x71 特效值 2`、敌方 `slot85/95/112` 各有 `0x71 特效值 1`
  ⇒ **该特技正在生效**；`slot2 (13,20)` 九宫格内 7 个敌方 ⇒ 若该单位也有此特技，`X=7`、`(1+7)×N/100`。

## 已确认事实

### 1. 能力结算函数 `0x4C0300`（八段链，`ret 0`）

```asm
0x4C0300  55 8B EC                 push ebp / mov ebp,esp
0x4C0303  51                       push ecx                 ; [ebp-4]
0x4C0304  50                       push eax                 ; [ebp-8] = 入口 eax（基础值）
0x4C0305  E8 D2 77 FB FF           call 0x477ADC            ; 取当前单位编号（al=0xFF ⇒ 无单位）
0x4C030A  3C FF / 75 07            cmp al,0xFF / jne 0x4C0315
0x4C030E  8B 45 F8 ...             mov eax,[ebp-8] / 原样返回
0x4C0315  89 4D FC                 mov [ebp-4],ecx          ; ★ 单位指针（入口 ecx）
0x4C0360  FF 75 08                 push [ebp+8]             ; 能力索引
0x4C0363  FF 75 F8                 push [ebp-8]             ; 基础值
0x4C0366  FF 75 FC                 push [ebp-4]             ; 单位
0x4C0369  E8 C2 80 F6 FF           call 0x428430            ; ① 修正段（0x428430 = jmp 0x432700）
0x4C036E  89 45 F8                 mov [ebp-8],eax
0x4C0371  8B 45 F8 / 8B 4D FC      mov eax,[ebp-8] / mov ecx,[ebp-4]
0x4C0377  FF 75 FC                 push [ebp-4]
0x4C037A  50                       push eax
0x4C037B  E8 2B 8B FB FF           call 0x478EAB            ; ② ★ 0x47 一骑当千
0x4C0380  8B 4D FC                 mov ecx,[ebp-4]          ; ★ 桩要求 ecx=单位
0x4C0383  51 / 50                  push ecx / push eax
0x4C0385  E8 26 60 F7 FF           call 0x4363B0            ; ③ ★★ 0x55 万夫莫敌 / 0x71 戮力同心
0x4C038A  FF 75 08 / 50            push [ebp+8] / push eax
0x4C038E  8B 4D FC                 mov ecx,[ebp-4]
0x4C0391  E8 0C FD F5 FF           call 0x4200A2            ; ④ 末段修正（内含 0x425AD9 百分比）
0x4C0396  89 45 F8                 mov [ebp-8],eax
0x4C0399..0x4C03F6  90 …         NOP 填充（94 字节，历史补丁留下的洞）
0x4C03F7  8B 45 F8 / 8B E5 / 5D / C2 00 00   mov eax,[ebp-8] / ret 0
```

- **调用约定**：`ecx` = 单位指针，`eax` = 基础值，`[ebp+8]` = 能力索引；返回值在 `eax`。
- ⚠ `[ebp+8]` **只传给** ①`0x428430` 与 ④`0x4200A2`；②③两个特技段不区分索引 ⇒ **对每一项能力都生效 = 「全能力」**。

### 2. 万夫莫敌 handler `0x4363B0`（`ret 8`）

```asm
0x4363B0  55 8B EC                 push ebp / mov ebp,esp
0x4363B3  E8 26 60 00 00           call 0x43C3DE            ; eax = N（特效值；0 = 无此特技）
0x4363B8  85 C0 / 74 2C            test eax,eax / je 0x4363E8
0x4363BC  50                       push eax                 ; ★ 同时充当局部：[ebp-4] = N
0x4363BD  8B 4D 0C                 mov ecx,[ebp+0xC]        ; 单位
0x4363C0  E8 4B 03 FD FF           call 0x406710            ; 阵营组：1 = 我方组，其余 0/2
0x4363C5  3C 01 / 75 04            cmp al,1 / jne 0x4363CD
0x4363C9  6A 05                    push 5                   ; 我方组 ⇒ 数【敌方组】
0x4363CB  EB 02 / 6A 04            jmp / push 4             ; 否则 ⇒ 数【我方组】
0x4363CF  8B 4D 0C                 mov ecx,[ebp+0xC]
0x4363D2  E8 73 58 FE FF           call 0x41BC4A            ; eax = X（九宫格人数）
0x4363D7  40                       inc eax                  ; ★ X+1
0x4363D8  0F AF 45 FC              imul eax,[ebp-4]         ; × N
0x4363DC  FF 75 08 / 50            push [ebp+8] / push eax
0x4363E0  E8 F4 F6 FE FF           call 0x425AD9            ; 值 × pct / 100
0x4363E5  01 45 08                 add [ebp+8],eax          ; ★ 值 += 增量
0x4363E8  8B 45 08                 mov eax,[ebp+8]
0x4363EB  8B E5 / 5D / C2 08 00   mov esp,ebp / pop ebp / ret 8
```

**公式推导（逐条对应）**：

| 汇编 | 含义 |
|---|---|
| `call 0x43C3DE` | `N` = 特效值；`N=0` ⇒ 直接返回原值 |
| `0x406710` + `cmp al,1` | 我方组 ⇒ `side=5`（敌方组）；否则 `side=4`（我方组） |
| `call 0x41BC4A` | `X` = 九宫格（`X-1..X+1 × Y-1..Y+1`，含中心格）内该阵营组人数 |
| `inc eax / imul [ebp-4]` | `pct = (X + 1) × N` |
| `call 0x425AD9` | `增量 = 值 × pct / 100`（`0x425AD9` = `a*b/100` 无符号除） |
| `add [ebp+8],eax` | `值 += 增量` |

⇒ **最终值 = 基础值 × (1 + (X+1)·N / 100)**，与用户口径「全能力提升 [1+X]×N」一致。

### 3. 特效值来源 `0x43C3DE`（双渠道桩）

```asm
0x43C3DE  55 8B EC
0x43C3E1  6A 00 6A 01              push 0 / push 1
0x43C3E5  6A 71                    push 0x71        ; 装备/另一渠道
0x43C3E7  6A 55                    push 0x55        ; 个人/主渠道
0x43C3E9  E8 A1 8D FE FF           call 0x42518F    ; 包装判定 → 返回 eax（特效值）
0x43C3EE  5D C3                    pop ebp / ret
```

- `0x42518F` = 包装：`0x40B922`（内部 `0x40B913()==3`）为真 ⇒ `call 0x4101D9`，否则 `call 0x41301E`。
- `0x4101D9` 尾 `jmp 0x4D4120`（`.text3`）→ 内部再 `call 0x41301E`，为 0 时继续走 `0x4D4500`（DLL 侧扩展查询）。
  ⇒ **特效值查询最终落到扩展 DLL（`[0x4F0004]` 的 person_effect 表）**，EXE 只做分派。
- `ecx` 在桩内**未设置** ⇒ 调用方必须保证 `ecx = 单位指针`（`0x4C0380` 正是 `mov ecx,[ebp-4]`，对齐）。

### 4. 阵营组判定 `0x406710`

```asm
0x406710  55 8B EC
0x406713  0F B6 41 05              movzx eax, byte [ecx+5]      ; 单位阵营
0x406717  3C 03 / 75 0A            cmp al,3 / jne
0x40671B  80 3D 54 5F 50 00 00     cmp byte [0x505F54],0        ; 特殊开关
0x406722  74 01 / 40               je / inc eax                 ; 阵营 3 且开关开 ⇒ 按 4 查表
0x406725  8A 80 2D 67 40 00        mov al,[eax+0x40672D]        ; ★ 8 字节映射表
```

- 映射表现读（`0x40672D`）：`01 01 00 00 02 01 01`。
  ⇒ 阵营 `0/1 → 1`（我方组）、`2/3 → 0`（敌方组）、`4 → 2`、`5/6 → 1`。
- 桩里只看 `==1`：`1` ⇒ 数敌方组；`0/2` ⇒ 数我方组。

### 5. 周围人数 `0x41BC4A`

详见 `03-机制详解\周边人数-九宫格与阵营组.md`：九宫格含中心格；`side 4 = 阵营<2`、`side 5 = 阵营 2/3`。
⇒ 万夫莫敌的 `X` **不会把自己算进去**（自己是哪一组，数的就是另一组）。

### 6. 上限与调用位置

- `0x43C4C0(索引)` → `0x43C51C call 0x4C0300` → **`0x43C521 cmp eax,0x270F; jb; mov eax,0x270F`** ⇒ 能力上限 **9999**。
- `0x43C4C0` 的入参是能力索引：基础值取 `word [unit + 0x11 + 索引*2]`，成长/加成取 `byte [unit + 0x21 + 索引]`。

**要改这条特技的三条路线（按风险从低到高）**：

| 路线 | 做法 | 风险 | 备注 |
|---|---|---|---|
| ① 改数值 | 写 person_effect 槽的 `byte1`（特效值 N） | **零代码**，最低 | 只影响该单位；退出游戏即恢复（内存写） |
| ② 改公式常数 | 把 `0x4363D7 40`（`inc eax`）改成立即数运算，或改 `0x4363D8` 的 `imul` | 只改立即数/单指令 | `inc eax` 1 字节，改成 `nop` ⇒ 变 `X×N`（去掉 +1） |
| ③ 加条件/换算法 | 在 `0x4363B3`（整条 `call 0x43C3DE`，5B 天然对齐）挂 5 字节 hook | 中；动控制流 | **`0x4363B0` 前 5 字节会吃掉 `call` 首 2 字节**（历史 A1 补丁就栽在这），要用 `0x4363B3` |

## 风险与边界

- **⚠ 与 A1 补丁（中毒物理易伤 20）同址**：A1 把 `0x4363B0` 当「伤害修正」挂点，但本函数**只被能力结算 `0x4C0300` 调用**，
  `[ebp+8]` 是**能力值**不是伤害 ⇒ **A1 的前提存疑**（A1 目前登记为「未写入」，尚未造成影响）。落地前必须与 A1 设计核对。
- `0x4363B0` 的 `push eax`（`0x4363BC`）既是传参又是局部（`[ebp-4]=N`）；`call 0x43C3DE` 会临时把返回地址写在 `[ebp-4]`，
  但 `0x4363D8` 读之前已被 `push eax` 覆盖 ⇒ **不是「靠残留数据撞对」**（纠正台账已同口径）。
- `X` 用静态坐标；`0x41BC4A` 对「非玩家可控 + `[0x4B3D18]!=0`」会改用动态坐标 ⇒ 位移动画中的瞬时值可能不同。
- 九宫格**含中心格**：若自己属敌方组（如敌方单位），数我方组时不含自己；反之亦然 ⇒ `(X+1)` 的 `+1` 是常数项，不是「算自己」。
- 上限 9999 在 `0x43C4C0` 里截断，**不在** `0x4363B0` 内 ⇒ 若绕过 `0x43C4C0` 直接调用，需要自己截断。
- **扫描教训**：跨节 `call` 的 `rel32` 必须在 **VA 空间**算（`目标VA = 源VA + 5 + rel32`）；
  按文件偏移相加会漏掉 `.api → .code` 的调用（本次就漏了 `0x4C0385`）。

## ⚠ 更正（2026-10-18 15:5x，用户指正）：`0x71` 不是「万夫莫敌的装备渠道」

- 本页初版把 `0x43C3DE` 里的 `push 0x71` 读成「装备渠道 = 戮力同心」，并写成同一效果 —— **错**。
- **已确认（兵种特技 0x71 = 戮力同心，独立实现）**：
  - 桩 **`0x405954`**：`push 0 / push 0 / push 0x58 / push 0x71 / call 0x4101D9`（个人 0x71 + 装备号 0x58）。
  - **2 项函数指针表 `0x415E2B`**：项0 = `0x405942`（`0x3B 同仇敌忾` 桩）、项1 = `0x405954`（`0x71` 桩）。
  - 分派点 **`0x438F28`**：`call dword [eax*4 + 0x415E2B]` → `test al,al` → 与 `[ecx+0x23]` 比次数 → 写 `[0x4B2C28]`。
  - 收集函数 **`0x438EBD`**（← 由 `0x4223CB` 在 `0x4223A9` 的 0..2 循环里调用）：
    逐单位判 `0x418C90==2`、非攻击者、`0x42E2B7` 通过、`0x426B33==0`、桩返回非 0 且次数比较通过、
    再用 **`0x4091F4(候选单位, 0x50, 2)`** 算候选单位的攻击范围，覆盖攻击者才把候选 slot 追加进 `0x500EA5`。
- **行为（用户口径，代码对得上）**：**敌方回合、敌军攻击友方单位时，若该敌军处于本单位的攻击范围，则本单位攻击该敌军**（协力反击）。

