## 结论速览

1. **当前 `0x24` 的行为（原始态）**：`0x405EF9` 段把伤害槽**整个清零** ⇒
   **目标带 `0x24`（且特效值 ≠ 0）时，对该目标的物理伤害 = 0（完全免伤）**。
   "按特效值百分比减伤"是 **v7 补丁**带来的，**当前不在样本里**。
2. **唯一的例外**：**攻击者**带 `0x70`（暴击增幅，特效值 ≠ 0）时，
   复合谓词 `0x42AA2A` **恒返回 0** ⇒ **跳过清零 ⇒ 满伤**。
   ⇒ 即"`0x70` 与 `0x24` 互斥"，这是**确定的分支，不是概率**。
3. **判定谓词 = `0x42AA2A`**（不是取值器！）：
   `call 0x422E56`（查**攻击者** `0x70`）→ 非 0 则 `xor eax,eax`；
   否则 `call 0x405DCF`（查**目标** `0x24`）。两个子调用都是
   **`push 1 / push 1 / push <装备槽> / push <特技号>` → `call 0x4101D9`**。
4. **本次独立复核**：`0x4101D9` 的签名由普罗源码给出（见第四节），
   据此把两个子调用读成"个人特效号 = `0x24` / `0x70`，需效果值 ≠ 0"
   —— 与库内既有结论**一致**（`防御暴击0x24-实机证据链.md:462-464`）。
5. **★ 本次最有价值的新结论**：**v7 的"预览同步"是假同步**。
   v7 把减伤写在 `0x405EF9`（**实战链**），而预览根本不走那条链 ⇒ 预览数值**必然不变**。
   `call 0x43F1E8` = **0 处**、预览函数不调用 `0x43F1E8~0x43F2FF`（0 处）⇒
   库内"预览与实战共用特技修正链"的说法**必须降级**。
6. **要改预览只有一个地方**：`0x44049E` 面板层（`0x44066D mov [ebp-0x18],eax` 之后）。

**⇒ 行为表**：

| 攻击者有 `0x70` | 目标有 `0x24` | 谓词 | 结果 |
|---|---|---|---|
| 否 | 否 | 0 | 正常伤害（走暴击加成） |
| 否 | **是** | ≠0 | **伤害清零（完全免伤）** |
| **是** | 是/否 | **0** | **满伤**（`0x24` 被无视） |

## 三、★ v7「预览同步」为什么是假同步（本次核心发现）

| 检验 | 结果 |
|---|---|
| `call 0x43F1E8`（特技修正链入口）的调用点 | **0 处** |
| 预览函数 `0x44049E` 内调用 `0x43F1E8~0x43F2FF` | **0 处** |
| `call 0x452E69`（v6/v7 的减伤/取 V 代码体） | **0 处**（它不是被 `call` 进入的） |
| v7 的减伤写在哪 | `0x405EF9`（**`0x405DE1` 实战主控内**） |

⇒ **v7 只能改实战，改不到预览**。库内此前记的
"预览与实战**共用** `0x43F1E8~0x43F27F` 特技修正链（断点命中 2 次）"
**不能作为"改该链即可同步预览"的依据** —— 那 2 次命中很可能来自实战侧调用。

**⇒ 要让预览显示减伤后的数值，只有一条路：改 `0x44049E` 面板层**
（`0x44066D mov [ebp-0x18],eax` = 预览伤害；见
`03-机制详解/伤害预览数值来源-预览函数0x44049E.md`）。

## 四、`0x4101D9` 的准确签名（普罗源码给出，不是猜）

`_外部源码\普罗\ccz-LuaSkill\…\lua_api.cpp:1838-1864`：

```c
// engine.check_skill(战场编号, 个人特技号, 装备特技号 [, 叠加标志, 效果值标志])
// 返回: 效果值 (0=无该特技, >0=有且效果值为该数值)
// 叠加标志默认1(不叠加), 效果值标志默认0(需要效果值)
__asm {
    push p_effect        // 参5
    push p_stack         // 参4
    push p_equip         // 参3 = 装备特技号
    push p_personal      // 参2 = 个人特技号
    mov  ecx, uptr       // 单位指针
    call fn              // call 0x4101D9, ret 0x10 自清理栈
}
```

- 与库内 `0x41301E` 段的 `and dword [ebp+8],0xFF` 硬证据一致（`[ebp+8]` = 特技号）。
- 失败返回 **`0xFF`**（`cmp al,0xFF / je`）—— 写调用方必须处理这个魔数。
- ⇒ 谓词 A/B 的 `push 1 / push 1 / <装备> / <个人>` 读作
  **叠加标志 = 1、需效果值 = 1**，即"有该特技**且**特效值 ≠ 0"。

## 风险与边界

- **`0x42AA2A` 是判定，不是取值器** —— v5 曾把它当取值器 ⇒ 带 `0x70` 时 V 恒 0 ⇒ 零减伤。
  再写补丁时**必须自己遍历特效表取 `0x24` 的真值**（v6-fix 的做法）。
- 改 `0x42AA38` / `0x42AA44` 会同时影响所有走 `0x405DE1` 的物理攻击（主动/连击/反击），
  属**引擎级改动**，须先按 `01-核心引擎/地址语义与Hook契约.md` 做契约登记。
- 本页为**静态复读**；`0x24` 的实机观感（伤害 0 是否显示为 0、动画表现）未复测。

## 2026-10-25 当前样本静态复读：0x42AA2A 当前调用者与返回契约

当前 Ekd5.exe SHA256=2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A。文件字节复读确认：

- 0x42AA2A 仍为 19 字节复合判定函数：ECX 先取 ctx+0x0C，call 0x422E56；返回非零时在 0x42AA44 强制 xor eax,eax；否则恢复原始对象调用 0x405DCF，并把其返回值原样带回。
- 0x422E56 当前仍压入 push 1、push 1、push 0x68、push 0x70 后调用 0x4101D9，含义是攻击者个人特效号 0x70、装备槽哨兵 0x68、需要效果值且不叠加。
- 0x405DCF 当前仍压入 push 1、push 1、push 0、push 0x24 后调用 0x4101D9，含义是目标个人特效号 0x24、装备槽 0、需要效果值且不叠加。
- 全映像 rel32 扫描确认 0x42AA2A 只有一个直接调用点：0x405EF0。调用后 test eax；eax=0 跳过清零并进入 0x42E4FD，eax 非零则在 0x405EFC 将目标伤害槽写为 0。
- 这次复读只确认当前静态字节、调用者数量和压栈契约；没有把效果值读回、战斗命中或 4018=1 动态验证混入本结论，也没有操控游戏/X32DBG。
