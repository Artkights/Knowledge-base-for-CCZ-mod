# 策略目标判定 与 AI 方针（6.6 山贼版逆向）

## 结论速览

- 战术单位取址 `0x4A7B20 + 战场编号 × 0x30`（函数 `0x4061F9`）；**AI 方针在 `+0x0E`**：`0`=攻击武将/到点、`1`=主动出击、`2`=坚守原地、`3`=被动出击、`4`=跟随/逃跑、`7`=友军可控；单位编号有效范围 `< 0xFA`（`0xFA`~`0xFE` 无效、`0xFF`=空）。
- ★「策略能否对该目标使用」的真正判定器 = `0x43623B`（AL = 某标志(0xFF 特殊)、DL = 策略号、`[ebp+8]` = 单元格索引；返回 AL：`2`=允许使用 / `1`=禁止并显示提示 / `0`=跳过），全文件唯一调用者 `0x45554F`（正是玩家选目标处）；提示串 `0x48B85C` = 「不能在这里使用。」。页内两处口径不同：二·补称它是"正式补丁的落点"，而六·成功案例的最终挂钩点是 `0x417B77`，且 `0x43623B` 又出现在"失败过的 10 个位置"清单里 —— 动手前按 `0x417B77` 那条已验证链走。
- 可复用的限制模式（以后给任何策略加使用条件都照这个来）：在 `0x43623B` 入口挂钩 → `lea eax,[ebp+8] / push eax / call 0x435884 / add esp,4` 取该格单位ID（**cdecl，调用方必须 `add esp,4`**，`AL=0xFF` = 空格）→ `0x4061F9` 转单位指针 → 判 `[单位+0x0E]`；命中则恢复 AL/DL → `mov al,1` → `jmp 0x4362AC`（禁止 + 显示提示），否则逐条复刻原逻辑（`cmp al,0xFF` / `cmp dl,0x24` 两条分支）。
- 最终生效的落点与补丁：挂钩 `0x417B77`（入口 7 字节 `55 8B EC 51 8A 45 10`，全文件唯一调用者 `0x42341A`），命中显示「本策略无法对坚守ai的敌军使用」，提示函数 `0x42A423`（stdcall，`ret 4`）；**判定前必须 `cmp al,0xFA / jae orig`，否则越界闪退**。第一版落点改 `0x43915D`（原 5 字节 `33 C0 40 EB 02` → `E9 9E 96 FF FF`，跳代码洞 `0x432800`），可调参数只有 `cmp ecx,0x22`（策略号 34）与 `cmp eax,2`（AI 值）；补丁文件 `【6.6山贼】无情铁手-对坚守敌人不可用.txt`、备份 `Ekd5.exe.bak_before_ironhand_20261013_001426`。"失败过的 10 个位置"（勿重踩）：`0x4390EF` `0x437BCE` `0x43623B` `0x437AFF` `0x4179B4` `0x417AF6` `0x41C0E8` `0x426551`（实测调用次数=0，根本不是拉人）`0x423230`（入口时 `[ctx+0x0D]`=0xFF）`0x42325B`（循环内部，寄存器敏感，闪退两次）。
- 四个"编号"不可混用（本项目最大的坑）：策略列表位置 `0x34`(52)（上下文 `[0x497AF8+0]` 用它）、策略类型 `0x24`(36)、**★策略索引 `0x20`(32)**（效果跳板表 `0x4259C3[索引]` 的真正索引，`[0x20]=0x4256D0`）、策略执行ID `0x42`(66)（`0x425627` 执行器的 `[ebp+8]`，另一条链路）。另外「诱敌深入」在引擎里不是"策略"，而是"让敌方单位移动到我军施法者旁边"的效果（跳板只 `mov [edx],0x43`），最终都汇入万能效果处理器 `0x423230`。
- 已推翻/修正与待验证：策略表源数据 `Data.e5` 起始 = `0xB204`（步长 `0x61`、共 144 条），**原记 `0xB8D6` 是错的**（那是 id `0x12`「小石头」，id `0x00` 是「小火」），`0x42B171` 注册循环的 68(0x44) 只是它的 count；且 `Data.e5` 布局 ≠ 运行时 `StrategyRecord`（6 字段换位：运行时 `+0x0B` 施法对象 getter `0x425AC7`、`+0x0C` 施法范围、`+0x0D` 效果范围、`+0x0E` 消耗MP、`+0x0F` 策略类型 getter `0x44270C`、`+0x10` 图标），字段不可直接照搬。未闭环：第二层钩子（`0x437BCE` → `0x432830`，三重条件 `[0x497AF8+00]==34`、`[0x497AF8+01]==施法者`、`[单位+0x0E]==2`）有"陈旧上下文"误伤风险（同一单位先打策略、再物理攻击 AI=2 的敌人可能被误挡），静态搜索确认**没有任何指令直接写 `0x497AF8`**（4 种绝对寻址形式全试过）⇒ 结算后是否清空 `+00` 只能靠实机验证；`0x440F1C skill_target` 尚未定位到真实函数入口（旧记录可能是错的）。

## 二·补、★★ 策略可用性判定函数 0x43623B（2026-10-13 突破，正式补丁的落点）

> **这是"策略能否对该目标使用"的真正判定器**，也是纵火补丁同一族的函数。
> 前两版补丁（0x4390EF 只作用 AI 评分路径、0x437BCE 拦目标数组但范围图已先写）
> 都因此失败；本函数才是玩家选目标时的必经之处。

### 函数签名（寄存器传参）

```
0x43623B(AL = 某标志(0xFF 特殊), DL = 策略号, [ebp+8] = 单元格索引)
返回 AL:  2 = 允许使用    1 = 禁止使用(并显示提示)    0 = 跳过
```

### ★ 参数含义的验证链（2026-10-13，怎么确认 DL 就是策略号）

```
① 调用者 0x45553D: mov edx,[ebp-0x20]
   → DL 来自调用者函数的局部 [ebp-0x20]

② 该函数入口 0x45533D:
   0x45533D: push ebp / mov ebp,esp
   0x45534D: mov [ebp-0x18], ecx
   0x455350: mov [ebp-0x20], eax     ← ★ [ebp-0x20] 存的是寄存器参数 EAX
   → 所以 DL = 调用方传入的 EAX

③ 阈值分派 0x455540: cmp dl,0x4A / jb 0x45554E
   · 策略表共 68 条（编号 0~0x43）→ "< 0x4A" 恰好覆盖全部策略 ✓
   · ≥0x4A 走另一族 0x40E975（其中 0x40E9C4 正是纵火补丁改的地形判定）
   → 两族都是"目标合法性检查"，DL = 技能/策略编号 ✓

④ 同函数内 0x455372: call 0x425AD0
   0x425AD0 = movzx eax,byte [ecx+0x0E]
   → 游戏自己就是用 "[单位+0x0E]" 读 AI 方针的（这里判 7=友军可控）
   → 本补丁判 2=坚守，用的是同一个套路 ✓
```

**单元格参数**：`0x43623B` 的 `[ebp+8]` 来自调用者的 `ecx = [ebp-0xC]`
（调用者先 `0x455515: lea edx,[ebp-0xC] ... call 0x4174FF` 填好），
再 `0x45554E: push ecx` 传入 → 所以 `[ebp+8]` 是**单元格描述值**。
要取该格单位：`lea eax,[ebp+8] / push eax / call 0x435884`（与调用者 `0x455529` 写法一致）。

|---|---|---|

→ `0x45533D` 是**全局共享的"某单位能否对某格执行某动作"检查器**，
  内含范围图检查（`0x4554F3` 读 `+0x12C0`）与策略号分派，玩家与 AI 都要过这一关。

### 可复用的限制模式（★ 以后给任何策略加使用条件都照这个来）

```
在 0x43623B 入口挂钩：
  if (DL == 目标策略号) {
      取得该格单位：lea eax,[ebp+8] / push eax / call 0x435884 / add esp,4
      if (单位[+0x0E] == 目标AI值) {
          恢复 AL/DL → mov al,1 → jmp 0x4362AC   ; 禁止 + 显示提示
      }
  }
  → 否则逐条复刻原逻辑（cmp al,0xFF / cmp dl,0x24 两条分支）
```

- `0x435884(&单元格索引)` → AL = 该格单位ID（`FF` = 空格），**cdecl，调用方要 `add esp,4`**
- `0x4061F9(单位ID)` → 战场单位指针
- 单位 `+0x0E` = AI方针（`2` = 坚守原地）

## 三、本补丁（无情铁手限制）

**需求**：策略编号 34「无情铁手」对 AI方针=2（坚守原地）的敌人不可用。

## 五、逆向小抄（本次用到的手法）

- **找函数入口**：从目标地址往前扫 `55 8B EC`，并要求前一个字节是 `C3/CC/90/C2`（函数尾部或对齐）。
- **找调用者**：全文件扫 `E8` 并按 `rel32` 反算目标地址。
- **找引用**：把目标 VA 按小端 4 字节搜索（如 `F8 7A 49 00` 找 `0x497AF8`）。
- **交叉比对**：两个函数的调用点若密集落在同一地址区间，那里通常就是相关业务模块。

## 6.7 关键结论

- **「诱敌深入」在引擎里不是"策略"，而是"让敌方单位移动到我军施法者旁边"的效果**。
  效果分派表按【策略索引】索引，每项跳板只是设置一个效果ID（`mov [edx],0x43`），
  最终都汇入 `0x423230` 万能效果处理器。
- AI方针字段 `+0x0E`：`2`=坚守（本项目要拦的值）、`7`=友军可控。
- 单位编号有效范围 `< 0xFA`（`0xFA`~`0xFE` 无效，`0xFF`=空）。
