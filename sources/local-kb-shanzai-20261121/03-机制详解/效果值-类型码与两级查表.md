# 效果值：类型码变换与两级查表（`0x4200F5`）

> 适用样本：`Ekd5.exe` **SHA256 `2AC91CB8…E3A7D45`**｜归并自 `可搬回清单-初版对照.md` **§128–§132**

## 1. 结论速览

1. **低段那些"看起来随机的小数值"不是效果值本身，而是"变换类型码"** —— 由 `0x4200F5` 解释成对该数值的换算 ✓
2. **取值位置**：**数值 byte 在 `[eax]`、类型码 byte 在 `[eax-2]`**（同一结构内相邻）✓
3. **签名（实测）**：`ecx` = 结构指针、**`dl` = 档位参数**（两处调用点分别传 `[ebp+0xC]` / `[ebp+0x10]`）✓
4. **两张 7 项小表**：**表A `0x4CB6BA` = `04 05 04 04 01 04 02`**（类别/档位，判定 `<7`）｜**表B `0x4CB5CA`**（较长字节值表，含 `FE` 疑"无值"）✓
5. **索引 = 类型码 − `0x1A`**（至少 `0x420145` 链如此），且**索引须 < 7** ⇒ 该分支的类型码落在 `[0x1A, 0x21)` ✓

## 2. 已确认事实：`0x4200F5` 的分支表（现读）

| 类型码 | 对该值的换算 |
|---|---|
| `0x00` | `ecx ×= (dl + 1)` |
| `0x32` | `ecx ×= 2`（`shl ecx,1`）|
| `0x33` | `cl == 4 ? cl += 3 : 不变` |
| `0x36` / `0x42` / `0x46` | `ecx += 1`（三值同支）|
| `0x72` | `ecx ×= 3/4`（`imul ecx,3 / shr ecx,2`）|
| **其它**（索引 = 类型码 − `0x1A`，须 `< 7`）| **表A[索引] < 7 ⇒ `ecx ×= 1.5`**；若 `dl ≥ 0x12` ⇒ `al = 表B[索引]` ⇒ 与 **`0xFE`** 比较 |

- 另有 `cmp dl, 0x10`（`0x42010D`）与 `cmp dl, 0x12`（`0x420155`）两处档位判定 ✓

**表B 前 48 字节（现读）**：
`32 14 23 16 06 1E 28 28 24 1C 1C 28 3C 05 02 01 04 41 73 37 03 16 01 03 0D 01 05 2D FE 32 28 0F 14 FE 1C 1C 32 23 FE FE 10 37 10 5A AB 01 03 03`

## 3. 实现·使用方法

- **改效果值**：先确认"你要改的是数值（`[eax]`）还是类型码（`[eax-2]`）" —— 改错位置会得到完全不同的换算 ✓
- **看某效果的最终值**：把类型码代入上表算一遍即可（不需要跑游戏）✓
- **速查表（含两张表字节）**：见 `【6.6山贼】静态结论汇总-2026-10-17.xlsx` 的「效果值类型码速查」✓

## 4. 风险与边界

- 类型码集合**未穷举**（现读见 `0x00/0x32/0x33/0x36/0x42/0x46/0x72` 与"其它"分支）⇒ 见到未列出的值时按"其它"分支算 ✓
- **表B 的长度未确定**（至少 48 字节有值），且 `0xFE` 的确切含义（疑"无值/无效"）未定 ✓
- `0x4200F5` 是**被多路调用**的公共换算函数（5 处：`0x407B46`/`0x407CAD`/`0x461EAF`/`0x46218A`/`0x465EBC`）⇒ 不要假定它只服务某一类数据 ✓

## 5. 证据来源

- 静态复读：`0x4200F5`–`0x420160` 全段（§130）；调用点字节解码 `0x461E9F`/`0x46217A`（§132）；`0x4CB6BA`/`0x4CB5CA` 内容（§128/§129）；`exe_bytes`

## 6.5 破甲攻击（0x1F）每级 +20（上传样本 SHA 496D00C7…）

- `0x420131` `02 CA EB 36` → `42 EB A8 90`：先 `inc edx`，再跳 `0x4200DC`（0x55 分支 `base×(dl+1)`）。
- `0x462374` `21` → `FE`：`0x46236F` 表第 5 项（对应特效号 0x1F）改成“用计算结果”，避免 dl>=0x0A 回固定值 0x21。
- 物品行 `+0x16`（装备特效值）设为 20（0x14）时：1 级（等级字节 0）= 20×(0+2) = 40，每升 1 级 +20。

## 2026-10-26 纠正：6.5 破甲攻击（0x1F）等级换算基准 = dl（1 级对应 dl=1）

- 样本：上传 6.5 `Ekd5.exe` SHA256 496D00C7…（1135616 B）。
- **实机事实（用户 2026-10-26 实测）**：物品行 `+0x16 = 0x14`(20) 时，**1 级显示 60** ⇒ **等级 1 对应 `dl = 1`**，不是 0。
- 因此 `base×(dl+2)`（预增写法 `42 EB A8 90`）会多算一级（1 级 60、2 级 80…）；**已改为不预增**：
  - `0x420131` `02 CA EB 36` → **`90 EB A8 90`**（nop / `jmp 0x4200DC` / nop）

  - `+0x16 = 20` 时实测目标序列：1 级 40 / 2 级 60 / 3 级 80 … ✓
- `0x462374`（表 `0x46236F` 第 5 项，对应特效号 `0x1F`）仍必须为 `FE`，否则 `dl<7` 或 `dl>=0x0A` 会回固定值 `0x21`(33)。

### 纠正（2026-10-26 19:40）：上一条「`0x41C50C` 按特效码分派」的判断**有误**

- `0x43AD20` 实际是 `movzx eax, byte [ecx+0x11]`（**道具类型**，武器/防具段）；真正的特效号取值函数是紧邻的 `0x43AD29` = `movzx eax, byte [ecx+0x14]`。

- 全映像搜 `call 0x43AD29` = **0 处**（`call 0x43AD20` 同为 0）⇒ 取特效号的函数经间接/内联方式使用，「使用道具 → 加属性」的真实入口**尚未定位**（前一条的"无实现"结论作废）。
- 已确认可用的部分不变：人物 DATA 记录 `+0x11..+0x19` = 派生五维（攻击力/防御力/精神力/爆发力/士气，word），写入器 `0x406ECA` 索引 `0..4` 可加值并封顶 9999；`0x4620D9` 处"五维 +1 时 `inc word [记录+0x11]`"证明该字段就是攻击力。
- **待办**：继续定位消耗品使用入口（读 `+0x14` 特效号的那条链），再决定新效果码的挂点。

  `0x2C` 原本属 handler 7（`0x4224D4`，语义 =「获得道具（特效值当道具号）」）。
- **修法**：`0x44F37A: 90 → 03`，把 0x2C 改道到 handler 3 = `0x41D14A`（五维道具处理函数）。
- **洞代码另一处错**：v3 的 `mov ecx,[ctx]` 把 ctx+0 的 4 字节整读成道具ID（应只取 1 字节），
  会算出越界物品记录地址；改为 `movzx ecx, byte [edx]`，与 `0x42252B`（handler 7 同类写法）一致。
- **「第二道门」不存在（纠正）**：`0x41C52A cmp al,0xD / ja` 跳 `0x41C567` → `jmp 0x41C5BE`
  → 返回 `[ebp-8]`，与 0x21..0x25 五维道具走的 `0x41C579 jbe 0x41C5BE` **同一返回点**；
  拒绝分支是 `0x41C5A6 add esp,8; dec byte [ebp-8]`，0x2C 不进那里 ⇒ 无需放宽类型范围。
- **`0x47FA89` = min(旧值+加值, 上限)**（`push 上限 / push 加值 / push 旧值`），只改 `ECX`/`EAX`，
  `EDX` 不破坏 ⇒ 洞内可用 EDX 跨调用保存人物记录指针。

## 2026-10-26 v5：0x2C 改「借武力全流程」方案（v4 新分支写法已废弃）

- **v4 为何「用不了 / 点角色弹回」**：新分支在 `0x41D1A6` 拦下后自己写攻击力再 `jmp 0x41D22F`，
  绕过了原尾部（`0x43F98E` 刷新、`0x41C74D` 提示/消耗、`ctx+0x1C` 结果）⇒ 外部表现为"什么都没发生"。
  **不是选择框过滤**：`0x45533D`（选人框）拿到的参数是 `ctx+0`(道具ID)、4、`ctx+0x18`(1)、`ctx+2`(战场编号)，
  **不含特效号**，所以它无法按 0x2C 特意拒绝。
- **`ctx` = 静态结构 `0x497750`**（`0x43729C` 里 `mov edx,ecx`，ECX 由分派器传入的常量）：
  `+0` 道具ID（byte）、`+1` 特效号（`0x43AD20` 取物品 `+0x11`）、`+2` 战场编号、
  `+4` 战场单位、`+0xC/+0x10` 人物记录、`+0x14` **物品记录指针**、`+0x18` 常量 1、`+0x1B` 图标、
  `+0x1C` **结果字段**（分派器尾部 `mov eax,[ecx+0x1C]` 即返回值）。
- **v5 方案**：
  ① `0x4372AF`（`call 0x43AD20`）挂钩，把 `特效号 0x2C` 映射成 `0x21` 写进 `ctx+1`
     ⇒ 分派器按 0x21 选 handler 3，**整条五维流程原样跑**（选人、检查、加值、刷新、提示、消耗）。
  ② `0x41D1E3`（`call 0x423E93`）挂钩：算完新五维后，若物品 `+0x11 == 0x2C`，
     把 `AL` 换成旧五维值 `[ebp-0xC]` ⇒ 五维写回等于没变，只有 `+0x11` 攻击力按 `min(旧+特效值,9999)` 变。
  ③ `0x44F37A: 90→03` 仅作保险（若真身 0x2C 仍走到分发表，路由 handler 3 而非垃圾指针）。
- `0x423E93` 是**读调用者栈帧的半函数**（`xor eax,eax; mov ecx,[ebp-0x14]; push [ebp-0xC]…`），
  只读 `[ebp-0x14]`（加值）与 `[ebp-0xC]`（旧五维），从洞里 `call` 它时 ebp 未变即可照用。

## 2026-10-26 v6：一次做五种「使用道具加派生能力」（0x2C~0x30）
