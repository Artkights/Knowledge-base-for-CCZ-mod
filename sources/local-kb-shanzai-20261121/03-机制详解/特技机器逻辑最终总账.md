## 六、方法论（定稿）

1. **桩体形态**：`add/sub/imul/mov` 写回内存（参数或局部累加器）⇒ 数值型
2. **参数来源**：桩所在函数的调用者 push 了什么 ⇒ 值被谁用
3. **桩后第一 call**：归族（`0x425AD9` 数值 / `0x45D513` 判定 / `0x41B500` HP / `0x420B08` 阶段 / `0x406710` 阵营）
4. **读法**：**必须从调用点地址本身开始反汇编**（往前读会落在指令中间 ⇒ 乱码）
5. **基址验证**：已知字符串反查 → 求步长 → 第三项校验

## 七、10 条假阳性来源（都踩过）

1. `6A FF` = `push -1`，不是 id `0xFF`
2. capstone：`[ebp + 8]` 十进制 vs `[ebp + 0x10]` 十六进制
3. `call` 之前的 `add/sub` 与本特技无关
4. 局部累加器不算"参数写回"，但同样是数值型
5. "字面可疑" 13/22 是假警报
6. 域锚点会把相邻桩误当本特技的域
7. 检测窗口跨函数
8. 域锚点 A 可能为假（`cmovne`/`test→call` 不是算术）
9. "test 后 call" 不能当"发动动作"（`0x425B12` 只是分配缓冲）
10. **不要相信元数据的 `base_va`**（`0x4CC600` 就是这么错的）

## 八、还剩什么

1. **11 个"域锚点 A"** 未验到具体形态（`0x17 0x18 0x2D 0x2E 0x44 0x46 0x54 0x57 0x6A 0x6C 0x70`）
   ⇒ 它们的"下一站"都是一串 `call + push`，要定案得再往下追一层（下游函数语义）
2. **`0xB1 辅助移动力`**：机器上**找不到专属接入点** ⇒ 需人类侧确认"引擎里到底有没有实现"
3. **6 个空名槽**（`0xED 0xF4 0xF7 0xF9 0xFC 0xFD`）：`0xF7` 有代码路径 ⇒ 需人类侧确认来历
4. **三胞胎 `0x7D/0x7E/0x7F`**：三项名表 raw 完全相同 ⇒ 需人类侧确认编辑器里挂哪一个
