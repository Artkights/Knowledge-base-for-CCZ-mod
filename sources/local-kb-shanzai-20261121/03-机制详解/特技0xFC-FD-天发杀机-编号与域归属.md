# 特技 0xFC / 0xFD / 0x6F —— 天发杀机血统、域归属与钩点顺序

## 结论速览

1. **血统**：`天发杀机` 早期整合版用的特技号就是 **`0x6F`**（十进制 111），见 `【6.6山贼】天发杀机-0x6F-整合版策略勠力同心（敌军施法范围）.txt`：名表行 `0x4CC600 + 0x6F*16 = 0x4CCCF0` 改名为「天发杀机」（GBK `CC EC B7 A2 C9 B1 BB FA`）+ flag `0x06`；钩点 `0x41C0F9` → 洞 `0x430978`（768B）。**后续版本才切到 `0xFC`（判定）+ `0xFD`（次数）**。
2. **`0x6F` 是真特技号，不是“只是个名表标签”** —— 之前的说法作废。机制是：**特技号与名表行用同一个索引**（`0x4CC600 + id*16`），所以选号时两者同时确定；改名只是让界面显示中文名。
3. 选号纪律（补丁原文）：该行必须是 **「预留/空」**，且**引擎代码没有 `call 0x4101D9` 查过该号** —— 查过的号会与原生效果冲突。这才是“选号”的真正约束。
4. **v7 行为**：敌方**策略**命中「不带本特技的我方」时 —— 范围内带本特技、不在目标表、`[unit+0x23] < 特效值` 的我方，各对施法者**物理打 1 下**（执行器 `0x41058D`；范围 = 目标策略 `+0x0C` 段表，`值-2` 索引，`0x436611` 展开）。**特效值 = 本回合每人最多触发次数**。
5. **`0xFC`/`0xFD` 是后续版本**：`0xFC 天发杀机`（判定）、`0xFD 天发杀机次数`（配额，174 类型表无此条）。界面 `F0–FE` 那段里 `F0/F4/F9/FD` 在总表无行。

## 为什么「被击杀后吸血活下来」在 v7 上做不到（结构性原因）

v7 的钩点是 **`0x41C0F9`**，位置在 `0x41C0E8` 内、`call 0x425627` **之后** —— 也就是「敌方策略命中并结算完之后」才轮到我们进场。

⇒ 若那次策略结算**已经把我方打死**，钩子进场时单位已是死亡/待处理状态：**反击发不出来，吸血更谈不上**。这不是数值不够，是**顺序晚了**。

要让「被击杀后吸血活下来」成立，必须满足其一：
- **A（改顺序）**：把触发点前移到「策略伤害写回之后、死亡判定之前」—— 本质是换钩点，不改判定逻辑，字节少；
- **B（劫持死亡判定）**：允许带 `0xFC`/`0x6F` 且次数 > 0 的单位以负血存活到反击结算 —— 新增分支，且负血会被预览/AI/集气等读 HP 的代码看到，有静默错算风险。

**优先验 A**：A 成立就不需要 B。

## 待证（决定 A 是否可行）

需要一张受击链顺序图：

```
敌方策略 → 伤害计算 → HP 写回 → [?? 钩点 0x41C0F9 在这里 ??] → 死亡判定 → 死亡处理
```

- 静态：沿 `0x41C0F9` 的调用者 `0x41C0E8` 往上找，确认它与死亡判定的先后；
- 实机：在 HP 写回点与 `0x41C0F9` 各挂一次，比较命中顺序。

## 与 `0xFE` 的关系

`0xFC` 的域 `0x43F9E9` 与 `0xFE ☆神圣庇佑☆` 共享。**用户决定不使用 `0xFE`**（不做任何分配）⇒ 该域对 `0xFE` 空置，`0xFC` 独占，不需要互斥分支。

## 空白名表行的回滚字节

名表 `0x6F` 原字节：`D4 A4 C1 F4 00…00`（「预留」）。回滚三处：`0x4CCCF0` 名字区、洞里两处 `68 6F 00 00 00`、钩点 `0x41C0F9 → E8 29 95 00 00`。
