# 特技触发链：通用分派器 `0x45AA37` 与种类跳表 `0x43E75E`

## 结论速览

1. **`0x45AA37` = 通用技能触发分派器**（不是某个特技的桩）：**9 处调用**，参数布局
   `[单位记录] , 种类 , 号 , flag , [记录+4]`（push 顺序见下），内部先 `0x43E4D6(号)` 取技能结构，再交 `0x43E6AA` 执行。
2. **`0x43E75E` = 6 项"种类→取值器"跳表**（种类 `0~5`）：分别读单位记录的 `[ecx+0x18]`~`[ecx+0x1D]`；
   **种类 6 不走该表**（走 `0x43E70C` 分支）。⇒ 表只有 6 项，**第 7 项起就是相邻数据，禁止越界读**。
3. **号域上界 `0x400`**（分派器里 `cmp ecx,0x400 / ja`），**`0xFF` = 空/哨兵**（与库内"0xFF=空"一致 ✓）。
4. **这解释了"桩扫描的洞"**：破坏系/每回合exp/麻痹封锁混乱等**不是**由 `push 立即数` 桩触发的，
   而是走这条通用链（号由**栈参数**或单位记录传入）⇒ 例如 `0x40399F`（破坏系实现）**全样本只有 1 处调用** `0x405A24`，
   且号来自 `push [ebp-0x20]; push [ebp-0x2c]` ✓
5. **`0x40DDAF` = 标志位→名表行号 的映射器**：`al & 0x80 → 0x2C`、`& 0x02 → 0x32`、`& 0x04 → 0x33`、
   `& 0x08 → 0x30`、`& 0x10 → 0x31`，否则 `0xFF`。⇒ 这些值是**名表行号**（= 附加文本/后缀名），与后缀主题同域。

## 适用版本

- 样本：`复刻版6.6山贼\Ekd5.exe`。**SHA 会被并发会话改写，引用前必须现读**（`_样本时间线.py`）。
- 本文所有地址均为**本轮现读字节/反汇编**所得（静态证据，非实机命中）。

### 1. 分派器 `0x45AA37`（前 140 字节反汇编要点）

## 实现·使用方法（给"桩扫描洞"补实现入口）

1. 对扫不到桩的号（破坏系 `0x06~0x0B`、每回合exp `0x03~0x05`、麻痹/封锁/混乱 `0x0D~0x0F` 等）：
   **不要**再在 `push 立即数` 里找它 ⇒ 改查**这条通用链**：
   - 先看该号是否出现在 `0x45AA37` 的 9 个调用点上下文（号可能来自寄存器/栈参数）；
   - 或从"实现函数"反查：如 `0x40399F`（破坏系）唯一调用者 = `0x405A24`，号由 `[ebp-0x20]/[ebp-0x2c]` 传入。
2. 需要"号→结构"时用 `0x43E4D6`（入参在 `ecx`）；需要"种类→取值器"时用 `0x43E75E` 表。

## 风险与边界

- **种类跳表只有 6 项**（`0~5`）；`cmp al,6 / jbe` 之后的 `je` 分支才处理 6 ⇒ **不要把它当 7 项表读**（第 7 项现读是 `0x23282227` = 字符串字节，属越界）。
- 号域 `≤0x400`；`0xFF` 与 `0xFFFF` 都是"空"语义，**不能按假值处理**（与库内既有口径一致）。
- 本页结论是**静态证据**；任何"该号真的走这条链"的断言仍需实机（x32dbg 断点 `0x45AA37`/`0x43E6AA`）确认。
- `0x4917B0`、`0x4B4250` 是全局对象；库内已有涉及 `0x4B4250` 的记录，引用前先查冲突。

### 1. ★ `0x43E776` 确认是**真表**（原「待验证项 P1」结案）

从函数头 `0x43E6AA` 精确解码（含字节）：

```
0043E6EC  mov  ecx,[ebp+0xC]                ; 种类
0043E6EF  cmp  al, byte ptr [ebp+0x10]      ; 值 vs 参数(第5参 flag)
0043E6F2  jle  0x43E6FD

0043E6FD  je   0x43E708
0043E6FF  mov  al, byte ptr [ecx*2 + 0x43E777]   ; 值 < 参数 ⇒ 取 B 字节
0043E708  mov  al, 0xFF                          ; 值 = 参数 ⇒ 空
```

- **表在 `0x43E776`，12 字节 = 6 组（种类 0~5）**，位置恰好**晚于 `0x43E6AA` 的 `ret`(0x43E75B)、早于下一函数序言** ⇒ 是**函数间隙里的数据表** ✓（不是指令字节误读）。

## 内部链路（2026-10-16 深夜）：`0x43E6AA` 的完整过程 + `0x4917B0` 对象

### 1. `0x43E6AA` 全函数（现读，到 `ret` 为止）逐段语义

```

mov ecx,[ebp+8] ; call 0x4061F9          ; [ebp+8]=编号 → 记录 = [0x4A7B20]+编号*0x30（库内已知 ✓）
push ecx ; push [ecx+6] ; push [ebp-0xb] ; push [ebp-0xc]
mov ecx,0x4B4250 ; call 0x45503F         ; ★ 渲染上下文成员（0x4B4250 库内已知=渲染上下文；此处读 [0x505FDC] 开关，ret 8）
mov eax,[ebp+0xC] ; cmp al,6 ; jbe …
    >6  → al = 0xFF
    ==6 → mov eax,[ebp+0x10] ; call 0x40DDAF        ; 种类6：参数经「标志→名表行号」映射器
    else→ cmp byte [ebp+8],0xFF ; je → xor eax,eax
          mov ecx,[ebp-8] ; call [eax*4 + 0x43E75E] ; 种类0~5：6 项跳表取「值」
cmp al,[ebp+0x10] ; jle / je               ; 三态：>参数→A；=参数→0xFF；<参数→B（表 0x43E776）
cmp al,0xFF ; je 0x43E750                  ; 空 ⇒ 直接收尾
push eax ; mov ecx,0x4917B0 ; call 0x40BCD2   ; ★ 把「值」交给 0x4917B0 的成员
push [ebp+8] ; mov ecx,0x4917B0 ; call 0x452F9D ; ★ 用「编号」查询 → eax
test eax,eax ; je 0x43E746
    push 1 ; push 0 ; mov ecx,0x4917B0 ; call 0x401E5D   ; 两立即数参数（疑排序/重排）

```

⇒ 整段读作：**「判定出一个值（A / B / 映射值，或空）→ 作为一条效果加入 `0x4917B0` 列表 → 用编号查回该项 → 必要时重排 → 提交」**。
这正是"技能生效落地"的那一步（不是判定本身）。

### 2. `0x402396(this, i, k, arg2)`：逐项处理 = **贴图/绘制**

```

mov edx,[ecx + i*4 + 0x14]             ; ★ 数组 A[i]（= 元素指针）
push edx
mov al, byte [edx]                     ; ★ 元素 +0x00（byte）= 二级索引
push [ecx + eax*4 + 0xB4]              ; ★ this+0xB4 表[二级索引]
mov eax,[ecx+0xC] ; imul eax,[ecx+8]   ; ★ this+0x08 × this+0x0C
push eax ; imul eax,eax,3 ; push eax   ; ★ ×3 ⇒ 每像素 3 字节 ⇒ 图像缓冲大小
mov eax,[ebp+0xC]                      ; k
push [ecx + k*4 + 0xC10]               ; ★ 数组 C[k]
push [ecx+0xFD0]
call 0x4819E0 ; add esp,0xC
movzx edx, byte [eax+3] ; imul edx,6 ; add edx,4   ; ★ 尺寸 = 元素[+3] × 6 + 4
cmp dword [ebp+0x10], 1 ; je 0x4023FD              ; ★ arg2 == 1 分两支
   非 1：push [this+0xFD0]; push 0; push 2; push edx; push [ebp-0xC]; push [ebp-0x10]; call 0x40690C
   == 1：push [this+0xFD0]; push edx; movzx edx,byte [元素]; push edx; mov dl,[元素+2]; push edx; push [ebp-0xC]; push …
```

- **`this+0x08` × `this+0x0C` × 3** = 典型**位图尺寸**（宽×高×3 字节/像素）⇒ `0x4917B0` 含**图像缓冲** ✓

### ② `0x47E09B` 与 `0x47E239` —— **同源孪生（两个落图入口）**

### ★ 纠正 5：`0x40E905` 的 `ecx` = **容器自身**（`0x4917B0`），不是元素指针

`0x402396` 内到该调用前的完整栈帧（现读）：

```
004023DC  mov  ecx, dword ptr [ebp - 4]     ; ★ ecx = [ebp-4] = this（= 0x4917B0 容器）
004023E5  push dword ptr [ecx + 0xfd0]      ; 参数①= [this+0xFD0]（子容器）
004023EB  push 0 / 004023ED push 2
004023EF  push edx                          ; 尺寸
004023F0  push [ebp-0xc] / 004023F3 push [ebp-0x10]
004023F6  call 0x40690C                     ; arg2 != 1 支
004023FD  push dword ptr [ecx + 0xfd0]      ; arg2 == 1 支（ecx 仍是 this）
00402403  push edx / 00402407 push edx / 0040240B push edx
0040240C  push [ebp-0xc] / 0040240F push [ebp-0x10]
00402412  call 0x40E905
```

⇒ 因此 `0x40E905` 里的 `[ecx+1]`、`[ecx+2]`、`[ecx+0xB4]` **全是容器字段，不是元素字段** ✗
（上一节我写成"元素类型码 `+0x02==0x2001`"、"`byte[元素+1]`"**作废**。）

**`0x4917B0` 容器字段表（据本轮修正后）**：

| 偏移 | 现读用法 | 语义（判定） |
|---|---|---|
| `+0x01` | `movzx eax, byte [ecx+1]` → `imul × 参数 × 3` | **行/步长因子（byte）** |
| `+0x02` | `cmp word ptr [ecx+2], 0x2001` | **容器格式/类型码（word，本处 = `0x2001`）** |
| `+0x08` / `+0x0C` | `imul eax,[ecx+8]`（配合 `+0xC`） | 宽 / 高（位图尺寸） |
| `+0x14` | `mov edx,[ecx + eax*4 + 0x14]` | 元素指针数组（步长 4） |
| `+0xB4` | `push [ecx + eax*4 + 0xB4]`、`add eax,[ecx+0xB4]` | **数据/资源基址（按索引的数组或缓冲）** |
| `+0xFD0` | 多处 `push [ecx+0xFD0]` | 子容器指针 |
| `+0x2A4` | 项数（byte） | 条目数 |

### ★ 纠正 6：`0x47E09B` 与 `0x47E239` **不是"同源孪生"**

逐条对照（规范化到各自 `ret`）：

| 指标 | 值 |
|---|---|
| `0x47E09B` 指令数 | **107** |
| `0x47E239` 指令数 | **114** |
| **逐条完全相同** | **11 / 107** ✗ |

⇒ 二者**只共享"取址前导"**（`sub esp,0x20` + `push ebx/esi/edi` + 读 `[0x4BD044]` → `[eax*8+0x4B8598]`/`+0x4B859C` → `lea`/`mov [ebp-0x20/-0x1C]`），
**从第 12 条起实现不同**（`0x47E239` 走 `shl eax,4; add eax,0x4B8BE0` 表 B 路线）⇒ 应表述为
**"共享取址前导的两个不同落图实现"** ✓（上一节"同源孪生"的说法作废。）
