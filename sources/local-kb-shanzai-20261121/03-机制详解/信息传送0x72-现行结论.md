## 结论速览

1. **[6.6-现读] 指令上限 0x7B**：分派器 `0x4109E6` 处 `83 F8 7B / 77 34`（`cmp eax,0x7B; ja 失败分支`）⇒ 可分派的指令号封顶 `0x7B`；上限立即数字节已定位于 **`0x4109F8`**（勘察摘要 F 节「位置未定位」由现读解决）。
2. **[6.6-现读] `0x72` 处理器 = `0x47D89E`**，经两次参数类型校验后 `call [P1*4 + 0x47D8DF]` 分派子功能；成功返 `1`、失败返 `5`。
3. **[6.6-现读] P1 跳转表共 38 项**（`0x47D8DF`，索引 0..37），表尾紧接 `90 90 90 90`；处理器**无 P1 边界校验** ⇒ 越界风险条款见 §二。
4. **[6.6-现读] 0x7A 是真实实现 `0x4284A2`**（串参数校验 + `call 0x42DB2C`），推翻 6.5 时代「0x7A 为占位」的旧口径；表尾 `0x7C..0x7F` 才统一指向占位 `0x4D0000`。
5. **[6.6-现读] `0x7B` 原生入口 `0x47E9F0` 与六项跳转表 `0x47EA2F` 完整存活**，结构与 0x72 处理器同构。
6. **[6.6-现读] DLL 通道仍是活代码**：`0x4670B5` → `call 0x464599`，两处均经 `call [0x4862F4]`（SendMessageA IAT）发消息 `0x102C` ⇒ 与原生 0x7B 构成**两条并存路径**（路线②口径已在该页改为「两条并存」）。
7. **[6.6-现读] `0x43F27F = jmp 0x43BDCC`** 是历史补丁时代的等价跳转，**不能**据此声称存在 LuaSkill 运行时。
8. **编辑器名单止于 33**：引擎 38 项中 **34/35/36/37 有实现指针、编辑器无名字**（缺口见附表一）；本页**不给未验证的子功能起名**。

## 一、指令分派链 [6.6-现读]

分派器 `0x4109E6`（前 32 字节现读）：

```asm
0x4109E6  push ebp / mov ebp,esp / push ecx
0x4109EA  call 0x40FCB2                  ; 读指令号（参数读取器，语义清单见附表三 [6.5pl]）
0x4109EF  push eax
0x4109F1  mov edx,[ebp-4] / mov [edx+0x2E], al   ; 指令字节存入上下文 +0x2E
0x4109F6  cmp eax, 0x7B / ja 失败分支     ; ⇒ 指令上限 0x7B（立即数在 0x4109F8）
0x4109FB  cmp al,1 / ja … / add eax,3 / cmp al,4 / jne …   ; 少数低位指令的特判分支，不影响本族 0x72/0x7B
```

指令表 `0x410BF0`（0x70..0x7B，12 项，现读）：

| 指令 | 处理器 | 指令 | 处理器 |
|---|---|---|---|
| `0x70` | `0x40F2EA` | `0x76` | `0x416C41` |
| `0x71` | `0x403936` | `0x77` | `0x416C87` |

| `0x73` | `0x40F244` | `0x79` | `0x415093` |

## 二、0x72 处理器 `0x47D89E` 与 P1 跳转表 [6.6-现读]

处理器 64 字节现读反汇编要点：

```asm
0x47D89E  push ebp / mov ebp,esp
0x47D8A3  push 4 / mov ecx,[ebp+8] / call 0x4183F7   ; 类型 4=数值 读取（语义 [6.5pl] 既有结论）
0x47D8AE  cmp eax, 0x80000000 / je → 失败路径
0x47D8B4  push eax / push 5 / mov ecx,[ebp+8] / call 0x4183F7  ; 类型 5=字符串 读取
0x47D8C0  cmp eax, 0x80000000 / je → 失败路径
0x47D8C6  push eax / mov eax,[ebp-4] / call [eax*4 + 0x47D8DF] ; 以 P1 为表索引分派
0x47D8D1  mov eax,1 / jmp 返回        ; 成功 ⇒ 返 1
0x47D8D8  mov eax,5                   ; 任一类型校验撞哨兵 ⇒ 返 5（失败）
```

**P1 边界：无。** 处理器全程没有对 P1 做 `cmp/jae` ⇒ `P1 ≥ 38` 时读表越过 `90 90 90 90`（位于 `0x47D8DF+152`）乃至后续代码字节，把任意值当函数指针 `call` ⇒ **越界调用/崩溃风险**。这是「现行引擎行为」条款，不是缺陷修复建议。

**P1 跳转表 `0x47D8DF` 完整序列（38 项，[6.6-现读]，表尾 `90 90 90 90`）**：

`0x4081F2, 0x40C4B7, 0x41419F, 0x40221B, 0x402AA6, 0x408811, 0x40886E, 0x41104B, 0x41E5BB, 0x414571, 0x411C4A, 0x44CE20, 0x4295FB, 0x404E70, 0x40DC06, 0x40DCB3, 0x4107A7, 0x42C846, 0x406CFA, 0x4290FC, 0x41648E, 0x4078ED, 0x4211F4, 0x408CFA, 0x4236C2, 0x425B66, 0x426404, 0x423E63, 0x425BF2, 0x47A919, 0x42AF6F, 0x42D260, 0x42C45A, 0x42A61D, 0x42C992, 0x42FD47, 0x436EB0, 0x453533`

- 前 5 项（索引 0..4）与 6.5 时代记录的表**逐字节相同**（对比口径 [6.5pl]）。
- **禁止按索引给这 38 项起语义名**——除编辑器名单（附表一，[外部]）外均未现读验证；索引 34..37 有实现指针而编辑器无名字。

## 三、0x7B 原生入口 `0x47E9F0` 与六项表 `0x47EA2F` [6.6-现读]

入口与 0x72 处理器同构：`push 4 / call 0x4183F7` → 哨兵判 `0x80000000`；`push 5 / call 0x4183F7` → 哨兵判；然后 `call [eax*4 + 0x47EA2F]`，成功返 `1`、失败返 `5`；同样**无索引边界校验**。

六项表（`0x47EA2F`，24 字节现读）：`0x42FB85, 0x42FBB5, 0x42FAEE, 0x42FB17, 0x42FB62, 0x42CC8E`。

语义标签沿用 6.5 时代既有结论 **[6.5pl]**（6.6 未逐项语义现读）：索引 0 疑为未用、1 道具、2 入队、3 地形、4 天气、5 异常状态。

**结论：6.6 的 `0x7B` 原生处理链在 `0x47E9F0` 处完整存活**——「6.6 必须靠 DLL 才有 7B」不成立；DLL 路径是并存的第二条通道（§五）。

## 四、0x7A（`0x4284A2`）是真实实现 [6.6-现读]

```asm
0x4284A2  push ebp / mov ebp,esp
0x4284A7  push 5 / mov ecx,[ebp+8] / call 0x4183F7   ; 读串参数
0x4284AF  test eax,eax / jge 成功路径
0x4284B4  mov eax,5 / jmp 返回                        ; 负值 ⇒ 失败返 5
0x4284C0  push eax / call 0x42DB2C                    ; 真实功能体（0x42DB2C 未展开现读）
0x4284CA  push 1 / pop eax / pop ebp / ret            ; 成功返 1
```

推翻「0x7A 是 0x4D0000 占位」的 6.5 旧口径：**6.6 表槽 `0x410C18` = `0x4284A2`，为活实现**；占位只覆盖 0x7C..0x7F。

## 五、DLL 通道：`0x4670B5` → `0x464599` → `SendMessageA(…,0x102C,…)` [6.6-现读]

- `0x4670B5`：`push [ebp+8] / call 0x464599`，随后本组参数直发：`push 2 / push [obj+8] / push 0x102C / push [obj+0x10] / call [0x4862F4]`。
- `0x464599`：同一形状（`68 2C 10 00 00 … FF 15 F4 62 48 00`），`[0x4862F4]` 为 SendMessageA 的 IAT 表项。
- 参数序（cdecl）：`SendMessageA( hwnd=[obj+0x10], msg=0x102C, wParam=[obj+8], lParam=2 )`。

⇒ **消息 `0x102C` 的 DLL 扩展通道在 6.6 仍是活代码**；接收端（ExtendData.dll）的 7B 槽表**未现读**（见 §待验证）。两条并存路径的取舍与落地设计见 `08-剧本与战场/剧本子功能原生化-路线②落地设计.md`（该页口径已同步为「两条并存」）。

## 2026-10-27 定案：0x72 的活性执行链是「原生表 `0x410A38`」这一条（DSH 现读，样本 `78D0B871…E808AF`）

- **分派器 `0x4109E6` 才是指令执行入口**：`call 0x40FCB2` 读 u16 指令号 → `cmp eax,0x7B`（立即数在 `0x4109F8`）→ `sub eax,2` → `call dword [eax*4 + 0x410A38]`。
  即 `0x410A38` 是 **opcode 2..0x7B 的整表**，`0x410BF0` 只是它 `0x70..0x7F` 那一段的切片（`0x410BF8` = opcode `0x72` → `0x47D89E`）。
