## 详细记录

#### 概述

曹操传中的连击并非独立的"特技"系统，而是**游戏物理攻击流程中的基础战斗判定机制**。该机制通过比对攻击方与被攻击方的"爆发力"属性，计算出三项核心战斗参数：**连击率**、**命中率**、**回避率**，并将这些参数应用于物理攻击的全过程。

#### 核心概念：爆发力

##### 什么是爆发力

"爆发力"是曹操传中用于衡量单位战斗爆发能力的综合属性。该属性直接影响战斗中的三项关键判定：

| 战斗参数 | 计算来源 | 作用 |
|----------|----------|------|
| **连击率** | 攻击方爆发力 vs 防御方爆发力 | 决定是否发动追加攻击 |
| **命中率** | 攻击方爆发力 vs 防御方爆发力 | 决定攻击是否命中目标 |
| **回避率** | 防御方爆发力 vs 攻击方爆发力 | 决定目标能否闪避攻击 |

##### 爆发力与敏捷的关系

根据游戏机制分析，爆发力的数值来源与单位的**敏捷属性**高度相关。敏捷越高的单位，其爆发力数值越大，在战斗判定中越容易：
- 发动连击
- 命中敌人
- 回避敌人攻击

#### 爆发力比对的计算公式

##### 核心公式（待证假设）

基于游戏机制分析，爆发力比对可能采用以下形式的计算：

```
连击率 = (攻击方爆发力 / (攻击方爆发力 + 防御方爆发力)) × 基础系数
命中率 = (攻击方爆发力 / (攻击方爆发力 + 防御方爆发力)) × 技能加成
回避率 = (防御方爆发力 / (攻击方爆发力 + 防御方爆发力)) × 地形加成
```

##### 随机判定

所有百分比判定（连击率、命中率、回避率）最终都通过随机数进行比较：

```
if (随机数(0-100) < 判定阈值) {
    // 判定成功
}
```

#### 与特技系统的区别

##### 关键区分

| 特性 | 战斗基础判定 | 特技系统 |
|------|-------------|----------|
| **性质** | 物理攻击流程的固有部分 | 需通过特技桩函数触发 |
| **触发方式** | 自动计算，无需显式触发 | 特定条件满足后触发 |
| **判定依据** | 爆发力属性比对 | 特技定义数据 |
| **修改方式** | 修改属性计算逻辑 | 添加特技定义 |

##### 错误理解纠正

**❌ 错误理解**：连击是一种特技，通过特定装备或能力获得

**✅ 正确理解**：连击是战斗的基础判定机制，所有物理攻击都会进行爆发力比对，进而决定是否触发连击

## 2026-10-15 静态定案：连击判定在 6.6 有「两份副本」，`.code` 的 `0x4060D2` 已是孤儿

> 证据：离线反汇编（capstone，`_dsh反汇编工作台.py`）+ **全节原始字节扫描**（`E8`/`E9`/`Jcc rel32`/`dword` 四类引用，含非可执行节）。
> 样本 `Ekd5.exe` SHA256 `25DB2211FE8F495DE4993BAB296C23C180E18679F00A0E43B47B1FD2034B7EAF`（46 补丁）。
> **证据层级 = 1 静态检查**（未做运行时断点；运行时确认项见 `00-总览与规范/待验证清单.md`）。

### 一、活体（`.text3`，被攻击循环真正调用）

- **攻击主循环 `0x4064F1`**（`ret 8`）：
  `0x406514 mov byte [edx+0x608],0`（**先清连击标志**）→ `jmp 0x406539`；
  重跑段入口 `0x40651D inc byte [eax+0x608]`（**连击计数 +1**）→ `0x406526 call 0x4061F9`（战场编号→单位）
  → `0x40652E push 8 / call 0x423FE8`（状态掩码 8 = 混乱，命中即收尾）→
  **`0x40653E call 0x4E30E1`（连击判定）** → `0x406543 jae 0x40655E`（失败即收尾）→
  `0x406555 call 0x4E3000` → `0x40655A test eax,eax / jne 0x40651D`（成立 ⇒ 再来一段）。
- **`0x4E30E1`**（被上面调用，48 字节）：`mov ecx,[ecx+0x0C]`（攻方单位）→ `push 0 / push 1 / push 0 / push 0xB5`
  → `call 0x4101D9`（**特技个人号 `0xB5`**）→ `inc eax / inc eax`（档位）→ 再按 `[ebp+8]` 分支。
- **「判定 + 清暴击标志」主体在 `0x4E3095`…`0x4E30DD`**：
  `0x4E30A8 call 0x4E30E1`（特技门控）→ `0x4E30B8 call 0x4E40E0`（**连击率**）→
  `0x4E30BD push 0 / push eax / call 0x4287A8`（**集气/随机判定**）→
  **`0x4E30D1 mov [edx+0x604],eax`（`xor eax,eax` 后 ⇒ 清 `ctx+0x604` 暴击标志）** → `ret`。

### 二、孤儿（`.code` 的 `0x4060D2`，即写点 `0x406141` 的宿主）

- 与上面那段**逐条结构镜像**：特技门控用 `0x35`（个人）/`0x42`（装备）→
  `0x406128 call 0x4E40E0`（连击率）→ `0x406130 call 0x4287A8`（集气判定）→
  **`0x406141 mov [edx+0x604],eax`** → `mov eax,[ebp-4] / mov esp,ebp / pop ebp / ret`。
- **原始字节扫描结果（全节，含 `.text1/.text2/.rsrc`）**：指向 `0x4060D2` 的
  **`E8` 0 个、`E9` 0 个、`Jcc rel32` 0 个、dword 指针 0 个** ⇒ **静态不可达**。
- 对照（同一脚本、同一次运行）：`0x4E30E1` 有 **4 个 `E8` 调用者**
  （`0x40653E` + `.text3` 内 `0x4E3025`/`0x4E3043`/`0x4E30A8`）⇒ 脚本有效、结论可信。
- ⇒ **`0x4060D2` 是"实现被搬进 `.text3` 后遗留的旧副本"**；`0x406141` 的清零**不在活路径上**。
- 附带纠正一个读法：该函数开头 `push 1` / `push ecx` 是 MSVC 的**压栈即初始化局部变量**
  （`push 1` → `[ebp-4] = 1`，`push ecx` → `[ebp-8] = ECX`），
  所以正文里"凭空使用 `[ebp-8]`"是正常的——`[ebp-8]` 就是传入的 `ctx`（`0x4927F0`）。

### 三、版本护栏实例（**别用旧清单认地址**）

### 四、对当前主线（防御暴击 0x24 / 暴击预览）的意义

- `ctx+0x604` 的**活写入点只有两个**：`0x405F17`（置 1，段尾）与 `0x4E30D1`（清零，段间）。
  `0x406141` 可**从兼容清单中排除**（此前把它当"第二条活路径"是过度采信外部库）。

### 六、★ 特技个人号 `0xB5` 语义定案：**「一剑一念」= 提高连击段数上限**（2026-10-15，静态）

> 证据：名表 GBK 直读（`Ekd5.exe` 文件偏移 `0x9F350`，SHA `25DB2211…`）+ 反汇编 `0x4E30E1` 全函数。
> **证据层级 = 1 静态检查**（`0xB5` 的效果未做游戏内实测）。

**名表读法（可复用）**：个人特技名表 VA `0x4CC600`，**行号 = 特技号**，**16 字节/行**（名字 12B GBK + 2B 零 + flag 2B）；
`.api` 节 `文件偏移 = 0x090200 + (VA − 0x4BE000)` ⇒ `0xB5` 行 = VA `0x4CD150` = 文件偏移 **`0x9F350`**。

邻行实测（同一段读出来的，用于确认家族）：

| 特技号 | 名字 | 备注 |
|---|---|---|
| `0xB4` | 反击成双 | 反击家族 |
| **`0xB5`** | **一剑一念** | ★ 本页对象：连击段数 |
| `0xB6` | 自身治疗强化 | |
| `0xB7` | 辅助治疗策略 | |
| `0xB8` | 致命成双 | 暴击家族 |
| `0xB9` | 辅助连击率 | 提**连击率**（与 `0xB5` 提**段数**不同） |
| `0xBA` | 动如雷霆 | |

**语义（`0x4E30E1`，`ret 4`，1 个栈参 = 模式）**：

```asm
004E30E5  mov  ecx,[ecx+0x0C]      ; ECX = 攻方战术单位（调用方传 ctx）
004E30E8  push 0 / push 1 / push 0 ; 效果值标志=0 / 叠加=1 / 装备特效号=0
004E30EE  push 0xB5                ; 个人特效号 = 一剑一念
004E30F3  call 0x4101D9            ; EAX = 特效值 V
004E30F8  test eax,eax / jne +2 / xor eax,eax   ; V=0 归一为 0
004E30FE  inc eax / inc eax        ; EAX = V + 2   ← 连击段数上限
004E3100  cmp  dword [ebp+8],0
004E3104  jne  0x4E3111            ; 模式 1
004E3109  cmp  byte [ecx+0x608], al   ; 计数 vs V+2   （模式 0）
004E310F  jmp  0x4E311B
004E3114  dec  eax                    ; 模式 1：EAX = V+1
004E3115  cmp  byte [ecx+0x608], al
004E311B  mov esp,ebp / pop ebp
004E311E  ret  4                   ; ★ 不破坏标志位
```

- **★ 契约坑（最该记住）**：本函数**用标志位回答**——`ret 4` 前最后一条是 `cmp byte [ctx+0x608], al`，
  调用方的条件跳转紧跟在 `call` 后、读的就是这个 `cmp` 的标志
  （`0x40653E call … / 0x406543 jae 0x40655E`、`0x4E30A8 … / 0x4E30AD jle 0x4E30B5`）
  ⇒ **只读 EAX 会读错语义**，必须连标志位一起看。
- **模式 0（`push 0`；攻击循环 `0x40653E`）**：`计数 ≥ V+2` ⇒ `jae` 收尾、停止连击。
  实走一遍：`0x406514` 清计数 → `0x40651D inc` → 判定 → `0x406555 call 0x4E3000` 执行 → `jne 0x40651D` 重跑
  ⇒ **V=0：共 2 段（原生）；V=1：3 段；V=n：n+2 段**。
- **模式 1（`push 1`；连击判定函数内 `0x4E30A8`）**：阈值取 `V+1`，`计数 ≤ V+1` 才继续去算连击率/集气。
- 与 `0xB9 辅助连击率` 区分：`0xB9` 提**率**（走 `0x40C7D8`/`0x4E40E0` 类），`0xB5` 提**段数上限**（本函数）。
- 家族旁证：`0xB4 反击成双`、`0xB8 致命成双` 同段命名，佐证"成双/多段"这一语义族。

### 七、`0x4E3000` / `0x4E30E1` 分工定案（2026-10-15 第 2 轮，静态）——并**修正第六节的一处表述**

> 样本 SHA `25DB2211…`；`_dsh反汇编工作台.py da 0x4E3000 26` + `_注入区图谱.py 0x4E3080 0x4E3130`（该范围只发现 `0x4E30E1` 一个入口）。

**修正**：第六节把 `0x4E3095`…`0x4E30DD`（含清零点 `0x4E30D1`）描述成"独立函数"是**错的**——
`0x4E3035 jbe 0x4E30A3` 直接跳入该段 ⇒ **它整段都属于 `0x4E3000` 的函数体**，
`0x4E30D1` 的清零是 **`0x4E3000` 的收尾**。

| 函数 | 规模/角色 | 关键点 |
|---|---|---|
| **`0x4E3000`** | **连击/多段"成立性"判定主函数** | `push 1`/`push ecx`（`[ebp-4]=1`、`[ebp-8]=ctx`）→ `ctx+0x01 = ctx+0x10`（主目标）→ `call 0x4101D9`（**特技个人 `0x35` / 装备 `0x42`**）→ 命中且 `0x4E30E1`(模式1) 成立 ⇒ `[ebp-4]=1` → 反击标志 `[0x492E04]`(=`ctx+0x614`) 分支 → `call 0x4E40E0`（连击率）→ `call 0x4287A8`（集气判定）→ **收尾 `0x4E30D1 mov [edx+0x604],eax`（清暴击标记）** → `ret` |
| **`0x4E30E1`** | 其内部调用的**段数上限查询**（48B，`ret 4`） | 用特技 **`0xB5`「一剑一念」**算上限：模式0 `V+2`、模式1 `V+1`；**用标志位回答**（见第六节） |

**攻击循环实走（`0x4064F1`）**：`0x406514` 清 `+0x608` → `0x40651D inc +0x608` → 混乱检查（掩码 8）
→ `0x40653E call 0x4E30E1`（**还有余量吗**，`jae` 失败即收尾）→ `0x406555 call 0x4E3000`（**这一段成立吗**）
→ `test eax,eax / jne 0x40651D`（成立 ⇒ 回重跑段）
⇒ **两个函数一个管"上限"，一个管"本次成立"，并在成立返回前把 `+0x604` 归零** ——
这就是"`+0x604` 每段一个生命周期"的机械原因。
