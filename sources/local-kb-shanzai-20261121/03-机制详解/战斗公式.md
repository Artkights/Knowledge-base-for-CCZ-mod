# 曹操传战斗计算公式解析

## 结论速览

- 适用：页内未标注游戏版本；「概述」明说"当前仅覆盖常规流程，不考虑特技（必定暴击/必定连击等）的影响"，且全文只有「2026-06-11 测验1」一节是 x32dbg live 命中 + HP 写断点闭环，其余均为静态反汇编与"待证假设"——套用到复刻版6.6山贼前须逐条复读核对。
- 解引用公式与关键偏移：战术单位 = `4A7B20 + 战场编号 × 30H`；人物运行时 = `[4CEA00] + Data号 × 48H`（由 `4061E4` 取得）；策略记录 = `4A3E77 + 策略号 × 61H`（`484005: imul ecx, ecx, 61`）；`unit+00`=Data 号（`40658F`/`4061E4`）、`unit+04`=出场/显示编号（不是 Data 号）、`unit+10`=当前 HP（`41B500`/`43F70C`）、`unit+14`=当前 MP（setter 待动态闭环）、`unit+1E`=异常状态组合（`423FE8` 等）。
- 物理攻击主链入口 `43DADA`：Stage1 `43F8C0` 攻击者能力检查（返回 `al=FF` 即攻击被阻，非 FF 才继续）→ Stage2 `435829` 防御修正（调 `4D3000`、`4351DA`）→ Stage3 `410F1C` 伤害+暴击（`41CECC` 基础伤害判定、`423FE8(08)` 暴击检查、`426B33` 二次暴击判定）→ Stage4 `4363DC` 伤害应用（结果存 `4B2C28`）→ Stage5 `4212F1` 追击检查（需追击特技：装备号 `36` / 个人号 `18`）；其中伤害有效判据在 `417B27 → 41CECC`：`attack = [attacker_unit+14]`（word，via `472840`）、`defense = [defender_unit+0E]`（byte，via `425AD0`），有破防能力（via `44DF49`）时先经 `41EDC1` 缩放为 `defense × (100 - 破防值) / 100`，满足 `attack >= adjusted_defense` 才产生伤害（`41EDC1` 本身即通用百分比缩放 `result = value × ratio / 100`，`41EDCC mov cl, 64` / `41EDCE div ecx`）。
- 暴击是状态标志位判定、不是概率判定：`423FE8` 读 `[unit+1E]` 并以掩码 `08`（bit 3）做最多 4 次移位匹配，`[unit+10] != 0`（`41B500`）且 `unit[1E]` 含 `08` 位时该单位每次攻击必定暴击（成功返回 `al=FF`）；暴击伤害倍率在 `4179B2 → 425627`，但 `00497AF8` 是策略上下文基址，不得把该结构整块命名为"暴击加成系数"。
- 已推翻/待验证：命中率公式尚未定位，`4759BC`/`406431`/`426B52` 只标"已定位"、公式仍是待证假设（敏捷偏移待证 `unit+0A` 或 `unit+0C`）；基础连击（爆发力比对）公式与判定位置均未定位，`4212F1` 内部先调 `4210D0`（装备号 36、个人号 18 → 调度 `6002C6`）属追击特技而非基础连击，应继续在 `43F8C0`、`4D3000` 区域或战斗准备阶段搜索；`unit[1E]` 暴击位的设置/清除机制也未闭环。
- 扣血落点与边界（2026-06-11 实机闭环）：`00405966` 攻击结果/伤害结果循环 → `00405ADC` → `0043F6DB` HP setter → `0043F70C: mov [ecx+10], edx`；`0043F70C` 只是最终 HP 写入、不是伤害公式，`00405966` 只是循环应用已生成的攻击结果、不应标为"伤害计算函数"；实测两段伤害 `59`（`118`→`59`）与 `44`（`59`→`15`）的上游来源未闭环，下一步在 `00405966` 入口采集 `[ebp-14]`、`[ebp-18]`，并对 `004927F0` 附近设写断点。

#### 二、伤害计算公式

##### 基础判定：攻防比对

**核心逻辑** 位于 `417B27` → `41CECC` 调用链：

```
伤害有效条件: 攻击力 ≥ 有效防御力
```

具体实现：

```
Step 1: 读取攻击力
   attack = [attacker_unit + 14]  (word, via 472840)

Step 2: 读取防御力
   defense = [defender_unit + 0E]  (byte, via 425AD0)

Step 3: 穿透修正 (如果攻击者有破防能力, via 44DF49)
   if has_penetration:
       ratio = 100 - penetration_value
       defense = defense × ratio / 100  (via 41EDC1)

Step 4: 最终判定
   if attack >= adjusted_defense:
       攻击命中，产生伤害
   else:
       攻击无效
```

##### 关键计算公式

**百分比缩放函数** [41EDC1](../03-机制详解/战斗公式.md)：

```asm
41EDC4: movzx ecx, cl      ; cl = 百分比(0-100)
41EDC7: imul eax, ecx      ; eax = value × ratio
41EDCC: mov cl, 64       ; cl = 100
41EDCE: div ecx            ; eax = (value × ratio) / 100
```

即：`result = value × ratio / 100`

##### 伤害公式（简化）

```
基础伤害 = max(攻击力 - 有效防御力, 0)

其中:
  有效防御力 = 防御力 × (100 - 破防值) / 100
              (无破防能力时破防值=0，即有效防御力=防御力)
```

##### 暴击伤害加成

当暴击判定成功时（详见第三节），伤害增加：
- 在 `4179B2` → `425627` 中处理暴击伤害倍率
- `00497AF8` 是策略上下文基址；本条调用链若借用其字段参与倍率，必须按具体偏移解释，不能把整块结构命名为暴击加成系数

#### 三、暴击率计算公式

##### 暴击判定机制

暴击不是概率判定，而是**状态标志位判定**。核心函数是 `423FE8`。

```
单位状态字段 unit[1E] 是一个 8-bit 打包标志位:
  
  bit pattern: [??][??][??][??][??][??][01][00]
                                  ↑
                             暴击标志 = 08 (bit 3)

当 unit[1E] 的位匹配参数 08 时，单位处于"可暴击"状态。
```

##### 判定函数 [423FE8](../03-机制详解/战斗公式.md)

```
参数: 状态位掩码 (如 08 = 暴击)

流程:
1. 读取 [unit+1E] → 获取单位状态字节
2. 循环匹配 (最多4次迭代):
   a) 参数右移1位，检查最低位
   b) 如果最低位为1，取状态的低2位
   c) 如果状态低2位匹配，返回成功
   d) 否则状态右移2位，继续循环
3. 4次迭代后仍未匹配 → 返回失败
```

##### 完整暴击判定流程

```
┌─────────────────────────────────────┐
│ 1. 攻击者HP > 0?  (41B500)       │
│    ↓ 是                            │
│ 2. unit[1E] 位匹配08?          │
│    (423FE8)                       │
│    ↓ 是                            │
│ ★ 暴击成功 → al=FF               │
└─────────────────────────────────────┘
```

##### 暴击触发条件

| 条件 | 检查方式 | 说明 |
|------|----------|------|
| 攻击者存活 | `[unit+10] != 0` | HP必须>0 |
| 暴击状态 | `unit[1E] 含 08 位` | 单位必须具有暴击状态 |

> **注意**：当 unit[1E] 的暴击位被设置时，该单位的每次攻击都必定暴击。
> 在常规流程中，暴击位的设置/清除受装备、状态、兵种特性影响。

#### 五、连击率计算（待深入验证）

##### 当前分析状态

连击（double attack）基于**爆发力比对**的机制尚未在当前分析的代码路径中定位。

根据用户描述和曹操传经典机制：
```
连击率 = (攻击方爆发力 - 防御方爆发力) × 系数

其中:
  爆发力 ≈ 敏捷属性 + 装备/兵种加成
  系数 = 触发连击所需的差值比例
```

##### 已定位的相关代码

在 `43DADA` 攻击流程末尾，`43DB80` 调用 `4212F1`：

```
43DB80: call 4212F1    ; 追击/连击检查
```

但 `4212F1` 内部首先调用的是特技桩函数 `4210D0`（装备号=36，个人号=18 → 调度函数6002C6），这是**追击特技**，而非基础连击机制。

基础连击（爆发力比对）的计算位置还需进一步在以下区域搜索：
- `43F8C0` 攻击者能力检查（可能在内部进行爆发力比对）
- `4D3000` 开始的 模组引擎函数（可能在内部计算连击率）
- 或战斗准备阶段（非攻击执行阶段）的预计算

#### 六之补、跨版本对照：普罗 6.5 的伤害公式（★ 2026-10-15 新增）

> 来源：`ccz-LuaSkill`（普罗 / Puluomiyuhun，目标 **Ekd5.exe v6.5pl**），
> 文件 `LuaSkillEngine/lua_api.cpp:1259-1337`、`knowledge/function-index.md:51-52`。
> **地址不得直接套到 6.6**；此处只作**公式语义**的交叉验证。

```c
// 物理：damage = level + 25 ± |ATK - DEF| / 2
atk = atk * (100 + (atkBuff - 3) * 20) / 100;   // buff 每档 ±20%，正常值 = 3
def = def * (100 + (defBuff - 3) * 20) / 100;
diff = atk - def;
damage = level + 25;
if (diff >= 0) damage += diff / 2;  else damage -= (-diff) / 2;   // ★ 物理 ÷2
if (damage < 1) damage = 1;

// 策略：同式，除数改 ÷3，另乘策略威力系数
// damage = level + 25 ± |INT_A - INT_D| / 3   （README.md:193）
```

**与本页既有结论的一致性**：

| 要素 | 本页（原版资料 / 6.6 复读） | 普罗 6.5 源码 | 判定 |
|---|---|---|---|
| 基数 | `伤害基数(25) + 等级` | `level + 25` | ✅ **一致** |
| 攻防差 | `(攻击 - 防御) / 2`（`shr eax,1`） | `diff / 2` | ✅ **一致** |
| 下限 | `call 0x47fa9e` 保底 | `if (damage < 1) damage = 1` | ✅ **一致** |
| 攻防来源 | 单位/人物记录 | 人物 `ATK +0x11` / `DEF +0x13` | ✅ 与库内 `character+11/+13` 吻合 |
| 策略除数 | 本页未定 | `/3` | 🆕 **新增** |
| 策略威力系数 | 本页未定 | 表 `0x4D1840`（百分比） | 🆕 **新增**（地址 6.5 专属，6.6 待复读） |
| 属性克制 | 本页未定 | 天气/属性匹配 **+25%** | 🆕 **新增** |
| 浮动伤害 | 本页未定 | 仓库**未收录**，本地已单独闭环 | 见 `浮动伤害-取消浮动伤害地址复核.md` |

**物理公式函数的跨版本关系**（6.6 样本 SHA `36694DBE…032668`）：

- 6.6 的公式入口仍是 **`0x43BC5A`**（`55 8B EC 83 EC 3C`），
  `call 0x43BC5A` 共 **5 处**：`0x405E6D`（`0x405DE1` 主控内，★主路径）、
  `0x419AED`、`0x438A2A`、`0x438CCA`、`0x440668`。
- 普罗 6.5 记为 `0x43BC62`（差 **`0x08`**）⇒ 疑似**同一函数的版本漂移**，
  引用时**必须写清版本**，不要混用（P1 待复核）。
- 命中率总函数 **`0x43B4B6` 在 6.5 与 6.6 同址** ⇒ 可作"未移位函数"参照点。
