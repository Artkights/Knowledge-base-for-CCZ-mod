# 外部补丁写法 vs 我们的写法 —— 可吸收清单（2026-10-18）

> 用户口径：「**都对比一下，别人的写法优化我们的写法，不一定要用他们的东西，但是要反汇编处理，
> 有哪些地址或者逻辑，跳转是我们能吸收的**」
>
> 方法：读外部补丁的**反汇编**（不是读它的结论），逐一对照我们的实现，只吸收**手法**。

## 一、`【6.5】暴击伤害预览-F版专用` —— 洞结构与我们的洞1 **几乎一模一样**

### 它的挂点+洞（`0x4E8000`）

```asm
; ---- 挂点侧（对我们很有参考价值：它把这 23B 放洞头）----
0x4E8000  9C                 pushfd              ; ★ 保护 EFLAGS
0x4E8001  51                 push ecx
0x4E8002  52                 push edx
0x4E8003  FF 75 D8           push [ebp-0x28]
0x4E8006  FF 75 D4           push [ebp-0x2C]
0x4E8009  50                 push eax            ; 预览伤害
0x4E800A  E8 31 00 00 00     call 0x4E8040       ; 主体
0x4E800F  5A                 pop edx
0x4E8010  59                 pop ecx
0x4E8011  9D                 popfd               ; ★ 恢复 EFLAGS
0x4E8012  89 45 E8           mov [ebp-0x18],eax  ; 存预览伤害
0x4E8015  6A 01              push 1
0x4E8017  E9 56 86 F5 FF     jmp 0x440672        ; ← 和我们的回跳目标完全相同
```

**对照我们的洞1（`0x442BD9`）**：

```asm
0x442BD9  89 45 E8           mov [ebp-0x18],eax
0x442BDC  51 52 56 57        push ecx/edx/esi/edi   ; ✓ 保护了通用寄存器
; ……判定主体……
0x442C4B  5F 5E 5A 59        pop edi/esi/edx/ecx
0x442C4F  6A 01              push 1
0x442C51  E9 1C DA FF FF     jmp 0x440672
```

### ★ 可吸收 #1：`pushfd / popfd`

**我们的洞没有保护 EFLAGS**，而洞内大量 `cmp/test/add/imul` 会改写 ZF/CF/OF。
当前之所以没出问题，是因为回跳后紧跟 `push 1`（不改标志）再 `jmp`，
但**这是靠运气**——一旦以后有人在 `push 1` 前插入读标志的指令就会炸。

⇒ **建议**：洞1 加 `pushfd`（洞首）/`popfd`（`push 1` 之前），代价 +2 字节。

### ★ 可吸收 #2：补丁元数据（工程规范）

它的补丁头带机器可校验的元信息：

```
#@risk mode critical_preview_f_inject
#@risk engine_sha256 8ddacee0ea74e28b45b51ddf2aec6aae08a067da2faf57d7723e8fbfc2c602a2
#@risk preimage 0x004E8000 0000…（整段前像，全 0 = 空洞）
#@risk new_cave 0x004E8000 len=0x200 reservation=0x200 boundary=0x20
```

⇒ 我们的补丁文本只有 `# 原字节: …`（逐段），**没有**：
- 目标 `engine_sha256`
- 洞的 `len / reservation / boundary`（预留空间与对齐）

**价值**：`reservation` 能防"以后扩写洞时踩到后面的代码"；`boundary` 能防"洞起点不对齐"。
⇒ 建议给 `_应用补丁通用.py` 加这两个可选头字段，缺省不影响现有补丁。

## 二、`6.5辅助五维单特技` —— 位序处理手法对照

### 它的实现

```asm
0x407326  E9 54 31 01 00   jmp 0x41A47F
0x41A47F  50              push eax
0x41A480  6A 00 6A 00 6A 00    push 0,0,0
0x41A486  68 FF 00 00 00   push 0xFF              ; 查特技号 0xFF
0x41A48B  E8 FF AC 00 00   call 0x42518F          ; 返回 effect 值（位图）
0x41A490  85 C0            test eax,eax
0x41A492  74 0D            jz  0x41A4A1
0x41A494  8B 4D 08         mov ecx,[ebp+8]        ; 位索引 i
0x41A497  D3 E8            shr eax,cl             ; ★ effect >> i
0x41A499  83 E0 01         and eax,1              ; 取第 i 位
0x41A49C  D1 E0            shl eax,1              ; ×2（它是"每项+1点"的量纲）
0x41A49E  01 45 FC         add [ebp-4],eax
0x41A4A1  58              pop eax
0x41A4A2  8B E5 5D C2 04 00   ret 4
```

### 对照我们的 0x0C 位掩码

```asm
; 洞1 @0x4748A0（0x0C 效果洞）
0x4748DD  89 F0            mov eax,esi          ; 掩码（已 and 0x3F）
0x4748DF  D3 E8            shr eax,cl           ; ★ 同一手法
0x4748E1  A8 01            test al,1            ; 取第 i 位
0x4748E3  74 0D            je  next
0x4748ED  E8 2F 4F F9 FF   call 0x409821        ; 破坏第 i 项
```

**结论**：**位序处理手法相同**（都是 `shr eax,cl` + `test/and 1`），
差别只在"取出置位后做什么"：
- 它：`shl 1; add [ebp-4]`（累加到返值）
- 我们：`call 0x409821`（逐项调用引擎的破坏函数）

⇒ **没有可吸收的**，我们已经是等价写法。

### ★ 但有一处**位宽差异**要注意

| 补丁 | 位数 | 全开值 |
|---|---|---|
| `6.5辅助五维单特技` | **5 位**（攻防精敏士）| `0x1F`(31) |
| `策略破坏能力` | **6 位**（攻防精爆士移）| `0x3F`(63)，另 `0x40`=64 随机 |
| **我们的 0x0C** | **6 位**（攻防精爆士移）| `0x3F`，映射到 `0x41/42/44/48/50/60` + `0x7F` 全开 |

⇒ 我们的 `0x41..0x60` 是"**0x40 前缀 + 位**"，而外部补丁直接用"裸位"（1/2/4/8/16/32）。
**两种编码都成立**（我们用 `0x40` 前缀是为了和"随机模式 `0x01~0x3F`"划界）。
⇒ **无需改**，但要在文档里写清"我们为什么加 `0x40` 前缀"（否则以后看外部补丁会以为我们错）。

## 三、`【star6.6x】策略破坏能力` —— 多目标循环可参考

它的主体（`0x42E3B0`）里有：

```asm
0x42E3B0  6A 01            push 1
0x42E3B2  6A 00            push 0
0x42E3B4  8B 55 FC         mov edx,[ebp-4]
0x42E3B7  FF B2 06 05 00 00  push [edx+0x506]     ; ★ 目标列表（+0x506）
0x42E3BD  E9 A9 4C FF FF  jmp …
```

⇒ **`ctx + 0x506`** 是它的"目标/单位列表"入口。

**对照我们**：我们用 `[ebp-0x28]`（单个目标记录）。
⇒ 若将来要做"多目标预览"（一次预览显示多个目标是否斩杀），它这个 `+0x506` 值得查一次。

## 四、吸收建议（按性价比）

| 优先级 | 吸收项 | 来源 | 代价 |
|---|---|---|---|
| **P0** | 洞1 加 `pushfd/popfd` | 暴击预览-F | +2 字节，零风险 |
| **P1** | 补丁头加 `engine_sha256` / `new_cave len+reservation+boundary` | 暴击预览-F | 改 `_应用补丁通用.py`，可选字段 |
| **P2** | `ctx+0x506` 目标列表（为多目标预览铺路） | 策略破坏能力 | 需先验证 |
| — | 位序 `shr/and` | 五维单特技 | 已等价，无需 |
