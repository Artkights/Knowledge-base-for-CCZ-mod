# 破坏MP攻击：改造成「特效值控制」

样本：`复刻版6.6山贼\Ekd5.exe`（本轮复核 SHA256 `92D80A82F743F2E239E13F97FA30B198D4DDA5DDDA41B02E8EA47B260A9660D0`）
外部参考：`[本地盘]\qq\qq群\破坏MP\破坏MP（代码版）.txt`（SHA256 `0442B3FE03E23CE66EA57A74F7FEA2CE48197B1B0DBD69F64949657659276F47`，1999 字节）

## 结论速览

- 本工程**已经内置**「破坏MP」补丁：hook `0x405FB0` → 代码洞 `0x40CC73` → 查询桩 `0x40CCA1`（装备号 `0x4A`、个人号 `0xB3`）。
- 原状是**清空对方全部 MP**：桩里 `call 0x4101D9` 拿到特效值后没有使用，而是 `call 0x472840` 取目标的**当前 MP**当破坏量。
- ✅ **当前生效版本（v3，钳制版）**：把桩尾段 `0x40CCBF` 起 28 字节重写为
  `test eax,eax / je / push eax / mov ecx,[ebp+8] / call 0x472840 / pop edx / cmp eax,edx / jae / mov edx,eax / mov eax,edx / mov esp,ebp / pop ebp / ret 8`。
  - 特效值 = N（>0）→ 破坏 **min(N, 目标当前 MP)** 点 MP（不够就扣到 0，**不再回满**）；
  - 特效值 = 0 **或没有该特技** → 完全不触发（不清 MP）。
- ❌ **失败方案 A（已实机复现，勿再用）**：`0x40CCC1` 的 `74`(je) → `75`(jne)。原因：`0x4101D9` 对「没有该特技」和「有特技但特效值为 0」**都返回 0**，把 `je` 反成 `jne` 会让**没有特技的人**掉进 `call 0x472840` 分支 → **全体普通攻击都清空对方 MP**（用户 2026-10-13 03:45 报告）。
- ❌ **失败方案 B（已实机复现）**：只做特效值、不做钳制 → 特效值大于目标当前 MP 时 MP 变负，引擎随后把它按上限拉回 → **实机现象：目标回满蓝**（用户 2026-10-13 03:54 报告）。
- 时间线：`03:42` 失败方案 A（`7C43BBB2…8955AE` → `0BA86D6E…640FA4`）→ `03:52` 纯特效值版（`16839CC8…D4CF0B`）→ `03:55` **钳制版 v3**（→ `916DF2A5…EFD7F39B`，备份 `Ekd5.exe.bak_before_bmpclamp_20261013_035500`）。
- 补丁文件：`大鲸鱼产生专用/【6.6山贼】破坏MP攻击-特效值化.txt`（v3，单条 `-40CCBF` 指令，含两段踩坑说明与回滚点）。
- **事实更正**：`0x472840` = `movzx eax, word ptr [ecx+0x14]`，读的是 `unit+0x14` = **当前 MP**（见 `02-数据结构/单位结构体.md`）；库内多处旧注写「MP 基值 / MP 上限」是误标，本页据此改用「当前 MP」。
- ⚠️ 附带发现（已按用户纠正）：桩里的**装备号 `0x4A` 属「宝物特效空间」（表 A `0x9D800`）= 禁忌破法**（不是个人特技表 B `0x9E800` 的「辅助防御力」——两张表同名 id 含义不同）。物品 `ID38 梨花开山斧` 的特殊效果号正是 `0x4A`，实机确认**会**连带触发破坏MP，**用户已决定保持现状、不改**。同一空间 `0x4A` 还被桩 `0x472C41` 共用，详见下文「两个特效号空间」一节。

## 适用版本

- 仅适用复刻版6.6山贼当前样本及其后续同源构建；改前必须确认 `0x405FB0`/`0x40CCA1` 两处原字节与本页一致。

## 已确认事实

### 三段结构（本工程实测字节）

```asm
00405FB0: E9 BE 6C 00 00            jmp 0x40CC73

0040CC8A: 8B 55 FC / 8B 4D F4      mov edx,[ebp-4] / mov ecx,[ebp-0xC]
0040CC8D: 89 84 91 54 02 00 00      mov [ecx+edx*4+0x254],eax    ; ★ 写入 MP 伤害数组

0040CCCB: 8B E5 / 5D / C2 08 00    mov esp,ebp / pop ebp / ret 8

0040CCC3: 50                        push eax          ; 保存特效值

0040CCD5: 8B E5 / 5D / C2 08 00    mov esp,ebp / pop ebp / ret 8
```

> 参数按 `4101D9` 的 ABI 取**最后四次 push**：`[ebp+8]=个人特效号(0xB3)`、`[ebp+C]=装备特效号(0x4A)`、`[ebp+10]=叠加标志(1)`、`[ebp+14]=效果值标志(0)`；桩首那个 `push 0` 落在 `[ebp+18]`，不被读取，末尾 `mov esp,ebp` 会把它丢掉（见 `01-核心引擎/桩函数.md`、`01-核心引擎/调度函数.md`）。

- `0x4101D9` 返回 EAX = **特技效果值**（0 同时表示「没有该特技」和「效果值为 0」——**两者不可区分**，这是本条最重要的边界）。
- `0x472840` = `movzx eax, word ptr [ecx+0x14]` = 读 **`unit+0x14` 的当前 MP**（WORD，不做符号扩展/裁剪）。库内旧注把它写成「MP 基值 / MP 上限」是**误标**；它正是目标的当前 MP，也正是 v3 钳制所用的上限来源。对照：`0x41B500` = `mov eax,[ecx+0x10]` = 当前 HP（DWORD）。
- MP 伤害数组 `ctx+0x254` 在本工程被多处读取/累加，例如 `0x405FB0` 原位、`0x406012`（`add [eax+edx*4+0x254],ecx`）、`0x4059A5`、`0x405E08`、`0x4062C2`；因此桩返回什么，最终就扣多少 MP（**注**：`0x406012` 是累加写入，见「风险与边界」的多段命中条目）。

### 两个「特效号空间」必须分清（2026-10-13 用户纠正）

本工程 `Ekd5.exe` 里有**两张并列的 255×16 名称表，相距正好 `0x1000`**，同名 id 含义完全不同：

| 表 | 基址（文件偏移 / VA） | 用途 | `0x1C` | `0x3D` | `0x49` | `0x4A` | `0x55` | `0xB3` | flag 列 |
|---|---|---|---|---|---|---|---|---|---|
| **A** | `0x9D800` / `0x4CB800` | **宝物（装备）特效名表** | 猛击强攻 | 辅助格挡 | 逆境减伤 | **禁忌破法** | 策略反伤 | B3空效果 | 全 `0x00` |
| **B** | `0x9E800` / **`0x4CC600`** | **个人特技名表** | 辅助策略命中 | 洗髓易筋 | 辅助攻击力 | **辅助防御力** | 万夫莫敌 | **破坏MP攻击** | 有值（`0x02/0x04/0x05`） |

- 表 A 与 `CCZModStudio_Reports` 的 **Item 渠道目录逐条一致**（0x1A 横戈跃马、0x1B 深谋远虑、0x1C 猛击强攻、0x3D 辅助格挡、0x49 逆境减伤、0x4A 禁忌破法、0x4B 步兵克制、0x55 策略反伤、0xB3/B6 空效果）→ 表 A 就是**宝物特效空间**。
- 表 B 与工具的 **PersonalJob 渠道**一致（0xB3 破坏MP攻击、0xB6 自身治疗强化）→ 表 B 是**个人特技空间**。
- 因此：**宝物特效号 `0x4A` = 禁忌破法**（用户编辑器里 038 梨花开山斧 的「特殊效果 4A 禁忌破法」就是这个空间）；**个人特技号 `0x4A` = 辅助防御力**。二者不可混用/互换。

破坏MP 桩的两个渠道分别落在两个空间：`[ebp+C] = 0x4A` 属**宝物特效空间**（禁忌破法），`[ebp+8] = 0xB3` 属**个人特技空间**（破坏MP攻击）。

物品表里“实际特效号 = `0x4A`”的条目：`ID 38 梨花开山斧`（`+0x12 = 0x4A`）、`ID 233 e9`（`+0x12 = 0x03` 类别标记，实际特效号取 `+0x11 = 0x4A`）。

⚠️ 与之相关的两点（待实机确认，不是结论）：

1. 既然桩的装备渠道用的就是宝物特效空间，**梨花开山斧（特殊效果 4A）按此口径会满足该渠道**，从而一起触发破坏MP；不想要这种连带就采用变体③（装备号改 `0`，只留个人渠道）。
2. 同一空间里 **`0x4A` 还被另一个桩 `0x472C41` 使用**（`push 1 / push 1 / push 0x4A / push 0x11 / call 0x4101D9`，库内旧记录把它记作「随机状态攻击」）→ 说明 `0x4A` 这个宝物特效号在本工程被至少两个桩共用，存在 id 复用迹象，同样建议实机确认。

## 风险与边界

- **装备渠道**：装备号 `0x4A` 属**宝物特效空间**（表 A `0x9D800`）=「禁忌破法」，物品 `ID38 梨花开山斧` 正引用它；实机确认**会**连带触发破坏MP，用户已决定保持现状（同空间 `0x4A` 还被桩 `0x472C41` 共用）。
- **`0x4101D9` 的返回值无法区分“没特技”和“特效值 0”**：任何“用返回值当开关再倒转条件”的改法都会波及没特技的单位（失败方案 A 即此）。要做这种区分必须另调布尔型查询（`9BBFE4`/调度函数通道）。
- **必须钳制**：引擎对 MP 伤害数组的结算是 `MP -= damage`，当结果为负时会被后续逻辑按上限拉回（实机表现为“回满蓝”，失败方案 B）。因此**任何把伤害量做成可配置的改动**都要照 v3 那样取 `min(伤害, 目标当前 MP)`。
- **多段命中仍可能溢出（待验证）**：`0x406012` 是累加写入（`add [eax+edx*4+0x254],ecx`），若同一次行动内同一目标被多个 破坏MP 命中（引导、连击等），各自按“命中瞬间的当前 MP”钳制后累加，总量理论上仍可能超过当前 MP。当前 `特效值` 常见为个位数，实际风险低，但若以后把特效值调大需要复测。
- **叠加标志**：桩里为 1（不可叠加）——个人与装备两个渠道只取其一，与 `桩函数.md` 的参数表一致；不要为了别的目的改它。
- 本页结构分析基于静态字节复读 + 用户实机验证（三次应用、两次修正）；`0x4101D9` 的返回值语义沿用库内既有结论，未做动态断点。

## 说明显示方式（已改为「05 显示为效果值」）

「显示效果」不是独立的表，而是**名称表每行第 16 字节（flag）**；引擎 `0x428350` 把 flag `dec` 后查格式串表 `0x462274[flag-1]` 生成说明文本。因此改显示 = 改那一个字节。

| flag | 格式串 | 显示效果（工具口径） |
|---:|---|---|
| `0x00` | 空串 | 00 不显示特殊效果值 ← **改造前** |
| `0x01` | `"+%d"` | 01 显示为 + 效果值 |
| `0x02` | `"+%d%%"` | 02 显示为 + 效果值 % |
| `0x03` | `"-%d%%"` | 03 显示为 − 效果值 % |
| `0x04` | `"%d%%"` | 04 显示为 效果值 % |
| **`0x05`** | **`"%d"`** | **05 显示为 效果值 ← 现在** |
| `0x06` | `"%d次"` | 06 显示为 N 次 |

- 位置：**个人特技名表 `0x9E800 + 0xB3*16 + 15`** → 文件偏移 `0x9F33F` / VA `0x4CD13F`，`0x00` → `0x05`。
- 效果：挂 `0xB3` 的人物在说明里直接显示特效值数字（如 `10`），配合「破坏 min(特效值, 当前MP) 点 MP」一眼可见。
- 未动：宝物特效名表（`0x9D800`）里 `0x4A 禁忌破法` 的 flag（保持 `0x00`），所以梨花开山斧的说明显示不变。
- 完整 flag 机制与其它取值样本见 `能力辅助特效值编码.md`「说明文字机制」节。
