# 死亡退场与清槽链 —— view=3 的唯一入口 `0x441744`

## 结论速览

1. **`view(+0x0C)=3` 的唯一静态写入点 = `0x443120`；唯一写 `3` 的调用者 = `0x44181F`（⊂ `0x441744`）**。全 exe `xref 0x443120` 只有 3 个调用者：`0x44181F`(3) / `0x442761`(1) / `0x442B3B`(2)。
2. **`0x441744` = 阵亡/退场执行器（`ret 8`）**：入口门禁 `cmp byte [ecx+0xC],2 / jne 0x441890` ⇒ 只有 `view==2` 的单位才会执行；否则静默返回。
3. **攻击链内部没有置 3 的指令**：攻击后判死发生在攻击分发 `0x43DB23` **返回之后** —— `0x439413 → 0x439466 call 0x43DB23 → 0x439470 call 0x4065D9 → 0x4065E7 call 0x42BC14 → 0x42BC1C call 0x40502B → (view==2 && HP==0) → 0x441744`。
4. **`0x40502B` 是唯一"按 HP 判死"的入口**：槽 `0..0xFA`，`0x4061F9` 取单位，`[+0xC]==2`，`0x41B500`（HP）==0 ⇒ `push 0/0; call 0x441744`。
5. **`0x426BA0` 只加击杀数，不处理阵亡**：`cmp byte [0x505FDC],0 / jne skip / inc word [eax+0x35]`。
6. **剧情/撤退路径也会置 3**：`0x45B771`（`ret 0xC`，唯一调用点 `0x41480E` ⊂ 剧本处理器 `0x414790`）内部 `0x45B82B call 0x441744`，与 HP 无关 ⇒ **不能单用 `view==3` 判死**。
7. **判据**：在场可操作 = `view==2`；死亡 = `HP==0 && view==3 && DataID != 0xFFFF`。
8. **`0x441744` 尾部不是单纯清引用，而是"死者绑定清理 + 控制方复位"**：遍历所有槽，把 `unit+0x08`（绑定槽号）指向死者的单位解除绑定（写 `0xFF`），并把其 `unit+0x0E`（控制方）从 `0`/`4` 复位为 `1`。
9. **补丁含义**：要"攻方已死就不再结算" ⇒ 在 `0x435829` 洞入口加 HP/状态前置门；**不要**在攻击链里拦 `0x441744` 或死亡结算（会破坏 `0x42BC14` 的全槽一致性）。

## 适用版本

- 现读 `Ekd5.exe` SHA256 `C1F7A827D7E3575E5D7772055D00003B392DE3F192409F9B0A11B9BB420C008D`（= 基底 + 执天之行 v32 + 转移策略 `0x6F` v10）。

- 6.5 / 6.4 资料不得套用。

尾部还有一次 `0..0xFA` 槽扫描（`0x441847`–`0x44188F`），语义 = **"死者绑定清理 + 控制方复位"**：

- 对每个槽 `0x4061F9` 取单位 → `0x41C457` 读 `unit+0x08`（**绑定槽号**，`movzx eax, byte [ecx+8]`，`ret`）→ 与死者的 `unit+0x04`（**槽号**）比较；
- 命中 ⇒ `0x443140(0xFF)`（`mov [ecx+8], al`，`ret 4`）：**解除该单位对死者的绑定**；
- 再读 `0x425AD0` = `unit+0x0E`（**控制方**）；值为 `0` 或 `4` 时，`0x442669(1)`（`al<=7` 才写，`ret 4`）把控制方**复位为 `1`**。

字段定名依据：

| 字段 | 定名 | 证据 |
|---|---|---|
| `unit+0x04` | 战场槽号（dword） | `0x435829` 用它压 slot 参数；`0x4061F9(cl)` 用槽号反查单位 |
| `unit+0x08` | **绑定槽号**（`0xFF` = 未绑定） | 写入者只有 `0x443140` 两个调用点：`0x426357`（`0x42632C` 把 `0x456079(id)` 找到的**另一个单位的槽号**写进来）、`0x44187C`（死亡清理写 `0xFF`）；读取者 `0x41C457`（真实调用点 `0x441857` 死亡清理、`0x459561` 读绑定+控制态） |
| `unit+0x0E` | **控制方**（`7` = 玩家；`1`/`3` = 敌方；库内旧称"AI 方针"） | setter `0x442669` 只接受 `al<=7`；`0x4073D3` 写 `7`、`0x4073ED` 写 `1`；全库大量 `cmp [unit+0x0E],7` |

- **绑定建立器 `0x42632C(unitA, id)`**：`0x456079(id)` 遍历槽 `0..0xFA` 找到匹配单位 B（`0x45F670` 取比对标量），返回 B 的 `+0x04` 槽号，再写进 A 的 `+0x08`；唯一调用点 `0x459E1C`（⊂ `0x459D95`）。
- ⚠ **不要和 `person+0x08` 混**：`person` 记录（`[0x4CEA00]+Data号×0x48`）的 `+0x08` 是 **GBK 名字**；本页说的是 `unit` 记录（`0x4A7B20+slot×0x30`）的 `+0x08`，两者不是同一结构。

### 3. `0x441744` 的 6 个调用者（现读 `xref` 与库内一致）

| # | 调用点 | 所属函数 | 协议 | 定性 |
|---:|---|---|---|---|
| 1 | `0x405050` | `0x40502B` | 逐槽扫描 | `view==2 && HP==0` ⇒ 判死（**唯一"按 HP 判死"入口**） |
| 2 | `0x417C45` | `0x417BF2` | `ret 8` | 策略结算后判死（前置 `0x426B33`==2 且 ≠8） |
| 3 | `0x44EF2B` | `0x44EEE5` | `ret 4` | 剧本状态机（尾部 `jmp 0x47B800`） |
| 4 | `0x44EF4F` | `0x44EEE5` | `ret 4` | 同上，第二处 |
| 5 | `0x45A7F2` | `0x45A7A2` | `ret 0x10` | 阵亡公共 API（前后 set/clear `+0x0D` bit `0x80`） |

### 5. 判死扫描 `0x40502B`

```

00405030  mov  ecx, [ebp-4]        ; slot = 局部字节
00405033  cmp  cl, 0xFA

0040504C  push 0 / push 0
```

- `xref 0x40502B` 现读 **2 处**：`0x42BC1C`（原生）+ `0x45827C`（转移策略 v10 洞体 `0x458000+0x300`，**非原生**）。
- 换补丁后必须重扫 `xref`，不能把 MOD 洞的调用点当引擎入口。

### 6. HP 写入与击杀数

- HP setter `0x43F6DB`：两个写点 `0x43F701 mov [edx+0x10],eax`、`0x43F70C mov [ecx+0x10],edx`，`ret 4`。它是**写入器，不是伤害公式**。
- 击杀数 `0x426BA0`：`cmp byte [0x505FDC],0 / jne 0x426BB0 / inc word [eax+0x35]`。
  `0x4037F0 → 0x4290C8 → 0x4290F2 → 0x426BA0` 是原生死亡结算里的 +1；它**不置 view、不清槽**。

### 7. 剧情 / 撤退路径 `0x45B771`（清槽）

- `0x45B771`（`ret 0xC`）内 `0x45B82B call 0x441744`；`xref 0x45B771` 现读**唯一调用点 `0x41480E`**（`0x414790+0x7E`，剧本处理器）。
- 库内定性：按阵营区段 `0x00/0x14/0x3C/0xFA` 做阵亡 + 空槽迁移；与 HP 无关。
- ⇒ 战斗结束后 `view==3` 数量会大于实际阵亡数；剧情离场/撤退也走同一条置 3 通道。

### 8. 判据与伪阳性

- 在场可操作 = `view==2`（唯一正向判据）。
- 死亡 = `HP==0 && view==3 && DataID != 0xFFFF`（三条件）。
- 伪阳性：`0x429FAD` 的 `mov [edx+0xC], al` 写的是队伍/阵列结构的槽号，不是 `unit+0x0C`。

## 实现·使用方法

1. **按引擎标准退场**：`HP=0` 后调 `0x441744`（`ret 8`，两个参数都传 0）；必须在受击/飘字动画之后调用 —— v4 在伤害结算里直接 `HP=0 + call 0x441744` 出现瞬退；v5/v9/v10 改为 wrapper 先 `0x4251BD` 再退场。
2. **攻方已死时不再出手**：在 `0x435829` 洞入口读 `word HP==0`（或 `0x426B33` 结果），直接跳回 `0x43DB52`；参数由调用方唯一的 `add esp,8` 清理。
3. **禁止**手写 `[unit+0x0C]=3`：v3 已否证 —— 绕过 `0x441744` ⇒ HP=0 但死亡动画/清理没走 ⇒ 残尸。
4. **不要**在 `0x42BC14` / `0x40502B` 全槽扫描里拦 `0x441744`：会破坏全槽一致性。

## 风险与边界

- `0x441744` 门禁 `view==2`：`view==1`（未登场）时静默返回，不报错也不置 3。
- 当前样本 `0x40502B` 的第二个调用点来自转移策略 v10 洞体，属 MOD 代码；不可当原生链路引用。
- `0x45B820` 附近工具线性反汇编有错位（`FC 00 75 0C`），以 `xref` 的 `E8` 落点为准。
- 地址随 SHA 变动，引用前现读；本页数值仅对 `C1F7A827…` 负责。
