# 中毒物理易伤：实现尝试总账与结论（2026-10-16）

> **现行结论（L1）**：`03-机制详解/特技-中毒物理易伤-现行结论.md`（当前样本未安装；v12 链尾方案与失败边界见本页）。
> 目标功能：**目标单位处于中毒时，其受到的物理伤害 ×1.2**。中毒判定以 2026-10-17 权威为准：**`[+0x1E] & 0xC0` 非零**（旧稿的 `bit4=0x10` 是错的，`0x10` 是混乱第 1 档）。
> 本文汇总 6 次实现尝试的**证据、结论与失败边界**，供后续接手者避免重复踩坑。

## 结论速览

1. **干净样本（`2A555B0B…`）**：推进 3 轮次存活 ✅（基线对照）
2. **v6 / v6b / v6c / v6d**（挂 `0x405DE1` 内两处，改伤害槽）：**每个轮次必崩** ❌（多次复现）
3. **v7**（挂 MOD 易伤函数 `0x4E6000` 内的 `0x4E6052`）：推进 4 轮次存活 ✅，但
   **该分支命中 0 次**（`0x4E6000` 只在"评估值 ≥100"时被调用，实测 `0x43BDA0` 命中 12 次而 `0x4E6000` 0 次）⇒ **无效果**
4. **v8**（挂公式出口 `0x43BF1C`）/ **v9**（挂 `0x43BF0E`）/ **v10**（挂公式中段 `0x43BE2E`）：
   均为"改 `0x43BC5A` 函数体"⇒ **表现不稳**
   * **v10 已取得可靠判定**：**无调试器**环境下，推进 **1 个回合**即进程终止（单次完整调用、无中止、无调试器）❌
   * v8/v9 **未取得可靠判定**（当时有调试器在场或命令被中止）
5. **★ 失败边界（本次最有价值的结论）**：
   **只要在物理伤害公式 `0x43BC5A` 的函数体内做 inline hook，游戏就会在推进回合时终止**；
   不做修改（干净版）或改在别的函数（v7）则稳定。
   ⇒ 该函数**大概率被多条路径共用、或内部多条 `jmp` 旁路共享寄存器/栈不变量**，
   inline 改动会破坏未覆盖到的路径（其 6 条旁路：`0x43BD06→0x43D3B5`、`0x43BDC7→0x43F1E8`、
   `0x43BE7C→0x43EAC3`、`0x43BEA0→0x4E3124`、`0x43BEE8→0x43EA4F`、`0x43BF0E→0x43BC2F`）。
6. **尚未尝试的低风险路线**：
   * **全局百分比插槽 `0x500C48`**：引擎自有的"某特技设值 → 公式读它乘算"机制（读取点 `0x43BE3A`），
     可在"目标中毒"时把 20 写进该字节（**一处内存写入，不新增 hook**）；
   * **改现有立即数 / 替换现有桩效果**（用户举的 7 个例子全是这种形态）；
   * **装备挂特技 `0xF6`（※物理易伤）**：零代码，但绑装备而非绑中毒。

## 风险与边界（本次踩过的坑，全部有现场）

1. **`tool call aborted` 会连带杀掉前台工具启动的游戏子进程** ⇒ "进程消失"≠"游戏崩溃"。
2. **调试器操作会改变行为**：附加后游戏可能停在输入法 TLS 回调；**在暂停态 `breakpoint_delete_all`
   或 `debug_stop` 会让进程消失**，从而污染"崩溃"判定。⇒ 判"补丁是否崩"**必须无调试器**跑。
3. **`0x43BF1C` 不能挂**：其原始字节 `8B 45 FC 59 EB 02`，5 字节 `E8` 会吃掉 `0x43BF20` 的跳转偏移。
4. **回跳落点后面若紧跟 `TEST EAX,EAX`**，注入函数必须**先 `PUSH EAX` 再 `POP EAX` 还原**
   （v10 第一版漏了 ⇒ 覆盖了前一条 CALL 的返回值）。
5. **临时脚本崩溃会生成半成品补丁文本** ⇒ 曾把 582 字节错误内容写进洞区；
   清洞/生成一律用**固化脚本 + 前像断言 + 写入字节数复核**。

## 🆕 2026-10-17 21:00 补充：`0x4E6000` 的**入口门**与「1 字节开关」（现样本 `9E8E1C2E…` 现读）

### 1. 门在哪（`0x43BDA0`）
```
0x43BDA0  83 F8 64        cmp  eax, 0x64        ; 评估值 == 100 ?
0x43BDA3  74 11           je   0x43BDB6        ; ★ 只在"==100"时才跳去调 MOD 易伤
0x43BDA5  ...             （否则走 0x425AD9 百分比乘算分支）
0x43BDB6  push [ebp+8] / push [ebp-0x2C] / push [ebp-4]
0x43BDBF  E8 3C A2 0A 00  call 0x4E6000        ; MOD 物理易伤结算
0x43BDC4  mov  [ebp-4], eax
0x43BDC7  E9 1C 34 00 00  jmp  0x43F1E8        ; 链尾
```

### 2. ⇒ **1 字节开关**：`0x43BDA3: 74 → EB`
- 语义：把 `je`（条件跳）改成 `jmp`（无条件跳）⇒ **每次物理伤害都进 `0x4E6000`**
- **符合 §3.6 安全判据**：只改操作码 1 字节，**不动指令边界、不动寄存器/栈契约** ✓
- 前像字节：`83 F8 64 74 11`（`0x43BDA0` 起 5 字节），改后 `83 F8 64 EB 11`

### 3. `0x4E6000` 内部在做什么（现读）
```
0x4E6003  push 0 / push 1 / push 0 / push 0xC4 / push 0xFF / push 0xFF / push 0
0x4E601D  mov  ecx, [ebp+0xC]            ; 攻击者
0x4E6020  call 0x4E0000                   ; MOD 通用"查特技"助手（id 由参数传入）
0x4E6025  test eax, eax / je 0x4E605B     ; 查不到 ⇒ 直接返回
0x4E6032  call 0x4E008F                   ; 再算
```
而 `0x4E0000` 是**参数化**的：
```
0x4E0004  push [ebp+0x20] / [ebp+0x1C] / [ebp+0x18] / [ebp+0x14]
0x4E0010  call 0x4101D9                   ; ★ 用传进来的 id 查特技
```
⇒ 即：**现有 MOD 物理易伤 = "目标/攻击者带某特技(0xC4等) ⇒ 按百分比加伤"**，与"中毒"无关。

### 4. ⇒ 实现「中毒 +20% 物理易伤」的两条可行路线（都不碰 `0x43BC5A` 体内）

| 路线 | 做法 | 风险 | 依据 |
|---|---|---|---|
| **A（推荐）** | ① `0x43BDA3` 改 `74→EB`（1 字节）让 MOD 块每次都被调用<br>② 把 `0x4E6000` 的判定从"查特技 0xC4"换成/加上"**目标中毒位**"：`mov al,[目标+0x1E] / test al,0x10 / jz 返回0`<br>③ 20% 用既有 `imul`+钳 ≤100 的写法 | **中**：改的是 `.text3` 的 MOD 块（`0x4E6xxx`，属"替换现有桩效果"，用户口径认可），**不在崩溃边界函数 `0x43BC5A` 体内** ✓ | 失败边界页第 5 条；§3.6 |
| **B（保守）** | 不改门；在"目标中毒"时把 `20` 写进全局百分比槽 `0x500C48` | **低（写入）/ 但可能无效** | 该槽读点 `0x43BE3A` 位于"攻击者带 `0x19` 冲锋攻击"分支内 ⇒ **普通攻击不读**。另发现 `0xE1` 的 `0x460142` 也读该槽，**是否在普通物理链上待确认** |
| C（无代码） | 装备挂 `0xF6 ※物理易伤` | 极低 | 但**绑装备不绑中毒** ⇒ 不满足"中毒才 +20%" |

### 5. 中毒位判定（库内既有口径）
- **目标单位记录 `+0x1E` 的 bit4 = `0x10`** 表示中毒

## ✅ 2026-10-17 21:20 权威口径：`+0x1E` 异常状态**位布局**（用户给出 + 探针实测印证）

> 用户原话：「**正常：0 ／ 麻痺：1、2、3 ／ 禁咒：4、8、12 ／ 混亂：16、32、48 ／ 中毒：64、128、192**
> **異常狀態計算：狀態對應數據相加**」

### 1. 位布局（每个状态占 **2 bit**，取值 1/2/3 = 三档，0 = 无）
| 状态 | 十进制取值 | 十六进制 | 位掩码 |
|---|---|---|---|
| 正常 | 0 | `0x00` | — |
| **麻痺** | 1 / 2 / 3 | `0x01` / `0x02` / `0x03` | **`& 0x03`** |
| **禁咒** | 4 / 8 / 12 | `0x04` / `0x08` / `0x0C` | **`& 0x0C`** |
| **混亂** | 16 / 32 / 48 | `0x10` / `0x20` / `0x30` | **`& 0x30`** |
| **中毒** | 64 / 128 / 192 | `0x40` / `0x80` / `0xC0` | **`& 0xC0`** |

### 2. 「相加」= 各字段并存（不是进位相加）
例：中毒(第1档 `0x40`) + 混乱(第1档 `0x10`) = **`0x50`**；
中毒(第3档 `0xC0`) 就是 `0x40 + 0x80` 两位同时置 ⇒ **仍是"中毒"，不是两种状态** ✓

### 3. ⇒ 中毒判定（唯一正确写法）
```asm
mov  al, byte [目标 + 0x1E]
test al, 0xC0          ; 中毒 = 高 2 位任意置位
jz   无毒
```
- ✅ `0x41`（毒+麻痺）⇒ `& 0xC0` = `0x40` ⇒ 判"有毒" ✓
- ✅ `0x0F`（禁咒+麻痺）⇒ `& 0xC0` = 0 ⇒ 判"无毒" ✓

### 4. 🔴 本条推翻库内旧口径
旧口径说「`+0x1E` 的 **bit4 = `0x10`** 是中毒」—— **错**：`0x10` 其实是**混亂的第 1 档**。

### 5. 探针实测印证（2026-10-17 21:17，现样本 `9E8E1C2E…`）
- 用户确认「447 枪将2（敌军）中毒」⇒ 现读 **slot 97 / `0x4A8D50` / 记录头 `bf 01 00 00` = 447 / 阵营(0x0F)=2 / HP(u16@0x10)=762 / `+0x1E` = `0xC0`** ✓ 与"中毒第 3 档 = 192"完全吻合
- 全表 250 个非空槽中 `+0x1E` 只有两种取值：**`0x00` × 245、`0xC0` × 5**（后者全为中毒第 3 档）

### 6. 顺带确认的字段（现读实测）
| 偏移 | 含义 | 依据 |
|---|---|---|
| `+0x00` | **Data 号（u16）** | slot 97 头 4 字节 `bf 01 00 00` = 447 ✓ |
| `+0x0F` | 阵营（2 = 敌军，3 = 我军）| 447 为敌军 ⇒ 2 ✓ |
| `+0x10` | **HP（u16）** | 447 = 762 ✓（旧记录把 `+0x10` 当成单字节 HP，应改为 u16）|
| `+0x11` | 类别 | 447 = 2 |
| `+0x1E` | **异常状态字节**（见上表）| ✓ |

## ✅ 2026-10-17 21:22 补充：**持续回合数会影响中毒的值**

> 用户原话：「**持续回合数也会影响中毒的值**」

### 1. 含义
中毒字段（高 2 bit）的取值 `64 / 128 / 192` **不只是"强度档"，还与剩余回合数相关**：
- 回合数越少 ⇒ 值越小（`0xC0 → 0x80 → 0x40 → 0x00`）
- 归零即解除

### 2. ⇒ 对实现的影响：**判定逻辑不变，反而更稳**
```asm
mov  al, byte [目标 + 0x1E]
test al, 0xC0        ; ← 只看"非零"，与剩余回合数无关
jz   无毒
```
- 剩 1 回合（`0x40`）、2 回合（`0x80`）、3 回合（`0xC0`）**都能判出"有毒"** ✓
- 毒解除瞬间变 `0x00` ⇒ 立刻不再加伤 ✓
⇒ **"中毒 +20% 物理易伤"用这一条判据就够**，不必区分回合档 ✓

### 3. 若以后想按剩余回合做"递增强度"
- 档位 = `(值 >> 6) & 3` ⇒ 1/2/3（0 = 无毒）
- 例：`0xC0>>6 = 3`（3 回合）、`0x80>>6 = 2`、`0x40>>6 = 1`
- 可与 20% 组合成"每回合 +6.7%"之类（本需求不需要）

### 4. 与实测的一致性
探针当时读到的 5 个中毒单位 **全部是 `0xC0`**（= 剩 3 回合档）——
说明那场里它们都是"刚中毒不久"，与"回合数影响值"的说法自洽 ✓
