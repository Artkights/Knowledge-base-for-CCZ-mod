2. 特技名「转移策略」，flag `0x04`；名表行 = `0x4CC600 + 号×0x10`。

4. 范围索引 = **范围号 − 2**，但**只对 `0x0C+` 成立**（`0x00~0x0A` 直查、`0x0B` 跳过）。
   ⚠ 走 `call 0x412B30` 时**不用手做**：映射在 `0x436511` 内部（`cmp al,0x0B` / `dec eax`×2 / 查 `0x4D1400`）。
5. **★ `0x412B30` 两条硬规矩（v27/v29 全踩，这才是「完全不生效」的根因）**：
   ① arg1 必须是「`+6`=X、`+7`=Y」的指针：v24/v30 传局部坐标块 `&块`（块内 `+6/+7` 写施法者 X/Y）；
      **v31 起直接传 `[ctx+8]`（施法者记录本身，`+6/+7` 就是同一对值 ⇒ 等价，省 12 B）**；
      v29 传 `[ctx+8]-6` ⇒ 函数内 `+6` 还原成单位首地址 ⇒ 坐标读成单位号字节 ⇒ 候选表空。
   ② **候选表 `0x4AC748` 必须「算完立刻建、建完立刻用」**：v24 在目标循环内算完 xfer 后再调 `0x412B30`、紧接着读表；
      v28/v29 在循环外只建一次，中间夹了 `0x42518F`（内部跑 `0x426A07/0x41301E/0x4101D9`）⇒ 全局缓冲被冲 ⇒ 候选空 ⇒ 不减不转。
6. **击杀后「复活」已闭合（v35）**：根因 = **伤害槽两处漏钳**（`.append` 与 `.found 且 位置≥原目标数` 写完整转移量）
   ⇒ 承接者 HP 变负 ⇒ `0x40502B` / `0x426B33` 只认 `HP==0` 判不出死，负 HP 按 u16 读 ⇒ 显示「满血复活」。
   修法 = **伤害槽钳到 `min(总伤害, 承接者 HP)`**（不是 `HP-1`；飘字不绑）。详情见 §六。
7. **★ 承接者阵营 = 与「施法者」同阵营，且必须在「施法者自己的策略范围」内（用户口径 2026-10-28）**。
   实现方式 = **调用 `0x412B30` 前把施法者记录 `+0x05` 临时 `xor 2`，返回后立刻还原**。

## 一、核心语义

> 策略命中后，把**原本打给 A 的伤害**，转移一部分或全部给**范围内的承接者 B**。

三个参数必须同时锁定，缺一个就落不了地：

| 参数 | 取值 | 做歪长什么样 |
|---|---|---|
| 谁转给谁 | 原目标 → 范围内另一单位 | 转给敌方/转给自己 |
| 转多少 | 按配置百分比，从原目标伤害扣出 | 凭空加伤害（不是转移，是增伤） |
| 什么策略不转 | 禁用策略号（默认 `0x18` 落雷）+ 单体类 | 单体策略也转 ⇒ 找不到段表 |

## 二、换号 SOP（用户点名优先）

**三处耦合，一次写完：**

| # | 位置 | 改什么 | 漏改后果 |
|---|---|---|---|
| 1 | **`0x458065`**（`6A 6F` 的立即数，1 字节；v32 在 `0x458068`、v30 及更早在 `0x458074`）| `6F` → 新号 | 功能仍认旧号 ⇒ 新号持有者不触发 |
| 2 | 名表新行 `0x4CC600 + 新号×0x10` | 名 12B(GBK) + 2B 零 + flag `0x04` | 生效但**显示「预留」/错名** |
| 3 | 名表旧行 `0x4CCCF0` | 清回「预留」（`D4 A4 C1 F4` + 12×`00`）| 旧号仍显示「转移策略」⇒ 玩家以为旧号还有效 |

**不用改**：`0x458400`（豁免策略号，与特技号无关）、挂点 `0x42365C`、洞首 `0x458000`、洞内任何指令。

**硬约束（违反会静默失效或崩）**

1. **新号必须是 1 字节（`00~FF`）**：`0x458404` 是字节参数，超过 `FF` 无处可写。
2. **不许回头改洞内指令换号**（`68 imm32` / 原地改写 `push` 等）—— 那是改指令边界，违反 §3.6.4 第 1 条红线。
3. **新号必须未占用**：先 dump 名表确认该行为「预留」/全零，并确认没有别的特技在用这个号。
4. **不许只改一处**（见上表）。

**四步执行**

```
① 现读名表全部行 → 选「预留/全零」且 1 字节可写的号，现读该行 16B 作前像
② 前像断言三处：`0x458064` 现须 = `6A 6F`；旧行 `0x4CCCF0` 现须 = `D7 AA … 04`；新行现须 = 预留
③ 同一次 safe_write_exe 写三处
④ 写后复读三处 + `_改动总账.py`；进游戏确认：持新号者触发、旧号不触发、名表显示正确
```

## 三、触发链规则（照做，不必自写）

1. **范围不自写段表**：用 `0x412B30` → `0x436511` 生成候选 `0x4AC748`（`FF` 终止）。
2. **承接者伤害写 `ctx+0x108 + 4×列表位置`**（下标是列表位置，**不是单位槽号**）。
3. **飘字单独排**：`0x44FB73(slot, 值, 0x12, 0x18)`。**"钳制"与"飘字显示"是两件事**，
   不要像当年 v6→v7 那样绑在一起。
4. **挂点 `0x42365C`** = 伤害**写入器**收尾（不是结算器），在这里动手伤害还没进 HP。
5. **单钩原则**：只挂 `0x42365C`；要挂第二处必须先解释为什么单钩不够。

## 五、禁止项（红线，别试）

1. **门控到 `0x87`** —— 错号，旧 v3~v18 的根因。
2. **手写 `[unit+0x0C]=3`** —— 绕过原生退场 ⇒ 残尸。
3. **在伤害结算里过早 `HP=0 + call 0x441744`** —— 飘字/受击没播完 ⇒ 瞬退。
4. **`pushad` 出口不 `lea esp,[ebp-0x3C]`** —— 寄存器读成局部变量 ⇒ 跳数据区闪退。
5. **"钳伤害槽 ≤HP"** —— 引擎 `0x422999` 已钳，这是**空操作**，不要再做。
6. **用 `68 imm32` 换号** —— 破坏 `call`（见 §2）。
7. **单位号 `==0` 判空槽** —— 空槽是 `0xFFFF`，刘备的单位号就是 0。
8. **阵营读 `+0x0F`** —— 阵营在 `+0x05`（我军 = 0）。

## 六、击杀「复活」：根因已定案，修法已在装

**根因（`转移策略0x6F-击杀退场-失败史整合与根因定案.md` §3.7，静态现读 + 库内实机观测）**

- 引擎 `0x4229F0 call 0x41B500 / sub eax,[ebp-0x14]` **无下限** ⇒ 伤害槽大于 HP 时 HP 变负。
- `0x40502B`（收尸）要求 HP **严格 `== 0`**（`0x405048 test eax,eax / jne`）；`0x426B33` 也只判 `HP==0` + 状态位 8 ⇒ **负 HP 判不出死**。
- HP 字段按 `u16` 读（`0x407272 movzx eax,word [ecx+0x1B]`）⇒ 负 HP 显示成巨大值 = 「原地满血复活」。
- 分派器 `0x42269C` 只负责扣血/飘字，**不负责收尸**；收尸靠上层 `0x417BF2 → 0x417C3E`（`0x426B33==2`）或行动结束 `0x42BC14 → 0x40502B` ⇒ 只要 HP 恰好归 0，原生链就会收。

**修法（v35 在装，`0x45817C` 起）**：写回的两条分支合并成一条「先钳后写」：

```
eax = 承接者伤害槽 + xfer
edx = [edi+0x20]        ; 承接者 HP（选人时快照）
cmp eax, edx / jbe 写 / mov eax, edx
写 [esi+ecx*4+0x108] = eax
```

- **不要**钳成 `HP-1`（v6 老路，会污染飘字）；飘字要显示完整 xfer 就单独用 `0x44FB73(slot, 值, 0x12, 0x18)`。
- 合并后比原实现**少 15 B**（原 `.found` 的 `cmp ecx,[edi] / jb` 分叉与重复写值被删）。

**对照物理 `0x57` 借力打力**：物理侧由引擎按 `[unit+0x10]` 钳，且调用者 `0x452907` 用 `0x47FD13(ctx+0x10+N, 新增数, 0xFF)` **把追加槽清回 `0xFF`**，不污染原始目标表。
⚠ 但**策略侧不能照搬"用完即清"**：我们的追加槽要靠 `inc byte [ebp-0xC]` 让 `0x423594` 的目标循环继续跑到它、把伤害落地；清掉就等于不转移。策略侧只需要"钳"。

**判据（若仍出现不退场）**：在那一帧读 `[unit+0x10]` —— `==1` = `0x40DA4A` 档位刷新抬升；`== maxHP` = 负值支；`HP==0 && view==2 停着不退` = 收尸链未跑。工具 `_阵亡收集链探针.py --scan`（只读）。
