# 引导攻击机制详解

## 结论速览

- 引导攻击＝物理攻击特技：击杀目标后继续攻击范围内的其他敌人，最多重复 3 次；特技参数为装备特效号 `54 (36)`、个人特效号 `24 (18)`、效果值标志 `1`（不需要效果值）、叠加标志 `1`（不可叠加）。（页内未标注基底版本与 SHA）
- 入口与循环：桩函数 `4210D0`（特技判定入口）→ 包装函数 `4212F1`（核心循环：先 call `4210D0` 判定，再 call `425B12` 初始化、call `436499` 取目标列表，每轮 call `435829` 执行攻击）。
- 三条终止条件：目标编号读到 `FF` 结束；`chain_count >= 3` 结束；目标未死结束。死亡判据只有 HP==0（`00421343` 取目标单位编号 → `00421346 call 004061F9` 转单位指针 → `0042134B call 0041B500` 读 HP → `00421350 test eax,eax`、`00421352 jnz 00421359` 存活则停 → `00421354 inc dword [ebp-14]` 死亡则继续），没有额外的“死亡标记”。
- 顶层编排 `43AAF7` 双分支：先查全局标志 `[505FDC]`、单位 `80` 标志位、游戏状态 != 4，取角色编号与坐标做相邻判定，再 call `43F8C0` 取游戏子状态；子状态 ≠ 2/3/4 → 走调用者1 `417C67`（构建目标列表后引导），子状态 = 2/3/4 → 直接调用包装函数 `4212F1`；两路汇合后 `438E78` 效果应用 → `442718` → `443AC3` 收尾。
- 目标列表与全局量：候选来自全局数组 `[500E9D]`（`417C67` 遍历后标记 `FF` 终止符），`417C67` 入参为 `[ebp+08]`＝参数1（单位编号）、`[ebp+0C]`＝攻击者单位指针、`[ebp+10]`＝目标数量上限；配套 `500E9A`＝阶段/列表标志（**1 字节槽**，写点 byte/word 混合）、`500E9C`＝实际目标数量（**独立 byte**）、`500E9D`＝目标单位数组（**byte 项，`FF` 终止**）、`501BF9`＝行动类型标志（设为 6）。**四者相邻但相互独立，不构成 dword 结构** —— 宽度权威表见 `00-总览与规范\待验证清单.md` 的「2026-10-26 N1」节。
- 行动分发入口 `43DADA`：行动分发器 `43DEE2`（switch，al==1＝物理攻击）调用它，流程为 `44533D` 取目标单位 → 坐标操作 `435829` → 前置条件检查 `4363DC`、`4061F9`、`41B500` → 调用包装函数 `4212F1` → 后处理 `438E78`、`442718`、`443AC3`；轻量查询入口为 `423BD7`（只判断单位是否拥有该能力）。

## 详细记录

#### 概述

**引导攻击**是一种物理攻击特技，其效果为：攻击击杀目标后，继续攻击范围内的其他敌人，最多重复3次。

| 个人特效号 | 24 (18) |

#### 核心函数详解

##### 桩函数 - 4210D0

特技判定入口，向调度函数传递参数。

##### 包装函数 - 4212F1

引导攻击的核心循环执行器。

**伪代码**：

```c
int wrapper(Unit* attacker) {
    if (!has_ability(attacker))    // call 4210D0
        return 0;
    
    init();                        // call 425B12
    target_list = get_list();      // call 436499
    
    chain_count = 0;
    while (true) {
        target = *target_list;
        if (target == FF) break;         // 列表结束
        
        execute_attack(target);            // call 435829
        chain_count++;
        
        if (chain_count >= 3) break;       // 最多3次
        
        if (!target_is_dead(target)) break; // 目标未死则停止
        
        target_list++;                      // 下一目标
    }
    return chain_count;
}
```

遍历全局数组 [500E9D] 中的候选目标，验证有效性，标记列表终止符(FF)，然后调用包装函数执行引导攻击。

#### 死亡判定

##### 判定流程

在包装函数 4212F1 的引导循环中，每次攻击后执行：

```asm
00421343: mov ecx, [ebp-10]      ; ecx = 目标单位编号
00421346: call 004061F9         ; 单位编号 → 单位指针
0042134B: call 0041B500         ; 读取 HP
00421350: test eax, eax            ; HP == 0 ?
00421352: jnz 00421359          ; HP != 0 → 存活，停止引导
00421354: inc dword [ebp-14]    ; HP == 0 → 死亡，继续引导
```

##### 判定逻辑

| HP状态 | 结果 | 行为 |
|--------|------|------|
| HP == 0 | 目标死亡 | 继续引导，攻击下一个目标 |
| HP != 0 | 目标存活 | 引导终止，停止连锁 |

> **注意**：没有额外的"死亡标记"——HP 归零本身就是死亡的唯一判据。

## ★ 补充（2026-10-16，DSH）：`0x42133D` 具体地址 + 与「奋战攻击」的同形对照

> **本页原有内容已含**：桩 `0x4210D0` → 包装函数 `0x4212F1`、`call 0x436499` 取目标列表、
> 每轮 `call 0x435829`、三条终止条件、目标数组 `[0x500E9D]` 等。
> **本次只补两条本页原先没有的**：① `chain_count >= 3` 那个判定的**确切地址**；
> ② 与「奋战攻击」的**逐项同形对照**（含两个目标数组的地址关系）。

### 一、★ 「chain_count >= 3 结束」的确切地址 = **`0x42133D`**
```asm
0x42133A  FE 45 F8      inc  byte ptr [ebp - 8]      ; chain_count++
0x42133D  80 7D F8 02   cmp  byte ptr [ebp - 8], 2   ; ★★★ 就是这个判定（现读立即数 = 2）
0x421341  73 16         jae  0x421359               ; ≥ 2 ⇒ 结束（合计 3 次：第 1 次 + 重复 2 次）
```
**⇒ 语义澄清**：本页称「`chain_count >= 3` 结束」，而**代码里的立即数是 `2`**
—— 因为计数器**从"第 1 次打完之后"开始**（`inc` 在前、`cmp` 在后）⇒ **总次数 = 立即数 + 1 = 3** ✓ 与本页描述一致。
**⇒ 推论（供改号参考）**：把立即数从 `2` 改成 `N` ⇒ **总重复次数 = N + 1**（`2`→3 次，`3`→4 次）。

**⚠ 与外部线索的差异（记录在案）**：用户提供的一份线索写作 `80 7D **E8** **03**`（`CMP BYTE [EBP-18], 3`），
而**本样本现读 = `80 7D F8 02`**（位移 `-0x8`、立即数 `2`）。**以现读为准**（§2/§3），那份大概来自别的样本或已被改过。

### 二、★★★★★ 与「奋战攻击」（`0x4363F1`）是**同一套模板的两个实例**
| 结构 | **引导攻击 `0x4212F1`** | 奋战攻击 `0x4363F1` |
|---|---|---|
| 查桩 | `call 0x4210D0`（push `1/1/0x36/0x18`）| `call 0x478E5D`（push `0/1/0x36/0x17`）|
| 不带则返回 | `test al,al` / `je 0x42135F` | `test al,al` / `je 0x436491` |
| 初始化 | `call 0x425B12` | —— |
| **取周边目标列表** | **`call 0x436499`**（返回 `eax` → 存 `[ebp-0x14]`）| **`0x500EA5` 常量** + `call 0x436499` |
| **打一次** | **`call 0x435829`** | **`call 0x435829`** ✅ 同一个 |
| **AI打分 / 预览** | **`call 0x4064F1`** | **`call 0x4064F1`** ✅ 同一个 |
| 计数器 | `inc byte [ebp-8]` | `inc dword [ebp-8]` |
| **上限判定** | **`cmp byte [ebp-8], 2` @ `0x42133D`** | **`cmp byte [ebp-8], 2` @ `0x436476`** |
| 下一个目标 | `inc dword [ebp-0x14]` | `inc dword [ebp-0xC]` |

**⇒ 三条结论**：
1. **两处上限点（`0x42133D` / `0x436476`）是**同一机制的两个实例****
2. **★★ 两个目标数组相邻**：本页记的引导数组 **`0x500E9D`** vs 奋战攻击用的 **`0x500EA5`** ⇒ **相差 8 字节** ⇒ **是两个不同的数组**
3. **★★★ `0x436499` / `0x435829` / `0x4064F1` 是两特技**共用**的** ⇒
   **改动这三个中的任何一个，必须**同时验收引导攻击与奋战攻击**（§8：`0x4064F1` 还在 AI打分/预览共用链上）**

### 三、★ 与既有补丁的关系（重要，避免误判）
**既有补丁「奋战攻击次数按特效值 v1」（`0x43646D` 15 B + 洞 `0x457E2E` 77 B）**
**⇒ 只改 `0x4363F1`（奋战），**不经过 `0x4212F1`（引导）****

## 76. ★★★ 用户口径核实：「切不同的特技号就是奋战或引导」—— **成立**；并撤回「`0x500E9B` = 当前特技号」（2026-10-16，DSH）

### 76.1 ★ 用户的记忆**成立**（硬证据）
| 特技槽第 1 字节（名表id）| **桩内号** | 桩入口 | 桩的 push | 结果 |
|---|---|---|---|---|
| **`0x17`** | **`0x36`** | `0x478E5D` | `0 / 1 / 0x36 / 0x17` | **奋战攻击** |
| **`0x18`** | **`0x36`** | `0x4210D0` | `1 / 1 / 0x36 / 0x18` | **引导攻击** |

**⇒ 区别另在 `p1`**：奋战 `p1=0`（需要效果值）、引导 `p1=1`（不需要效果值）
