# 伤害预览数值来源 —— 预览函数 `0x44049E` 全链

> **本页回答**：界面上的**伤害预览数字**到底是谁算出来的、和实战伤害是不是同一条链、
> 为什么"防御暴击 `0x24` 的减伤"在预览里看不到。
> 建立日期：2026-10-15｜证据类型：**6.6 样本离线反汇编（capstone）+ 调用点穷举**。
> 样本 SHA-256 `36694DBE208D60A0915EA9451BB6B5D575B06F2C57F6A4356B946A45EB032668`。

## 结论速览

1. **预览函数 = `0x44049E`**。它把 `单位名 / Lv / Exp / HP / MP / 伤害` 一并算好送进预览面板，
   内部字符串常量 `%s`、` Lv%2u`、`Exp`、`MAX`、`%3u`、`%4u%%` 就是面板那几行。
2. **预览的伤害数字 = `0x43BC5A`（物理伤害公式）的返回值**：
   `0x440668 call 0x43BC5A` → `0x44066D mov [ebp-0x18],eax` ⇒ 直接进面板参数。
   ⇒ **预览"算"伤害，而不是"读"伤害槽**：`0x44049E` 内**没有任何一条写 `ctx+0x84` 的指令**（0 条）。
3. **实战伤害走另一条**：`0x405DE1` 主控 → `0x405E6D call 0x43BC5A` → `0x405E9A mov [edx],eax`（写 `ctx+0x84`）
   → 之后才叠 `0x405EF9`（`0x24` 减伤）与暴击/连击/浮动。
4. ⇒ **预览 = 公式裸值**（公式之后的所有修正都不含）。这就是"预览与实战不同步"的**根因**，
   也解释了为什么把 `0x24` 减伤补丁打在 `0x405EF9` 时**界面预览数值不变**。
5. **预览会读集气**：预览用的命中率函数 `0x428925` 内部直接读 `byte [edx + ecx*4 + 0x4930C8]`
   并按 `[0x505EC8]`（= 整型 `4018`，集气模式开关）切分支 ⇒ 这就是"集气满 100 时预览变红"的实现。
6. **浮动伤害与预览无关**：`0x412C78`（浮动）只有 2 个调用点（`0x433FA5` / `0x4D280F`），
   **都不在预览链上**；取消浮动（`0x412CA1: 07→00`）**不改变预览值**。

## 适用版本

- 复刻版 6.6山贼 `Ekd5.exe`，SHA-256
  `36694DBE208D60A0915EA9451BB6B5D575B06F2C57F6A4356B946A45EB032668`（1,148,928 字节）。
- ⚠️ 6.5 的 `0x43BC62`（普罗 `ccz-LuaSkill`）与 6.6 的 `0x43BC5A` **不同址**，不得混用。

## 已确认事实

### 一、预览函数 `0x44049E` 的三条证据

**证据 1 —— 面板字符串常量**（函数体内直接 `push` 的立即数）：

| 指令地址 | 字符串 VA | 内容 |
|---|---|---|
| `0x4405E8` | `0x48E054` | `%s` |
| `0x4405FE` | `0x48E058` | ` Lv%2u` |
| `0x440B21` | `0x48E060` | `Exp` |
| `0x440B5F` | `0x48E064` | `MAX` |
| `0x440B7C` | `0x48E068` | `%3u` |
| `0x440C23` | `0x48E07C` | `%s` |
| `0x440C4C` | `0x48E080` | `%4u%%`（百分比，命中率/集气用） |

**证据 2 —— 它算伤害但只写局部变量**：

```asm

0044065E  89 4D D4         mov [ebp-0x2C],ecx
00440661  6A 00            push 0
00440663  6A 01            push 1
00440665  FF 75 D8         push [ebp-0x28]      ; 攻击者
00440668  E8 ED B5 FF FF   call 0x43BC5A        ; ★★ 物理伤害公式
0044066D  89 45 E8         mov [ebp-0x18],eax   ; ★ 预览伤害 = 公式返回值
00440670  6A 01            push 1
00440672  FF 75 10         push [ebp+0x10]
00440675  FF 75 D8         push [ebp-0x28]
00440678  FF 75 D4         push [ebp-0x2C]
0044067B  E8 A5 82 FE FF   call 0x428925        ; ★ 命中率（预览用，见第三节）
00440680  89 45 04         mov [ebp-4],eax
```

- 全函数（`0x44049E` ~ `0x440D2F`）内 **`ctx+0x84` 写入 0 条** ⇒ 预览不碰伤害槽。

**证据 3 —— 面板参数调用点**：

```asm

00440CAF  FF 75 EC         push [ebp-0x14]
00440CB2  FF 75 E0         push [ebp-0x20]

```

- `0x440C8E` 处另有一次 `call 0x440EB6`（同族的面板绘制入口）。
- `0x4131CF` 是**预览参数函数**：`0x4131F7` 起读 `[0x505EC8]`（`4018` 集气开关），
  命中时按 `0x4930C8 + 单位×4` 的**单字节**改伤害值 ⇒ **集气满时预览数值会变**。

### 二、预览链与实战链的分叉点

```
        ┌────────────────────────── 预览（只显示，不落槽）──────────────────────────┐
        │  0x44049E（预览函数）                                                     │
        │    0x440668 call 0x43BC5A  ← ★ 同一条物理伤害公式                        │
        │    0x44066D mov [ebp-0x18],eax   ← 伤害存局部，供面板显示                 │
        │    0x44067B call 0x428925        ← 命中率（内含集气表读取）               │
        │    0x440CB5 call 0x4131CF        ← 写面板参数                            │
        └──────────────────────────────────────────────────────────────────────────┘
                                        ↕ **不写 ctx+0x84**
        ┌────────────────────────── 实战（写槽 + 叠加修正）────────────────────────┐
        │  0x405DE1（物理伤害主控）                                                 │
        │    入口先清零 ctx+0x84 / ctx+0x254                                       │
        │    0x405E6D call 0x43BC5A  ← 同一条公式                                   │
        │    0x405E9A mov [edx],eax  ← ★ 写伤害槽 ctx+0x84                          │
        │    0x405EDD call 0x4287A8  ← 暴击/集气判定                                │
        │    0x405EF0 call 0x42AA2A  ← 0x24 防御暴击谓词                            │
        │    0x405EF9 ← ★ v5/v6 减伤补丁点（按 (100-V)/100 改小 ctx+0x84）          │
        │    0x405F17 mov [eax+0x604],1 ← 暴击标志                                 │
        │    0x404A77（物理飘字）读的正是 ctx+0x84                                 │
        └──────────────────────────────────────────────────────────────────────────┘
```

**⇒ 预览拿到的是公式裸值；`0x24` 减伤、暴击倍率、连击、浮动全都在公式之后 ⇒ 预览一概不含。**
这与库内实机结论完全吻合（"指向目标看预览"既不执行 `0x405DE1` 结算段、也不写 `ctx+0x84`）。

### 三、预览用的命中率函数 `0x428925`（★ 新增，含集气）

```asm
00428925  55                 push ebp
00428926  8B EC              mov ebp,esp
00428928  8B 45 14           mov eax,[ebp+0x14]
0042892B  D1 E8              shr eax,1                        ; 参数5 / 2 → 跳转表索引
0042892D  FF 75 10           push [ebp+0x10]
00428930  FF 75 0C           push [ebp+0xC]
00428933  6A 01              push 1
00428935  8B 4D 08           mov ecx,[ebp+8]
00428938  FF 14 85 61 89 42 00  call dword [eax*4 + 0x428961]  ; 跳转表：物理/策略命中率实现
0042893F  80 3D C8 5E 50 00 01  cmp byte [0x505EC8],1          ; ★ 集气模式开关（整型 4018）
00428946  75 15              jne 0x42895D
00428948  8B 4D 0C           mov ecx,[ebp+0xC]
0042894B  0F B6 49 04        movzx ecx,byte [ecx+4]           ; 防守方单位记录的 +4 = 战场编号
0042894F  8B 55 14           mov edx,[ebp+0x14]
00428952  38 84 8A C8 30 49 00  cmp byte [edx + ecx*4 + 0x4930C8],al   ; ★ 读集气表

0042895B  F7 D8              neg eax                          ; ★ 集气 ≥ 命中率 ⇒ 取负（语义翻转）
```

- **集气表步长确实是 4**：`edx + 战场编号×4 + 0x4930C8`，`edx = [ebp+0x14]` 是**模式/字节偏移**。
- 与 `0x4287A8`（集气判定主函数）**同一张表、同一套步长**，但这里是**预览侧**的读取。
- 调用点（本样本实测）：`0x44067B`（预览函数内）、`0x440763`、`0x44092D`、`0x440992`。

## 实现·使用方法

- **要改预览显示的伤害**：改 `0x44049E` 里 `0x44066D` 之后的 `[ebp-0x18]` 即可（**不要**去改公式本身，
  否则实战也会跟着变）。推荐做法：在 `0x44066D` 处插跳板，按与 `0x405EF9` 相同的 `(100-V)/100` 折算。
- **要核对预览**：只读断点/采样 `0x44049E` 内的 `0x44066D`（预览伤害）与 `0x405E9A`（实战写槽），
  两者之差就是"公式之后的全部修正"。
- **不要**用"指向目标看预览"来验证 `0x405DE1` 的补丁 —— 那条路径根本不执行 `0x405DE1`。

## 风险与边界

- 本页为**离线静态**结论；`0x44049E` 的 3 个上层调用者尚未做执行级区分（见待验证 P1）。
- `0x4131CF` 只有 1 个调用者，但 `0x4131F7` 处**没有直接 call**（是函数体内联代码），
  引用时按"函数体偏移"理解，不要写成"被调用的地址"。
- 预览函数在 `0x4404060F`、`0x44066F` 等地址附近有**反汇编错位的假 call**
  （`0x764307DE`、`0xAE07F4` 之类越界目标）⇒ 用线性 `md.disasm` 全段扫描会得到垃圾，必须**按函数边界对齐**再解。
- `0x428925` 的跳转表 `0x428961` 索引是 `参数5 / 2`，参数5 的取值域未闭环。

## 证据来源

- 6.6 样本 `Ekd5.exe` SHA `36694DBE…032668`：capstone 线性反汇编 + 全映像 `E8 rel32` 调用点穷举 +
  字符串常量（GBK）解码；工具 `大鲸鱼产生专用/_dsh反汇编工作台.py`（`da` / `df`）。
- 交叉：`03-机制详解/防御暴击0x24-预览减伤-现行改动状态.md`（实机：预览不写伤害槽）、
  `03-机制详解/物理伤害计算链与预览不同步.md`（实战链 5 个公式调用点）。

## ★ 2026-10-17 06:0x 更正：结论 6「浮动与预览无关」**成立** —— 我 2026-10-16 登记的"冲突"**撤回**

**上一节的"待核对冲突"现已解释清楚（以字节为准）**：

`0x412C78`（伤害浮动函数）**自身**带一道预览门：
```asm
00412C78  push ebp / mov ebp,esp
00412C7B  push 0 / push [ebp+0x10] / push [ebp+0xC] / push [ebp+8]
00412C86  call 0x408DB1
00412C8B  cmp  dword [ebp+0x14], 1       ; ★ 第 4 参 = 计算模式
00412C8F  je   0x412CCA                   ;   ⇒ 模式 == 1（预览）⇒ **跳过浮动**
00412C91  … call 0x41D716 / mov [ebp+0x10],eax
```
⇒ **预览（模式 1）时，浮动在函数内部就被跳过**，`0x4D2800` 的返回值里**不会有浮动**（我原先只看到"返回值 = `[ebp+0x10]` 槽"就推断"预览含浮动"，**漏看了这道门**）。

⇒ **正确口径（与本节结论 6 一致）**：
1. **`0x412C78` 只有 2 个调用点（`0x433FA5` / `0x4D280F`），都不在预览链上** —— 更准确的说法是：**即使它们在公式链上，模式 1 也会让浮动被跳过** ⇒ **取消浮动（`0x412CA1: 07→00`）不会改变预览值** ✓
2. 因此**不需要**再做"改 `0x412CA1` 后比预览"的判定实验（该实验的目标已由静态字节回答；如需最终确认，仍可在游戏内复核一次）。
