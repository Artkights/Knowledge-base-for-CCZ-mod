# 族名更正 与 两个大报告的细读结论（0x76 绝对克制 / 0x2F 防御远距攻击）

> 样本：`Ekd5.exe` SHA `F3455B30…`（2026-10-17 早复核，**未变**）；证据：静态反汇编（未实机）
> 起因：用户选「继续纯静态 —— 细读两个大报告」；细读过程中**发现族名与实现不符 2 处**

## 结论速览

1. **★ 族名更正 ①：`0x76 绝对克制`（域 `0x41CE8C`）实际与"绝对克制"无关**
   —— 它是 **「攻击距离/施法距离 +1」的共用查表器**：
   | 调用者 | 传入 arg | 实际查询的特技 | 个人表名 |
   |---|---|---|---|
   | `0x401E14` | **2** | **`0x5C`** | **施法距离 +1** |
   | `0x43038B`（原记"武器精通域"）| **1** | **`0x5B`** | **攻击距离 +1** |
   ⇒ **族报告里把它归到 `0x76 绝对克制` 是错的**（族名取自"同域特技群"，而该群的归属本身需复核）。
2. **★ 反查出 `0x41CDEE` 的真实语义（关键小函数）**：
   ```
   0041CDF7  mov eax,[ebp+8] / add eax,0x5B / dec eax    ⇒ 查【arg + 0x5A】
   0041CDFF  call 0x4101D9(0x76, 3, 0, arg+0x5A)
   0041CE04  and eax,[ebp+8]                             ⇒ ★★ 用 arg 当【位掩码】取位
   ```
   ⇒ 这是"**按位取某特技是否生效**"的写法（`arg` 既是 `+0x5A` 的偏移量、又是位掩码）。
3. **★ 挖出三级索引链**（`0x43038B` 内）：
   ```
   movzx eax, byte [unit+0x2E]        ; 取一个 id
   cmp eax,0xFF / je 跳过             ; 0xFF = 无
   imul eax, eax, 0x19                ; ×25 步长
   movzx ecx, byte [eax + 0x49F831]   ; 一级表
   movzx eax, byte [ecx + 0x4303C8]   ; 二级表（代码区内嵌表）
   ```
4. **★ 域 `0x41CE8C` 内嵌一张 32 字节数据表 `0x41CEAB`**：
   `01 06 03 04 12 13 0C 08 12 1F 0A 00 0D 21 0F 16 11 12 25 0C 0C 16 22 01 20 1D 03 1C 1D 23 1F 03`
   （值域 0~37）⇒ **疑为"单位/兵种类型 → 某 id"的映射表**，`arg2` 是索引基准（`0x401E14` 传的是
   `call 0x418C90` 的返回值 = **view 字节**）。
5. **`0x2F 防御远距攻击`（域 `0x47EE64`）** 是"大函数"形态：`sub esp,0x2c` + `push edi/esi` +
   `lea eax,[ebp-0x2c]` 传缓冲 → `call 0x47F36E`；随后把 `[ebp+0xC]` 存 `[ebp-0x28]`、
   `neg ([ebp+0x10]+0x10)` 存 `[ebp-0x24]` ⇒ **算"距离/偏移"的一族**（细节见 `_族-0x2F_防御远距攻击.md`）。

## 已确认事实：两处更正的前后对照

| 项 | 族报告里写的 | 细读后的结论 | 依据 |
|---|---|---|---|
| 域 `0x41CE8C` 的域族 | `0x76 绝对克制` | **攻击/施法距离加成（查 `0x5B`/`0x5C`）** | `0x41CDEE` 内 `arg+0x5A`；两个调用点分别传 `1`/`2` |
| `0x43038B` 的域族 | `0x6D 武器精通` | **同上**（它先把 `arg=1` 传给 `0x41CE8C`） | `0x43038B` 全文反汇编 |

**⚠ 但要保留一句**：`0x43038B` **后面**还有 `test eax,eax / je` + `[unit+0x2E]×0x19` 两级查表
⇒ 它**不止**做距离判定 ⇒ **它可能是"武器/兵种 → 距离加成"的复合判定**（两个族名的成分都在里面）。

## 实现·使用方法

```bat
python 大鲸鱼产生专用\_读两族细节.py      :: 读 0x76 域体 + 表 0x41CEAB + 0x2F 域体
python 大鲸鱼产生专用\_核0x41CE8C.py      :: 核两个调用点传的 arg（⇒ 实际查哪个特技号）
python 大鲸鱼产生专用\_族核心.py 0x41CDEE 0x43038B
```

**★ 复核"某域属于哪个特技"的判据（本次获得）**：
**不要只看"该域的特技群"**（那是从桩调用点推的，可能错），
要**追到"域/其调用的小函数里 `call 0x4101D9` 的 `push imm` 到底是多少"**，
并且注意 **`push` 的参数可能是 `arg + 常数`**（本次就是 `arg+0x5A`，所以"同一个小函数"会查**不同**特技号）。

## 风险与边界

* 本页**未实机验证**；"更正"来自静态反汇编 + 名表核对，**置信度高但非执行级证据**。
* `0x41CEAB` 那张 32 字节表的**索引语义未定**（是 view？兵种？地形？）⇒ 见待验证项。
* `0x4303C8` 是**代码区内嵌的二级表**（不是独立数据段）⇒ 与"`.code` 里的 `90` 洞"一样，
  **改动前必须确认它没被别的东西引用**。

* **P0**：`0x41CEAB` 32 字节表的**索引语义**（`0x401E14` 传 view 字节；`0x43038B` 传 EAX）—— 实机取样

* **P2**：`0x2F 防御远距攻击` 的 `0x47F36E`（缓冲初始化）与 `neg ([ebp+0x10]+0x10)` 的几何含义

## ★★★ 2026-10-17 补：**批量复核 39 族族名 —— 33 族一致、0 族错配、6 族待深查**；并找出 `0x76 绝对克制` 的真桩

### 一、批量复核（工具 `_族名复核.py`）

**判据**：对每族的每个域，反汇编其函数体并**跟进 1 层 `call`**（本样本桩是独立小函数），
收集所有 `push <imm>` … `call 0x4101D9/0x42518F` 的**被查询号**（含 `push imm`+`add al,imm` 算术编码的解），
再看**族名号是否在该集合内**。

| 结果 | 族数 | 说明 |
|---|---:|---|
| ✅ 一致（族名号在域的查询集合内）| **33** | 族名归属可信 |
| ❌ 错配 | **0** | —— |
| ⚠ 域内无特技查询（需深查）| **6** | `0x02` / `0x40` / `0x32` / `0x57` / `0x76` / `0x2F` |

**★ 关键**：`0x76` 落在"⚠ 域内无查询"里 —— 而这个 ⚠ **恰好就是"族名归属错了"的正确报警**
（`0x41CE8C` 域内查的是 `0x5B/0x5C`，**根本没有 `0x76`**）。

### 二、`0x76 绝对克制` 的真桩已找到

```
00413272  55 / 8B EC            push ebp / mov ebp,esp
00413275  6A 00 / 6A 01        push 0 / push 1
00413279  6A 4E                push 0x4E          ← 公共参数
0041327B  6A 76                push 0x76          ← ★ 特技号 0x76 绝对克制
0041327D  E8 → 0x4101D9        call 特技查询
00413282  5D / C3              pop ebp / ret      （17 字节，**标准独立桩**）
```
**⇒ `0x413272` = 绝对克制的桩**；全映像**只有 1 处**查询 `0x76`（就在这个桩内）。
⇒ **族报告把 `0x76` 的域写成 `0x41CE8C` 是错的**（`0x41CE8C` 实际服务 `0x5B/0x5C`）。
