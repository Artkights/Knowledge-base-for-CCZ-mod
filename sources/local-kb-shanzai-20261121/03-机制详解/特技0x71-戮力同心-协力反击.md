# 特技 0x71 戮力同心 —— 协力反击（敌军攻击友军时参战）

## 结论速览

- **语义（用户口径）**：**敌方回合，敌军攻击友方单位时，若该敌军处于本单位的攻击范围，则本单位攻击该敌军**。
- **桩**：`0x405954` = `push 0 / push 0 / push 0x58 / push 0x71 / call 0x4101D9`
  ⇒ 查 **兵种特技 `0x71`**（装备号 `0x58`），返回布尔（不带即 0）。
- **分派**：2 项函数指针表 **`0x415E2B`**
  - 项0 = `0x405942`（`0x3B 同仇敌忾` 桩）
  - 项1 = `0x405954`（`0x71 戮力同心` 桩）
  分派点 **`0x438F28`**：`call dword [eax*4 + 0x415E2B]`。
- **收集函数 `0x438EBD`**（由 `0x4223CB` 在 `0x4223A9` 的 0..2 循环里调用）：
  逐单位筛选 → 命中者 slot 追加到 **`0x500EA5`**（`0xFF` 终止）→ `0x41058D` 收尾。
- **判定链（`0x438EE6`..`0x438F5D` 现读）**：
  1. `0x418C90(unit)==2`（有效单位）
  2. `cmp ecx,[ebp+8]` 跳过攻击者自己
  3. `0x42E2B7(攻击者, 候选)` 通过（`edx==0`）
  4. `0x426B33(候选)==0`
  5. 桩返回非 0，且 `cmp cl,al`（`[unit+0x23]` 与返回值，次数门）
  6. **`0x4091F4(候选, 0x50, 2)` 计算候选单位的攻击范围**，覆盖攻击者（`cmp al,[ebp-8]`）才追加
- **结果写 `[0x4B2C28]`**（本次参与反击的单位/次数）。

### 4. 谁调用

- `0x438EBD` ← **`0x4223CB`**（唯一调用点）。
- `0x4223A9`：`mov eax,[ebp-4]; cmp al,2; jae` ⇒ **循环 0..2 三次**调用 `0x438EBD`（对应不同的索引/类型）。

## 实现·使用方法

- **只读观察**：`_周边人数探针.py --engine` 可看 `0x500EA5` 当前列表（反击参战者会被追加到这里）。
- **调试实证**：断 `0x438F28`（分派点），命中时读 `[ebp+8]`（攻击者 slot）、`[ebp-0xC]`（索引）、`[ecx]`（候选单位）、
  随后看 `0x500EA5` 是否追加了候选 slot。

## 风险与边界

- `0x500EA5` 同时被 **奋战 `0x4363F1` / 引导 `0x4212F1`** 用作“周边目标列表”；反击收集也写这里 ⇒ 三者**共用同一张表**，
  调试时要按调用栈区分是谁写进去的。
- `[unit+0x23]` 是次数门（`cmp cl,al`），语义与「戮」界面标签一致（库内已有记录）。
- `0x4091F4(候选, 0x50, 2)` 与奋战/引导用的是同一个范围构建器 ⇒ “处于攻击范围”就是引擎攻击范围，不是固定九宫格。

## 判定规则（以后一律按这个分清两个 `0x71`）

**桩的 4 个 push，位置决定字段，不能按数字对号：**

```
push A / push B / push C / push D  →  call 0x4101D9 / 0x42518F
                                   [ebp+8]=D  [ebp+0xC]=C  [ebp+0x10]=B  [ebp+0x14]=A
⇒ D（最后压的、[ebp+8]）= 个人/兵种号   ← 只有这个能拿去查 0x4CC600 名表
⇒ C（[ebp+0xC]）        = 装备渠道号    ← 不能拿去对兵种名表
```

**代码证据（`0x41301E` 现读）**：

```asm
0x413022  call 0x40BE7D
0x413028  and  dword [ebp+8], 0xff     ; ★ 只对【个人号】取低字节
0x41303E  call 0x4198BE                ; ★ 0x4198BE 内部：shl ecx,4 / add edx,ecx
                                       ;   ⇒ 把【个人号】当 16 字节行索引 ⇒ 查名表
0x413050  call 0x43C794                ; ★ [ebp+0xC]（装备号）走另一个函数，与名表行索引无关
```

`0x4198BE` 开头：`mov ecx,[ebp+8]; shl ecx,4; add edx,ecx; ... call [0x4F0008]`（DLL 侧名表/特效查询）。

## 2026-10-24 勠力同心交互闪退定案：`0x438F75` 多套一层 call 破坏了 type=0/1 的栈契约

- **现象（用户实机）**：我军单位攻击敌军、**目标旁边有带 `0x71` 勠力同心的敌军**时，攻击动画刚结束即闪退，敌军来不及反击；**没有 `0x71` 在旁边就不崩**。
- **对照 1｜排除 type=2**：把 `0x4223B2` 的 `cmp al,3` 改回 `cmp al,2`（禁用 v21 第三轮），**仍然闪退**，且策略同仇按预期不再追加 ⇒ 与 type=2 无关。
- **对照 2｜锁定 v21**：把 `0x438ECD→0x41B500`、`0x438F0D→0x42E2B7`、`0x438F4B→0x4091F4`、`0x438F75→0x41058D`、分派表 `0x431FC0→0x415E2B` 全部回滚为原生 ⇒ **不崩，敌军正常发动勠力同心**。⇒ 崩因在 v21 的钩子内，不在基底本身。
- **根因**：v21 原实现把 `0x438F75` 的 `call 0x41058D` 换成 `call 0x432010`，`0x432010` 内再 `call 0x41058D`、返回后再 `jmp 0x438F7A`。于是 **type=0/1 进入 `0x41058D` 时，栈帧比原生低 4 字节，返回地址是 `0x43201B`（原生是 `0x438F7A`）**。`0x41058D` 逐候选调 `0x435829` 执行物理攻击；`0x71` 的反击本身就是一次完整物理攻击，会经 `0x435829` 重入 `0x4223A9→0x438EBD→0x438F75`，该偏差在嵌套链里累积；崩溃形态与库内《闪退排查-战斗中后期GS栈检查失败》同型（`0xC0000409` /GS 栈检查失败）。
- **修复（1 字节）**：`0x432016` 由 `E8` 改 `E9`，把 `call 0x41058D` 压平为 **`jmp 0x41058D` 尾跳**。rel32 不变（下一条指令地址仍是 `0x43201B`，目标仍是 `0x41058D`），type=0/1 的栈布局与返回地址**与原生逐字节一致**；type=2 的策略同仇执行体（0x432020 起 `pushad…popad`）**零改动**。
- **实机判据**：写前 SHA=`BCCE082D2B80B1D7AFD38DACEFCAF79A00986C9264C49D3AE7AB05A02EADEC3A` → 写后 `7CCEA262513466476900BD5CE8EDDAFF48AF374DE643CAC305BF4BAD3D27A965`；备份 `edk5（78）修复-戮力同心闪退-EXEC压平尾跳`。用户实测：**不崩，勠力同心正常，策略同仇正常追加**。
- **同时修掉的隐藏缺陷**：type=0（`0x3B 同仇敌忾`）走的是同一条物理执行分支，此前同样带这层栈偏差，只因当前剧本无人携带 `0x3B` 而未暴露。⇒ 凡"挂 `0x438F75` 做 type 分流"的补丁，**不得用 `call` 套层，必须尾跳**。
- **未实测项**：本次未抓崩溃 EIP（对照组直接给出二分结论），"栈帧低 4 字节导致 /GS 失败"是按 A/B 结果的最小改动解释；若要逐字节证实，需在 `0x41058D` 入口下断读 `[esp]`（返回地址）与 `esp-ebp` 差值。
