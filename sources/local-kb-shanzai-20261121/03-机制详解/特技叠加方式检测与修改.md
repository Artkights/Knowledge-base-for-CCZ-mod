# 特技叠加方式检测与修改

## 结论速览

- **一个工具搞定「叠加方式」的检测与修改**：
  `大鲸鱼产生专用/_特技叠加检测.py`
- 它扫描全 exe 的**特效判定桩调用点**（`call 0x4101D9`），解析四个栈参数，
  按「人物/兵种特效号」索引，输出每个特技的**叠加方式**，并可原地改。
- 实测（本次样本）：**150 个调用点**，能静态定值 **104** 个，
  动态参数（代码洞写法）**46** 个。
- 叠加方式分布：**`0`（叠加）23 个**、**`1`（不叠加）80 个**、
  **`3`（特殊，致命一击类）2 个**。

## 适用版本

- 复刻版6.6山贼 `Ekd5.exe`（扫描时 SHA 见 `_特技叠加方式报告.md`）。
- 判定桩地址 `0x4101D9` 为引擎固定入口。

## 已确认事实

### 1. 判定桩四参数（栈序 = push 顺序）

```
push 效果值方式       ; 第 1 个 push（栈底）
push 叠加方式         ; 第 2 个 push   ← 本工具的主目标
push 宝物/装备特效号   ; 第 3 个 push（无则 0）
push 人物/兵种特效号   ; 第 4 个 push（栈顶，紧邻 call）
call 0x4101D9
```

`ECX` = 待判定单位指针；返回值 `EAX` = 开关或特效值。

| 参数 | 取值 |
|---|---|
| 效果值方式 | `0`=读配置值；`1`=只返回拥有开关 |
| **叠加方式** | `0`=个人与装备渠道**允许累加**；`1`=**不可叠加**只取一个；`2`=装备优先、未命中回退个人 |
| 宝物号 | 无则 `0` |
| 人物/兵种号 | 目标特技号 |

> 用户 2026-10-14 提供的截图标注「00 叠加，01 不叠加」与上表**一致**，互为印证。

### 2. ★ 机器码要点：小立即数用 `6A imm8`

实测 `0x405DCF` 的个人特效 `0x24` 判定桩：

```
00405DCF  55                push ebp
00405DD0  8B EC             mov  ebp, esp
00405DD2  6A 01             push 1          ; ← 6A imm8（2 字节），不是 68 imm32
00405DD4  6A 01             push 1
00405DD6  6A 00             push 0
00405DD8  6A 24             push 0x24
00405DDA  E8 FA A3 00 00    call 0x4101D9
```

**只有大于 `0x7F` 的立即数才用 `68 imm32`（5 字节）**，两种混用。
任何"从 call 反推参数"的扫描器都必须同时识别 `6A` 与 `68`，并按实际长度后退。

### 3. 样例校验（工具输出与库内既有记录一致）

| 调用点 | push 序列 | 解析结果 | 库内记录 |
|---|---|---|---|
| `0x405DDA` | `1 / 1 / 0 / 0x24` | 效果值方式=1、叠加方式=1、宝物号=0、特技号=`0x24` | 「`0x405DCF` 个人特效 `0x24` 判定桩」✓ |
| `0x44F9B4` | `0 / 3 / 0x31 / 0x33` | 效果值方式=0、叠加方式=3、宝物号=`0x31`、特技号=`0x33` | 「致命一击个人 `0x33`/装备 `0x31`，叠加方式 3」✓ |
| `0x405F3B` | `1 / 1 / 0x44 / 0x30` | 效果值方式=1、叠加方式=1、宝物号=`0x44`、特技号=`0x30` | 防御暴击洞内判定 ✓ |

### 4. ★ 同一特技号可能有多个调用点（改之前必看）

| 特技号 | 调用点 | 各自叠加方式 | 备注 |
|---|---|---|---|
| `0x24` | `0x405DDA`、`0x410FEC` | 1、1 | 一致 |
| `0x34` | `0x405CEE`、`0x4E4112` | 1、1 | 一致 |
| `0x35` | `0x4060E9`、`0x4E3017` | 1、1 | 一致 |
| `0x3A` | `0x4390C2`、`0x4E4814` | 1、1 | 一致 |
| **`0x48`** | `0x4E3081`、`0x4E31C5` | **0、1** | ⚠️ **不一致**，改之前必须先定意图 |
| `0x70` | `0x422E61`、`0x42E50E` | 1、1 | 一致 |

### 5. 另一种写法：代码洞动态参数（46 个调用点）

部分特技不在原位压立即数，而是**经寄存器/内存算出**参数，例如：

```
004039BF  8B 45 F8            mov   eax, [ebp-8]
004039C2  6A 01               push  1                     ; 效果值方式（常量）
004039C4  6A 01               push  1                     ; 叠加方式（常量）
004039C6  0F B6 88 19 7E 43 00  movzx ecx, byte ptr [eax+0x437E19]   ; 宝物号（动态）
004039CD  51                  push  ecx
004039CE  83 C0 06            add   eax, 6
004039D1  50                  push  eax                   ; 特技号（动态指针）
004039D2  8B 4D FC            mov   ecx, [ebp-4]
004039D5  E8 FF C7 00 00      call  0x4101D9
```

用户提到的另一种形态是**「转到 `4D0000` + `mov al,0e3` / `add al,0e4`」**：
特技号由 `al` 算术得出（如 `0xE3+0xE4` 之类组合）。这类调用点本工具
**标记为「动态参数」并列出，但不会去改**——要改必须编辑对应代码洞。

## 风险与边界

- **动态参数调用点不可静态改**（46/150）：需编辑代码洞；本工具只报告。
- **同一特技号多调用点**：改叠加方式会把该特技号**所有**静态调用点一起改
  （除非用 `--only <调用点>` 指定单个）。`0x48` 本来就"一 0 一 1"，改前先定意图。
- **叠加方式 `3`** 属非 0/1/2 的特殊用法（致命一击类），不要随手动。
- 写入遵守 AGENTS.md 第 3.5 节（W1~W5）：唯一入口 `safe_write_exe()`、
  三重校验、自动备份 + 复读 + 审计、写完重生成 `_改动总账.md`。
- 本结论基于**静态反汇编 + 样例校验**；改完必须实机确认叠加是否真的生效。

## 补录：代码洞「动态特技号」实测实例（2026-10-14）

用户提示的另一种写法是 `转到 4D0000 / mov al,0e3 / add al,0e4`。
本轮在样本里找到**同类真实实例**，确认这类调用点的判定桩参数不是原位立即数。

### 实例 1：`0x432559` —— 特技号由 `add al,imm8` 算出

```
00432540  55                push ebp
00432541  89 E5             mov  ebp, esp
00432543  53                push ebx
00432544  56                push esi
00432545  57                push edi
00432546  0F B6 F0          movzx esi, al                      ; al 原值存 esi
00432549  C6 05 E0 26 43 00 00   mov byte [0x4326E0], 0
00432550  6A 00             push 0                             ; 效果值方式 = 0
00432552  6A 03             push 3                             ; 叠加方式   = 3
00432554  6A 7D             push 0x7D                          ; 宝物号     = 0x7D
00432556  04 8F             add  al, 0x8F                      ; ★ 特技号 = al + 0x8F
00432558  50                push eax                           ; 特技号（动态）
00432559  E8 7B DC FD FF    call 0x4101D9
```

- **特技号 = 入参 `al` + `0x8F`**，属"由基数偏移算出"，正是 `add al,imm8` 形态。
- 本调用点**叠加方式 = 3**（可静态读出，因为在 `push` 里是立即数）。

### 实例 2：`0x405F3B` —— 参数经栈帧转发

```
00405F30  6A 01             push 1        ; 效果值方式
00405F32  6A 01             push 1        ; 叠加方式
00405F34  6A 44             push 0x44     ; 宝物号
00405F36  6A 30             push 0x30     ; 特技号
00405F38  8B 4D E0          mov  ecx, [ebp-0x20]
00405F3B  E8 99 A2 00 00    call 0x4101D9
```

`call` 与 `push` 之间**夹了一条 `mov ecx`**（传单位指针），
所以"只看紧邻 call 的字节"会数不满 4 条 push ⇒ 必须允许中间插入 `mov ecx,[...]`。

### 实例 3：`0x403A34` —— 叠加方式由条件决定

```
00403A16  8B 45 F8          mov  eax, [ebp-8]
00403A19  3C 02             cmp  al, 2
00403A1B  74 04             je   0x403A21
00403A1D  6A 01             push 1                ; 条件 A：叠加方式 = 1
00403A1F  EB 02             jmp  0x403A23
00403A21  6A 00             push 0                ; 条件 B：叠加方式 = 0
00403A23  6A 01             push 1
00403A25  0F B6 88 1F 7E 43 00  movzx ecx, byte ptr [eax+0x437E1F]
00403A2C  51                push ecx
00403A2D  83 C0 0D          add  eax, 0xD
00403A30  50                push eax
00403A31  8B 4D FC          mov  ecx, [ebp-4]
00403A34  E8 A0 C7 00 00    call 0x4101D9
```

**叠加方式在运行期二选一**（`al==2` 则 0，否则 1）⇒ 静态无法定值，必须实机判定。

### 实例 4：`0x4D2828` —— 注入函数（代码洞）内的判定

`0x4D2800` 是一个注入函数（`push ebp; mov ebp,esp` 开头），函数体内连续做多次判定：

```
004D2803  FF 75 14          push [ebp+0x14]
004D2806  FF 75 10          push [ebp+0x10]
004D2809  FF 75 0C          push [ebp+0xC]
004D280C  FF 75 08          push [ebp+8]
004D280F  E8 64 04 F4 FF    call 0x412C78            ; 先算实际值
004D2814  89 45 10          mov  [ebp+0x10], eax
004D2817  6A 00             push 0                   ; 效果值方式
004D2819  6A 01             push 1                   ; 叠加方式
004D281B  68 68 00 00 00    push 0x68                ; 宝物号
004D2820  68 AC 00 00 00    push 0xAC                ; 特技号 = 0xAC
004D2825  8B 4D 08          mov  ecx, [ebp+8]
004D2828  E8 AC D9 F3 FF    call 0x4101D9
```

后续同族判定（同一函数内）：`0x4D285D`（宝物 `0x4B`/特技 `0xAE`）、
`0x4D2892`、`0x4D28C7`（宝物 `0x4B`/特技 `0xAF`）、`0x4D28FC`（宝物 `0x1D`/特技 `0xB0`）。
这类**能静态读出**，因为参数是 `push imm`，只是在**注入函数体内**而非引擎原代码里。

### 对工具的修正（重要）

本轮曾尝试"回溯注入函数的调用者、用调用者压栈的立即数冒充本调用点参数"，
结果**产出一个错误值（叠加方式 255）**。已撤销该逻辑：

- 参数不是原位立即数时，**一律标为「未知」并给出线索**（所在注入函数地址、调用者数量、
  紧邻 call 前是否为 `al` 算术）；
- **不猜值** —— 错误值会让使用者做出错误修改，比"未知"危险得多。

### 45 个未定值调用点的分类

| 类型 | 特征 | 能否静态定值 |
|---|---|---|
| 立即数分散在 push 中 | `push imm` ×4（可能夹 `mov ecx`） | ✅ 能 |
| 注入函数体内判定 | `push imm` ×4，但在 `0x432xxx`/`0x4Dxxxx` 注入区 | ✅ 能 |
| 特技号由 `al` 算术算出 | `mov al,imm` / `add al,imm` → `push eax` | ❌ 需知道 `al` 入参 |
| 参数经栈帧转发 | `push [ebp+0xNN]` | ❌ 需回溯调用者 |
| 条件决定叠加方式 | `cmp/je` 后分两路 `push` | ❌ 运行期二选一 |
