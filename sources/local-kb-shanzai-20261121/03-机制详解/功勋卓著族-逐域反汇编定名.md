# 功勋卓著（0x45）族 · 逐域反汇编定名

> 样本：`Ekd5.exe` SHA `F3455B30…`（= 干净 `2A555B0B…` + 奋战攻击 v1）
> 证据类型：**静态反汇编 + 全映像调用者反查 + 函数入口归位**（未实机）
> 起因：用户「特技的反汇编还有哪些没做」→「继续吧」⇒ 啃第一族（工单里的最大族：7 个域）

## 结论速览

1. **这族的机制一句话**：**功勋卓著 = 单位带特技 `0x45` 时，把该特技的效果值加成写进「功勋表」的某一维**
   （功勋表 `0x508000 + 人物号×10`，每人 **5 个 WORD**：武力/统率/智力/敏捷/运气）。
2. **★ 本族真正的"加成写入"只有一处**：**`0x42AB8E`**（`ret 0x10`，4 参数）——
   7 个域**全都是它的调用者**（实测 **8 个调用点，归位后正好落在那 7 个域里**）。
   ⇒ **改一处即可改全族行为**。
3. **另有 2 个共用辅助**：
   * **`0x42ACD2`** = 「**取功勋记录指针**」`f(人物号, flag)`：`人物号 ≥ 0x66` 或人物记录 `+0x2A == 0xFF` ⇒ 返回 `AL=0xFF`（无效）；
     否则返回 **`&功勋表[人物号]` = `0x508000 + 人物号×0x0A`** ✅（与库内"每人 10 字节"完全吻合，`imul edx,eax,0xa` 即实证）
   * **`0x477ADC`** = 「**按 view 扫单位**」`f(key)`：先 `call 0x40B922`（`byte[0x4AC63C]==3` 分流），
     再循环 **slot 0..0xFA**，每轮 `call 0x4061F9`（取记录）+ `call 0x418C90`（**view 门禁**，读 `[ecx+0xC]`）
4. **7 个域的分工 = 「功勋在哪些场合结算」**（因为功勋在物理/策略/技能/回合结束等多处都会加）。

## 已确认事实：7 个域逐个定名

| 域 | 被本族调用的位置 | 定名（依据） |
|---|---|---|
| **`0x42A96D`** | `call 0x42ACD2`@`42A97D`；`call 0x42AB8E`@`42A990`/`42A9B9`（**一个域内调 2 次**）| **【某结算阶段结束时的功勋结算】** —— 其 `0x42A995~0x42A9AD` 明确比较 **`ctx+0x84`（物理伤害数组）** 与 **`ctx+0x254`（MP 伤害数组）** 是否为 0 ⇒ 判"本次攻击是否已结算/是否有伤害" |
| **`0x40DC5C`** | `call 0x42ACD2`@`40DC65`；`call 0x42AB8E`@`40DCA5` | **【移动/行动类结算】**（入口形态简洁，取 `[ecx+4]` 作人物号）|
| **`0x411892`** | `@41189D` / `@4118AC` | **【一个独立小流程内的功勋结算】** |
| **`0x422DDE`** | `@422DE6` / `@422DF5` | **【一个独立小流程内的功勋结算】** |
| **`0x42A9C4`** | `@42A9C9` / `@42A9E7` | **【紧随 `0x42A96D` 的第二个结算点】** |
| **`0x42AA0B`** | `@42AA10` / `@42AA21` | **【紧随其后的第三个结算点】** |
| **`0x46206C`** | `@4620EF` / `@462102` | **【另一处结算点】**（本族最靠后的域）|

**⇒ `0x42A96D` / `0x42A9C4` / `0x42AA0B` 三个域地址相邻（`0x42A96D`→`0x42AA0B`，跨度仅 0x9E）**
⇒ 很可能是**同一个大函数里的三段功勋结算**（不同条件各加一次），建议后续按"一个函数三段"合并理解。

## 已确认事实：核心函数 `0x42AB8E` 的完整契约

```
0x42AB8E  f(加成值 [ebp+8], 属性系数 [ebp+0xC], 单位指针 [ebp+0x10], slot [ebp+0x14])   ret 0x10
 0042AB97  cmp byte [unit + slot*2 + 0x21], 0xFF
 0042AB9C  jae 返回           ← ★ 该字节 ≥ 0xFF ⇒ 直接返回（此单位"没有这一维功勋"？）
 0042AB9E  edx = [ebp+0xC] + slot*2                 ← ★ 功勋记录指针（结果写回处）
 0042ABA1  shl eax,1                                ← slot*2
 0042ABA5  push edx / 0 / 1 / 0x1E / 0x45
 0042ABAE  call 0x42518F                            ← ★ 特技查询：特技 0x45 功勋卓著、参数 0x1E(30)
 0042ABB3  ecx = [ebp+8]                            ← (a) 默认加成 = arg1
 0042ABB6  cmp byte [0x500E9A], 1                    ← LIST_BUILD_FLAG（目标列表构建标志）
 0042ABBD  jne 0x42ABD6                             ← 不在"构建中" ⇒ 走默认
 0042ABBF  cmp byte [0x505FDC], 0 / je 0x42ABD3      ← (b) 该标志为 0 ⇒ **加成 ×2**（imul ecx,ecx,2）
 0042ABC8  cmp byte [0x505F5C], 0 / je 0x42ABD6      ← (c) 该标志为 1 且前者非 0 ⇒ **整段跳过**（不记功勋）
 0042ABD6  eax = 特技值 + ecx                        ← key = 特技查询结果 + 加成值
 0042ABD8  push eax ; call 0x477ADC(ecx=slot)        ← ★ 按 view 扫单位，取"该给谁记"
 0042ABE6  cmp byte [eax + 0x501B00], 0 / je 跳过      ← ★ 查 `0x501B00` 表：只有该项非 0 才真正加
 0042ABEF  ecx += [ebp+8]                            ← 累加
 0042ABF3  add word [edx], cx                         ← ★★ **写功勋：WORD[功勋记录] += cx**
```

**三个全局标志的库内既有口径**：
* `0x500E9A` = **`LIST_BUILD_FLAG`**「目标列表构建标志（1=构建中/0=完成）」（库内 `02-数据结构/全局变量.md`、`03-机制详解/引导攻击.md`；xref 实测 23 处引用）
* `0x505FDC` / `0x505F5C` = **未定名**（本族判据首次用到）⇒ 见待验证项
* `0x501B00` = **一张表基址**（`[eax + 0x501B00]` 查表）⇒ 很可能就是**功勋表/人物表**的伴生表；未定名

**★ 函数入口归位的判据（踩过的坑）**：从调用点向前找 `55 8B EC` 后，校验必须允许
**"解码出的某条指令覆盖调用点"**（`ins.address <= va < ins.address + ins.size`）；
我第一版用严格 `ins.address == va` ⇒ **8 处全"未定位"**。

## 风险与边界

* **未实机验证**：以上全部为静态反汇编 + 调用者反查。功勋是否真的按此累加、`0x501B00` 表是什么，需实机取样。
* **`0x505FDC` / `0x505F5C` 的语义未定**：它们决定"加成 ×2"与"整段跳过"，是**行为开关**，
  改这两个字节可能显著影响功勋节奏 ⇒ 动之前必须先实机读值。
* **本族只覆盖 7 个域**；`0x42ACD2` 还有 **6 个域外调用者**（`0x410C39` / `0x41D238` / `0x4224D4` /
  `0x423EAD` / `0x42AB32` / `0x456CB4` / `0x456DA6`）也在读写功勋表 ⇒ **功勋体系不止这 7 个域**。

## 待验证项

* **P0**：实机确认"带 `0x45` 的单位在哪种结算后功勋 +N"（断点 `0x42ABF3` 读 `[edx]` 与 `cx`；**前提 `4018=1`**；
  对照组 = 不带 `0x45` 的单位）
* **P0**：`0x505FDC` / `0x505F5C` 的语义（决定"×2"与"跳过"）；`0x501B00` 表的起始与项含义
* **P1**：`0x42A96D` / `0x42A9C4` / `0x42AA0B` 是否**同一个大函数的三段**（三域地址相邻，跨度仅 0x9E）
* **P1**：`0x42ACD2` 的 6 个域外调用者（`0x410C39` 等）属哪一族 ⇒ 补齐功勋体系全图
* **P2**：`0x42AB8E` 里 `cmp byte [unit + slot*2 + 0x21], 0xFF` 的语义
  （疑与状态字节 `unit+0x1E` 附近的 2-bit 字段布局有关，见 `02-数据结构\异常状态位定义.md`）
