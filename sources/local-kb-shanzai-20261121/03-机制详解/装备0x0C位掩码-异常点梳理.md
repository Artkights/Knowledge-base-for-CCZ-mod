# 装备/个人特技 0x0C 位掩码补丁 —— 异常点梳理与结论

> 样本 SHA256：`ACB5C3733E5D7E5E98FF96402520D7FBA4310B256B2C1C3E8B9AED7F8F89FEC1`（**补丁未装**，两段现字节均为原样）
> 被审对象：`大鲸鱼产生专用\未注入的过程补丁\【6.6山贼】装备0x0C固定组合位掩码-同步策略版.txt`（2 段 / 112 B）
> 证据类型：补丁字节用 capstone 反汇编 + 与原函数（当前 EXE 未装态）逐条对照 + 全 `.code` `E8` 扫描；**未实机验证**

## 结论速览

1. **致命缺陷：代码洞里的 `call 0x436392` 是错的，应为 `call 0x436334`（整整偏了 `+0x5E`）。**
   `0x436392` 落在 `0x436391: E8 CD 0E FD FF`（`call 0x40658F`）的**操作数中间**，从那里解码出来是 `int 0x0E`
   ⇒ 只要 0x0C 效果真的执行，就会进异常 ⇒ **这份补丁装上会崩**（这也是它当初"预演全绿、复读一致"却没人敢用的原因）。
2. **个人特技没有"另一套"实现**：0x0C 的桩 `0x472D5C` 四参数是 `(个人号=0x0C, 装备号=0x5E, 叠加=1, 需求效果值=0)`
   ⇒ **个人特技 0x0C 与装备特技 0x5E 共用同一个处理函数 `0x472D6E`** ⇒ 位掩码改造对**两条来源都生效**，
   不存在"只改了装备、个人还是老的随机"。
3. `0x472D6E` 全样本**唯一调用者 `0x405A32`**，且调用后**不使用返回值 EAX**（下一条就 `mov ecx,[ebp-0x24]` 重设）
   ⇒ 洞实现的返回值差异无影响。
4. 其余语义差异（0x40=随机一项 vs 原来"随机 N 项不重复"）是**设计变更**，不是 bug；但 **`>0x40` 的取值未定义**
   （如 `0x41` 会落到"只破坏攻击"，因为只测 bit0..bit5）。
5. 结论：**这份补丁不能原样用**。要用必须先把 `E8 E2 1A FC FF` 改成 `E8 84 1A FC FF`（目标 `0x436334`），
   再重算/复读，并做"触发 0x0C 不崩"的实机判据。

### 二、为什么之前会"合并"

原实现的思路是**直接替换 0x0C 的处理函数 `0x472D6E`**（`0x405A32` 唯一调用点），
而 `0x472D6E` 正好是"随机破坏能力"的执行体 ⇒ 一替换就把随机行为了吃掉。
这不是"新增一个特技"，是"改写既有特技" —— 方向错了。

### 三、分开的两种做法（待用户选）

| 方案 | 做法 | 风险 | 工作量 |
|---|---|---|---|
| **A：效果值扩展**（推荐） | 保留 0x0C 原样（`01~06` = 随机 N 项）；新增语义 `0x41~0x7F` = 位掩码固定组合（低 6 位）。洞入口先判 `cmp al,0x40 / jae 位掩码分支`，否则跳回原函数 | **低**（只改洞 + 入口 jmp，原逻辑完整保留） | 小（一次生成 + 预演） |

### 四、分派链现状（方案 B 的前置调研，已做了一部分）

- `0x405A32 call 0x472D6E` 的上下文是**条件链**，不是表跳转：
  ```

  0x4059BE  cmp al,1
  0x4059C0  jae 0x405A7D          ; [0x500C44] >= 1 ⇒ 走另一分支（末尾 call 0x40CD54）
  0x4059C6/0x4059CC  cmp [ebp-0x14],0 / [ebp-0x18],0

  0x405A24  call 0x40399F
  ```

## ✔ 方案 A 已实装（2026-10-18 10:55）：随机与固定**并存**

> 用户口径：「一个处理固定的，一个照样随机」→ 选定**效果值扩展**方案（同特技、两种模式，互不干扰）。

### 一、行为矩阵（现在生效）

| 效果值 | 行为 |
|---|---|
| `0x01~0x06` | **原版随机**：随机破坏 N 项（N=效果值，不重复）—— 原函数体完整保留 |
| `0x40` | 随机破坏 **1 项** |
| `0x41~0x7F` | **固定组合**：低 6 位位掩码（`01`攻/`02`防/`04`精/`08`爆/`10`士/`20`移） |
| `0x00` | 不破坏 |

### 二、实现（122 字节洞 @ `0x4748A0`）

```asm
0x472D6E  E9 2D 1B 00 00      jmp 0x4748A0            ; 入口 5 字节
; --- 洞内 ---
0x4748A0  55 89 E5 6A 00 51                          ; 复刻原前段（[ebp-4]=0, [ebp-8]=ecx）
0x4748A6  6A 0E FF 75 08 E8 .. call 0x436334          ; 原函数同款前置判定
0x4748B4  8B 4D F8 E8 ..    call 0x472D5C            ; 双渠道取 0x0C 效果值
0x4748C0  0F B6 C0           movzx eax,al            ; ★ 规范化（避免高位垃圾）
0x4748C3  3C 40              cmp al,0x40
0x4748C5  72 45              jb 0x47490C             ; ★ <0x40 ⇒ 回原随机逻辑
0x4748C7  89 45 F4           mov [ebp-0xC],eax
0x4748CA  83 F8 40 / 75 14   cmp eax,0x40 / jne 位掩码
0x4748CF  6A 06 / E8 ..      push 6 / call 0x47FB13   ; 0x40 ⇒ 随机一项
0x4748DC  E8 ..              call 0x409821
0x4748E3  ...                ; 位掩码循环 i=0..5，逐位 call 0x409821
0x47490C  8B 45 F4           mov eax,[ebp-0xC]
0x47490F  E9 7A E4 FF FF     jmp 0x472D8E            ; ★ 回原函数继续（随机 N 项）

```

## ★★★ 2026-10-18 11:27 修掉一个真 bug：**位掩码被自己的 `push` 覆盖**（现象：「0x43/0x7F 实际都只破坏攻」）

> 用户实测：文本显示正确（`0x43`→破坏攻防、`0x7F`→破坏全能力），**但实际效果都只破坏"攻"**；HP/MP 辅助说明正常。

### 一、根因（栈帧算错）

旧洞（102 字节版）的栈帧只有 **8 字节**：

```
push ebp / mov ebp,esp / push 0（[ebp-4]）/ push ecx（[ebp-8]）
⇒ esp = ebp-8
```

然后它把位掩码存在 **`[ebp-0xC]`（= ebp-12）**：

```asm
0x4748C7  and eax,0x3F
0x4748CC  mov [ebp-0xC],eax      ; ← 存掩码
...
0x4748E5  6A 00                  push 0        ; ← 写到 ebp-12 = 覆盖掩码！
0x4748E7  FF 75 FC               push [ebp-4]  ; ← 写到 ebp-16
0x4748ED  E8 ..                  call 0x409821
```

`push` 从 `esp` 向下写 ⇒ `ebp-12`/`ebp-16` 正是**调用 0x409821 的临时参数区**。
所以：**第 1 轮（i=0）读掩码是对的（破坏攻），一 push 就把 `[ebp-0xC]` 写成 0，之后所有轮次掩码都是 0 ⇒ 再也不会破坏别的项**。
⇒ 无论填 `0x43` 还是 `0x7F`，结果都只剩"攻"被破坏 —— 与用户实测完全一致。

### 二、修复（新洞 99 字节）

1. 栈帧多推 4 字节：`push 0 / push ecx / **push esi**` ⇒ `esp = ebp-12`，临时参数区下移到 `ebp-16/-20`；
2. **掩码改存 `esi`**（`mov esi,eax` / `mov eax,esi`），不再用 `[ebp-0xC]`；
3. `push esi` 是必须的：原函数（`0x472D8E` 之后）不会保存 `esi`，我们改它就得自己保护；
4. 正常出口 `pop esi` 再 `mov esp,ebp`；走原逻辑分支时直接 `jmp 0x472D8E`（原函数末尾 `mov esp,ebp` 会丢弃我们压的 esi，且我们没改过 esi 的值，安全）。

```asm
0x4748A0  55 89 E5 6A 00 51 56        push ebp / mov ebp,esp / push 0 / push ecx / push esi
0x4748A7  6A 0E FF 75 08 E8 ..        call 0x436334（原前置判定）
0x4748B5  8B 4D F8 E8 ..              call 0x472D5C（取 0x0C 效果值）
0x4748C1  0F B6 C0 3C 40 72 2F        movzx / cmp al,0x40 / jb 0x4748F7（回原逻辑）
```

### 四、教训（通用）

**在注入代码里用栈槽存跨 `call` 的临时值之前，必须先算清楚 `esp` 在哪、`push` 会写到哪。**
