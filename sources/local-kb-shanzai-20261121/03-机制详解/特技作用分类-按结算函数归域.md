# 特技作用分类：按「所在结算函数」归域

> 样本：`Ekd5.exe` SHA `F3455B30…`（= 干净 `2A555B0B…` + 奋战攻击 v1 补丁；补丁只改 `0x43646D`/`0x457E2E`）
> 证据类型：**静态反汇编** + **调用者反查** + **函数归域**
> 触发：用户 2026-10-16「反汇编每一个特技的作用，狠狠查它调用的地方」→「开工」→「继续」

## 结论速览

1. **★ 判定「特技作用」的系统方法（本次确立）**：
   > **桩本身只是「取该特技的数值」（`0xFF` = 没有）；真正的作用在「哪个结算函数里调用了这个桩」。**
   > **⇒ 看一个特技的桩在哪个函数里被调用，就知道它属于哪一类作用。**
2. **★ 形态实证**（`0x43CDDD` 内，`0x43CE20` 一带）：
   ```
   call <桩>              ; 取该特技的数值
   call 0x425AD9          ; 百分比乘算
   add  [ebp-x], eax      ; 累加到某个结算量
   …
   call 0x423FA1          ; 钳制/收尾
   ```
   ⇒ **桩返回的是「数值」而非布尔**（`0xFF` = 没有）—— 这解释了为什么多数桩"只做查一下就 `ret`"。
3. **归域结果（本样本现读）**：**254 个桩调用点，落在 136 个函数里**；产出
   `大鲸鱼产生专用\_特技作用-分组.md`（19 KB）。
4. **前 14 个"结算函数"**（按调用点数）：

### ★ 判一个特技"作用"的五步（本次确立的流程）
1. `_特技桩映射.json` 按名字/名表id 找到 ⇒ 桩内号 + 桩入口 + 判定点
2. `_特技作用-分组.md` 找它的桩落**在哪个函数** ⇒ **该函数就是它的结算域**
3. 反汇编那个函数里**调它前后**的代码 ⇒ 看 `call 桩` 之后是否 `call 0x425AD9`(乘算) + `add [局部],eax`(累加)
4. 追那个**局部变量**最终写到哪个**绝对字段** ⇒ 就是它改的东西
5. 若该函数在 §8 名单上（如 `0x4064F1`）⇒ **改动必须做预览/实战双路径验收**

## 风险与边界

1. **归域不完整**：有 **37 个调用点归到 `0x?`**（向上找不到 `55 8B EC` 入口）。
   原因可能是**跨段调用**（如 `0x4C037B`/`0x4D314F`）或**函数入口不是 `55 8B EC`**。
   ⇒ **这 37 处不是"无作用"，是本工具的归域失败**，待修。
2. **`0x43CDDD` 里的 `[ecx+0x10]` 我一度读成"HP"** —— 该函数上下文里 `ecx = [ebp-0x1c]`，
   **它到底是不是"单位对象"未验证** ⇒ **不要照抄"HP"这个结论**。
3. **桩返回值 = 数值**这一条**有强证据**（`call 桩` → `call 0x425AD9` → `add [局部],eax`），
   但**"每个桩返回什么量纲"未逐个验证**。
4. 分组只按**直接 `E8` 调用者**；**经函数指针的调用看不到**（13 个桩无直接调用者）。

## 69. ★★★★★ 归域修复 + 域画像 + 对象链追到源头（2026-10-16，DSH）

### 69.1 归域修复：把 37 个 `0x?` 全部归位
**旧法**（向上找 `55 8B EC` 且中间无 `C3`）在**跨段**、**非 `55 8B EC` 序言**、**叶函数**上失败
⇒ 本工具第一版有 **37 个调用点归到 `0x?`**。

**新法**（已实现）：**函数入口候选 = 所有 `E8`(call) / `E9`(jmp) 的目标**（本样本 **5939 个**），
再用 `bisect_right` 取「≤ 目标 VA 的最大候选」。

**结果**：**`0x?` 消失** ⇒ **254 个桩调用点归入 155 个域**（此前 136 个域、37 个未归）。

### 69.3 ★★★★★ 对象链追到源头：`0x40658F` → `0x4061E4`
**起因**：`0x43CDDD` 里 `[ebp-0x1c]` **从未被显式赋值**，只在
```asm
0x43CDE2  push eax ×6          ; 预留 6 个局部
0x43CDE9  call 0x40658F        ; ★ 副作用填局部
0x43CDF0  mov  ecx,[ebp-0x1c]
```
之后被读。

**追 `0x40658F`（现读）**：
```asm
0x40658F  push ebp / mov ebp,esp
0x406592  push dword ptr [ecx]     ; 取 [ecx]（一个 id）
0x406594  call 0x4061E4            ; ★★★
0x406599  ret
```
⇒ **`0x40658F(obj) = 0x4061E4([obj])`**
⇒ 而 **`0x4061E4` 库内早有定论**（外部公共知识库对账页）：
> **「Data号 → 人物运行时记录走 `0x4061E4`（`[0x4CEA00] + Data号 × 0x48`）」**

**⇒ ⇒ 定论**：`0x43CDDD` 里的 **`[ebp-0x1c]` = 角色动态数据记录指针**（`[0x4CEA00] + id*0x48`）

### 69.4 ★ 由此**否掉我自己一个未验证的说法**
| 我上一版说 | 现在 |
|---|---|
| `0x43CDDD` 里 `[ecx+0x10]` = **HP** | **✗ 收回**。`ecx = [ebp-0x1c]` = **角色动态数据记录**，其 `+0x10` 语义**仍未定**（库内只记了 `+0x08` 名字 / `+0x21` 五围 / `+0x2A` 兵种·我军标志）|

**⚠ 但 `[+0x10]` 是高频字段**：`0x4E3000` 里也有 `mov dl,[ecx+0x10]` / `mov [ecx+1],dl`
⇒ **值得单独查角色记录 `+0x10` 的语义**（新增待验证 P0）。
