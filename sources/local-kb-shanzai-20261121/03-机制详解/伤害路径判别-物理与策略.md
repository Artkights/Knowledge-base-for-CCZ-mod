# 伤害路径判别（物理 / 策略）

## 结论速览

- **物理伤害**走 `0x405DE1` 函数，操作伤害槽 **`ctx+0x84`**，飘字在 `0x404A77`。
- **策略伤害**走**另一套独立上下文** `0x497AF8`，伤害数组 = **`0x497AF8 + 0x108 + 4×i`**（每目标一个 DWORD），飘字在 `0x421CAA`。
  ⚠️ 旧写法「策略伤害槽 = `ctx+0x254`」**已于 2026-10-15 证伪**（`ctx+0x254` 是**物理上下文里的 MP 伤害数组**，见下 §1 与
  `02-数据结构/复刻版6.6山贼策略记录与施法对象.md`:8）。
- **`0x24`（防御暴击）的减伤补丁只在物理路径**（补丁点 `0x405EF9` 在 `0x405DE1` 函数内）。
- ⚠️ **复用发生在祖父层**：`0x405DE1` 本身**只有 1 个调用者**（`0x452802`），
  但它上游的 `0x4527FE` 有 2 个调用者、再上游的 **`0x4064F1` 有 11 个调用者**
  ⇒ 同一个 `0x405DE1` 会被**伤害预估 / AI 决策 / 预览 / 各种效果结算**共用
  ⇒ **在该函数下断点命中，不代表玩家真的发起了一次攻击**。
  （口径校正 2026-10-14：旧写法"`0x405DE1` 上层 `0x4064F1` 有 11 个调用者"易被读成
  "`0x405DE1` 有 11 个调用者"；精确层级见下方第 2 节实测调用链。）

## 适用版本

- `Ekd5.exe`（v6 补丁后 SHA `B6EBDE6B5B6EB0CC5916E0D24601B21AE466E0A31996ADCE03E366C7E8544CBB`）
- 地址为运行时绝对地址（与样本绑定）。

## 已确认事实

### 1. 路径对照表

| 维度 | 物理 | 策略 |
|---|---|---|
| **上下文基址** | **`0x4927F0`**（常量基址本身，不是指针） | **`0x497AF8`** —— ★ **两块互相独立，不是"共用上下文"** |
| 伤害函数 | **`0x405DE1`**（函数内 `add eax,0x84`） | 没有单一"伤害函数"：由**策略效果处理器**逐目标写（写点见下） |
| 伤害数组 | **`0x4927F0+0x84`**（0x74 B = 29×DWORD，按被攻击顺序） | **`0x497AF8 + 0x108 + 4×i`**（每目标一个 DWORD）★2026-10-15 定案 |
| `+0x254` 是什么 | **MP 伤害/MP 消耗数组**（`0x405DE1` 入口 `0x405E06 add ecx,0x254` 同构初始化；写点 `0x405FA9`/`0x40600F`） | 不适用（策略上下文里没有这块） |
| 飘字调用点 | **`0x404A77`** | **`0x421CAA`** |
| 暴击标志 | `0x4927F0+0x604` | 未确认（策略侧只有集气模式编码 `+0x12` 那一路，见 `集气模式-闪避暴击连击.md`） |
| 连击标志 | `0x4927F0+0x608` | 不适用 |
| `0x24` 减伤是否作用 | **是** | 否 |
| 攻击者标识 | `*(WORD*)(ctx+4)` = 角色号 | `*(BYTE*)(0x497AF8+1)` = 施法者战场 slot（需转角色号） |

- 物理依据：`0x405DE1` 函数内 `00405DF1  add eax,0x84`、`00405E06 add ecx,0x254`；
  `0x405EF9`（我们的补丁跳板）就在这个函数体内。
- **策略伤害数组依据（2026-10-15 现读，样本 SHA 见下）**：全映像字节扫描 `89 8? 08 01 00 00`（`mov [reg+0x108], eax`）命中 6 处，
  其中 **3 处落在策略效果处理链且同函数内还读写策略上下文的招牌字段** ⇒ `ecx` 即 `0x497AF8`：
  | 写点 | 指令 | 同函数内的上下文旁证 |
  |---|---|---|
  | **`0x423B34`** | `mov dword [ecx+0x108], eax` | 紧接 `mov byte [ecx+0x401], al` |
  | **`0x4242D2`** | `mov dword [ecx+0x108], eax` | 紧接 `mov byte [ecx+edx+0x401], al`；随后 `mov al,[ecx+1]` → `mov [ecx+0xC],al` → `mov [ecx+0xD],al`（＝施法者/选中目标/目标表，与策略上下文布局逐项对应） |
  | **`0x42463E`** | `mov dword [ecx+0x108], eax` | 紧接 `mov byte [ecx+0x401], al` |
  （另 3 处 `0x45C2DE`/`0x45D90C`/`0x45D99B` 落在别的结构上，其后续指令是 `cmp eax,[ecx+4]`/`mov edx,[ecx]` 形态，**不要混进来**。）

### 2. `0x405DE1` 的调用链（实测）

```
0x405DE1  ← 唯一调用者 0x452802
0x4527FE  ← 2 个（0x406545、0x4179A9）
0x4064F1  ← ★ 11 个：
   0x4105DB  0x41797A  0x417C29  0x417C5C  0x421335
   0x436468  0x43ACB8  0x43DB90  0x4532C5  0x465FBF  0x4C04E6
```

⇒ 该函数被**伤害预估 / AI 决策 / 预览 / 各种效果结算**复用。

### 3. ⚠️ 由此得出的操作纪律

- **断点命中 ≠ 发生了一次实际攻击**。它只说明"这段代码被执行过"。
  注意层级：`0x405DE1` 是**唯一入口**（1 个调用者），复用发生在祖父层 `0x4064F1`（11 个调用者）；
  所以在 `0x405DE1`/`0x405EF9` 上命中，同样不能说明"真的打了一下"。
- 想证明"真的打了一下"，必须**同时**核对上下文：
  - `ctx+0x00`（攻击者）、`ctx+0x01`（目标）是否变化
  - 目标 HP 是否真的下降（`0x4A7B20 + slot*0x30 + 0x10`）
- 相对地，**只读 HP 采样**（`_减伤采样v2.py`）反映的是"真的掉血"，
  比单纯的断点计数更贴近"实际发生"。

```bat

```

## 风险与边界

- 策略路径的具体函数地址**尚未细查**（只知伤害槽与飘字点）——
  若以后要给策略也加减伤/预览，需先补这块。
- `0x405DE1` 被复用 ⇒ 在那里做的补丁**会作用于所有调用它的场景**
  （包括预估），这可能带来副作用（例如预估数值被减伤、而实际伤害也被减伤）。

## 证据来源

- 反汇编：`_dsh反汇编工作台.py` 读 `0x405DC0~0x405E10`
- 调用链：`_查物理伤害调用链.py`（静态扫描 `E8 rel32`）
- 断点实测：`0x452EA4`（v6 体）命中 1 次（当时未见明显攻击动作）

## 待验证项

- **P1**：策略伤害函数的地址与内部伤害槽写入点（补全对照表）。
- **P1**：`0x4064F1` 那 11 个调用者各自属于什么场景（攻击 / 预估 / AI / 其他）。
- **P2**：`0x405DE1` 被复用时，我们的减伤补丁是否会波及「预估数值」。
