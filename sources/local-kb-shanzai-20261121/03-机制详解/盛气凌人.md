# 盛气凌人（暴击触发全属性下降）机制分析

## 结论速览

- 自定义注入式特技：个人特效号 `BF` (191)（补丁文件改地址 `-4529BF`）、装备特效号 `00`（补丁文件改地址 `-4529BD`，不可通过装备获取）；触发条件 = 物理攻击**暴击** + `4101D9` 判定通过，效果为目标 6 项属性各降 1 档。
- Hook 模式为函数尾部 epilogue 劫持：原地址 `472D92` 写 `E9 10 FC FD FF`（jmp 4529A7）+ `90` 对齐，代码洞 `4529A7`（空洞 D-1，72 字节），洞内重新执行被替换的 `mov esp,ebp / pop ebp / ret 08`。
- 暴击门槛读 `[4927F0+604]`（`4927F0` 战斗数据结构，`+604` 暴击标志），为 0 直接跳 epilogue；判定用 `mov ecx,[ebp-08]`（attacker）后 `push 01 / 01 / 00 / BF` → `call 4101D9`，`jz` 失败同样跳 epilogue。
- 下降循环：`[ebp-04]` 从 0 计到 5，每轮 `push 00`（arg3 下降模式）+ `push [ebp-04]`（arg2 属性索引）、`ecx = [ebp+0C]`（target）→ `call 409821`；索引 0-5 对应 `target+18`…`target+1D`（攻击/防御/精神/爆发/士气/移动增益）。
- 下降幅度同 `414361`：当前值 `> 3` → 降至 3，当前值 `<= 3` → 归零；与原版随机降 2 项（`0C/5E`）的差别是**固定全 6 项、各降 1 档**。
- 版本迭代（勿退回旧 Hook）：v1-v2 的 `43DB53`（`43DADA` 内）`push ebx/push esi` 会干扰 `4064F1` 栈参数；v3 `43DB53` 与模组版引擎不兼容；v4 `405F24` 在伤害结算前触发、v5 `406023` 太靠后，时序均不对；**v6 最终版 `472D92`** 才与原版属性下降触发时序一致（全程用 `[ebp-04]` 栈变量计数，不用 `ebx`/`esi`）。

## 详细记录

#### 概述

"盛气凌人"是一个**自定义注入式特技**：攻击者在物理攻击发生暴击时，使目标全部 6 项属性（攻击、防御、精神、爆发、士气、移动）各下降 1 档。

- **个人特效号**：`BF` (191)
- **装备特效号**：`00`（不可通过装备获取）
- **Hook 模式**：函数尾部 epilogue 劫持（不破坏任何原指令）

#### 完整调用链

```
后伤害效果调度 405966 (attacker, target)
  │
  ├── call 40399B              ← 伤害效果执行
  ├── call 472D48              ← ★ 原生属性下降 + 盛气凌人
  │     │
  │     ├── 前置条件检查 (436392)
  │     ├── 特技检测 (5E/0C → 600127 → 4101D9)
  │     ├── 随机降 2 项属性 (循环调用 409821)
  │     ├── 472D92: jmp 4529A7 ──────────┐  ★ Hook 劫持
  │     │                                      │
  │     └── ★ 盛气凌人代码洞 4529A7 ────────┘
  │         ① mov eax, 4927F0
  │         ② cmp [eax+604], 0     ; 检测暴击标志
  │         ③ jz .epilogue           ; 非暴击 → 跳过
  │         ④ mov ecx, [ebp-08]    ; ecx = attacker
  │         ⑤ push 1/1/00/BF → call 4101D9
  │         ⑥ jz .epilogue           ; 无特技 → 跳过
  │         ⑦ mov [ebp-04], 0      ; 计数器归零
  │         ⑧ .loop: push 00; push [ebp-04]
  │              mov ecx, [ebp+0C]; call 409821
  │              inc [ebp-04]; cmp [ebp-04], 6; jl .loop
  │         ⑨ .epilogue: mov esp, ebp; pop ebp; ret 08
  ├── call 4039F4              ← 伤害动画/音效
  └── ...
```

#### 设计理念

##### 为什么选择 472D48 尾部 Hook

1. **与原生属性下降（`0C/5E`）完全一致的触发时序**：伤害已结算，属性下降在同一后伤害调度循环中执行
2. **复用现有栈帧**：`[ebp+0C]` = target 指针，`[ebp-08]` = attacker 指针，无需额外查询
3. **无需恢复被覆盖指令**：Hook 替换的是 epilogue（`mov esp, ebp; pop ebp; ret 08`），在代码洞中重新执行这 3 条指令即可
4. **遍历全部 6 项属性**：与原版随机降 2 项的"攻击附带属性下降"形成差异化设计

##### 为什么不使用 ebx/esi 寄存器

该代码洞位于 `472D48` 的栈帧上下文中，原函数不使用 `ebx`/`esi`。
代码洞全程使用栈局部变量 `[ebp-04]` 做循环计数，这直接沿用了原版 `472D48` 的写法
（见 `472D72: inc dword [ebp-04]`），保持了与原版完全一致的编码风格。

此外，`[ebp-N]` 栈变量的使用方式在原版引擎中广泛存在：
- `472D48` 用 `[ebp-04]` 做属性下降循环计数
- `412D52` 用 `[ebp-04]` 保存单位指针、`[ebp-08]` 保存状态标志地址
- `43DADA` 用 `[ebp-0C]` 保存 this 指针、`[ebp-04]` 保存临时状态

使用栈变量而非 `ebx`/`esi` 等 被调用方保存 寄存器，可以避免不必要的 push/pop 操作，
降低代码出错的概率，同时让注入代码的风格与所在原函数的上下文保持一致。

#### 完整反汇编（代码洞 4529A7，72 字节）

```asm
; ─── 暴击标志检测 ───
4529A7: mov eax, 4927F0            ; eax = 战斗数据基址
4529AC: cmp dword [eax+604], 0     ; [4927F0+604] = 暴击标志
4529B3: jz 4529E9                  ; 非暴击 → 跳 epilogue

; ─── 特技判定（复用原版 [ebp-08] = attacker） ───
4529B5: mov ecx, [ebp-08]          ; ecx = attacker
4529B8: push 01                     ; 效果值标志 = 1
4529BA: push 01                     ; 叠加标志 = 1
4529BC: push 00                     ; 装备特效号 = 00
4529BE: push BF                     ; 个人特效号 = BF
4529C3: call 4101D9                ; ★ 核心引擎
4529C8: test eax, eax
4529CA: jz 4529E9                  ; 无特技 → 跳 epilogue

; ─── 全属性下降循环 ───
4529CC: mov dword [ebp-04], 0      ; 计数器 = 0
4529D3: push 00                     ; arg3 = 0 (下降模式)
4529D5: push dword [ebp-04]         ; arg2 = 属性索引 (0-5)
4529D8: mov ecx, [ebp+0C]           ; ecx = target 指针
4529DB: call 409821                ; ★ 属性下降包装
4529E0: inc dword [ebp-04]         ; 计数器++
4529E3: cmp dword [ebp-04], 6      ; i < 6 ?
4529E7: jl 4529D3                  ; 继续循环

; ─── 恢复原 epilogue ───
4529E9: mov esp, ebp
4529EB: pop ebp
4529EC: ret 08
```

#### 受影响的属性

`attr_index` 取值 0-5，对应战术单位 `[target + attr_index + 18]` 处的 6 个字节：

| 索引 | 实际偏移 | 属性 |
|------|----------|------|
| 0 | `target+18` | 攻击力增益 |
| 1 | `target+19` | 防御力增益 |
| 2 | `target+1A` | 精神/智力增益 |
| 3 | `target+1B` | 爆发力/敏捷增益 |
| 4 | `target+1C` | 士气/运气增益 |
| 5 | `target+1D` | 移动力增益 |

属性下降规则同 `414361`（与原生属性下降一致）：
- `当前值 > 3` → 降至 3
- `当前值 ≤ 3` → 归零

#### 开发历程

此次特技补丁经历了多轮迭代：

| 版本 | Hook 点 | 问题 |
|------|---------|------|
| v1-v2 | `43DB53`（43DADA 内） | `push ebx/push esi` 干扰 `4064F1` 栈参数 |
| v3 | `43DB53`（修正 push 顺序后） | 与 模组 版引擎不兼容 |
| v4 (模组) | `405F24`（模组 暴击汇合点） | 伤害结算前触发，时序不对 |
| v5 (模组) | `406023`（经验结算） | 太靠后，不符合"伤害→属性下降"时序 |
| **v6 最终版** | `472D92`（原生属性下降函数尾部） | ✅ 与原版完全一致的触发时序 |

最终版放弃使用 `ebx`/`esi`，改用 `[ebp-04]` 栈局部变量计数，与原版编码风格统一。
