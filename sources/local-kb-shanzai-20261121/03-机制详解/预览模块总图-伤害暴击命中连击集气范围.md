## 结论速览

2. **★ 预览与实战共用"率"函数、不共用"值"**：
   | 率 | 实战调用点 | 预览调用点 |
   |---|---|---|
   | 物理暴击率 `0x40C7D8` | **`0x405ECD`**（`0x405DE1` 内） | **`0x4131EF`**（`0x4131CF` 内） |

## 实现·使用方法

- **要让预览显示"减伤后的伤害"**：改 `0x44049E` 的 `0x44066D`（预览伤害局部变量）之后，
  按 `(100-V)/100` 折算 —— **不要**动 `0x43BC5A`（一动实战也变）。
- **要让预览显示某类必定触发**：照 `0x4131CF` 的写法 —— 判定成立时**把该率取负**（`neg`），
  面板自会表现为"必定"。
- **要看预览/实战差异**：同时观察 `0x44066D`（预览值）与 `0x405E9A`（实战写槽值），差值 = 公式之后的全部修正。

## 风险与边界

- 本页全部为**离线静态**结论；`0x44049E` 的 3 个上层入口**未做执行级区分** ⇒ 改预览前必须先定
  "哪个入口是玩家界面路径"（P0），否则会连 AI 决策一起改。
- `0x428925`（预览命中率）与 `0x43B4B6`（命中率总函数）**是两个函数**：
  前者带集气读、后者是实战链；不要因为"都在算命中率"就互换。
- `0x412C78`（浮动伤害）**不在本模块内**（调用者 `0x433FA5`/`0x4D280F`）⇒ 取消浮动不影响任何预览项。
- 反汇编时**必须按函数边界对齐**：`0x44049E` 内有若干"假 call"（越界目标如 `0x764307DE`），
  线性全段扫描会产出垃圾。

## ⚠ 2026-10-18 12:01 修正：「会斩变红」第一版闪退（call 栈不平衡），改 jmp 版

> 用户实测：装上第一版后**直接闪退**。回滚（`8229915E → 07AA3FA5`）后定位并重做。

### 一、崩因（我的错）

第一版挂点写成了 **`E8 call`**：

```asm
0x457F28  E8 4C 91 FE FF   call 0x441079    ; ← 压入返回地址（esp -= 4）
```

而洞1 之后是 `... jmp 0x440672`（**不是 ret**）⇒ 那个返回地址**永远留在栈上**，
后续 `0x440672` 起的所有栈访问全部偏移 4 字节 ⇒ 读取错位 ⇒ **闪退**。

**正确做法**：挂点用 **`E9 jmp`**（不压返回地址），洞内自己 `jmp` 回目标。
洞内若需要 `call` 别的函数，那些函数自带 `ret`，栈是平衡的。

### 三、★★★★★ 本轮最大的坑：**两个结构都有 `+0x1B`，语义完全不同**

| 结构 | `+0x1B` 是什么 | 读错的后果 |
|---|---|---|
| **战场单位记录** `0x4A7B20+slot×0x30` | **`+0x18..0x1D` 是攻/防/精/爆/士/移的升降状态字节**（1=减少 3=正常 6=增加）| 读成 word 得 `03 03` = **771**，看起来像上限，其实是两个"正常"状态字节！ |
| **person 记录** `[0x4CEA00]+Data号×0x48` | **HP 上限（u32）** | 这才是真值 |

**权威来源**：扳手源码
- `engine_profile.py:790` → `FieldSpec("hp_max", 0x1B, 4)`
- `mywindow.py:4287` → `hp_max = read_u32(mem.value + 0x48*n + 0x1B)`
- 另 `mywindow.py:4285` 有版本分支：`-1/V64/V65/V63_MP/V66` 用 `+0x1B u32`、`+0x1F u16`(MP)；旧版用 `+0x1C u32`、`+0x20 u8`

实测验证（`[0x4CEA00]`=0x31E1000）：n=1（关羽）= **7818**（界面显示 7616）、n=0=6595、n=2=760、n=8=536 ⇒ 确为 HP 上限。

### 四、斩杀公式的完整来源（参考补丁 `【star6.6x】斩杀攻击 改进`）

文件写明：「斩杀攻击 N%：如果本次攻击使敌人生命值低于 N%，则此次攻击直接斩杀敌人。每 50 杀敌数会让斩杀阈值提升 1%」

引擎实现（`0x40CFF6`）：
```
T = 0x45D2DA() = 0x4101D9(ecx=攻击者, 0x6E, 0x1D, 0, 0)
阈值 = T + 攻击者杀敌数/分母      （原版 100，参考改进版改 50）
加成 = 阈值 × (上限×80) / 100     （0x407263 返回 上限×80，0x425AD9 = a*b/100）
斩杀 ⇔ 伤害 + 加成 >= 目标HP
```

⚠ **注意**：引擎原生 `0x407263` 返回的是 `上限×80`（如 771×80=61680），代入 `0x425AD9(阈值, 61680)/100` 会得到 **6168** 这种巨大加成 ⇒ **引擎原生斩杀对常见血量几乎必触发**。所以预览判定**不能用引擎原样公式**，要用"剩余 ≤ T% × 上限 × 80%"（= 61~92 量级）才符合直觉 —— 这正是 v18 采用的。

### 二、为什么"只在实战弹"天然成立

`0x40CFF6`（斩杀函数）**只有一个调用者**：`0x452911`（在 `0x452907` 实战攻击结算里）。

### 三、四条判定（缺一条就会"普通攻击也叫"）

挂在 `0x40D06A`（引擎的"伤害+加成≥HP"处）**不够**，因为斩杀加成 = `阈值×上限×80/100`
极大（实测 6168），对常见血量恒真。洞内重算后：

| # | 判定 | 汇编 | 作用 |
|---|---|---|---|
| ① | `T == 0` | `call 0x4101D9` + `je` | 没有 `0x6E` 特技 |
| ② | `剩余 <= 0` | `sub eax,edx` + `jle` | **伤害本身就能打死 = 普通击杀** |
| ③ | `剩余 > 阈值` | `cmp eax,ecx` + `ja` | 血还多，斩不到 |
| ④ | 开关 == 0 | `cmp byte [0x442E10],0` + `je` | 手动关闭 |

其中 `剩余 = 目标当前HP − 原始伤害`，**原始伤害必须在 `mov [ecx],eax` 覆盖前先 `push [ecx]` 取出来**。

### 六、★★ 栈平衡（这轮连续栽了两次，记牢）

**洞结构的正确顺序**：
```asm
pushad          ; ① 先保护全部寄存器
pushfd          ; ② 再保护标志
push [ecx]      ; ③ 最后压"要跨调用保存的值"
...
pop ecx / pop edx   ; 弹回"值"
popfd / popad       ; 弹回标志/寄存器
```

**错误 1**：`push [ecx]` 写在 `pushad` **前面** ⇒ 出口 `popad` 从错位恢复 ESP ⇒ **闪退**。
**错误 2**：`jz`(T=0) 路径**跳过** `pop ecx/pop edx` ⇒ 残留 4 字节。
  ⇒ 修法：**分离出口**——`jz` 走「`add esp,4` + popfd + popad」，`ja` 走「popfd + popad」。

最终三条出口的栈深度（校验器实测）：
| 分支 | 跳转时深度 | 出口动作 | 净 |
|---|---|---|---|
| `je`(T=0) | +40 | `add esp,4`+`popfd`+`popad` | 0 |
| `jle`/`ja`/开关`je` | +36 | `popfd`+`popad` | 0 |
| 正常弹完 | +0 | — | 0 |
