# 6.6X爱要不要系列策略特效注入拆分分析

## 结论速览
- 可以拆分启用，但正确形态是“公共底座 + 单特技配置”，不能按文本段任意删块。
- 公共底座包含 4 个挂钩与 3 个共享代码块：0x43C2C3→0x41B245、0x43D658→0x452CFE、0x422F71→0x40CDCA、0x4230A2→0x40CE1C；代码块为 0x452CFE(33B)、0x40CDCA(126B)、0x41B22D(723B)。
- 0x41B22D 是主函数和一排子桩的混合大段，特技 ID 槽位嵌在这段代码内部；因此不能把某个子桩当成完全独立的注入段。
- 单特技可通过配置槽启用：天气、地形、魔法盾、别小看法师、别小看法师2、法神、原地施法分别有自己的 ID/阈值字节。

## 已确认事实
### 公共底座
- 0x43C2C3 跳到 0x41B245，落在 0x41B22D 大段主函数内。
- 0x43D658 跳到 0x452CFE；该段写共享状态 [0x4B5DDB]、复制单位字段并回跳。
- 0x422F71 跳到 0x40CDCA；0x4230A2 跳到同一共享段内的 0x40CE1C。
- 0x41B22D 大段内存在 7 个同形态的 0x4101D9 特技查询桩。
### 单特技配置槽
- 策略指定天气：0x41B235、0x41B23A、0x41B251。
- 策略指定地形：0x41B478、0x41B47D、0x452D10。
- 策略魔法盾：0x41B490、0x41B495。
- 别小看法师：0x41B4A8、0x41B4AD。
- 别小看法师2：0x41B4C0、0x41B4D5；MP阈值 0x41B3D6=0x14。
- 策略法神：0x41B4D8、0x41B4DD、策略类型 0x41B3F9；HP阈值逻辑在 0x41B414。
- 原地施法：0x41B4F0、0x41B4F5。
### 修复版仍有风险
- 修复版只把 0x41B41E 的跳转位移从 0x0D 修到 0x0E，修复落入指令中间导致乱码的问题。
- 只把 0x41B4F5 的桩号从 0 改为 0xE7；其余同形态桩仍有多个 push 0，可能查询 0x00 覆海之龙，不能默认视为禁用。

## 实现·使用方法
- 先建立公共底座，再为目标特技写独立配置段；配置段只写该特技的 ID/阈值，不重复写共享代码。
- 在确认 0 值是否为禁用哨兵前，不得用 00 作为“关闭其他特技”的依据；应逐桩确认最后一个 push 的特技号。
- 每个单特技包必须声明依赖的公共底座、目标 ID 槽、阈值字节、原字节和回滚范围。

## 风险与边界
- 不能只导入 0x41B4xx 的一小段；主函数、公共跳转和状态区仍是必要依赖。
- 当前样本代码洞/挂钩地址是未占用状态，不等于已验证可直接写入；写入前要跑占用登记、样本时间线和写锁。
- 策略伤害测试仍需遵守 4018=1 前提。

### 两个必须保留的冲突

1. S6：外部文本第 6 行写的是“HP 低于 50% 时特效值翻倍”。但修复版字节在 0x41B41D 是 73 0E（jae），跳到 0x41B42D 的直接翻倍分支；按知识库已定案的 unit+0x10=当前 HP、人物记录 +0x1B=最大 HP，当前机器逻辑是 HP 大于等于半血时翻倍，低于半血时走特效值百分比加成。0x41B41E 的 0D→0E 只修正落点，不改变方向。
2. S7：修复版最后一个 push 是 0xE7；知识库名表将 0xE7 定为火战精通，而外部文本把该分支命名为原地施法。因此“移动快照/不移动控制条件”已对上，但特技编号语义仍冲突。

### 地址纠正

现有本页旧条目把“别小看法师2”的第二个立即数写成 0x41B4D5。按 0x41B4B8 子桩反汇编：第一处立即数起点是 0x41B4C0，第二处立即数起点是 0x41B4C5；0x41B4D5 实际是 S6 的 6A 01 操作码位置。以后使用 0x41B4C5。
