# 特技新增 · 提示词模块（精简优先 / 复用优先，但不冒险）

## 结论速览

- **用途**：以后每次「新增 / 移植特技」直接照「实现·使用方法」四节执行，不再从零推导。
- **核心语义（先定住这一句，其余全是推论）**：斗将 = 在敌军行动**进行中**插入一次策略攻击，
  并因此**中断这次行动**；由此推出「逐格判定 / 不成立就不打断 / 整回合作废 / 先触发者独占」（见 §4）。
- **精简的边界**：精简 = 少做**无关查证**（不读别的特技的补丁版本史、不追与本次无关的链）+
  **不重复推导已带 SHA 固化的库内事实**；**不是**少做必要验证。四条"不可省"见「边界与坑」。
- **复用阶梯**（先下后上，不许跳）：改立即数 → 空位搬移 → 内联桩 → **借洞塞函数（条件放行）**。
  借洞不再禁止（2026-10-26 用户修正）：过 `AGENTS.md` §3.6.2 四组门槛即可写盘，
  细则见 `00-总览与规范\改引擎判据-只改立即数禁止扩展.md`、最高优先级页
  `00-总览与规范\特技补丁写法总纲-引擎优先与精简理念.md`。
- **号位必须先现读**：名表 255 行逐行扫，不许凭印象说"某号是预留"。
  2026-10-26 实测事故：`0x96/0x97` 看着像预留，实际已被「执天之行」占用。
- **名表改名 ≠ 生效**：引擎只查询它认识的号；未被任何桩查询的号，改名表只显示、不触发。

## 适用版本

- 样本 `Ekd5.exe` SHA256 `2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`（工作基底）。
- 名表：VA `0x4CC600`，255 行 × 16B；行格式 = 名字 12B(GBK，尾 0) + 2B 零 + flag 1B（偏移 15）。

## 已确认事实

### 1. 真正空闲的名表行（2026-10-26 全表现读，15 个）

```
0x6F  0x99  0x9A  0x9C  0x9D  0xED  0xF4  0xF5  0xF6  0xF7  0xF8  0xF9  0xFC  0xFD  0xFF
```

- `0x9C / 0x9D`：宝物表同号 = 忽视攻击 / 忽视防御 ⇒ **尽量不选**。
- `0x96 / 0x97`：**已占用**（执天之行 / 执天之行次数，flag `0x07` / `0x06`）。
- `0x98 / 0x9B`：有功能（天纵之资 / 远距攻击）⇒ **禁选**。
- 默认推荐：`0x99 + 0x9A`（原为重复号、功能已关、不撞宝物表）。

### 2. 桩查询现状

- `0x4101D9` 当前 **150 个调用点**（本节实测，不是库内旧口径的 105）。
- `0x99 / 0x9A` **没有任何桩查询** ⇒ 要生效必须新增桩（内联桩）。
  反之：若所选号已被查询，直接复用现成桩，不许重复建。

### 3. 可复用的现成入口（不要新写）

| 用途 | 地址 | 契约要点 |
|---|---|---|
| 策略号 → 61H 策略记录 | `0x484002` | 之后必须 `0x425AC7` 判空 |
| 策略施放（先手用） | `0x420420` | 唯一标注"先手策略施放"，`0x5E` 域二在用 |
| 先手条件判定 | `0x41CECC` | 参数：上下文 / 单位记录 / 值−1，`ret 0xC` |
| 单点范围判定 | `0x412B30` | **会写排除槽 `[0x4B2C28]`**，连续判多目标前必须复位 |
| 范围枚举 | `0x412B5F` | `0x41031C` 初始化 → `0x435884` 取范围内单位号 |
| 登记式消费 | `0x417AF6` | `0x5F` 域二写法：按 值−1 登记，成功走 `0x401DFF` |
| 物理斗将主域 | `0x428A53` | 候选遍历 + `record+0x22` 次数门槛（`0x428B1F` 只生成候选结果） |

## 实现·使用方法

### 1. 号位选取流程（照抄，四步）

1. 扫名表 255 行 → 列出名字为「预留」或全零的行。
2. 排除有功能的号、排开撞宝物表的号（`0x9C/0x9D`）。
3. 扫 `0x4101D9` 全部调用点 → 判断所选号是否已被查询（决定"复用桩"还是"新增桩"）。
4. 现读所选行 16B → 作为写前像断言（**不许硬编码旧快照**）。

工具：`_法术斗将-定位.py`（只读，输出 `_法术斗将-定位.json`）、
`_名表-法术斗将-0x99-0x9A.py`（干跑打印，`--go` 走 `_dsh写锁.safe_write_exe`）。

### 2. 两格语义（策略载体 + 次数）

- 格1 = 策略载体：持有即启用；特效值 = 策略 Data号（走 `0x484002` 解析，不缓存表指针）。
- 格2 = 次数：特效值 = 剩余次数；**禁止复用 `record+0x22`**（物理斗将已占该字节）。
- 只持一格不生效；两格齐备才触发。

### 3. 生命周期（缺一段就会出现"装了没反应"或"空转扣次数"）

1. 战斗开始：把格2 配置值写入运行时计数器**一次**（幂等，不许叠加）。
2. 判定顺序（**= 核心语义的否定面：不成立就"不打断"**）：格1 空 → 退；格2=0 → 退；策略号无效 → 退；范围不通过 → 退；**都不扣次数**。
3. 只有施放成功才扣 1（登记制则先扣后回滚）。
4. 归零后：不触发、不扣、不清空字段（保持 0，避免"0 与未配置"二义）。
5. 格1 空 ⇒ 整技视为不存在，不参与查询命中、不初始化计数。

### 4. 核心语义：**斗将 = 在敌军行动「进行中」插入一次攻击，并因此中断这次行动**

> **这一句就是斗将的全部。** 后面所有"要求"（移动中打断其移动与攻击 / 格1 空或格2=0 怎么办 /
> 被打断者本回合彻底作废 / 先触发者独占）**都不是独立需求**，而是这一句的不同侧面解释 ——
> 写实现时按下面的推论逐条落实，**不要当成四条并列功能各自开关**。

**三个参数必须同时锁定，缺一个就落不了地**

| 参数 | 取值 | 反例（做出来就不是斗将）|
|---|---|---|
| **谁打谁** | 持有者 → 进入其**策略**攻击范围的敌军单位 | 打成物理攻击；或范围口径取错（应复用 `0x5E` / `0x5F` 同款策略范围）|
| **什么时候** | 敌军**移动途中逐格** | 敌军走到位、打完才触发 ⇒ 那是"回合末反击"，不是斗将 |
| **打断到什么程度** | 该敌军**本次行动整回合作废** | 只打断移动、仍允许它攻击 ⇒ 等于没打断 |

**由核心语义直接推出的三组约束（落实要点，不是新需求）**

1. **"进行中"⇒ 必须逐格判定**：移动步进每格后查范围；**落点判定不算**（落点 = 移动已结束）。
2. **"打中了"才打断 ⇒ 成立条件全过才动手**：格1 空 / 格2=0 / 策略号无效 / 范围不通过
   ⇒ **不打断、不扣次数**，敌军照常行动。任何"部分成立"都不许打断（否则只是白扣次数）。
3. **"整回合作废"⇒ 打断必须是一个完整的动作**：停移动（停在触发格）+ 清路径缓冲 + 取消攻击意图，
   三者同属**一个动作**，不可只做局部（只停动画不清缓冲 = 下次行动错位，且极难复现）。
   回合级收敛：同一敌军同一回合**只触发一次**（先触发者独占），否则多持有者会连锁打断同一单位。

## 边界与坑

- **精简 ≠ 冒险**：以下四条任何一条都不能省，省了就是返工：
  ① 现读目标字节（不信手写 SHA / 旧快照）；② 前像断言（不符即停，不许覆盖）；
  ③ 写入只走 `_dsh写锁.safe_write_exe`（自动备份 `edk5（N）<补丁名>`）；
  ④ 实跑判据（动作前后值），"框消失 / 没报错"不算成功。
- **要落洞时必须过 `AGENTS.md` §3.6.2 四组门槛**（精简 / 挂点 / 洞 / 验证），
  尤其：**洞体目标 ≤150B**、**代码结束即止不留填充**、**整条指令覆盖**、**入边唯一**、
  **回跳前还原寄存器与原指令副作用**。判洞三步第②步**必须按指令边界对齐**。
- **`0x428B1F` 不等于"打了一下"**：它调 `0x43F8C0`（取默认动作/特效）+ `0x411BFB` + `0x403789`
  生成候选结果；要"物理斗将打一下"必须先证到真正的攻击执行点。
- **`0x412B30` 会污染 `[0x4B2C28]`**：连续判定多目标必须备份/复位。
- **`0x426B33` 返回值语义库内两处相反**（`0x5E` 域一按"非 0 合法"，第4批:190 按"非零阻断"），
  用前必须现读定案。
- 新增特技要落洞时必须过判洞三步；`.text` 内 `90` 块共 454 块，**不等于都是洞**。
