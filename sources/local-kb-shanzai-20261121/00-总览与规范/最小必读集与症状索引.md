| 体系 | 基址 / 规则 | 权威页 |
|---|---|---|

### A2 判定链（四层 + 第四入口）

**桩 → `0x42518F`（双渠道包装）→ `0x40B922` 分流 → 真 `0x4101D9` / 假 `0x41301E`**；
另有**第四入口 `0x436334`**：参数化桩 `0x40399F`（`cmp al,6` + `add eax,8` ⇒ **特技号 = 特效值+8**，即 8~13）走的是 `call 0x436334`，**不经过 `0x4101D9`/`0x42518F`/`0x413009`**。

* 权威页：`03-机制详解/特技判定链-架构与全部入口.md`
* 扫描口径：已扫 **225 点 / 62 处内联桩**；`0x42518F` = **「桩统一出口」**（`_动态桩索引.py:42` 亦如此标注）。
* ⚠ **「有名无桩」≠「没有代码」**：那 9 个是**内联桩**；全映像**被查询过的特技号 188 个**（165 独立桩 + 23 内联桩）。
  ⇒ **判「某特技有没有代码」要用「桩调用模式」扫，不能用「有没有独立桩函数」。**

### A3 族 → 域（口径已重建，旧表作废）

## B. 反汇编 / 写补丁

### B1 落点判定：四条硬判据（**缺一不许落点**）

权威：`01-核心引擎/注入落点判定-四条硬判据.md`

1. 判「**是否已被某补丁占用**」⇒ **调那个补丁生成器的 `build_cave()` 取回它自己的字节、再全文搜索**。
   ⚠ **绝不能**靠"洞里的字节像不像代码"目视判断 —— **注入体常以【被覆盖的原指令字节】开头**。
2. 判「**洞有多长**」⇒ 从候选起点数连续 `90`，并**扣除其前方已被占用的注入体**。
3. **引用普查必须按指令边界对齐**（逐字节滑窗会把 `8B 45 00` 这类指令操作数当指针）。
4. **洞起点必须是合法指令边界**（反向解码验证：找"能线性解码、且有一条指令恰好结束于洞起点"的起点）。

* 配套：`_注入地址占用登记.py --check <VA> <len>`（报「空闲」才可落点）；**生成器必须自动 `claim()`**（写 `_注入占用声明.json`）。
* ⚠ **连续零字节 ≠ 空洞**：`.text3` 最大零区 `0x512DC2`（**127,547 B**）**起点前 2 字节 `0x512DC0` 是一张活跃的数据表头**（`FF FF` = 空表，容量 **31,886 项**）⇒ **写进去会破坏表**。
* ⚠ **判"有没有空隙"必须同时扫 `00` 和 `90`**（编译器留 `90`、链接器留 `00`；只扫 `00` 会误报"没有洞"）。
* ⚠ **`VSize ≫ RawSize` 的是 `.text2`**（虚拟填充，文件里无字节）；**`.text3` 的 `VSize == RawSize == 0x64000`**（文件里有实体）。**两者不要混**。

### B2 失败边界（实测，别重踩）

* **不是「注入一律不行」**，而是「在【内部有多条 `jmp` 旁路、共享寄存器/栈不变量】的函数体里做 inline hook 不行」。
  * 反例：物理伤害公式 `0x43BC5A` 体内 v8/v9/v10 **全部推进 1 个回合即进程终止**（该函数有 6 条 `jmp` 旁路共享不变量）。
  * 正例：v7 挂**别的函数**（`0x4E6000` 内的 `0x4E6052`）⇒ **推进 4 轮次存活**。
  * ⇒ **换一个「线性、无旁路」的挂点，注入是可行的**（`【star6.6x】斩杀攻击` 143 B 已实装可正常游戏）。
* **`0x43BF1C` 不能挂**：原字节 `8B 45 FC 59 EB 02`，5 字节 `E8` 会**吃掉 `0x43BF20` 的跳转偏移**。
* **回跳落点后若紧跟 `TEST EAX,EAX`，注入函数必须先 `PUSH EAX` 再 `POP EAX` 还原。**
* **判"补丁是否崩"必须【无调试器】跑**（附加/暂停态 `debug_stop` 会让进程消失，污染判定）。
* ⚠ **静默算错比闪退更危险**（v6 把单位指针 `0x4A8AE0` 当伤害值写进伤害槽 ⇒ **156 万伤害**，不报警）。
* **页权限不是崩因**（实测运行时 `VirtualQueryEx`：`0x457E2E`/`0x426F17`/`0x512DC2` 等 **全部 `PAGE_EXECUTE_WRITECOPY` + `COMMIT` ⇒ 可执行**）。

### B3 工具与格式

* 批量 / 离线：`_dsh反汇编工作台.py`（`asm` / `cave` 算字节）；`_可靠rel32引用扫描.py`；`_函数指针引用普查.py`。
* **补丁 txt 必须用 `-<VA>` 独立一行格式**（`_应用补丁通用.py:93` 的正则 `^\s*-\s*([0-9A-Fa-f]{6,8})\s*$` **只认这个**），原字节从段头上方 `# 原字节:` 注释读。
  ⚠ 写成 `0x42133D E8BE6B0300`（同行）⇒ **解析出 0 段 / 写入 0 字节**（无害但无效）。
* **社区通用格式** = `.1.0.6.6` + `o` + `#` 注释 + `-<VA>` 独立行 + 字节行；**CRLF / UTF-8 无 BOM / 段间空行**。
* **Keystone 对"带尾注释的整块"报 `KS_ERR_ASM_INVALIDOPERAND`** ⇒ 送汇编前剥注释。
* ⚠ **归档补丁前必须核对「洞体字节是否与 EXE 里的一致」**（实测抓到一个同名不同版的坑）。
* ⚠ **新洞落点前必须检查与已装洞是否重叠**（实测：旧 `0x457D7B..0x457DC2` 与新 `0x457DB4..0x457E2D` **重叠 15 B**）。
* **`0x00` 是合法特技号**（`push 0`）⇒ 判空必须 `is not None`，**不能用 truthiness**。

1. **先放行，再叫人**：设完断点**必须循环 `debug_run` 到 `state==running` 且 `Ekd5.Responding==True`**，**然后才**告诉用户可以操作。工具：`_先放行再叫人.py`（设断点+放行+确认，一条命令）。

3. **断点一次不超过 2~3 个**，用完**立刻全删**（曾留下 `0x405E9A` 把游戏卡死 44 次）。

### D3 状态契约（省时间的关键）

* **MCP 进程活着 ≠ 调试会话存在** ⇒ **先读 `state`**。`stopped` = 没有会话；`paused` 才能读写内存；**空响应通常 = 会话已结束**（别盲目重试）。
* `memory_read` 对**新分配页**有约 **1.5 秒缓存延迟**（`-32010 Memory not readable`）⇒ **不是权限问题**，重试即可。
* `script_execute` 在本 bundle **不可用**（`Method not allowed`）⇒ 用 `script_execute_batch` 或把逻辑写进 Python 侧。
* ⚠ **原生软件条件断点陷阱**：命中时**无条件先递增 `hit_count`**，之后才求值 break condition ⇒
  **「`hit_count` 增加」只证明"执行到该地址"，不证明条件成立、也不证明已暂停。**
  要条件成立 ⇒ 用**条件跟踪**。要分别核对四件事：断点状态 / 条件表达式与进制 / 实际暂停状态 / 适配器如何解释计数。

# ★ 2026-10-17 增补二：`edit` 工具**静默剥掉 BOM**（工具链缺陷 + 已加自检）

> 发现时间 2026-10-17 08:0x（DSH）｜ 起因：改完本页后用终检复核，发现**本页 BOM 不见了**

## 1. 结论速览

1. **`edit` 工具写回文件时会剥掉 UTF-8 BOM**（CRLF 会保留）⇒ 凡是 `edit` 过的知识库页
   **静默地**违反 AGENTS §1「Markdown 用**带 BOM 的 UTF-8**」。
2. **这不是推测，是受控复现**：造 `_bomtest.md`（前 3 字节 `ef bb bf`）→ 用 `edit` 改一行 →
   前 6 字节变 `6c 69 6e 65 31 2d`（= `line1-`），**BOM 消失**。
3. 实测库里 **23 / 499 页缺 BOM**（含 `更新记录.md`、`工具清单-制作与工程.md`、
   `会话成果索引-2026-10-17-….md` 等 —— 多为被 `edit` 或 MCP 追加写过的页）。
4. **已加自检**：`_自检.py` 新增 **I 项**（`check_i`）持续报「N/499 页缺 BOM」+ 修法，
   ⇒ 不再依赖"我记得补"。
5. **修法（复用现成工具）**：`python 大鲸鱼产生专用\_落盘-补BOM通用.py "<页路径>" …`
   （该工具同时把换行规范成 CRLF —— 本库 499 页里 CRLF 229 / LF 270，**两种风格本就混用**）。

## 2. 为什么这条值得单独记

* **它是"静默降级"**：文件内容一个字都不变，`kb_read` 也照读，**只有 BOM 没了** ⇒
  不做字节级复核就永远发现不了。
* **它专打知识库**：本库的写入路径里有两条会碰文件 ——
  `_落盘结论.py`（保留原字节再追加 ⇒ **BOM 不丢**）与 **`edit` 工具（会丢）**；
  MCP `kb_write_page` 只在 `content` 不以 `\ufeff` 开头时补 BOM，**追加模式下用的是既有字节**。
* **和门禁同源**：与「查库留痕没人调用」「索引缓存从不命中」属于同一类问题 ——
  **规则写在文档里、动作发生在工具里，但没人核对结果**。

## 3. 实现·使用方法（照抄）

```bat
:: ① 看现在有多少页缺 BOM（含 I 项一行）
python 大鲸鱼产生专用\_自检.py --print

:: ② 补 BOM（可一次给多个页；复用现成工具，勿另写）
python 大鲸鱼产生专用\_落盘-补BOM通用.py "ai使用库\小暗的本地知识库\00-总览与规范\某页.md"

:: ③ 复核（必须做，别假定成功）
python -c "raw=open(r'<页路径>','rb').read(3); print('BOM' if raw==b'\xef\xbb\xbf' else '无BOM', raw.hex())"
```

## 4. 风险与边界

* **`_落盘-补BOM通用.py` 会同时把换行统一成 CRLF** ⇒ 若某页原本是 LF，改写后**全文行尾字节都变**
  （内容语义不变，但**文件哈希会变**）。要避免动行尾时，可只补前 3 字节。
* **不要为了补 BOM 而批量重写别人的页**（本库与 Codex 共用）⇒ 现只标 ⚠ 报数，**批量补需人确认**。
* **`edit` 之后必须复核 BOM** —— 这是目前唯一会静默破坏编码的常用动作。
