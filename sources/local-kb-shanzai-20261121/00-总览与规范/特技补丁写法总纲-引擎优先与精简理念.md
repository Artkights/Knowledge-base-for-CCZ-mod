# 特技补丁写法总纲 —— 引擎优先与精简理念（最高优先级）

> 用户口径 2026-10-18：「写法是根本，能写好为啥要写差」「结合你的库、反汇编知识、QQ 群新增写法，做一个新的逻辑规则和精简理念」。
> 本页**取代**此前“按体积分档”的口径（`特技补丁精简规范.md` 第 5 节已改为本页的 7 项检查表）。

## 1. 一句话理念

**补丁的价值 = 复用引擎已有逻辑的比例 ÷ 自己新增的字节数。**
写得越少、越靠引擎 ⇒ 越安全、越好测、越好回滚。自写逻辑不是在“实现功能”，是在“重新引入 bug”。

## 2. 五条根本原则

| # | 原则 | 反例（本工作区真实发生过） |
|---|---|---|
| 1 | **引擎优先**：先找现成判定/执行，只写“差异的那一步” | v1~v3 在洞里 `for slot 0..0xFF` 自己筛人、自己展开 `0x4D1400` 段表 ⇒ 672~768B |
| 2 | **单点挂钩**：一功能一挂点，多点必须写理由 | ★斩杀整合 11 段；HP-MP 7 段 |
| 3 | **参数立即数**：特技号/次数/阈值 = 补丁里 1 字节，代码与数据分离 | 常数编进洞体，换号要重出补丁（QQ 群两份就是 `-43D3B8` / `-43D0E9` 单字节） |
| 4 | **上下文即输入**：用 ctx 里现成的攻防双方，不扫战场 | 打完还在洞里重算攻方/防方 slot |
| 5 | **回滚同构**：正/反补丁段数相同、逐段对应 | 回滚缺段、需另算地址 |

## 3. 判定分层（写补丁前先走这棵树）

```
① 只是“数值改一改”？            → 型 A：改伤害链上的立即数（0 洞）
     参考：策略保底&限伤(≈90B)、无视策略减伤(≈50B)
② 是“谁有资格出手 / 出手几次”？   → 型 C：复用 0x438EBD（物理选人，表 0x415E2B 由 type 索引）
③ 是“出手动作换一种”？           → 只换执行器：物理 0x41058D ↔ 策略 0x41CECC
④ 以上都不是                     → 才允许自写；洞体 ≤150B，并在注释写明「已查 A/B/C，不采用原因 = …」
```

## 4. 现成零件表（照抄调用约定，别自己实现）

| 用途 | 地址 | 约定 |
|---|---|---|
| 物理攻击后选人（含存活/范围/次数） | `0x438EBD(攻击者单位, type)` | 表 `0x415E2B[type]` → 桩 → 值；结果填 `0x500EA5`；**末尾自己调 `0x41058D` 执行** |
| 循环驱动（type=0,1,…） | `0x4223A9`，上限在 `0x4223B2` `cmp al,N` | 加一项 = 表加一条 + N+1 |
| 范围形状 | `0x42E2B7`（eax=`0x42E2ED`）+ `0x4091F4(0x50,2,2,0)` | 由 `0x438EBD` 内部调用，自写时照抄调用序 |
| 存活/有效性 | `0x418C90` → 2 = 有效 | — |
| 阵营组 | `0x406710` → al（1=我方） | — |
| slot → 单位 | `0x4061F9` | **返回 ECX**，不是 eax |
| 查特效值 | `0x4101D9` | `push 0/0/0/<号>`；`ret 0x10`；每次调用前必须重设 ECX |
| 策略执行（带术前检查） | `0x41CECC(目标单位, 施法者单位, 策略号)` | 策略先手同路径（内含 `0x401DFF`/`0x412B30`） |
| 策略底层执行 | `0x4179B4(施法者slot, 目标slot, 策略号)` | `ret 0xC` |
| 物理列表执行 | `0x41058D(ecx=0x500EA5, 目标slot)` | 逐个 `0x435829` 并 `inc [unit+0x23]` |
| 单次攻击执行 | `0x435829(攻击方slot, 目标slot)` | `ret 8` |

## 5. 三型写法（按复杂度选，不要越级）

| 型 | 形态 | 体积 | 适用 |
|---|---|---|---|
| **A** | 只改立即数（1~8 字节，0 洞） | ≤8B | 阈值、上限、开关 |
| **B** | 单点 + 小洞：上下文直取 → 一次 `0x4101D9` → 一次执行器调用 | 30~64B | 单目标、单次触发 |
| **C** | 复用收集器 + 执行点按 type 分流 | 60~150B | 多人/范围/换执行方式 |

**判据**：能用 A 不用 B，能用 B 不用 C，能用 C 不自己写。

## 6. 安全边界（红线，违反即不合格）

1. 不碰 `0x43BC5A`（物理伤害公式函数体内 hook，实测必崩）。
2. hook 只能覆盖**整条指令**（5B `E8`→`E9` 可用；`55 8B EC 6A 00` 这种不行）。
3. **不使用 `[unit+0x23]` 当“我们自己的次数”**：它是引擎共享字段；要么按引擎语义用，要么自建表并注明。
4. 新桩/新表必须落在**已判洞的 `90` 区**，且过“判洞三步”（原始字节 / 4 字节引用普查 / 表形态）。
5. 写盘四件套缺一不可：**前像断言、写后复读、自反汇编全覆盖、段间不重叠**；写完立刻出回滚补丁。
6. 判“有没有生效”不许用“对话框消失/没报错”：必须有内存判据（MP、HP、`+0x23`、`0x500EA5`、`0x431200+slot` 之类）。

## 7. 七个检查项（每份补丁必须过）

1. 选人用 `0x438EBD`？ 2. 范围用 `0x42E2B7`/`0x4091F4`？ 3. 单挂点？ 4. 参数是立即数？
5. 复用执行器？ 6. 洞体无填充浪费？ 7. 回滚同构？

→ 全过 = 合格；5~6 = 记台账可接受；≤4 = **必须重写，与体积无关**。

### 1. 结论（数据）

- 63 份里 **38 份带洞体（>16B）**，其余是纯小改。
- 洞体最大段：**中位数 ≈120 B**，绝大多数落在 **50~200 B**。
- 最大的几份：`1195`（物理改造）、`723`（策略特效注入）、`573`（连击反击）、`512`（暴击预览）、`346`（多多益善）。
- **我们自己做的 768B（天发杀机 v7）/ 688B（移星易宿 v2 系）属于这份榜单的前 1%**，而功能复杂度只是中游。

### 2. 标准结构（高频形态，占绝大多数）

```
-XXXXXX          挂点 5 字节（E8 → E9，覆盖整条 call）
   E9 xx xx xx xx
-XXXXXX          洞体（30~200 字节）
   ...
-XXXXXX          参数 1 字节（特技号 / 阈值）
   NN
```

### 3. 由此补全的规则（写进第 2、3 节）

1. **“1 字节参数段”是社区标配**：特技号/阈值必须单独成 1 字节段（改号 = 改 1 字节）。
   我们的补丁里特技号是编进洞体的常量 ⇒ **违背第 4 项**。
2. **挂点 5 字节、只覆盖一条 call**；洞体 50~200 字节为常态。
3. **洞体 >300B 的参考件也有，但都是“整段流程替换”**（如物理改造 1195B），而且多数伴随 20+ 段；
   我们是“一个特技”却做到 688~768B，属于写法问题，不是功能复杂度。
4. 参考件常见 **“挂点 + 洞 + 参数”三段式**，回滚就是同三段反向 ⇒ 第 7 项（回滚同构）天然满足。

## 附二：重写洞体的强制核对流程（2026-10-18 闪退事故后新增，**P0 红线**）

> 事故：把「策略连击第二段伤害」重写为“等价版”时，`je` 落点算错 6 字节，开关=0 那条路漏掉
> `mov ecx,[ebp-0x10]` + `push [ebp-4]` ⇒ 后续公式少一个参数 ⇒ **进游戏闪退**。
> 根因：**手写跳转偏移，没有逐条对照控制流，也没有验证两条分支的栈平衡。**

### 强制四步（缺一步不许写盘）

1. **逐条映射表**：把原洞的每条指令列出来，逐条标“新洞对应哪条 / 或新增 / 或删除”。
   任何一条对不上，就不叫“等价重写”。
2. **跳转落点表**：每个 `jcc/jmp` 写成 `（指令地址 → 目标偏移 → 目标处第一条指令）`。
   目标处的第一条指令**必须写明是哪条**（例：`je → 偏移43 = mov ecx,[ebp-0x10]`）。
   禁止只写“跳回原逻辑”。
3. **两条分支的栈平衡**：对每个条件分支，分别累加 `push/pop/call(参数+ret)/add esp`，
   两条路径出口的 `esp` 必须相同，且与“被替换掉的原始指令序列”的净效果一致。
4. **离线执行轨迹**：用 capstone 把两条分支的指令序列打印出来，人工读一遍；
   发现“某条路径少一条 push”立刻停。

### 写盘前的自问三句

- 我这条 `je` 跳过去，落地的是**哪条指令**？（不能答“原逻辑”）
- 两条路的 `esp` 变化一样吗？
- 原版被吃掉的 6 字节，我在**每条**路径上都补齐了吗？

> 这三问答不上 = 不许写盘。用户口径 2026-10-18：「做精简的时候可以严谨一点吗，这是规矩，不然每次我都要不停闪退。」

## 附三：新特技「强检验」冲突清单（用户口径 2026-10-18，写盘前必过）

> 用户原话：「后续做新特技的时候，一定要考虑这些点或者内存是否冲突哦，强检验」
> 任何新特技补丁，**下面 7 项全部要有实测输出**，缺一项不许写盘。

| # | 检验项 | 怎么做 | 不做的后果（真实事故） |
|---|---|---|---|
| 1 | **挂点占用** | `_注入地址占用登记.py --check <VA> <len>`；现读前像逐字节比对 | 踩到并行补丁/旧版残留 |
| 2 | **洞区合法性** | 全 `90`；过判洞三步（原始字节 / 4 字节引用普查 / 表形态）；避开数据表容量区 | `.text3` 大零区曾是活跃表 |
| 3 | **特技号** | 名表行必须「预留/空」；引擎未用 `0x4101D9` 查过；两格相邻；把号写进 7 项检查表 | `0xF7/0xFC/0xFF` 已被查询，选中即冲突 |
| 4 | **共享字段** | `[unit+0x23]`、`0x500EA5`、`0x500C46` 等引擎状态**不得当自有计数**；自建表要放判过的洞区并初始化 | 用 `+0x23` 当次数 ⇒ 无限触发/被别的特技吃掉 |
| 5 | **参数段** | 特技号/次数/阈值一律 1 字节独立段，地址同样登记 | 换号要重出整份补丁 |
| 6 | **影子验证** | 补丁套在目标基线副本上算「预期 SHA」；写后 SHA 必须相等 | 写错段/前像不匹配 |
| 7 | **回滚同构** | 同段数反向，且回滚补丁先预演通过 | 出事无法撤 |

### 另加两条（本案新增）

8. **挂点方向要先用探针证伪**：同一效果可能有多个 `0x435829` 调用点（敌方物理攻击与反击不同路径）。
   先挂「命中标记」确认哪条真的执行，再写正式逻辑。**禁止**凭"看起来像"选挂点。
9. **桩/洞内的 `call`/`jmp` rel32 必须逐条核落点**（用 capstone 反汇编确认目标地址），
   曾因 `Q-(STUB+16)` 少算 3 字节直接崩。
