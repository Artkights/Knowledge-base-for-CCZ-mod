### ★ `status` 的 head 显示契约（2026-10-15 修，附一起真实误判）

**现象（我踩过）**：`status` 原先把 head 截成 **10 位**（如 `de63f2ed42`），
而本库惯例用 **8 位前缀**（如 `63f2ed42`）—— 两者**对不上**，
`de63f2ed4200…` 的**后 8 位**恰好是 `63f2ed42`（**掐头去尾**），
**我据此误判"远端有更新"**，实际远端与本地完全一致。

**修法（`_云端知识库订阅.py`，扩展现成工具）**：
1. head **一律显示 12 位 + `…`**，`status` 与 `fetch` **口径统一**；
2. `status` 每次**调 git commit 接口取远端 head 并与 `_state.json` 比对**，
   **直接打印判定**，不再让人（或 AI）肉眼比字符串：

```
上次抓取: 2026-10-15 23:22:56  head=de63f2ed4200…  files=26
远端 head=de63f2ed4200…   ✅ 与上次抓取一致（无更新）
```
判定只有四种：`✅ 与上次抓取一致（无更新）` / `★★ 远端已更新：A → B（请跑 fetch）` /
`★ 从未抓取过` / `远端 head 读取失败`。

> ★ **教训（可复用）**：**凡是跨工具/跨页引用同一个哈希或编号，
> 必须统一"截断长度 + 是否加省略号"，并在显示层直接给判定** ——
> 否则"两个字符串不相等"会被误读成"东西变了"。

## 风险与边界

1. **只读远端、只写 `_外部源码\_云端快照\`**；`_云端知识库订阅.py` **没有任何写 `Ekd5.exe` 的能力**。
   写 EXE 仍只走 `_dsh写锁.py`（AGENTS.md §3.5）。
2. **外部地址一律只作线索**，必须在本样本重新核对，**不得互套**（§3 版本护栏、§12）。
3. **报告不自动吸收结论**；吸收走 §2.5 门禁 + `逆向方法层-行为契约与五级证据.md` 的五级证据。
4. **`candidate` 状态条目不得作为自动写回依据**（对方 CONTRIBUTING.md 明文，与本库口径一致）。
5. **git 协议不可用**：`git ls-remote`/`clone` 走 `127.0.0.1` 代理必失败；若代理恢复需重测。
6. **API 额度**：未认证 60 次/小时。`fetch` 用整包 zip，**不要**改成逐文件 contents 拉取。
7. 云端文件 **UTF-8 无 BOM**，吸收进本地库必须**补 BOM**。
8. **`.cmd` 硬约束（2026-10-15 实测，违反则任务"成功但什么也没干"）**：
   **被调用/被引用的文件名必须纯 ASCII** —— 中文名在**写入那一刻**就被降级成 `?`，
   `.cmd` 里真的存着 `_????_run.py`，实跑报 `can't open file '...\_????_run.py' [Errno 22] Invalid argument`。
   ⇒ **`.cmd` 层全 ASCII，中文只允许出现在 Python 内部**。
   > ⚠ **已撤回的误判**：同轮一度把并发的 `'oud_kb.cmd' is not recognized` / `'II-ONLY' is not recognized`
   > 归因于「`.cmd` 必须 CRLF」。**对照实验证伪**：12 行纯 ASCII 的 **LF-only `.cmd` 同样正常执行**
   > （`_tmp_enc\d_lfmulti.cmd` / `e_crlfmulti.cmd` 实测均输出 `D-OK-LF-multiline`）。
   > CRLF 仍按既有约定保留（`_digest.cmd` = 12 CR/12 LF），**但它不是本次故障的原因**。
   > 教训：**同一现场的两个现象未必同因，必须做对照实验分离，不能合并归因。**
