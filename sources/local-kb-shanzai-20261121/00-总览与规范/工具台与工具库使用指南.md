## 八、踩坑：`.cmd` 启动器必须用 **GBK** 编码（★ 重要）

**现象**：桌面快捷方式打不开工具台；手动双击 `.cmd` 弹出一堆
`'权限檫…echo' 不是内部或外部命令`、`'\Amsg' 不是内部或外部命令` —— 全是乱码。

**根因**：`.cmd` 文件被写成了 **UTF-8**，而中文版 Windows 的 `cmd.exe` 按 **GBK(936)** 读取该文件。
文件里的中文（注释、`echo` 文字、甚至含中文的路径）在解析阶段就已乱码，
所以命令被拆错；而 `chcp 65001` 写在文件开头也**救不回来**——编码在解析前就定了。

**正确做法（二选一）**：

1. **`.cmd` 用 GBK 保存**（推荐）：
   ```powershell
   [System.IO.File]::WriteAllText($path, $text, [System.Text.Encoding]::GetEncoding('GBK'))
   ```
   并且**不要**在文件里写 `chcp 65001`，也不要放多余中文；
   脚本里只保留：`@echo off` / `cd /d "%~dp0"` / 设置 `PY` / 调用 python / `if errorlevel 1 pause`。

2. **干脆不用 `.cmd`**：把快捷方式**直接指向 python.exe** + 脚本路径：
   ```
   目标   : <python.exe 全路径>
   参数   : "[本地盘]\...\大鲸鱼产生专用\大鲸鱼工具箱.py"
   起始位置: [本地盘]\...\大鲸鱼产生专用
   ```
   **本工作区桌面快捷方式采用此法**（最稳，不受编码影响）。

**注意**：本机 `python.exe` 用的是 DSH 运行时路径：
`[本地盘]\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`
系统里的 `WindowsApps\python.exe` 只是 Microsoft Store 存根，**不可靠**，不要依赖它。

★ 同理：**`.bat` 也必须是 GBK**；而 Python 脚本本身用 **UTF-8**（Python 3 默认）。
两种文件编码规则相反，写启动器时最容易踩。

## 九、踩坑：**PyInstaller 打包的 exe 不能放在含中文/全角字符的路径**（★ 重要）

**现象**：在工具箱点「6.6扳手」→ 弹出
```
Fatal error detected
INTERNAL ERROR: cannot create temporary directory!
```
单独双击也一样。

**根因**：`6.6扳手.exe`（34.5 MB）是 **PyInstaller 单文件包**，
启动时要把自身解压到临时目录；而它所在的完整路径含**中文与全角冒号**：

```
[本地盘]\ccz\曹操传6.6-V7.30 解压密码：66\复刻版6.6山贼\ai使用库\扳手\6.6扳手.exe
                     ↑ 全角冒号 + 多层中文
```
PyInstaller 的 bootloader 处理不了这种路径 → 建临时目录失败 → 报上面的错。

**验证**（决定性证据）：
- 同一 exe 复制到 `[本地盘]\banshou_test\banshou.exe`（纯英文）→ **启动成功**
- 复制到 `[本地盘]\CCZTools\banshou\banshou.exe`（纯英文）→ **启动成功** ✓

**解决**：把这类 exe 放到**纯英文路径**。本工作区已建：

```
[本地盘]\CCZTools\
└── banshou\
    └── banshou.exe        ← 6.6扳手（工具箱里显示名仍是“6.6扳手”）
```

工具箱的 `EXT_TOOLS` 因此支持**绝对路径**（`os.path.join(ROOT, 绝对路径)` 会直接采用绝对路径）。

**排查同类问题的方法**：
1. 先看 exe 是不是 PyInstaller 包 —— 同目录常有 `*.spec`、`_MEI*`、`main.py`、`requirements.txt`；
2. 报错文本 `INTERNAL ERROR: ...`（PyInstaller bootloader 口吻）或 `install4j` 字样；
3. **把 exe 复制到 `[本地盘]\test\` 再试** —— 能跑就是路径问题，不是程序坏了。

**适用面**：凡是"打包成单文件"的工具（PyInstaller / install4j / exe4j / 部分自解压包）
都建议放英文路径；Delphi/C++ 编的（如 Resource Hacker、CczEditor）通常不受影响。

★ 附：扳手的源码就在 `ai使用库\扳手\`（`main.py` + `mywindow.py`，PyQt5 程序），
但它自带的 `.venv` **已失效**（`Failed to import encodings module`，虚拟环境指向的基础 Python 不在原位），
所以目前用打包版 + 英文路径。

## 十一、★ 工具库「工具总数」与磁盘 `.py` 为什么不相等（2026-10-25 01:5x 三方对齐坐实）

**症状**：`大鲸鱼专用工具库\README.md` 写「工具总数：**950** 个」，而 `os.walk` 数出来的 `.py` 是 **1110** ⇒ 看上去像索引漏登 160 个。**别去"修平"，这是口径不同。**

**实测判据（三方对齐，可复算）**：

```bat
python -X utf8 -c "import os;H=r'大鲸鱼产生专用';n=[f for f in os.listdir(H) if f.endswith(('.py','.cmd','.bat','.ps1')) and os.path.isfile(os.path.join(H,f)) and f!='__init__.py'];print('根级可归档=',len(n))"
```

- 磁盘 `.py`（13 个分类目录递归，排除 `__pycache__`）= **1110**
- 索引「工具总数」= **950**
- **根级可归档文件数 = 950** ⇒ 与索引**逐字相等**

**根因（代码点，非推论）**：`_归档工具源码.py:260`

```python
all_src = [f for f in os.listdir(HERE)
           if (f.endswith(".py") or f.endswith(".cmd") or f.endswith(".bat") or f.endswith(".ps1"))
           and os.path.isfile(os.path.join(HERE, f)) and f != "__init__.py"]
```

索引由 `groups_all`（= `all_src` 按分类分组）重建（`_归档工具源码.py:367` 起 `for cat in sorted(groups_all)` ⇒ `index.append(...)` ⇒ `:414` 写「工具总数：**len(index)** 个」）。
⇒ **索引数 ≡ 当次根级可归档数**；差额 = 「库里归档副本还在、**根级原件已被移走或删除**」的历史件
（归档是复制不是移动；静置 / 搬迁只动根级，库内副本留在原分类里不动）。

**由此得到两条可直接用的口径**：
1. 问「**现在还能跑哪些工具**」⇒ 看**根级**（`README-根级脚本索引.md`，键 `ROOTPY`）；工具库索引就是它的可归档子集。
2. 问「**库里存了多少份源码**」⇒ 数磁盘 `.py`（键 `TOOLPY`）。

⇒ 两个键 2026-10-25 已进 `大鲸鱼产生专用\_更新目录计数.py` 的 AUTO 回填，引用处
（`README-目录地图.md` §一 / §3b 第 51 行 / §五，`README-工作区布局.md` §七）只写成对注释，**不再手写数字**。
**校平判据** = `python -X utf8 大鲸鱼产生专用\_更新目录计数.py --check` 报 `[一致]`；
**不是** `TOOLPY == TOOLIDX`（按上面的口径那一条永远不成立，拿它当 bug 就会误"修"）。

⚠ 同型手写漂移实证：本页「结论速览」与末行「证据类型」原写「**594 个工具 / 14 分类**」（10-21 快照；
现读 = **13** 个分类目录、索引 950、磁盘 `.py` 1110），目录地图与布局页曾长期写「**1522**」。
⇒ **判定规则**：工具库数量只要**不是** AUTO 回填值（也没写现读日期），先当过期处理；
要引用就跑 `--check` / `--apply`，别再抄一遍数字。
