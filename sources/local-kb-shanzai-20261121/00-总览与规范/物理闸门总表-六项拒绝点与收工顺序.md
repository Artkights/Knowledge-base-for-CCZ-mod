## 结论速览

1. 写 `Ekd5.exe` 前：30 分钟内**能命中**的查库（`ok=true` + `hits>0` + 任务词匹配），零命中不放行。
2. 落盘结论：`--cite` 必须来自最近成功检索的 `hits_detail`（同页/同行/行全文哈希），或 `--no-hit`；否则零写入。
3. 交接：`交接-CAS/<task_id>.json` 是真相源；`交接.md` 与 `交接-当前.md` 必须 `samefile` 且 `nlink≥2`。
4. 归档：新脚本要有「已查 N 个/处 + 不采用」docstring + 24 小时内 `_复用留痕.jsonl`，否则 apply 拒绝且不复制。
5. 收工：`release --status done` 先过 `_收工门禁.py` 六条判据，失败拒绝写盘。
6. 固定顺序：**回归 → 严格自检 → 归档 → 交接页 → 台账 → CAS 收口**。

## 2. 固定收工顺序（照抄）

```bat
:: 0) 开场 / 换话题
python 大鲸鱼产生专用\_开工门禁.py --full --task "<任务关键词>"

:: 1) 回归
python 大鲸鱼产生专用\_测门禁闸门.py

:: 2) 严格自检（必须 0 ✗ 才继续）
python 大鲸鱼产生专用\_自检.py --json --strict

:: 3) 归档（新工具先出复用留痕）
python 大鲸鱼产生专用\_开工门禁.py --dup <主函数名>
python 大鲸鱼产生专用\_归档工具源码.py apply

:: 4) 交接页：覆盖式写入后校验硬链接
python 大鲸鱼产生专用\_交接CAS.py fix-link

:: 5) 共享台账：追加一行
::    走 kb__ledger_append（时间 | 谁 | 做了什么 | 证据 | 下一步）

:: 6) CAS 收口（会触发 _收工门禁.py）
python 大鲸鱼产生专用\_交接CAS.py update <task_id> <owner> <rev> --summary "…" --evidence "[...]"
python 大鲸鱼产生专用\_交接CAS.py release <task_id> <owner> <rev+1> --status done
```

> 顺序理由：回归与自检先证明工具没坏；归档把本轮改动留档；交接页和台账必须在 release 前更新，
> 否则 `_收工门禁.py` 会以“超过 120 分钟未更新”拒绝。

## 3. 交接硬链接（Q 项 + fix-link）

```bat
python 大鲸鱼产生专用\_交接CAS.py check     :: 只读：CAS JSON / 锁 / 临时文件 / 过龄 / 基线
python 大鲸鱼产生专用\_交接CAS.py render    :: 只读：打印 Markdown 预览，不写盘
python 大鲸鱼产生专用\_交接CAS.py fix-link  :: 取 mtime 较新的一份为真相，先备份再重建
```

- 断链判据：`os.path.samefile(交接.md, 交接-当前.md) == True` 且 `st_nlink >= 2`。
- `fix-link` 备份位置：`AI协作\_mcp写备份\交接链接修复_<时间>\`；完成后复核 `samefile` 与 `nlink`。
- **不采用 `fsutil hardlink list/queryfileid` 作为硬性判据**：`samefile` 已比较文件 ID，`nlink` 已查链接数，
  再加一层只是 Windows 专属的重复取证，收益低；需要人工取证时可用，但不进门禁。

## ★ L1 现行结论页「身份判据」合并为唯一实现（2026-10-24，闸门 #2 的前置条件收敛）

**改了什么**：同一件事（"这页是不是 L1 现行结论页"）原先有**三份独立实现**，
现已收敛为 `大鲸鱼产生专用\_ccz知识库判据.py:is_l1_page` 一份，三处调用方改为**委托**：

| 调用方 | 用途 | 现在怎么接 |
|---|---|---|
| `_落盘结论.py:_is_l1_page` → `verify_gate` | 写 L1 页前做现场复核（按**本页所属链** `--verify <链>`） | `from _ccz知识库判据 import is_l1_page` |
| `_自检.py` **P 项** | 报告 L1 页写死的"现读 EXE SHA"是否等于现样本 | 同一函数 + `declared_sha_loose()` |
| `_更新样本SHA闸门.py:discover_l1_md` | 自动发现并刷新 L1 页的现读 SHA | 同一函数 + `MD_SHA_RE`（只认 `>` 引用行） |

**故意保留的两个不同 SHA 口径**（不要"顺手合并"）：报告用宽口径 `declared_sha_loose()`
（页首任意含"现读/EXE SHA/SHA256/样本 SHA"的行）；**写盘**用窄口径 `MD_SHA_RE`，
只命中**行首 `>` 引用行** —— 因为正文靠后的历史版本表 `| … 64hex … |` 里也有 SHA，
整页 search 会**改错地方**。⇒ 身份判据统一 ≠ 写盘条件统一；写盘条件必须更严。
