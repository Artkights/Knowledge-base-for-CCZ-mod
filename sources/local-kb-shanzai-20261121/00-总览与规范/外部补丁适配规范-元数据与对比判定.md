# 外部补丁适配规范 —— 元数据、对比判定、可吸收清单

> 用户口径（2026-10-18）：
> 「**所有问题都这样深入解读处理一下，元数据要做，加入了也要对比的，因为这些不一定我们引擎就有这个代码**」
> 「**都对比一下，别人的写法优化我们的写法，不一定要用他们的东西，但是要反汇编处理**」

## 一、补丁元数据（已落地到 `_应用补丁通用.py`）

### 写法

```
#@risk engine_sha256 <64 位十六进制>
#@risk new_cave 0xADDR len=0xN reservation=0xR boundary=0xB
```

### 校验规则（分级，不阻止无害情况）

| 项 | 行为 |
|---|---|
| `engine_sha256` 与本样本不符 | **⚠ 只警告**（打印两边 SHA 前 12 位）——外部补丁基线通常不同，不能因此拒写 |
| 段长 > `len` | ❌ 拒绝写 |
| 段长 > `reservation` | ❌ 拒绝写 ← **防"以后扩写洞踩到后面的代码"** |
| 洞起点 `% boundary != 0` | ❌ 拒绝写 |
| 无元数据的老补丁 | 照常解析（已回归验证）|

### 为什么重要（今天的真实代价）

今天 14 个版本里有 3 次栽在同一个坑：**洞选址 / 洞扩写**。
`reservation` 与 `boundary` 这两条约束若一开始就有，能直接挡住：
- 洞放在 `call` 返回地址上（`0x441079` / `0x440F3D`）
- 洞放在连续 NOP 区里被顺序执行滑入（`0x440F70`）
- 洞扩写后与后面的代码重叠

> 外部参考：`【6.5】暴击伤害预览-F版专用` 的补丁头就带 `engine_sha256` + `preimage` + `new_cave len/reservation/boundary`。

## 二、对比判定工具 `_外部补丁适配检查.py`

```bat
python 大鲸鱼产生专用\_外部补丁适配检查.py "<补丁.txt>"
python 大鲸鱼产生专用\_外部补丁适配检查.py "ai使用库\6.6山贼注入特技情况"   :: 整个目录
```

对每段给出三种判定：

| 判定 | 含义 | 能否直接用 |
|---|---|---|
| **已装** | 现读 == 补丁新字节 | 功能已在，无需再打 |
| **干净可打** | 现读 == 补丁前像 | 可以打 |
| **不同** | 两者都不等 | ❌ **禁止直接打**；该地址上是别的构建的代码或其他补丁的改造，必须先在反汇编里确认语义 |

### 策略破坏能力的"不同"是**参数没启用**

| 段 | 补丁 | 本样本 | 判定 |
|---|---|---|---|
| `0x42305E` 挂点 / `0x42E3B0` 洞 / `0x45D4AF` 起始号 | — | 相同 | ✅ 已装 |
| `0x45D4B8` 辅助函数 | 另一版实现 | — | 版本差 |
| `0x45D4AB` 宝物号 | `00` | `01` | 参数不同 |
| **`0x45F4C2` 特效数量** | **`03`** | **`00`** | ★ 数量 0 ⇒ **7D~7F 未分配** |

但 `0x4CC600` 的 `0x7D~0x7F` 现在被 **「深策缚影」**（flag `0x0A`）占着 ⇒ **要启用得先腾号**。

## 四、位宽对照（重要，避免以后误判）

| 来源 | 位数 | 全开 | 编码 |
|---|---|---|---|
| `6.5辅助五维单特技` | 5（攻防精敏士）| `0x1F`(31) | **裸位** 1/2/4/8/16 |
| `策略破坏能力` | 6（攻防精爆士移）| `0x3F`(63)，`0x40`=64 随机 | **裸位** 1/2/4/8/16/32 + 64 |
| **我们的 0x0C** | 6 | `0x41/42/44/48/50/60`、`0x7F` 全开 | **`0x40` 前缀 + 位** |

**我们为什么加 `0x40` 前缀**：为了和"随机模式 `0x01~0x3F`"划界（`<0x40` 走随机 N 项，`>=0x40` 走位掩码）。
⇒ 两种编码都成立。**看外部补丁时不要以为我们错了**。
