## 结论速览

1. **旧口径「借洞一律禁止」作废**。三条实测理由见「作废记录」；真正的失败边界是**挂点选错 / 指令边界被吃掉 / 寄存器契约被破坏**，不是"借洞"这个形态。
2. **风险阶梯**：改立即数（安全）→ 空位搬移（中低）→ 内联桩（中）→ **借洞塞函数 + `JMP`（条件放行）**。
3. **放行 = 四组门槛全过**：精简（≤150B / 7 项检查表 / 无填充浪费）→ 挂点（整条指令 / 入边唯一 / 洞内线性 / 契约还原 / 影响面最小 / 黑名单）→ 洞（判洞三步 / 边界 / 占用登记 / 工作基底）→ 验证（前像 + 写锁 + 复读 + 无调试器判崩 + 1→5 回合）。
4. **不是"改字节 vs 塞代码"，是"挂点选对没有"**：库内 5 件成功实例**全部**是函数体内点，**没有一个**是函数入口。
5. **精简规则本身没错，错的是执行没跟上**：社区同类 50~90B，我们在装的洞是 240/467/512/688/768/949B —— 5~10 倍。

## 四组门槛（照 `AGENTS.md` §3.6.2 执行，此处只列判据要点）

**第一组·精简（最高优先级）**
- 价值 = **复用引擎逻辑的比例 ÷ 新增字节**（总纲 §1）；
- 洞体目标 **≤150B**；**>300B 必须逐条点名**「已查 `0x438EBD`/`0x42E2B7`/`0x4091F4`/`0x41CECC`/`0x41058D`，不采用原因 = …」；
- 过总纲 §7 **7 项检查表**，≤4 项 = 重写（与体积无关）；
- **代码结束即止**，尾部仅 `90` 对齐，**不留大块填充余量**（要扩写就重新 claim 新洞）。

**第二组·挂点**
- 覆盖区间 = **整数条完整指令**，区间内无任何 `jmp`/`jcc` 目标落点；
- **入边唯一**（只能顺序流进入；不得"从前面跳来、落在后面"）；
- **洞内线性**，每个 `jcc` 两条分支分别算栈平衡；
- **回跳前还原寄存器/标志位 + 原指令副作用**（原指令 `call 0x41932B` 就得复现它清 `ECX/EDX`）；
- **优先影响面最小的点**，不用"函数入口优先"；
- **黑名单先查表排除**：`0x43BC5A` 族（`0x43BD06/0x43BDC7/0x43BE7C/0x43BEA0/0x43BEE8/0x43BF0E/0x43BF1C`）、`0x405DE1` 内两处。

**第三组·洞**
- 判洞三步（**第②步必须按指令边界对齐**，用 `_tmp判洞三步-对齐版.py`）；
- 起点是合法指令边界（`_tmp验洞边界.py`），洞尾之后是下一函数序言；
- `python 大鲸鱼产生专用\_注入地址占用登记.py --check <起址> <长度>` 报「空闲」；生成器自动 `claim`；
- 扫洞的"干净"= **与当前工作基底 SHA 一致**（`2B279F3F…`），不是出厂原版 `6929FE0D…`。

**第四组·验证（不可省）**
- 前像逐字节断言 → `_dsh写锁.safe_write_exe`（备份 `edk5（N）<补丁名>`）→ 写后复读 → 自反汇编 → 段间不重叠 → 立刻出回滚；
- **判崩必须无调试器**（§6 的 x32dbg 只管取证，两者不能同时）；
- 单次调用驱动 + `pid_of` + `Responding`；与干净版同存档同流程对照；
- 首次上洞 **1 回合** → 过 ⇒ **直接 5 回合**；硬上限 5，禁止叠加 batches。

## 与「精简规则」的关系：哪些改、哪些不能改

| 类别 | 条目 | 结论 |
|---|---|---|
| **该改** | 「借洞一律禁止」 | ✅ 作废（本页） |
| **该改** | 「精简 = 少做查证」的误读 | ✅ 改为：**已带 SHA 固化的库内事实不必重新推导**；同函数/同挂点/同基底可复用上次判洞留痕；换建构/换挂点才重做 |
| **该改** | 路线风险评级里的「型 C 中高」 | ✅ 降为**中低（风险取决于挂点，不取决于洞）** |
| **不能改** | 四条不可省（现读字节 / 前像断言 / 写锁备份 / 实跑判据） | ❌ 一字不动 —— 它们是借洞能安全试错的**前提** |
| **不能改** | 判崩必须无调试器 + 干净版对照 | ❌ |
| **不能改** | 写 EXE 只走 `_dsh写锁.py` | ❌ |
| **不能改** | 5 回合硬上限 / 不碰剧本存档 | ❌ |

**一句话**：**"精简" = 少做无关查证与重复推导，不是少做写盘前的现场断言。**
