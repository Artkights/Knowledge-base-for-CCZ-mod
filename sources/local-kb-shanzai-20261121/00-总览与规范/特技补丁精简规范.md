# 特技补丁精简规范（最高优先级，2026-10-18 用户口径）

## 1. 结论速览

1. **判据不是“能不能写”，而是“洞体多少字节”**：社区成熟补丁（`[本地盘]\qq\qq群\`）同类效果普遍 **50~90 字节**；
   我们自己写的动辄 672~768 字节 ⇒ 说明在**重写引擎已有的东西**。
2. **三条硬规则**：① 能用引擎判定就不自己写（选人 / 范围 / 存活 / 次数）；② 特技号、次数一律做成**单字节立即数**；
   ③ 洞体目标 **≤150 字节**，超过必须写出“为什么引擎现成的不能用”。
3. **优先级高于其它纪律**（用户 2026-10-18：「这不是纪律了，是最高优先级」）。
4. 先按本规范写新补丁；存量补丁按《存量清单》逐个精简，**一版一测**。

## 3. 复用地址表（写补丁前先查这张表）

| 存活/有效性 | `0x418C90`（返回 2 = 有效） | — |

| slot → 单位 | `0x4061F9`（返回 **ECX**） | — |

## 4. 写补丁的固定流程

```
① 先查本页第 3 节：这件事引擎有没有现成的？
② 有 ⇒ 只挂一个点 + 单字节立即数参数，洞体 ≤150B
③ 没有 ⇒ 才允许自写；且必须在补丁注释里写明「已查 0x438EBD/0x42E2B7/0x4091F4，不采用原因 = …」
④ 前像 + 复读 + 自反汇编 + 段间不重叠 四项齐全才允许写盘
⑤ 写盘后立刻出回滚补丁
```

## 5. 判定检查表（**与体积无关**，任一不过 = 要重写）

> 用户口径 2026-10-18：「不大于就没有精简空间了吗，优化写法对你来说不也是一种提升吗」
> ⇒ **体积只是信号，写法才是判据。** 小补丁同样要过这张表。

| # | 检查项 | 通过标准 | 常见反例 |
|---|---|---|---|
| 1 | 选人是否用引擎 | 物理反击类必须走 `0x438EBD`（含存活/范围/次数） | 洞里 `for slot 0..0xFF` 自己筛 |
| 2 | 范围是否用引擎 | `0x42E2B7` + `0x4091F4` | 自己展开 `0x4D1400` 段表（100+ 字节） |
| 3 | 挂点数量 | 单点挂钩；非要多点时必须写明理由 | 同一功能挂 2~3 处（前像/回滚都翻倍） |
| 4 | 参数是否单字节立即数 | 特技号/次数/阈值写成补丁里的 1 字节 | 常数编进洞体，换号要重出补丁 |
| 5 | 是否复用执行器 | 策略 → `0x41CECC`；物理 → `0x41058D` | 洞里自己拼列表再调底层 |
| 6 | 洞体是否无填充浪费 | 代码结束即止；尾部 `90` 仅对齐 | 每段补 16 字节对齐造成碎片 |
| 7 | 回滚是否与正补丁同构 | 同段数反向即可 | 回滚缺段、需另算 |

**评分口径**：7 项全过 = 合格；过 5~6 项 = 可接受但记台账；≤4 项 = **必须重写（与体积无关）**。

**体积只作排序信号**：社区同类 50~90 B；我们合格线 ≤150 B；>300 B 基本可断定第 1、2 项没做。
