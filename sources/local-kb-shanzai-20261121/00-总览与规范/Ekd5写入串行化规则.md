# Ekd5.exe 写入串行化规则（强制）

> 用户口径（2026-10-14）：**先串行化**。多个助手/脚本/会话可能同时改同一个 `Ekd5.exe`，
> 必须强制互斥，否则补丁基线错位、互相覆盖。

## 结论速览

| 编号 | 规则 |
|---|---|
| **W1** | **任何写 `Ekd5.exe` 的操作必须通过 `大鲸鱼产生专用/_dsh写锁.py` 的 `safe_write_exe()`**；禁止直接 `open(EXE,'wb')` 或 `shutil.copy2(bak, EXE)` |
| **W2** | 写入前必须做三轮校验：**游戏进程未运行** → **跨进程写锁可用** → **目标 SHA 匹配** |
| **W3** | 写入必须**自动备份 + 写后复读比对**，并追加审计行到 `大鲸鱼产生专用/_写入审计.log` |
| **W4** | 发现锁被占用时**必须报错退出**，不得强制抢占；确需解锁由人执行 `_dsh写锁.py release` |
| **W5** | 完成后必须**重新生成 `_改动总账.md`**（`python 大鲸鱼产生专用/_改动总账.py`），让事实集跟上 |
| **W6** | **测试注入补丁的备份命名 = `edk5（N）<补丁名>`**，`N` 从 **1** 起**自动递增**（用户口径 2026-10-19）。全角括号、小写 `edk5`、**不带 `.exe`**；`N = max(已有)+1`；补丁名自动清洗（去扩展名/非法字符）。**旧 `backup_prefix` 默认被忽略**（打印一行提示），逃生门 `DSH_LEGACY_BACKUP=1` |

### W6 细节（2026-10-19 落地）

- **用户原话**：「每次测试注入补丁edk5保存备份的命名规则为：**edk5（1）+对应补丁的名字**，
  然后下一个就改（）中的为**2**。以此类推」。
- **实例**：`edk5（1）斩杀攻击v1` → `edk5（2）奋战攻击次数` → `edk5（3）特技叠加面板`。
- **实现**：`_dsh写锁.py` 的 `next_backup_name()` / `clean_patch_name()`；
  `safe_write_exe()` **默认强制**该命名（`ENFORCE_NEW_NAMING = not os.environ.get("DSH_LEGACY_BACKUP")`）。
- **为什么默认强制**：本工作区有 **139 处** `safe_write_exe()` 调用、其中 **~30 处**显式传了旧
  `backup_prefix="Ekd5.exe.bak_before_xxx_"`。逐个改文件既慢又易漏 ⇒ 在写锁里统一忽略旧前缀。
- **预览下一个名字**（不写盘）：`python 大鲸鱼产生专用\_dsh写锁.py backup-name "<补丁名>"`。
- **沙箱自检（2026-10-19 实测，未碰真实 EXE）**：临时目录伪造 `Ekd5.exe`，
  ① 不传前缀 → `edk5（1）斩杀攻击v1`；② **传了旧前缀 → 仍被强制成 `edk5（2）奋战攻击次数`**
  （并打印「已按新命名规则忽略旧前缀」）；③ 第三次 → `edk5（3）特技叠加面板`；
  且每份备份内容 = **该次写入前**的 EXE 字节（`OLD-EXE-BYTES` / `NEW-BYTES-1` / `NEW-BYTES-2`）。
- ⚠ **历史备份不追溯改名**：`Ekd5备份\补丁前备份\` 里现有的
  `Ekd5.exe.bak_auto_<时间戳>`（约 610 个）保持原样，规则只约束**新**备份。

- 对抗测试（`大鲸鱼产生专用/_写锁自检.py`）验收通过：
  - holder 进程持锁 8s 期间，另一进程取锁 → **被正确拒绝**（提示持有者 pid/用途/时间）；
  - holder 释放后 → 另一进程**取锁成功**；
  - 游戏运行中调用 `safe_write_exe` → **被拒绝**（"游戏正在运行，拒绝写 Ekd5.exe"）。

## 实现·使用方法

```python
# 推荐：唯一写入口（进程检查 + 锁 + SHA 校验 + 备份 + 复读 + 审计）
import importlib.util, os
spec = importlib.util.spec_from_file_location("_dsh写锁", r"大鲸鱼产生专用\_dsh写锁.py")
W = importlib.util.module_from_spec(spec); spec.loader.exec_module(W)
ok, msg = W.safe_write_exe(new_bytes, "补丁名称", target_sha="FA14F84C…")
```

```bat
:: 命令行
python 大鲸鱼产生专用\_dsh写锁.py status     :: 看锁
python 大鲸鱼产生专用\_dsh写锁.py log        :: 看审计
python 大鲸鱼产生专用\_dsh写锁.py release    :: 强制解锁（确认无人写入时）
python 大鲸鱼产生专用\_写锁自检.py try       :: 自检：尝试取锁应被拒
```

- 锁文件：`大鲸鱼产生专用/_dsh写锁.lock`（含 pid / 用途 / 时间 / 目标 SHA）
- 审计日志：`大鲸鱼产生专用/_写入审计.log`（每行：时间 / 用途 / SHA 前后 / 字节数 / pid）
- 陈锁（持有进程已死）自动接管；存活且未超时 → 拒绝写入。

## 风险与边界

- 本锁只保护**走本模块的**写入者。外部手工编辑、Resource Hacker 写回、其它工具直接写盘**不受保护**。
  → 人工操作前先 `_dsh写锁.py status` 确认无锁。
- 游戏运行中改 exe 会被拒绝（文件也可能被锁）；**必须先完全退出游戏**。
- 锁文件是"软锁"，不做内核级独占；跨机器/跨用户不生效。

## ★ 2026-10-25 纠正：僵尸判据改为「线程=0」；这批僵尸**用户态杀不掉**

- **实测样本**：11 个残留 `Ekd5.exe`（2026-10-24 16:37 起陆续产生），`HasExited=True`、
  **线程=0**、句柄=0、各占 20 K；活进程 23116 为 16 线程。
- **杀不掉（三条证据）**：`taskkill /F` 与 `TerminateProcess(PROCESS_ALL_ACCESS)` 均返回
  拒绝访问（err=5）；`NtTerminateProcess` 返回 **0xC000010A（STATUS_PROCESS_IS_TERMINATING）**；
  用 `NtQuerySystemInformation(class 64)` 枚举句柄表，对这些 pid 开出的句柄 **Object=0**
  ⇒ 内核对象已拆、只剩空壳 PID。**用户态无解，只能重启清除**（不占 CPU/内存，不影响游戏）。
- **旧判据漏判**：`_ekd5_procs()` 原以「`OpenProcess` 失败」判僵尸，而这批 `OpenProcess`
  **会成功** ⇒ 全部被当成活动进程 ⇒ `game_running()` 恒 True ⇒ `safe_write_exe()`
  **永久拒绝写入**（不是"游戏正在运行"，是残留）。
- **已修 `_dsh写锁.py`**：
  ① 僵尸判据 = **线程数 == 0**（辅以 OpenProcess 失败）；
  ② `game_running()` 只统计**线程 > 0** 的实例；
  ③ 全僵尸文案改为「只能重启清除」。
- **口径**：「打不开 ≠ 僵尸」，**先看线程数**；真正的映像锁由写入路径的
  `open(EXE,'r+b')`（`probe_writable()`）兜底，所以忽略僵尸不会放过"游戏真在跑"的情况。
