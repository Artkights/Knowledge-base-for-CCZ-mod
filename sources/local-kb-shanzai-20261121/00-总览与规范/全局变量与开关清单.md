## 3. 实现·使用方法

- **判"某全局是否被写"** ⇒ 三层都查：① 绝对 `mov` 系；② 绝对**读改写**（`80/81/83`×modrm、`FE/FF`×`05/0D`）；③ **装入寄存器**（`mov reg,imm32` / `lea`）⇒ 三层皆空才写"EXE 内无操作数形式写入者" ✓（§103）
- **判"变动性"** ⇒ 至少**六次采样带时间基线**：Δ 恒定 = 时间/帧驱动；Δ 偶发 = 事件驱动；Δ=0 且隔久才变 = 低频事件；恒 0 且无写入者 = 未用槽 ✓（§112）

## 4. 风险与边界

- **场景依赖**：`0x4AC63C`、`0x505FA4` 在标题页与战场**取值不同** ⇒ 判"战斗逻辑是否执行"必须**在战场读** ✓
- **MOD DLL 可直接写引擎全局** ⇒ "无写入者 ⇒ 恒为某值"的推理**只在 EXE 内成立** ✓
- 本清单是**滚动更新**的：新发现的全局请追加到本页（并在 `更新记录.md` 留行）✓

## 2026-10-27 当前 6.6：phase/回合缓存与选中单位编号投影（静态补证）

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B；备份 183、补丁 64。本节仅离线原始字节/反汇编，未启动游戏、未附加 x32dbg，未写 EXE、RS 或 SV。

### 1. 回合字节与 phase 是两条独立门

- `0x4B3D08+2=0x4B3D0A` 是当前回合/行动方字节的现行读点：`0x411694` 直接读取它并加 1，`0x4170CF` 将其作为参数传给 `0x40B922`；`0x417127` 是 `0x4B3D0B`（回合上限/计数字节）的唯一绝对写点。
- `0x4B3D18` 是独立的 phase 字节。当前样本中 `0x4024CC`、`0x41BC53`、`0x420B14`、`0x425331`、`0x430D92`、`0x430DAD`、`0x43B50C`、`0x47510B` 直接读它；这些读点分别参与单位计数、坐标/移动目标分支、状态返回、AI 命中率门和阶段表分派，不能把 phase 当回合计数。
- 已装的 `0x430D80` 例程同时快照 `byte[0x4B3D0A]` → `byte[0x430B06]` 与 `byte[0x4B3D18]` → `byte[0x430B07]`；任一变化就对 `0x430C00..0x430CF9` 执行 `rep stosb` 清零（`ECX=0xFA`，250 字节）。这证明“回合/行动方 + phase”是次数表刷新键，但不证明游戏推进时两者的先后顺序。

### 2. phase 直接串入角色战场字段

- `0x41BC4A`：`unit+0x0E==7` 或 `phase==0` 时取 `unit+0x06` 坐标；否则调用 `0x407BF6(1)` 取另一坐标源，再把坐标送入 `0x428DF1`，即 phase 改变单位移动/目标坐标来源。
- `0x420B08`：同样先检查 `unit+0x0E==7` 与 `phase==0`；非零 phase 分支把 `0x407BF6(1)` 的结果和调用方 `+0x06` 位置交给 `0x41F637`，失败返回 `0xFF`，成功返回单位 `+0x04` 字节。该返回值不能直接命名成 Data 号。
- `0x4024AA` 计数帧在 `unit+0x0E!=7`、`phase!=0`、且返回字节不等当前调用槽时才递增计数；这是“编号+控制字段+phase”联合门，业务名称仍待动态。
- `0x425325` 先检查共享门 `0x505FDC`，再以 `phase>=2` 分支；phase<2 时按输入 AL 归一化，phase>=2 时改用 `[0x4B5DF0]` 与当前 `[unit+0]` 比较。这是选中单位 Data 快照参与 phase 分支的静态证据。

### 3. 选中单位的两个全局投影，不能混称

- `0x406240` 是位于 `0x4061F9`（slot→U）之后的独立无栈叶子，指令为：
  ```
  and  byte [ecx+0x24],0x7F
  mov  eax,[ecx]                 ; U[0]，Data 号载体
  mov  [0x4B5DF0],eax            ; Data 号 dword 快照
  mov  [0x500AC0],ecx            ; U 指针快照
  ret
  ```
  当前 4 个直接调用者为 `0x43AD8F`、`0x43D51B`、`0x43DE46`、`0x44EA07`。因此 `0x4B5DF0` 应写作“最近一次登记单位的 `U[0]` Data 号快照”，`0x500AC0` 才是“最近一次登记的 U 指针”；旧的“`0x4B5DF0` 是上下文对象指针”口径作废。
- `0x421D8D` 先由输入槽调用 `0x4061F9`，再用 `dword[0x4B5DF0]` 与 `[U]` 比较；`0x425342` 也用同一比较结果分派。这两处把 Data 号快照用于选中/当前单位身份比较，但没有把 `0x4B5DF0` 当 U 指针解引用。
- `0x4B5DDB` 的两处写入口仍保留“编号投影”命名：`0x43D655→0x43D658` 写入 `byte[U+0x04]`，`0x455418→0x45541B` 写入选择入口参数；读取/传递点包括 `0x4543EA`、`0x45441D`。由于 `U+0x04` 还被 `0x445D72` 用作 `0x4930C8 + value*4` 集气索引，当前静态只能确认“U+0x04 的全局投影”，不能把它无条件等同于 `0x4061F9` 的表槽号；动态交接必须同时记录表槽、`U[0]`、`U+0x04`、`0x4B5DDB`。

### 4. 动态交接最小判据（本节不执行）

- phase/回合：动作前后同时读 `byte[0x4B3D0A]`、`byte[0x4B3D0B]`、`byte[0x4B3D18]`，并观察 `0x430C00+slot` 是否仅在前两者任一变化后清零。
- 编号投影：在同一选中单位上记录 `slot → U=0x4A7B20+slot*0x30 → U[0] → R=[0x4CEA00]+U[0]*0x48`，再对照 `U+0x04`、`0x4B5DDB`、`0x4B5DF0`、`0x500AC0`。任何一项不一致都只能写“投影关系待定”。
- 依据仍是 `_42结束回合.py --probe` 的 `field_w/phase/enemy_alive/ours_ready/sw4018`，并附 `4018=1`；本轮不做动态判定。

## 2026-10-27 当前 6.6：选中单位三组全局投影的静态读写分类

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B。本节只做原始字节、`xref` 和调用点复读，没有启动游戏、没有附加 x32dbg、没有写 EXE、RS 或 SV。

### 1. 已闭合的写入方向

- `0x406240` 是叶子写入器：先执行 `and byte [ECX+0x24],0x7F`，再把 `[ECX]` 写入 `[0x4B5DF0]`，把 `ECX` 写入 `[0x500AC0]`。因此这里的两个投影分别是“最近登记单位的首 dword/DataID 快照”和“最近登记单位 U 指针”。
- `0x43D655→0x43D658` 把当前对象 `[U+0x04]` 的字节写入 `[0x4B5DDB]`；`0x455418→0x45541B` 则把选择入口的 `[ebp+8]` 低字节写入同一全局。两者都是写入，不是读取。
- `0x406240` 的 4 个直接调用者仍为 `0x43AD8F`、`0x43D51B`、`0x43DE46`、`0x44EA07`。静态上只能确认它们把某个对象登记为“最近单位”，不能据此命名成某一个 UI 动作。

### 2. 已闭合的读取/消费方向

- `0x4543EA` 读取 `[0x4B5DDB]` 到 `CL`，随后调用 `0x4061F9` 得到 U，再用 `0x406710` 的返回值做比较；`0x45441D` 把同一全局值作为参数继续传递。这里的 `0x4B5DDB` 是索引/投影输入，不是 DataID dword。
- `0x425342` 在 `phase>=2` 分支读取 `dword[0x4B5DF0]`，与当前对象 `[ECX]` 比较；`0x421D8D` 也把输入 slot 经 `0x4061F9` 后与该快照比较。两个读取点都把 `0x4B5DF0` 当作 DataID 快照使用，没有把它当 U 指针解引用。
- `0x419D7B` 读取 `dword[0x500AC0]` 后访问 `[U+0x04]`，与 `0x406240` 的写入契约一致；因此 `0x500AC0` 的类型可以静态定为 U 指针快照，而不是 DataID 标量。
- 当前原始 `xref` 共见 `0x4B5DDB` 4 个直接操作点、`0x4B5DF0` 36 个指令内引用、`0x500AC0` 11 个指令内引用；其余引用若要给出具体业务名称，仍需按各自函数帧继续分流，不能把所有引用统一归为“选中单位”。

### 3. 当前静态判定边界

`0x4B5DDB`、`0x4B5DF0`、`0x500AC0` 是三种不同宽度/类型的投影：字节索引、DataID 首 dword 快照、U 指针快照。当前静态已经闭合主要写入者和关键消费点，但尚不能证明它们在每次选择、移动、重建或行动时都同步更新。

动态交接时仍需同帧记录 `slot → U → U[0] → R`，并对照这三个全局值；只有出现 `0x4B5DF0 == U[0]`、`0x500AC0 == U` 且 `0x4B5DDB` 与对应投影输入一致，才能把“当前选中角色”的关系升级为运行时闭环。

## 2026-10-27 当前 6.6：`0x501BF9` 与 `0x501B00+0xF9` 同址、行动阶段与 U+0x0D 的交互

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B。本节只读复核当前镜像，没有启动游戏、没有附加 x32dbg、没有写 EXE、RS 或 SV。

### 1. 同址关系

`0x501B00 + 0xF9 = 0x501BF9`。因此当前样本中的 `0x501BF9` 不是一块独立于 `0x501B00` 的存储区，而是同一 `0x500` 字节状态工作区的第 `0xF9` 个字节，同时被部分路径当作行动/阶段标记读取和写入。

当前原始引用共 11 处，静态写值集合为 `{1,2,5,6,FF}` 加动态 `AL`：

- 写入 `6`：`0x417D4F`；
- 写入 `1`：`0x43ACBF`；
- 写入 `2`：`0x43B314`；
- 写入 `FF`：`0x43D50F`、`0x44AD4A`；
- 写入 `5`：`0x465FE8`、`0x467CFE`；
- 动态写入：`0x43DEFB`；
- 读取：`0x4125DC`、`0x44A5DE`。

### 2. 与行动阶段和 U+0x0D 的静态交汇

- `0x43DEFA` 是中心分派：`AL=1` 进入 `0x43DADA`，`AL=2` 进入 `0x42C177`，`AL=3` 进入 `0x40A985`，`AL=4` 调 `0x442718` 更新 U/对象的 `+0x0D` 掩码，`AL=5` 进入 `0x467C9E`，失败时再走 `0x423358`，`AL=6` 进入 `0x41D693`，`AL=7` 进入 `0x4151FE`，`AL=FF` 返回阶段循环。
- `0x44A5DD` 读取该字节；当值为 2 时进入 `0x497AF8` 策略槽匹配，值为 1/5/6 时进入不同对象、策略或队列分支。
- `0x4125DA` 把该字节和调用者 AL 比较，并结合 `0x4B5DF0` 的 DataID 快照参与阶段门。因此，`0x501BF9` 同时连接“阶段标记”和“当前选中角色快照”消费。
- `0x43D50F`、`0x44AD4A` 写入 FF 后分别进入后续行动/阶段收尾路径；FF 是共享哨兵，不能静态命名为某一个特技或只属于二次行动。

### 3. 当前静态边界

可以确认：`0x501BF9` 是 `0x501B00` 状态工作区内的共享阶段字节，且某些阶段分支会经 `0x442718` 触碰 U+0x0D。不能把它独立命名为表外全局，也不能把每个值直接映射为一个产品层特技。

动态交接时需要同帧记录 `byte[0x501BF9]`、同一 U 的 `+0x0D`、`0x4B5DF0`、`phase`、`0x501B00+index` 和动作前后状态；测试前固定 `4018=1`。只有看到同一动作中阶段字节变化与 U+0x0D 写入的调用链对应，才能升级为运行时阶段关系。


## 2026-10-27｜选中单位投影消费细化：`0x4B5DDB` 在不同路径的输入类型分流

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`。本节只读复核当前镜像，未启动游戏、未附加 x32dbg，未写 EXE、RS 或 SV。

- `0x421D8D` 遍历 `0x4AC748` 的目标 slot 字节表；每项经 `0x4061F9` 得到 U，再比较 `dword[0x4B5DF0]` 与 `[U]`（U[0]/DataID）。因此它是“目标 slot→U→DataID 与当前快照相等性”的明确消费者，返回 `1/0/FF` 取决于命中、未命中和终止哨兵。
- `0x425342` 在 `phase>=2` 且 `0x505FDC==0` 时，把 `dword[0x4B5DF0]` 与当前对象 `[ECX]` 比较；phase<2 则使用输入 AL 归一化后调用 `0x407BF6`。这里 `0x4B5DF0` 仍是 DataID 快照，不是 U 指针。
- `0x4543EA` 先从当前 U 经 `0x406710` 得到分类/阵营结果，再把 `byte[0x4B5DDB]` 放入 CL 调 `0x4061F9`，对该投影解析出的另一个 U 再调 `0x406710` 比较。故在这条消费路径中，`0x4B5DDB` 被当作 battle slot 输入。
- 但 `0x43D655→0x43D658` 的写入源是某个对象的 `U+0x04`，`0x455418→0x45541B` 的另一写入源是选择入口参数低字节；所以静态不能把 `0x4B5DDB` 在所有场景无条件命名成 slot，也不能把它永远等同于 U+0x04。它是一个跨路径的字节投影，具体含义由父帧决定。
- `0x419D7B` 读取 `dword[0x500AC0]` 后访问 `[U+0x04]`，再处理 `0x4AC748` 目标表；这进一步证明 `0x500AC0` 是 U 指针快照，不能拿它与 `0x4B5DF0` DataID 快照互换。

### 对编号闭环的更新判据

- 静态闭合：`0x4B5DF0 = 最近登记 U 的 U[0]`，`0x500AC0 = 最近登记 U 指针`；`0x4B5DDB` 在至少一个消费点被当作 slot，在至少一个写入点来自 U+0x04。
- 动态只需验证投影是否在具体父帧中一致：同一时刻记录 `slot/U/U[0]/R/U+0x04/0x4B5DDB/0x4B5DF0/0x500AC0`，并在 `0x4543EA/0x421D8D/0x425342/0x419D7B` 对照读取结果。

## 2026-10-27 当前 6.6：`0x45533D` 父帧收口 `0x4B5DDB` 的 slot 投影

> 样本绑定：当前 `Ekd5.exe` SHA256=`2B279F3F0A917B1BD6E6F812E473DFB4B06A4101F38903EE1092EF3BDB70652A`，1148928 B。本节只读复核当前镜像，没有启动游戏、没有附加 x32dbg，也没有写入 EXE、RS 或 SV。

- `0x45533D` 的入口参数 `[ebp+8]` 在 `0x455367` 直接送入 `0x4061F9`，返回 U 并保存到局部；该函数随后调用 `0x436511` 展开范围/动作合法性，调用 `0x411BFB` 写动作结果后，在 `0x455418→0x45541B` 把同一个 `[ebp+8]` 低字节写入 `[0x4B5DDB]`。因此在这个父帧内，`0x4B5DDB` 是明确的 battle slot 投影，不再只是“选择入口参数”候选。
- `0x454269` 的 `0x45441D→0x454427` 把 `[0x4B5DDB]` 作为 `0x44049E` 的第二个栈参数，ECX 为当前 U；按 `0x44049E` 的调用协议，该参数在模式 1/2/3 分支经 `0x4061F9` 再解析为目标 U，并继续进入 `0x43BC5A`、`0x43C01D`、`0x43C5DF`、`0x43B730` 等结果/预览子路。由此闭合“动作选择 slot → 预览/合法性计算”的一条静态路径。
- `0x43D4FC` 的另一写入端仍是 `byte[U+0x04] → byte[0x4B5DDB]`。`U+0x04` 同时被 `0x445D72` 用作 `0x4930C8+value*4` 的集气索引，说明它是 slot-like 的单位内索引；但静态没有证明所有父帧都满足 `U+0x04==0x4061F9` 的表槽，仍需按帧对照。
- 因此三种字段的当前口径是：`0x4B5DDB` 在 `0x45533D` 父帧明确为 slot，在 `0x43D4FC` 父帧是 U+0x04 的字节投影；`0x4B5DF0` 是最近登记 U 的 U[0]/DataID dword 快照；`0x500AC0` 是最近登记 U 指针。不能把它们合并成一个“角色编号”。
