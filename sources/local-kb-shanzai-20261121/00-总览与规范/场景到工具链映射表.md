## 实现·使用方法（自动战斗 + 断点，一条完整链）

```bat
:: 0) 开场：自检提醒 + 交接 + 台账 + 摘要 + 时间线 + 检索
python 大鲸鱼产生专用\_开场.py --task "自动战斗 断点"

:: 1) 进战场（权威读档，含 R1 断言）
python 大鲸鱼产生专用\_自动读档进战场.py --go-safe

:: 2) 托管我军主动出击
python 大鲸鱼产生专用\_42托管我军.py --on

:: 3A) 不必看断点 ⇒ 直接打一批（R3：--rounds 5；唯一入口，默认只读所以必须给 --go）
python 大鲸鱼产生专用\大鲸鱼自动战斗.py --go --rounds 5
::     先看现场不动手：python 大鲸鱼产生专用\大鲸鱼自动战斗.py --check

:: 3B) 要看断点 ⇒ 还是用唯一入口（断点观测已并入它的回合循环）
::     --breakpoint 是**开关**；地址走 --watch（只统计别人已设的点）或 --set-bp（本次自设⇒收尾自删）
python 大鲸鱼产生专用\大鲸鱼自动战斗.py --go --rounds 3 --breakpoint --set-bp 0x43F1E8=伤害链
::     只看不设（别的会话已挂好点）：--go --rounds 3 --breakpoint --watch 0x43F1E8=伤害链
::     ★ 旧写法 `_自动打几轮.py --rounds 5` 已退役 ⇒ 它会绕开 4018 门禁与 R3.5 回合上限
::       并把断点留在游戏上（§4.④ 禁止后台持断点）

:: 3C) 要读断点现场（命中即抓寄存器）—— 这条仍用库件（保留）
python 大鲸鱼产生专用\_等命中读数.py --address 0x43F1E8 --secs 120

:: 4) 收尾（顺序固定，反了会留入口断点）
::    breakpoint_delete_all → debug_stop
::    工具化入口：python 大鲸鱼产生专用\大鲸鱼自动战斗.py --cleanup-bps
::    （旧入口 `_x32断点探针.py --cleanup` 已退役；--cleanup-bps = 列点 → 全删 → paused 则放行）
```

## 风险与边界

* **断点会挂住整个进程**（x32dbg 命中软件断点 = 目标进程暂停）；
  ⇒ **必须走带"超时 + 自动放行 + 自动收尾"的入口**：`大鲸鱼自动战斗.py --go --breakpoint …`
  （收尾由 `Watch.finish()` → `--cleanup-bps` 负责）。~~`_x32断点探针.py` 已退役 2026-10-26，能力并入入口~~
  纯手工 `breakpoint_set` 后忘了放行会把游戏和 PowerShell 一起卡住（已踩过）。
* **§7 死规则**：任何要用户操作的步骤之前，必须先**循环 `debug_run` 到 `running` 且
  `Ekd5.Responding == True`**，否则用户什么都做不了。
* **不要为了"顺手"再写一个同功能脚本**。真需要新能力时，
  **先给上面这些加参数**；无法扩展才新建。
* 表中工具名会随归档变动；**以 `_知识检索.py` 的实时命中为准**，本页只是索引。
