## 实现/使用方法

### 命令行

```bat
python _C盘瘦身.py scan                     :: 只读分析（默认）
python _C盘瘦身.py clean-plan               :: 看清理计划（不删）
python _C盘瘦身.py clean --yes               :: 执行清理
python _C盘瘦身.py migrate-plan             :: 看迁移计划（不动文件）
python _C盘瘦身.py migrate --target "[本地盘]\_C盘迁移" --yes
python _C盘瘦身.py status                   :: 看已迁列表 + junction 是否正常
python _C盘瘦身.py undo --all --yes         :: 全部回滚
python _C盘瘦身.py undo --id 2 --yes        :: 回滚某一项
```

**Python 用 DSH 运行时**：`[本地盘]\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`

### 安全设计（四道保险）

1. **只读优先**：`scan` / `*-plan` 全程不改文件。
2. **白名单制**：`MIGRATE_CANDIDATES` 硬编码允许迁移的路径，
   **不接受任意路径参数**，防手滑。
3. **双保险黑名单**：`[本地盘]\Windows`、`Program Files`、`ProgramData\Microsoft`、
   `$Recycle.Bin`、`System Volume Information` 等，即使写进白名单也会被拒。
4. **安全移动顺序**（防数据丢失，关键）：
   ```
   ① robocopy 复制到目标盘
   ② 校验文件数 + 总大小（不一致即中止，源目录不动）
   ③ 原目录改名 .old（瞬间，不复制数据）
   ④ mklink /J 建 junction
   ⑤ 验证 junction 能列出文件
       ↑ ①~⑤ 任一步失败 → 自动回滚到原样
   ⑥ 才删除 .old
   ```
5. **全程日志**：`~/.dsh/_c盘瘦身日志.json`，`undo` 据此回滚。

### 可迁移候选（白名单）

| 风险 | 路径 | 说明 |
|---|---|---|
| 安全 | `~/.cache` | 工具缓存，可重建 |
| 安全 | `~/.codex` | Codex 运行时缓存 |
| 安全 | `~/.trae-cn` | Trae 缓存 |
| 谨慎 | `~/.dsh` | **⚠️ 不建议迁 —— DSH 正在运行，文件占用会导致改名失败** |
| 谨慎 | `AppData\Local\google` | Chrome 配置，迁移前关浏览器 |
| 谨慎 | `AppData\Local\OpenAI` | Codex 桌面数据 |
| 谨慎 | `AppData\Local\Programs` | 用户目录安装的程序 |

## 风险与边界

1. **junction 不是零风险**：一旦 junction 损坏或指向的盘不可用，程序会找不到数据。
   所以**本次没做迁移** —— C 盘已到 44.74 GB，为 3~7 GB 冒系统级风险不值得。
2. **`~/.dsh` 绝不能迁**：DSH 正跑着，`os.rename` 必失败（工具会安全回滚，但白折腾）。
3. **`[本地盘]\Windows\Installer`（0.67 GB）不能删** —— 删了以后程序无法卸载/修复。
4. **`[本地盘]\Windows\WinSxS` 绝不能手删** —— 只能走 `DISM /Online /Cleanup-Image /StartComponentCleanup`。
5. **清理会删掉「占用中以外的全部」Temp 文件** —— 正在运行的程序若把重要临时文件放在
   Temp 且未加锁，会被删。这是 Temp 语义本来的约定，但值得知道。
6. **本次副作用**：`.codex\auth.json` 丢失（不是本工具删的，是同期其它清理/用户操作），
   Codex 需重新登录。
