# 安全点击与鼠标不抢占（三级点击策略）

## 结论速览

| 编号 | 结论 | 证据 |
|---|---|---|
| **C1** | 自动化点鼠标**优先走消息**（控件消息 → 窗口消息），只有游戏自绘窗口才降级到物理注入 | 工具源码 + 实机 |
| **C2** | 物理注入前后必须：**确认目标已在前台** → 点击 → **光标原位还原**；每次记录 method 以便审计 | 实机（光标 954,555 → 954,555） |
| **C3** | 旧 `_安全点击.py` 只解决"点到别的进程"，**仍会移动光标**，不能用来满足"不抢鼠标" | 工具源码 |

## 适用版本

- 复刻版6.6山贼自动化脚本（`Ekd5.exe`）；其它带自绘窗口的程序同理。

## 已确认事实

### 两个模块的分工（别混用）

| 模块 | 解决什么 | 手段 | 是否动光标 |
|---|---|---|---|
| `_安全点击.py`（2026-10-13） | 坐标算错点到**别的进程**（曾误启 WPS） | 点前 `WindowFromPoint` 校验归属 | **会动**（SetCursorPos + mouse_event） |
| `_安全点击2.py`（2026-10-14） | **抢用户鼠标** | L1 控件消息 / L2 窗口消息 / L3 物理兜底 | 仅 L3，且还原 |

### 三级策略

| 级别 | 手段 | 适用对象 | 实测有效性 |
|---|---|---|---|
| L1 | `WM_COMMAND(IDOK)` 回投对话框 | 模态框**消失** | 有效（但**动作不执行**，见输入协议 I5 表） |
| L1 | `LVM_SETITEMSTATE` | ListView 选中 | 控件态有效，**游戏不认** |
| L2 | `PostMessage(WM_LBUTTONDOWN/UP)` | 自绘窗口 | **无效**（Ekd5 实测） |
| L3 | `SetForegroundWindow` + `mouse_event` + 还原光标 | 标题页菜单、存档行、确认框按钮 | **有效** |

## 实现·使用方法

```python
import _安全点击2 as S
S.click_client_message(hwnd, cx, cy)                 # L2：不动光标
S.select_listview_row(lv_hwnd, 0)                    # L1：控件消息
S.click_screen_physical(x, y, hwnd=hwnd)             # L3：会短暂借光标，自动还原
r = S.ack_dialog(dlg_hwnd, want=("是",))             # L1：只让框消失
S.cursor(); S.set_cursor(x, y)                       # 审计/还原用
```

- 协议实现见 `_自动读档进战场.py` 的 `click_menu_safe()` / `click_button_safe()` /
  `click_listview_row_safe()` / `focus_foreground()`。

## 风险与边界

- L3 会改变前台窗口：用户正在别的程序里打字时会被打断。**降级顺序不许颠倒**
  （能 L1/L2 解决就不许用 L3）。
- `require_foreground=True`（默认）时，目标不是前台窗口会**拒绝点击**并返回
  `{"method": "SKIPPED"}`，脚本应把它当失败而不是成功。
- 抢前台用 `AttachThreadInput`，**不要**注入 ALT（会与调试器抢前台冲突）。
- 一次点击不一定生效（游戏启动后首次点击被吃掉，见 I3），调用方必须**验证结果再重试**。
