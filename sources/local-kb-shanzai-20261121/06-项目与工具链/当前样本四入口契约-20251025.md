## 一、0x43CDDD：单单位回合结算 / HP-MP 与效果调整

**入口与清栈**

- 入口 `0x43CDDD`，函数尾为 `ret`（无立即数），因此没有形式化的栈参数，也不清理调用方栈。
- 唯一直接调用点为 `0x44EE9A`。调用前由 `0x4061F9` 按槽位取出单位记录并把结果留在 `ECX`，随后直接 `call 0x43CDDD`。
- **已确认入口契约**：`ECX = TacticalUnit*`（战场单位记录）；`[ebp+8]` 等栈参数不属于本函数的正式输入。

**关键寄存器与内部链**

- `push ecx; call 0x40658F`：由单位记录取得 person 记录，返回值经后续保存为 `[ebp-0x1C]`；这也确认了入口 `ECX` 是单位记录而不是 person 指针。
- `0x418C90` 读取单位记录的 `+0xC` 门禁；当前反汇编为 `cmp al,2`，不等于 `2` 时直接跳到函数尾。
- `0x42F8D9 → 0x43D038 → 0x407263 → 0x428A25` 形成恢复量/上限计算；结果先进入局部槽 `[ebp-4]`、`[ebp-8]`。
- `0x423FA1` 对累积值做单位侧修正；`0x43D0FA` 查询固定特技/效果值后进入 `0x423930`。
- `0x43CEB6` 读取最大 MP，`0x43CEC7` 做 MP 上限裁剪；`0x43CF8A` 最终执行 `add [unit+0x10], delta_hp` 与 `add [unit+0x14], delta_mp`。
- 末段继续经过 `0x4065C7`、`0x4088CD` 写入辅助状态/效果；这些调用的细节不应简化为“只改 HP”。

**返回值**

- 尾部为无立即数 `ret`，无稳定的返回值契约；`EAX` 只是最后一个内部调用遗留值，不能当作 HP、MP 或结算量读取。

**可复用调用链**

```text
0x44EE9A
  └─ 0x4061F9(slot) → ECX=unit
       └─ 0x43CDDD(ECX=unit)
            ├─ 0x40658F(unit) → person
            ├─ 0x418C90(unit+0xC == 2 门禁)
            ├─ 0x42F8D9/0x43D038/0x407263/0x428A25 计算
            ├─ 0x423FA1/0x423930 修正
            └─ 写回 unit+0x10、unit+0x14
```

## 二、0x45EEB0：特效累积分数/百分量合成

**入口与栈形状**

- 入口 `0x45EEB0`，尾部 `ret 8`；形式上清理 `[ebp+8]`、`[ebp+0xC]` 两个 dword。
- `[ebp+0x10]`、`[ebp+0x14]` 也被读取并转发给 `0x405D0A`，但不由本函数清栈；因此这两个字是外层调用帧中仍需保留的上下文，不应擅自改成“本函数再清理的两个参数”。
- **已确认的寄存器/参数形状**：`[ebp+8]` = 进入时的累计基值（当前调用链由 `0x40C817` 压入）；`[ebp+0xC]` = 当前单位/效果查询对象，装入 `ECX` 调 `0x45EE62`、`0x45EE7C`、`0x45D513`、`0x45EE96`。

**计算与分支**

1. `0x405D0A([ebp+0x10],[ebp+0x14])` 返回基础量，保存到 `[ebp-4]`。
2. `0x45EE62`（效果 `0xBA`）非零时，读取全局字节 `[0x500C48]`，执行 `base += effect_BA * [0x500C48]`。
3. `0x45EE7C`（效果 `0xC9`）返回值加入累计量；累计量上限裁为 `100`，再加入口基值 `[ebp+8]`。
4. `0x45D513`（效果 `0xFE`）为硬清零门；命中则直接返回 `0`。
5. 未命中清零门时，`0x45EE96`（效果 `0xEF`）作为削弱/扣减量；结果再次以 `100` 为上限，并做不低于零的扣减。

**返回值**

- `EAX` = 最终合成后的累计值；正常路径范围由两次上限逻辑约束到 `0..100` 附近，`0xFE` 门命中时严格为 `0`。
- 该函数只返回数值，不直接写 HP；调用方 `0x40C81A` 在 `0x40C817` 压入累计值后接收此返回值。

## 三、0x4064F1：物理攻击/连击与预估共用的祖父层

**入口与清栈**

- 入口 `0x4064F1`，尾部 `ret 8`，清理两个显式栈参数。
- 入口第一条 `push ecx` 保存到 `[ebp-4]`，说明 **`ECX` 是战斗上下文指针**；现有调用链明确使用 `ECX=0x4927F0`。
- **已确认参数形状**：`[ebp+8]`、`[ebp+0xC]` 是攻守两侧的槽位/单位标识，具体哪一侧为 attacker/target 要按各调用点在进入前的压栈顺序读取，不能从函数体单独交换命名。

**关键寄存器与调用链**

- `ECX` 保存的上下文先进入 `0x406252`；随后循环路径以 `0x4E30E1`、`0x4527FE`、`0x417983`、`0x4E3000` 处理一次攻击、候选目标和连击重复。
- `[ctx+0x608]` 是本函数维护的字节计数：`0x500E9A==1` 时清零；普通路径先自增，再由 `0x4E3000` 的结果决定是否回到 `0x40651D` 重复。
- 退出前依次调用 `0x406B3C`、`0x42AB32`；若 `[0x500E9A] != 1`，再调用 `0x406453` 做普通收尾。
- 库内已有结论：该层有 11 个直接调用者，覆盖实战、AI 评分、预估、预览与效果结算；因此这里命中不能单独证明“玩家实际打出一次攻击”。

**返回值**

- 函数没有统一的 `mov eax, …` 收口；`EAX` 是最后一个尾调用的返回值：`[0x500E9A]==1` 时来自 `0x42AB32`，否则来自 `0x406453`。
- 因而 `EAX` 应按“状态/收尾结果”使用，不能当作稳定伤害值；真正伤害槽与 HP 写回要沿 `0x405DE1` / `0x43F6DB` 等下游单独核对。

## 四、0x43F6DB：当前 HP 的有上限写入器

**入口与清栈**

- 入口 `0x43F6DB`，尾部 `ret 4`，清理一个显式栈参数。
- **已确认入口契约**：`ECX = TacticalUnit*`；`[ebp+8] = requested/new_hp`。
- 反汇编没有把新 HP 从 `EDX` 作为入口寄存器接收；`EDX` 只在函数内部被装载为最终写入值。旧笔记中的“`EDX=new_hp`”应按当前样本修正为“栈参数 `[ebp+8]`，内部落到 `EDX`”。

**计算与写回**

- `push [ecx]; call 0x4061E4; call 0x407263` 取得该单位最大 HP，存入 `[ebp-4]`。
- 比较 `[ebp+8]` 与最大 HP：请求值较大时写 `unit+0x10 = max_hp`；否则写 `unit+0x10 = requested`。
- 唯一实际写点是 `0x43F70C: mov [ecx+0x10],edx`；这是上限裁剪后的结果。

**返回值**

- 结尾没有把写入值显式搬入 `EAX`；因此 `EAX` 不是稳定的 new_hp 返回值，调用方应以 `unit+0x10` 复读作为结果判据。

## 五、复用边界与后续待验证

- **可直接复用的静态入口**：`0x43CDDD(ECX=unit)`、`0x43F6DB(ECX=unit,[esp+4]=new_hp)`、`0x45EEB0([esp+4]=base,[esp+8]=object, ret8)` 的形状已由当前字节和调用点支持。
- **只能带调用点复核复用的入口**：`0x4064F1` 的两项槽位参数必须随具体调用点确认攻守顺序；其返回值也不能跨分支当统一伤害值。
- **仍属静态待证**：`0x45EEB0` 的 `[ebp+0x10]/[ebp+0x14]` 外层帧来源、`0x4064F1` 11 个调用者的场景分类、四个入口的运行时命中与寄存器实值。当前 x32dbg 探针未建立有效动态闭环，因此这些项目保留为 P1。

## 六、口径校正（与既有逐条页合并）

- `0x45EEB0` 的**语义输入**仍按四个位置描述：`[ebp+8]` 基础/累计值、`[ebp+0xC]` 单位或效果对象、`[ebp+0x10]` 攻方上下文、`[ebp+0x14]` 守方上下文；机器码层面只由 `ret 8` 清理前两个位置，后两个由共享上层帧保留。这是“4 个读取位置”和“2 个本函数清栈参数”同时成立的原因。
- `0x43CDDD` 的 `unit+0x10`、`unit+0x14` 在该域先记录为**累计写回字段**，不把它们直接命名成 HP/MP。当前样本中能明确证明“HP 上限裁剪后写回”的专用入口是 `0x43F6DB`；这样可以避免把回合成长/效果累计域与伤害结果应用域混为一谈。
- 因此复用时：需要“按最大 HP 裁剪并写当前 HP”调用 `0x43F6DB`；需要“每单位回合结算”才沿 `0x44EE9A → 0x43CDDD`，不从 `0x43CDDD` 的返回寄存器推导 HP。

### 7.2 `0x45EEB0` 的共享上层帧已定位

- 当前唯一直接调用点 `0x40C81A` 位于函数 `0x40C7D8`。
- `0x40C7D8` 在 `0x40C804~0x40C80A` 先准备 `0x44F9A9` 的暴击率前置结果；若未命中直接加 `0x64` 到 `[ebp-8]`，随后只执行 `push [ebp-8]; call 0x45EEB0`。
- 因而 `0x45EEB0` 的 `[ebp+8]` 明确来自 `0x40C7D8` 的累计槽；`[ebp+0xC]`、`[ebp+0x10]`、`[ebp+0x14]` 不是本调用点新压入的独立参数，而是共享上层帧中仍可读取的上下文位置。
- 这解释了“语义四位置输入、机器码 `ret 8`”的形状；不能把它改写成普通四参数 `cdecl`。

### 7.3 `0x43CDDD` 与 `0x43F6DB` 的写回链已闭合

- `0x44EE9A` 的当前字节为 `call 0x4061F9` 后紧接 `call 0x43CDDD`；`0x4061F9` 的返回单位记录留在 `ECX`，因此 `0x43CDDD` 入口契约为 `ECX=unit`、无正式栈参数。
- `0x405ADC` 当前函数先读取物理 `ctx+0x84`、策略 `ctx+0x254` 和第三结果数组 `ctx+0x430`，再执行：`call 0x41B500` 取当前 HP → `sub eax,[ebp-0x14]` → `push eax` → `ECX=unit` → `call 0x43F6DB` → 随后进入 `0x43F715` 写 MP。
- `0x45AB0E` 另一条效果结算路径先由 `0x40DA4A` 计算新 HP，执行 `push eax`、`ECX=unit`、`call 0x43F6DB`；这进一步证明 `0x43F6DB` 的新 HP 输入是栈参数，而不是入口 `EDX`。
- 当前可复用的真实链因此是：

```text
物理/策略结果应用：
ctx+0x84 或 ctx+0x254
  → 0x405ADC
  → 0x41B500(current_hp)
  → push(new_hp)
  → ECX=unit
  → 0x43F6DB
  → unit+0x10 = min(new_hp, max_hp)

效果结算：
0x40DA4A → push(new_hp) → ECX=unit → 0x43F6DB
```
