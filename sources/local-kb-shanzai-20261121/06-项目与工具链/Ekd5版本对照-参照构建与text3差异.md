## 结论速览

1. **两个构建（实测）**：

   | 构建 | SHA256 | 说明 |
   |---|---|---|
   | **参照** | `69A9074AC044DCFB33449F8F41EF116D9A29C7B815F9467229086D0E15ED09E7` | 用户提供；**不在任何自动备份里** |
   | **当前** | `25DB2211FE8F495DE4993BAB296C23C180E18679F00A0E43B47B1FD2034B7EAF` | 46 补丁全现行 |
   | 基线 | `813F4D7190EC52CE2A153519491E17158778633176AA3B42CC35722CCDA5C902` | = 当前撤掉暴击槽补丁；**自动备份里有 4 份** |

2. **两构建差异 = 6759 字节 / 1222 个区间**，分布极不均：
   **`.text3`(0x4CE000~0x532000) 占 1144 个区间（2644 字节）**，`.code` 50 个，`.text1/2` 25 个。
3. **`.text3` 的差异形态**（这是"引擎被改坏"的量化证据）：
   * **系统性 `+0x10`**：`0x505204` 起每 `0x10` 字节一个字节，值**统一 +16**
     （`C8→D8`、`74→84`、`BC→CC`、`E0→F0`…）
   * **数据插入**：`0x518363`(文件 `0x117763`) 处**插入 16 字节**，其后整体后移 16
     （`0x117800` 起位移 = `+16`）；另有 **4 处小插入**（`0x518F1C/0x518F30/0x518FB4/0x519118`）
   * 与**已注册补丁零重叠**（138 条声明逐条核对）⇒ **属构建自带差异，非我方补丁**
4. **⚠ 但"这处差异是否就是闪退原因"仍未证实**：
   2026-10-15 我一度报"干净基线 `813F4D71` 读 `No.001` 第 1 回合闪退"，
   **用户实测同构建不闪退** ⇒ **是我的测试脚本（`subprocess` 循环 + `--try-n 12`）导致的中止/脏状态被误报成构建闪退**。
   **⇒ 在拿到"同流程 A/B 两构建"的干净对照前，不得把 `.text3` 差异认定为闪退根因。**
5. **版本档案体系已建立**（见下），因为**当前状态曾经全盘无同 SHA 备份**（实测只剩工作副本本身）。

## 已确认事实

* `.text3` 差异**不是**任何已注册补丁写的（`大鲸鱼产生专用\*.txt` 138 条声明，逐条区间重叠检查 = 0 命中）。
* `.rsrc` 的 **VSize 在两个构建间差 `+16` 字节**，与"表里多一条记录"吻合；两构建**入口点都是 `0x4817E0`**、ImageBase `0x400000`。
* 链尾 `0x43F27F` 与代码洞 `0x457D7B` 在**参照版与基线版字节完全相同**
  （`E9 48 CB FF FF` / `90×16`）⇒ 暴击槽补丁可干净互用。
* **43 个补丁 txt 中 30 个存在"同址互相覆盖"**（用 `_样本时间线.py:parse_patch` 校验，
  多个文件的字节与当前 EXE 不一致）⇒ **补丁不可盲序重放**，"换基底 + 重放全部补丁"有覆盖依赖风险。

## 实现·使用方法（版本档案与留档）

**目录**：`大鲸鱼产生专用\_Ekd5版本档案\`

```
Ekd5_<SHA8>_<说明>_<时间戳>.exe     归档本体
MANIFEST.md                          清单：时间/角色/全64位SHA/大小/文件/依据补丁
留档规则.md                          规则正文
```

**工具**：`大鲸鱼产生专用\_补丁留档.py`

```bash
python _补丁留档.py --snapshot --purpose "已知良好点"
python _补丁留档.py --apply --purpose "暴击槽" --patch "【6.6山贼】暴击槽-链尾代理.txt"
python _补丁留档.py --restore Ekd5_69A9074A_参照不闪退版_20261015_164217.exe
```

* `--apply` 自动做：**前像归档 → 走 `_dsh写锁.py` 写入 → 后像归档 → 清单追加两行**。
* ⚠ **踩坑（已修）**：`_dsh写锁.safe_write_exe` 返回 **`(ok, 说明)` 元组**，
  调用处**必须解包**；写成 `if ok:` 会**恒真**并误报成功。

## 风险与边界

* **不得**在没有"同流程 A/B"对照前，把 `.text3` 差异认定为闪退根因（本条已踩过一次）。
* **不得**把 `subprocess` 反复调 `_找空地并结束回合.py --try-n 12` 的结果当作"游戏闪退"证据；
  该组合在本工作区产生过**误报**。判定"游戏是否崩"用 `C.pid_of()` + `Responding`，
  并要求**单次调用**也能复现。
* **补丁重放**必须先做"前像/覆盖关系"分析（同址多文件）；不可按文件名字典序盲放。
* 参照版 `69A9074A` **不在自动备份里** ⇒ 唯一副本已归档到 `_Ekd5版本档案\`，勿删。

## ★ 2026-10-15 更正（DSH）：那 1144 区间 / 2644 字节在 **`.rsrc`**，不在 `.text3`

**原口径（本页上文）**：两构建差异主在 `.text3`（1144 区间 / 2644 字节）、系统性 `+0x10`、
`0x518363`（文件 `0x117763`）处插入 16 字节 ⇒ 判为"引擎 `.text3` 被改坏"。

**现证据（按各文件自己的节表重新分类；配对 = 本页原配对 `69A9074A` 参照 vs `25DB2211` 46补丁）**：

| 节 | 区间 | 字节 |
|---|---|---|
| **`.rsrc`** | **1144** | **2644** |
| `.code` | 50 | 3726 |
| `.text3` | **12** | **337** |
| `.api` | 13 | 47 |
| HEADER | 3 | 5 |
| 合计 | 1222 | 6759 |

- 文件偏移 `0x117763` 按其节表属 **`.rsrc`（VA `0x545F63`）**（不是 `.text3`）：
  该处 B 相对 A 正好多 16 字节（`00 00 00 00 00 00 00 01 50 58 00 0F 01 2F 00 1B`）。
- 本页上文引的 VA **`0x505204` 是按 `.code` 差值 `0x400C00` 反算的**（文件偏移 `0x104604`），
  真实位置 = **`.rsrc` VA `0x532E04`**：A = `C8 00 00 00 … 74 5F 14 00` → B = `D8 … 84 5F 14 00`
  （资源目录 16 字节块里的 **+0x10** 传播，与"插入 16 字节"自洽）。
- 若按 `.text3` **正确**换算（`VA − 0x432800`）读 VA `0x505204`：**两文件同为全 `00`**（无差异）。

**⇒ 更正后的口径**：该差异是 **`.rsrc` 资源区**差异（资源目录块 + 16 字节插入），
**`.text3` 只差 12 区间 / 337 字节**；"引擎 `.text3` 被改坏"的表述作废。
凡引用"`.text3` 被改坏"的页面/结论，请改读为"`.rsrc` 资源区差异"。

**新增纪律（工具级）**：跨构建差异分类**必须用该文件自己的节表**换算 VA；
禁止拿单一段差值（`0x400C00`）去换算尾部节（`.text3`/`.rsrc`）的文件偏移 ——
本页上文那处 `+0x20E00` 的 VA 错位就是这么来的。
