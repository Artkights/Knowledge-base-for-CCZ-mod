### 已复现并修正的问题

| 问题 | 修订后的行为 |
|---|---|
| PE按VirtualSize映射文件，虚拟尾部会读入邻节 | 虚拟零填充无文件偏移；读取最多到当前节文件边界；精确读取不足即报错 |
| PE字节和节表分别读磁盘，可能混入不同样本 | 只读一次文件，再从同一字节快照解析PE |
| 架构未经核验就固定用32位解码 | 显式核验Machine和OptionalHeader；拒绝其他架构、截断节和重叠节 |
| 两个原始扫描器的循环上界漏节尾5/6字节指令 | 共用 `scan_branches`，补齐节尾、短跳、loop、FF15/FF25槽引用 |
| 扫描器把 `--ctx 0` 的0当成另一个目标 | 改用argparse；支持指定样本、完整SHA前置校验、JSON |
| 从命中前24字节起线性解码可能吞掉命中本身 | 前文仅作候选；命中和后文从命中地址独立解码 |
| 手写解码器对前缀/F7立即数等支持不全 | 旧API转接Capstone；不能解码时标成invalid/db，不猜长度 |
| 跳板按原始E9位置解析，可能读到立即数内部 | 仅沿连续指令边界识别尾跳；遇call/jcc/ret停止，记录已访问入口避免循环 |
| func_end每次从节首重扫，入口可能已经失步 | 从明确入口开始；修复节末单字节遗漏、GCC序言与入口候选晚于查询地址的问题 |
| 补丁核对不一致/没解析出记录仍返回0 | 返回非零；该文本解析仍为启发式，不替代正式补丁应用器前像校验 |
| string命中显示误用了搜索结束时的变量 | 按每条命中的真实文件偏移取上下文 |
| 汇编器缺失会阻断只读能力 | Keystone改为可选；缺失时doctor/反汇编仍可用 |
| 间接 call/jmp 一律只报"未解析"，跳表 case 全部漏掉 | `ind`/`cfg` 接入解析：IAT→导入名；指针槽→静态目标；跳表→按 cmp/jcc 上界展开 case；不能证明的仍记 unknown |

```powershell
python 大鲸鱼产生专用\_dsh反汇编工作台.py xref 0x45533D --json

python 大鲸鱼产生专用\_dsh反汇编工作台.py ind 0x403E34 24 --json
python 大鲸鱼产生专用\_dsh反汇编工作台.py ptrtable 0x486458 --json
python 大鲸鱼产生专用\_dsh反汇编工作台.py scan "80 61 24 ??" --exec-only --json
python 大鲸鱼产生专用\_dsh反汇编工作台.py fields 0x1B 1 read --layout dataseg0_person_base
python 大鲸鱼产生专用\_dsh反汇编工作台.py note 0x4061E4 5 --json
python 大鲸鱼产生专用\_dsh反汇编工作台.py da 0x4054A0 12 --label
python 大鲸鱼产生专用\_扫调用.py 0x45533D --ctx 0 --exec-only --json
python 大鲸鱼产生专用\_反汇编工具链自检.py
```

- **`note <VA> [最多条]`**：函数目录条目 + 地址反查命中，每条带 `evidence`（同SHA/跨样本/未声明SHA）与 `page_sha`。跨样本条目不等于当前样本语义。
- **`da --label` 扩展（2026-11-01）**：除 `call/jmp` 直接目标外，**常量内存引用（`[abs]`，base/index 均为空）命中函数静态目录时也追加角色名**，原有字符串识别保留。实测 `xref 0x4A8AE0` ⇒ 0 引用（运行时指针在 EXE 内无静态引用，属正常）——说明 `xref` 的原始字节扫描与 `da` 标注是两套独立证据。
- **`--entry <VA>`（`funcstart` / `func`，2026-11-01）**：跳过序言推定，直接用已知入口（来源可为知识库记录或 `xref`）。实测 `funcstart 0x416E1B --entry 0x416A75` ⇒ 入口偏移 `-0x3A6`、解码 333 条、断裂在 `0x416E29`（跨数据表），与 `func_start` 推定结果一致，证明“推定 vs 已知入口”两条路径可互相核对。
- **`scan <签名> [--exec-only] [--limit N] [--ctx N]`**：字节模式普查，`??`/`?` 为单字节通配；默认扫全部节（找写入点/IAT 常量），`--exec-only` 只扫可执行节。命中是**字节候选**，可能落在立即数/数据内部；`--ctx` 用 Capstone 从命中地址解码上下文，指令级只认 `da/ind/cfg`。
- `note` 依赖 `_生成输出\索引\_地址反查.json`；索引不存在时提示先跑 `python 大鲸鱼产生专用\_地址反查.py build`（不自动重建 15.8MB 索引）。

- **`ind <VA> [条数]`**：窗口内每条间接分支给 `resolution` + 证据。`iat`（槽地址命中导入表，回填 `DLL!Name`，无静态代码边）/ `pointer-slot`（槽内静态 dword→代码，confidence=medium）/ `jump-table`（表基址、索引寄存器、读取项数、上界来源、表尾实测）/ `register`、`indexed-memory`（静态不可恢复）。
- **`ptrtable <VA> [最大项数]`**：从 VA 起连续 dword 均落在可执行节 ⇒ 函数指针表候选；第一个非代码 dword 即表尾，输出前后各一次 dword 作边界证据。**只证明"连续 dword 是代码地址"，不证明起点/语义**。
- **`cfg ... --no-indirect`**：关闭间接解析，退回"间接一律未解析"的旧行为，便于对照。
- 跳表上界判据：`cmp 索引寄存器, imm` + 目标**大于跳表地址**的条件跳转；`ja/jg/jbe/jle` 取 imm，`jae/jge/jb/jl` 取 imm-1；若跳表前有 `sub 索引, imm` 则减去下界偏移。索引寄存器被其他指令改写（如 `mov al,[...]` 查表转码）时旧 cmp 作废。

## 风险与证据边界

- 原始字节扫描不会受线性解码失步影响，但可能命中立即数/数据内部；Capstone局部可解码不证明真实指令起点。无候选不等于无间接调用。
- `FF15/FF25` 搜索目标为槽地址，不能当成槽内保存的函数地址；寄存器、基址+索引的间接内存仍不自动恢复。
- **跳表上界只在本函数窗口内寻找**：上界由调用者决定、或索引寄存器在跳表前被 `mov/lea/xor` 等改写时，一律 `unknown`。当前样本 67/89 属此类，不能因为"连续读到 k 项都像代码"就把 k 当表长（`0x403FA0` 声明 4 项，紧接着还有 4 项属于相邻表）。
- `ptrtable` 只证明"连续 dword 落在可执行节"；表起点是否指令/数据中部、表的语义（分派/回调/虚表）仍需引用它的代码证明。
- IAT 槽的静态文件值通常是 hint/name RVA，不是函数地址；非导入槽内的 dword 只是静态快照，运行时可能被改写。
- 全节 `fields`、序言候选、`func/df` 仍是启发式；失败重同步不能保证恢复正确指令流。需要明确入口与对照窗口。
- `cave` 只报告连续填充候选；不能据此写入。代码洞仍须按库内流程核验边界、入边、占用、契约；未知项不能当作通过。
- **「清洞填充不算占用」只解冲突噪音，不解安全**：它证明的是“这条声明没有把代码塞进这段”，**不证明**该段当前没有别的作用；`--applied-only` 也只认“当前字节与声明一致”，回滚/还原段同样会命中。真实写入前仍须 `--check` 现读 + §3.6.2 四组门槛。
- **体检模式把“边界未证明”降为提示，不等于边界已确认**：钩点段必须人工确认原指令边界（整条指令、入边唯一），数据段必须确认是否活跃数据表（`0x512DC0` 事故）。提示项永远需要人来闭合。
- **锚点法的入口本身是启发式**：`boundary_from_entry` 的 `entry` 来自 `func_start`（`55` + 8B 内 `8B EC`），重排/无帧指针函数会落到上一函数或 `no-entry`；95 段实测 **62 段 `no-entry`**（洞/数据段本就没有入口）⇒ `ok` 只证明“**按这个入口**解到起址是整条指令”，入口是否正确仍须人工或 `--entry` 明确给出。`inside` 才是强信号（起址确定落在某条指令内部）。
- 本轮只验收离线静态工具；未启动/操控游戏或x32dbg，未写EXE、DLL、Data.e5、剧本或存档。
- 未执行全工作区通用自检，也未证明历史所有脚本消费者的语义兼容；已保留旧返回形状及手动切换DATA/PE方式，并覆盖已检索到的decode2/disasm用法。
