# 标题页与读档输入协议（Ekd5 输入只认前台物理点击）

## 结论速览

| 编号 | 结论 | 证据 |
|---|---|---|
| **I1** | 游戏自绘窗口（标题页菜单、战场、地图）**不认窗口消息**：`PostMessage` / `SendMessage` 的 `WM_LBUTTONDOWN/UP`、`WM_MOUSEMOVE` 全部无效，**前台也一样** | 实机命中 2026-10-14 |
| **I2** | 输入生效条件 = **窗口真的是前台** + **真实硬件级点击**（`mouse_event`）；不满足则点击被静默丢弃 | 实机命中 |
| **I3** | **游戏启动后第一次点击会被吃掉**（前台已确认也会）：脚本必须先点一次再重试，或把首次点击当"唤醒" | 实机命中（2 次独立复现） |
| **I4** | 读档三步：`烽烟再起`（客户区 686,220）→ 列表**第 0 行**（屏幕 x=列表横向中心, y=列表 top+11）→ 确认框 `是`（屏幕 858,544） | 实机命中 3/3 进战场 |
| **I5** | 读档进程列表控件与确认框是**标准 Win32 控件**，可读文本做断言；但**选择存档行必须物理点击**，`LVM_SETITEMSTATE` 游戏不认 | 实机命中 |

## 适用版本

- 复刻版6.6山贼 `Ekd5.exe`（主窗口类 `SOUSOU`，标题含 `AAA`）。
- 分辨率/窗口尺寸变化后，客户区坐标需重测（本页坐标基于客户区 800x550）。

### 消息类手段的实测结论（都试过，别重复踩）

| 目标 | 手段 | 结果 |
|---|---|---|
| 标题页菜单 | `PostMessage/SendMessage(WM_LBUTTONDOWN/UP)` | 无效 |
| 存档列表行 | `LVM_SETITEMSTATE`（选中+焦点） | 控件状态变了，**游戏不认**，不弹确认框 |
| 模态框「是」按钮 | `BM_CLICK` | 框不消失 |
| 模态框「是」按钮 | `WM_COMMAND(IDYES=6)` 回投对话框 | 无效 |
| 模态框「是」按钮 | `WM_COMMAND(IDOK=1)` 回投对话框 | 框**消失**，但**动作不执行** |
| 模态框「是」按钮 | `WM_COMMAND(IDCANCEL=2)` | 同样只是消失，无动作差异 |
| 关游戏 | `WM_CLOSE` / `WM_SYSCOMMAND(SC_CLOSE)` + 回投 | 只弹/只销毁确认框，**进程不退** |

## 风险与边界

- **坐标随分辨率/窗口尺寸变化**：换分辨率必须重测；客户区坐标优先（`ClientToScreen` 换算）。
- **物理点击会短暂占用光标**（实测点完可原位还原）；抢前台会改变前台窗口，
  用户正在操作别的程序时会被打断 —— 纪律见
  [安全点击与鼠标不抢占](安全点击与鼠标不抢占.md)。
- 战斗界面内**不能**用 `Esc` 回标题页（实测内存仍是战场态 `field_w=6676`），
  反复读档只能"重开游戏"或打完当前关。
- 强杀不走走存档退出流程（本作存档是显式存档/自动存档，不影响已落盘进度）。
