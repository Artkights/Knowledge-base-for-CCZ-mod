# 加速补丁（小暗 6.6）配置口径与"停止加速"的正确做法

> 建立 2026-10-15｜触发：用户「你连锁一下我们库里面的加速补丁的源码，你看怎么先暂时停掉它？」
> 「而且我看到加速补丁还挂在上面」「你居然忘记这个了」「我来禁用吧」
> **本页是"怎么读、怎么停、有哪些坑"的唯一权威页。**

## 结论速览

> ★★★ **2026-10-15 关键更正（推翻本页第一版）**：
> **真正生效的开关 = 按存档独立配置 `patch\xiaoan66\pl_06.saves.ini`，
> 不是全局 `patch\pl_06.ini`。**
>
> **实测证据链**：
> * 把全局 `pl_06.ini` 的 `[0]` 改成 `0` ⇒ **加速依旧**（读数仍波动，用户也反馈仍是快速）。
> * 查 `pl_06.saves.ini`（150 行）**存在两段**：`[SV000.E5S]` 与 `[SV.E5S]`，
>   **两段 `[0]` 原本都是 `1`**（超级加速开）⇒ **读档时按存档段覆盖全局** ⇒ 改全局无效。
> * 把**两段的 `[0]` 都改成 `0`** 后，配置文件层面才算"关"。
>
> **⇒ 停用必须改"存档段"的 `[0]`（连带 `[6]`/`[15]`）。**
> ⚠ 且 `pl_06.saves.ini` **没有 `[SV002.E5S]` 段** ⇒ **读 002 会回落全局**（条件干净）。

1. **加速开关不在 `AutoDLL.ini` 里**。`AutoDLL.ini` 只管 **自动存盘 + 快速点击鼠标**
   （`EnableAutoSave` / `EnableFastKey` / `DelayTime` / `AutoSaveSlot` / `Resize`）
   —— **改它不会停加速**（2026-10-15 我改错过一次，实测无效）。
2. **两个配置文件、两条读取路径**：

   | 文件 | 作用 | 何时生效 |
   |---|---|---|
   | `patch\pl_06.ini` | **全局基线**（74 行十进制，字段序 `gConfigLines[0..73]`） | 启动时 `LoadSettings()` 读；**被存档段覆盖** |
   | `patch\xiaoan66\pl_06.saves.ini` | **按存档独立配置**（段名 = 大写存档文件名，如 `[SV000.E5S]`，每段 74 行同序） | **读档时**按当前存档套用；**没有该段才回落全局** |

   | 行 | 含义 |
   |---|---|
   | **`[0]`** | **超级加速开关**（0=关 / 1=开）← **"一直超级快速推进"就是它** |
   | `[1..5]` | 超级的五个子项 |
   | **`[6]`** | **阶段加速开关** |
   | `[7..9]` | 阶段三选项 |
   | `[10]` | 滚轮微调开关 |
   | `[11..13]` | 三阶段值 |
   | `[14]` | 滚轮步长 |
   | `[15]/[16]` | 齿轮开关 / 倍率 |
   | `[35]` | Ctrl→Shift |
   | `[65..69]` | 五个热键（Z/X/V/W/Q） |
3. **★ 最大的坑：不要用会加 BOM 的写文件方式。** 游戏是 C++ 逐行解析十进制，
   首行带 `EF BB BF` 很可能**解析失败**（并可能回落到默认 ⇒ 看起来"改了还是加速"）。
   2026-10-15 我用 PowerShell `Set-Content -Encoding UTF8` 写，**确实加了 BOM**，
   用户当场指出「你居然忘记这个了」。改正为 `open(p,"wb").write(("...").encode("ascii"))`。
4. **`Koeicda.dll` / `GearNtKe.dll` 是必需件，不能靠改名停用**：
   把 `Koeicda.dll`（759KB 加速版）换成 `Koeicda_org.dll`（44KB 原版）后，
   **读档框都弹不出来**（2026-10-15 实测）⇒ **停用只能走配置开关，不动 DLL。**
5. **⚠ `0x4B3D20` 不能当"加速是否生效"的判据。**
   库内既有口径：它**只是状态指示**，引擎自己 `1↔3` 狂刷；**直写 ≠ 真提速**；
   **权威判据 = 手按 X + 人眼确认**。
   实测：配置确已改成 0 且**未被游戏覆写**（mtime 未变、段内值仍 0），
   但该字节照样 `[2,3,0,0,1,1,2,3,…]` 波动 ⇒ **拿它下结论是错的**（我犯过）。

## 实现·使用方法（停止 / 恢复加速）

```python
# 停用（两个文件都要改；纯 ASCII、无 BOM —— 硬要求）
import os
files = [
    r"<游戏目录>\patch\pl_06.ini",
    r"<游戏目录>\patch\xiaoan66\pl_06.saves.ini",
]
for p in files:
    raw = open(p, "rb").read()
    assert raw[:3] != b"\xef\xbb\xbf", "有 BOM，必须先去掉"
    lines = raw.decode("ascii").splitlines()
    sec, idx, out = None, 0, []
    for ln in lines:
        s = ln.strip()
        if s.startswith("[") and s.endswith("]"):
            sec, idx = s, 0
            out.append(ln); continue
        if sec is not None:                      # 存档段：每个段的 [0]/[6]/[15] 归零
            out.append("0" if idx in (0, 6, 15) else ln)
            idx += 1
        else:                                    # 全局文件：只有 [0]/[6] 归零
            out.append("0" if idx in (0, 6) else ln)
            idx += 1
    open(p, "wb").write(("\n".join(out) + "\n").encode("ascii"))

# 恢复：直接用 .bak_停加速前_20261015 覆盖回即可
```

**改完必须重启游戏**（配置在启动时读；存档段在读档时套用）。

**验证**：⚠ **不要用 `0x4B3D20`**。请**人眼/手感确认**速度，或读游戏内加速菜单看开关状态。

## 风险与边界

* **BOM 陷阱**（本页最重要）：任何"写数字配置文件"的脚本**一律用 `wb` + `ascii`**，
  不要用 PowerShell `Set-Content -Encoding UTF8`。
* **只改全局无效**：`pl_06.saves.ini` 里有该存档段时会覆盖全局 ⇒ **必须改存档段**。
* **不要动 DLL**：`Koeicda.dll` 换原版会导致读档框不出现；`GearNtKe.dll` 停掉不解决问题
  （2026-10-15 A/B：只停它仍闪退）。
* **`0x4B3D20` 只是状态指示**，别拿它判"是否真加速"。
* 停用**不影响** `patch` 目录以外的东西（不动 EXE、不动存档）。
