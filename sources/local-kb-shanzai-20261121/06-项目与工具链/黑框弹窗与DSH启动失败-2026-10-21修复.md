# 黑框弹窗与 DSH 启动失败 —— 2026-10-21 修复定案

## 结论速览

- **「每几秒闪一个黑框」的元凶 = `phone-tools.vbs` 里的 `WScript.Shell.Exec("netstat ...")`**。
  **`Exec` 每次调用必创建一个可见控制台窗口**；该调用在"等 DSH 就绪"的 5 秒轮询里，
  探测失败就空转 150 秒 ⇒ **连闪 30 次**。
- **探测失败的原因**：DSH 的 `webserver` 配置块丢失后改用**随机端口**（实测 64832），
  而脚本写死 19387 ⇒ 永远探测不到。
- **「DeepSeek Harness is unavailable」弹窗 = `host: 0.0.0.0` 被 DSH 0.2.1 拒绝**。
  必须绑**具体地址**（`127.0.0.1`），否则 webserver 插件激活失败 ⇒ 5 个插件卡在等 `webServer` ⇒ 启动失败。
- **手机代理也写死 19387** ⇒ 手机访问其实早就坏了（表现为 401 或连不上）。
- 修完后实测：DSH 固定 19387、手机入口/窗口镜像本机与内网各 5 次全部 200、代理连打 20 次 20/20、**conhost 无新增（零黑框）**。

## 适用版本

- DSH 桌面版 **0.2.1**（`DeepSeek Harness.exe`，安装于 `%LOCALAPPDATA%\Programs\DeepSeek Harness`）。
- 0.2.0 时代允许 `host: 0.0.0.0`，0.2.1 **不允许** —— 这是升级后行为变化的关键点。
- 与 `Ekd5.exe` 样本无关。

## 已确认事实

### 1. DSH 0.2.1 拒绝通配地址（崩溃日志原文）

日志位置：`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-*-host.log`

```
Error: webserver: host "0.0.0.0" is an unspecified (wildcard) address,
which is not supported: binding every interface would expose remote code
execution to the network; bind one concrete IPv4 or IPv6 address of a
local interface instead
```

连锁反应（弹窗里显示的就是这个）：

```
webserver 插件激活失败
  ⇒ web-runtime / open-in-app / directory-picker / client-hmr 等 5 个插件
    卡在「等待 webServer 服务」
  ⇒ 启动审计失败（AggregateError: Plugin activation failures）
  ⇒ 弹窗「DeepSeek Harness is unavailable」
```

**正确写法**（`~/.dsh/profiles/desktop/cordis.patch.yml`）：

```yaml
- id: webserver
  config:
    host: 127.0.0.1      # ★ 必须具体地址，不能 0.0.0.0 / ::
    port: 19387
```

绑 127.0.0.1 **不影响手机**：19388 代理是从**本机回环**连上去的。

### 2. `WScript.Shell.Exec` 必开控制台（黑框根因）

| 写法 | 是否弹窗 |
|---|---|
| `sh.Exec("cmd /c netstat ...")` | ❌ **每次必开可见控制台** |
| `sh.Run("cmd /c ...", 0, False)` | ⚠️ 窗口样式 0 可隐藏，但 `start /min /b` 仍会给你一个最小化控制台 |
| **`WinHttp.WinHttpRequest.5.1` 探 HTTP** | ✅ **零进程、零窗口**（本次采用） |

替换实现（`phone-tools.vbs` 的 `PortListening`）：

```vbs
Set http = CreateObject("WinHttp.WinHttpRequest.5.1")
http.SetProxy 1                 ' 1 = 直连，避免系统代理拦 127.0.0.1
http.SetTimeouts 500,500,500,800
http.Open "GET", "htt[本地盘]//127.0.0.1:" & port & "/", False
http.Send
If Err.Number = 0 Then PortListening = True    ' 能建立连接就算在听（401/403 也算）
```

### 3. 端口不要写死：两种无窗口探测法

**VBS 侧（WMI，零子进程）**：

```vbs
Set svc = GetObject("winmgmt[本地盘]\\.\root\StandardCimv2")
Set conns = svc.ExecQuery("SELECT LocalAddress,LocalPort,OwningProcess " & _
                          "FROM MSFT_NetTCPConnection " & _
                          "WHERE State=2 AND LocalAddress='127.0.0.1'")
' 再按 DeepSeek Harness.exe 的 PID 匹配
```

**Python 侧（IP Helper API，纯 ctypes）**：`GetExtendedTcpTable(..., TCP_TABLE_OWNER_PID_LISTENER)`
读出「监听端口 → 属主 PID」，配合 `tasklist`（加 `CREATE_NO_WINDOW = 0x08000000`）拿 PID。

### 4. 手机代理的两个坑

1. **`UPSTREAM_PORT` 不能写死** —— 改为 `detect_upstream_port()`：
   环境变量 `DSH_UPSTREAM_PORT` → `--upstream-port` → 查进程 → 回退 19387。
   **`LOOPBACK_AUTHORITY` 必须跟着上游端口变**（cookie 名 =
   `dsh-auth-<b64(sha256(authority))>`，authority 错就必然 401）。
2. **偶发 401（实测约 1/10）** —— 同一 cookie 直连 DSH 100% 通，经代理偶发 401。
   已加**内部重试**：GET/HEAD 收到 401 时换一个新签 cookie 重发一次。修好后连打 20 次 = 20/20。

### 5. 三种文件的编码铁律（都踩过）

| 文件类型 | 必须存成 | 原因 |
|---|---|---|
| `.vbs` | **纯 ASCII** | WSH 按 ANSI 代码页读，中文会乱码 |
| `.ps1` | **UTF-8 带 BOM** | PS 5.1 读无 BOM 的 UTF-8 会按 GBK 解析 → 中文路径乱码 → 语法错 |
| `.cmd` / `.bat` | **GBK 或纯 ASCII + CRLF** | cmd.exe 按 936 解析；LF-only 会解析错乱 |

**MCP `kb` 服务掉线的修法**（本次一并处理）：

## 风险与边界

1. **`host: 127.0.0.1` 意味着局域网无法直连 19387** —— 手机必须走 19388 代理。这是有意的安全取舍。
2. **改 `cordis.patch.yml` 有启动失败风险** —— 改前必备份；本次已提供带自动回滚的重启脚本思路
   （起不来就还原备份再启动）。
3. **401 重试只对 GET/HEAD 做**：POST 带 body 不能重放，否则会重复提交。
4. **孤儿 MCP 进程会累积**：每次 DSH 异常退出都可能留一个，占用不大但会越积越多，建议定期清理。
