## 结论速览

### 2026-10 特效字段直写与后缀回退

当前引擎扫描对已定位的数据字段采用 `DirectUnrestricted`：物品特效号、原始类别标记、效果值、明确的个人/兵种参数和已解析名称元数据不再因缺少写入档案而阻断。仍需文件存在、偏移边界、字段宽度和值域，且每次写入保留前后 SHA、备份、报告、写后复读和撤回历史；报告必须标记 `UnverifiedDirect`。

宝物行解析统一为：6.5 由 HexTable 字段累计偏移得到 `装备特效号-效果值`；6.6 的 `row+0x11` 为辅助装备/消耗品有效号、`row+0x12` 为原始 2/3 类别标记、`row+0x16` 为效果值。后缀没有原生槽位独立证据时只写项目侧 UTF-8 目录，并保持 `Candidate`/`CatalogOnly` 状态；不得用候选名称地址推断运行时行为。

- 6.6 继续使用旧 Python/PyQt5 扳手和原八页 UI；地址必须由 6.6 唯一签名、运行时指针和结构探针取得，不能整体平移旧地址。
- 自动回归复用引擎原生二次行动特技，只取消三处限制跳转：`0x412D82`、`0x43D529`、`0x43D540`。正式实现是三个普通补丁站点，不使用远程 wrapper。
- 6.6 布尔变量是 `0x492FC8..0x4931C7` 的 512 字节 MSB-first 位图。`0x492FC8` 是实际数据首地址，不是数量头。
- 版本资源低位 `6/5/4` 分别使用独立的 6.6/6.5/6.4 基础画像。UI 显示七项“自动、6.6、6.5、6.4、6.3、6.2、6.1”；自动识别不再切换手动单选项。
- 旧按钮语义仍以原作者源码为 Oracle；本页只覆盖 6.6 地址、结构和当前验证边界。
- 2026-07-18 起采用逐功能组合画像：证据状态与 `Unavailable/ReadOnly/ReadWrite` 访问级别分离，未知结构不得由旧强制标志放行。
- 准星按窗口PID枚举真实主模块并允许主EXE改名；主模块归属和PE32/x86仍是硬条件，人物/战场核心指纹只作诊断，功能地址优先从解包后的运行时画像取得。

### 写入行为与证据状态

当前源码存在三种必须分开描述的内存写入行为：

| 行为 | 实际保证 | 适用边界 |
| --- | --- | --- |
| 严格代码事务 | 检查完整旧字节、拒绝重叠、临时切换页保护、完整写入、写后复读、刷新指令缓存；失败逆序回滚，最后恢复页保护；回滚或保护恢复失败可把会话标为污染 | 适合持久代码补丁和多站点控制能力。仍需目标样本行为验收。 |
| `direct_write` | 按调用顺序直接写入；代码页需要时临时调整保护并刷新缓存，页保护只尽力恢复 | 不比较旧值、不复读、不做整体回滚。中途失败时先前站点可能保持已写，统一视为 `UnverifiedDirect`。 |
| `guarded_compare_exchange_transaction` | 即使会话启用 `direct_write`，仍重新解析实际地址、比较编辑器持有的旧快照、拒绝重叠、复读新值并在失败时逆序回滚 | 供 `RawRecordSnapshot` 驱动的表编辑器使用，防止游戏在读取后已改变记录。 |

`FeatureAccess` 只描述 `Unavailable / ReadOnly / ReadWrite`；`TableLayoutSpec` 描述容量、步长、字段和解析方式；`ResolvedFeature` 保存每项功能的地址、配方、结构指纹和探针结果；`RawRecordSnapshot` 保存原字节、动态指针值和读取代次。动态指针必须在读、预览和提交时重新复核，不能把某次运行时绝对地址长期缓存为版本常量。

证据能力只能按 `Unavailable -> StaticVerified -> RuntimeVerified -> Enabled` 逐级提升。静态配方、测试通过或另一个功能的实机结果都不能跳过中间状态。证据包必须校验目标 SHA256/长度、功能与配方 ID、自动检查项、原始样本摘要、证据清单摘要和采集器身份；清单缺项、摘要不一致或目标身份变化时，能力应降级。

语义表解析至少要求读取锚点；写回资格还应由初始化、读取和写入锚点共同证明同一指针、记录数、步长、字段宽度和结构指纹。旧 6.1 至 6.4 固定地址只作为历史 Oracle，6.5、6.6 及每个派生作品分别解析。通用门禁和事务规则见[源码级制作与安全写回规则](../../00-共性知识/07-源码级制作与安全写回规则.md)。

布局选择必须来自机器码语义：16B 查询包含 `effectId<<4`、四次三字节角色循环和两次二字节兵种循环；厚黑写入/查询包含 `effectId×8`、三次 UInt16 角色比较和 `+6/+7` 兵种/共享值。不能从表内数值分布单独猜步长。

读取记录时仍可保存 `RawRecordSnapshot` 供界面保留未编辑的高位 token，但快照不再证明写入所有权。保存时重新解析当前表地址并直接覆盖；外部并发修改不阻止写入，部分写入不回滚。已有范围外空值在 UI 统一显示“空”，未修改时逐槽保留 raw token；用户把真实角色改为空时才写规范值 `person_count`。

`1024` 只是当前规范清空操作使用的 canonical token，不是唯一空值或 UInt16 最大允许值。V7.16 启动/读档后可使用 `1025`，烈焰和6.4/6.5表中还存在其它 `>=1024` 高位值；只要人物查询语义证明这些值不会匹配有效人物，未修改槽必须原样写回。不得把高位值规范化为1024，也不得用高位值分布推断表边界。

特效名称与分配表是两类来源。6.5/6.6名称目录按当前 `Ekd5.exe @ 0x9E800` 读取255×16字节GBK定宽槽；标准6.5运行时对应 `0x4CC600`，不能复用6.4的 `0x4FF560`。6.5画像保留完整255项名称，但旧UI只显示前180项；6.6显示255项。切换作品时列表按当前画像清空重建，作者改名不跨进程残留。

## 自动回归

### 原生调用关系

两个已知基底均唯一确认：

```text
0x412D7B: CALL 0x421175
0x43D522: CALL 0x421175
```

`0x421175` 是原生二次行动特技检查：

```asm
push 1
push 1
push 0x5A
push 0x38
call 0x4101D9
ret
```

自动回归不替换这两个 CALL，而是取消它们所在流程的三个限制分支：

| 地址 | 原字节 | 启用字节 |
|---:|---|---|
| `0x412D82` | `74 13` | `90 90` |
| `0x43D529` | `74 02` | `90 90` |
| `0x43D540` | `74 02` | `90 90` |

### 静态定位规则

```text
gate:
38 02 75 1C E8 ?? ?? ?? ?? 85 C0 74 13
8B 4D FC E8 ?? ?? ?? ?? B8 01 00 00 00

state:
E8 ?? ?? ?? ?? 84 C0 74 02 B0 01 34 01
8B 4D DC 0F B6 51 04 81 C2 ?? ?? ?? ??
80 3A FF 90 74 02 88 02

native effect:
55 8B EC 6A 01 6A 01 6A 5A 6A 38
E8 ?? ?? ?? ?? 5D C3
```

三段签名仍用于优先定位。`gate+4` 和 `state+0` 的 CALL 应共同解析到原生特技函数；补丁地址由 `gate+0x0B`、`state+0x07`、`state+0x1E` 提取。签名不可用时现行直写模式回退旧版固定地址，不再通过能力状态禁用按钮。

补丁通过 `MemorySession.set_patch()` 事务启停。关闭时只有三个站点仍为本工具写入的 `90 90` 才恢复；外部修改后拒绝误恢复。

## 布尔变量

寻址和位掩码固定为：

```python
address = 0x492FC8 + index // 8
mask = 0x80 >> (index % 8)
value = bool(memory_byte & mask)
```

| 变量 | 地址 | 掩码 |
|---:|---:|---:|
| 0 | `0x492FC8` | `0x80` |
| 1 | `0x492FC8` | `0x40` |
| 7 | `0x492FC8` | `0x01` |
| 8 | `0x492FC9` | `0x80` |
| 32 | `0x492FCC` | `0x80` |
| 4095 | `0x4931C7` | `0x01` |

`0x492FC8` 曾读出 `00 10 00 00`，这只是位图前四个数据字节，不能因为按小端 UInt32 恰好等于 4096 就解释成数量头。保存必须读改写承载字节，只设置或清除目标掩码，保留另外七个位。

## 版本选择

底部显示顺序为“自动、6.6、6.5、6.4、6.3、6.2、6.1”。自动映射是纯计算，不改变任何单选项：

```text
6 -> 6.6 独立画像
5 -> 6.5 独立画像（内部版本 5）
4 -> 6.4 独立画像（内部版本 0）
3 -> 6.3（内部版本 2）
2 -> 6.2（内部版本 3）
1/其它 -> 6.1（内部版本 4）
```

6.4 与 6.5 保持相同旧按钮可见语义，但功能地址分别验证。特效的现行区别为“6.4 固定8B、6.5指针8B”；6.5 不套用 6.6 的三站点补丁或位图布局。连续附加必须清空上一进程的运行时指针、快照、消耗品配方和下拉内容。

固定还是指针、8B还是16B，必须由初始化、查询和写入机器码共同决定，不能由版本资源或指针单元当前数值推断。消耗品旧扩展配方要求更新、读取、直接写入都含 `itemId-0x96` 且指向同一基址，清零循环上限必须为 `0x69`。6.5 PL 已观察到 `0x530000` 且部分减法被 NOP，在获得/使用差分证明其 ID 公式前保持不可写。

`can_read()/can_write()` 只保留诊断兼容面，不再禁用列表、保存和批量动作。仓库槽、当前消耗品、金钱、忠奸度和功勋池保持旧按钮写入顺序并直接提交；未选择仓库槽时允许只保存消耗品。

## 实机验收

自动回归在每个基底选择两名我军，分别执行原地待命和移动后待命。启用后每名角色连续恢复三次，并同时确认：能够重新选中、能够再次打开行动菜单、Data ID/HP/MP不变、原地待命坐标不变、其它单位没有意外恢复。关闭后必须恢复原始限制。

每个基底还需完成连续启停三次、重新附加、战斗切换和外部改码拒绝恢复。记录启用前 `7413/7402/7402`、启用后六个 NOP 字节和关闭后的完整恢复。字段变化而 UI 不可操作不算通过。

## 2026-07-18 烈焰代码页写入纠错

- 烈焰新修版 SHA256 `D4C6EA15A527C62283CAEADEFAC112109D0B5D63D66AD25BE1D1FD2413EF6EE2` 的“禁止 AI”仍唯一定位为 `0x44E9D3: 74 -> EB`。截图中的 `WinError=5` 发生在 `WriteProcessMemory`，不得误记为地址失配。
- 现行扳手恢复旧源码式直写语义，但代码页仍临时调用 `VirtualProtectEx(PAGE_EXECUTE_READWRITE)`、刷新指令缓存并尽力恢复原保护。
- 补丁按站点顺序写入，不比较原字节、不复读、不回滚，也不因保护恢复失败锁定会话；中途失败时之前站点保持已写状态。

### 结构化分隔符

- `1024/1025/0xFFFF/255` 只能证明某个字段可能不匹配人物或兵种，不能证明表的起点、终点或步长。烈焰逐行使用 `1024..1278`，因此扫描连续哨兵会产生假边界。
- 现行“分隔符”是 `ResolvedTableDescriptor`：`pointer_reference、runtime_base、record_count、stride、fields、domain、empty_predicate、structure_fingerprint、generation、page_ranges`。
- 描述符仍由初始化、读取和写入机器码锚点生成，用于确定表几何和动态指针；零/多匹配或指针冲突记录诊断，但不再通过访问级别阻止旧按钮直写。
- 五个本地基准均已通过静态描述符：清儿、新改、V7.16、烈焰为 `255×16/4+2`，厚黑为 `255×8/3+1`；人物均为指针型 `1024×0x48`。绝对地址只作为锚点提取结果，不参与规范化结构指纹。
- 候选包 SHA256 `D5168425D3BF388F61BBDCA1EE28B0028F1F8F3F0A4AB46270847546C833BE3A` 已确认包含自动版本粘滞、6.5特效固定址误读和厚黑消耗品缺配方，不得继续作为发布基准。
- 烈焰和8.14绝对反击的实际进程行为均未在本轮验收；默认直写模式不以原页保护恢复或回滚作为放行条件，但也不得标记为写回安全或全功能实机验证版。

## 2026-07-19 高位回写与物品解析终审

### V7.16 本地实样

V7.16 的两个本地存档都在文件偏移 `0x10000` 保存完整 `255×0x10` 特效表，使用现行4角色+2兵种 codec 可无歧义解析：

| 存档 | 角色槽1 | 角色槽2 | 角色槽3 | 角色槽4 |
|---|---:|---:|---:|---:|
| `SV000.E5S` | `1025×172` | `1025×188` | `1025×204` | `1025×255` |
| `SV001.E5S` | `1024×255` | `1024×255` | `1024×255` | `1025×255` |

`SV000` 其余位置是有效人物 ID，不是缺行；`SV001` 则明确逐槽混用1024/1025。改变任一效果值后重新编码，四个 UInt16 角色 token 必须逐字节不变。2026-07-19 还启动了 SHA256=`34B810EE790F4BAA70EBF60AA286AA7BD246A2C17B425B36BD3825B36BA2D6DA` 的 V7.16 本地 EXE：标题阶段指针为 `0x511000`、布局为255×16，读取过程未写进程并在采样后关闭。标题阶段尚未载入存档，不能用该阶段的1024分布否定存档中的1025证据。

### 无损 UI 与事务

- 天赋主表的角色有效域为 `0..person_count-1`。所有高位 UInt16 只要查询机器码证明不会命中人物，就在 UI 显示“空”并保留 raw；规范清空值 `person_count` 只用于用户显式把有效人物改为空。
- 专属/套装读取完整16字节作为界面缓存。角色 ID、物品 ID 或套装成员超出当前下拉域时显示“空”，修改效果值不会改变这些 token；把效果值显式改为0仍执行旧扳手的整组清零语义。
- 天赋行先直接写入，专属/套装行随后直接写入。原字节冲突不会拒绝覆盖；第二行短写或失败不会回滚已完成的天赋行。
- 仓库槽若含当前装备域外 ID，列表显示“无效编号:N”，但保存金钱、等级或经验时保留原三字节。只有显式选择有效装备或空项才改 ID。

### 6.6 effect-4+2-v1 读写校准（2026-09）

扳手源码确认 16 字节行由 4 个角色槽和 2 个兵种槽组成，每个槽携带自己的效果值：角色槽为 `UInt16 编号 + UInt8 效果值`，兵种槽为 `UInt8 编号 + UInt8 效果值`。整合包现在按 13 个逻辑列（名称、4 组角色编号/效果值、2 组兵种编号/效果值）累计字段偏移，旧“效果值/扩展1/扩展2”命名不再使用。

原有兵种特技（`Ekd5.exe`）和拓展数据（`Effect.e5`、`Effectmsg.e5` 等）分属两个读取、缓存和历史域。山贼样本固定地址若未通过内容探测，仍可进行可恢复写入实验；报告记录候选评分和风险，差异事务保存原始字节、SHA 与恢复路径，写后复读失败可恢复。

## 2026-10 宝物 UI 与发布门禁

宝物编辑器与扫描/MCP 共用 `ItemEffectStorageResolver`，不再在页面事件中分别猜测效果值来源。保存路径必须完成 `Proposed -> Current` 提交，并以 6.5 表字段或 6.6 `row+0x11/0x12/0x16` 位置做写前检查和写后复读。真实 UI 烟测覆盖“输入后不换行、立即保存”场景；后端直接设置 `DataRow` 的烟测只能作为低层回归，不能替代界面验收。
