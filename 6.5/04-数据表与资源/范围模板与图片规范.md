# 范围模板与图片规范

## 配置模型

`RangeProfile` 包含：单字节 `Id`、`Attack/Pierce` 类型、名称、格点 `Cells`、原始两字节段落 `EncodedSegments`、参考图片编号、证据状态、编解码器版本、`OverrideOf`、`RuntimeId` 和动态测出的 `MaxVerifiedTargets`。格点必须包含 `(0,0)`，最多 32 个，不得重复，坐标限制为 `-32..32`。攻击和穿透 ID 分开校验，禁止类型混用。

配置文件：

```text
项目工作区/CCZModStudio_Config/RangeProfiles.json
```

## 图片生成

- 攻击范围输出到 `Hitarea.e5`，穿透范围输出到 `Effarea.e5`。
- 生成器从参考 PNG 读取尺寸、背景、活动格和中心格颜色；没有有效参考图时使用固定 192×192 透明栅格样式。
- 生成是确定性的，同一模板每次输出完全相同；图片只负责显示风格，不定义引擎行为。
- `E5ArchiveAppendService` 追加目录条目和 PNG 载荷，写入前备份，写入后重新解析并验证新条目；旧条目载荷必须逐条保持一致。

## 反推辅助功能边界

从既有预览图估计格距、中心格和活动格只能作为模板编辑器输入。识别失败、低置信度或手动点选结果不能直接产生 EXE 写入授权，必须经过字节差分和实机探针。

## 版本与证据

`BuiltIn` 表示工具内置名称，不代表本版本已经证明每一个名称的业务 ID。F9A `00436616` 已静态确认 segment 几何：第一字节是 X 轴绝对偏移，第二字节是 Y 轴绝对偏移，双非零时生成四个镜像格点；单轴分支、中心点插入、packed descriptor 字节顺序仍待动态探针。`Custom`/`Unverified` 表示可保存和预览但不可写 EXE；`Verified` 只能由完整探针报告提升。跨版本教程不得直接成为 6.5 默认编码器。

## 原生表与运行时描述表

F9A 的原版范围指针表位于 VA `004D1400`（当前 PE 文件偏移 `0xA2C00`）。每个表项为 little-endian 32 位指针，指向连续的两个字节 segment；segment 以 little-endian word `FFFF` 结束。当前 6.6 的几何函数入口为 `00436611`；历史资料中的 `00436616` 仅作为旧样本指令位置对照。静态指令确认第一字节为 X 轴绝对偏移、第二字节为 Y 轴绝对偏移；双非零时对中心坐标做四向镜像展开。工具的 `RangeTableReaderService` 仍只负责读取和报告原始字节，不能把该静态几何结论扩大成未经动态验证的业务 ID 或完整战场语义。

未来代码洞描述表使用以下确定性布局，游戏不直接读取 JSON：

```text
magic[4] = CCZR
codec_version[1]
reserved[1]
attack_profile_count[2]
pierce_profile_count[2]

profile:
  kind[1]              0=Attack, 1=Pierce
  id[1]
  override_of[1]       FF means no native replacement
  cell_count[2]
  cell[cell_count]: signed X[1], signed Y[1]
  encoded_segment_count[2]
  segment[encoded_segment_count]: first[1], second[1]
```

描述表只在 Attack/Pierce Hook 契约、SHA、旧字节、代码洞范围和动态实机证据全部通过时嵌入 EXE。未通过时，工具仍可生成描述表 SHA 供审计，但不会写入机器码或覆盖 `004AC748`、`004927F0+0x10`。

范围图片追加到 E5 后，工具会重新解析目录、复读 PNG 载荷、保留旧条目载荷并输出目录 SHA。参考图片只决定尺寸、透明度和颜色风格；图片活动格不能替代引擎 segment 的动态验证。

## F9A 资源与 ID 护栏

本次静态扫描得到的原版范围表结果是“读取到 36 个以 `FFFF` 终止的有效表项”，它只说明当前 `004D1400` 表中存在这些可解析条目，不等于 36 个条目的每一个都已经完成战场行为验证。工具和文档必须把“表项可读”和“运行时语义已验证”分开显示。

自定义运行时 ID 与 E5 图片编号分离管理：

- 运行时 ID 是传给攻击/穿透分派逻辑的单字节值；图片编号是 `Hitarea.e5` 或 `Effarea.e5` 的目录顺序，两者不能互相推导。
- 自定义 ID 分配器必须避开 `0xFF`、特殊候选 `0x0A`/`0x0B`、当前 F9A 无效或未初始化的 `0x24`/`0x25`，以及所有已登记的原版 ID。
- 在动态契约尚未确认前，只能分配项目配置中的临时/自定义 ID，并生成预览和报告；不能把 ID 写成可运行的 EXE 分支。
- 删除模板前必须扫描 `Data.e5` 兵种、策略字段和项目配置引用；存在引用时阻断删除并列出引用位置。

## E5 追加烟测结果

`E5ArchiveAppendService` 的当前职责是保留旧目录、共享载荷和条目顺序，在目录尾部追加 PNG 条目，写前备份、写后复读并输出目录 SHA。范围模板相关烟测已经通过：

- `RANGE_PROFILES_SMOKE_OK`：模板校验、确定性图片生成和配置往返。
- `RANGE_NATIVE_STATIC_SMOKE_OK`：F9A 原生表按 section 映射读取、segment 原始字节保留和 `FFFF` 终止检查。
- `RANGE_PROBE_PLAN_SMOKE_OK`：17 个断点、寄存器/栈参数/关键全局内存采集计划可生成。
- `RANGE_RUNTIME_ASSEMBLY_SMOKE_OK`：未有 `InGameVerified` 契约时，攻击运行时汇编生成器保持阻断；原版表槽位映射 `0x0C -> 0x0A` 通过。
- `RANGE_NATIVE_STATIC_SMOKE_OK` 同时覆盖未修改 segment 的原版表替换预览，确认可复用 `PatchApplyService` 而不写入基底。

这些是工具层和资源层烟测，不代表“图片活动格 = 引擎受击格”。当前可把 segment 几何标记为 `StaticConfirmed`，但只有动态探针在固定矩阵地图中闭合“预览活动格 = segment 解码格 = 实际可选攻击格 = 实际穿透受击格”四方一致性后，图片编号和范围模板才可标记为 `InGameVerified`。

## 资源反推的证据边界

从现有预览图识别格点时，先用已知图估计格距、中心格、活动格颜色和透明度，再把结果交给模板编辑器。反推服务输出置信度和人工点选结果，但不产生 `EncodedSegments` 的可信语义，也不绕过 SHA、旧字节、Hook 契约和实机验证门禁。图片只能复现显示风格，不能作为攻击范围或穿透范围的行为定义。

## 写入门禁与当前验证状态（2026-08-24）

原生表替换使用逐段旧字节锁：短 segment 原地写回时锁定完整原槽位；超长 segment 重定位时同时锁定代码洞载荷区和 `004D1400` 表项原指针。预览或应用时只要任一锁定字节不匹配，必须拒绝写入，不能依赖全文件 SHA 单独放行。

运行时 Hook 包必须同时携带 Attack/Pierce 两份 F9A 契约的 ID、契约哈希、代码身份哈希和证据状态；两类 Hook 均达到 `InGameVerified` 才可授权正式应用。当前桥接调试器未在线，尚未生成真实 `RangeHookContracts.json`，所以范围配置、PNG/E5 资源和静态描述表可以保存/预览，但 EXE 运行时分支仍明确标记为 `NeedsVerifiedHook`。
