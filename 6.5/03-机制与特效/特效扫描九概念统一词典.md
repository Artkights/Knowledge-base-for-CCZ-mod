# 特效扫描九概念统一词典

## 适用范围

本页统一“引擎号、宝物特效号、个人特效号、宝物特效名称、宝物特效后缀、个人特效名称、个人特效后缀、宝物特效值、个人特效值”九个概念。当前主样本是 `基底/复刻版6.6山贼/Ekd5.exe`，SHA256 为 `6929FE0DB049935EEC793CE785D431947E48BED406ED94233F9B3A9C6DB4BCB8`；结论不得自动套用到其他版本。

## 统一定义

| 概念 | 数据层 | 正式口径 | 空值/高位规则 |
|---|---|---|---|
| 引擎号 | EXE 调用参数 | 进入特效核心或包装函数的逻辑编号；一个编号可有多个物理来源 | 不能把任意立即数当作引擎号；必须保留定义链和渠道 |
| 宝物特效号 | 物品/装备渠道 | 四参数 ABI 的装备参数，或物品记录解析出的有效效果号 | `00` 表示不使用宝物渠道；`80-FF` 可保存但无证据时只能标为未验证 |
| 个人特效号 | 人物/兵种渠道 | 四参数 ABI 的个人参数，来源还包括兵种分配、人物专属、套装和 6.6 扩展效果 | `FF` 不是全局空值；空槽按对应表和版本规则判断 |
| 宝物特效名称 | 显示元数据 | 项目侧目录、目标 EXE 名称池、已验证绑定、基础名称表按优先级解析的文本 | 名称存在不代表运行时行为已确认 |
| 个人特效名称 | 显示元数据 | 6.X-7 名称区、目标 EXE 定长名称池、绑定表和扩展表的文本 | 与绑定和机器码证据独立记录 |
| 宝物特效后缀 | 显示元数据候选 | 目前未定义；待从旧工具、导出文本、界面拼接和目标样本确认 | 未确认前使用 `suffixStatus=Undefined` |
| 个人特效后缀 | 显示元数据候选 | 目前未定义；不得从宝物后缀推导 | 未确认前使用 `suffixStatus=Undefined` |
| 宝物特效值 | 物品绑定参数 | 物品行的效果值字段；其单位由效果值模式和消费者决定 | 必须记录原始值、读取位置、解释类型和证据等级 |
| 个人特效值 | 人物/兵种绑定参数 | 兵种/武将分配、人物专属/套装或扩展效果中的效果值 | 6.6 ExtendData 返回值存在 24 位组合及 EXE 取 AL 边界，不能当普通整数值处理 |

## 四参数 ABI

```text
push 效果值模式
push 叠加方式
push 宝物特效号
push 个人/兵种特效号
ECX = 当前单位指针
call 004101D9
```

效果值模式 `0` 读取配置值，模式 `1` 只返回拥有开关；叠加方式 `0/1/2` 分别表示个人与宝物相加、不相加、宝物优先回退个人。`0041301E`、`00413009`、`0042518F` 是相关双渠道/取值/包装路径。静态扫描必须保存参数定义链；`mov/add/lea` 和间接内存来源不得截断成固定编号。

## 6.6 物品纠偏

目标样本物品运行时记录候选为 `0049F820 + item_id*0x19`。`row+0x16` 是特效值候选；`row+0x11` 是类型/有效效果号候选；`row+0x12` 在辅助装备和道具中常为 `2/3` 类别标记。扫描和导出必须同时保留：

```text
rawId/rawMarker = 原始物理字节
effectiveId     = 按物品类别规则解释后的有效宝物特效号
effectValue     = 效果值字节及其来源
```

因此旧 CSV 中的 `255/FF` 只能作为冲突样本，不能直接视为真实宝物特效号。普通装备、辅助装备、道具/消耗品必须分别标注解析规则和物理偏移。

## 证据状态

每个概念至少带 `evidenceTier`：`VerifiedCurrentBytes`、`VerifiedTableField`、`InferredStaticDataFlow`、`Dynamic` 或 `SampleOnly`。名称、特效值和运行时行为分别评级；名称目录、旧 TXT、相似样本和静态候选不能单独提升写入权限。

6.6 物品逐行诊断见 `CCZModStudio_Reports/EffectSemantics/6.6山贼物品原始效果号诊断.json` 与同名 Markdown。报告以 `rawMarker` 和 `effectiveEffectId` 双字段保存 2/3 类别标记纠偏，并记录 Data.e5/Star.e5 SHA、文件偏移、效果值来源和旧 CSV 冲突。

## 2026-10 统一读写实现

`ItemEffectStorageResolver` 是物品三字段的唯一物理位置来源。6.5 从当前表定义累计字段偏移读取效果值，6.6 固定复核 `row+0x11`（类型/辅助装备及消耗品有效号）、`row+0x12`（原始 2/3 类别标记）和 `row+0x16`（效果值）。九概念服务、宝物设定 UI、物品索引和 MCP 不得重新按类别猜测效果值。

扫描到明确物理位置的数据字段可使用 `DirectUnrestricted`：`CanEdit/CanPreview/CanApply=true`、`Capability=DirectUnrestricted`、`ProfileTrustTier=UserAuthorizedUnverified`。该模式不把未知 EXE 档案或发布清单当写入前置条件，但仍执行文件存在、边界、宽度和值域、备份、前后 SHA、复读和撤回。

后缀双层存储优先级是“已验证原生槽位 > 项目 UTF-8 后缀目录 > 候选文本”。当前原生名称池只标记 `Candidate`；没有独立位置证据时 `auto` 只写 `CCZModStudio_Notes/EffectSuffixes.json`，后缀永远不参与特效号或效果值解析。
## 可读写字段状态

当前统一模型为 `EffectNineConceptRecord`，由 `EffectNineConceptService.Read` 生成；`SaveCatalog`、`ExportCsv`、`ExportMarkdown` 用于保存和交换项目侧九概念记录。物品渠道已提供 `PreviewItem`/`ApplyItem`：普通装备写 `row+0x12`，辅助/道具有效号写 `row+0x11`，值写 `row+0x16`，并经 `DifferentialWriteTransaction` 登记撤回历史。

特效清单工作台总览已展示九概念核心列，个人和宝物通道的名称、后缀和值分别显示。项目目录中的后缀字段可编辑，状态仍应保留 `Candidate` 或 `Undefined`；后缀编辑不会改变运行时编号和数值。
