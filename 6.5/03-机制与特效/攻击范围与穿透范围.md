# 攻击范围与穿透范围（6.5）

## 当前结论

### 当前 6.6 山贼样本纠偏

本页早期段落保留了 F9A/6.5 动态研究口径。对当前 `复刻版6.6山贼/Ekd5.exe`（SHA `6929FE0DB049935EEC793CE785D431947E48BED406ED94233F9B3A9C6DB4BCB8`），地址必须按专属静态报告重新绑定：真实范围调用是 `004553F2`，几何函数入口是 `00436611`，攻击上下文入口是 `00406252 -> 00406289`。`004553F8`、`00436616`、`00406232`、`00406282`、`0040629E`、`004062B4`、`004062CA`、`00406323` 均不得作为当前 SHA 的函数入口；这些旧地址只可在历史样本说明或`错误知识纠正台账`（来源文件未随公开知识库发布）中出现。

当前 6.6 静态链：`0043DADA -> 0045533D -> 004553F2 -> 00436511 -> 00436611 -> 00437AFF`；目标结果上下文由 `00406252 -> 00406289` 初始化。目标数组容量、穿透消费和最终业务语义仍待验证。

工具已将范围模板拆成两类：`Attack`（攻击/施法目标选择）和 `Pierce`（穿透受击目标）。用户编辑的格点集合是权威输入，配置保存在项目工作区的 `CCZModStudio_Config/RangeProfiles.json`。

工具当前编解码器为 `6.5-static-pair-v2`：第一字节按 X 轴绝对偏移、第二字节按 Y 轴绝对偏移，并按 F9A `00436611` 的单轴/双轴对称规则展开。编码器仍只产生静态候选结果；packed descriptor 的业务 ID 映射、目标数组容量、中心点插入和运行时 Hook 必须通过动态契约才能升级为 `6.5-ingame-verified-pair-v4`。所有自定义模板默认 `EvidenceStatus=Custom/StaticCandidate`，因此不能正式写入运行时 EXE。

## 已由本地样本确认

- `6.5-4-2 兵种成长` 位于 `Data.e5`，兵种攻击范围是记录内单字节字段。
- `6.5-4-3 兵种穿透` 位于 `Ekd5.exe`，每个兵种使用一个单字节值。
- 策略施法范围和穿透范围复用 `Hitarea.e5` / `Effarea.e5` 图片资源。
- 当前范围预览沿用“字段值 + 1 = E5 图片编号”的既有读取逻辑。
- `Hitarea.e5`、`Effarea.e5` 的索引是 0x110 起的 12 字节目录；旧条目载荷可以在扩展目录时保持不变。
- 战斗上下文中的 `4927F0 + 0x10` 和 `4927F0 + 0x424` 是目标数组/穿透相关运行时字段，但它们不是范围段落编码规则的证明。

## 用户样本与 F9A 几何契约

```text
0,1                 十字
0,1 / 1,1           九宫
0,1 / 1,1 / 0,2     没羽箭
```

用户给出的含义与 F9A `00436611` 的静态几何代码一致，现可标记为 `StaticConfirmed`，但还不能标记为 `InGameVerified`：

- 攻击发起者或施法者中心是 `(0,0)`。
- segment 的第一字节是 X 轴绝对偏移 `dx`，第二字节是 Y 轴绝对偏移 `dy`。
- `(0,1)` 进入单轴分支，表示中心上下左右一格的十字；`(1,1)` 在双轴分支中生成四个镜像角点，和前一段组合后形成九宫。
- 当 `dx`、`dy` 均非零时，静态调用 `00437AFF` 生成：`(x-dx,y+dy)`、`(x-dx,y-dy)`、`(x+dx,y-dy)`、`(x+dx,y+dy)`。
- `0,1 / 1,1 / 0,2` 因此是多个 segment 的并集，中心点是否由分派器单独插入、单轴分支是否包含中心线，仍需动态确认。

对应的 F9A 静态指令要点（省略保存寄存器和过滤细节）为：

```asm
; 00436611
movzx eax, byte ptr [ebp+21] ; segment first byte = dx (X)
movzx ecx, byte ptr [ebp+20] ; segment second byte = dy (Y)
; dx != 0 && dy != 0:
; call 00437AFF(x-dx, y+dy)
; call 00437AFF(x-dx, y-dy)
; call 00437AFF(x+dx, y-dy)
; call 00437AFF(x+dx, y+dy)
```

这些样本仍必须通过原始字节差分、战场格点采集和预览图对照后，才能提升为 `DynamicConfirmed`/`InGameVerified` 编解码规则；不要根据图片编号或名称反推 packed descriptor 的业务 ID。

## 运行时写入边界

新图片可以通过确定性栅格渲染生成并追加到 E5；字段写回仍应使用现有 HexTable/表写入服务。运行时自定义 ID 需要在攻击目标枚举和穿透目标数组处分派。`RangeRuntimePatchCompiler.Compile` 只输出 `NeedsVerifiedHook` 能力报告；新增的 `CompileVerifiedPatchPackage` 会在 SHA、旧字节、指令边界、代码洞和 Attack/Pierce 动态契约全部通过后，生成 NASM 编译的 `EffectPackage`，仍不绕过现有 PatchApply 事务。

## 推荐探针顺序

1. 在测试副本中只改变一个范围 ID，并保存 Data/Ekd5/Hitarea/Effarea 的差分。
2. 固定中心攻击者和矩阵目标，记录可选格、实际受击格、穿透顺序和目标数组。
3. 对范围读取和目标枚举函数设置 x32dbg 断点，确认 ID 来源、段落长度/终止方式、目标上限和特殊 ID 分支。
4. 只有预览格、解码格和实机格完全一致时，才把模板标成 `Verified` 并允许正式 EXE 补丁。

## F9A 汇编静态扫描结果

目标文件固定为 `基底/加强版6.5未加密版/Ekd5.exe`，SHA256：
`F9A357585F4D77C273A8BADD3E4EF4062983CC81D8040C0CB74768FAB7C04F5F`。
ImageBase 为 `00400000`。VA 到文件偏移必须按 PE section 映射；`004D1400` 位于 `.text3`，文件偏移为 `0xA2C00`。

### 攻击范围链

当前 F9A 静态调用链为：

```text
0043DADA  物理攻击入口候选
  -> 004109A1
  -> 0043F8C0
 -> 0045533D / 004553F2（当前样本；`004553F8` 仅为历史资料中的内部地址）
  -> 00436511  packed 范围分派
  -> 00436611  二维 segment 几何展开
  -> 00437AFF  坐标落地、单位过滤、目标追加
  -> 00435884  坐标转地图单位 ID
```

`00436511` 的 `[EBP+0C]` 不是单个编号，而是最多 4 个 packed range byte：

```text
[EBP+0C]、[EBP+0D]、[EBP+0E]、[EBP+0F]
```

普通分支逐字节读取；`FF` 跳过，首字节为 `0` 时只允许首段，`0x0A` 进入全地图特殊分支候选，`0x0B` 跳过/保留，其他值索引 `004D1400`。每个表项指向连续 2 字节 segment，segment 以 `FFFF` 终止，并在 `00436611` 中传入几何展开器。`00436611` 在两字节都非零时静态生成四个对称点：

```text
(x-dx,y-dy) (x+dx,y-dy) (x-dx,y+dy) (x+dx,y+dy)
```

第一字节为 X、第二字节为 Y 已由 F9A 静态指令确认；`1..0x09` 的 `dec eax` 映射、模式位、packed 字节顺序、单轴分支和中心点插入仍属于待动态确认内容。`0043F8C0`/`0043F8FB` 是攻击状态或特效检查候选，不应再解释为范围几何读取函数。

`00437AFF` 执行地图边界、地形、阵营、单位状态过滤，并扫描 `004AC748` 的 `FF` 终止目标数组；`004B2C34` 是写指针，`004B2C28` 是范围扫描哨兵。数组容量没有静态保护结论，不能在 Hook 中直接写满。

### 远距/穿透特效覆盖候选

F9A `00407835` 在读取 `00407881` 兵种穿透表前，会检查 `505FDC`、`500E9A` 和 `0040CC13` 的效果判定桩；`00407831` 是穿透值被覆盖或禁用的高价值候选入口。当前静态代码只能证明“默认表读取 + 若干特效/状态前置判断”，不能证明 `0x79..0x7F` 穿透攻击或 `0x9D..0xA4` 远距攻击已经在 F9A 基底中把特效值直接写成范围 ID。

本地 6.5 特效目录把 `0x33`/`0xDD` 记录为强化攻击穿透样本，把 `0x79..0x7F`、`0x9D..0xA4` 分别记录为穿透攻击、远距攻击系列；这些是语义目录和注入样本，不等于当前 EXE 已安装。针对当前样本，动态探针应在 `00407835`、`00407831`、`0040CC13`、`00406289` 观察效果号、返回值和 `004927F0+0x424` 的先后关系；`00406282` 只保留为历史地址说明。

### 穿透范围链

`00407835` 是当前穿透值读取函数候选，实际兵种表从 `00407881` 读取 80 个单字节值；文件偏移为 `0x6C81`。真实直接调用者为：

```text
00406289  物理战斗上下文初始化函数内部的穿透准备逻辑
004109A9  短包装调用点
00438AC8  另一条战斗/效果路径候选
00477E20  UI/提示/效果路径候选
```

`00406289` 内部将返回值写入 `004927F0+0x424`，随后清空 `+0x10` 目标数组、`+0x84` HP 伤害数组和 `+0x254` MP/效果数组。之后调用 `004364C7`：

```text
ECX      = [004927F0+0x0C]  攻击者战术单位指针
[EBP+08] = [004927F0+0x01]  当前目标战场编号
[EBP+0C] = [004927F0+0x424] 穿透值
[EBP+10] = pointer to [004927F0+0x11] 输出缓冲区候选
[EBP+14] = 0
[EBP+18] = FF
[EBP+1C] = FF
```

`004364C7 -> 00435CE9 -> 0042399B -> 00435C10` 是当前样本的穿透/效果目标扩展候选链：`00435CE9` 负责分类与 segment 分派，`0042399B` 负责二维几何展开，`00435C10` 负责坐标合法性、单位/状态过滤和目标追加。地址 `00435BF2` 位于函数之间的数据区域，只能作为 `DAT_00435BF2[param_1]` 的表数据候选，不能作为函数入口。`004361B1` 消费 `004927F0+0x10`，计算结果并写入 `+0x84`。首次生成点、主目标/穿透目标排列、终止符和最大容量必须由 x32dbg 动态确认。

`00406289` 清空的是 `004927F0+0x10`，传给 `004364C7` 的输出指针却是 `004927F0+0x11`。因此 `+0x10` 可能保存主目标或前置目标，`+0x11` 可能是穿透追加起点；在动态确认首次写入、`FF` 终止、容量和消费上限前，禁止直接覆盖整个数组。

### 回复周围 HP/MP 等效果范围候选

本次扫描发现恢复类效果不宜直接假定复用攻击范围链：

- `0043CDF5` 是回合开始恢复总处理候选；`0043CE8F`/`0043CE9A` 计算 MP 恢复值，关联 `00421106` 和 `004210AC` 两个恢复值桩。
- `00450986` 是通用 HP 变化事件入口候选，可能承接回复周围 HP 的实际写入。
- `0043D038`、`0043D025` 更接近状态恢复/状态掩码处理，不应直接当作几何枚举器。
- `0043CC9A` 会保存/恢复 `004B2C34` 和 `004B2C28`，并复制 `004AC748` 工作区；任何恢复周围 Hook 都必须保留该范围工作区的进入、退出和游标状态。

本地特效目录中的 `0x64`（恢复周围状态）、`0x65`（回复周围 HP）、`0x66`（回复周围 MP）只说明效果语义。F9A 尚未静态确认它们是否调用 `00436511 -> 00436611 -> 00437AFF`，也未确认是否使用固定九宫/segment 几何。动态探针应在固定矩阵地图中分别触发三种效果，采集候选中心坐标、目标单位列表、HP/MP/状态写入和 `00450986` 调用栈。

### 自定义 Hook 门禁

工具现在提供：

- `RangeTableReaderService`：按真实 PE section 映射读取 `004D1400`、2 字节 segment 和 `FFFF` 终止。
- `RangeEngineVersionProfileService`：绑定 F9A SHA、ImageBase、静态地址和 Hook 候选。
- `RangeProbePlanService`：生成 17 个断点、寄存器/栈参数/全局内存采集和固定战场场景计划。
- `RangeRuntimePatchCompiler`：生成 `CCZR` 描述表和能力报告；`CompileVerifiedPatchPackage` 在两份 `InGameVerified` 契约存在时生成两个代码洞分支和旧字节锁定的 `EffectPackage`，否则保持阻断。
- `RangeRuntimeAssemblyFactory`：按契约生成攻击 `00436511` 和穿透 `00435CE9` 的 x86 分派源，未提供栈偏移、回跳、几何调用和返回策略时拒绝生成。
- `RangeNativeTableWriter`：按 `00436511` 的 ID->表槽位规则预览/应用原版 segment 替换；超长 segment 只在安全代码洞存在时重定位，并复用 `PatchApplyService` 备份和报告。

在 `RangeHookContracts.json`、动态目标数组容量和实机格点闭环完成前，任何自定义范围只能保存模板、预览、追加 E5 图片和写入已确认字段；报告必须显示“运行时范围尚未生效”。

## 2026-08-24 实际攻击范围精确定位

### 结论

通过对移动预览和实际攻击入口做静态交叉追踪，已经可以确认：预览和实际物理攻击共用 `00436511 -> 00436611 -> 00437AFF` 的范围几何与候选单位过滤链。实际物理攻击不是只绘制预览后再走另一套范围，而是由 `0045533D/004553F2` 在攻击入口中再次调用同一个 packed 分派器，读取其返回的目标字节继续执行。

实际穿透范围在目标选定后分叉，不使用 `004D1400` 的攻击 packed segment 表，而是走：

```text
0043DADA
 -> 0045533D/004553F2
 -> 00436511 -> 00436611 -> 00437AFF
 -> 0045533D 返回 AL（目标字节）
 -> 00410F1C
 -> 004064F1
 -> 00406252 -> 00406289
 -> 00407835 -> 004364C7 -> 00435CE9 -> 0042399B -> 00435C10
```

范围值本身的首要来源候选是 `0043F8C0`：`0043DADA` 在物理攻击模式下调用它，取返回 `EAX` 压栈作为 `0045533D` 的 `[EBP+0C]`；`004553F8` 再把该参数传给 `00436511` 的 `[EBP+0C]`。因此实际自定义攻击范围的观察顺序应为 `0043F8C0 返回值 -> 0045533D+0x0C -> 00436511+0x0C -> 004D1400/segment`，而不是只观察预览图片编号。

### `00436511` 为什么是实际攻击范围

`00436511` 的四参数 ABI 为：

```text
[EBP+08] 中心坐标指针
[EBP+0C] packed descriptor，最多四个范围字节
[EBP+10] 模式/中心格/过滤标志
[EBP+14] 临时目标表初始化/返回模式
ret 0x10
```

它在 `[EBP+14]==0` 时将 `004AC748` 首字节置为 `FF`，把 `004B2C34` 设为写指针；遍历 packed descriptor，按 `004D1400` 的指针表读取 2-byte segment，遇 `FFFF` 结束，并对每个 segment 调用 `00436611`。所以它不只是显示层计算，而是在真正构建可攻击候选单位列表。

`0045533D` 在实际攻击中由 `0043DADA` 调用，`004553F8` 明确执行：

```asm
lea edx, [ebp-10]      ; 中心坐标
push edx
push [ebp+0C]          ; packed descriptor
push mode
mov ecx, [ebp-1C]
call 00436511
mov [ebp-14], al       ; 接收范围扫描结果
```

随后 `0043DADA` 将 `0045533D` 的 `AL` 保存到 `[EBP-08]`，并把该目标字节传给 `00410F1C`。因此，攻击范围 Hook 的正确位置是 `004553F8` 调用前或 `00436511` 入口，而不是 `00410F1C`。

### `00436611` 和 `00437AFF` 的实际职责

`00436611` 的 `ret 0x1C` ABI 中，`[EBP+20]`、`[EBP+21]` 是 segment 的两个字节，`[EBP+0C]`、`[EBP+10]` 是中心 X/Y。双非零时四次调用 `00437AFF` 形成四向镜像格；单轴进入十字/轴向分支。

`00437AFF` 接收候选 X/Y，执行地图边界、地图格、单位 ID、阵营/状态过滤，并扫描 `004AC748` 去重；通过 `004B2C34` 追加单位 ID，同时写入高字节 `FF` 终止。因此“预览红格”和“实际可攻击格”的底层过滤逻辑相同。

0040628A  mov [004927F0+424], al
0040629E  清空 [004927F0+10]，长度 0x74，填 FF
004062B4  清空 [004927F0+84]，长度 0x74
004062CA  清空 [004927F0+254]，长度 0x74

## 2026-08-24 8.14 特效范围地址纠正与四类效果归档

目标文件 `基底/8.14-绝对反击Ekd5.exe` 的 SHA256 为 `4A5221B4842A261647D0DE23CDE3867974A5493A9C98C21015A6116AA5F2E063`。`.code` 的 VA 到文件偏移必须使用 `0x400 + (VA - 0x00401000)`；此前把部分 RVA/文件偏移直接当成 VA，造成了错误反汇编。

- 真实特效屏蔽外层范围：指令 `004253A9`，文件偏移 `0x247A9`，原始 `3C 04`；实际立即数字节在 `004253AA` / 文件 `0x247AA`。它属于 `00425390` 的外层邻格扫描，`04` 遍历方向索引 `0..3`，改 `08` 遍历 `0..7`。调用链是 `00410213 -> 0040F1AC -> 00425390 -> 0041031C -> 004359F5 -> 00435884`。
- `0040F1E8` 仍是 `0040F1AC` 内部谓词的循环边界；单独改它不会扩大外层候选格，之前 `3C04 -> 3C08` 的结论已降级为错误候选。
- 状态强化：指令 `00422150`（文件偏移 `0x21550`，立即数字节 `00422151` / `0x21551`）当前就是 `3C 09`。循环索引 0 直接使用当前单位自身，索引 1..8 减一后访问方向表 0..7，所以 `09` 的“八格 + 自身”在该函数中有直接汇编证据，`08` 表示八格。
- 封锁攻击范围：指令 `0042BB73`（文件偏移 `0x2AF73`，立即数字节 `0042BB74` / `0x2AF74`）是 `0042BB57` 的 `3C 04`，通过 `004359F5 -> 00435884 -> 0043A289/004210E2` 处理邻格；可独立改为 `3C 08`。
- `0042D707`（文件偏移 `0x2CB07`）不是范围上限，而是 `0042D705: cmp dword ptr [ebp-24],3` 的立即数字节。它依据 `0042637F` 的方向值选择 `-0x10` 或 `+0x28` 的绘制偏移；改 `03 -> 08` 不会得到八邻格，当前版本应阻断该修改并按动态调用链重新定位“自动提升周围能力”。
