## 详细记录

### 2026-10 统一物品效果值物理位置与直写口径

当前工具实现以 `CCZModStudio.Core.ItemEffectStorageResolver` 为唯一物品物理位置解析器。6.5 依据 `HexTableDefinition` 的字段累计偏移读取 `装备特效号-效果值`；标准物品行长为 `0x19`，该字段落在行内 `+0x16`。6.6 使用 `Data.e5+0x818C` 的 104 行和 `Star.e5+0` 的 151 行，行内 `+0x11` 是类型/辅助装备及消耗品有效特效号，`+0x12` 是原始类别标记（2/3），`+0x16` 是宝物特效值，普通装备的有效号写入 `+0x12`。

九概念、宝物设定页面和 MCP 写回均保存 `rawMarker / effectiveEffectId / effectValue` 三个独立字段。辅助装备和消耗品不再按类别把“初始能力”冒充特效值；只有目标版本扫描结果明确声明“初始能力”为效果值来源时才允许使用，目前 6.5/6.6 均按物理效果值字段读写。

引擎扫描数据字段默认使用 `DirectUnrestricted`，信任层为 `UserAuthorizedUnverified`，写入报告标记 `UnverifiedDirect`。该模式只取消档案资格、未知差异、旧字节、动态证据和发布清单门禁，仍要求目标存在、偏移/宽度和值域有效，且生成 SHA、备份、报告、写后复读和撤回记录。行为逻辑与汇编仍必须由用户提供明确物理位置和字节内容。

后缀属于显示元数据；没有独立原生槽位证据时，项目侧 UTF-8 `CCZModStudio_Notes/EffectSuffixes.json` 是正式写入回退，原生名称池只登记为 `Candidate`。详见《特效后缀位置与读写方案》。

#### 概述

**特效值**是特技的"强度数值"，由游戏数据配置决定。例如：MP恢复特技的特效值=10，则每回合恢复10点MP。

#### 效果值标志

桩函数的第一个 push 参数是"效果值标志"，用于控制返回值类型：

| 标志值 | 含义 | 典型用途 | 返回值 |
|--------|------|----------|--------|
| `1` | 不需要效果值 | 纯开关型特技 | 1（有）或0（无） |
| `0` | 需要效果值 | 有强度等级的特技 | 具体数值或0 |

#### 效果值标志对比

| 特性 | 效果值标志=1 | 效果值标志=0 |
|------|--------------|--------------|
| 典型特技 | 二次行动、引导攻击 | MP恢复、HP恢复 |
| 桩函数返回值 | 1（有）或0（无） | 具体数值或0 |
| 调用者用法 | `test eax, eax; jz skip` | `add accumulator, eax` |
| 强度概念 | 无（纯开关） | 有（数值强度） |

#### 特效值传递路径

##### 标准路径（引擎原生）

```
游戏数据（特效值配置）
    ↓
核心引擎 4101D9（双渠道判定 + 读取效果值）
    ↓ 返回 EAX = 效果值
调度函数 60002A（透传）
    ↓ 返回 EAX = 效果值
桩函数 421106（透传）
    ↓ 返回 EAX = 效果值
调用者 43CE8F（使用效果值）
    ↓ add [ebp-04], eax → 累加到MP恢复量
```

##### 内联直接调用路径（模组补丁常用 ⭐）

```
游戏数据（特效值配置）
    ↓
代码洞中的内联桩代码:
    push <效果值标志:0>
    push <叠加标志>
    push <装备特效号>
    push <个人特效号>
    call 4101D9       ← 直接调用核心引擎
    ↓ 返回 EAX = 效果值
调用者（在代码洞中直接使用效果值）
```

> **注意**：在内联直接调用模式下，效果值通过 `call 4101D9` 的返回值（EAX）直接携带，无需经过调度函数透传。效果值标志=0 时返回配置的效果值数值；效果值标志=1 时返回 0/1 布尔值。

#### 叠加标志

桩函数的第二个 push 参数是"叠加标志"，用于控制效果值能否叠加：

| 标志值 | 含义 | 说明 |
|--------|------|------|
| `1` | 不可叠加 | 只取其中一个渠道的效果值 |
| `0` | 可叠加 | 两个渠道的效果值累加 |

**示例**：MP恢复特技的叠加标志=0（可叠加），如果角色自身拥有该特技（个人特效号=1），且装备也提供该特技（装备特效号=1B），两个渠道的效果值会叠加。

##### 完整恢复流程

```c
void process_turn_recovery(Unit* unit) {
    // HP恢复
    hp_recovery = percent_calc(base_hp, rate);  // 425AD9
    hp_recovery = check_poison(hp_recovery);   // 423FA1
    if (hp_recovery > 0) {
        if (unit->hp + hp_recovery > unit->max_hp)
            hp_recovery = unit->max_hp - unit->hp;
    }

    // MP恢复（通过桩函数获取效果值）
    mp_recovery = 0;
    mp_recovery += stub_mp_recovery_1();    // call 421106 → 返回效果值
    mp_recovery += stub_mp_recovery_2();    // call 4210AC → 返回效果值
    mp_recovery = check_poison(mp_recovery); // 中毒则减半
    if (mp_recovery > 0) {
        max_mp = get_max_mp(unit);           // 40728F
        if (unit->mp + mp_recovery > max_mp)
            mp_recovery = max_mp - unit->mp;
    }

    apply_recovery(unit, hp_recovery, mp_recovery);
}
```

## 2026-10 宝物界面提交与物理复读约束

WinForms `DataGridView.EndEdit()` 只保证单元格控件结束编辑，绑定的 `DataRowView` 可能仍保留 `DataRowVersion.Proposed`。保存按钮、筛选、导出、粘贴、批量填充、撤销/重做和页面切换必须统一执行：提交脏单元格、验证表单、结束网格编辑、显式调用 `DataRowView.EndEdit()`、结束 `BindingSource`/`CurrencyManager`，最后确认没有 `Proposed` 版本。只检查 `DataTable.GetChanges()` 或界面显示值不足以证明输入已进入可写数据。

宝物“特效值”唯一对应物品行物理字段 `装备特效号-效果值`。标准 6.5/6.6 行长 `0x19` 时必须复核 `row+0x16`；不得在辅助装备/消耗品行把 `初始能力` 当作效果值。保存前以 `ItemEffectStorageResolver` 核对文件、物品 ID、行偏移、行长、字段偏移和值域；保存后从实际文件再次读取 `rawMarker/effectiveEffectId/effectValue`，三者不一致时禁止 `AcceptChanges()`。

界面烟测必须真实绑定 `DataGridView`：输入后不切换行，断言 `Original/Current` 仍为旧值、`Proposed` 为新值且 `GetChanges()==null`，再调用与保存按钮相同的提交路径。验收同时比较测试副本的前后字节、备份、JSON 报告和撤回历史，确认只改变目标效果值字节。
